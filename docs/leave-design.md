# 企业年休假额度账户服务 — 设计说明

包路径：`ontology/leave`（实现）、`ontology/leave/naive`（独立朴素参考模型，仅供测试对照）。

## 1. 问题与模型

时间以整数日序号计，年度 `y` 覆盖日序号 `[365y, 365y+364]`，不考虑闰年。
服务管理员工按年度的假期额度：发放、结转、占用、扣减、销假回补与到期作废，
要求任意边界下的余额、扣减来源与回补去向可精确复现。

### 1.1 核心概念

- **当年额度**：年度 `y` 首日按累计工龄档位发放；入职当年按入职当日（含）至年底
  剩余日数占全年比例折算（`quota * (365 - doy(hireDay)) / 365`，不足一日舍去），
  折算后不再受工龄档影响。工龄档边界取等归高档（`tier = #{b : tenure >= b}`）。
- **结转额度**：上年度当年额度的未用量（扣除占用中，占用计入已用）可结转到次年，
  量不超过结转上限，超出部分自然消失；结转额度仅可用于次年内日偏移
  `<= 结转截止日` 的请假日。
- **四量视图**：当年额度 / 结转额度 × 占用中（待批准）/ 已确认使用。

### 1.2 API 一览

| 方法 | 语义 |
| --- | --- |
| `NewService(cfg)` | 校验并创建服务 |
| `Register(now, emp, hireDay)` | 登记员工与入职日 |
| `RequestLeave(now, emp, from, to)` | 申请（提交即占用），返回假单 ID 与逐日扣减明细 |
| `Approve / Reject / Withdraw` | 批准（占用转已用）/ 驳回、撤回（释放占用） |
| `CancelLeave` | 整单销假：仅限尚未开始（`now < from`）的已批准假单，全额回补 |
| `EarlyEnd(now, emp, id, newEnd)` | 提前结束：仅限已开始的已批准假单，回补 `(newEnd, to]` 的计扣日 |
| `Balance(now, emp)` | 查询 `now` 所在年度四量余额，支持历史时刻，只读 |
| `DumpYears(emp)` | 全年度台账诊断视图（守恒审计用） |

错误类别可区分（`leave.Error.Cat`），优先级：参数非法 > 时钟回退 > 员工不存在 >
状态不允许 > 区间重叠 > 额度不足。被拒绝的操作不改变任何额度、状态与时钟。

## 2. 关键设计取舍

### 2.1 发放是确定性函数，不入账

年度 `y` 的当年额度发放量只依赖配置与入职日（`quota(y)`），因此**从不落账**，
需要时直接计算。落账的只有可变量：已用、占用、作废、已结转出去（`carriedOut`）。
这消除了"发放事件"与"扣减事件"之间的顺序歧义，也是惰性年度切换的前提。

### 2.2 结转仅由 now 触达时钉死（lazy pinning）

年度切换不做后台定时：当被接受操作携带的 `now` 进入年度 `Y` 时，把
`(carryYear, Y]` 各年的结转按年度顺序依次"钉死"：
`carriedOut(y-1) = min(quota(y-1) - usedCur(y-1) - pendCur(y-1), cap)`。
跨越多个年度未触达时，该循环与逐年触达完全等价（结转只依赖上一年台账，
循环内无外部输入），由 `TestLazyMultiYearCatchUp` 与朴素模型（显式逐年循环）
的随机对照双重验证。

**推论（重要）**：年度 `y` 的结转额度只有在 `now` 到达年度 `y` 后才存在。
跨年夜之前提交的跨年请假，其次年计扣日只能使用次年的**当年额度**
（次年结转尚未触达，按 0 计）。这使"每日按所属年度判定来源"在任意提交
时点都有确定答案，且与惰性模型自洽。

### 2.3 被拒绝的操作不钉死结转

扣减先完整模拟（只读），全部计扣日都有着落才落账；钉死结转只发生在模拟通过
之后。因此失败操作既不改变额度，也不改变结转状态与时钟（`TestRejectLeavesNoTrace`
验证：失败后余额逐字段相等、台账为空、更小的 now 仍被接受）。

### 2.4 回补到来源与结转作废

假单保存逐日扣减记录（日序号 + 来源），任何释放（驳回/撤回/整单销假/提前结束）
都按记录回到当初的来源。回补到结转额度时，若计扣日所属年度的结转截止日
（`365y + deadline`）**已早于**销假的 `now`，该部分回补作废（计入 `voidedCar`，
不恢复为可用）；恰等截止日不属"早于"，正常恢复。

**为什么提前结束允许 `newEnd < now`（追溯）**：若要求 `newEnd >= now`，则被回补的
计扣日恒 `> now`，而结转计扣日恒 `<= 365y+deadline`，作废条件 `365y+deadline < now`
将永不可达，规格中的作废规则成为死代码。允许追溯提前结束（`from <= newEnd < to`，
`newEnd` 可早于 `now`）后，作废规则自然可达：例如年假单含截止日前的结转计扣日，
在截止日之后追溯提前结束，这些日子的回补作废。该解读同时覆盖"结束日起未发生的
计扣日全部回补"（`newEnd >= now` 的常规情形）。驳回/撤回待批准假单的释放适用同一
规则（统一实现，避免两套回补语义）。

### 2.5 历史余额：按年追加式历史 + 二分

每个年度台账维护一条按 `now` 递增的追加式变更历史（每次被接受操作只向它实际
改动的年度追加一条）。历史时刻 `t` 的余额 = 年度 `year(t)` 台账在 `t` 的快照
（二分查找）+ 确定性的发放量与结转推导。由于结转钉死值与"假想 t 时刻钉死"的
推导值在任一时刻都一致，历史查询不需要重放操作序列，也不需要全量快照。
查询为只读，不推进时钟、不钉死结转。

### 2.6 复杂度设计（开销与历史规模无关）

- **重叠判定**：未终结假单区间存入按起点排序的 Treap（优先级为假单 ID 的确定性
  哈希，保证重放一致）。区间两两不相交，重叠判定只需前驱/后继查询，期望 O(log n)。
- **申请/销假**：O(计扣日数 + log n)，与历史假单总数无关。
- **余额查询**：O(log（该年变更次数）) 二分 + O(1) 推导。
- 对照验证：`TestPerfScaleIndependence` 在 2,000 与 200,000 张历史假单（相差两个
  数量级）两档下测量申请+批准、提前结束、历史余额查询的单次耗时，比值远小于
  线性（实测 ≤ 3 倍，阈值 5 倍），证明无随历史规模增长的扫描。

### 2.7 并发模型

- 全局时钟为原子变量，只在操作**被接受**时以 CAS-max 推进；被拒绝的操作不动时钟。
- 员工表用读写锁保护；每个员工一把互斥锁，所有状态变更在员工锁内完成。
- 时钟检查做两次：员工查找前一次（保证"时钟回退"优先于"员工不存在"的报错
  优先级），员工锁内再复查一次（保证同一员工被接受操作的 now 单调）。
- 可串行化论证：同一员工的操作在员工锁内全序；不同员工状态独立；被接受操作的
  now 按该全序单调不减，故全体结果等价于按 now 排序的某个串行执行。
- `TestConcurrentEquivalence`（多员工分轮并发 vs 串行参考逐结果对照）与
  `TestConcurrentSameEmployeeContention`（32 协程竞争同一区间，恰好 1 个成功）
  在 `-race` 下验证。

### 2.8 确定性重放

无随机源（Treap 优先级为 ID 哈希）、无挂钟依赖、无后台协程；相同操作序列
重放得到完全相同的结果。朴素模型以事件溯源方式整体重放，与主实现逐步对照
一致（`TestRandomModelComparison`，40 组随机配置 × 400 步，逐步打印输入、
输出与判定依据）。

## 3. 被放弃的方案

1. **后台定时年度切换**：违反"不得依赖后台定时"，且引入时钟与状态的竞态。
2. **提交跨年请假时提前钉死次年结转（含"预留"变体）**：预留 `min(可用, 上限)`
   在数学上与年末结转等价，但当上年存在待批准占用、随后被驳回释放时，
   提前钉死值与年末真实结转值会出现不可调和的偏差（结转可能已被花掉，
   无法回冲）。因此未来年度的结转一律视为 0，待 now 触达时钉死（见 2.2）。
3. **每次操作全量快照台账**：历史查询最简单，但快照成本随年度数增长，
   且长历史下内存随操作数线性膨胀；被按年追加式历史取代（见 2.5）。
4. **有序切片/链表存区间**：插入 O(n)，违反"开销不随历史记录总数增长"。
5. **要求 `newEnd >= now`**：使结转作废规则永不可达（见 2.4）。
6. **销假回补一律恢复、不作废**：违反规格；统一在释放路径上实现作废规则。

## 4. 守恒与不变式

对每个年度台账恒有（`DumpYears` 可审计）：

- 当年额度：`granted = usedCur + pendCur + carriedOut + availableCur`，`availableCur >= 0`
- 结转额度：`carriedIn = usedCar + pendCar + voidedCar + availableCar`，`availableCar >= 0`

`TestConservationInvariant` 在混合操作序列的每个被接受操作后断言上述恒等式。

## 6. 已知边界与约定

- 非工作日集合按年内日偏移（0..364）给出，对每个年度同样生效。
- 请假申请要求 `from >= now`（不允许补登过去的请假）；`from` 不得早于入职日；
  单张假单跨度上限 200 年（防止超长区间退化）。
- 查询不推进时钟；早于员工登记时刻的余额查询报"员工不存在"。
- 假单 ID 为服务级单调递增整数；并发下 ID 分配顺序取决于实际串行化顺序
  （不影响等价性）。
- 跨年未审批的待批准假单可长期占用额度；其占用不计入结转（计入已用），
  亦不随年度切换自动释放。
