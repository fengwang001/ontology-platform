# 合约广告库存预订簿（booking 包）

带超订比例、定向交叉可行性校验与候补顺位的库存预订簿。多个定向单元可以共享库存；
预订判定基于所有定向子集的 Hall 型可行性条件；库存释放后候补合约按到达顺序一轮递补。

代码位于 `booking/`：

- `booking/booking.go`：对外类型、错误、结果与查询入口。
- `booking/impl.go`：容量预算、受影响子集枚举、四个变更操作与一轮递补。
- `booking/booking_test.go`、`booking/counter_test.go`、`booking/naive_test.go`：
  边界用例、子集计数/并发、与朴素模拟的 2000 组随机对照。

## 1. 参数与容量

- 单元个数 `C ∈ [1,10]`，单元编号 `0..C-1`。
- 各单元库存 `s_j ∈ [0, 10^12]`；超订比例 `ρ ∈ [1,1000]`（百分数）。
- 定向为非空位掩码 `mask ∈ [1, 2^C-1]`；数量 `qty ∈ [1, 10^12]`。

对任意非空单元子集 `T`：

```
S(T)   = Σ_{j∈T} s_j
Cap(T) = floor( ρ × S(T) / 100 )
```

注意是对**子集库存总和先求和、再乘 ρ、最后统一取整**，不是逐单元取整后相加。
例如库存 `[105,55]`、`ρ=90`：

- `Cap({0}) = floor(90·105/100) = 94`
- `Cap({1}) = floor(90·55/100) = 49`
- `Cap({0,1}) = floor(90·160/100) = 144`（逐单元取整再相加只有 94+49=143）

容量用 128 位乘法（`math/bits.Mul64` + `Div64`）计算，最大中间值
`ρ·S(T) ≤ 1000·10·10^12 = 10^16`，不会溢出且取整精确。

## 2. 可行性定义

已预订合约集合可行，当且仅当对**每个非空子集 T**：

```
Σ { qty_i | 已预订合约 i 且 mask_i ⊆ T } ≤ Cap(T)
```

这是“每份合约都能整量落在自己定向单元内”的充要条件（双向容量/Hall 条件）。
定向为 `{0,1}` 的合约同时计入 `{0}`、`{1}`、`{0,1}` 等所有包含其掩码的子集约束，
因此会出现“单个单元看似充足、但交叉子集不可行”的情形：
`[100,50], ρ=90` 下 `a{0}=80` 已订后，`b{0,1}=60` 单看 `60≤Cap({0,1})=135`，
但 `{0}` 上 `80+60=140>90`，仍不可行。

## 3. 操作语义

### Book(id, mask, qty)

1. 参数校验（id 非空、mask 与 qty 越界检查）。
2. id 已在已预订或候补中 → `ErrAlreadyExists`。
3. **单点判定**：`qty > Cap(mask)` → `ErrNeverBookable`，拒绝且永不进入候补。
   该判定只检查 `T=mask` 一个点，不计入决策子集计数器。
4. 否则检查“加入后集合是否可行”，只枚举 `T ⊇ mask` 的全部
   `2^(C-|mask|)` 个子集；可行则预订，不可行则追加到候补队列尾部。

### Cancel(id)

- 命中已预订：移除并触发**一轮递补**。
- 命中候补：直接移除，**不触发递补**。
- 不存在：`ErrNotFound`。

### Resize(id, q2)

仅对已预订合约有效（候补合约报 `ErrNotBooked`）。

- `q2 == qty`：空操作，不检查、不递补。
- `q2 < qty`：单调放松约束，必然可行；直接改量并触发递补。
- `q2 > qty`：枚举 `T ⊇ mask` 的 `2^(C-|mask|)` 个子集；全部满足才接受，
  否则 `ErrInfeasible`，拒绝且**不进候补、不改任何状态**。

### Retarget(id, mask2)

仅对已预订合约有效。

- `mask2 == mask`：空操作，不检查、不递补。
- 否则只检查 **`T ⊇ mask2` 且 `T ⊉ mask`** 的子集：

```
|检查子集数| = 2^(C-|mask2|) − 2^(C-|mask ∪ mask2|)
```

  推导：包含 `mask2` 的子集共 `2^(C-|mask2|)` 个；其中同时包含旧 `mask`
  （即包含 `mask∪mask2`）的有 `2^(C-|mask∪mask2|)` 个，这些约束在改动前已满足。
  纯扩大（`mask ⊂ mask2`）时该数为 0，恒可行；纯缩小时该数为 0 但会释放约束，
  因而仍触发递补。
- 检查通过才写入新定向，随后触发递补；否则 `ErrInfeasible` 且不改状态。

## 4. 候补与递补

- 候补是严格保持到达顺序的 FIFO 队列。
- 递补在触发它的操作内完成：按候补顺序**只扫一遍**，对每个候选项枚举
  `T ⊇ mask_i` 的 `2^(C-|mask_i|)` 个子集；可行则立即转为已预订（本轮已递补者
  会占用容量并影响后续判定），不可行则留在原位并**继续检查后面的项**（不阻塞队首）。
- 扫描完成后满足不变量：每个仍在候补的合约，单独加入当前已预订集合都不可行。
  （同一次扫描内“前面的不可行、后面的可行”是允许的。）
- `Book` 成功不触发递补；候补只在 `Cancel(已预订)`、`Resize(变小)`、
  `Retarget(成功)` 后递补。

## 5. 拒绝原因与优先级

按以下顺序只返回第一个命中的原因，被拒绝的操作不改变任何状态：

1. `ErrInvalid`：`C`、库存长度/范围、`ρ`、id 为空、`mask` 或 `qty` 越界。
2. `ErrAlreadyExists`：`Book` 的 id 已在已预订或候补中。
3. `ErrNotFound`：`Cancel`/`Resize`/`Retarget` 的 id 不存在。
4. `ErrNotBooked`：`Resize`/`Retarget` 作用于候补合约。
5. `ErrNeverBookable`：`Book` 的 `qty > Cap(mask)`。
6. `ErrInfeasible`：`Resize` 变大或 `Retarget` 后集合不可行；
   `Book` 的加入不可行不属于“拒绝”，而是进入候补。

## 6. 并发、原子性与可复现

- 所有方法持有同一把互斥锁；每个变更与其触发的递补在同一临界区内完成，
  外部不可能观察到“只递补了一部分”的中间状态，整体可线性化（等价于某个串行顺序）。
- 查询返回快照副本；任何串行等价状态下已预订集合都可行、候补顺序保持不变。
- 操作无随机、无时钟依赖：相同操作序列在任意并发交错下，最终预订集合、
  候补队列与递补顺序都可精确复现（`TestDeterministicReplay` 双簿重放逐位对比）。

## 7. 子集计数与非导出计数器

`Book.ResetCounters()` 后，以下两个计数器只统计**决策可行性判定**
（不含永不可订的单点判定，也不含 `Feasible()` 全量查询）：

- `CounterSubsets()`：累计枚举的子集数。
- `CounterCalls()`：可行性判定次数（每个候补项一次、每次 `Book`/`Resize`/
  `Retarget` 判定一次；纯扩大 Retarget 为 0 次）。

每次判定都**枚举全部规定子集、不提前退出**（先算出布尔结论再继续枚举），
因此计数精确等于公式值。`TestSubsetCounters` 在 `C=4` 与 `C=10` 两档验证：

- `Book`/候补/`Resize` 变大：恰为 `2^(C-|mask|)`。
- `Retarget`：恰为 `2^(C-|m2|) − 2^(C-|m1∪m2|)`。
- 一轮递补：Σ（每个候补项的 `2^(C-|mask_i|)`）。

## 8. 本地验证方法

需要 Go 1.26+（`/usr/local/go/bin`）。构建缓存建议指向可写目录：

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache GOPATH=/tmp/gopath

go build ./...
go vet ./...
gofmt -l .

# 全量测试（含 2000 组随机对照、C=4/10 计数、并发）
go test -v ./booking/

# 竞态检测
go test -race ./booking/

# 仅跑朴素模拟对照
go test -run TestNaiveDifferential2000 -v ./booking/
```

### 测试覆盖

- qty 恰等于 `Cap(mask)` 可订、多 1 永不可订且不进候补；
- 子集负载恰等于 `Cap(T)` 可行、多 1 不可行进候补；
- 整体取整与逐单元取整不同（`[105,55], ρ=90`）；
- 跨单元定向导致交叉子集不可行；
- 候补不阻塞队首（队首仍不可行时其后者先递补）；
- 递补先到先排，且本轮已递补者影响后续可行性；
- `Resize` 变小递补、变大拒绝且不改状态、相等空操作；
- `Retarget` 扩大（纯扩大恒可行）、缩小（释放并递补）、交叉改向被拒、相同定向空操作；
- 取消候补项不触发递补；永不可订不进候补；
- 六类拒绝原因的优先级与拒绝不改状态；
- 与逐子集枚举的朴素模拟器对照 2000 组随机操作序列（每步比较输出、原因、
  阶段、递补顺序与完整状态；失败时打印种子、输入、输出与判定依据日志）；
- C=4/C=10 的子集精确计数、并发可线性化观测与确定性重放。
