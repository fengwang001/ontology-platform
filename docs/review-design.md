# 专业技术职称评审会务服务 — 设计说明

包路径：`ontology/review`。演示入口：`cmd/server`。

## 1. 领域模型

- **评委（Expert）**：编号、所属单位、专业组。
- **申报人（Applicant）**：编号、所属单位，以及四个回避索引集合：
  已登记关系（对称、仅直接关系）、待受理回避申请、已受理回避申请、
  作废评审评委索引（`VoidedExperts`）。
- **评审（Review）**：评委人数 `n`（奇数）、专业组最低人数、
  评委构成版本链（`Versions`）、全部投票记录（`Votes`）、
  结算留痕（`Trail`）、异议（`Objection`）与终止标志。

评委 `e` 对申报人 `a` 须回避，当且仅当：同单位；有登记关系；
`a` 对 `e` 的回避申请已受理；`e` 曾在 `a` 以往已作废评审中任评委
（任一版本的成员均计入）。

## 2. 关键取舍

### 2.1 抽取唯一性：贪心替代枚举

要求“所有满足条件的集合中，编号升序排列后字典序最小者”。
直接枚举子集是指数级的，被放弃。观察到每位评委只属于一个专业组，
可行性仅取决于各组剩余人数，因此采用贪心：按编号升序逐个考虑，
只要纳入后仍存在可行补全（各组缺口均不超过剩余候选数、
缺口总数不超过剩余名额）即纳入。交换论证可证该结果即字典序最小。
复杂度 O(E·G)，与历史评审总数无关。

### 2.2 回避判定的 O(1) 索引（复杂度可验证性）

“曾在以往已作废评审中任评委”若靠扫描历史评审判定，
开销随评审总数线性增长，被放弃。改为在评审被裁定作废时，
将其全部版本成员写入申报人的 `VoidedExperts` 哈希集合，
此后判定为 O(1)。服务内置 `recusalChecks` 计数器，
`TestDrawCostIndependentOfHistory` 断言：历史评审从 0 增至 30 个，
一次抽取的回避判定次数恒等于评委总数（12），以此可验证地证明
开销不随历史增长。朴素模型（见 §5）则刻意保留线性扫描写法作对照。

### 2.3 逻辑时钟

所有操作携带调用方时间 `at`，服务维护逻辑时钟 `now`；
`at < now` 报“时钟回退”。被接受的操作把时钟推进到 `at`，
被拒绝的操作不改变任何状态与时钟。这保证相同操作序列重放
结果完全相同（`TestReplayDeterminism`），也使公示期边界可精确测试。

### 2.4 版本化评委构成与作废票

每次替补形成一个新 `PanelVersion`，历史版本只增不改。
每票记录投票时的版本号；评委退出时其全部有效票标记
`VoidedAt = 新版本号`（记录保留，不删除）。
`EffectiveVotesAtVersion(v)` 还原版本 `v` 当时的有效票集合：
该版本成员所投、投票版本不晚于 `v`、且在 `v` 期间尚未作废的票。

### 2.5 结算即重推导 + 只增留痕

每次投票或替补后，从当前有效票集合**从头推导**应成立的结论链
（第一轮 → 复议 → 终局），再与留痕对账：不一致的旧条目标记
`Superseded`（保留不删除），新结论追加。由此天然满足：

- 票未补齐（有效票 < n）时结论链为空，不会宣布任何结果；
- 已宣布结果因票作废而改变时，旧结论被取代、新结论生效并留痕；
- 公示期自最新一次有效终局宣布时刻起算（结果改变则公示重启）。

### 2.6 单一互斥锁串行化

所有公开操作在同一互斥锁内完成“校验 → 变更”，
并发调用等价于某个串行顺序（`-race` 下的并发测试验证）。
放弃了分评审加锁等更细粒度方案：正确性优先，且避免了
跨评审操作（回避复查波及多个评审）的锁序问题。

### 2.7 惰性终局生效

“公示期满且无异议或异议不成立则生效”不做定时器，
而是由状态查询按当前逻辑时钟惰性推导。异议的受理、裁定、
终局生效互斥且各至多一次：已生效评审不再受理/裁定异议，
已受理/已裁定的异议不可重复。

### 2.8 错误优先级

`ErrorKind` 按优先级声明（参数非法 > 时钟回退 > 不存在 >
状态不允许 > 无权限 > 评委不足 > 重复投票），每个操作严格按
该顺序逐项校验，命中即返回，保证只报第一个错误且拒绝无副作用。

## 3. 被放弃的方案

- **子集枚举抽取**：指数级，仅保留在测试中作暴力对照。
- **回避判定扫描历史**：随历史评审总数线性增长，改为作废时建索引。
- **事件溯源全量日志**：对当前需求过重；版本链 + 只增留痕已满足
  可还原与留痕要求。
- **评委跨评审互斥占用**：需求未要求；“评委不足不占用任何评委”
  实现为失败零副作用（不产生评审、不推进时钟）。
- **关系的传递闭包**：需求明确“仅限直接关系”，不做传递推导。
- **物理时钟**：不可重放、边界不可测，改为逻辑时钟。

## 4. 表决规则实现要点

- 第一轮：赞成 ≥ ⌈2n/3⌉ 通过；赞成 ≤ ⌊n/2⌋ 不通过；否则复议。
  弃权计入总人数 n 但不计赞成。n 为奇数时 n=3 不存在复议区间。
- 复议：全体重新投票，赞成严格大于 n/2 方通过，否则不通过。
- 每人每轮一票不可更改；非现任评委投票报无权限；
  同轮重复投票报重复投票。
- 中途回避：退出者全部已投票作废，最小编号合格替补补入；
  已完成轮次替补须补投，补齐前该轮不得结算；无法替补则评审中止。

## 5. 测试与本地验证

```bash
export PATH=$PATH:/usr/local/go/bin

# 全量测试（含竞态检测）
go test ./... -race -count=1

# 查看随机对照的逐步日志（输入、输出、判定依据）
go test ./review/ -run TestRandomizedAgainstNaiveModel -v

# 演示
go run ./cmd/server
```

测试分层：

- **边界单测**（`review/service_test.go`）：三分之二/过半门槛恰等与差一、
  弃权影响、复议严格过半、四类回避来源、替补补齐前不得结算、
  公示期末刻恰等、异议后原评委回避、抽取唯一性、拒绝优先级链、
  拒绝原子性、并发等价、重放等价、复杂度不变性、版本还原。
- **朴素模型对照**（`review/model_test.go`）：独立编写的朴素实现
  （回避扫描全部历史、抽取暴力枚举子集、结算每次从头推导），
  30 个随机种子 × 150 步随机操作序列（含时钟回退、非法参数、
  智能推进投票/异议），每步比对错误类别与全量确定性快照，
  并以 `t.Logf` 打印每步输入、输出与判定依据。

## 6. 假设（需求未明确处的决定）

- 同一申报人可并存多个评审；评委可同时服务于多个评审。
- 评审中止（无法替补）不同于作废：不触发原评委回避。
- 评审作废时，其**全部历史版本**的成员均对该申报人回避。
- 结果宣布后（公示期内）发现回避同样触发替补与重新结算，
  公示期自新的宣布时刻重新起算。
- 异议在公示期内提出但期满后才裁定的，允许裁定；
  裁定不成立则结果随即生效。
