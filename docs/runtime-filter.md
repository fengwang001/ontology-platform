# 哈希连接运行时过滤器协调器

`runtimefilter` 包把构建侧连接键的取值摘要下发给探测侧扫描，提前丢弃
不可能匹配的行。过滤器只减少进入连接算子的行数，从不改变连接结果：
在任何连接类型、空值、超时与分片放弃下，最终输出与不加过滤器完全
相同。

## 摘要合并与降级规则

构建侧由 N 个分片并行产出，每片上报 `ShardSummary`：

- `Min` / `Max`：本片连接键的最小、最大值；
- `Keys`：本片去重后的连接键集合；
- `Empty`：本片没有任何构建行；
- `Aborted`：本片放弃构建摘要。

N 片全部到齐后过滤器才就绪，合并规则：

1. 任一片 `Aborted` → 整个过滤器作废（`Invalid`），所有探测行放行；
2. 所有片 `Empty` → `Empty` 过滤器，内连接/半连接下探测行全部丢弃；
3. 否则取所有非空片的最小的最小值、最大的最大值，以及键集合的并集；
4. 并集去重数超过 `maxDistinct` 上限 → 降级（`Degraded`），只保留
   最小/最大值做区间过滤，不再按集合过滤。

合并产物是一份不可变的 `Filter` 快照，通过 `atomic.Pointer` 一次性
发布；探测侧每一批只加载一次快照，不会看到合并了一半的摘要。

## 各连接类型可否过滤的推导

过滤器会丢弃探测侧的行，因此只有当**探测侧不是保留侧**时才安全：

| 连接类型 | 保留侧 | 探测侧可过滤 | 依据 |
| --- | --- | --- | --- |
| Inner | 无 | 是 | 不匹配的行本就不会输出 |
| LeftSemi | 无（只输出匹配行） | 是 | 同上 |
| RightOuter | 构建侧（右） | 是 | 探测侧（左）不匹配的行不会输出 |
| LeftOuter | 探测侧（左） | 否 | 不匹配的行仍需以 NULL 补齐输出 |
| FullOuter | 双侧 | 否 | 同上 |
| LeftAnti | 探测侧 | 否 | 恰恰要输出不匹配的行 |
| Unknown | — | 否 | 类型未知时任何报告整体拒绝 |

空值语义：等值连接下 `NULL = anything` 不成立，就绪后键为空的探测行
直接丢弃（仅限可过滤的连接类型）。构建侧全部为空时，内连接与半连接
不可能有任何输出，探测行全部丢弃。

## 超时语义

探测侧按批取行。每批最多等待 `waitTimeout` 让过滤器就绪：

- 就绪前的批（含超时批）原样放行，不做任何过滤；
- 超时后晚到的过滤器只作用于其后的批，不回溯；
- 每批的判定依据（不过滤 / 超时放行 / 作废放行 / 按键摘要过滤）连同
  输入、输出键序列写入日志。

不变量：每一批恒有 `Dropped + Passed == Scanned`。

## 报告校验

`ReportShard` 对以下情况整体拒绝并返回可区分错误，且不改变任何状态：

- `ErrUnknownJoinType`：连接类型未知；
- `ErrShardOutOfRange`：分片编号越界；
- `ErrDuplicateShard`：同一分片重复报告。

## 并发与确定性

分片报告与多个探测扫描可并发调用：报告路径由互斥锁保护，快照通过
原子指针发布。过滤器只能丢弃**不可能**匹配的行（降级、超时、未就绪
只会多放行、不会误丢），因此最终连接结果与不加过滤器对拍一致；同一
输入反复执行，连接结果完全相同。

## 本地验证

```bash
# 全部测试（含竞态检测）
go test -race -v ./runtimefilter/

# 反复执行验证确定性
go test -race -count=10 ./runtimefilter/

# 代码检查
gofmt -l .
go vet ./...
```

测试覆盖：左外连接与反连接不过滤、空键、构建侧为空、去重超上限降级、
分片放弃、超时后晚到、并发执行与不加过滤器对拍；日志中打印每批的
输入、输出与判定依据。
