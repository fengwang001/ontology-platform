# 容量受限转发表管理器 — 设计说明

`fib` 包维护控制面全量路由与数据面聚合转发表,保证两个面对全部
2^32 个地址的最长前缀匹配结果逐地址一致(含无路由与黑洞的区分),
数据面条目数在该约束下最少,任何更新使最少条目数超过容量上限时
整体拒绝。

## 问题建模:地址着色与树形 DP

把控制面看作对全部 2^32 个地址的**着色**:每个地址的颜色是覆盖它
的最长路由前缀的下一跳(普通下一跳、黑洞),没有任何前缀覆盖则为
**无路由**。数据面要用最少的前缀条目复现同一着色,其中:

- 条目颜色可以是普通下一跳、黑洞,也可以是**无路由**(无路由条目,
  占条目数);
- 未被任何条目覆盖的地址视为无路由(零长度前缀上的隐含无路由,
  不占条目数)。

在深度 32 的完整二叉 trie 上定义 `f(v, c)`:当"继承色"为 `c`
(即祖先条目决定的当前颜色,根节点处为无路由)时,`v` 子树内复现
着色所需的最少条目数。则

```
f(v, c) = min( g(c), 1 + min_c' g(c') ),  g(c) = f(左, c) + f(右, c)
```

即"本节点不放置条目"与"放置一个最优颜色条目"两种决策取优;叶子
(均匀子树)在继承色等于自身颜色时开销为 0,否则为 1。可以证明
`f(v, c)` 恒具有闭式形态

```
f(v, c) = D_v - [c ∈ A_v]
```

`D_v` 为默认开销,`A_v` 为**候选色集合**(使开销减一的颜色)。设两
个孩子槽对应的函数为 `(D1,A1)`、`(D2,A2)`,孩子不存在时该槽是颜
色为 `v.gamma` 的均匀子树,即 `(1, {v.gamma})`。令
`savings(c) = [c∈A1]+[c∈A2]`,`m = max savings`,则

```
m == 0:  D_v = D1+D2,      A_v = ∅
m >= 1:  D_v = 1+D1+D2-m,  A_v = { c : savings(c) == m }
```

每个节点只需保存 `gamma`(控制节点为自有下一跳,非控制节点为最近
路由祖先的继承色)、`D`、`A`。根节点在继承色"无路由"下的函数值
`D_root - [无路由 ∈ A_root]` 就是全表最少条目数。

该闭式形态的正确性由归纳法保证:均匀子树显然满足;合并公式与
`f(v,c)` 的通用递归逐项等价(测试中用通用递归的朴素模型独立验证,
见下文)。

## 数据面重建

数据面**不在更新时物化**(物化会使更新开销随表项总数增长),而是
读取时自顶向下回溯 DP 决策(`fib/reconstruct.go`):

- `c ∈ A_v`:不放置条目即可达到 `D_v - 1`,不放置;
- `base(c) <= K`(不放置的开销不超过放置的最优开销):不放置;
- 否则放置一个使孩子槽总开销最小的颜色 `c*`(候选集中按固定全序
  取定,保证数据面内容确定、可复现)。

空洞孩子槽(不含路由的子树)在继承色与其颜色不同时,在槽根放置
一个该颜色的条目——无路由条目正是由此产生(例如路由
`0/1, 128/2, 192/3 -> a` 的最优数据面是 `{0/0 -> a, 224/3 -> 无路由}`
共 2 条,见 `TestNoRouteEntry`)。每条放置决策恰好对应 DP 记账中的
一个条目,因此 `List()` 的长度恒等于 `Count()`(随机测试逐步断言)。

按地址查询数据面时只沿该地址的路径做同样的决策,开销 O(32)。

## 增量维护(关键取舍)

`f(v,·)` 只取决于 `v` 的子树,因此单条路由的增删改只需:

1. 沿目标前缀的路径做 trie 结构修改(O(32));
2. 若控制节点的下一跳变化,把它下方、未被更深路由隔断的非控制节点
   的 `gamma` 下推更新(开销正比于**受影响地址范围内**的 trie 节点
   数,`fixGamma`);
3. 沿路径自底向上重算各节点的 `(D, A)`(O(32) 个节点)。

因此单次更新开销 = O(地址位数 + 受影响范围内的路由规模),**不随
无关路由总数增长**。这是本设计最重要的取舍:不做全量重新聚合。
全量重聚合只出现在测试里的朴素对照模型中。

可验证性:`Manager.Stats()` 暴露每次更新实际重算的节点数与继承色
更新数。`TestUpdateCostIndependentOfUnrelatedRoutes` 在无关路由从
2 万涨到 4 万时,断言一次 /32 写入的重算节点数恒为 33(≤ 地址位数
+1),而写入 `0/0/0` 的重算数随受影响范围(全空间)增长到数十万,
从正反两面证明开销模型。

已知理论边界:候选色集合 `A_v` 在大量下一跳"平局"时可以达到
Θ(n)(例如所有路由下一跳两两不同),此时单次更新的集合合并开销
与候选集规模相关。该情形需要刻意构造的对抗性下一跳分布;在下一跳
取值有界的实际场景中候选集很小。我们用 `Stats` 把节点级工作量做成
可观测、可断言的指标,正是为了把这一开销置于可验证之下。

## 容量、批量与回滚

- 每次更新(含批量)生效后检查 `最少条目数 > C` 则回滚:
  回滚通过撤销日志实现——批量应用前记录每个受影响前缀的原值,
  失败时按逆序恢复,保证控制面、数据面与条目数零变化。
- 批量先统一校验全部参数(参数非法优先级最高),再按顺序执行
  (撤销目标不存在以第一个出现者为准),最后做容量检查,三级错误
  优先级为:参数非法 > 撤销目标不存在 > 容量不足。
- 写入与原值完全相同在 trie 层识别为空操作,不触碰任何状态。
- `SetCapacity` 只改上限值:新上限小于当前最少条目数时报容量不足
  且状态不变,本身不触发任何路由变化。

## 并发

全部状态由一把 `sync.RWMutex` 保护:写操作(含批量、容量调整)持
写锁,读操作(查询、计数、列表)持读锁。因此并发调用的结果等价于
某个串行顺序,且 `Query` 一次调用返回的两个面必然来自同一次更新
之后(`TestConcurrent` 在 `-race` 下验证)。

## 被放弃的方案

- **全量重新聚合**:每次更新重算整表,实现最简单,但开销随路由
  总数增长,被性能要求明确排除;仅保留为测试对照模型。
- **路径压缩 trie + 链变换**:压缩边上需要做 `T^j` 链式变换,实现
  复杂度明显高于收益(节点数仅省常数倍),改用只沿路由路径展开的
  非压缩 trie(深度 ≤ 32,规模 ≤ 32·路由数)。
- **更新时物化数据面**:维护一份真实的数据面前缀表,读取更快,
  但单次更新可能引起 Θ(表项数) 的条目变动,违反更新开销约束;
  改为读取时按 DP 状态重建。
- **持久化/惰性候选集**:为避免平局时候选集 Θ(n) 的合并开销,考虑
  过把 `A_v` 表示为子集合的交/并表达式、按需求值,但成员查询与
  增量传播都会变得复杂且仍有线性最坏情形,收益不明确,放弃。

## 本地验证方法

```bash
# 全部单元测试(默认路由、黑洞夹心、兄弟合并/拆分、撤销退化、
# 容量边界、批量净效果、拒绝后状态不变等)
go test ./fib/

# 1200 组随机操作序列与朴素模型逐步对照;-v 可看到每步的
# 输入、输出与判定依据日志
go test ./fib/ -run TestRandomSequences -v

# 换随机种子回归
FIB_SEED=12345 go test ./fib/ -run TestRandomSequences

# 竞态检测(并发读写一致性)
go test ./fib/ -race

# 更新开销与无关路由总数无关的可验证证明
go test ./fib/ -run TestUpdateCostIndependentOfUnrelatedRoutes -v

# 代码检查
gofmt -l fib/ && go vet ./fib/
```

随机对照的朴素模型(`fib/naive_test.go`)与生产代码完全独立:
用通用递归 DP(不做闭式合并)全量重算最少条目数,用前缀表扫描做
控制面查询,用整表快照做回滚;每个序列结束时对少量地址范围
(/20,每 25 组一次 /16)内的**全部地址**穷举比对控制面、数据面
与数据面列表三者与朴素模型一致。
