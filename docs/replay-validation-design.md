# 差异记录重放校验组件设计说明

包：`ontology/replay`

## 问题

灾难发生后，只保留灾难前某已知良好快照与一份结构与实例差异记录。
校验组件判定：将该差异记录重放到良好快照之上，能否被**确证**为与灾难
发生时刻本应达到的状态等价；并在失败时区分三类互不相同的原因。

## 组件划分

校验编排入口为 `Validator.Validate`（`replay/validator.go`），按固定顺序
串联四个职责清晰的阶段，命中靠前类别后立即返回：

| 阶段 | 文件 | 职责 | 失败类别 |
| --- | --- | --- | --- |
| 一 | `replay/selfcheck.go` | 差异记录自身自洽性校验（不访问快照） | `DeltaInconsistent` |
| 二 | `replay/precondition.go` | 重放前提环境（良好快照）校验（只读） | `PreconditionUnmet` |
| 三 | `replay/replay.go` | 在写时复制覆盖层上按声明顺序重放 | `DeltaInconsistent`（重放期发现） |
| 四 | `replay/equivalence.go` | 重放结果与声明目标逐项等价核对 | `NotEquivalent`（含结构/对象/链接位置） |

## 三类失败的边界与固定优先级

判定顺序固定为：**差异记录自身不自洽 → 前提环境不满足 → 结果不等价**，
命中靠前的类别后不再继续后续判定。理由：

1. **自洽性优先**：阶段一只读取差异记录本身，不依赖任何外部环境。
   若差异记录自身都不可信（变化前状态自相矛盾、结构/实例顺序错位、
   声明目标与被触及投影不完备对应），则以其为前提的一切后续判定
   都没有意义，必须最先排除。
2. **前提环境其次**：只有当差异记录自身可信时，“它依赖快照提供什么”
   才是良定义的。阶段二把阶段一收集到的全部依赖（`assumption` 列表）
   逐条与快照核对：被更新对象在快照中不存在、快照中取值与声明的变化
   前状态不一致等，都属于**重放环境与差异记录产生时的环境不一致**。
3. **等价性最后**：只有差异记录可信且前提环境满足，重放才能执行，
   此时才谈得上比较重放结果与声明目标。

两阶段边界规则：**凡不读快照即可判定的问题归为差异记录自身不自洽；
凡必须读快照才能判定的问题归为前题环境不满足**。例如“更新一个快照中
不存在的对象”——差异记录本身形式完好，是环境缺失，故属第二类；
而“同一差异记录中后一条更新声明的变化前状态与前一条推出的状态矛盾”
不读快照即可判定，故属第一类。

重放期（阶段三）发现的失败（如新建链接违反当前已生效的基数约束）
说明差异记录声明的变化无法组合成合法状态，此时前提环境已确认满足，
故归类为 `DeltaInconsistent`，不与前两阶段冲突。

## 关键取舍

1. **声明目标 = 被触及投影，而非全量状态**。`DeclaredTarget` 只声明被
   差异记录触及的类型/对象/链接的终态（`nil` 表示终态不存在）；未被
   触及的部分由重放语义保证与快照逐字节一致（覆盖层只写被触及条目），
   无需声明也无需核对。这是“校验开销与快照未触及部分无关”的前提。
   代价：差异记录格式对声明目标有完备性要求（多报、漏报均判不自洽）。
2. **写时复制覆盖层重放，而非整体深拷贝**。`replayState` 只把被触及
   条目复制进覆盖层，读取回退快照。原始快照零修改、每次校验独立覆盖层，
   天然并发安全且确定。
3. **约束计数依赖构造期索引**。`NewSnapshot` 建立 `(链接类型,端点)→计数`
   索引（一次性、不属于校验开销），重放时以“快照索引 + 覆盖层增量”
   做 O(1) 基数约束核对，避免全量扫描链接。
4. **实例合法性只在重放时、基于当前已演化结构核对**。结构层变化应用
   之前不对相关实例做任何先行校验；结构层变化生效后，后续实例变化
   必须按新结构（含新增约束）重新核对，不采信任何先行结论。
5. **顺序规则严格化、绝不代为纠正**：对同一类型名，结构层变化必须先于
   所有相关实例层变化（按“每类型首个实例变化下标 < 最后一个结构变化
   下标”判定），违反即整体拒绝，不重排。
6. **不允许部分重放**：阶段一、二全部通过后才进入重放；差异记录前段
   合法、后段不自洽时整体拒绝，快照不受任何影响。

## 被放弃的方案

- **全量状态哈希比对**（差异记录只带目标状态哈希，重放后哈希全量状态
  比对）：哈希计算必须遍历全部对象与链接，违反复杂度要求，放弃。
- **整体深拷贝快照后重放**：时间与内存均随快照全量增长，违反复杂度
  要求，放弃（仅朴素参照模型采用，用于对照）。
- **校验组件自动调整结构/实例顺序**：题面明确禁止代为纠正，放弃。
- **在前提校验阶段对实例做约束先行校验**：违反“结构变化应用前不得
  先行校验、应用后必须重新核对”的要求，放弃；约束核对只发生在重放期。
- **对未触及实例做结构演化级联校验**（如删除类型时扫描全部存量实例）：
  随快照规模增长，违反复杂度要求，放弃；等价结论因此严格限定在
  “被触及投影 + 未触及部分不变”的语义上。

## 复杂度论证与可复核方式

设差异记录含 `m` 条变化、触及 `t` 个实体。各阶段工作量：

- 阶段一：每条变化 O(1) 投影操作，顺序核对按类型名聚合 O(m)，目标
  完备性 O(t)；
- 阶段二：每条假设 O(1) 次快照读取，合计 O(m)；
- 阶段三：每条变化 O(1) 次覆盖层读写与 O(1) 次索引查询，合计 O(m)；
- 阶段四：仅比较被触及的 `t` 个实体，O(t)。

均与快照中未被触及的对象/链接总数无关。可复核方式有二：

1. **计数复核**：校验对快照的一切访问经 `snapshotView` 计数，
   `Verdict.Stats` 返回读取次数。`TestCostIndependentOfUntouched`
   断言未触及规模 0 → 100000 时 Stats 完全一致。
2. **基准复核**：`BenchmarkValidateScaling` 在未触及规模
   100 / 10000 / 1000000 下耗时近似恒定。

## 测试与本地验证

```bash
# 全量测试（含竞态检测）
go test ./... -race -count=1

# 复杂度基准
go test ./replay/ -bench BenchmarkValidateScaling -run XXX
```

测试覆盖（`replay/*_test.go`）：

- 专项：结构/实例顺序错位、快照缺失被依赖对象、变化前状态与环境不符、
  结构/对象/链接三个层面各自单独不等价、声明目标要求实体不存在、
  约束新增与依赖实例紧邻（含快照中本无该链接类型、收紧存量约束后
  重新核对）、不允许部分重放、反复校验结果一致、并发调用结果一致且
  快照不被修改、三类失败的固定优先级。
- 差异对照：`naive_test.go` 为按规则逐步独立判定的朴素参照模型
  （整体深拷贝重放、全量扫描计数）；`differential_test.go` 在 3000 组
  随机快照与差异记录（含故障注入）上对照双方判定类别与不等价位置，
  并把每次校验的输入、输出与判定依据写入 JSONL 日志
  （路径见测试输出，默认 `$TMPDIR/replaycheck_differential.jsonl`）。
- 复杂度：见上节。
