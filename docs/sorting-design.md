# 快递中转场集袋分拣系统 — 设计说明

## 模块划分

代码位于 `sorting/` 包，按职责拆为四个文件：

| 文件 | 职责 |
| --- | --- |
| `sorting/types.go` | 领域类型：品类、集袋状态、快件、配置、拆袋结果、只读快照 |
| `sorting/errors.go` | 六类可区分错误及其优先级次序 |
| `sorting/bag.go` | 集袋内部表示：聚合计数（件数/总重/品类标记）随加入 O(1) 维护 |
| `sorting/hub.go` | 中转场门面：并发控制、时钟、编号分配、四类写操作与三类只读查询 |

测试侧另有四个文件：`hub_test.go`（规格边界单测）、`model_test.go`（独立朴素模型）、
`fuzz_test.go`（随机对照）、`bench_test.go`（复杂度基准）。

## 关键取舍

### 1. 并发模型：单把 `sync.RWMutex` 实现线性化

所有写操作（加入/封袋/出场/拆袋）在同一把写锁内完成"校验 → 提交"，
天然等价于某个串行顺序，且"封存旧袋 + 开新袋 + 放入快件"无需额外机制即为原子操作。
查询走读锁并返回深拷贝快照（`BagInfo`），调用方持有期间不随场内状态变化，
不可能读到"封袋进行到一半"或"已封存却仍可加入"的中间态。

被放弃的方案：

- 分段锁（按网点/按集袋加锁）：集袋编号全局递增、时钟全局单调、运单号全局唯一，
  这三者都是跨网点共享状态，分段锁仍需一把全局锁兜底，复杂度上升而收益不确定。
- 无锁 CAS 状态机：换袋涉及"改旧袋状态 + 删索引 + 建新袋 + 加索引 + 放件"五步，
  多字段原子提交在无锁模型下需要引入间接层与版本号，正确性风险远高于收益。

### 2. 时钟与编号只在"接受"时推进

每个写操作先按优先级完成全部校验（参数非法 → 时钟回退 → 对象不存在 →
状态不符 → 网点不符 → 业务拒绝），全部通过后才 `commitClock` 推进时钟并修改状态。
因此被拒绝的操作不改变任何状态、编号与时钟，相同操作序列重放得到完全相同的
集袋编号、封袋时机与差异清单。

### 3. O(1) 加入判定

加入快件只依赖三个常量时间结构：

- `openBySite`：目的网点 → 开放集袋（map 查找）；
- `inField`：场内运单号 → 所在集袋编号（map 查找，判重）；
- 开放袋上的聚合计数：件数、总重、是否含易碎/液体，随每次加入 O(1) 更新。

停留时限用 `now - firstAddTime >= DwellLimit` 一次比较完成（恰好满即到时）。
全程不扫描历史集袋与历史快件。可验证证明见下文"本地验证方法"的基准测试。

### 4. 在场语义与拆袋核对

`inField` 记录"已加入且尚未被拆袋确认"的运单号。拆袋时：

- 扫到且在袋内 → 确认离场，从 `inField` 删除，可重新加入；
- 袋内有而未扫到 → 缺失清单，标记待查，仍留在 `inField`，重新加入报重复；
- 扫到而不在袋内 → 多出清单，只记录到集袋快照，不进入 `inField`。

差异清单在拆袋时刻一次性计算并按运单号升序固化到集袋上；
重复拆袋报状态不符，不触碰既有记录。

### 5. 错误模型

`Error{Kind, Reason}` 携带六类错误之一，`ErrKind` 的声明顺序即判定优先级，
各操作实现中校验代码的书写顺序与之严格一致，`KindOf` 供调用方区分。

## 被放弃的方案（汇总）

- 分段锁 / 无锁状态机：见第 1 节。
- 每袋维护运单号有序结构以便拆袋时免排序：袋内件数受件数上限约束，
  拆袋时一次 `sort.Strings` 开销可忽略，有序结构反而拖慢高频的加入路径。
- 用事件溯源重放替代锁：规格要求的是"可重放的确定性结果"，
  串行化执行 + 拒绝不改变状态已经满足，引入事件日志属于过度设计。

## 本地验证方法

```bash
# 单元测试 + 随机对照（含竞态检测）
go test -race -v ./sorting/

# 随机对照日志：打印每步输入、输出与判定依据
go test -run TestRandomAgainstNaiveModel -v ./sorting/

# O(1) 证明：历史规模 1k/1w/10w/100w 下加入耗时基本持平
go test -run=NONE -bench=BenchmarkAddParcelByHistorySize ./sorting/

# 代码检查
gofmt -l . && go vet ./...
```

基准实测（linux/arm64）：history=1k/1w/10w/100w 时单次加入约
427/459/642/412 ns/op，无随历史规模增长的趋势。
