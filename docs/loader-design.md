# 浏览器资源加载调度器 — 设计说明

## 模块划分（loader/ 包，6 个 .go 文件）
- `types.go`：Origin/ResourceType/Priority/State/Config/Status 与五类可区分错误（sentinel + errors.Is）。
- `queue.go`：待调度集合。按（优先级档 × 源）分桶的 seq 有序双端队列；堆索引各源队首。
- `cache.go`：预加载缓存。map[(源,地址)] 一次探测 + 三次标量比较完成命中判定；sweep 产出浪费报告。
- `scheduler.go`：登记/推进/放弃/失败/时钟，单互斥锁串行化，等价于某串行顺序。
- `scheduler_test.go` / `model_test.go`：确定性场景、独立朴素模型随机对照、并发与基准。

## 关键取舍
- 逻辑时钟：每个操作带 `at`，早于当前时钟即“时钟回退”；校验全通过前不改动任何状态（含时钟）。
- 拒绝次序固定为 参数非法 → 时钟回退 → 请求不存在 → 状态不允许，逐条校验天然保证。
- 选择“下一个可开始的请求”会跳过连接已满的源：ready 堆只装有空闲配额的源，
  取堆顶为 O(1)；另设 top 堆（无视配额）专供最高档抢占候选，保证抢占语义不被跳过逻辑遮蔽。
  入堆/调整 O(log 源数)，与待调度请求总数无关（基准：pending=100→100000 时 26.6→13.9 ns/op）。
- 被暂停请求按原登记序插回（insertBySeq），进度保留不回退；恢复从 progress 继续。
- 抢占受害者：同源、有效优先级严格低于最高档、暂停次数未达上限中，优先级最低、同档最晚开始者。
- 附着：非预加载请求键（源,地址）命中“在途”（传输中或已暂停）预加载即附着，共享完成/失败/放弃；
  有效优先级 = max(自身, 所有附着者)，升到最高档的暂停预加载可立即触发抢占（syncTier 换档）。
- 重复预加载（在途或缓存中有同键条目）按参数非法拒绝，绝不覆盖；缓存条目被用即删、超 TTL 未用进浪费报告。

## 被放弃的方案
- 全局队头阻塞（不跳过满源）：实现最简但会让空闲源饿死，且与“下一个可开始”语义不符。
- 单一堆装全部待调度请求：O(log n) 随总数增长，不满足性能约束。
- 暂停请求按暂停时刻重排：违背“按原登记序恢复”的要求。

## 本地验证
- `go test ./loader -race -v`：13 组场景测试 + 3 种子 × 3000 随机操作与朴素模型逐操作全状态对照，
  每步校验每源/全局上限与进度单调；日志打印输入、输出与判定依据。
- `go test ./loader -run xxx -bench .`：证明选择与缓存命中开销不随规模增长。
