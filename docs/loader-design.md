# 资源加载调度器设计说明

## 模块划分（`loader/` 包，7 个实现文件 + 2 个测试文件）
- `types.go`：类型/优先级/状态/错误类别/事件/配置，五类错误可互相区分。
- `request.go`：请求内部状态；预加载用 `As` 声明被预加载资源类型（类比 `<link rel=preload as=...>`），否则“类型匹配”对预加载条目恒不成立。
- `queue.go`：待调度队列。按 5 个优先级分层，每层记录有待调请求的源集合，源内用按登记序的小顶堆。选择开销只随“源数 × 档位”变化，与待调度总数无关（`steps` 计数器可验证）。
- `cache.go`：预加载缓存。键为（来源、地址）的 map，命中判定 O(1)；完成时刻单调，故按 FIFO 队头扫描过期，年龄 > TTL 判浪费。
- `scheduler.go` / `ops.go` / `schedule.go`：登记/放弃/进度/失败/时钟五个入口，单互斥锁串行化，等价于某串行顺序；事件在锁外派发给订阅者（完成通知）。

## 关键取舍
- 拒绝次序固定为参数非法 → 时钟回退 → 请求不存在 → 状态不允许；全部校验通过后才改动时钟、配额、缓存与进度，被拒绝操作是纯的。
- 抢占仅由最高档触发，牺牲者为同源传输中优先级最低、同档最晚开始且暂停次数未达上限者；被暂停请求保留进度，按原优先级与原登记序重新入队。
- 附着：非预加载请求四条件（地址、类型、凭据、完整性，空摘要=空摘要）命中进行中或待调度的预加载时共享其传输，联合优先级取两者较高，升到最高档可抢占；预加载被放弃则附着者以“被放弃”类别失败。附着者主动放弃不回落已提升的优先级（简化取舍）。
- 同一（来源、地址）的预加载在活动或缓存期间重复登记按参数非法拒绝；条目被消费或判浪费后允许再次预加载。
- 浪费判定用“年龄严格大于 TTL”，恰好到期仍存活，便于边界测试。

## 被放弃的方案
- 全局单一堆：无法在 O(1) 内跳过配额已满的源，改为“层内源集合 + 源内堆”。
- 暂停请求直接插回队尾：违反“按原登记序恢复”，改为源内按登记序的堆。
- 每操作都全量扫描缓存判过期：改为利用完成时刻单调性的队头扫描。

## 本地验证
- `go test ./loader -v`：规定场景全覆盖，日志含输入/输出/判定依据。
- `go test -race ./loader`：并发不变量（配额上限、进度不回退）。
- `go test ./loader -run TestModelAgainstRandomOps`：与独立朴素模型对照随机操作序列。
- `go test ./loader -bench .`：选择与缓存命中开销不随规模增长（平坦的 ns/op）。
