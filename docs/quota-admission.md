# 多租户命名空间资源配额准入控制器 — 设计说明

位置：`quota/` 包。本文档记录模块划分、关键取舍、被放弃的方案与本地验证方法。

## 模块划分

- `quota/types.go`：核心数据类型（`PodSpec` / `Defaults` / `QuotaSpec` / `Scope` / `ResourceName`）与参数校验。
- `quota/errors.go`：六类可区分错误及其优先级，`Error` 携带配额名与资源名定位。
- `quota/defaults.go`：默认值补全，补全结果即被记账的值。
- `quota/scope.go`：服务等级与期限属性推导、作用域匹配、配额配置校验。
- `quota/controller.go`：准入、原位调整、删除、配额 CRUD、一致性自检与增量记账。

模块间协作是单向的：`controller` 依赖 `defaults`（补全）与 `scope`（属性与匹配），
`defaults` 与 `scope` 只依赖 `types`，错误统一由 `errors` 构造。

## 语义要点

- 补全：缺省上限取默认上限；缺省请求在已有上限（声明或补全后）时取该上限，
  否则取默认请求；仍缺省则保持缺省。已声明的值不被改变。
  注意推论：当某资源只有默认请求而没有（默认或声明的）上限时，默认请求才生效。
- 服务等级：补全后所有资源的请求量与上限量均缺省或为零为尽力型。
  因此"空 Pod + 非零默认值"是非尽力型。
- 适用性：配额只记账与限制满足其全部作用域的 Pod；空作用域适用全部。
  适用性只取决于 Pod 属性，属性不变则适用配额集合不变——这是增量核算的前提。
- 准入：先核对、后提交。缺失声明核对与超限核对分两轮进行，
  保证缺失声明优先；每轮按配额名升序、资源名升序扫描，第一处失败即返回。
- 原位调整：属性不变时做增量核算（只核对变大的资源）；属性变化时
  从原适用配额释放、对新适用配额全量重新准入。两种路径都全有或全无。
- 不变式：任意时刻 `used[q][r]` 等于其适用 Pod 补全后的 r 量之和，缺省按 0 计。
  `CheckConsistency` 从存储的原始声明出发重新补全、重新判定适用集合并汇总，
  与增量计数逐一比对。

## 关键取舍

1. 缓存补全结果与属性。Pod 创建 / 调整时计算一次 `completed` 与属性并缓存，
   准入路径只访问"适用配额 × 硬上限资源"，与命名空间内 Pod 数量无关。
   自检接口独立重算补全结果，防止缓存腐化（测试证明缓存与重算始终一致）。
2. 增量记账与全量重算两条路径并存。Pod 的创建 / 调整 / 删除走增量路径（O(1)）；
   配额新增 / 修改、默认值变更走全量重算（O(Pod 数)）——这些操作本身可能改变
   每个 Pod 的适用配额集合（如默认值使尽力型 Pod 变为非尽力型），无法增量完成，
   且规格只要求 Pod 准入不随 Pod 数增长。
3. 一把互斥锁串行化全部操作。任意并发调用等价于锁的某个串行顺序，
   用量计数在锁内更新，不会超售。准入临界区极短（微秒级），吞吐不是瓶颈。
4. 错误优先级用固定的校验顺序实现。每个操作按
   参数非法 → 命名空间不存在 → 重复创建 → 非法配置 →（准入）缺失声明 → 额度超限
   的顺序检查，先命中先返回。为此把配额校验拆成参数层（`validateQuotaParams`）
   与语义层（`validateQuotaConfig`），让"重复创建"能插在两者之间。
5. 更新路径的缺失声明核对是全量的。即使属性未变，只要适用配额限制了
   `requests.X` / `limits.X` 而调整后该资源缺省，即拒绝（缺失声明）。
   理由：配额限制某资源意味着其下的 Pod 必须声明该资源，否则记账语义被架空；
   规格中"没有变化的资源不核对"约束的是超限核对（增量），不约束缺失声明。
6. 缺省按 0 记账。配额对缺省资源的记账量为 0，使不变式在
   "先有 Pod、后建配额"等场景下依然成立；新建 / 调整准入则用缺失声明错误
   阻止新的缺省 Pod 进入限制该资源的配额。
7. 错误定位只报第一处。同类问题多处时按配额名升序、资源名升序报第一处，
   使失败可复现、可测试。

## 被放弃的方案

- 准入时实时扫描全部 Pod 汇总用量：实现最简单，但违反
  "一次准入的开销不得随已有 Pod 数量增长"的性能要求，放弃。
- 每命名空间一把锁 / 分片锁：能提高跨命名空间并行度，但锁层级与
  自检的全局快照语义冲突，正确性风险大于收益；当前单锁已满足串行化要求，放弃。
- 默认值 / 配额变更时重新准入既有 Pod 并驱逐违规者：规格明确
  "上限下调到低于当前用量时允许，已有 Pod 不被驱逐"，故只重算用量、不驱逐。
- 把缺失声明按 0 参与超限核对：规格要求缺失声明是独立错误类别且
  优先于超限，放弃。
- 无锁原子计数：全有或全无的多配额多资源提交无法用单变量原子操作表达，
  需要复杂的多阶段回滚，放弃。

## 本地验证方法

```bash
# 全部单元测试 + 随机对照测试（竞态检测）
go test -race ./quota

# 查看随机对照测试逐步日志（每次操作的输入、实际输出与判定依据）
go test ./quota -run TestModelDifferential -v

# 性能证明 1：TestAdmissionIsO1 断言 Pod 准入/调整/删除对 Pod 集合的扫描次数为 0
go test ./quota -run TestAdmissionIsO1 -v

# 性能证明 2：基准对比 100 与 10000 个既有 Pod 下的单次准入开销
go test ./quota -run=NONE -bench=Admission -benchmem

# 代码检查
gofmt -l .
go vet ./...
```

## 测试覆盖索引

- 补全各分支：`TestComplete`
- 服务等级与期限：`TestBestEffort` / `TestAttributes`
- 四种作用域组合：`TestScopeMatches`
- 非法作用域配置：`TestQuotaValidation`
- 缺失声明与超限的先后、报告顺序、多配额多资源全有或全无：`TestCreateAdmission`
- 调整时的增减混合：`TestUpdatePod`
- 等级 / 期限变化导致的适用配额迁移：`TestUpdateAttrMigration`
- 配额上限下调后的行为：`TestQuotaLowered`
- 删除释放：`TestDeletePod`；配额 CRUD 与重算：`TestQuotaCRUD`
- 默认值变更重算：`TestSetDefaults`；错误优先级：`TestErrorPriority`
- 并发：`TestConcurrentAdmission` / `TestConcurrentMixed`（配合 `-race`）
- 性能：`TestAdmissionIsO1` / `BenchmarkAdmission`
- 与独立朴素模型在随机操作序列上的逐步对照：`TestModelDifferential`
  （多种子各 300 步，每步比对错误类别 / 定位与全部配额用量，
  并周期性调用 `CheckConsistency`，日志打印每步输入、输出与判定依据）
