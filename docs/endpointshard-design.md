# 服务端点分片维护器 — 设计说明

包路径：`ontology/endpointshard`

## 职责与模块划分

| 文件 | 职责 |
| --- | --- |
| `endpointshard/endpoint.go` | 端点模型与派生条件：就绪 = 健康且非终止中；可服务 = 健康；终止中 = 终止中位 |
| `endpointshard/errors.go` | 可区分的错误类别与优先级（参数非法 > 服务不存在 > 服务已存在） |
| `endpointshard/report.go` | 变更报告、查询结果、只读快照等对外类型 |
| `endpointshard/treap.go` | 泛型有序集合（treap），全部索引的公共底座 |
| `endpointshard/shard.go` | 分片结构与两类分片排序键（落位键、整理键） |
| `endpointshard/service.go` | 单服务核心：同步、整理（删空分片 + 至多一次合并）、查询、容量调整 |
| `endpointshard/manager.go` | 服务生命周期（创建/删除）、参数校验、错误优先级、并发入口 |
| `endpointshard/stats.go` | 索引节点访问计数器，性能可验证性的客观度量 |

协作关系：`Manager` 校验参数并路由到 `Service`；`Service` 持有端点数据的唯一副本，
分片只存端点标识；四个索引（就绪集、回退集、落位索引、整理索引）都建立在
`orderedSet`（treap）上，由变更原语（`removeEndpoint` / `updateEndpoint` /
`placeNew` / `cleanup`）统一维护；`Stats` 被所有索引操作计数，供测试断言。

## 关键规则到实现的映射

- **稳定落位**：`Service.endpoints`（标识→端点）与 `locate`（标识→分片号）分离。
  同步时先按 `locate` 处理移除与内容更新（内容更新只改数据、不动 `locate`），
  再集中处理新增，因此已有端点永不换分片。
- **新增落位**：落位索引以 `(−端点数, 编号)` 为键，最小键即“端点数最多但未满、
  并列编号最小”的分片；索引为空则新建分片（`lastShardID` 单调递增、永不复用）。
  新增端点先按标识字典序排序再依次落位。
- **整理**：先删除本次操作变空的分片（不变式保证空分片只能来自本次移除），
  再从整理索引 `(端点数, 编号)` 取最小两个键，之和 ≤ M 时把编号较大者并入
  编号较小者，至多一次。
- **变更报告**：一次操作内每个分片首次被标记时代次恰好 +1（含新建与被删除），
  报告按分片号升序输出，非删除条目附带操作后的完整内容（按标识字典序）。
- **查询**：就绪索引为空则切到回退索引（可服务且终止中），`Fallback` 标记是否
  发生了回退；中序遍历天然按标识有序，一次遍历按区域分成两组拼接，
  同区域组在前。读锁保证结果是同步前或同步后的完整视图。
- **容量调整**：变大只把“原本恰好满”的分片补回落位索引，不做任何搬移与整理；
  变小先按编号升序处理所有超容分片（各自移出字典序最大的端点），
  修正落位索引中“恰好等于新 M”的分片，再把全部被移出端点按字典序依新增规则
  重新落位，最后整理一次，整体在一次写锁内原子完成。

## 关键取舍

1. **空操作同步跳过整理**。规范要求“同步到与当前完全相同的期望集合，报告为空，
   且不改变任何代次”；但上次整理可能留下仍可合并的布局（每次最多合并一次，
   如 `[2,1]`、M=4）。两者唯一自洽的解读是：期望集与当前完全一致时整个同步
   为空操作，不触发整理。实现据此在“零变更”时直接返回空报告。
2. **代次统一规则**：分片在报告里出现 ⟺ 代次恰好递增一次，被删除的分片也按
   此规则递增后随报告输出其最终代次。新建分片代次从 1 开始。
3. **回退标志的定义**：只要就绪端点一个也没有即视为发生回退（`Fallback=true`），
   即使回退集也为空、结果为空。这让“是否回退”只取决于系统状态而非结果大小。
4. **端点数据单份存储**：分片只存标识集合，端点数据只在 `Service.endpoints`
   存一份，避免多副本不一致；报告与快照在构建时解析标识到数据。
5. **treap 作为唯一索引结构**：插入/删除/取最小元/遍历四种操作期望 O(log n)，
   代码量小且无外部依赖。优先级由固定种子的随机源产生，只影响树的内部形状，
   不影响任何可观察输出，行为精确可复现。
6. **每服务读写锁 + 管理器互斥锁**：服务表由 `Manager.mu` 保护；每个服务的
   同步/调整取写锁，查询/快照取读锁。同一服务上的同步与读取互不交错，
   不同服务之间完全并行；任意并发调用等价于某个串行顺序。
7. **查询不校验区域参数**：规范只对同步（标识/区域非空、标识不重复）与容量
   （正整数）规定了参数非法，查询按未校验处理（空区域只是不匹配任何端点）。
   空服务名在所有操作上按参数非法处理。

## 被放弃的方案

- **全量重算（控制器调和风格）**：每次同步重建全部索引。实现最简单，但开销
  随全部端点与分片线性增长，直接违反增量性能要求，放弃。
- **排序切片 + 二分查找做索引**：查询遍历同样是 O(结果)，但插入/删除需要
  O(n) 的元素搬移，同步开销会随未受影响端点线性增长，放弃。
- **二叉堆做落位/整理索引**：堆不支持高效删除任意分片（计数每次变化都要
  删除旧键），需要懒惰删除 + 定期重建，复杂且有隐藏线性开销，放弃。
  treap 统一解决了四种索引需求。
- **集合哈希（XOR/和）检测移除集**：可以不扫描当前端点集，但只是概率正确，
  与“精确可复现”冲突，放弃。改为利用 |当前集| ≤ |期望集| + |被移除数|
  的事实，扫描当前集的开销已被输入规模覆盖。
- **全局单锁**：实现更简单，但不同服务的操作会互相阻塞；改为每服务锁，
  管理器锁只保护服务表的短暂查找。

## 性能论证与可验证方法

复杂度（n = 端点总数，S = 分片总数，k = 受影响端点数，q = 受影响分片数）：

- 同步：O(|期望集| + k·log n + q·log S)。读取期望输入本身即 O(|期望集|)；
  不变端点只做 O(1) 哈希比较；不扫描未受影响的分片。
  注意 |当前集| ≤ |期望集| + k，移除检测不引入额外维度。
- 查询：O(结果大小)。中序遍历就绪/回退索引，访问节点数恰好等于结果大小。
- 调整：O(超容分片端点数·log n + 被移出端点数·log S)。

可验证性（不依赖计时，避免抖动）：

- `Stats` 统计索引节点访问次数；`TestNoopSyncHasZeroIndexVisits` 断言空操作
  同步的索引访问恰好为 0；`TestSyncCostIndependentOfUnaffected` 断言规模
  从 5 千涨到 5 万（分片数同步放大，M=1）时单端点变更的访问数至多对数增长
  （实测 27 → 31 次）；`TestQueryCostProportionalToResult` 断言查询访问数
  恰好等于结果大小。
- 计时侧证：`go test ./endpointshard -bench . -benchmem` 中
  `BenchmarkSyncSingleEndpointChange` 的增长来自读取期望输入本身，
  `BenchmarkQuery` 与结果大小成线性。

## 本地验证方法

```bash
# 全量测试（含竞态检测；测试日志打印每次操作的输入、实际输出与判定依据）
go test ./... -race -v

# 只看随机对照与性能证据
go test ./endpointshard -run 'TestRandomized|TestNoop|TestSyncCost|TestQueryCost' -v

# 基准
go test ./endpointshard -bench . -benchmem

# 静态检查
gofmt -l . && go vet ./...
```

正确性由三层保障：针对每条规则的确定性单元测试；`model_test.go` 中独立
朴素模型（字面执行规则、全量扫描、无任何索引）与优化实现在多种子、数千步
随机同步/调整/查询/非法操作序列上的逐步对照（报告、查询结果、完整快照逐项
相等）；`-race` 下的并发测试校验查询不变式与最终一致性。
