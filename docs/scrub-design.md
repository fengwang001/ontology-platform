# 多副本块存储：后台校验巡检与修复仲裁 —— 设计说明

## 1. 目标与范围

为 2~5 副本块存储提供“巡检 → 仲裁 → 修复 → 记录/告警 → 到期调度”的闭环，
使每一次巡检都能被精确复现：**修了什么、没修什么、为什么**。

代码分为三个职责单一的模块：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 纯仲裁 | `scrub/arbitrate.go` | 给定副本快照，判定自洽性、已提交版本、权威、修复目标与终局；无副作用 |
| 到期索引 | `scrub/dueindex.go` | 以 `(到期时刻, 块号)` 为键的 treap，支持只随到期块数增长的枚举 |
| 服务核心 | `scrub/store.go` | 时钟、间隔、告警、外部事件注入、巡检修复流程与并发串行化 |

另有独立参考实现 `scrub/naivemodel/naive.go`，用于随机对照。

## 2. 核心判定规则（`Arbitrate`）

输入为某块当前全部副本（位腐副本同样计入），输出为纯值 `Arbitration`：

1. `quorum = n/2 + 1`（整数除法语义即向下取整）。
2. 全部副本版本降序排列，第 `quorum` 个版本即**已提交版本**。
3. 只在自洽副本（`SavedDigest == ActualDigest`）中选来源：
   - 无自洽副本 → `no-available-source`；
   - 自洽最大版本 `< 已提交版本` → `committed-data-lost`；
   - 自洽最大版本下出现不同 `SavedDigest` → `version-conflict`；
   - 三类按此次序**只报第一个**，且不修改任何副本。
4. 否则 `(最大自洽版本, 该版本唯一摘要)` 即权威：
   - 位腐副本（无论版本高低）与自洽但版本落后的副本都进入修复目标；
   - 没有修复目标 → `no-repair-needed`，全部成功 → `repaired`，
     存在失败 → `partial-repair`。

**向前提交**：最大自洽版本高于已提交版本（未完成的写入只要自洽且不冲突）
照常成为权威，其余副本前滚——这正是“提交与否由仲裁推断”的含义。

“没修什么、为什么”被结构化地保留在返回值里：`CommittedVersion`、
`AuthorityVersion/Digest`、每个 `RepairTarget` 的 `Node` 与 `Kind`
（`bitrot` / `stale`），加上 `Repaired` / `FailedNodes`。

### 关键取舍

- **仲裁做成无状态纯函数**。所有判定只依赖副本快照，测试可直接构造场景，
  也天然保证“巡检期间的并发写不可能被看到一半”（见第 5 节）。
- **位腐副本按权威无条件重写**，即使其版本号恰好等于或高于权威版本：
  版本元数据可信，但内容已腐，不能作为来源，只能被覆盖。
- **摘要冲突只在“最大自洽版本”这一层判定**。低版本的历史分叉副本被标记
  `stale` 前滚即可，不算冲突——它们本来就不该参与权威选取。

## 3. 时钟、间隔与拒绝次序

时间由调用方注入的单调逻辑刻度 `Time`（可理解为秒）。服务维护
`clock = 上一次被接受操作的时刻`。四类错误严格按以下次序，只报最前者：

1. 参数非法（`ErrInvalid`）
2. 时钟回退（`ErrClockBack`，`at < clock`；相等允许）
3. 块不存在（`ErrNotFound`）
4. 过于频繁（`ErrTooFrequent`，巡检专有：已巡检过且
   `at < lastPatrol + minInterval`；恰等于间隔允许）

**事件注入类操作（建块/写/位腐/丢弃）同样参与时钟**，因此时钟反映
“上一次被接受的操作”，而不仅仅是上一次巡检——任何带时刻的调用都不能回退。
`Due` 只读但也做时钟检查，不推进时钟。

被拒绝的操作不改变任何状态、不推进时钟、不记录巡检时刻、不产生告警。
成功完成、部分修复与三类不可修复的巡检都记录巡检时刻并刷新到期索引；
三类不可修复同时向追加式告警列表写入一条告警，同一块重复告警不合并。

## 4. 到期选取与复杂度

### 排序规则

到期 = 从未巡检，或 `t >= lastPatrol + minInterval`。返回顺序：

1. 从未巡检块优先（块号升序）；
2. 其余按上次巡检时刻从早到晚；
3. 时刻并列取块号小者；
4. `limit` 截断。

### 数据结构

朴素地每次线性扫描全部块违反题设复杂度要求。`dueIndex` 用随机优先级
**treap** 维护键 `(dueAt, blockID)`（中序即升序）：

- `upsert/remove`：期望 `O(log n)` 次键比较（每个块另有一个 map 定位旧键）；
- `enumerate(t)`：中序走 treap，对**每个被访问的键恰好做一次** `dueAt > t`
  比较，沿左右指针的推进不产生键比较。一旦遇到第一个 `dueAt > t` 即停止。
  因此枚举比较次数 = 到期条目数（再多加 1 次边界比较），**与块总数无关**；
- 从未巡检块的 `dueAt` 固定为 0，天然排在键序最前。

`Due` 枚举到期条目后，在内存里只对到期集合做排序
（`O(d log d)`，`d = 到期块数`）以应用“从未优先 / 上次巡检升序 / 块号决胜”，
排序代价只随到期集合与返回数量增长。

### 可验证的证据

`dueIndex` 内部对唯一的键比较入口计数，经测试钩子暴露。
`TestDueComparisonsIndependentOfTotal` 构造“5 个到期 + 其余全部远期”
的存储，在总块数 100 与 50000 两种规模下测量枚举比较次数：

```
due enumeration: k=5 comparisons=6 at N=100 and N=50000 (identical)
```

两次完全相同且等于 `k+1`，直接证明枚举不随块总数线性增长。
仲裁的 `O(副本数)` 由代码本身保证：除对该块副本切片排序外无任何遍历，
不触碰其他块。

### 被放弃的方案

- **最小堆 + 惰性删除**：可以取最早到期块，但实现“枚举全部到期且不弹出”
  时需要不断 peek/pop 再放回，且“从未优先、再按 lastPatrol 排序”的输出序
  与堆序不一致，仍需二次排序；统计比较次数也更难给出干净界。treap 的
  中序枚举给出恰好 `d(+1)` 的可验证比较界，故胜出。
- **两套有序集合（从未/已到期分开）**：输出顺序更直接，但巡检会让块在
  两个集合间迁移，维护两套树增加一致性面，收益不足以抵消复杂度。

## 5. 并发与“不被看到一半”

服务用**单一互斥锁**串行化全部方法。这是刻意的取舍：

- 仲裁与随后的修复写发生在**同一个临界区**里（先对副本快照做纯仲裁，
  再就地改写目标副本），因此并发的 `Write` 要么在该临界区之前整体生效，
  要么在之后整体生效，仲裁读到的永远是某个串行时刻的完整状态。
- 锁持有期间没有 IO 等待（修复写失败由调用方通过 `writeFail` 集合注入，
  是纯内存判定），所以单锁不会阻塞在慢节点上。
- 全局可线性化，`go test -race` 下并发测试无数据竞争
  （`TestConcurrentWritesAndPatrolsSerializability`、
  `TestConcurrentClockMonotonic`）。

被放弃的方案：每块一把锁 + 全局锁保护索引/时钟。在存在跨块的时钟与告警
次序约束时，细粒度锁需要额外的定序协议；而当前所有关键段均为纯内存操作，
单锁已经满足吞吐要求，简单且可证明正确。

## 6. 外部事件注入

- `Write(at, block, version, digest, nodes)`：在给定节点写入同一新版本，
  三个字段同时落地（版本、保存摘要、实际摘要），天然自洽；节点副本此前
  被丢弃则重新创建。不要求法定数——提交与否留给仲裁推断。
- `Rot(at, block, node, corruptDigest)`：只改实际摘要模拟位腐；
  目标节点不存在或新摘要等于保存摘要视为参数非法。
- `Discard(at, block, node)`：删除副本；法定数与已提交版本在下一次仲裁时
  按**当前副本数**重新推断。剩 1 副本仍可巡检（quorum=1）；剩 0 副本时
  块整体消失并从到期索引移除。

## 7. 测试策略与本地验证

`go test ./scrub/...`（建议加 `-race -v`）包含：

- 定向用例（`scrub_test.go`、`store_test.go`）：2~5 副本法定数、
  已提交版本恰等于/低于最大自洽版本、最高版本全位腐、同版本不同摘要、
  未提交向前提交、修复部分失败（含“全部目标失败”）、间隔恰等于与小一秒、
  从未巡检选取次序与并列决胜、丢弃后法定数下降到 2/1/0、
  各类拒绝不留痕、错误次序、告警不合并。
- 随机对照（`scrub_diff_test.go`）：7 个固定种子、每条约 400 个操作，
  与独立朴素模型逐操作比对终局、法定数、已提交版本、权威、修复集合、
  全部块副本状态、告警序列与错误类别。
- 复杂度（`complexity_test.go`）：比较计数在 N=100/50000 下恒为 6。
- 并发（`concurrent_test.go`）：竞态检测 + 串行顺序不变量。

对照日志逐行打印每条操作的输入、两侧输出与判定依据，默认落在
`${TMPDIR}/scrub-diff-logs/seedN.log`，可用 `SCRUB_DIFF_LOG=<目录>`
重定向。

本地验证：

```bash
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache   # 按本机环境
go test -race -v ./scrub/...
go vet ./...
gofmt -l scrub
```
