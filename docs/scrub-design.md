# 多副本块存储巡检与修复仲裁服务 — 设计说明

实现位于 `scrub/` 包，独立朴素模型位于 `scrub/naive/`，本文档记录关键取舍、
被放弃的方案与本地验证方法。

## 模块划分

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 公共类型 | `scrub/types.go` | 副本、巡检结果、告警、六类结果枚举、四类哨兵错误 |
| 仲裁器 | `scrub/arbitrate.go` | 纯函数 `Arbitrate`：自洽判定、已提交版本推断、权威选取、修复目标计算 |
| 到期索引 | `scrub/heap.go` | 索引堆 `dueHeap`，支撑不按块总数线性增长的到期选取 |
| 服务编排 | `scrub/service.go` | 时钟、频率限制、修复写入（含失败注入）、告警、并发串行化 |
| 朴素模型 | `scrub/naive/naive.go` | 语义相同的最直白实现，用于差分对照 |

仲裁器不触碰服务状态，输入是副本快照、输出是判定（`Verdict`），因此
"修了什么、没修什么、为什么" 可由输入快照完整复现；服务层只负责
前置检查（参数 → 时钟 → 存在 → 频率）、应用判定与记账（巡检时刻、告警）。

## 关键语义与取舍

- **已提交版本**：全部副本（含位腐）版本号降序的第 `Quorum(n)` 个，
  `Quorum(n) = n/2 + 1`。版本号元数据可信，因此位腐副本也参与排序。
- **仲裁次序**：无自洽副本 → `NoSource`；自洽最大版本低于已提交版本 →
  `CommittedDataLost`；最大版本自洽副本摘要冲突 → `VersionConflict`；
  否则该摘要为权威。三类不可修复只报第一个命中者，互不修改副本。
- **修复目标**：全部位腐副本（即使其版本高于权威版本，修复后版本回落到
  权威）以及版本低于权威版本的自洽副本。高于已提交版本的未提交写入
  只要自洽且不冲突即按权威处理（向前提交）。
- **部分修复**：写失败节点由调用方按节点注入；失败副本保持原状，
  成功副本立即自洽；全部失败同样记为 `PartialRepair`。
- **时钟**：所有改变状态的操作携带时刻；时刻小于上一次被接受操作的
  时刻即报 `ErrClockRegression`（相等允许）。被拒绝的操作不推进时钟、
  不改变任何状态。`SelectDue` 只读：受时钟回退检查但不推进时钟。
- **频率限制**：距上次已记录巡检严格小于间隔才拒绝，恰等于允许；
  从未巡检的块不受限。成功、部分修复与三类不可修复都记录巡检时刻。
- **告警**：仅三类不可修复产生告警，追加到有序列表，同块重复不合并。
- **错误优先级**：参数非法 > 时钟回退 > 块不存在 > 过于频繁，
  只报次序最靠前的一类（`errors.Is` 可区分）。
- **并发**：单一互斥锁串行化全部操作。巡检的仲裁与修复在同一临界区内
  完成，因此并发的新版本写入要么完全在仲裁之前、要么完全在之后生效。

## 到期块选取的复杂度证明

`dueHeap` 以 `nextDue = lastScrub + minInterval` 为键（未巡检块为
`math.MinInt64`，恒最先到期），每块常驻一个条目，创建/巡检/丢弃时
以 `O(log n)` 就地更新。`SelectDue(now, limit)` 循环弹出堆顶直到
`key > now`：弹出次数恰为已到期块数 `d`，随后对弹出的 `d` 个条目按
（未巡检优先、lastScrub 升序、块号升序）排序取前 `limit` 个，再把弹出
条目放回堆。总开销 `O(d log n + d log d)`，只随已到期块数与返回数量
增长，与块总数 `n` 无关（仅带对数因子）。

可验证方式：`BenchmarkSelectDue` 固定 16 个到期块，块总数取
1k / 10k / 100k，单次选取耗时与分配次数基本持平（实测约 2.5–3.5 µs、
恒 8 次分配），即不随块总数线性增长。

## 被放弃的方案

- **全量扫描选取到期块**：实现最简单（朴素模型即采用），但开销随块总数
  线性增长，不满足约束，仅保留为对照实现。
- **以 `lastScrub` 直接作堆键**：排序规则要求按上次巡检时刻，但到期
  判定是 `lastScrub + interval <= now`，各块间隔不同时按 `lastScrub`
  排序无法在堆顶停顿时保证更深无到期块。故堆键用 `nextDue`，最终展示
  顺序在弹出集合上另行排序。
- **懒删除堆（陈旧条目跳过）**：免去索引维护，但陈旧条目使堆大小与
  弹出开销随历史操作数漂移，复杂度证明变弱；改用索引堆 `O(log n)` 精确
  更新/删除。
- **读写锁（RWMutex）**：巡检包含修复写入，读锁无法覆盖；且 `SelectDue`
  的弹出-放回会暂时变更堆结构。统一互斥锁换取简单且可证明的串行化。
- **写失败按副本逐个注入错误值**：与"按节点注入"等价但接口更啰嗦；
  节点编号已足以定位副本。

## 本地验证方法

```bash
# 单元测试（法定数、已提交版本边界、位腐、冲突、向前提交、部分修复、
# 间隔边界、选取次序、法定数下降、拒绝不留痕、并发）
go test ./scrub/ -v

# 随机差分对照：真实实现 vs 朴素模型，逐条打印输入/输出/判定依据
go test ./scrub/ -run TestDifferentialRandomOps -v

# 竞态检测
go test -race ./...

# 复杂度证据：选取开销不随块总数增长
go test ./scrub/ -run xxx -bench SelectDue -benchmem

# 静态检查
gofmt -l . && go vet ./...
```
