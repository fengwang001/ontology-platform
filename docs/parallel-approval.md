# 行政许可并联审批设计说明

## 模型

- 日序号是整数；`Calendar` 保存排序后的非工作日集合。
- 无前置环节在受理当日启动；有前置环节在全部前置实际通过时刻的最大值当日启动。
- 时限从启动日的下一个工作日起算。若剩余 `n` 个工作日，届满日是起算工作日序列中的第 `n` 个工作日；届满当日仍可办结。
- 补正通知记录当前计时段已用工作日：启动后的第一工作日至通知日之间的工作日数。通知日若是工作日，当日计入已用。
- 补正期限从通知日次日起数固定个工作日。最后一日提交有效；晚于该日提交前，目标链结算会把环节定为不通过，生效时刻为补正届满日的下一工作日。
- 补正提交后的当前计时段起点是提交日；从提交日的下一工作日继续消耗暂停时剩余的时限。
- 自动通过环节在届满日后的第一个工作日、第一次有效命令触及目标链时通过；通过时刻即该工作日。
- 非自动通过环节超时后仍保持办理中，只设置不可清除的超时标记；办结后结果按人工结果记录。

## 终局规则

- 所有环节已通过时为 `准予许可`，终局时刻为最后通过时刻。
- 任一环节不通过时，尚未启动的后继立即终止；失败当时已办理中的并行环节继续，可通过或不通过，但不能改变结论。
- 为兼容“并行环节继续办理”和“任一环节不通过终局为不予许可”，系统在仍有并行在办环节时先保持非终局；最后一个在办并行环节停止后，终局为 `不予许可`。
- 申请人终局前可撤回。撤回时未启动、办理中、补正中环节均标记为已撤回；已通过或不通过的结果保留。
- 终局后所有办理、补正和撤回均返回 `状态不允许`。

## 状态与历史查询

正式状态记录不可变事件：

- `start`
- `pass`
- `auto_pass`
- `fail`
- `request_correction`
- `submit_correction`
- `correction_expired`
- `terminate`
- `withdraw`

事件同时包含业务生效时刻 `At` 和操作记录时刻 `Recorded`。历史查询只重放 `At <= 查询日` 且 `Recorded <= 查询日` 的事件，然后投影查询日之前必然已经发生的自动通过、补正逾期和后继状态。投影不修改服务状态。

`QueryStage` 返回状态、剩余工作日、超时标记、启动/通过/不通过时刻和补正期限。`QueryProgress` 区分：

- 未启动
- 办理中
- 补正中
- 已通过
- 不通过
- 已撤回
- 因他环节终止而未启动

## 并发

- 许可类型 map 由 `sync.RWMutex` 保护，受理使用写锁，命令查找使用读锁。
- 每件许可有独立互斥锁；命令获取锁后完成校验、时钟推进、结算和状态迁移。
- 当前日使用 `atomic.Pointer[int]`。拒绝命令在校验阶段返回，不推进时钟，也不写事件。
- 同一件许可上的并发命令按拿锁顺序形成一个合法串行顺序；不同许可互不阻塞。

## 错误优先级

按下列顺序返回第一个错误：

1. `参数非法`
2. `时钟回退`
3. `许可或环节不存在`
4. `状态不允许`
5. `无权限`
6. `前置环节未通过`
7. `补正次数超限`

测试中直接构造已启动但前置未通过的非法快照，以单独验证第 6 类错误；正常 DAG 中该情况通常先表现为未启动，即状态不允许。

## 复杂度

设非工作日集合大小为 `H`，许可环节数为 `V`。

- 日历查询使用排序数组和二分查找，复杂度 `O(log H)`。
- 命令只锁定和处理目标许可，结算只沿目标环节的后继链传播，复杂度为 `O(V log H)`；多数 DAG 中是 `O((链长 + 出边) log H)`。
- 查询只 map 定位目标许可，然后重放该许可事件，不枚举其他许可。
- 因此时限判定和超时默认处理的主成本不随同时在办许可总数 `N` 增长。

`BenchmarkQueryOneLicense` 分别构造 100 与 1000 件许可，只查询 `license-0`。10 倍许可数下单次查询耗时保持同量级；这不是形式证明，而是对代码路径和复杂度结论的可重复验证。可运行：

```bash
GOCACHE=/tmp/ontology-gocache /usr/local/go/bin/go test -run '^$' \
  -bench BenchmarkQueryOneLicense -benchtime=1000x ./approval
```

## 放弃的方案

- **全局定时扫描**：实现简单，但每次判定可能扫描所有许可，成本随 `N` 增长；已放弃。
- **全局许可大锁**：并发结果容易正确，但不同许可也互相阻塞；改为每件许可一把锁。
- **查询时修改当前状态来实现自动通过**：会让读操作产生副作用，也破坏重放；改为命令写事件、查询只读投影。
- **只存当前状态**：无法回答双时间历史；改为追加事件并在查询时重放。
- **把超时作为立即调度任务**：整数日和非工作日下仍需补偿任务；改为触及目标链时按日历确定性结算。

## 本地验证

```bash
/usr/local/go/bin/gofmt -w approval
GOCACHE=/tmp/ontology-gocache /usr/local/go/bin/go test ./...
GOCACHE=/tmp/ontology-gocache /usr/local/go/bin/go test -race -v ./approval
GOCACHE=/tmp/ontology-gocache /usr/local/go/bin/go vet ./...
```

朴素模型对照测试使用固定随机种子 `1633`，执行 300 步随机人工办理、补正和历史查询。每一步通过 `t.Logf` 打印输入、输出和判定依据；运行 `-v` 可查看完整日志。
