# 在途库存调拨设计说明

## 模块划分

- `transfer/types.go`：领域类型、调拨单状态、输入行与只读视图。
- `transfer/errors.go`：统一失败类型、错误类别和可区分状态错误。
- `transfer/ledger.go`：库存原语，只负责仓库可用/冻结、单行在途、短缺、累计盈余和守恒核验。
- `transfer/system.go`：业务编排，负责参数校验、时钟、状态机、原子事务边界、并发锁和快照复制。
- `transfer/*_test.go`：边界用例、并发屏障测试，以及独立编写的朴素模型随机差分测试。

## 状态与库存流

调拨单状态为 `created -> shipped -> closed`，`created` 可转入 `canceled`，终态不可逆。

- 创建：逐行预检源仓可用量；任一不足则不写任何库存或单据。全部通过后才逐行从可用转入冻结。
- 取消：仅 `created` 可取消，将冻结量完整释放回源仓可用量。
- 发出：仅一次；冻结量离开源仓，进入“单据号 + 行下标 + 商品”的单行在途账。
- 收货：仅 `shipped` 可收；累计收货量不得超过 `发出量 + floor(发出量 * 千分比 / 1000)`。
- 关闭：所有行收齐可提前关闭；否则要求 `at - shippedAt >= WaitDuration`。
- 找回：仅关闭后可做，减少该行当前短缺并增加目的仓可用量。

## 守恒模型

对任一商品，任何已提交状态满足：

```text
全网可用量 + 全网冻结量 + 在途量 + 当前短缺
= 初始化总量 + 累计超收盈余
```

实现中的关键取舍是：在途按单据行独立保存，而不是按商品维护一个全局数字。收货超出该行发出量时，超额立即计入目的仓和全局累计盈余；该商品其他单据的在途不会冲抵本单超收，关闭时也不重复登记盈余。

关闭时只做两类差异落账：

- `shipped > received`：剩余单行在途转为短缺，不回源仓。
- `received > shipped`：行视图登记盈余；全局盈余已经在超收发生时入账，因此关闭不重复增加。

事后找回把短缺转入目的仓可用量，等式两边都减少短缺并增加可用，总量仍守恒。

## 并发与快照

所有写操作在同一把 `sync.RWMutex` 写锁下完成“校验 + 状态修改 + 时钟推进”。拒绝操作在校验阶段直接返回，不写入状态或时钟，因此每个并发交错都等价于某个全操作串行顺序。

查询使用读锁，并复制出库单行视图返回。调用方不会持有内部切片或结构体，因而不会读到创建过程中冻结到一半的中间状态。

## 复杂度

设调拨单行数为 `k`：

- 创建、取消、发出、关闭：`O(k)`。
- 单行收货、找回：`O(1)`，只访问目标行及其单行在途账。
- 单据查询：`O(k)`。
- 单仓单品库存查询：`O(1)`。

收货、关闭、找回不扫描调拨单集合、仓库集合或商品集合。关闭固定遍历目标单据的 `k` 行；收货和找回通过 `map[OrderID]*order` 找到单据，再访问固定下标，库存和在途均通过复合键直接定位。

`VerifyConservation` 是显式审计功能，复杂度故意与全网规模成比例；它不属于收货、关闭或找回路径。全网累计差异使用 `math/big.Int`，避免多笔累计差异溢出；单笔仓库数量仍由 `uint64` 表示，入仓前执行安全加法预检。

## 拒绝优先级

每个操作严格按以下顺序判定：

1. 不需要访问状态的参数非法。
2. 时钟回退。
3. 调拨单不存在。
4. 行下标非法（收货、找回）。
5. 状态不符。
6. 业务拒绝：库存不足、超收、未到关闭时刻、无短缺或找回过量。

状态错误分为 `already_shipped`、`not_shipped`、`already_closed`、`already_canceled`，取消不同状态的单据可以区分。库存不足错误携带最小不足行下标。

## 被放弃的方案

- **按商品维护全局在途量**：实现更短，但会把同商品其他单据的在途错误地用于抵消本单超收，破坏单行差异语义，故放弃。
- **每行一把锁 / 分仓锁**：可提升写并发，但需要多对象锁排序或事务协调，复杂度和死锁风险更高；当前需求更强调可证明的串行等价和原子创建，单把写锁更直接可靠。
- **关闭时才把超收计入全局盈余**：超收发生后到关闭前会暂时破坏守恒等式。实现选择在超收发生时立即入全局盈余，关闭只固化行视图。
- **让查询暴露内部结构体**：可减少复制，但调用方可能与后续写操作形成数据竞争，也无法保证快照一致性，故返回拷贝。

## 本地验证

```bash
go test ./...
go test -race ./...
go test -v ./transfer
go vet ./...
gofmt -d .
```

若环境中的 Go 不在默认 `PATH`，可使用：

```bash
PATH=/usr/local/go/bin:$PATH GOCACHE=/tmp/go-cache go test ./...
```

随机测试固定种子，可完全重放。普通成功测试不输出审计日志；使用 `-v` 时可看到每一步输入操作、输出类别、判定依据、两边守恒结果以及每个种子的最终对照结论。若某一步失败，测试框架会保留并展示该种子截至失败点的完整审计轨迹。
