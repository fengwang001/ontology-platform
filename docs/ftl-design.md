# 闪存转换层（FTL）设计说明

`ftl` 包实现闪存转换层的映射、垃圾回收与磨损均衡服务。本文档记录
模块划分、关键取舍、被放弃的方案与本地验证方法。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `ftl/config.go` | 几何与策略参数（块数、页数、水位、寿命、磨损阈值）及合法性校验 |
| `ftl/errors.go` | 三类可区分错误：参数非法、未写入、空间耗尽 |
| `ftl/block.go` | 擦除块与页状态（空闲/有效/失效）、顺序编程游标、物理地址 |
| `ftl/heap.go` | 通用最小堆及四类选择键（空闲块、受害块、冷块、擦除极值） |
| `ftl/ftl.go` | 核心服务：写入/读取/丢弃、准入、垃圾回收、磨损均衡、退役、统计 |
| `ftl/ftl_test.go` | 单元测试：水位边界、并列裁决、退役、准入收紧、统计守恒等 |
| `ftl/model_test.go` | 独立朴素逐页模型 + 随机操作逐条对照（含日志）+ 确定性重放 |
| `ftl/scale_test.go` | 复杂度可验证性测试与并发测试 |

## 关键设计

### 不变式

- 任一时刻至多一个部分编程的块（活动块）；非活动块只会是空闲、
  写满或退役三种形态之一。受害块与冷块因此只需在"写满块"中选取。
- 页只能按页号递增编程：`nextFree` 单调前进，整体擦除后归零。
- 各块有效页数之和 == 已映射逻辑页数 == 映射表长度（测试逐步断言）。

### 选择结构：堆 + 惰性删除

空闲块、受害块、冷块、擦除次数极值分别用最小堆维护，键严格对应
规格裁决顺序（如受害块：有效页数 → 擦除次数 → 块号）。状态变化时
压入新快照，过期快照在到达堆顶时才丢弃（惰性删除）。于是：

- 受害块选取为 O(log B)，不随块总数 B 线性增长；
- 不触发回收的写入只有 O(1) 次哈希表操作与 O(1) 次堆压入，
  与块总数、映射条目数均无关。

两条性质用计数器测试直接证明（见下"本地验证"）。

### 窥视而非弹出

受害块/冷块堆顶的有效候选只窥视不弹出。若回收中途因空闲页不足
（如块退役）而停止，该块仍保留在堆中可被下次选中；`reclaim` 内
逐页失效会维护最新快照。这是模型对照测试暴露并修复的真实缺陷：
弹出后回收失败会让该块从堆中永久丢失。

### 准入与错误次序

写入未映射逻辑页时，若 `已映射数+1 > (未退役块数-低水位)×每块页数`
则报空间耗尽，且不改任何状态、不触发回收；覆盖写不受限。所有操作
先校验参数（参数非法），再查映射（未写入），最后才考虑空间
（空间耗尽），只报次序最靠前的一类。

### 垃圾回收与磨损均衡

每次写入完成后，空闲块数严格小于低水位即循环回收，直到不小于高
水位或无可回收块（含最优候选无收益：有效页数==每块页数）。仅当
本次调用确实执行过至少一轮回收，才在循环结束后检查磨损差并至多
追加一次冷块搬迁。擦除次数达到寿命上限的那次擦除完成后块立即
退役，不再进入任何选择堆。

### 并发与确定性

所有导出方法持有同一把互斥锁，效果等价于调用时刻的某个串行顺序。
实现不含任何随机源与时间依赖，相同操作序列重放得到完全相同的
物理布局与统计量（有专门的重放测试）。

### 写放大

以 `(物理编程页数, 逻辑写入页数)` 两个整数返回，不做浮点除法，
调用方可自行约分或比较交叉乘积。

## 被放弃的方案

- **线性扫描选受害块/空闲块**：实现最简单（朴素模型即如此），但
  单次选取 O(B)，不满足"开销不得随块总数线性增长"，仅保留为对照模型。
- **有序 map（红黑树）维护候选集**：与堆同阶，但 Go 标准库没有，
  引入外部依赖不值得；惰性删除的堆在工程上更简单。
- **失效即删除堆中旧项**：需要堆中定位（O(log B) 索引或额外
  map），与惰性删除同复杂度但代码更复杂；且部分回收失败时容易
  丢项（见上），惰性方案天然容错。
- **后台 GC 线程**：能隐藏回收延迟，但破坏"相同操作序列重放得到
  完全相同布局"的确定性，且使串行等价性论证复杂化；改为写路径
  内同步回收。
- **每块一把锁的细粒度并发**：映射、水位、统计均为全局状态，
  细粒度锁收益小、死锁风险大；单锁足够且易于推理。
- **浮点写放大**：规格明确禁止，浮点还会引入舍入误差，不利于
  精确复现。

## 本地验证方法

```bash
# 全部测试（单元 + 模型对照 + 复杂度 + 并发）
go test ./ftl/

# 竞态检测
go test -race ./ftl/

# 查看随机对照测试的逐条操作日志（输入、输出、判定依据）
go test ./ftl/ -run TestModelRandomOps -v

# 复杂度证明测试的计数输出
go test ./ftl/ -run 'IndependentOf' -v
```

- `TestVictimSelectionIndependentOfBlockCount`：相同操作序列在 64
  块与 2048 块上执行，受害块堆弹出次数完全相同，证明不随块总数增长。
- `TestWriteIndependentOfBlocksAndMappings`：不同块数、不同既有映射
  数下相同写入序列的堆操作计数完全相同，证明写入路径与规模无关。
- `TestModelRandomOps`：3 种几何 × 3 个种子 × 2000 条随机操作，
  每条操作后与独立朴素模型逐页对比物理布局与统计量。
- `TestDeterministicReplay`：同一操作序列执行两次，布局与统计量
  完全一致。
