# 动作假设性重新预检子系统 — 设计说明

## 1. 目标

对动作（Action）提供**只读**的假设性重新预检：给定历史时刻 `t` 与一个假设在当时执行的动作调用，
系统重新演算该动作在 `t` 会经历的全部校验钩子，报告：

1. 假设结论：`allowed` / `denied` / `resolution_error`；
2. 若允许，将产生的状态改变意图（`Intent`），只演算不落地；
3. 演算所依据的、当时生效的钩子版本集合与权限继承快照；
4. 全部输入、依据与结论写入仅追加审计日志，可事后核查并可与朴素重演模型逐条对照。

实现位于 `precheck/` 包，演示入口为 `cmd/precheck-demo`。

## 2. 时间模型与全局串行顺序

- 时间是整数逻辑时钟 `Moment = int64`；所有真实事件进入一条全局日志，时间**单调不递减**。
  乱序写入会被引擎拒绝（`Apply` 返回错误），保证“按某个全局顺序串行执行”这一前提可执行。
- 同一全局序列上允许同一时刻存在多个事件（例如同一时刻同时切钩子版本并调整继承关系），
  它们按追加次序全序排列；点查使用“`At <= t` 的最后版本”。
- 预检只读取不晚于 `t` 的事件，天然等价于“在全局序列上切下时刻 `t` 的快照后独立演算”。
  对同一时刻的多次预检彼此无共享可变状态，因此结果等价、可重复。

### 2.1 边界方向（关键取舍）

**全部时态区间采用左闭右开 `[start, next_start)`，边界时刻 `t` 取新版本一侧。**

- 钩子集合 v20 在 `At=20` 生效：`t=19` 演算 v10，`t=20` 起演算 v20。
- 权限边在 `At=30` 被移除：`t=30` 的预检已经看不到该边。
- 参数 schema 在 `At=10` 引入新必填字段：`t=10` 的调用必须携带该字段。
- 历史缺口区间同样左闭右开：`[6,8)` 中 6、7 不可重建，8 恢复可用。

这一方向对钩子版本、schema、权限继承、对象状态、缺口判断**保持一致**，不存在“有些边界取旧侧、有些取新侧”的歧义。

## 3. 数据结构

### 3.1 分块时态存储 `TemporalStore[T]`（`temporal.go`）

- 每个逻辑键（动作类型、调用者、对象、边 `from␀to`）持有独立的段序列。
- 段序列按 1024 一段分块存放：追加 O(1) 摊还（无大切片整体复制）；
  点查先在“每块首元素”上二分定位块（O(log 块数)），再块内二分（O(log 块大小)），
  比较次数合计 O(log 段数)。
- 点查暴露 `TemporalStats{PointCalls, SegmentChecks}` 计数器，可被测试**独立核查**
  （不依赖我们对复杂度的口头声明，见 `TestTemporalSegmentChecksBounded` 与
  `TestSnapshotRebuildSublinear`）。
- 缺口用 `Gap(domain,key,start,end)` 显式标记；缺口判定优先于取值，
  即“无法重建”永远压过“恰好取到某值”。

### 3.2 权限继承快照（`permission.go`, `evaluate.go`）

- 权限图是带时态边的有向图：边 `a -> b` 表示 `a` 直接持有 `b`（b 为权限令牌）
  或 `a` 继承 `b` 的全部权限。调用者持有集合 = 从 caller 沿**当时活跃边**可达的全部节点，
  BFS 的 `visited` 自然处理继承环。
- 每条边有独立的布尔段史（键 `from␀to`）；重建快照时只对调用者**可达节点**的候选边做点查，
  与不可达子树、与系统在无关节点上的累计调整次数完全无关。

### 3.3 钩子注册表（`hooks.go`）

- 钩子是无外部副作用的不可变实现，ID 一经发布**永不复用、永不就地修改**。
  要“修改”钩子，只能注册新 ID 并用新 `HookSet` 版本引用它——这是历史可精确重演的前提。
- `HookSet` 是某动作类型在某时刻生效的有序前置/后置引用列表；该时刻没有钩子是合法状态
  （空集合），区别于“历史缺失无法重建”。
- 若历史 `HookSet` 引用的钩子实现当前不在注册表，归类为 `snapshot_missing`。

## 4. 两阶段校验流水线

顺序固定：

1. 解析阶段（四类错误，见 §5）；
2. 授权门：权限不足是**前置阶段的第一个失败**，一旦失败，任何前置钩子都不演算；
3. 前置钩子：按 `HookSet.Pre` 顺序执行，共享本次演算私有的 `PreContext`（含 scratch）；
4. 后置钩子：仅当前置阶段零失败才演算；看到的是前置快照的**冻结深拷贝**，
   不能回写 scratch、参数或对象。

### 4.1 失败聚合规则（在所有请求下表现一致）

| 聚合模式 | 前置阶段 | 后置阶段 |
| --- | --- | --- |
| `fail_fast`（默认） | 首个失败即停止，报告 1 条 | 前置全过后：首个失败即停止 |
| `collect_all` | 跑完全部前置钩子，聚合**所有前置失败** | 前置全过后：跑完全部后置钩子，聚合**所有后置失败** |

**跨阶段固定规则：前置阶段只要存在失败，后置阶段一律不演算。**
因此前置失败与后置失败**永不在同一次响应中混合出现**；“报告全部失败”的语义是
“报告所到达阶段内的全部失败”，而不是把被阻断阶段的失败也推测性地聚合进来。
授权门失败同理：它是前置阶段失败，并阻断前置钩子。被拒绝的动作不返回任何 `Intent`。

### 4.2 只读保证

- 预检路径不调用任何写时态存储的方法；写方法只在 `Apply`/`Execute` 上。
- 进入演算前对参数做深拷贝；钩子对 map/slice 的任何修改只作用于私有拷贝。
- 后置阶段的 scratch 是前置 scratch 的深拷贝；对象只暴露读接口。
- 预检唯一允许的可观察输出是**仅追加审计日志**（这本身不改变任何对象状态、
  钩子版本记录或权限关系）。
- `TestPrecheckIsReadOnly` 验证：预检后事件日志条数不变、调用方入参不被污染、
  后置钩子能读到前置 scratch 但无法影响前置阶段。

## 5. 四类解析错误与优先级

在进入任何钩子演算之前，先解析快照。四类错误互不相同，且同时触发时按固定优先级**只报一类**：

1. **B `snapshot_missing`（最高）** — 钩子版本、schema、调用者存在性或权限继承快照
   因历史数据缺失（缺口区间 / 钩子实现不可用）无法重建；
2. **A `action_not_yet_defined`** — 指定时刻早于动作类型被定义的时刻；
3. **C `caller_not_exist`** — 调用者身份在指定时刻尚不存在；
4. **D `invalid_params`（最低）** — 参数违反当时生效的结构约束。

**为何 B 高于 A/C/D（被放弃的直觉顺序 A→B→C→D）**：当历史存在缺口时，
“类型当时是否已定义”“调用者当时是否存在”这些判断本身不可信；把缺失报成“未定义”
会给出一个看似确定但可能错误的结论。因此先保证快照可重建，再讨论其上的事实。
随后按“定义先于主体（A→C）、事实先于内容（C→D）”排序。

权限不足**不是**解析错误：快照完整、事实清楚，只是演算结论为拒绝
（`denied` + stage=`pre` 的 `#authorization-gate` 失败）。

## 6. 状态改变意图

- 允许时，后置钩子可返回 `Intent{op, object_key, value, source}`；
  此外引擎根据参数 `object_key/value` 生成一条类型默认规范意图，保证无后置钩子的类型也有明确意图语义。
- 预检只报告意图。`Execute` 才会在允许时把意图落地为真实对象事件并追加真实调用事件
  （随机测试还验证：同刻“真实执行结果”与“假设预检结果”规范表示一致）。

## 7. 审计与可核查性

每次预检写一条 `AuditEntry`：请求、结论、失败明细、所引用钩子 ID 列表、
当时权限快照（活跃边/持有集合）、时态点查计数器、以及（经外部对照后回填的）
`CrossCheckRecord`。`Annotate` 只允许在审计条目上补全对照结论，
不修改任何业务事实。

## 8. 复杂度与“不随累计演进总次数线性增长”

设系统累计发生 `N` 次版本演进/继承调整。

- 一次预检中，对每个键的时态点查是 O(log 该键自己的段数) ≤ O(log N)，
  且只访问与本次演算相关的键（动作类型、调用者、可达权限节点、钩子读到的对象）。
- 权限重建只沿调用者**可达子图**做边点查；在无关节点上发生的海量调整不进入访问路径。
- 单段增量表示 + 每边独立段史，使同一边反复增删也只在自身历史上追加，不复制邻接表。

**可独立验证的方式**：

- 计数器：`TemporalStore.Stats()` 暴露每次点查的段比较次数，审计条目里持久化该数据。
- `TestTemporalSegmentChecksBounded`：10 万段热键，一次点查段比较次数上界为常数（实际约十几次）。
- `TestSnapshotRebuildSublinear`：在无关键 `g` 上制造 5 万次关系调整后，
  调用者 `u` 的快照重建 `edge_segment_checks` 不超过 10；
  并额外验证调用者自身 5 万段时单点查仍是 O(log n)。

朴素重演模型故意是 O(N) 全量扫描，作为语义对照而非性能方案。

## 9. 独立朴素重演模型与差分测试

`NaiveReplay`（`naive.go`）是**第二份实现**：不使用 `TemporalStore`/引擎索引，
每次从头线性扫描不晚于 `t` 的事件，用普通 map 重建世界后独立演算，
再按与生产一致的规则跑授权门与前后置钩子。

- `TestRandomDifferential`：40 个固定随机种子 × 220 步随机操作（继承增删、
  钩子版本演进、schema 演进、对象变更、真实执行、假设预检交错），
  每次预检都对照引擎与朴素模型的规范结论及权限快照；真实执行还与“同刻假设预检”对照。
- 固定种子保证失败可复现。

## 10. 被放弃的方案

- **每次预检全量重扫日志**：语义最直白但 O(N)，直接违背复杂度要求，仅保留为对照模型。
- **每条边的每个时态段保存整张邻接表快照**：读取直观，但同键高翻转时写入/存储 O(N²)，已放弃。
- **持久化 treap 邻接集**：结构共享、O(log 度数)，但“同键反复插入→删除→再插入”
  在固定/重复优先级下会退化，且节点分配量大；最终改用“每边独立布尔段史 + 候选目标集合”。
- **前置失败也聚合后置失败**：会要求在已被阻断的路径上做推测性演算，
  后置可能依赖前置 scratch，语义不成立，故明确禁止跨阶段聚合。
- **错误优先级 A→B→C→D**：缺历史时“未定义”判断不可信，改为 B 优先（见 §5）。

## 11. 本地验证方法

```bash
# 需 Go 1.26+
go test ./...                     # 全量测试（含随机差分、边界、复杂度）
go test -race ./precheck          # 竞态检测
go test -cover ./precheck         # 覆盖率
go test -v ./precheck -run TestBoundaryExhaustive   # 边界穷举
go test -v ./precheck -run TestRandomDifferential   # 随机逐条对照
go run ./cmd/precheck-demo        # 端到端演示（含审计条目计数）
```
