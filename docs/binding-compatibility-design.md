# 跨对象类型字段绑定兼容性校验 — 设计说明

本文档说明链接类型绑定依据字段兼容性校验的设计：判定模型、关键取舍、
被放弃的方案与本地验证方法。实现位于 `ontology/` 包。

## 1. 问题与模型

链接类型声明以两侧对象类型各自的某个字段作为链接实例的绑定依据
（`BindingDecl`，见 `ontology/binding.go`）。绑定兼容的判定标准：

> 存在一种确定的对应方式，使一侧字段的任意合法取值都能在另一侧字段的
> 取值空间中找到唯一且确定的对应取值，反之亦然。

建模要素：

- **取值空间（Domain）**：字段类型 + 取值约束（枚举）构成的集合；
  未声明枚举约束时为该类型的无界全域。字段可缺失（`Nullable`）时，
  缺失取值作为一个独立取值并入取值空间（`FieldDef.Domain()`）。
- **对应方式（Correspondence）**：`Identity`（同类型按相等对应）或
  `Explicit`（显式取值对，可跨类型）。声明后不可变。
- **缺失策略（MissingPolicy）**：`MissingForbidden` / `MissingToMissing` /
  `MissingToValue`，决定缺失取值如何参与对应。绑定建立时确定，运行期不可变
  （重复声明同一链接类型会被拒绝）。
- **方向（Direction）**：`LeftToRight` / `RightToLeft` / `TwoWay`。
  单向声明只要求声明方向唯一可对应；双向声明要求双射。

## 2. 判定算法

`CheckBinding`（`ontology/check.go`）是纯函数，判定顺序固定：

1. **字段删除优先**：任一侧字段为 nil（已删除）→ `IncompatFieldDeleted`。
   其余三类判断都依赖字段存在，因此该判定必须最先给出。
2. **类型可比较性**：`Identity` 要求两侧类型相同；`Explicit` 要求两侧
   取值空间均有限（无界空间上无法验证显式取值对的全覆盖性）。
   不满足 → `IncompatIncomparableTypes`（当前版本无法判定）。
3. **唯一性检查**：把对应方式与缺失策略合成为取值对集合
   （`composePairs`），过滤掉端点落在对应侧取值空间之外的取值对
   （对应关系只定义在合法取值之上），然后：
   - 左→右成立 ⟺ 每个左侧合法取值恰好有一个落在右侧空间内的像；
   - 右→左成立 ⟺ 每个右侧合法取值恰好有一个落在左侧空间内的原像。

结论分类（`IncompatKind`）：

| 分类 | 含义 |
| --- | --- |
| `Compatible` | 满足声明方向要求的唯一性 |
| `IncompatFieldDeleted` | 绑定依据字段被删除，定义失效（优先） |
| `IncompatIncomparableTypes` | 类型无法比较，无法判定 |
| `IncompatNotBijective` | 声明方向要求的唯一性不成立 |
| `IncompatDeclaredTwoWayOnlyOneWay` | 声明双向但实际只单向可对应 |

注意：交集非空不是放行条件——只有逐取值的双向唯一性检查通过才兼容
（测试 `non-empty intersection without bijection is still incompatible`）。

## 3. 关键取舍

- **声明期强校验**：`DeclareLinkType` 在声明时即运行完整核验，
  声明双向但实际只单向可对应的当场拒绝（`IncompatibleError`），
  不会延迟到反方向第一次被使用。
- **单向不退化**：`QueryBinding` 先查声明方向是否允许，再查兼容性；
  单向绑定的反方向查询/写入一律 `ErrDirectionNotAllowed`，绝不静默按双向处理。
- **重核验不撤销历史**：字段变更触发引用它的链接类型逐一重核验；
  不再兼容的链接类型被阻止新的绑定查询与写入，但已有链接实例保留在
  per-link-type 存活索引中，直到被显式 `RemoveLinkInstance` 处理。
- **状态按链接类型隔离**：兼容性结论存于每个 `linkTypeState`，
  字段本身不携带"兼容/不兼容"标记；一个字段被多个链接类型引用时，
  各链接类型的判定互不影响。
- **遍历上界可验证**：重核验只访问该链接类型的存活实例索引
  （`lt.instances`），不触碰对象类型的历史实例；每次核验把实际遍历数
  记入审计（`AuditRecord.InstancesVisited`），由测试证明其等于该链接类型
  当前存活实例数，与历史总量无关。
- **可线性化的并发**：`Registry` 用一把互斥锁串行化所有字段变更与绑定查询，
  并在锁内为每个操作分配全局序号（`seq`）。序号顺序即等价的全序串行执行；
  任何查询都不可能读到介于两次字段变更之间的中间状态。
- **审计可追溯**：每次核验（声明 / 字段变更 / 字段删除触发）记录两侧字段
  定义快照、合成后的对应取值对与检查说明（`CheckBasis`）以及结论，
  通过 `AuditLog()` 暴露供事后核对。

## 4. 被放弃的方案

- **按取值集合交集判定**：交集非空不代表存在双向唯一对应，会错误放行
  多对一、部分覆盖等情形，与判定标准直接冲突，放弃。
- **字段级兼容性缓存**：把兼容性结论挂在字段上会导致多个链接类型
  共享一份状态，违反"各链接类型判定相互隔离"的要求，放弃。
- **不兼容时级联删除既有链接实例**：历史绑定关系是事实数据，
  兼容性变化不应静默销毁；改为阻止新查询/写入、保留旧实例，放弃级联删除。
- **读写锁（RWMutex）**：查询也需要分配全局序号并可能追加审计，
  并非纯读；用 RWMutex 反而引入"读序列与写序列如何合并成全序"的
  额外论证负担。单互斥锁在本场景足够且线性化论证最简单，放弃 RWMutex。
- **无界取值空间上的显式对应**：无法在有界时间内验证全覆盖与唯一性，
  当前版本判定为"无法比较/无法判定"，不为它发明近似语义。

## 5. 本地验证方法

```bash
# 全部测试（含竞态检测）
go test -race ./...

# 并发对照测试单独多跑几轮
go test -race -count=5 -run TestConcurrent ./ontology/

# 代码检查
gofmt -l .
go vet ./...
```

测试覆盖（`ontology/*_test.go`）：

- `check_test.go`：单向/双向声明下唯一性的全部边界组合（双射、真子集、
  多对一、未覆盖、冲突取值对、交集非空但非双射、跨类型显式双射）；
  缺失取值参与判断的全部组合（缺失↔缺失、缺失↔指定值、缺失被禁止、
  缺失碰撞、显式对遗漏缺失）；类型无法比较与字段删除优先级。
- `registry_test.go`：声明期拒绝、单向绑定反方向拒绝、字段变更触发
  重核验并阻止新查询、已有实例保留、删除优先级、链接类型间状态隔离、
  重核验遍历数等于该链接类型存活实例数、缺失策略声明后不可变。
- `concurrency_test.go`：并发字段变更与绑定查询交织后，按全局序号
  串行重放到独立的朴素串行实现（无锁、每次从头重算）上逐条对照，
  并核对最终绑定兼容性结论一致。
