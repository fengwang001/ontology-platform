# 部分列更新事件的批内合并

`merge` 包把**同一批**内针对**同一主键**的多条变更事件（插入 / 更新）合并为**至多一条**输出，
使得“把合并结果应用到批前表”与“把原始事件逐条应用”**结果一致且可复现**。

## 列值三分

每个列值严格区分三种状态（见 `merge.Value`），三者互不相等：

| 状态 | 构造 | 谓词 | 说明 |
| --- | --- | --- | --- |
| 缺席（absent） | `merge.Absent()` | `IsAbsent()` | 该列根本不出现 |
| 显式空值（null） | `merge.Null()` | `IsNullValue()` | 列存在，但值为空 |
| 字符串（string） | `merge.Str(s)` | `IsString()` | 列存在，值为字符串（`""` 是合法且独立的值） |

`Value.Equal` 按三分语义比较：`absent != null != ""`。空串 `""` 与显式空值是**不同**的值。

## 事件规则

- **插入（insert）**：必须给出**全部** schema 列，且每列都必须“在场”（null 或字符串，不得缺席）。
  目标主键必须不存在，否则拒绝（`ErrKeyExists`）。
- **更新（update）**：只包含**本次变更**的列（至少一列），每列值必须“在场”。
  变更前镜像 `Before` 的列集合必须与本次变更列集合**完全相同**。
  目标主键必须存在，否则拒绝（`ErrKeyNotFound`）。

## 合并规则（同键）

同一主键的多条事件按批内顺序合并：

- **更新接更新**：取列**并集**；同列取**后到**的值；该列的变更前镜像取**批内首次**被更新时的值。
- **插入接更新**：结果仍为**插入**，更新值直接并入插入行。
- **插入接插入 / 更新后插入**：违反键唯一性，整批拒绝（`ErrKeyExists`）。

## 剔除规则

- 合并结果为**更新**时：剔除“变更值 == 原值（批内首次前镜像）”的列；若剔后为空，则该键**不输出**。
- 合并结果为**插入**时：**不剔除**，整行输出。

## 输出顺序

- 每个键在输出中**至多一条**。
- 输出按键在批内**首次出现**的顺序排列。

## 错误类别（互不相同、可区分）

所有拒绝都返回 `*merge.BatchError`，其 `Kind` 字段可程序化区分：

| Kind | 含义 |
| --- | --- |
| `ErrIllegalColumn` | 未知列 / 插入列不全或多余 / 更新无列 / 前镜像列集合 ≠ 变更列集合 / 值缺席 |
| `ErrKeyNotFound` | 更新目标键不存在 |
| `ErrKeyExists` | 插入目标键已存在 |
| `ErrBeforeImageMismatch` | 变更前镜像与实际值不符 |
| `ErrConflict` | `Apply` 时表已被并发提交改变（乐观并发失败） |

**整批拒绝**：任一事件非法，整批拒绝，且**不改动表**（失败不留痕）。

## 并发模型

- 行查询（`Get`/`Snapshot`/`Len`）与自检（`SelfCheck`）使用**读锁**，可被多个执行体并发调用，
  并可与单个 `Commit`/`Merge`/`Apply`（写锁）并发。
- `Commit`：校验 + 合并 + 应用**原子**完成。
- `Merge`：只校验 + 合并，**不改表**；随后可用 `Apply` 持久化（带前镜像乐观校验，漂移则 `ErrConflict`）。

## 本地验证

```bash
# 单元 + 朴素参照一致性 + 随机化 + 并发测试
go test ./merge/

# 竞态检测
go test -race -count=3 ./merge/

# 逐步日志演示（每步输入、合并结果与判定依据）
go run ./cmd/merge-demo

# 代码检查
gofmt -l . && go vet ./...
```

测试要点：

- `merge/merge_test.go`：三分区分、插入接更新、无变化列剔除、非法输入与拒绝后状态不变、输出顺序与唯一性、可复现。
- `merge/reference_test.go`：独立的**朴素逐条参照**（`naiveApply`），随机化生成合法批（固定种子，可复现），
  断言“合并提交后的表 == 逐条应用后的表”，并校验输出不变量；另有并发测试（读写并发 + `-race`）。
