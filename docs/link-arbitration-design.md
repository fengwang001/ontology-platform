# 链接实例层创建与去重仲裁 —— 设计说明

实现位于 `link/` 包（module `ontology`）。本文记录语义约定、关键取舍、
被放弃的方案以及本地验证方法。

## 1. 领域模型与语义

- `LinkType`：声明 `SourceType`、`TargetType`，以及两个方向各自的基数
  上限 `ForwardCap` / `BackwardCap`。上限取值为非负整数（0 表示禁止）或
  `Unlimited()`；两方向独立，可以不同。
- `Link`：一条已登记链接，携带源/目标实例与一个区分属性组合
  `Discriminator map[string]string`，并拥有全局唯一的 `Link.ID`。
- 基数计数粒度：**链接类型 + 有序实例对 + 方向**。对同一有序对
  `(S,T)` 在方向 d 上的在库链接数达到 `Cap(d)` 后，新增即拒绝。一条
  `S→T` 链接只增加 S 在该方向的出度计数；`T→S` 属于另一个方向，受
  另一方向上限约束，互不影响。
- 去重：同一链接类型、同一有序对、同一方向上，规范化后的区分属性组合
  相同即视为同一条链接的重复声明，返回 `ErrDuplicateLink`。判重在基数
  判断之前，重复不消耗名额。区分属性仅在各自链接类型命名空间内比较，
  跨类型不互相抑制。
- 撤销：`Delete` 立即从活动集合移除并释放度数槽；同一区分属性组合之后
  可以重新占用，但会分配新的 `Link.ID`。系统不持久化任何已撤销条目，
  因此新链接不可能继承被撤销链接的派生状态。
- 自引用链接类型（源类型与目标类型相同）：用两个实例 ID 的全序消歧，
  同一实例的自链接固定计入 forward；这是确定性的、对相同输入稳定的约定。

## 2. 失败分类与优先级

创建按下列固定优先级仲裁，保证多类失败同时成立时结果稳定、可区分：

1. `ErrObjectInstanceDeleted` —— 源或目标实例不存在 / 已逻辑删除
   （**最高优先，先于一切基数与重复性判断**）。
2. `ErrLinkTypeDirectionNotAllowed` —— 实例类型与链接类型端点不匹配；
   未知链接类型单独给出 `ErrUnknownLinkType`（同属“类型不允许”一族，
   调用方可用 `errors.Is` 进一步区分）。
3. `ErrDuplicateLink` —— 与在库链接的区分属性组合完全相同。
4. `ErrCardinalityExceeded` —— 目标方向在库数已达上限。

删除在链接不存在时返回 `ErrLinkNotFound`。任何失败都不修改活动集合或
度数；判定日志是仅追加的审计输出，不参与任何后续判定。

## 3. 并发控制（关键取舍）

采用**分片互斥 + 临界区内检查并登记（atomic check-and-insert）**：

- 256 个分片（`shardCount`）。互斥键是“链接类型 + 无向实例对”
  （`pairKey`，两个实例 ID 排序后入键），因此同一对实例上两个方向的
  创建/删除互斥，而互不相关的实例对可以并行。
- 度数槽 `degreeKey{typeID, instanceID, direction}` 独立分片存放。
  一次创建/删除最多按分片索引升序持有 pair 分片与源端度数分片，
  统一的“排序后加锁、逆序解锁”规则避免死锁。
- “是否重复 / 是否超限 / 插入 / 度数增减”全部在同一临界区内完成，
  从根上消除“两个请求都看到当前未超限而双双通过”的 TOCTOU 窗口。
- 删除与同区分属性新建因此必然串行：要么删除先提交（名额已释放，新建
  成功），要么新建先提交（名额尚未释放，新建被拒）。不存在第三种状态。
- 判定日志 `DecisionLog{Seq, Op, Request, Reason, Result, LinkID}` 在
  临界区内、对调用方返回之前追加。于是 `Seq` 给出一个**保持实时序
  （real-time order）的合法全序**：若操作 A 在 B 开始前已返回，
  则 `Seq(A) < Seq(B)`。并发正确性即可用“按 Seq 用朴素模型重放”来
  机器校验，而不依赖人工推理交错。

### 被放弃的方案

- **单全局锁**：正确但吞吐随实例规模线性下降；改为按无向实例对分片，
  仅相关操作互斥。
- **为“检查”与“插入”分两个临界区（先查后插）**：存在 TOCTOU，会
  超额登记，已否决；检查与登记必须原子。
- **数据库唯一索引 + 捕获冲突重试**：重试会让“判重 vs 基数满”的归属
  随调度抖动，且难以给出稳定优先级与确定性日志；本方案在内存仲裁层
  一次性决定。
- **逻辑删除（tombstone）保留已撤销链接以支持历史查询**：会让去重集合
  与存储随历史无限增长，且容易让重新占用“继承”旧派生状态。本方案要求
  撤销即物理移除活动结构；历史审计需求只由仅追加日志承担，日志不参与
  判定，二者职责分离。
- **全局单调序列号生成器作为单独锁**：会成为争用点；`nextID` 与日志
  Seq 的递增都发生在已持有的链接临界区之后、日志锁内，临界区很短。

## 4. 查询代价与可验证性

`CountDirection(typeID, instanceID, direction)` 只对单个度数槽做一次
map 读取：O(1) 时间、O(1) 空间。删除会回收归零的度数槽，并在一对实例
上两个方向都为空时回收整个 `pairState`，因此活动结构规模有上界
“当前有效链接数”，与历史创建/撤销总量无关。

`TestCountCostIndependentOfHistory` 直接进行 2000 次“创建后撤销”，
随后断言所有分片的内部 map 均为空；再建 2 条链接并断言全库 pair 槽与
度数槽各只有 1 个。这是对“代价只与有效链接相关”的可执行证明。

## 5. 本地验证方法

```bash
# 需 Go 1.26+；若 go 不在 PATH：export PATH=$PATH:/usr/local/go/bin
go test ./...
go test -race -count=1 ./...        # 竞态检测
go test -v ./link                    # 查看 3x3 上限矩阵等用例
go test -cover ./link                # 当前语句覆盖率约 90%
go vet ./... && gofmt -l .
```

关键测试：

- `TestBidirectionalCapsMatrix`：双方向 0/1/不限的 3×3 组合边界。
- `TestRevokedSlotReuse`：撤销后重占用、新 ID、已撤销与未撤销取值混合
  下的判重与基数。
- `TestFailurePriority`：四类失败精确区分，实例不存在优先；拒绝无副作用。
- `TestDirectionIndependence` / `TestLinkTypeIsolation`：方向间、
  链接类型间的基数与判重隔离。
- `TestCountCostIndependentOfHistory`：查询代价与历史无关的结构性证明。
- `TestConcurrentIsSerializable`：30 轮、每轮 800 个并发创建/删除随机
  交织，按判定日志 Seq 用独立朴素模型逐条重放，核对五类结果与终态计数、
  在库集合完全一致。
- `TestConcurrentSameKeyCreateDelete`：cap=1 下“删除 + 同区分属性新建”
  并发，终态只能归约为两种串行序之一。

## 6. 假设与边界

- `ObjectChecker.Lookup` 由对象实例子系统提供，是实例存在性与对象类型
  的唯一事实来源；本包不负责实例生命周期。
- 判定日志为进程内仅追加结构，长期运行应外置（同一提交全序内追加）；
  其规模属审计域，不影响判定与计数的复杂度。
- 区分属性的值类型限定为字符串；非字符串属性应在进入仲裁前规范化。
