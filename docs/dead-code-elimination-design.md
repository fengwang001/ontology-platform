# 死代码裁剪分析器设计说明

## 职责划分

- `model.go`：声明、导入、导出、副作用、错误码与结果类型，不包含算法。
- `registry.go`：并发登记、拒绝操作的原子性、会话创建时的深拷贝快照，以及构造期校验。
- `resolver.go`：具名导出链、通配重导出、默认导出屏蔽、歧义和循环解析。
- `analyzer.go`：最小固定点工作流、保留原因优先级、导入绑定检查和有序输出。
- 测试文件：确定性语义、错误类别、并发快照、随机图与独立朴素迭代模型对照。

## 核心算法

### 导出解析

每个模块先建立两类索引：

- 显式导出：本地声明导出和具名重导出，按“模块 + 导出名”唯一索引。
- 通配重导出：按登记次序保存。

具名解析优先查显式导出。具名重导出沿 `(目标模块, 导入名)` 继续解析，并使用路径集合识别重导出循环。没有显式导出时，再查该模块的通配结果；通配同名映射到同一声明则有效，映射到不同声明则返回歧义。

通配展开遵守以下规则：

- 当前模块的显式导出覆盖通配来源中的同名导出。
- 通配重导出不转发名为 `default` 的导出。
- 通配链使用活动模块集合截断递归，并把每个根模块的通配结果物化为缓存；重入已完成模块时直接复用缓存。
- 同名一致只保留一个声明；同名冲突记录为歧义，不参与通配导入或入口导出。

具名解析结果按 `(模块, 导出名)` 记忆化。通配结果按模块物化：无环通配图中的每个模块只展开一次；环上的回边按空贡献截断，避免无限递归，环上模块在其根展开路径中完成一次物化。声明保留工作流中的每个 `(模块, 声明)` 只入队一次，因此总工作不随入口数量成倍增长。

### 最小固定点

求解维护：

- `included`：最终被引入的模块集合。
- 模块工作队列：模块首次进入时只处理一次导入和模块级副作用声明。
- `kept`：保留声明及其最高优先级原因。
- 声明工作队列：每个 `(模块, 声明)` 只入队一次。

初始种子是入口模块的全部有效导出。工作流反复应用：

- 被引入模块中且声明自身带副作用的声明，在模块级副作用不是“无”时保留。
- 被引入模块的所有导入语句参与模块引入：目标模块副作用为“有”则直接引入。
- 被保留声明引用本地声明时保留本地声明；引用导入绑定时解析到目标声明并保留。
- 目标模块副作用为“无”时，不因导入本身引入，但一旦其中有声明因引用保留，就引入该模块，然后处理其全部导入。
- 通配导入展开为目标全部有效、非歧义导出；这是保守保留。

两个集合都从空开始，仅在规则要求时增加成员，且没有删除或猜测规则，因此队列为空时得到包含所有种子的最小解。

## 原因优先级

同一声明可同时满足多个原因，输出取以下最高优先级：

1. `entry-export`
2. `referenced`
3. `side-effect`

原因只向更高优先级提升，不会被后续弱原因覆盖。

## 错误模型与报告顺序

登记时立即检查并拒绝：

1. 非法参数：空标识、声明名重复、导入本地名重复、导出名重复或结构非法。
2. 重复模块。

以上检查失败时不写入注册表。

在会话快照上、解析检查之前检查：

3. 未知模块：导入、重导出目标不存在；入口未知模块也在求解时归入此类。
4. 未定义引用：声明引用既不是本地声明也不是本地导入绑定，以及本地导出找不到本地声明。

固定点求解时，无法解析的绑定先按“不产生引用”处理。得到被引入模块集合后，再按模块标识升序、模块内绑定登记次序检查，并区分：

- `missing-export`
- `ambiguous-export`
- `reexport-cycle`

任一解析错误都会让整次求解失败，不返回部分结果。

## 并发与快照

`Registry` 使用读写锁保护 map。`NewSession` 在持锁期间深拷贝所有已接受模块及入口集合；之后 `Solve` 只读该快照。登记过程继续调用方持有的切片不会影响会话，会话后的登记也不会影响旧会话。

因此，任意并发已接受登记集合都等价于某个线性化顺序；每个会话观察其创建时刻的一致快照。

## 关键取舍

- 使用工作队列而不是“每轮扫全图”：模块和声明首次进入即处理，避免随入口数量或迭代轮数重复扫描。
- 通配导出结果直接物化为“名字到声明”和歧义集合：语义直观，便于入口、通配导入和具名回退复用。
- 解析错误延后到固定点之后：错误绑定在求解时不产生引用，但仍需先知道最终被引入模块集合，才能按要求选择第一处错误。
- 不尝试语法层面的 tree-shaking 重写：分析器只输出模型上的保留集合和原因，不修改输入。

## 被放弃的方案

- 每轮全量扫描所有模块直到不变：实现简单，但无法证明每个模块、声明只处理一次，也会随迭代深度重复工作。
- 为每个入口独立求闭包再合并：会让成本随入口数量成倍增长，并需要额外合并原因。
- 在登记时立即解析跨模块导出：后续登记可能改变可解析性，也破坏基于会话快照求解的语义。
- 遇到第一个解析失败立即停止：无法满足“错误绑定求最小解时视为无引用，再在最终被引入集合中报告第一处”的规则。
