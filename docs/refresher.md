# 按键节流的物化视图刷新器

包 `refresher` 实现一个按键节流的物化视图刷新器：同一键的连续变更
在防抖窗口内被合并为一个批次，批次到达刷新时刻后才应用物化视图。

## 节流合并规则

- 变更通过 `Upsert(key, value, at)` 到达。
- 若该键已有尚未刷新的批次，则**并入**：合并条数加一、值更新为最新
  值、刷新时刻顺延为 `at + debounce`。
- 否则**新建批次**：条数为 1，刷新时刻为 `at + debounce`。
- 视图只在刷新时更新；待刷新批次中的最新值通过 `View` 对外不可见。
- 待刷新键数不得超过 `maxPending`；新建批次会超限时拒绝（并入已有
  批次不占新键位，不受限）。

## 刷新时刻规则

- `Advance(now)` 刷新所有 `refreshAt <= now` 的批次（**含等号边界**），
  每批产出一条 `Record`（键、最终值、合并条数、刷新时刻、应用时刻）
  并应用到视图；同一批返回的记录按键名字典序排列，保证可复现。
- `Shutdown()` 停机收尾：全部待刷新批次立即刷新，应用时刻为当前逻辑
  时钟；此后实例关闭，重复调用安全。

## 时钟单调规则

- 逻辑时钟取上一次**成功**操作的时间；所有时间戳（`Upsert` 的 `at`、
  `Advance` 的 `now`）不得小于它，否则拒绝。
- 时间戳允许并列：同一键时间戳相等时按到达顺序**后者胜**（后到的值
  覆盖先到的值）。
- 被拒绝的操作不改变逻辑时钟、批次、视图与累计批数，实例仍可正常
  使用。

## 错误

四类非法输入对应四个互不相同的哨兵错误，均可用 `errors.Is` 判定：

| 场景 | 错误 |
| --- | --- |
| 构造参数非正（`debounce` 或 `maxPending` <= 0） | `ErrNonPositiveParam` |
| 键为空 | `ErrEmptyKey` |
| 时间回退 | `ErrClockRegression` |
| 待刷新键数超限 | `ErrTooManyPending` |

另：`ErrClosed` 表示实例已停机，不再接受变更或推进。

## 并发

`View` 与 `Snapshot` 使用读锁，可并发调用；`Snapshot` 返回视图副本、
待刷新批次数、累计刷新批数与逻辑时钟的一致性快照，并发只读同一实例
得到的结果逐字段相同。
