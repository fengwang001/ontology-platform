# 稀疏检出规则引擎 — 设计说明

## 模块
- `sparse/tree.go`：提交文件树（目录/文件二分），节点带 Merkle 哈希；两提交 diff 跳过哈希相同子树。
- `sparse/rules.go`：三类模式解析与校验；规则集编译为 trie，每节点只保留「精确/前缀/本层」各最后一条；
  匹配 = 沿路径收集候选、取规则序号最大者，O(深度)。规则集 diff 同样按子树哈希剪枝，输出变化作用域。
- `sparse/engine.go`：工作区状态（当前提交、规则集版本、目录物化文件计数、本地修改标记）与原子 Apply。
- `sparse/query.go`：五态单路径查询与前缀列举（只递归物化计数 > 0 的目录）。

## 关键取舍
- 物化集合不显式存储：文件由规则即时判定，目录由「物化后代文件计数」推导；变更只重算受影响作用域。
- 「保持不变」集合以计数返回而非列表，否则任何变更的开销必然随未受影响路径数线性增长，违反性能契约；
  完整枚举可用 `ListMaterialized("")` 另行获得。
- 目录自身状态判定优先级：有物化后代 → 物化；否则看自身最后命中规则（排除→因规则排除，无命中→无规则，
  包含→空目录）。祖先隐含物化不受排除规则阻断（题目规定）。
- 「无意义重复」按「动作+模式完全相同的规则再次出现」判定，整组拒绝且不消耗版本号。
- 并发用单把 RWMutex：写者互斥、读者快照，天然线性一致；换取实现简单与可证明性。

## 被放弃的方案
- 每次变更全量重算物化集合并返回完整三元组列表：简单但违反「开销不随未受影响路径增长」。
- 不可变持久快照（路径拷贝）：查询隔离好，但内存与实现复杂度高，互斥锁已满足串行等价。
- 按规则区间树/线段树合并：对「最后命中者胜」语义无收益，trie 已做到 O(深度)。

## 性能证明方式
引擎内置原子计数器（匹配步数/文件求值数/树节点访问数）。`perf_test.go` 在 1k 与 100k 文件、
1106 与 100106 条未受影响物化路径两种规模下断言计数完全相等，确定性证明两条复杂度契约。

## 本地验证
```bash
go test -race -v ./sparse/   # 功能 + 并发 + 随机对照模型 + 性能证明
go vet ./sparse/ && gofmt -l sparse/
```
随机对照测试（`model_test.go`）以固定种子驱动 400 步随机操作，逐步与线性扫描朴素模型比对
物化集合、五态查询、受阻/丢弃列表与保持计数。
