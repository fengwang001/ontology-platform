# 承运商运价合同运费计算与结算系统 — 设计说明

包路径：`freight/`。本文档记录关键取舍、被放弃的方案与本地验证方法。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `freight/types.go` | 对外数据模型：合同、运单、费用明细、询价请求/结果 |
| `freight/errors.go` | 可区分的错误类别（`ErrKind`）与错误类型 |
| `freight/contract.go` | 合同参数校验、单线路合同区间索引 `contractSet`（排序 + 二分） |
| `freight/pricing.go` | 纯函数计价引擎：计费重量、累进阶梯、各项附加费 |
| `freight/system.go` | `System` 门面：并发控制、合同管理、计价、结算、多承运商询价 |

协作方式：`System` 持有全部状态并用一把互斥锁串行化所有操作；计价时先经
`contractSet` 定位合同，再调用 `pricing.go` 的纯函数算出 `FeeBreakdown`；
结算只是把当时的明细快照复制进 `settlements`，因此天然不可被后续合同变更改写。

## 关键取舍

- **合同索引**：按 `(承运商, 线路, 等级)` 分桶，桶内合同按生效起点排序。
  重叠检测与时刻定位都是二分查找（`sort.Search`），开销只随**同一线路上**
  的合同数对数增长，与系统内合同总数无关。因为区间互不重叠（相接允许），
  排序数组上的单个二分即可同时回答"前驱是否重叠"与"后继是否重叠"。
- **累进阶梯**：添加合同时预计算各档累计运费前缀和 `tierPrefix`，计价时
  二分定位计费重量所在档，`前缀和 + 档内部分` 一次算出，O(log 档数)。
  为此要求阶梯从 0 开始连续相接、档边界为计重单位整数倍（作为参数校验），
  使"档内部分"恰好是整数个计重单位，全程整数运算、无浮点误差。
- **取整语义**：体积重量 `ceil(体积/系数)`；计费重量取实际与体积较大者后
  向上取整到计重单位整数倍；燃油费 `ceil(提升后基础运费 × 千分比 / 1000)`。
  全部用整数 `(a+b-1)/b` 实现，保证可复现。
- **结算固化**：`Settle` 深拷贝当时的 `FeeBreakdown` 存入 `settlements`，
  之后任何合同新增都不触碰该表；未结算运单重新计价总是读当前合同集合。
  同一运单号在 `settlements` 中的存在性即"已结算"判定，重复结算报错。
- **并发**：单一 `sync.Mutex` 包住每个公开方法的整体。所有操作因此可线性化，
  任意并发交错都等价于某个串行顺序；无锁/分片锁被放弃（见下）。
- **确定性**：`QuoteAll` 先收集再显式排序（总价升序、承运商编号升序，
  失败项按承运商编号升序附后），不依赖 map 迭代顺序；相同操作序列重放
  得到完全相同的明细（随机对照测试中用第二个实例重放验证）。
- **拒绝优先级**：`Price` 内按 参数非法 → 无合同 → 时刻未覆盖 → 超出承运范围
  的顺序检查；`AddContract` 先校验参数再查重叠。无合同（该键没有任何合同）
  与时刻未覆盖（有合同但时刻落在间隙）用不同 `ErrKind` 区分。
- **承运范围判定**：用实际重量与最大单边尺寸，在计费之前完成；
  计费重量（可能远大于实际重量）不参与该判定。

## 被放弃的方案

- **全量扫描 + 逐档循环**：最直观但计价开销随合同总数与档数线性增长，
  不满足复杂度要求；仅保留为测试中的独立朴素模型用于对照。
- **区间树 / 平衡树（如红黑树）**：能支持重叠区间，但本场景区间互不重叠，
  排序数组 + 二分更简单、缓存友好且足够；引入额外数据结构属于过度设计。
- **允许阶梯有空隙/任意边界**：会让"档内部分"出现非整数计重单位，
  需要定义额外的舍入规则，增加二义性；改为在合同添加时校验拒绝。
- **结算时重新计价**：若结算金额在结算时刻才计算，则合同变更会影响
  已计价未结算运单的结算额，语义含糊；选择"结算即固化当时的计价结果"。
- **分桶锁 / 读写锁**：读多写少场景下 `RWMutex` 或按线路分锁能提升并发度，
  但会引入跨桶不变量（结算表、运单报价表是全局的）与死锁风险；
  当前单锁实现已满足"等价于某个串行顺序"，且基准显示单次计价约 130ns，
  复杂度优化收益不值得牺牲可验证的正确性。

## 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache   # 默认缓存目录只读时

go test ./... -race           # 全部单元测试 + 随机对照 + 竞态检测
go test ./freight/ -run TestRandomOps -v   # 查看随机操作的输入/输出/判定日志
go test ./freight/ -run xxx -bench .       # 复杂度基准
go vet ./... && gofmt -l .
```

- **边界测试**（`freight/system_test.go`）：生效区间两端取等、相接合同、
  体积/实际重量互换、取整边界、跨档累进、最低收费恰等、两项超限独立、
  结算后合同变更、拒绝优先级、并发下至多结算一次。
- **随机对照**（`freight/model_test.go`）：固定种子生成 4000 个随机操作
  （加合同/计价/结算/询价），同时驱动优化实现、第二个重放实例与独立编写的
  朴素模型（线性扫描 + 逐档循环），逐步比对错误类别与完整明细；
  日志打印每次操作的输入、输出与判定依据。
- **复杂度证明**（`freight/bench_test.go`）：
  - `BenchmarkPriceVsTotalContracts`：系统内合同总数 100 → 1,000,000，
    单次计价耗时约 134ns → 145ns，近似平坦；
  - `BenchmarkPriceVsContractsPerLane`：同线路合同数 10 → 100,000，对数增长；
  - `BenchmarkPriceVsTiers`：阶梯档数 8 → 131,072，耗时近似平坦。
