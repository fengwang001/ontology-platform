# 多人对局房间生命周期服务 — 设计说明

## 目标与范围

`room` 包（`room/`）实现单个多人对局房间的完整生命周期：

```
等待 -> 倒计时 -> 进行中 -> 结算中 -> 已结束 / 已作废（终态）
```

关键要求是在**惰性计时**下可精确复现：倒计时到期、上报期限到期都不依赖
真实定时器，而是由调用方传入的逻辑时钟 `now` 驱动，任意操作序列重放结果一致。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `room/types.go` | 状态、拒绝码、作废原因、配置、快照等公共类型 |
| `room/clock.go` | 单调逻辑时钟：范围校验、回退检测、推进 |
| `room/roster.go` | 在室名册：成员、加入次序、就绪计数器、房主迁移 |
| `room/countdown.go` | 倒计时值对象：起算/到期时刻、到期判定 |
| `room/match.go` | 对局名单与上报计票：中途退出、改报、票型统计 |
| `room/room.go` | 编排者：互斥串行化、惰性到期、校验优先级、各操作入口 |

`Room` 组合上述模块：每个公开方法先经 `beginOp` 做公共前置
（参数 -> 时钟 -> 惰性到期 + 推进时钟），再按优先级做阶段、名册、
权限、冲突校验，最后把状态变更委派给对应模块。

## 关键取舍

### 惰性到期（lazy expiry）

每个操作与查询在执行自身逻辑**之前**，先判断倒计时/上报期限是否到期，
到期则以**到期时刻**（而非当前 `now`）完成跃迁：

- 倒计时到期 -> 以 `expiry` 为开局时刻进入进行中；
- 上报期限到期 -> 按多数一致规则当场裁决（结束或超时作废）。

恰等于到期时刻视为已到期（`now >= expiry`）。这样"到期先于操作生效"
是确定性的：同一操作序列无论何时执行都得到相同结果。

### 校验与副作用顺序

一次操作的处理顺序严格为：

1. **参数非法**（空标识、`now` 越界）——拒绝，不做任何处理；
2. **时钟回退**（`now` 小于上一次被接受的值）——拒绝，不做任何处理；
3. **惰性到期处理 + 推进时钟**——只要通过前两步就执行，无论最终是否被接受；
4. 阶段不允许（终态报"已终止"）-> 玩家不在室/不在对局名单 ->
   权限不足（非房主）-> 状态冲突（已就绪再就绪、已满、已加入）。

一次拒绝只报告按该顺序排第一的原因；第 4 步的拒绝不产生除
"到期处理 + 时钟推进"外的任何变化。

### O(1) 就绪条件与有界扫描

- 全体就绪判断用 `readyCnt == len(members)` 计数器完成，O(1)，
  不随在室人数线性增长；
- 房主迁移、开局建名单、计票、快照排序都是扫描当前在室/名单成员，
  上界为 U≤20 的常数，不随历史事件数增长；
- 内部 `work` 计数器记录所有循环迭代次数，测试据此**可验证地**证明
  复杂度上界（见下文"本地验证"）。

### 并发模型

一把 `sync.Mutex` 串行化所有操作与查询。由于所有状态都在单房间对象内、
单操作路径短（常数级），互斥锁的串行化天然满足"并发调用等价于某个
串行顺序"，无需更复杂的演员模型或分片锁。

## 被放弃的方案

- **真实定时器 / `time.AfterFunc`**：到期时刻依赖调度，无法精确复现，
  且与"惰性到期、恰等于视为到期"的语义冲突。放弃。
- **事件溯源（追加事件日志 + 重放）**：天然可复现，但状态查询随历史
  事件数线性增长，违反性能约束。放弃（改为原地状态 + 计数器）。
- **有序结构（堆/平衡树）维护房主继承顺序**：U≤20 时扫描即是常数，
  引入有序结构只增加复杂度。放弃。
- **上报资格用"名单成员且未退出"动态推导**：与"取消上报资格"语义一致，
  但中途退出者同时移出在室名册，`matchPlayer.inRoom` 单标志即可表达，
  无需独立资格表。采用单标志。
- **结算中允许 Leave**：规范未定义，且会改变"在室对局玩家数"这一多数决
  分母，引入歧义。选择拒绝（阶段不允许），并在文档中显式记录该决定。

## 语义备忘（实现中固化的解释）

- 倒计时起算时刻 = 使"人数≥L 且全体就绪"成立的那个操作的 `now`；
  等待阶段任何操作完成后条件成立即进入倒计时（含最后一名未就绪者离开）。
- 倒计时期间：加入/取消就绪立即退回等待；离开仅当破坏条件才退回，
  否则起算时刻不变。
- 房主离开（任何阶段）迁移给在室玩家中加入次序最早者；进行中离开者
  为中途退出：保留在对局名单（可被上报为胜者），取消上报资格。
- 进行中在室对局玩家 < 2 立即作废（`insufficient_players`）。
- 期限到期仍未全体上报：已上报者全部一致且人数严格多于在室对局玩家
  一半 -> 以该胜者结束，否则作废（`timeout`）。
- 胜者不在对局名单、上报者不在室，统一归入"不在室/不在对局名单"拒绝码。

## 本地验证方法

```bash
# 全量测试（含竞态检测）
go test -race ./room/

# 定向场景（倒计时边界、房主迁移、裁决规则、拒绝优先级等）
go test ./room/ -run 'TestCountdown|TestSettle|TestExpiry' -v

# 差分对照：1500 组随机序列 vs 独立朴素模型，打印覆盖统计
go test ./room/ -run TestDifferentialAgainstNaive -v

# 复杂度证明：每循环工作量恒定、与历史无关
go test ./room/ -run 'TestWorkUnits|TestMatchPath' -v

# 基准
go test ./room/ -bench . -run '^$'
```

验证层次：

1. **定向测试**（`room/room_test.go`）：逐条覆盖规范要求场景——到期恰等于
   与差一秒、倒计时中离开条件仍成立、房主迁移后原房主中途退出、不足两人
   作废、全体一致/不一致、超时过半/不过半、改报、到期先于操作、拒绝优先级、
   被拒操作仍推进时钟、空房作废、终态拒绝，每个用例打印判定依据。
2. **差分测试**（`room/differential_test.go` + `room/naive_test.go`）：
   独立朴素模型（线性扫描、不共享任何实现逻辑）与被测实现跑 1500 组
   随机操作序列（含时钟回退与非法参数注入），逐步比较拒绝码与完整快照；
   尾部按状态驱动收敛到终态，保证 `ended`/`dispute`/`timeout` 均被覆盖，
   并断言所有状态与拒绝码至少出现一次。失败时打印完整输入序列、
   双方输出与首个分歧点。
3. **复杂度证明**（`room/work_test.go`）：实现内置 `work` 循环计数器，
   测试断言 2 万个循环每循环工作量**严格相等**（与历史事件数无关），
   且对局/结算路径平均每操作工作量有常数上界。
4. **并发**：`TestConcurrentOps` 在 `-race` 下跑 8×500 并发操作，
   验证无数据竞争、无 panic、所有拒绝均有合法编码。
