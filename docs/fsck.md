# 块文件系统映像一致性检查与修复器（fsck）

`fsck` 包实现对一个简单块文件系统映像的一致性检查（`Check`）与修复
（`Repair`）。映像布局：

```
块 0        超级块（魔数 ONTOFS01、版本、布局字段、CRC32 校验和）
块 1..      索引节点表（每节点 64 字节：类型、链接计数、大小、12 个直接块指针）
...         块位图（每块 1 位，元数据块恒为已用）
...         数据块（文件内容 / 目录项，目录项 32 字节：节点号 + 28 字节名）
```

根目录固定为节点 0，恢复目录名为 `lost+found`。

## 不一致类别与判定

发现项按类别声明顺序、再按节点号（然后块号、名称）排序，同一映像反复
检查得到逐字节相同的发现清单。

| 类别 | 判定依据 |
| --- | --- |
| `shared-block` | 同一数据块出现在多个已分配节点的块列表中 |
| `dangling-dirent` | 目录项指向未分配或越界的节点 |
| `multi-parent-dir` | 同一目录节点被多个父目录的有效目录项收录 |
| `unreachable-inode` | 已分配节点从根目录沿有效目录项不可达 |
| `bad-link-count` | 节点链接计数不等于实际收录它的目录项数（根目录约定为 1） |
| `bitmap-mismatch` | 位图位与“元数据块已用 + 实际被引用数据块”不一致 |

## 修复顺序（固定）

修复在内存副本上按以下顺序执行，成功后通过“临时文件 + fsync +
rename”原子替换原映像；任何失败或注入中断（`RepairOptions.FailAt`）
都保证原映像逐字节不变。

1. **共享块**：块归引用它的节点号最小者；其余节点各取最低号空闲块并
   复制原块内容；无空闲块则从该节点块列表截除该块并报告数据丢失
   （`RepairLog.DataLoss`）。越界块指针与节点内重复指针一并清除。
2. **悬空目录项**：删除指向未分配节点的目录项。
3. **多父目录**：子目录只保留父目录节点号最小者中的目录项，其余删除。
4. **不可达节点**：有内容（文件有块 / 目录有项）的挂到恢复目录下、以
   节点号命名；无内容的释放。不可达目录子树只挂顶层；互成环的目录挂
   环中最小节点号，并断开其余指向它的入边以保证单一父目录。恢复目录
   不存在时在根下新建。
5. **链接计数**：改为实际收录数（根目录无引用时记 1）。
6. **位图**：按实际引用重建。

修复后的映像满足全部结构不变量，再次检查零发现；同一映像反复修复得
到逐字节相同的结果映像。

## 整体拒绝（可区分原因）

| 错误 | 条件 |
| --- | --- |
| `ErrCorruptHeader` | 魔数 / 版本 / 校验和 / 布局字段损坏 |
| `ErrRootNotDir` | 根节点不是目录 |
| `ErrRecoveryNameConflict` | `lost+found` 名被非目录节点占用 |
| `ErrNoFreeInode` | 需新建恢复目录但已无空闲节点 |
| `ErrMounted` | 映像正被写挂载 |

拒绝或中途注入中断时，原映像逐字节不变。

## 并发模型

`Volume` 使用读写锁：多个只读 `Check` 可并发调用；`Repair` 与
`MountWrite` 互斥（写挂载期间修复返回 `ErrMounted`）。

## 本地验证

```bash
# 单元测试（含竞态检测），日志打印输入、输出与判定依据
go test -race -v ./fsck/

# 代码检查
gofmt -l .
go vet ./...

# CLI 冒烟
go run ./cmd/fsck format /tmp/fs.img -blocks 64 -inodes 16
go run ./cmd/fsck check /tmp/fs.img
go run ./cmd/fsck repair /tmp/fs.img
```

测试覆盖：两节点共享一块、空闲不足时截除、不可达目录环、目录被两个
父目录收录、悬空目录项、仅位图不符、修复后再检查零发现、修复中途中
断（`mid-write` / `before-rename`）、五类整体拒绝、并发只读检查、反
复修复的逐字节确定性。
