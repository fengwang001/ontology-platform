# 角色委托链模块设计说明

包路径：`ontology/delegation`

## 1. 需求与语义模型

### 1.1 数据模型

- **权限**：`PermissionSet = map[对象类型]ObjectPerm`，`ObjectPerm` 由属性集合
  （属性级权限）与行集合（行级权限）构成；子集关系按两个维度同时判定。
- **原始权限**：主体直接持有的权限，通过 `GrantBase`（并集授予）与
  `ShrinkBase`（差集收缩）变更。每次变更仅向该主体的事件流追加一条
  `baseEvent{at, principal, grant, perms}`，永不修改历史。
- **委托记录**：`Delegation{ID, Delegator, Delegatee, Subset, Start, End,
  AllowRedelegate, CreatedAt, RevokedAt}`。记录仅追加；撤销只是补上
  `RevokedAt` 时间戳，不删除记录。

### 1.2 核心语义

主体 `p` 在时刻 `t` 的**有效权限**递归定义为：

```
effective(p, t) = baseAt(p, t)
                ∪ ⋃ { d.Subset | d.Delegatee = p, d 在 t 生效,
                                 d.Subset ⊆ effective(d.Delegator, t) }
```

- **级联收缩、整体失效**：委托 `d` 生效的前提是其声明子集被委托方当前
  有效权限**完整**覆盖。上游收缩后若不再完整覆盖，`d` 整体不贡献任何
  权限（而非保留交集）；该判定沿链递归，天然完成级联。
- **独立来源豁免**：`effective` 对所有来源取并集，因此只要委托方另有
  独立来源仍能覆盖 `d.Subset` 的全部内容，`d` 继续生效。
- **多路径独立有效性**：并集语义直接保证"任一有效路径即放行"，撤销
  一条路径不影响其他路径。
- **有效期级联**：`d` 仅在 `t ∈ [Start, End)` 且未撤销时生效；任一环
  过期即断开该环及其下游。
- **可再委托权限**：

```
redelegatable(p, t) = baseAt(p, t)
                    ∪ ⋃ { d.Subset | d 在 t 对 p 生效且 d.AllowRedelegate }
```

### 1.3 委托声明校验（固定且唯一的错误优先级）

`Delegate` 按以下顺序校验，任一失败都不改变任何状态：

| 顺序 | 错误 | 条件 |
|---|---|---|
| 1 | `ErrSubsetExceeds` | 声明子集 ⊄ 委托方当前有效权限 |
| 2 | `ErrRedelegateNotAllowed` | 声明子集 ⊄ 委托方当前可再委托权限 |
| 3 | `ErrCycle` | 受托方沿现存委托边已可达委托方 |
| 4 | `ErrExpired` | `End <= Start` 或 `End <= now` |

成环检测沿"委托方 → 受托方"方向、在"未撤销且 `End > now`"的边上做
可达性搜索（对未来生效的边保守地计入，防止未来成环）。被拒绝的声明
不写入任何索引，对既有委托链零影响。

### 1.4 访问判定与历史不可追溯

- `Decide` 总是针对请求时刻 `At`（零值表示当前）**重新计算**
  `effective`，不缓存任何历史判定结论。
- 全部状态变更（授权、收缩、委托、撤销）仅以追加方式记录，因此任意
  历史时刻的权限与委托状态都可被精确重放：对同一历史时刻的重复判定
  永远返回相同结论，后续收缩/撤销/过期均无法追溯改变它。
- 判定放行时返回 `Witness`：支撑该结论的委托记录 ID 链（可能含多条
  链），供审计与日志记录"据以裁决的委托链依据"。

## 2. 关键取舍

1. **求值时计算 vs 写入时物化**：选择在判定时沿委托图实时求值。
   收缩、过期、撤销无需任何"级联更新"写路径——级联效应由递归定义
   自动成立，写路径 O(1)，且不存在物化视图与真实状态不一致的窗口。
2. **单互斥锁 vs 细粒度锁**：所有公开方法共用一把 `sync.Mutex`。
   这直接给出可线性化语义（任意并发调用等价于按锁序串行执行），
   实现简单、无死锁风险。判定与写入互相阻塞是本模块规模下可接受
   的代价；若未来读远多于写，可换成 `RWMutex` + 不可变快照。
3. **整体失效 vs 交集收缩**：严格按需求实现整体失效——委托声明是
   一个整体承诺，上游不再完整支撑时整条失效，避免"部分权限幽灵
   存续"造成的审计歧义。
4. **成环检测只算活边**：已撤销或已永久过期的边不参与成环检测，
   避免历史垃圾永久阻塞合法的新委托。

## 3. 被放弃的方案

- **缓存/物化历史判定结果**：被明确禁止（判定不得基于历史缓存假设），
  且缓存会在收缩后产生一致性难题，故完全不做判定缓存。
- **写入时维护传递闭包**：每次收缩/撤销都要级联重写下游物化记录，
  写放大严重，且难以保证历史时刻视图不被污染；放弃。
- **删除式撤销**：物理删除被撤销的委托会破坏历史判定的可重放性，
  改为追加 `RevokedAt` 时间戳。
- **交集式收缩语义**：与需求"整体失效"冲突，放弃。
- **完整事件溯源 + 每次全量重放**：语义等价但判定的遍历开销会随
  事件总数增长，违反遍历复杂度要求；仅原始权限采用按主体分桶的
  事件流（重放范围限于该主体自身的事件）。

## 4. 遍历复杂度与可观测证明

`byDelegatee` 索引使判定遍历只沿"受托方 → 委托记录 → 委托方"的
反向边进行，检查的记录数只与实际支撑该主体的委托路径规模相关，
与系统中累计记录总数无关。该性质以可观测方式暴露：
`Decision.NodesVisited` 返回本次判定实际检查的记录条数，
`TestNodesVisitedIndependentOfTotalRecords` 在灌入 2000 条无关委托
前后断言该计数不变。

## 5. 并发与审计

- 并发：单一互斥锁保证可线性化；`TestConcurrentLinearizable` 在
  `-race` 下混合并发执行四类操作，校验日志与调用一一对应、委托 ID
  无重复分配。
- 审计：`Logger` 接口在每次调用（含被拒绝的调用）记录输入、最终
  输出、错误与见证链；`JSONLogger` 提供 JSON Lines 实现。

## 6. 测试策略

- 单元测试：级联收缩（整体失效/独立来源豁免）、有效期级联、多路径
  独立有效性、成环检测与既有链不受影响、四类错误及其优先级、历史
  判定不可追溯、判定不缓存、遍历计数与记录总数无关。
- 对照测试：`Naive`（`naive.go`）是独立维护的朴素参照实现——无索引、
  无记忆化、全表扫描、每次从头重算。`TestDifferentialAgainstNaive`
  在多组随机种子下生成数百步随机操作序列（授权/收缩/委托/撤销/时钟
  推进），逐步比对两个实现的委托错误、委托 ID 与全部主体在多个
  （含历史）时刻的判定结论，并断言四类错误均被真实触发。

## 7. 本地验证方法

```bash
go build ./...
go vet ./...
gofmt -l .
go test -race -count=1 ./...
go test -run TestDifferentialAgainstNaive -v ./delegation/
```
