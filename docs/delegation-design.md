# 角色委托链模块设计说明

包路径：`ontology/delegation`。本文档记录核心模型、关键取舍、被放弃的方案与本地验证方法。

## 1. 模型与核心语义

- **权限**：`Permission{ObjectType, Attribute, RowScope}`，表示某对象类型上的一条属性级 + 行级权限；权限子集即该结构的集合（`PermissionSet`），子集关系为集合包含。
- **直接权限**：主体原始持有的权限，以“持有区间”形式记录（授予序号 → 收缩序号），支持任意历史时刻回放。
- **委托记录**：委托方、受托方、权限子集、有效期 `[ValidFrom, ValidTo)`、是否允许再委托、声明序号、撤销序号。记录创建后不可变，撤销只追加标记。

派生出两个核心概念（对任意状态截止点与判定时刻定义）：

- **实际权限 effective(s)** = 直接权限 ∪ 所有“生效且被完整支持”的入向委托的子集。
- **可委托权限 delegatable(s)** = 直接权限 ∪ 所有“生效、允许再委托、且被完整支持”的入向委托的子集。

其中委托 d “被完整支持”指 `d.subset ⊆ delegatable(d.delegator)`。注意支持条件用的是**可委托权限**而非实际权限：一条委托本质上是一次再委托，委托方必须握有再委托权。由此自然得到：

- **全有或全无失效**：子集不再被完整支持时，该委托整体不贡献任何权限（不保留交集）。
- **级联收缩**：上游任何一环收缩/撤销/过期，都会在下游的 `delegatable` 中传播，下游委托随之整体失效。
- **独立来源豁免**：只要委托方的 `delegatable`（来自任意来源的并集）仍完整覆盖子集，下游委托就继续有效。
- **多路径独立**：访问判定取所有有效路径的并集，一条路径被撤销不影响其他路径。

## 2. 关键取舍

### 2.1 惰性（拉取）求值，而非主动（推送）级联

收缩、撤销、过期发生时**不**主动扫描并标记下游委托；所有失效都在判定时沿委托图重新计算得出。

- 优点：写操作 O(1)，不存在“标记传播中途崩溃”的一致性问题；历史语义天然正确（同一套求值函数作用于不同状态截止点）；“立即级联”在可观测层面等价——任何后续判定都会看到收缩结果。
- 代价：判定要遍历上游子图，通过邻接索引 + 单次判定内记忆化控制成本（见 §2.4）。

### 2.2 事件溯源式历史，而非结论缓存

直接权限以持有区间存储，委托记录保留声明/撤销序号，每次调用分配全局单调序号 `seq` 并记录 `(seq, time)`。`CheckAt(t)` 把 `t` 映射到状态截止序号后，用与实时判定**完全相同**的求值逻辑重算。历史事件永不删除、永不修改，因此历史结论在后续收缩/撤销/过期后保持不变（不可追溯性由“只追加”保证，而非靠冻结结论）。实时 `Check` 也永远重新计算，不读取任何历史判定缓存。

同一时钟刻内发生多个事件时，as-of 语义为“包含所有时间 ≤ t 的事件”，次序由 `seq` 决定；需要区分同一刻内先后的事件时，应推进时钟（测试均如此处理）。

### 2.3 保守成环检测

声明时在**全部未撤销委托**构成的图上判断新增边是否成环（不论其有效期）。这保证任意时刻的“生效委托子图”都是 DAG，求值递归必然终止，且不存在“两条边在不同时间段各自合法、叠加后成环”的时间维度漏洞。代价是会拒绝一些按精确时间区间看并不冲突的声明（见 §3）。

### 2.4 遍历开销与可观测证明

委托记录按受托方建立入向邻接索引（`incoming`），判定只从目标主体沿入边向上游走，单次判定内对 `effective`/`delegatable` 按主体记忆化，遍历的委托记录数 = 目标主体上游可达子图的边数，与系统中累计委托总数无关。`CheckResult.NodesVisited` 把该计数作为可观测证据暴露；`TestTraversalBoundIndependentOfTotalRecords` 在灌入 2000 条无关委托前后断言计数逐位不变，且不超过链长的常数倍——这就是“不依赖实现细节的可观测证明手段”。

### 2.5 单互斥锁串行化

所有公开方法在同一把 `sync.Mutex` 下执行，每次调用分配递增 `seq` 并写日志。并发调用的结果按定义等价于 `seq` 序的串行执行（线性化）。`TestConcurrentLinearizable` 把并发期日志按 `seq` 重放进朴素实现，逐项比对输出，从外部验证了该性质。读多写少场景未来可换 `RWMutex` + 快照，但当前规模下简单性优先。

### 2.6 错误优先级

`Declare` 严格按固定顺序检查并只汇报第一个失败：

1. `ErrScopeExceeded`：子集 ⊄ effective（委托方实际拥有范围）；
2. `ErrRedelegationDenied`：子集 ⊆ effective 但 ⊄ delegatable（上游不允许再委托）；
3. `ErrCycle`：新增边成环；
4. `ErrExpired`：有效期已结束。

所有校验在任何状态变更之前完成，被拒绝的声明不产生副作用（有测试专门断言）。`ErrInvalidArgument`（空子集、非法有效期区间等）属于输入校验，不属于上述四类语义错误。

## 3. 被放弃的方案

- **主动级联标记（推送式失效）**：收缩时沿下游扫描并给委托打“已失效”标记。放弃原因：写路径重、需要处理部分失败；“失效”其实依赖判定时刻（有效期、多来源并集），静态标记表达不了，最终仍要在判定时重算。
- **收缩后保留交集**：把下游委托收缩为与剩余权限的交集。被需求明确否定（全有或全无），且交集语义会让“独立来源豁免”的判定含糊不清。
- **按有效期精确成环检测**：只拒绝“存在某个时刻使生效边成环”的声明。更宽松但实现复杂、边界情况多（未来生效的边与现有边的时间窗交叠），收益小，故采用保守方案并记录此行为（`TestCycleConservativeOnExpiredEdges`）。
- **判定结果缓存 / 物化有效权限表**：与“判定时刻重新计算”“历史结论不可追溯”的要求冲突，且需要失效传播（回到推送式问题）。放弃。
- **读写锁 + 无锁读**：在事件溯源结构上实现快照读复杂且收益不明，单互斥锁已满足线性化要求。

## 4. 日志与审计

每次调用（含查询）都产生一条 `LogEntry`：调用类型、全部输入、输出（判定结果/错误）、以及判定为允许时的**委托链依据** `Witness`（自目标主体向上游的委托 ID 序列，末端为直接权限）。`Recorder` 接口可对接任意审计后端，测试用 `MemoryRecorder`。

## 5. 本地验证方法

```bash
# 全量测试（含差分、并发、遍历上界）
go test ./...

# 竞态检测
go test -race ./...

# 仅差分对照（5 个随机种子 × 3000 个随机操作）
go test -run TestDifferentialAgainstNaive ./delegation/

# 覆盖率
go test -coverprofile=coverage.out ./... && go tool cover -func=coverage.out
```

测试分层：

- `service_test.go`：级联收缩、全有或全无、独立来源豁免、多路径独立、成环检测（自环/长链/撤销边/过期边）、有效期边界、四类错误优先级、拒绝无副作用、历史不可追溯、日志完整性。
- `differential_test.go`：
  - `TestDifferentialAgainstNaive`：随机委托链与变更序列上，与独立朴素实现（全量扫描 + 不动点迭代，不共享求值代码）逐项对照声明错误、实时判定、历史判定；
  - `TestConcurrentLinearizable`：并发混合调用后按日志串行重放比对；
  - `TestTraversalBoundIndependentOfTotalRecords`：遍历计数的可观测上界证明。
