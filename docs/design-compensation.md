# 动作副作用补偿回滚子系统 — 设计说明

代码位于 `ontology/compensate`，无第三方依赖，仅用标准库实现。

## 1. 模型与关键对象

- `Graph`：对象实例（属性 map + `Version` 版本戳）、链接实例、污染表、
  以及资源锁表。所有读写都经过一个单容量 channel 互斥量串行化，
  因此每个图原语都是"检查 + 提交"原子的。
- `Action` / `SubOp`：动作是有序子操作序列。子操作三类：
  `set_attrs`（改属性集）、`create_link` / `delete_link`（建/删链接）、
  `validate`（级联到另一实例的只读校验钩子，经 `Checker` 接口注入）。
- `Engine.Execute`：一次动作的唯一入口，三阶段：预检 → 前向生效 → 反向补偿。
- `NaiveModel`：独立实现的朴素顺序补偿模型，仅共享输入/输出类型，
  不共享任何引擎代码，作为随机对拍的 oracle。

## 2. 逐条需求的落地方式

1. **有序生效**：前向阶段严格按下标 0..n-1 执行，前一步返回后才到下一步。
2. **生效与逆操作登记同处一个不可分割单元**：每个图原语
   （`setAttrsIfExists` 等）在同一个临界区内完成"前置检查 + 变更 +
   返回变更前快照"；`applyAndRegister` 在同一调用帧内用该快照构造逆操作
   闭包并压入本次动作私有的 LIFO 栈。帧返回前不存在"已生效未登记"或
   "已登记未生效"的可观察中间态。登记号由全局单调计数器 `regSeq` 分配，
   并发流程间不重复、不缺失。
3. **只补偿已生效步骤，严格逆序**：失败的子操作不产生登记项；其后的操作
   永不执行。补偿从栈顶（最后生效项）向栈底逐个执行。
4. **补偿不中止 + 汇总 + 状态保留**：某个逆操作返回失败时记录
   `CompFailure`，继续执行其余逆操作。一旦某资源的逆操作失败，
   该资源被加入 `blockedTokens`，更早子操作若作用于同一资源，则该逆操作
   被处理但不允许再改图（记录为补偿失败），保证"失败子操作对应的图状态
   保留在补偿失败前的样子，不被进一步改动"。
5. **污染态预检拒绝**：任何动作执行任何子操作之前，先检查全部涉及实例；
   命中污染立即以 `contaminated` 拒绝（甚至早于加锁），不可能先生效再中止。
   污染只能由 `Engine.Repair`（显式修复）清除。
6. **异常不穿透补偿流程**：逆操作闭包内层 `recover()` 把 panic 转成该环节
   的补偿失败记录；前向阶段的 panic 同样转成该子操作的业务失败。
7. **最早污染编号永久保留**：污染表为 `实例 -> 第一次补偿里最早失败的
   子操作编号`，写入规则为"仅当不存在或新值更小才更新"，后续污染永不覆盖；
   `PollutionIndex` 永远返回最早编号。
8. **并发不相交子集等价串行**：采用"全资源预声明 + 全局固定序加锁"
   （资源 token 字典序排序后一次性 `tryAcquire`）。不相交动作的 token 集
   不相交，可并发通过；相交动作至多一个拿到全部锁。由于锁序全局一致，
   不会死锁；任何并发交错都对应某个全序的串行调度。登记号来自原子计数器，
   跨流程无重复/缺失。随机对拍（`TestDifferentialConcurrentDisjoint`）
   在 `-race` 下验证最终世界与朴素模型串行结果一致。
9. **争用先拒绝、零改动**：争用判定发生在预检期（任何子操作之前），
   被拒动作没有执行任何图原语，因此属性、时钟戳、版本号均不变。
   `TestConcurrentContentionRejectsBeforeMutation` 与
   `TestDifferentialSameSubsetContention`（用阻塞钩子强制真实时间重叠）
   校验版本/属性不变。
10. **补偿开销不随历史成功补偿总次数增长**：逆操作只存在于每次动作私有的
    栈上，随栈长 O(k)（k = 本次动作已生效子操作数），动作结束栈即丢弃；
    不存在全局补偿历史，选取下一条逆操作是 O(1) 的栈顶弹出。
    可直接从代码结构证明：`compensate` 只接收本次栈，不引用任何跨动作存储。
11. **固定优先级**：`contaminated(3) > business_reject(2) > contention(1) >
    compensation_failed(0)`，由 `priorityRank` / `HigherReason` 唯一实现。
    预检顺序（污染→争用）与补偿后的归类（业务拒绝不被补偿失败降级）
    都遵循同一优先级表，与"补偿是否发生/成功"完全无关。

## 3. 关键取舍

- **预声明全量加锁（saga + 严格 2PL 混合）而非运行中逐操作加锁**。
  需求要求争用拒绝必须"零可观察改动"，纯 saga 的延迟加锁做不到
  （会先改后回滚）。预检期一次性按全局序拿全量资源，既保证拒绝发生在
  首个副作用之前，又用固定锁序消除死锁。代价是并发度保守：同一资源上
  不同键的操作也会互相排斥，但这是满足"不允许先改动后回滚"的直接结果。
- **逆操作为"检查-提交"原子原语，而非可变补偿日志两阶段提交**。
  属性逆操作恢复快照与旧版本号；链接逆操作恢复/删除具体记录。
  失败逆操作若前置条件不满足，原子地不改任何状态，天然满足
  "失败环节状态保留"。
- **失败逆操作之后，同资源的更早逆操作"处理但不改图"**。这是对
  "补偿不得中止"与"失败环节状态不得被进一步改动"两条要求的同时满足：
  它们仍被逐一处理并计入失败汇总，但以跳过变更的方式保护现场。
- **校验钩子建模为只读**：`validate` 不改图，逆操作为 no-op，但仍分配
  登记号并入栈，使"生效/登记成对"在形式上统一。
- **失败原因优先级高于补偿结果**：业务拒绝触发的补偿即使部分失败，
  动作主判定仍报业务拒绝（补偿失败明细完整保留在 `CompFailures`），
  避免补偿噪声掩盖用户最需要处理的拒绝原因。

## 4. 被放弃的方案

- **全局补偿历史 + 遍历查找逆操作**：直接违背"开销不随历史成功补偿次数
  增长"，放弃，改为每动作私有 LIFO 栈。
- **逐操作运行时加锁（抢到就改）**：无法保证争用拒绝先于改动，放弃，
  改为预检期全量加锁。
- **补偿遇错即中止**：会留下更多未补偿副作用且违背"继续尝试其余逆操作"，
  放弃；panic 也同样不允许中止，故逆操作统一 `recover`。
- **用 goroutine + 回滚 channel 实现分布式 saga**：本任务范围内对象图
  在单进程内，引入分布式协调只会增加不可验证窗口；并发正确性已能用
  锁序 + oracle 对拍证明，故不采用。
- **污染编号保留最近一次**：与"必须返回最早编号"冲突，改为首次写获胜。

## 5. 测试与本地验证

- 覆盖用例（`engine_test.go`）：单环节失败、失败发生在每个位置、
  逆操作返回失败、逆操作 panic、污染预检拒绝（版本不变）、
  最早污染编号多次卷入、不相交子集并发等价串行、同实例/同链接争用
  零改动不变量、固定优先级、登记号不重复。
- 随机对拍（`differential_test.go`）：固定种子集合（可复现）下随机生成
  1–5 个子操作的动作序列与 apply/undo 故障（返回失败或 panic）注入点，
  逐步比对 Engine 与 `NaiveModel` 的判定、属性、版本、链接、污染表；
  并包含 30 组不相交并发对拍与阻塞钩子强制重叠的争用对拍。
- 逐步打印（`logging_test.go`）：打印动作输入、注入点、每一步
  生效/撤销结果与最终判定依据；顺序对拍失败时同样输出完整输入与轨迹。

```bash
export PATH=/tmp/goshim:$PATH   # 若 go 不在 PATH
go test -race -v ./ontology/compensate
go test -race -count=5 ./ontology/compensate
go vet ./... && gofmt -l .
```
