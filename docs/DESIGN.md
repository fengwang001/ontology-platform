# 住院病区感染病例接触者追踪与隔离期判定 — 设计说明

## 1. 模块划分

| 包 / 文件 | 职责 |
| --- | --- |
| `contacttracing/model.go` | 领域常量与数据结构：`Stay`、`Case`、状态枚举、阈值（120 分钟 / 48 小时 / 7 天 / 3 天）。 |
| `contacttracing/store.go` | 追加式不可变存储：按患者与病房双索引的住宿、病例、全局单调时钟；一把 `sync.RWMutex`。 |
| `contacttracing/derive.go` | **纯函数式推导**：由“当前全部登记 + now”计算单个病例的密接/次密接；按病例缓存 + 按病房/患者反向索引的失效；扫描量仪表。 |
| `contacttracing/system.go` | 对外 API：住宿追补/入住/出住、病例登记/隔离/改正/撤销、清单与状态查询；错误优先级、时钟、并发串行化。 |
| `contacttracing/errors.go` | 五类可区分错误。 |
| `contacttracing/util.go` | 标识/时刻校验、左闭右开区间求交。 |
| `naivemodel/model.go` | **独立朴素模型**：不共享主实现任何代码，每次全量重算，作为差分测试事实基准。 |
| `contacttracing/difftest/` | 1500 组随机操作序列，逐步对照两套实现并写日志。 |

## 2. 关键不变量与时间语义

- 时间为整数分钟，范围 `[0, 10^7]`；操作 `now` 单调，回退报 `CLOCK_ROLLBACK`，且被拒操作不改任何状态/时钟（校验全部在写锁内、任何写操作之前完成）。
- 区间一律左闭右开 `[in, out)`；住宿“出时刻未登记”（`CheckOutOpen`）在推导时视为持续到当前 `now`。
- 同一患者住宿区间不得有**正时长**重叠；端点相接（`out == in`）不算重叠。
- 传染期 = `[max(0, onset-2880), isolated)`，未隔离则右端为 `now`；右端可被夹到等于起点（空窗口，无接触者）。
- 密接：与病例**同病房**、落在传染期内的正时长重叠跨病房/住宿段累计 `>=120`（含等于）。
- 次密接：非病例本人、非该病例密接，与某密接在其暴露期
  `[与病例首个正重叠起点, 确诊登记时刻)` 内同病房累计 `>=120`；次密接不再向外传递。
- 最后接触时刻 = 所有正时长重叠段中最晚的右端点。
- 隔离/观察边界：密接 `lastContact+10080`、次密接 `lastContact+4320`；`now < boundary` 为在期，`now >= boundary` 为恰解除。
- 多病例叠加：在期来源中取最严等级（密接 > 次密接），解除时刻取所有来源边界的最晚值；全部过期但曾被认定 → `RELEASED`。

## 3. 核心取舍

### 3.1 “全量重算 + 按病例缓存”，而不是增量维护接触关系
接触关系会因追补、改正、撤销、出住、时钟推进而整体改变，增量维护极易产生对旧推导的隐式依赖。
因此推导写成关于快照的**纯函数** `deriveCase(caseID, now)`：

- 结果只由当前 `stays/cases + now` 决定，与变更先后无关 → 天然满足“追补/改正/撤销后结果一致”和“任意顺序一次性给出结果一致”。
- 缓存项带 `derivedAt`：只有在**同一 now** 且未被失效时才命中。时钟一推进旧结果即作废，杜绝了“用旧 now 的结论回答新 now”。
- 清单与状态查询从不修改用户输入，只触发惰性推导；因此不依赖任何历史推导结果。

### 3.2 失效范围按“病房 + 患者”收窄，而非整库失效
缓存索引只增、脏项惰性丢弃：

- `roomCase[room]`：在该病房出现过（病例传染期段或密接暴露段）的病例。
- `patientCase[patient]`：该患者作为本人/密接/次密接参与过的病例。
- 住宿变更只失效 `roomCase[room] ∪ patientCase[patient]` 命中的病例；
  病例参数变更（发病/隔离/撤销）只失效该病例自身。

### 3.3 状态查询的候选病例发现：同病房两跳闭包
状态查询不能扫全院病例，也不能只靠“推导后才建立”的反向索引（否则首次直接查密接/次密接会漏）。
关键观察：接触链条深度恰为 2 跳且每跳都是同病房
`病例本人 →(同病房)→ 密接 →(同病房)→ 次密接`。
因此对被查患者取其病房的两跳室友闭包，只在这些患者名下的病例中推导。规模只与该患者及其同病房相关记录数有关，与全院无关（见 §6 实测）。

### 3.4 并发
所有方法在同一把 `sync.RWMutex` 下串行化“时钟校验 + 状态变更 + 失效”；只读语义的查询因需要惰性建立缓存，也走同一把锁（推导无外部副作用）。因此并发执行等价于某一串行顺序，`go test -race` 通过。

## 4. 被放弃的方案

1. **持久化增量边表（contact edge store）**：维护随住宿/病例变更做差量加减的接触边。问题是发病时刻改正、出住补登、撤销都会同时影响第一圈与第二圈，差量传播需要回溯，正确性证明复杂，且仍要处理时钟推进。改为纯函数重算后，正确性只依赖一处逻辑。
2. **按时间线事件流式推进**：把追补当作“迟到事件”回放。会引入“推导依赖操作顺序”，与“结果与登记先后无关”的要求直接冲突，放弃。
3. **全局读写锁细分为分病房锁**：可提升并发度，但跨病房累计（密接跨病房）与两跳闭包需要多锁加锁顺序，复杂度高、易死锁；在正确性优先的前提下保留单锁。接口未暴露锁，后续可平替。
4. **朴素模型直接复用主实现结构体**：会使差分测试失去独立性。朴素模型单独定义数据结构、四重循环全量重算，仅通过时间区间这一稳定语义与主实现对照。

## 5. 错误优先级

每个操作都按固定顺序校验，只返回第一个错误：

1. `INVALID_PARAMETER`：空标识、时刻越界、纯结构性非法（`out<=in`、`onset>now`、`isolatedAt>now` 等）；
2. `CLOCK_ROLLBACK`：`now < 上次接受 now`；
3. `NOT_FOUND`：病例/在住记录/患者不存在；
4. `INVALID_STATE`：重复隔离、重复/撤销后操作、重复开放住宿、已存在活动病例等；
5. `STAY_CONFLICT`：住宿正时长重叠。

## 6. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache   # 本机 Go 在 /usr/local/go/bin

go test ./...                                              # 全量
go test -race ./contacttracing/                            # 竞态
go test ./contacttracing/difftest/ -run TestRandomDifferential -v
```

### 6.1 边界用例（`contacttracing/*_test.go`）
覆盖：累计恰 120 与 119、跨病房 60+60 累计、传染期起点/隔离时刻取等（含空窗口）、
最后接触 +7 天/+3 天恰解除、次密接暴露期与确诊登记时刻取等（119 不计 / 120 计）、
多病例取最严与最晚、改正发病时刻使接触者进出、追补使已解除者重新隔离、撤销病例、错误优先级。

### 6.2 与独立朴素模型对照
`TestRandomDifferential` 跑 1500 组随机序列（3–8 名患者、2–5 个病房、40–99 步），
每一步都打印输入、输出与判定依据到 `logs/random_differential.log`，并在每一步对
清单与状态做双实现断言；另有时钟回退探测验证被拒操作不改变状态。

### 6.3 两档规模对照（局部性硬证据，`TestStatus*` / `TestRecomputeScopedOnChange`）

| 场景 | 总住宿 162（小） | 总住宿 16002（大，约 99×） |
| --- | --- | --- |
| 单次状态查询扫描住宿区间数 | 6 | **6** |
| 改正发病时刻后焦点重推导扫描 | 6 | **6**，重推导病例数 = 1 |
| 焦点病房住宿追补后扫描 | 9 | **9** |

扫描量与全院规模无关，只随焦点患者与其同病房邻域变化；测试对“两档扫描量相等且规模差距 ≥10×”做断言，可重复验证。
