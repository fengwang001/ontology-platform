# HasCycle 设计说明

本体链接图上的环检测器。检测范围严格限定为「调用者当前可见且可遍历的链接
构成的子图」；子图之外的对象与链接在判定中一律视为不存在。

## 1. 模型

- 对象类型 `ObjectType`、对象 `Object{ID, Type}`。
- 链接类型 `LinkType`：
  - `Direction`：`Directed`（仅 Source→Target 可遍历）或 `Bidirectional`
    （正反两个方向都可遍历）；
  - `AllowSelf`：是否允许 Source==Target 的自环；
  - `AllowMulti`：是否允许同一对象对之间存在多条同类型链接。有向按
    `type|src->dst` 判重，双向按无序对 `type|lo<->hi` 判重；
  - 可选的端点对象类型约束。
- 权限模型 `Permissions`（按调用者保存）：
  - 存在性权限 `ExistObject[objectID]`：是否看得到对象存在；
  - 遍历权限 `TraverseLink[linkID]`：是否能沿链接遍历。

环的口径（按弧方向）：

- 长度 1：自环；
- 长度 2：u→v 与 v→u 两条弧同时存在。单条双向链接展开为一对反向弧，
  因此单独一条双向链接即构成往返环；两条反向有向链接同理；两条同向平行
  边不构成环（平行边折叠为邻接集合，多重链接不会让证据重复计数）；
- 长度 ≥3：普通有向简单环。

## 2. 判定流水线（次序不可调换）

`HasCycle(caller)` 在 `Graph.mu` 读锁下一次性完成「取状态 → 过滤 → 判定」，
得到与外部完全隔离的值拷贝快照 `visibleSubgraph`：

1. 参数校验：调用者标识必须非空白且长度 ≤128，否则返回
   `ErrInvalidCaller`，优先级最高；
2. 阶段一（存在性）：只遍历权限表中授权且图中仍存在的对象 ID，得到
   可见集合；该集合为空时直接返回「无环」（非错误），不展开任何链接；
3. 阶段二（遍历性）：仅枚举与可见对象关联的链接（`incident` 索引），
   先要求两个端点都在可见集合内（阶段一的连带剔除效果），再要求调用者
   持有该链接的遍历权限，通过者才展开成有向弧（双向链接展开两条弧）；
4. 在快照上做环判定。

两个阶段是分开的循环，先存在性、后遍历性的顺序由代码结构固定。
被剔除的链接即使是某个环的唯一必要边也不会出现该环；权限在下一次调用
前补齐，下一次调用会重新取快照、重新过滤，立即感知变化，不存在跨调用
缓存结论。

## 3. 与起始对象/遍历顺序无关的确定性

「无关」通过两个层面保证：

- API 不接受起始对象参数；所有迭代输入（Tarjan 根序、邻接序、SCC 顶点序、
  BFS 序）都按 ID 排序，map 遍历顺序无法影响控制流；
- 不返回「最先碰到的」环，而是在全部候选中选规范证据：顶点数最少；
  同长时取排序后顶点集合字典序最小。自环（1 顶点）天然最短。

证据是一个对象 ID 集合，恰好等于某个简单环上的全部顶点，不含尾巴、
孤立点或其他与环无关的对象。多重同类型链接只改变弧的存在性，证据集合
中每个对象至多出现一次。

判定算法：

1. 自环单独在阶段二收集（O(Vv) 扫描）；
2. Tarjan 强连通分量（弧按 ID 排序驱动），仅 |SCC|≥2 的分量可能含
   长度 ≥2 的环（大小 2 的 SCC 必然存在 u→v、v→u，直接给 {u,v}）；
3. 对每个候选 SCC，以分量内每个顶点为起点做 BFS 求经过该点的最短有向
   环（找到回到起点的非平凡弧即闭合），在所有候选间按规范规则择优。

## 4. 并发与线性一致性

- `Graph` 用单把 `sync.RWMutex` 保护；对象/链接增删与权限变更在写锁下
  整体生效；
- `HasCycle` 持读锁完成状态复制与两阶段过滤，释放锁后在私有快照上判定，
  因此每次调用看到的权限与链接状态等价于某个串行时刻的完整状态，
  不可能读到增删或权限变更的中间态；
- 并发多次调用与并发变更的交错结果等价于某种串行顺序（`-race` 下有
  专门压测）。

## 5. 开销不随不可见规模增长

内部度量 `Metrics`（不对外暴露，仅供内部验证/测试读取）：

- `VisibleObjects`：阶段一选出的可见对象数；
- `ScannedLinks`：阶段二实际读取（去重后）的链接数；
- `VisitedObjects` / `VisitedLinks`：判定阶段真正展开的顶点与弧次数。

关键点：

- 阶段一只遍历「权限表授权的 ID」，不扫描全图对象表；
- 阶段二只从可见对象的 `incident` 邻接索引展开。完全位于两个不可见
  对象之间的链接既不在任何可见对象的邻接表里被触达，也永远不会被
  读取（读链接内容发生在可见性检查之后）。

`TestInvisibleBulkDoesNotGrowCost` 在 3 对象/3 链接的可见环之外追加
5000 个不可见对象对与 5000 条双向链接（它们自身含大量 2 环），断言
追加前后 `VisibleObjects=3`、`ScannedLinks=3` 完全不变。

## 6. 关键取舍与被放弃的方案

- 放弃「染色 DFS 命中第一条回边即返回」：环和证据会依赖根序与邻接序，
  不满足「同一状态证据逐元素相同」。改为 SCC + 规范最短环选取，
  代价是每 SCC 额外若干次 BFS（仍为可见子图规模的多项式，且找到
  长度 2 即提前终止）。
- 放弃「先全图过滤再按调用者裁剪」：会遍历调用者不可见对象/链接，
  违反开销要求。改为由权限表驱动、从可见邻接索引展开，不可见部分
  根本不触达。
- 放弃跨调用缓存（如记忆化的有无环结论）：权限/链接变更后可能延用
  旧结论。每次调用都在最新状态上独立构建快照，零跨调用可变状态。
- 平行边不按「边的环」返回：证据契约是对象集合，平行边折叠为
  邻接成员，避免同一对象在证据中重复。
- 双向链接的 2 环口径取「两个方向均可遍历即可」：一条双向链接
  本身就提供正反两条弧，题面明确该往返计入；两条同向有向平行边
  不能往返，不计入。朴素穷举参照模型与此口径完全一致。

## 7. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache
go test -race -count=3 ./...
go test -run TestRandomDifferentialAgainstNaive -v ./ontology/
go test -coverprofile=coverage.out ./... && go tool cover -func=coverage.out
gofmt -l . && go vet ./...
```

- 边界：自环、自环被类型拒绝、单条双向链接 2 环、反向有向对 2 环、
  单向链无环、多重性约束与双向反向插入判重；
- 权限：唯一闭合边被遍历权限排除（无环）→ 补齐（有环）；存在性
  缺失时即使误授遍历权限也无环；删链后下一次调用立刻无环；
- 确定性：重复调用证据逐元素相同；随机打乱内部根序/邻接序后重放；
  两种不同创建历史给出同一证据；多环并存取最短/字典序最小；
- 并发：1 路变更 + 6 路 `HasCycle` 在 `-race` 下 500 轮，断言任何
  时刻的证据要么为 nil 要么恰好是 {a,b,c}（无撕裂状态）；
- 度量：5000 对不可见对象追加前后访问计数不变；
- 对照：600 组随机「对象/链接/方向/两级权限」场景与独立朴素穷举
  实现逐例比对布尔结论与规范证据，并将每次调用的输入、输出、证据
  记录到 `docs/hascycle-call-log.jsonl`；此外还独立校验生产证据
  集合确实能沿弧走成环且不含无关对象。
