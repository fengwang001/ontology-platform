# 本体链接图子图快照提取器 —— 设计说明

## 1. 目标与范围

给定一组**范围对象标识**（scope），从版本化主图中提取一份自洽的子图快照：

- 链接纳入规则：一条主图链接当且仅当两端对象都在**有效对象集**中时进入快照本体。
- 边界悬挂链接：恰有一端落在有效对象集中的链接不进入快照本体，其“存在且被排除”的事实进入快照附属信息。
- 权限剔除先于悬挂判定：调用者对范围对象无存在性权限时，该对象与其全部关联链接整体剔除，剔除后新产生的悬挂同样记入附属信息。

## 2. 判定次序（强约束，不可调换）

```
参数非法（空集合 > 非法标识 > 超过上限）
  └─> 权限剔除（不存在于主图的范围标识按“无法证明存在”同等处理）
       └─> 剔除后有效集合为空：返回空快照（非错误）
            └─> 正常提取：链接纳入 / 悬挂分类
```

参数非法与“剔除至空”是不同结局：前者返回 `IllegalScopeError`，后者返回
`Revision` 已确定、三个内容切片为空的 `Snapshot` 且 `error == nil`。

## 3. 关键数据结构

| 文件 | 职责 |
| --- | --- |
| `model.go` | `ID` 合法性、`ObjectType`/`LinkType`（`Directed`）、`Direction`、`Object`、`Link`、存在性权限概念 |
| `graph.go` | 版本化主图：不可变 `graphState`、写串行化、端点链接索引、变更日志 |
| `snapshot.go` | `Snapshot`、`DanglingLink`、`DanglingSource`（boundary/permission） |
| `extract.go` | 参数校验、剔除、候选收集、纳入与悬挂分类、确定性排序、内部度量 |
| `diff.go` | `Compare` 快照差异与 `Graph.Attribute` 变更窗口归因 |

## 4. 时点一致性与并发（关键取舍）

主图写路径：单一互斥锁串行化所有变更；每次提交都对当前状态做**深拷贝**，
在私有副本上应用变更并递增 `revision`，随后以一个指针赋值发布。

提取路径：`Extract` 在校验通过后只取一次不可变状态指针（`snapshotState()`），
此后所有对象、链接、权限读取都只解引用该指针。因此：

- 一次提取看到的是唯一确定时点，不会对不同范围对象呈现跨时点的混合状态；
- 提取者与写者之间无需共享锁，读写不互相阻塞（写时复制）；
- 提取与变更并发的效果等价于某个串行顺序：每次提取对应某次提交后的状态。

被放弃的方案：

1. **全局长读锁**：语义可行但写者会被长提取阻塞，且仍需显式保证多表读取一致；
   写时复制把“一致性”收敛为“一次指针读取”，正确性更易论证。
2. **多版本保留（完整 MVCC）**：支持按历史版本重放，但本需求只要求“某一确定
   时点的映像”，保留历史版本会带来无界内存与 GC 复杂度，故放弃；变更日志已足以
   支持差异归因。
3. **逐对象懒加载**：会让一次提取天然跨越多个时点，直接违反单时点约束。

## 5. 权限剔除与悬挂来源的精确规则

记请求集合 `S`，剔除集合 `R ⊆ S`（无权限或主图中不存在），有效集合 `E = S − R`。
对每条与 `E` 中对象关联的主图链接：

| 条件 | 处理 |
| --- | --- |
| 两端都在 `E` | 纳入快照本体 |
| 恰有一端在 `E`（自环除外） | 记悬挂，标注来源 |
| 两端都不在 `E` | 整体排除，不记录（含“仅通过第三个有效对象才检查到”的边） |

悬挂来源标注采用**边界优先**：

- 被排除端不在 `R`（即从未被请求进 `S`）→ `boundary`；
- 被排除端在 `R`（请求过但被权限剔除）→ `permission`。

该判定是互斥且完备的：恰有一端存活时，被排除端要么属于 `S`，要么不属于；
“边界优先”在实现上体现为先判 `boundary`，保证任何重叠的实现路径都不会得到
两种标注。

**自环**：`From == To` 的链接只有一个端点对象。该对象存活则两端同时存活（纳入），
被剔除则随对象整体消失，任何情况下都不构成悬挂。

与被剔除对象相连、但另一端在范围外的链接：其范围内端点本身被剔除，无存活端，
按“剔除对象连同其全部链接整体剔除”处理，**不**记为悬挂（不存在可见端）。

## 6. 确定性与可归因性

- 范围标识先去重再按字典序排序；对象按 ID、纳入链接按 ID、悬挂按
  `(Included, Excluded, LinkID)` 全序排序。主图未发生相关变更时，重复提取
  得到逐字段一致的结果（`reflect.DeepEqual` 验证）。
- 所有主图变更写入仅追加的变更日志，`Graph.Journal(after, now]` 与
  `Graph.Attribute(prev, next)` 返回两次快照修订号之间的具体变更。
  `Compare` 输出的每一类差异都必须能在该窗口日志中找到对应变更；
  与范围无关的远处变更只推进修订号，不产生内容差异。

## 7. 开销与内部度量

提取只通过 `endpointLinks[有效对象]` 收集候选链接（按链接 ID 去重，自环只经
一个端点入索引一次），随后逐条判定。

内部度量 `Snapshot.candidateLinksChecked`（经 `InternalCandidateLinksChecked()`
读取，明确标注为仅用于本地验证、非调用者契约）统计本次实际检查过的**候选链接
实例数**。其上界为范围对象直接关联链接的并集规模，与主图中无关对象/链接的总量
无关。`TestCandidateMetricIsScopeBounded` 在主图中加入 200 个对象、200 条无关
链接后，断言度量仅随一条新增邻接链接 +1。

## 8. 朴素穷举参考模型与差分测试

`naive_test.go` 提供独立实现：对同一不可变状态**全表扫描**所有对象与链接
（O(|V|+|E|)），不复用生产提取代码，独立重建权限集、剔除集与分类逻辑。
`TestNaiveDifferentialRandom` 使用固定种子生成对象、有向/无向链接（含自环与
平行边）、随机权限矩阵与随机范围（含乱序/重复/偶发非法标识），在同一状态
指针上对照两者逐字段一致，并将每次提取的输入、输出与悬挂附属信息写入
`testdata/extraction_runs.jsonl`（每行一条 JSON 记录）。

## 9. 本地验证方法

```bash
go build ./...
go vet ./...
gofmt -l .
go test -race -v ./...
go test -run TestNaiveDifferentialRandom -v .   # 重新生成 JSONL 记录
```

测试覆盖：

- 校验次序与三类参数非法；
- 边界悬挂与权限剔除悬挂的来源区分、方向元数据、边界优先；
- 自环不参与悬挂的两种情形；
- 剔除至空返回空快照而非错误；
- 无变更窗口的逐字段一致性、有变更窗口的差异归因、无关变更无内容差异；
- 候选链接度量不随主图无关规模增长；
- 100 轮并发写 + 并发提取（`-race`）下快照始终内部一致；
- 200 组随机场景与朴素穷举模型的差分对照。

## 10. 刻意不做的事

- 不实现按历史修订号重放的完整 MVCC（见 §4 取舍）。
- 不对调用者暴露成本度量字段；快照 JSON/结构体中该字段保持小写不导出。
- 链接类型仅承载方向性，不扩展属性级 ACL；存在性权限是唯一参与提取裁决的权限。
