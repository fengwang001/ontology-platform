# 多人协同表格：按用户选择性撤销与重做服务 — 设计说明

## 模块划分

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 公共词汇 | `sheet/types.go` | `Edit`/`Record`/`Result`/`ErrCode` 等类型与取值约束（值域 ±10^15、now ≤ 10^12、编辑 ≤ 50、深度 1..100）。`Result.Dropped` 专门标明“被覆盖例外”。 |
| 历史栈 | `sheet/history.go` | 单用户撤销/重做栈，栈顶在切片末尾；撤销栈超深度 D 时丢弃最旧一条。 |
| 服务门面 | `sheet/service.go` | `Service` 状态（全局修订号、时钟、单元格、保护、各用户历史）与导出入口，统一持锁。 |
| 操作核心 | `sheet/ops.go` | Apply/Undo/Redo/Protect/Unprotect 的状态机与拒绝次序。 |
| 朴素模型 | `sheet/naive/naive.go` | 独立重写的参照实现（记录用无序 map、冲突靠收集后排序），仅供差分测试对照。 |
| 测试 | `sheet/*_test.go` | 场景测试、拒绝次序测试、1500 组随机对照、并发与重放、两档规模性能对照。 |

协作方式：`service.go` 的每个导出入口只做加锁与转发；`ops.go` 假设锁已持有，
操作 `history.go` 提供的栈原语；所有跨模块交换的数据结构都来自 `types.go`。

## 关键语义与取舍

- **串行化用单互斥锁**。所有操作（含查询）在同一把 `sync.Mutex` 下执行，
  并发调用天然等价于某个串行顺序；被接受的 Undo/Redo 在其串行位置上
  逐一校验版本与保护，满足题目的一致性要求。表格服务的操作粒度小
  （≤50 个单元格），锁竞争远低于锁实现本身的复杂度风险。
- **覆盖检测只看版本，不看值**。记录为每个单元格保存事务生效时的版本；
  Undo/Redo 要求当前版本精确相等。因此“值恰好相同但版本不同”自然被判为
  被覆盖，无需特判。被清除的单元格保留条目以维持版本号（版本不会回 0）。
- **记录内变更按键升序存储**（`Record.Changes`），Undo/Redo 依序扫描，
  “按键排序的第一个不符/受保护单元格”零额外成本且确定性可重放。
- **被覆盖例外显式化**。版本检查失败时立即弹出并丢弃栈顶记录（不进重做栈），
  返回 `Result{Code: Overwritten, Dropped: true, Cell: 第一个不符键}`；
  这是唯一允许改变状态的拒绝路径。其余拒绝路径在代码上先做全部校验、
  最后才写状态，从结构上保证“被拒绝的操作什么都不改”（含时钟）。
- **时钟只随被接受的操作前进**（含 Protect/Unprotect 与“成功但无变化”的
  重复自我保护）；所有拒绝路径不触碰 `lastNow`。
- **无效编辑在保护检查之后剔除**。保护检查覆盖全部编辑键（含无效编辑），
  次序为 参数非法 > 时钟回退 > 受保护 > 无变化，与题目一致。
- **重做栈不设独立深度上限**：它只能由 Undo 从撤销栈弹出压入、且被 Apply
  清空，其大小天然不超过 D；Redo 成功回到撤销栈顶时同样走 `pushUndo`
  的深度丢弃逻辑。
- **性能**：状态全部按单元格键/用户名散列索引，Apply/Undo/Redo 只访问
  事务内的单元格与本人栈顶记录；深度丢弃移动 ≤100 条（D 的上界），
  为常数级。复杂度 O(事务内单元格数)，与表格总量、历史总量、用户数无关。

## 被放弃的方案

- **OT / CRDT 式并发合并**：题目要求 Undo/Redo 在版本精确匹配时才生效、
  否则丢弃记录，这是显式的串行语义而非自动合并语义，引入 OT/CRDT 只会
  增加偏离规格的风险。
- **细粒度（每单元格/每用户）锁**：Undo/Redo 需要“版本检查 + 保护检查 +
  写入”原子完成，多锁会引入锁序与死锁问题；单锁在 ≤50 单元格的事务
  粒度下足够快，且串行化论证最简单。
- **全量快照历史**：每次操作保存整表快照可简化 Undo，但内存与复制开销
  随表格规模增长，违反性能约束；改为只记录事务级逆操作（原值/新值/版本）。
- **环形缓冲区历史栈**：切片 + 超深时整体前移在 D≤100 下是常数级，
  环形缓冲的索引复杂度不值得。
- **拒绝操作也推进时钟**：规格明确“被拒绝的操作不得改变时钟”，放弃。

## 本地验证方法

```bash
# 全部单元测试 + 1500 组随机序列对照朴素模型（-v 可见每步输入/输出/判定依据）
go test ./sheet/ -v -run TestRandomSequencesAgainstNaive

# 竞态检测下的全量测试（含并发串行化不变量：修订号 == 被接受变更操作数）
go test -race ./...

# 重放确定性
go test ./sheet/ -run TestReplayDeterminism -v

# 性能对照：10^4 与 10^6 两档规模, 比值应远小于 100（实测接近 1）
go test ./sheet/ -run TestPerformanceScaleIndependence -v
go test ./sheet/ -bench . -benchtime 2000x -run '^$'

# 静态检查
gofmt -l . && go vet ./...
```

随机对照的判定依据来自 `Result` 本身：拒绝类别（`Code`）、冲突单元格
（`Cell`）、被覆盖例外的丢弃标记（`Dropped`）与操作后修订号（`Revision`），
逐步与朴素模型比对，并在每步后比对全部可观察状态
（单元格值/版本、保护者、两栈计数与栈顶键集合、全局修订号）。
