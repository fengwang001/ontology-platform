# 链接基数约束 × 属性级权限联合仲裁 — 设计说明

## 1. 问题拆解与模块划分

系统把两类相互独立的判定（「链接两端是否还有基数名额」与「操作者对两端来源属性是否可见」）
放在同一个串行仲裁点联合裁决。三个职责严格分离的模块协作：

| 模块 | 文件 | 职责 | 明确不做的事 |
| --- | --- | --- | --- |
| 基数账本 | `ontology/ledger.go` | 物理链接集合、按链接类型分端的占用计数、`check/add/remove` | 不读取任何权限信息；不判断操作者 |
| 权限解析器 | `ontology/permission.go` | 角色层级、操作者→角色赋予、实例层覆盖；按「最近距离、同距离取最新声明」解析最终可见性 | 不知道链接与基数的存在 |
| 联合仲裁器 | `ontology/arbiter.go` | 全局串行日志与序号、参数校验、按固定次序调用前两者、错误归一化、读侧可见性过滤 | 不自行实现基数或层级算法 |

模式目录 `ontology/catalog.go`（对象类型/实例归属/链接类型/类型层默认）是纯查询数据，
被仲裁器与朴素对照模型各自独立组合，避免仲裁逻辑被对照实现“共享”而失去独立性。

## 2. 统一优先级（只报第一个命中的原因）

创建链接（`Arbiter.CreateLink`）严格按下列次序短路：

1. `ERR_INVALID_PARAM`：链接类型/两端实例必须存在；实例对象类型必须与链接类型两端一致；
   链接 ID 非空且未被占用；操作者非空。
2. `ERR_INVISIBLE`：操作者对**起点**或**终点**来源属性任一不可见（起点先判，但二者同属一类错误）。
   关键语义：链接的存在性对不可见操作者整体隐藏，而不是「看到链接、看不到值」。
3. `ERR_SOURCE_CARDINALITY_EXCEEDED`：账本独立给出的起点占用已达上限。
4. `ERR_TARGET_CARDINALITY_EXCEEDED`：终点占用已达上限。

权限与基数是**独立计算**的（账本 `check` 与解析器 `resolve` 互不调用），只是输出按优先级裁剪：
即使起点基数已满，只要权限不通过，基数结论永远不会被报告。

删除链接（`Arbiter.DeleteLink`）不涉及基数判断，次序简化为：

1. `ERR_INVALID_PARAM`：ID/操作者为空。
2. `ERR_NOT_FOUND`：链接确实不存在，**或**链接存在但操作者对任一端不可见——
   两者返回同一个错误构造（相同 `Code` 与相同文案 `"link not found"`），
   从而无法借错误类别或文案区分「不存在」与「被隐藏」。

不可见删除只做读判定，绝不 `ledger.remove`，因此物理链接、基数占用、其他操作者的可见性都不变。
测试用内部字段 `DeleteResult.HiddenButExists` 留痕，仅供打印判定依据，不进入对外错误。

## 3. 权限继承与覆盖的解析模型

- 类型层：属性在注册对象类型时给默认可见性，可用 `SetTypeDefault` 整体修改。
- 实例层覆盖：`DeclareOverride` 以 `(实例, 属性, 主体)` 为主键，主体是操作者本人或某个角色；
  覆盖可放宽也可收紧；对同一主键重新声明即替换值并取得新的声明序号，因此只影响声明主体，
  操作者 A 的直接覆盖不会影响操作者 B（`TestDirectOverrideAndIsolation`）。
- 层级：`AssignRole(operator, role)` 使操作者与角色距离 1；`IncludeRole(child, parent)`
  声明角色包含边。最终可见性取沿这些边**最短距离**处的覆盖；同一距离有多个覆盖时取声明序号最大者；
  没有任何可达覆盖才退回类型层默认。

解析器以「按层 BFS、命中即停」实现：距离 0 只查操作者本人；之后每一层只查上一层角色的包含目标；
某层一旦出现覆盖，取该层最新者并立即返回，既不展开下一层，也从不枚举系统中不可达的角色。
层级允许成环，BFS 的 `visited` 集合保证终止且距离仍是最短距离（`TestRoleCycleSafe`）。

## 4. 收紧后的可见性跟随与基数不释放

可见性不是物化状态。`VisibleLinks` 每次都即时解析两端属性可见性，因此：

- 覆盖收紧后，下一次查询该操作者立刻看不到这条链接；
- 链接仍在账本中、两端占用计数不变（收紧后其他人再建同起点链接仍被基数拒绝，
  见 `TestTightenHidesWithoutDeletion`）；
- 其他仍可见的操作者照常可见、可删除；重新放宽后该操作者立即恢复可见。

这也天然满足「链接存在性整体隐藏」：不可见操作者枚举、创建冲突探测、删除返回三个面都得到一致处理。

## 5. 并发等价串行与确定性重放

本实现把并发仲裁等价为「单一互斥串行点 + 只追加日志」：

- 所有生效命令经 `Arbiter.Apply`/`CreateLink`/`DeleteLink` 串行落账，
  成功命令的序号即其在日志中的位置（`seq = len(log)+1`），覆盖声明时间也复用该序号，
  因此「同距离取最新」在重放下严格确定。
- 失败命令不留痕，下一条命令的状态与它从未发生一致；创建是否成功只取决于该请求被串行化那一刻
  解析器与账本的快照。
- `Replay(cmds)` 用同一命令序列构造全新仲裁器；`TestReplayDeterminism` 校验物理链接集合
  与每个操作者的可见集合在重放后逐字节一致。

生产环境把 `Apply` 挂在单写者/互斥锁之后即可得到线性一致的串行化；命令对象是纯数据，可直接序列化传输。

## 6. 复杂度与可验证的性能证明

设 d 为操作者到最近一次覆盖的层级距离（无覆盖时为其可达 BFS 球半径），解析代价为 O(球内边数)，
**不依赖系统角色总数 N**。证明不以「读代码」为准，而是由解析器内置的确定性探针给出：

- `Probe.RolesVisited` / `Probe.OverridesChecked` 记录一次解析实际展开的角色节点与声明检查次数。
- `TestCostIndependentOfTotalRoles`：固定 d=3，把与操作者不可达的角色链从 0 膨胀到 10000，
  探针恒为 `{访问角色=3, 检查声明=4}`（4 = 1 个操作者 + 3 个角色层）。
- `TestCostScalesWithNearestDistance`：d ∈ {1,2,5,10} 且命中层之外另挂 5000 个可达角色时，
  访问角色数恰等于 d；距离 0 时为 0。
- `BenchmarkResolveHugeUnrelatedGraph`：10 万个不可达角色存在时，d=3 的解析约 0.7 µs/次
  （随机器波动），作为墙钟旁证。

朴素模型 `NaiveModel.visibility` 则刻意每次枚举全部角色与全部覆盖，在差分测试中充当独立参照。

## 7. 关键取舍

- **可见性即时计算，不物化授权位。** 好处是收紧立即生效且无需补偿/回收；代价是枚举链接时每条做两次解析，
  在「最近覆盖很近」的常态下是常数开销，可接受。被放弃的方案：维护 per-操作者链接可见性镜像，
  收紧时增量清理——该方案必须处理删除事件与基数账本的一致性，复杂且易错。
- **删除的「不可见」与「不存在」合并为同一个错误值。** 被放弃的方案：返回不同内部码再靠上层映射；
  那样任何日志/文案差异都会成为存在性泄露侧信道。内部判定依据只放在测试可见的结果字段中。
- **声明时间复用全局命令序号。** 不引入物理时钟，避免并发下时间戳同值或回退导致重放不确定。
- **类型层默认缺省为可见（属性已声明时以声明值为准）。** 被放弃的方案：未声明属性一律不可见。
  选择缺省开放是因为基数/类型系统通常先建模后授权；这只影响属性笔误时的行为，参数校验已覆盖主要误用。
- **角色覆盖不要求「成员关系在声明时成立」。** 先给角色声明、后把操作者加入角色同样生效；
  语义上覆盖是角色的属性而非赋予事件，更贴合权限模型的直觉。

## 8. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin      # 本机 go 位于该目录

go test ./...                             # 全量
go test -race -v ./ontology               # 竞态 + 逐条打印输入/输出/依据
ONT_TEST_ECHO=1 go test -v ./ontology     # 同时把判定记录打到 stdout
go test -run TestRandomDifferential ./ontology
go test -run TestCost ./ontology -v       # 复杂度探针证据
go test -bench BenchmarkResolve -run '^$' ./ontology
gofmt -l . && go vet ./...
```

测试清单与需求对应关系：

- 错误次序（参数→不可见→起点基数→终点基数）：`arbiter_test.go` 中
  `TestInvisibleBeatsSourceCardinality`、`TestCardinalityOrdering`、`TestInvalidParamFirst`。
- 收紧即时隐藏且不删链接/不释放基数/不影响他人：`TestTightenHidesWithoutDeletion`。
- 删除不可见 == 删除不存在：`TestDeleteHiddenLooksLikeMissing`。
- 最近优先与同距离最新、直接声明压制角色、覆盖按操作者隔离、类型默认回退、层级环：
  `permission_test.go` 全部用例。
- 大量随机序列与朴素模型逐条对照（24 个种子 × 300 步，每条比对错误码、物理链接、4 名操作者可见集）：
  `TestRandomDifferential`。
- 重放确定性：`TestReplayDeterminism`。
- 复杂度证据：`perf_test.go`。
