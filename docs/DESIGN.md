# 快递智能柜设计说明

## 模块划分

- `types.go`：公开类型、配置、错误码、结果和观测结构。
- `fee.go`：滞留费纯函数。免费时长、完整周期、封顶均只由时刻计算。
- `allocator.go`：格口建模与常数时间分配。三档格口各自维护空闲集合，请求时从快件规格开始向大规格扫描。
- `code_pool.go` 与 `code_format.go`：取件码生成、失效、冷却与确定性复用。
- `locker.go`：状态机、互斥、时钟、拒绝优先级、取件、缴费、回收和运营解锁。
- `*_test.go`：边界测试、并发测试、探针上界测试，以及独立朴素模型的随机差分测试。

## 关键语义

时间以非负整数秒表示。`Locker` 只记录最后一次被接受操作的时刻；所有拒绝均不更新时间。手机号后四位不符是唯一会改变业务状态的拒绝：递增该快件错误次数，达到配置阈值时锁定，但仍不推进时钟，也不改动其他状态。

取件拒绝严格按以下顺序判定：

1. 参数非法；
2. 时钟回退；
3. 取件码不存在或已失效；
4. 快件已锁定；
5. 手机号后四位不符；
6. 已超时；
7. 待缴费。

存件拒绝顺序为参数非法、时钟回退、重复运单，然后先判断柜体是否静态存在可容纳规格；只有存在可容纳规格但当前全部占用时，才返回暂时占用。

超时是纯函数：`at >= storedAt + StorageLimit`。系统不依赖后台任务。超时件仍占用格口，不能取件；运营回收后格口立即进入空闲集合，取件码进入冷却。

费用为 `floor((at - storedAt - FreeDuration) / Period) * PeriodFee`，再应用单件封顶；恰好等于免费时长应缴 0，不足一个完整周期不计费。缴费必须恰好等于当前新增应缴金额。后续时间推进后，可再次查询并补缴新增部分。

## 格口分配

需求规定先取最小可容纳规格，再在相同规格中取最小编号。实现为每个实际规格维护一个独立的分层位图：

- 小快件先查小格口，空则查中格口，再查大格口；
- 中快件先查中格口，再查大格口；
- 大快件只查大格口；
- 位图集使用 11 层 64 位字，覆盖 64 位编号空间；
- 每一层的空判断和下钻均是常数次映射访问；
- 三档最多检查三个集合，因此每次查找有固定小上界，与格口总数、历史快件数无关。

`AllocationStats.MaximumFindProbes` 暴露实测查找探针数。`TestAllocationFindProbeBound` 使用 10 万个格口和 1000 次存件，断言该值保持在固定小上界内。它证明的是“选择最小空闲可容纳格口”的过程；柜体初始化排序只发生在 `NewLocker`，不计入后续操作开销。

编号排序采用自然顺序：数字段按数值比较，非数字段按字节比较。例如 `cell-2 < cell-10`。

## 取件码复用

新取件码使用确定性递增十进制码。失效码放入按 `(availableAt, code)` 排序的最小堆：

- 冷却未结束时分配新码；
- `releaseAt + CodeCooldown <= allocateAt` 时可取回复用；
- 同刻多码可复用时，取数字编号最小者；
- 活动码存在于 `active` 映射中，结构上不可能出现同时重复有效码。

相同配置和相同操作序列重放时，格口、成功/失败路径和码池状态均确定，因此取件码序列相同。

## 并发模型

所有公开操作在同一把互斥锁内完成校验和状态变更。该方案主动放弃了更细粒度的格口锁：

- 全局时钟和码池是跨格口共享资源；
- 需求要求所有并发调用等价于某个串行顺序；
- 单锁使原子性、异常回滚和并发取件唯一成功更容易证明。

被拒绝路径在任何状态写入前返回；手机号不符例外只更新当前快件的错误计数。成功路径在锁内一次性完成格口释放、码池冷却、索引删除和时钟推进。

## 被放弃的方案

- 每次存件线性扫描全部格口：语义最简单，但选择开销随格口总数增长，只能作为测试模型，不能用于实现。
- 单个最小堆承载所有空闲格口：无法在常数时间内区分“规格最小”和“编号最小”，且释放后堆调整为对数时间。
- 三档普通最小堆：选择和释放均为 `O(log n)`，不满足严格的不随柜体规模增长要求。
- 每档有序链表：取头为常数，但释放任意格口时找插入位置通常需要线性时间。
- 后台任务定时超时或释放冷却码：会把纯函数语义变成调度依赖，影响重放确定性。
- 细粒度格口锁：提高理论并发度，但与全局时钟、码池和串行一致性要求组合后复杂度高，本系统操作很短，收益不足以覆盖正确性成本。

## 观测与日志

`Config.Logger` 可选。生产实现记录每次操作的输入、成功或拒绝结果、格口/运单/取件码和判定依据。手机号不符额外记录 `clockAdvanced=false`。测试中的随机差分用例通过 `t.Logf` 记录种子、步骤、输入、输出和判定依据；可用 `go test -v` 查看。

## 本地验证

如果当前 shell 找不到 Go，使用 `/usr/local/go/bin/go`。若默认构建缓存不可写，可把 `GOCACHE` 指到临时目录：

```bash
GOCACHE=/tmp/go-cache-ontology /usr/local/go/bin/go test -v ./...
GOCACHE=/tmp/go-cache-ontology /usr/local/go/bin/go test -race ./...
GOCACHE=/tmp/go-cache-ontology /usr/local/go/bin/go vet ./...
/usr/local/go/bin/gofmt -l .
```

随机差分测试固定种子，可稳定复现。若需要扩大覆盖，可调整 `TestRandomSequenceMatchesNaiveModel` 中的种子数、每序列步数和随机操作比例。
