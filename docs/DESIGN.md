# 能量隔离上锁挂牌（LOTO）工作票系统 — 设计说明

## 模块划分

| 模块 | 职责 |
| --- | --- |
| `loto/errors.go` | 七类可区分错误及其判定优先级，所有操作统一按序校验 |
| `loto/types.go` | 作业类型、票状态、角色、送电判定结果、审计条目 |
| `loto/config.go` | 设备/隔离点静态配置与校验，预计算“隔离点 → 设备”反向索引 |
| `loto/system.go` | 系统门面：互斥锁串行化、单调时钟、逾期扫描堆、锁/票计数器、审计 |
| `loto/permit.go` | 工作票生命周期全部带时刻操作（申请→批准→上锁→验证→开工→进出→完工→摘锁，试运行，强制摘除） |
| `loto/energize.go` | 送电判定（只读），输出判定依据 |
| `naive/` | 独立编写的朴素参考模型：无索引、全量扫描历史票与锁记录 |
| `difftest/` | 随机对照测试（loto vs naive）与两档规模性能证明 |

## 关键取舍

### 1. 错误模型：先分类、再定序
每个操作体内严格按 `参数非法 → 时刻回退 → 对象不存在 → 无权限/角色 → 状态不允许 → 冲突 → 条件不满足`
的顺序逐项校验，返回首个命中。校验全部通过后才触碰任何状态、时钟与审计，
因此“被拒绝的操作不改变任何状态与时钟、不消耗批准名额”是由代码结构保证的，而非事后回滚。

### 2. 时钟与逾期：接受时推进 + 虚拟状态判定
- 时钟只随被接受的操作单调推进；逾期扫描（最小堆，按票终点排序）只在 `accept` 时执行。
- 校验阶段使用 `stateAt(t)` 计算**虚拟状态**（占用态且终点已到视为逾期），
  使“到达终点即逾期”对校验立即可见，又不会让被拒绝的操作产生副作用。
- 只读查询（`PermitState`、`EnergizableAt`）同样用虚拟状态，不物化逾期转移。

### 3. 冲突与送电判定：只索引“占用态”，不碰历史
- 冲突判定只遍历当前占用态票集合 `active`；票完工即移出。
- 送电判定依赖两组计数器（隔离点锁数、设备锁数）与 `设备 → 占用态票` 索引，
  开销只与“该设备当前关联的占用态票数”有关，与历史票总数无关。
  `difftest.TestPerfScales` 用 1 万 / 10 万两档历史票对照验证（耗时比 ≈ 1）。

### 4. 试运行恢复后回到“已上锁”而非“已验证”
规格原文“全部恢复后票回到已验证状态，须再次执行零能量验证才可重新开工”存在字面矛盾。
取操作性更强的一句：恢复完成后回到**已上锁**，必须重新执行零能量验证才能再次开工。
（若直接回到已验证，则“须再次验证”无从强制。）

### 5. 逾期是终态旁路，不是死锁
- 逾期票：不可开工/进入/正常摘锁；人员仍可离场；全员离场后可 `Complete` 收尾；
  锁只能由主管+另一名不同主管附非空理由强制摘除（记审计）。
- 被强制摘除锁的人被标记 `mustRelock`，在逾期票上重新完成全部上锁后标记清除；
  `Enter` 额外检查该标记作为安全网（当前状态机下逾期票本就无法再进入）。

### 6. 并发：单互斥锁串行化
所有公开方法（含只读查询）共用一把 `sync.Mutex`，任何并发调用的结果
等价于按获得锁顺序的某个串行执行。`go test -race` 验证无数据竞争。
选择单锁而非细粒度锁：计数器/堆/票状态之间存在强不变量（如设备锁计数 = Σ 隔离点锁计数），
细粒度锁的复杂度与出错风险远高于收益；吞吐量对本场景（人均秒级操作）完全足够。

### 7. 零作业人员的票
“全员完成全部上锁”对空人员集 vacuously 成立：批准生效后直接进入“已上锁”，
可验证、开工。这恰好支持只读观察票等无需隔离的场景，未额外特判。

## 被放弃的方案

- **事件溯源 / 不可变日志作为唯一事实**：审计与状态分离虽优雅，但每次判定都需重放，
  与“开销不随历史增长”的要求冲突；改为内存状态 + 仅追加审计。
- **拒绝操作后回滚副作用**：曾考虑先执行逾期物化再校验、失败时回滚；
  回滚在计数器与堆上极易遗漏，改为“虚拟状态校验 + 接受时物化”，结构性消除回滚。
- **设备级阻塞票计数器**：曾维护 `deviceBlocking` 计数器做 O(1) 送电判定，
  但虚拟逾期（未物化）使计数器与真实判定之间出现口径差；
  改为基于 `deviceActive`（仅占用态）即时统计，开销同样与历史无关且口径唯一。
- **细粒度并发（每票一锁）**：见第 6 节，放弃。

## 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin
go test ./...                 # 全部单元/场景/对照/性能测试
go test -race ./...           # 并发竞态检测
go test ./difftest -run TestDifferential -v   # 查看随机对照日志（输入/输出/判定依据）
go test ./difftest -run TestPerfScales -v     # 查看两档规模耗时对照
go test ./loto -v             # 查看场景测试
gofmt -l . && go vet ./...    # 格式与静态检查
```

- 场景测试覆盖：首尾相接不冲突、只读共存、高风险批准人去重、共享隔离点最后一把锁、
  试运行期间他票的锁、逾期摘锁限制与强制摘除、送电判定全部条件、错误优先级、被拒绝操作无副作用。
- 随机对照：30 个种子 × 400 个随机操作，逐步比较两实现的错误类别、全部票状态与全部设备送电判定。
- 性能证明：`TestPerfScales` 输出两档耗时并断言比值有界。
