# 报警生命周期管理服务 — 设计说明

## 1. 目标与范围

为工业控制室提供单个进程内的报警生命周期服务，覆盖：触发、返回、确认、
手动屏蔽、震荡自动屏蔽、工况条件抑制、工程师停用/启用；维护操作员可见的
活动报警列表（四层排序）与报警率查询。所有写操作与查询都带非负整数秒
时刻，事件时刻必须非降，支持多 goroutine 并发调用（等价于某个串行顺序）。

## 2. 模块划分（职责清晰、相互协作）

代码位于 `alarm/` 包，每个文件只有一条变化轴：

| 文件 | 职责 |
| --- | --- |
| `types.go` | 领域类型：优先级/状态/角色、点配置、系统配置、点运行时结构 |
| `errors.go` | 可区分的六类错误码与错误对象（含次序定义） |
| `state.go` | 纯函数状态机：触发/返回/确认的迁移规则，无副作用、无 I/O |
| `shelve.go` | 屏蔽到期最小堆（`container/heap`）及登记逻辑 |
| `suppress.go` | 条件抑制的单点重算（任一工况为真即抑制） |
| `tree.go` | 活动列表的 Treap（按四层排序键），按节点身份删除 |
| `service.go` | 用一把互斥锁把上述模块编排成对外 API：校验次序、惰性到期、可见性同步、出现时间线、日志 |
| `doc.go` | 包文档 |

协作关系：`service` 每次操作先做校验，再调用 `shelve` 堆做惰性到期，
然后用 `state` 的纯函数迁移状态，必要时通过 `shelve`/`suppress` 改写
屏蔽/抑制，最后统一调用 `refreshTree` 让 `tree` 的成员关系与“应当可见”
对齐，并把“不可见→可见”的净变化追加到出现时间线（供报警率二分统计）。

## 3. 状态机（`state.go`）

```
                trigger                         ack
   normal ───────────────────▶ active-unacked ─────────▶ active-acked
     ▲                              │  ▲                     │
     │ ack(return)                  │  │ trigger(重复)       │ return
     │                              ▼  │ = no-op             ▼
   return-unacked ◀── return ───────────┘                  normal
```

- 触发：`normal / return-unacked → active-unacked`；已激活（AU/AA）重复触发为空操作，
  不改变 `lastActiveAt`，不计数。
- 返回：`active-unacked → return-unacked`；`active-acked → normal`。
- 确认：`active-unacked → active-acked`；`return-unacked → normal`；
  `normal / active-acked` 上确认报“状态不允许”。

状态机在屏蔽、抑制、停用下照常演进（停用例外：停用期间触发/返回直接忽略）；
屏蔽/抑制只影响“是否进入活动列表”，不影响状态本身。

## 4. 关键取舍

### 4.1 到期处理采用“惰性 + 最小堆”，不做后台时钟线程

系统没有真实时钟，只有事件携带的时刻。因此不维护后台 goroutine 去定时解除，
而是在**每个带时刻的操作入口**弹出堆顶所有 `until <= now` 的屏蔽并解除。
这样：

- 无后台线程、无竞态，并发模型退化为一把锁；
- 到期解除与手动解除共用同一份代码路径（`clearShelve` + `refreshTree`），
  规则天然一致；
- 到期导致的“出现”记录在**真实到期时刻 `until`**，而不是“被观察到的较晚
  时刻”。由于事件按非降时刻串行处理，`until` 时刻的可见性与惰性处理时刻
  完全一致，因此报警率的区间边界（左开右闭）可以精确落在 `until` 上。

堆项在“手动提前解除后又重新屏蔽”等情况下会失效，弹出时用
`shelved && shelveUntil == until` 核对身份，过期项直接丢弃。

### 4.2 “可见性”只有一个判定函数，列表成员关系由统一同步点维护

`shouldShow(p) = 状态∈{AU,AA,RU} 且 !disabled && !shelved && !suppressed`。
每次任何相关状态变化后只调用 `refreshTree(p)`：

- 不可见→可见：插入树并记录一次“新出现”；
- 可见→不可见：从树删除；
- 仍可见：**先删后插**，以吸收排序键变化（确认会把“未确认层”变为“已确认层”）。

这一点是测试逼出来的：第一版 `treapErase` 按排序键查找，确认改变层级后
旧键在新顺序里找不到，树中残留重复节点。最终删除改为**按节点身份
（指针相等）+ Treap `merge` 合并左右子树**，与键解耦，且不会成环。

屏蔽与抑制重叠时无需任何特例：两个布尔位都为 false 时 `shouldShow` 才为真，
自然实现“两者都解除后才出现”。“若屏蔽期间发生新激活则解除后必须未确认”
也无需额外标记——屏蔽不改变状态机，期间发生的 `AA → normal → AU` 本来就
让当前状态成为 AU。

### 4.3 震荡窗口：每点一个升序时刻切片，左开右闭

只有“非屏蔽、非停用”下真正进入激活才追加时刻；每次追加后裁掉
`t <= now-window` 的旧记录（左开：保留 `now-window < t`）。长度达到
`ChatCount` 即自动屏蔽 `ChatShelveSec` 秒，原因记 `chattering`，随后清空
窗口（屏蔽期间触发不追加；解除后从空窗口重新累计）。紧急点豁免。

选择“达阈值即清空窗口”而非滚动保留：屏蔽期内触发本就不计入，保留旧记录
只会在解除后制造没有对应新活动的再次自动屏蔽；语义上“一次震荡事件 → 一次
自动屏蔽”更直观。该取舍仅影响连续多轮震荡的再次触发节奏，不影响屏蔽期内
行为，已写入测试与文档。

### 4.4 活动列表：Treap 而非堆

需求是“查询开销只与活动条数相关”。被放弃的方案：

- **container/heap + 惰性删除**：过期/已确认条目会在堆内累积，反复触发同一
  点会让堆大小随历史增长，查询要先惰性弹出脏根，最坏开销与历史同阶——不满足要求。
- **有序切片（insert/delete 移动）**：无历史累积，但单次插入最坏 O(活动数)。

Treap 的期望插入/删除为 O(log A)（A 为当前活动条数），全量中序遍历 O(A)，
树中每个活动点恰好一个节点，**树大小严格等于活动条数**，与历史事件总数、
总报警点数都无关。排序键即题目四层：优先级降序 → 未确认先于已确认 →
`lastActiveAt` 升序 → 编号升序。

### 4.5 报警率：出现时间线 + 二分

维护一个全局升序切片 `appearAt`，每次“新出现”追加一个时刻（同一点多次
出现追加多次，天然按多次计）。`AlarmRate(ts, dur)` 对区间
`(ts-dur, ts]` 做两次 `sort.Search`（左开找第一个 `> ts-dur`，右闭找
第一个 `> ts`），O(log H + 结果数)，不做区间扫描。

### 4.6 并发：单把互斥锁的可线性化

所有 API 在入口 `mu.Lock()`，临界区内完成全部校验与状态变更，因此每次调用
原子可见，整体结果等价于按获取锁的顺序串行执行（可线性化）。被拒绝的操作
在任何状态写入之前返回（`refreshTree`、`lastTS` 都在校验通过后才触碰），
不留下任何痕迹。选择单锁而非分片，是因为操作需要同时一致地读改写“点 + 堆 +
树 + 时间线”，单锁的正确性最直接，且每操作都是期望 O(log A)，锁竞争不是
主要瓶颈。

### 4.7 错误次序

严格按题序短路：参数非法 → 时钟回退 → 点不存在 → 无权限 → 状态不允许
（紧急不可屏蔽/已屏蔽/已停用等）→ 屏蔽时长超上限。一个实现细节：`Shelve`
把“惰性到期”放在全部校验之后，避免“已屏蔽但恰好在本时刻到期”被到期副作用
抢先解除而改变 `已屏蔽 → 状态不允许` 的预期；其他操作的到期处理位于
“点存在/权限”之后、“状态检查”之前（例如 `Unshelve` 恰好落在到期时刻，
到期先解除、手动解除本身再报“未屏蔽”）。朴素模型按同一顺序实现，差分测试
对这一边界有覆盖。

## 5. 复杂度（每次操作）

| 操作 | 时间（期望） | 额外空间 |
| --- | --- | --- |
| trigger/return/ack/shelve/unshelve/disable/enable | O(log A + log E)，E 为堆中有效到期项（≤ 报警点数）；震荡追加/裁剪为 O(窗口记录数) | O(1) |
| setActiveConditions | O(P·c)，P 为总点数，c 为单点条件数（系统级信号变化本就需要全量评估） | O(条件总数) |
| activeList | O(A)（树大小即 A） | O(A) 输出 |
| alarmRate | O(log H)，H 为历史出现次数 | O(1) |

触发路径不读取树以外的历史，堆大小受“在屏蔽中的点数”上界约束，
因此不随历史事件总数增长。

## 6. 本地验证方法

需要 Go 1.26+。若 `go` 不在 PATH：

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache   # 本机 HOME 缓存目录只读时
```

```bash
gofmt -l .
go vet ./...
go test -race ./...
go test ./alarm/ -v                 # 查看每个操作的输入/输出/判定依据日志
go test ./alarm/ -run TestRandomDifferential -v
go test ./alarm/ -bench . -benchmem # 两档规模对照（历史事件、总点数、活动数）
go run ./cmd/alarmsrv               # 端到端演示（屏蔽/抑制/震荡/报警率）
```

### 测试矩阵

- `TestBasicTransitions`：四种基本状态迁移、重复触发空操作、非法确认。
- `TestShelveReturnRetrigger`：屏蔽期“返回再触发”，解除后必须 AU，不得沿用
  屏蔽前的确认；并核对报警率计入这次重新出现。
- `TestShelveSuppressOverlap`：屏蔽/抑制重叠的两种解除先后。
- `TestChatteringWindowBoundary`：左开右闭边界（t=0 被 `(1,11]` 排除）、
  达阈值自动屏蔽、到期自动解除；`TestChatteringEmergencyExempt` 紧急豁免。
- `TestDisableEnableInitialState`：停用期忽略触发/返回、启用后状态重置为
  normal，需等下一次触发。
- `TestActiveListOrdering`：四层排序并列（优先级/确认层/时刻/编号）。
- `TestAlarmRateBoundary`：左开右闭边界、同点多次出现多次计。
- `TestClockRollbackNoTrace`、`TestRejectedOpsLeaveNoTrace`、
  `TestErrorOrdering`、`TestShelveRestrictions`：回退/各类拒绝不留痕与错误次序。
- `TestConcurrentSerializability`：8 goroutine 并发，`-race` 下无数据竞争。
- `TestRandomDifferential`：60 个固定种子、每序列 500 个随机操作，与**独立
  编写的朴素模型**逐步比对错误码、每点（状态/屏蔽/停用/抑制/最近激活时刻）、
  活动列表与报警率。朴素模型不用树/堆，全量重放 + 全表扫描，思路与生产
  实现相互独立。

### 基准（两档对照，实测数据见 README）

- 触发：历史事件 1 万 vs 4 万，单次耗时基本持平 → 不随历史增长。
- 列表：总点 1 万/活动 500 vs 总点 4 万/活动 500 持平；活动 500 vs 4000
  随之增长 → 查询开销只与活动条数相关。

## 7. 被放弃 / 未采纳的方案汇总

- 后台定时 goroutine 解除屏蔽：没有真实时钟，引入线程与竞态，放弃。
- 堆 + 惰性删除维护活动列表：脏条目随历史累积，放弃。
- 有序切片维护活动列表：插入最坏 O(A)，在大活动量下不如 Treap，放弃。
- 屏蔽期额外用布尔位记录“期间已激活/已确认”：状态机本身已携带该信息，
  额外标记会制造双份事实源，放弃。
- 自动屏蔽后保留震荡窗口：会在解除后无新活动地再次触发屏蔽，放弃，
  改为达阈值即清空、屏蔽期不计数。
- 每点一把锁：操作跨“点/堆/树/时间线”一致性要求高，复杂度上升而收益有限，
  未采纳。
