# 单继承属性规则可见性判定机制 — 设计说明

## 问题域

对象类型沿单继承链条派生，子类型可对继承到的属性重新声明取值规则
（遮蔽），未重新声明的层级沿链条向上穿透。本设计回答：读取一个具体
实例的属性时，如何唯一确定最终生效的取值规则。

## 核心模型

- **规则即允许值集合**（`ontology/rule.go`）：取值域为字符串，规则是
  有限允许值集合。收窄约束因此等价于集合包含判定 `IsSubsetOf`，
  声明时即可 O(|新集合|) 完成检查，无需等实例写入暴露问题。
- **类型节点**（`ontology/registry.go`）：每个类型持有 `parentID`、
  `sealed`（禁止派生标记）、`declared`（本类型显式声明的规则表）与
  `children`（直接子类型集合，用于删除保护）。
- **查找即沿链行走**（`ontology/lookup.go` 的 `effectiveRuleLocked`）：
  从具体类型出发逐级向父类型行走，命中第一个对该属性有显式声明的
  类型即返回。未重新声明的层级天然被穿透，链条上无声明则落空
  （`ErrNotFound`）。查找结果由链条结构唯一确定，无类型变更时重复
  查找必然一致（`TestLookupDeterministic`）。

## 关键取舍

1. **每次查找都走链，不做生效规则缓存。**
   父层级重新声明后，未自行声明的子孙必须立即看到新规则。走链查找
   使这一传播语义成为零成本的自然结果，无需维护失效传播。代价是
   每次查找 O(深度)，而需求明确允许该上界。
2. **遍历开销只与链条深度有关。** 查找只访问 `parentID` 指针链，
   不触碰任何兄弟分支；`TestLookupDepthBound` 用 40 层链条加
   200→2200 个无关分支对照，验证遍历长度恒等于实际深度。
3. **单一互斥锁串行化全部操作。** 重新声明、写入校验、规则查找都在
   同一临界区内完成，全局序号 `seq` 即线性化点。这直接给出需求要求
   的全序：任何一次写入校验使用的规则都对应某个确定串行时刻，
   不存在"介于两次重新声明之间"的规则视图。
4. **历史取值与规则解耦。** 实例值原样保存，读取路径不触碰规则；
   只有 `WriteInstance` 在写入时按当前生效规则校验。规则收紧因此
   永不追溯（`TestHistoricalValuesSurviveTightening`）。
5. **错误优先级：不存在先于不合法。** 每个操作先判定类型/属性组合
   存在性（`ErrNotFound`），再判定密封、扩大、子类型依赖等业务约束，
   四类错误以不同哨兵错误分别暴露，调用方可用 `errors.Is` 区分。

## 被放弃的方案

- **生效规则缓存 + 失效传播**：在类型节点上缓存每个属性的生效规则，
  重新声明时向下游子树推送失效。查找虽降为 O(1)，但失效传播本身
  是 O(子树规模)，且缓存与源声明之间引入了一致性窗口，并发下需要
  额外的版本协议才能避免读到"介于两次声明之间"的规则。走链查找
  已满足深度上界要求，缓存属于为不存在的需求付出的复杂度。
- **声明时物化到全部子孙**：重新声明时把新规则复制到所有未自行
  声明的子孙节点。写入放大的同时引入"复制过的声明"与"自己的声明"
  的区分难题——后者正是遮蔽语义的关键，物化会抹平这一区分。
- **写入时追溯校验历史值**：在规则收紧时扫描存量实例并重新校验。
  被需求明确排除（历史取值必须始终可读），且扫描成本随实例数增长。
- **细粒度锁（每类型一把锁 / 无锁版本链）**：可提升并发吞吐，但
  线性化证明复杂得多。当前规模下单锁配合全局序号已能给出可机器
  核对的全序（见下），留作后续性能优化方向。

## 可验证性设计

- **审计日志**：每次 `EffectiveRule` 追加 `LookupRecord`（遍历路径、
  命中来源、规则快照、全局序号），每次被接受的变更追加
  `MutationRecord`（含写入校验实际使用的规则）。
- **朴素串行对照**（`ontology/concurrency_test.go`）：并发交织重新
  声明与读写后，把全部记录按 `seq` 重放到一个无锁朴素模型上，逐条
  断言：被接受的重新声明满足子集约束、每次写入校验所用规则等于
  该串行时刻的生效规则、每次查找观察到的来源与规则等于串行模型
  结果。这等价于验证存在合法线性化。

## 本地验证方法

```bash
# 环境：Go 1.26+；若默认缓存目录只读，设置 GOCACHE=/tmp/gocache
go build ./...
go vet ./...
gofmt -l .                 # 无输出即格式正确
go test ./ontology/        # 单元测试
go test -race ./ontology/  # 竞态检测下的并发对照测试
go test -run TestLookupDepthBound -v ./ontology/   # 深度上界证明
```

测试清单：

- `registry_test.go`：密封父类型拒绝派生、含子类型拒绝删除、
  扩大声明拒绝且原规则不变、不存在判定优先。
- `lookup_test.go`：4 层链条上 3 个可重新声明层级的全部 8 种组合、
  父级再声明对未声明子孙的穿透与对已声明子孙的遮蔽、无变更时
  查找确定性、遍历深度上界与无关分支数量无关。
- `instance_test.go`：规则收紧前后历史取值读取一致、新写入按当前
  生效规则校验。
- `concurrency_test.go`：8 协程 × 300 操作交织后与朴素串行实现
  逐条对照，含最终生效规则与实例终值一致性。
