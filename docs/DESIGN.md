# 高校教师授课任务分配与学期工作量核算服务 — 设计说明

## 1. 问题与领域模型

服务围绕三类领域对象运转：

- **课程任务（Task）**：学时、班级规模、是否新开、是否实验、闭区间周次 `[StartWeek,EndWeek]`、
  每周固定占用的节次集合。
- **教师（Teacher）**：职级决定学期工作量下限 `Min` 与上限 `Max`。
- **份额（Share）**：一名教师对一个任务承担的"一段课程"，带周次区间、整数学时、
  独立折算工作量与生命周期状态。份额是实现"合上"与"中途换人"的统一原语。

份额状态机：

```
              指派成功
 (不存在) ───────────────▶ pending ──教师确认──▶ active（生效）
                              │  │
                  教师拒绝 ───┘  └── now > deadline（惰性触达）──▶ released
                              ▼
                          rejected
```

`pending` 与 `active` 都占用时段与职级上限；`rejected` / `released` 立即释放。
换人时旧份额收缩、新份额直接为 `active`（换人是已生效教学安排的移交，不再需要二次确认）。

## 2. 关键数值规则（可精确复现）

### 2.1 规模档位

档位按 `MinSize` 升序，规模 `x` 命中满足 `MinSize <= x` 的最高档，因此**取等归高档**。

### 2.2 折算工作量（一次性连乘，禁止分步取整）

```
WL = floor( hours × scalePct × newPct × labPct / 100^3 )
newPct = 100 + NewCourseBonusPercent   （新开课）
newPct = 100                           （非新开课）
labPct = LabPercent                    （实验课）
labPct = 100                           （非实验课）
```

- 三个系数先连乘再与学时相乘，**最后只做一次整除**，保证不产生分步取整误差。
  例如 `7h, 110%, 120%, 150%` 时一次性得 `13`，而每步都取整只得 `12`，
  见 `TestTripleProductRoundingDiffersFromStepwise`。
- 全部整数运算，并用 128 位乘法（`math/bits.Mul64` 链式扩展）杜绝中间溢出；
  结果超出 `int64` 时按参数非法拒绝。
- 合上时每人按自身承担学时**独立折算**，允许各人取整误差并存。

### 2.3 学时守恒

一个任务首次必须通过一个**批量指派**完成分配，批次内各人整数学时之和
**恰等于**课程学时，否则整批拒绝（`ErrHoursConservation`）。

### 2.4 中途换人的均匀切分（零头归原教师）

学时在任务全部周次上均匀分布：每周得 `base = H / W`，余 `r = H mod W` 个零头学时
归任务**最早的 `r` 周**。自 `f` 周换人时：

```
oldHours = Σ_{w=start}^{f-1} (base + [w-start < r])
newHours = Σ_{w=f}^{end}    (base + [w-start < r])
oldHours + newHours == 该份额学时   （对原始份额即 == 课程学时）
```

因为零头总是挂在最早周次，无论对原始份额还是对已经是换人片段的份额再次换人，
零头都稳定落在原教师一侧，两人学时之和恒等于份额学时（内部不变量）。

### 2.5 学期核算

```
deficit = max(0, Min - total)          // 欠额（冲抵前）
excess  = max(0, total - Min)          // 超额
creditUsed = min(creditBrought, deficit, floor(Min/4))   // 本学期下限四分之一封顶
unmet      = deficit - creditUsed
creditNext = min(floor(excess/2), floor(Min/4))          // 超出部分作废
```

- 抵扣只冲抵欠额，**不抬高上限**：`total` 始终是原始折算累计，`CreditUsed` 单列。
- 抵扣在**使用学期**按该教师当时职级下限的四分之一封顶；额度在产生学期也已封过一次。
- 核算幂等：已核算学期重复调用返回首次结果（含首次 `SettledAt`），时钟不变。
- 核算后学期**冻结**：任何落在该学期的指派、换人都返回 `ErrState`。
- "上一学期"以已核算学期的 `SettledAt` 先后定义，保证幂等重放时前驱关系稳定。

### 2.6 惰性超时

`pending` 的截止时刻为 `assignedAt + ConfirmDeadline`。判定规则为 `now > deadline`
才超时，**恰等于期限仍有效**。超时不做后台扫描，而是在后续操作触达该教师时
（指派、确认、拒绝、换人，或结算全体教师）即时释放；释放后时段与工作量立刻可用，
且该份额不得再被确认。注意惰性释放只作用于**被触达教师**，这是与朴素模型对齐的
精确语义。

## 3. 错误类别与优先级

错误码按数值递增排列优先级，任何失败只报第一个：

| 优先级 | 类别 | 触发要点 |
| --- | --- | --- |
| 0 | `ErrInvalidArgument` | 空 ID、非正学时/节次、周次非法、未知职级等 |
| 1 | `ErrClockRollback` | `now < 当前时钟` |
| 2 | `ErrNotFound` | 教师或任务不存在 |
| 3 | `ErrState` | 学期已冻结、任务已指派、份额状态不允许响应 |
| 4 | `ErrConflict` | 周次×节次与任一 pending/active 占用相交 |
| 5 | `ErrOverCap` | 计入待确认后累计折算工作量 > 职级上限 |
| 6 | `ErrHoursConservation` | 合上学时之和 ≠ 课程学时（含换人内部不变量） |

**批量指派**必须同时满足"下标最小失败项"与"类别优先级"两条要求，因此校验被拆成
按类别推进的阶段：参数 → 时钟 → 全部项存在性 → 状态 → 冲突（单遍模拟，记录最小
下标但不提前返回）→ 上限 → 守恒。这样当 `items[0]` 守恒错误而 `items[1]` 冲突时，
正确地报 `Conflict@1`（类别优先），同一类别内报最小下标。

所有失败路径在修改真实状态前返回；批量的模拟视图（临时位图/工作量累加）与真实
`schedule` 完全分离，实现真正的全有或全无。

## 4. 并发与确定性

- 服务用单把 `sync.Mutex` 串行化所有写操作，因此任何并发交错都等价于某个串行顺序；
  并发测试以 `-race` 运行。
- 所有写操作都带调用方提供的单调不减逻辑时间 `now`；回退即报错且不动状态。
  份额 ID 由锁内单调计数器分配，因此**相同操作序列重放得到完全相同的 ID、状态与结果**
  （`TestDeterministicReplay`）。

## 5. 冲突判定的复杂度与可验证证明

每个教师持有一个 `schedule`：

```
bits   map[period]uint64             // 节次 -> 周次位图（bit w 表示第 w 周被占用）
counts map[period]map[week]int       // 引用计数，支持换人/释放后精确回收
```

判定新任务 `[s,e] × periods` 是否冲突：

```
mask = Σ_{w=s..e} 1<<w
for p in periods: if bits[p] & mask != 0 => 冲突
```

复杂度为 `O(|periods|)`（常数次位运算），**与该教师历史任务总数无关**。
`add/remove` 用引用计数维护位图，换人释放旧段后位图立即恢复，不残留幽灵占用。

这一点不是只靠"声称"：`TestConflictLookupIndependentOfHistory` 同时测量正式位图实现
与一个**刻意保留全部份额线性扫描**的朴素实现，在历史任务 10 条与 4000 条下的单次
查询耗时——位图几乎不变，朴素扫描随历史数线性增长（典型比值：位图约 1x，朴素约 14x）。

## 6. 被放弃 / 未采用的方案

- **区间树 / 时间线段树**：能支持任意连续节次，但每周节次是有限离散集合，位图更简单
  且无指针开销；位运算判定可精确复现，没有平衡树重平衡带来的非确定性。
- **按份额列表线性扫描冲突**：实现最直观，但判定开销随历史任务总数增长，直接违反
  需求；该方案被保留下来作为差分测试中的"朴素模型"反例。
- **每步立即取整的分步折算**：会产生与题目不符的系统性偏差，已用专门用例锁死差异。
- **换人后新份额重新进入 pending**：中途换人发生在教学过程中，再等待教师确认会留下
  "无人负责"窗口；本实现让交接即时生效，同时仍对新教师做冲突与上限校验。
- **后台定时器清理超时份额**：引入真实时间与异步竞态，破坏"相同序列重放结果相同"；
  改为由后续操作触达的惰性释放，所有状态推进都由输入的逻辑时间确定。
- **全局扫描全体教师做超时释放**：会让一次操作改变未被触达者的状态，既不必要也使
  对照模型复杂；最终只释放被触达教师。

## 7. 代码组织

- `errors.go`：错误码（优先级即数值序）与带批量下标的错误类型。
- `types.go`：配置、规格、报告等对外类型。
- `workload.go`：档位命中与 128 位一次性连乘折算。
- `schedule.go`：周次位图 + 引用计数。
- `teachers_tasks.go` / `assign.go` / `respond.go` / `change.go` / `settle.go`：
  各操作的分阶段校验与原子提交。
- `internals.go`：加锁状态、惰性释放、均匀切分等内部助手。
- `inspect.go`：只读快照，供测试与外部核对。
- `model_naive*.go`：独立编写的朴素模型（线性扫描冲突），仅被差分测试使用。
