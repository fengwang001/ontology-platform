# Pod 中断预算驱逐裁决服务 — 设计说明

面向节点排空（node drain）场景的 PodDisruptionBudget（PDB）驱逐裁决服务。
代码位于 `disruption/` 包，无任何第三方依赖。

## 1. 模块划分

| 文件 | 职责 |
| --- | --- |
| `types.go` | 值类型：`Pod`、`PodDisruptionBudget`、`Selector`、`IntOrPct`、`Phase`、`Tick`、`BudgetStatus`。 |
| `errors.go` | 可程序化判断的错误类别 `Kind`（含严格优先级）与 `AdjudicationError`、`KindOf`。 |
| `budget.go` | 纯函数：预算结构校验、选择器等值匹配、百分比取整、必须保持就绪数、额度。 |
| `state.go` | 索引化集群状态：Pod 表、预算表、命名空间→Pod 索引、标签倒排索引、成员集合与就绪计数、到期最小堆、单调时钟、探测计数器及全部增量维护原语。 |
| `service.go` | 裁决规则：单驱逐、整批驱逐、确认、取消、到期回补、Pod/预算的增删改与就绪翻转；一把互斥锁保证可串行化与批量原子性。 |
| `naive.go` | 独立朴素参考模型：无索引，每次裁决全量扫描所有 Pod×预算，决策簿记独立重写，仅复用纯函数。 |
| `*_test.go` | 单元/边界/错误优先级/并发/复杂度证明/随机差分测试。 |

关键取舍：**状态（state）只做索引维护，规则（service）只做裁决**。
状态层不知道“额度”“冲突”的语义，服务层不直接操作索引内部结构；
朴素模型则完全另起炉灶，避免与被测实现共享同一处潜在缺陷。

## 2. 语义要点与判定公式

- 选择器为空 ⇒ 不匹配任何 Pod；非空选择器要求所列键值**全部**相等；
  预算只匹配同命名空间、且阶段非 Succeeded/Failed 的 Pod。
- `expected` = 范围内被匹配 Pod 总数。
- `minAvailable` 为百分比时按 `ceil(pct*expected/100)`；
  `maxUnavailable` 为百分比时按 `floor(pct*expected/100)`。
- `required` = `minAvailable` 解析值，或 `expected - maxUnavailable` 解析值（不为负）。
- `currentReady` = 成员中“就绪且不在驱逐中”的数量（**记账就绪**）。
- `allowance = max(0, currentReady - required)`，每次查询即时推导，从不缓存。

单驱逐裁决顺序（即错误优先级）：

1. 参数非法（空 id、负宽限）；2. 时钟回退（并先处理到期）；3. Pod 不存在；
4. 阶段不可驱逐；5. 已在驱逐中；6. 被多个预算匹配（冲突）；7. 额度：
- 未匹配任何预算：放行；
- 就绪 Pod：`allowance > 0` 才放行，放行即刻置为“驱逐中”，就绪计数立即 −1；
- 未就绪 Pod：不消耗额度，仅当 `currentReady >= required`（查询时刻）时放行；
- 无论是否匹配，放行后一律进入“驱逐中”（重复驱逐/就绪修改均报 AlreadyEvicting）。

驱逐生命周期：
- `Confirm`：Pod 被移除；`Cancel`：立刻恢复放行前就绪状态；
- 放行时刻 + 宽限到期自动失效，**左闭**：恰在 deadline 时刻视为已失效，
  恢复到放行前就绪状态。任何裁决/查询入口都先处理到期，不存在观察到陈旧状态的窗口。

整批驱逐：
- 空批/批内重复 Pod = 参数非法；
- 每个预算维护“批开始时就绪数”与“已累计消耗的就绪数”；就绪 Pod 累计消耗，
  未就绪 Pod 只按批开始快照判定，不受同批其他 Pod 影响；
- 全部校验通过后才统一提交（validate-then-commit），拒绝时零状态变更，
  且只报告按提交顺序**最先**出问题的 Pod 及其 `Kind`。

## 3. 关键取舍

- **逻辑时钟注入**。所有接受操作都带 `Tick`；回退即 `ClockBacktrack` 且
  不改任何状态（包括时钟）。这让到期边界（左闭）与“回补”可精确复现，
  也让并发测试与差分测试确定性执行。
- **一把互斥锁，而非每预算锁**。单锁即可证明“任意并发等价于某串行顺序”
  且批量天然不可分割；每预算锁在跨预算批处理时需要两阶段锁/死锁规避，
  复杂度高、收益低（裁决本身是纳秒/微秒级内存操作）。
- **就绪计数与成员集合增量维护，额度即时推导**。不缓存 allowance，杜绝陈旧值。
- **驱逐中的 Pod 保留成员身份**，只是记账就绪数不计入；到期/取消做对称回补。
- **预算新增/修改/删除走冷路径全量重算**（只扫同命名空间 Pod）；热路径
  （单驱逐、额度查询）不随无关数据增长（见第 5 节）。
- **确认删除驱逐中 Pod 时先回滚驱逐记账再移除成员**，保证成员集合不残留、
  就绪计数不漂移（这是差分测试发现的真实缺陷，见 `TestSelectorSubsetOfLabelsAndDelete`）。

## 4. 被放弃的方案

- **后台 goroutine 定时扫描到期**：引入真实时间与竞态，无法复现左闭边界，
  且测试不稳定。改为“任何入口惰性处理到期 + deadline 最小堆”。
- **按倒排链交集求候选预算**：直觉上候选更“精确”，但选择器只要求 Pod
  标签集合的一个子集时，交集会漏掉真实匹配（随机差分曾稳定捕获该分歧）。
  最终采用“Pod 各标签倒排链的**并集** + 完整选择器复核”，既不漏匹配，
  也不探测键不相交/值不符/跨命名空间的预算。
- **缓存额度字段**：任何状态变更都要使缓存失效，极易产生陈旧值；放弃，
  改为 O(1) 即时推导（成员数、就绪计数都是现成的标量/集合长度）。
- **细粒度锁 / lock-free**：在内存裁决场景没有可衡量收益，却显著增加
  可串行性证明与批量原子性的难度。
- **朴素模型复用索引实现的内部函数**：会让两个实现共享同一缺陷。朴素模型
  只共享无状态纯函数（取整、选择器、校验），状态组织与簿记完全独立。

## 5. 性能证明方式（非耗时测量）

`state.go` 的 `Probe` 统计四类“原语触碰次数”：Pod 记录、预算记录、
成员条目、到期堆项。`TestCostIndependentOfClusterSize` 在
0/100/1 000/10 000 四个无关规模下断言：

- 单驱逐探测计数**逐字节相同**（1 个 Pod、1 个匹配预算、1 个成员条目）；
- 额度查询只探测 1 个预算记录；
- 另构造同命名空间内 5000 个选择器键不相交、以及 5000 个同键异值的噪声
  预算，断言它们在一次单驱逐中**一次都不被探测**。

因此“开销不随无关 Pod/预算数量增长”是结构性证明（计数器不变即不可能
发生扫描），而不是“耗时看起来差不多”。热路径复杂度：

- 单驱逐/确认/取消/到期：O(K + L)，K=该 Pod 标签命中的倒排链并集大小
  （且经完整选择器复核，只有真实匹配计数），L=真实匹配预算数（冲突即 L>1）；
  与集群总 Pod、总预算数无关。
- 额度查询：O(1)（预算记录内现成的成员集合长度与就绪计数）。
- 冷路径（预算增删改）：O(该命名空间 Pod 数 × 选择器长度)。

## 6. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin
# 若 GOCACHE 默认目录只读：
export GOCACHE=/tmp/gocache

go test ./...                       # 全量
go test -race ./...                # 含竞态检测
go test -v ./disruption             # 打印每步操作的输入/实际输出/判定依据
go test -run TestRandomDifferential -v ./disruption   # 仅差分（约 36000 条操作日志）
go test -run TestCost -v ./disruption                 # 复杂度计数证明
go vet ./... && gofmt -l .
```

差分测试固定随机种子（可复现），逐操作比对：错误类别与首个问题 Pod、
放行决定、每个 Pod 的存在/就绪/驱逐中状态、每个预算的四元组额度状态。
一旦分歧立即报告 seed 与 step，便于复现。

## 7. 公开 API 速览

`NewService()` 后：`UpsertBudget`、`DeleteBudget`、`BudgetQuota`、
`UpsertPod`、`SetReady`、`DeletePod`、`Evict(now,id,grace)`、
`EvictBatch(now,ids,grace)`、`Confirm`、`Cancel`、`Expire`；
所有方法以逻辑时刻 `Tick` 为首参之一。错误统一用 `KindOf(err)` 判别。
