# 本体链接图三态可达性判定器 — 设计说明

## 1. 问题与结果模型

判定器在本体链接图上回答 `ReachableFrom(起点, 终点, 调用者)`，严格区分两类权限：

- **存在性权限（existence）**：调用者能否知道某个对象实例存在。缺失时该对象对调用者等同不存在，任何对外输出都不得区分「不存在」与「存在但不可见」。
- **遍历权限（traversal）**：调用者能否沿某个**链接类型**遍历。缺失时该链接不参与搜索，但两端对象的存在性判定互不影响。

返回三种互斥结果：

| 结果 | 含义 |
| --- | --- |
| `Reachable`（可达） | 存在至少一条路径：两端可见、且路径上每一步的链接类型都可遍历。 |
| `Unreachable`（不可达） | 不存在这样的路径；并且起点、终点均有存在性权限；并且所有被遍历权限截断的候选分支，**即使补齐权限也不可能到达终点**。 |
| `Restricted`（受限未知） | 起点或终点不可见；或至少有一条被截断的候选弧在「无权限全图」中能够通向终点，因而无法证明路径不存在。 |

`Restricted` 与 `Unreachable` 绝不合并：二者是显式区分的两个枚举值。

## 2. 判定次序

固定且可测试的优先级（`ontology/reachability.go` 的 `ReachableWithHook` → `searchLocked`）：

1. **参数非法**：起点/终点/调用者标识不满足 `^[A-Za-z0-9_.:-]{1,128}$` → `ErrInvalidID`。在任何图查询之前完成，杜绝用报错时序探测对象。
2. **确实不存在**：图中根本无该实例（与权限无关）→ `ErrNotFound`。存在性在锁内与快照同时确定。
3. **存在性不可见**：两端之一不在调用者的存在性集合中 → `Restricted / endpoint_invisible`。
4. **正常搜索**：三态图搜索（见 §4）。

不存在错误与三态结果互斥：错误走 `error`，三态走 `Outcome`，调用者无法把「不可见」解析成任何额外信息。

## 3. 图模型与方向

- 对象实例隶属对象类型；链接实例连接两个对象实例并隶属链接类型；建链时校验两端实例类型与链接类型的 `FromType/ToType` 一致。
- 链接类型有方向：`Directed`（仅 Tail→Head）与 `Bidirectional`（正反均可）。
- 建链时把链接**物化为弧**：单向链接生成一条正向弧；双向链接生成正向、反向两条弧。正向 BFS 用出边表 `out`，后向闭包用入边表 `inArcs`（见 `ontology/graph.go`）。

**关键取舍（中间对象可见性）**：搜索过程中，只要求**起点与终点**具备存在性权限；路径中间对象通过「已获遍历权限的链接」抵达本身即构成发现关系——沿一条可遍历链接看到邻居是遍历语义的自然组成。若要求每个中间对象单独授权，则「遍历权限」将退化为冗余。朴素参照模型与引擎采用同一约定并在全部随机用例上一致；如需更严格策略，只需在 BFS 入队处增加一次 `snap.existence` 判断。

## 4. 三态搜索算法

搜索分两个可独立验证的闭包：

1. **前向 BFS（带权限）**：从起点出发，只沿调用者可遍历的弧扩展。
   - 抵达终点 → `Reachable / fully_traversable_path_found`。
   - 无权弧不扩展，但记录其弧头到「被拒集合」。
   - 队列为空且从未遇无权弧 → `Unreachable / exhausted_search_no_candidate`。
2. **后向闭包（无权限，用于精确分类被截断分支）**：从终点沿入边反向做不动点闭包，回答「忽略一切遍历权限时，哪些顶点能流到终点」。
   - 闭包命中任一被拒弧头 → 该弧若获授权即可能通向终点，且不存在其它完全可遍历路径（前向闭包未命中）→ `Restricted / denied_arc_may_reach_target`。
   - 闭包穷尽仍未命中任何被拒弧头 → 被截断的分支在结构上不可能到达终点 → `Unreachable / denied_arcs_cannot_reach_target`。

这正是「候选路径都因权限被截断」与「穷尽确认不存在任何路径」的精确分界线：判定依据不是「遇到过无权边」，而是无权边所在分支在**权限无关全图**中的可达性。

起点等于终点且可见时，零长度路径成立 → `Reachable / same_visible_object`。

## 5. 内部可验证的开销度量

`Trace.Metrics` 只统计本次查询**实际尝试展开**的工作量：

- `ObjectsExpanded` / `LinksAttempted`：前向 BFS 实际出队对象数、实际检查弧数（每次检查都发生一次权限判定）。
- `BacktrackObjects` / `BacktrackLinks`：后向闭包的对应内部工作量。

度量不暴露给普通调用结果，仅通过包内的 `Trace` 供内部验证（`Trace` 属于内部诊断结构，外部服务封装时不应把 `DeniedCandidates` 透传给无审计权限的调用者）。

**不随无关区域增长的保证**：前向 BFS 永远不会进入「调用者在每一条边界上都无遍历权限」的区域。后向闭包从终点反向扩展，因此也不会进入任何**无法流向终点**的区域。`TestMetricIndependentOfForbiddenRegion` 构造一个由单条无权有向弧挂入的 5 与 5000 个节点两种规模的纯汇点链区域，断言 `Metrics` 完全相等（该区域的每一个对象、每一条链接都从未被尝试）。被放弃的「全图 SCC/可达索引」方案见 §7。

度量的精确定位是：在「禁区边界由无权弧构成、且禁区不能回流到终点」这一规范明确覆盖的结构下，查询工作量对禁区规模为 O(1)。若禁区通过双向无权弧与可见核相连，则「补齐权限后是否可达」在最坏情况下确实需要把该区域计入后向闭包——这是问题语义本身要求的（双向弧获权后该区域确实可能成为路径），任何正确实现都无法回避；度量如实反映这部分真实尝试，而不会把完全不可进入的区域计入。

## 6. 并发与串行化

- `Graph` 以一把 `sync.RWMutex` 作为**唯一线性化点**：图变更与权限授予/撤销取写锁；查询在读锁内固定快照并完成搜索。所有操作因此整体等价于某个串行顺序，同一调用者在一次查询内的权限集合为固定深拷贝（`snapshot.existence/traversable`），不受查询期间其它主体修改影响。
- 每个被接受的变更推进单调序号 `seq`；`Trace.SnapshotSeq` 记录该查询看到的前缀边界。被接受的撤销之后开始的任何查询，其快照中必然不再含该权限。
- **查询进行中撤销的时序边界**由 `ReachableWithHook` 确定性复现：快照在 RLock 内固定后立即启动 hook 协程，hook 中的撤销操作阻塞在写锁上直到本次查询释放读锁——这正是串行序 `…查询快照/搜索, 撤销, 后续查询…`。`TestRevocationBoundary` 验证进行中的查询仍答 `Reachable`，而撤销返回后的新查询答 `Restricted`。

该方案的取舍是查询期间持有读锁、变更不与搜索并发执行；换来的是可证明的串行化与简单正确的快照。被放弃的 MVCC/图结构 COW 方案在 §7 说明。

## 7. 被放弃的方案

- **SCC 缩点 + 传递闭包位集（增量索引）**：可让分类在最坏情况下也做到查询期 O(1) 判定，但动态增量维护 SCC/传递闭包复杂度高、实现与验证成本大，且本题要求度量的是「本次查询实际尝试的对象与链接」，索引探测并不等价于尝试展开。当前双闭包方案对规范明确的禁区结构已给出 O(1) 不增长保证，且度量语义更贴合题意。
- **朴素 DFS 枚举全部简单路径**：语义最直观，但最坏指数级，仅适合作为独立参照。已作为 `ontology/naive` 包保留用于差分测试，不用于生产路径。
- **MVCC / 图结构写时复制 + 无锁并发搜索**：可获得真正的查询/变更并发与快照隔离，但显著增加内存与正确性负担；单机内存图上读写锁已满足「等价某串行顺序」的全部要求，故不采用。
- **遇无权边即返回「未知」**：实现最简单，但会把大量本可精确判为 `Unreachable` 的情况错误上报（例如无权弧通向与终点无关的汇点），违背「只有被跳过路径无论权限如何都不可能通向终点才允许判不可达」的精确区分要求，明确放弃。

## 8. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin   # 若 go 不在默认 PATH
go test -race -v ./ontology/...
```

覆盖内容：

- `TestExistenceVsTraversalDifference`：存在性缺失 vs 遍历缺失导致的不同结果与不同分类理由。
- `TestRestrictedVsUnreachableBoundary`：唯一可能路径恰被截断 → `Restricted`；被截断分支为无关汇点 → `Unreachable`；完全无候选 → `Unreachable`。
- `TestRevocationBoundary`：查询进行中撤销的串行化时序。
- `TestDirectionAsymmetry`：单向链接交换起终点结果不对称，双向链接对称。
- `TestMetricIndependentOfForbiddenRegion`：追加 4995 个调用者无权进入的对象后，查询度量保持不变。
- `TestRandomDifferential`：400 个随机种子下随机生成对象、链接（含两种方向）、授予/撤销序列，共 2400 次查询，与独立朴素模型逐次对照；每次查询的输入、引擎输出、朴素输出、三态分类理由与内部度量写入 `ontology/testdata/differential_queries.jsonl`。
- `TestRandomInvalidAndAbsent`：随机场景下反复验证判定次序的前两级（非法标识、确实不存在）。

静态检查：

```bash
gofmt -l .
go vet ./...
```
