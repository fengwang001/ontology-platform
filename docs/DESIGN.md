# 机关档案借阅与预约服务 — 设计说明

## 1. 范围与模型

- 时间为整数日序号；每个 `Service` 维护单调时钟 `lastNow`，只被**被接受**的操作推进。
- 密级（低→高）：`公开=0 < 内部=1 < 机密=2 < 绝密=3`；借阅人持有可借最高密级，`maxClass >= 卷密级` 才有资格。
- 卷状态：`在库 / 借出 / 封存`。实现内部把“已自动分配但尚未取走”也归为 `借出`（用独立的 `hold` 结构表达），因为此时该卷已不可能再借给他人；这满足“同一时刻一卷最多借给一人”。
- 借阅人状态：`正常 / 暂停`。

初始化参数（`archive.Config`）：

| 字段 | 含义 |
| --- | --- |
| `LoanDays[4]` | 各密级基础借期天数 |
| `PickupDeadlineDays` | 分配后取卷期限（自分配日起，最后一天仍可取） |
| `RenewWindowDays` | 续借窗口：`[借期最后一日 - 该值, 借期最后一日]`，两端都含 |
| `MaxRenewals` | 每次借阅的续借次数上限 |
| `OverdueThreshold` | 累计逾期天数达到该值（恰等）进入暂停 |
| `CooldownDays` | 解除暂停的冷静天数（自最近一次归还起，恰等解除） |

## 2. 关键不变量

1. 借期：借出日 `d`，借期最后一日 = `d + LoanDays`。归还 `<=` 最后一日不逾期；逾期天数 = `归还日 - 最后一日`。
2. 续借：窗口 `[due - W, due]`，起点、终点恰等都允许；`due` 之后窗口关闭。通过后 `due += LoanDays`，即新借期自**原借期最后一日的下一日**起算，与申请日无关。
3. 预约队列保持提交顺序；被分配者**分配即出队**（队列只含尚未被分配的等待者），其信息记录在 `hold` 中。
4. 分配只选“队首起第一个 正常 且 `maxClass>=卷密级`”的人；密级下调或暂停冻结者被**跳过但保留原序位**。
5. 取卷期限 `deadline = 分配日 + P`：`now <= deadline` 可取；`now > deadline` 未取即放弃，失去位置，卷继续向后级联分配。
6. 逾期只在**归还时**结算并入累计；仍在借的逾期卷不计入累计。累计 `>= 阈值`（恰等）立即暂停。
7. 暂停解除需同时满足：在借卷数为 0 且 `now - 最近归还日 >= CooldownDays`（恰等解除）；解除时累计逾期清零。
8. 封存：在库立即封存；借出/待取中的卷 `sealPending`，其既有预约**立即全部取消**，在卷归还或持卷人放弃后落到封存，不再分配。

## 3. 操作判定顺序（错误优先级的具体化）

错误枚举值本身即优先级序（小者优先）：
`参数非法 < 时钟回退 < 不存在 < 状态不允许 < 密级不足 < 暂停 < 卷已借出 < 续借超限/窗口未到 < 存在有效预约`。

所有时间相关操作统一按下列顺序判定，被拒绝不修改状态与时钟：

1. 结构性参数非法（空 id、批内重复卷、批为空）。
2. 时钟回退。
3. 卷或借阅人不存在。
4. 各操作的业务判定（见下）。
5. 通过后调用 `tick(now)` 做全局时间结算（暂停解除 + 待取到期放弃的级联），随后**复查**业务条件；复查失败同样整体拒绝（例如待取恰在本步到期）。
6. 生效并写入。

各操作业务判定：

- 借阅：封存(状态) → 密级 → 暂停 → 已借出。
- 预约：封存(状态) → 密级 → 重复预约(状态) → 在库只能借(状态)。**暂停不拦截预约**：依据题面“借阅人密级不低于卷密级方可借阅与预约”与“暂停期间已排预约冻结”，我们允许暂停者新预约，但预约立即处于冻结状态，不参与分配，解除暂停后自动恢复。
- 取卷：无本人待取(状态) → 暂停 → 密级（取卷当日重新校验密级，处理“分配后被下调”）。
- 归还：非本人在借(状态)。
- 续借：自审批(参数非法) → [存在性] → 机密及以上缺审批人(参数非法) → 非本人在借(状态) → 待封存(状态) → 密级 → 暂停 → 窗口未到/已过 → 续借超限 → 存在有效预约。

### 关键取舍（含被放弃的方案）

- **自审批归为“参数非法”并先于存在性检查**：审批人不得是本人是结构性约束，与空 id 同类；而“是否需要审批人”取决于卷密级，故“机密及以上 approver 为空”放在存在性之后。被放弃方案：新增独立错误码（题目错误类别已穷举，不应擅自增加）。
- **暂停者可以新预约但冻结**：被放弃方案是“暂停期间禁止新预约”。题面只禁止“借阅与续借”，且明确给出“已排预约冻结”概念；允许入队但不分配在随机模型中语义更平滑，也与“解除后恢复原序位”一致。文档化该选择。
- **待取（已分配未取）在外部状态上计为“借出”**：被放弃方案是新增“待取”第四态。题目状态枚举固定为三种，待取期间卷不可再借/再预约给他人，归入借出并用 `hold` 区分最贴切。
- **全局确定性 `tick` 而非事件驱动**：每次接受操作前以固定顺序（按 id 排序）处理“所有用户暂停解除、所有卷待取到期”。被放弃方案：只惰性处理当前卷。全局结算使“冷静期恰等解除”“无操作时时间也在流逝”的语义可由一次 `Advance(now)` 精确观测，且天然可重放；`map` 遍历显式排序消除不确定性。
- **续借后逾期与否按新 due 判断**，续借必须在 `due` 之前（含 due）完成，`due` 之后只能归还并计逾期。

## 4. 数据结构与“分配开销不随历史增长”

预约队列使用**侵入式双向链表**（`archive/queue.go`）：

- 入队 O(1)（尾插）；取消/分配出队 O(1)（前后指针直接摘除）。
- 分配扫描只遍历当前仍在队中的节点，并在第一个合格者处停止。因此扫描步数 ≤ 当前存活队列长度，**与历史上出现过多少预约完全无关**。

被放弃方案：

- 切片 + 全量扫描（朴素模型仍采用，作为对照）：随历史线性增长，违背要求。
- 单链表 + 惰性死节点：若合格者前面长期堆积跳过/死节点，扫描仍可能随历史增长。

可验证方式：

- `Service.ScanSteps(volumeID)` 暴露最近一次分配扫描实际访问的存活节点数。
- `TestAssignCostIndependentOfHistory` 制造 500 个“预约后取消”的历史节点，再以 3 个存活等待者（队首为暂停冻结者）归还，断言扫描步数恰为 2，且历史规模翻番不改变结论。

## 5. 并发与可串行化

- 所有公开方法在单个 `sync.Mutex` 下串行执行，因此任一并发执行的结果等价于这些操作按互斥获取顺序构成的某个串行序列；不可能出现一卷同时借给两人。
- 确定性来自：整数时钟、排序的全局结算、无随机/无 map 遍历顺序依赖、被拒操作零副作用。相同操作序列重放得到逐字节相同的结果日志与快照（`TestReplayDeterminism`）。

## 6. 被放弃的其他方案

- 用真实时间/墙钟：与“整数日序号、now 单调”冲突，放弃。
- 为预约/审批/封存新增更多错误码：题目给定九个错误类别且要求固定优先级，额外错误会破坏优先级，全部折叠进既有类别。
- 持久化：题目要求的是内存可重放服务；持久化不在范围，`Snapshot()` 已提供完整状态导出，可在此之上加日志快照持久化。

## 7. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache

go test ./...                         # 全量
go test -race -v ./...               # 竞态 + 详细
go test -coverprofile=cov ./...      # 覆盖率

# 随机对照逐步日志（每步输入/输出/判定依据）：
RANDOM_TRACE_LOG=$PWD/archive/testdata/random_trace.log \
  go test ./archive/ -run TestRandomDifferential -count=1

# 边界用例各自的逐步日志：
go test -v ./archive/ -run 'TestDueDay|TestRenew|TestQueue|TestPickup|TestSuspend|TestOverdue|TestSeal|TestBatch|TestRejection'
```

`archive/testdata/` 下同时保留边界测试的 `trace.TestXxx.log` 与随机对照日志。
