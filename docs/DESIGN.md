# 基于角色与标签的访问控制模块 — 设计说明

## 1. 问题与模型

标签不直接授予对象实例，而是授予由**对象类型**与**链接类型**构成的关系
网络；实例通过其所属对象类型在网络中的位置继承标签。角色对标签持有
允许（Allow）/显式拒绝（Deny）授权，授权沿角色层级继承。主体对实例的
最终权限 = 主体对实例携带的全部标签的授权结论的综合。

核心抽象（`ontology/types.go`）：

- `LinkType{From, To}`：对象类型间的有向边，From→To 为下游。
- 传播声明 `(tag, linkType, direction)`：标签可沿某链接类型向下游或上游
  传播，深度不限。
- 阻断点 `(tag, linkType)`：标签不得跨越该链接类型。
- 直接附着 `(tag, objectType)`：标签的种子来源。
- 角色层级 `role → parents`、直接授权 `(role, tag) → effect`。

## 2. 关键设计取舍

### 2.1 声明状态与派生状态分离，每次变更全量重算派生状态

引擎内部只有声明状态（对象类型、链接、传播、阻断、授权……）是事实源；
有效标签集、有效授权表、环标记全部是**派生物化视图**。每次变更在写锁
内调用 `recomputeLocked()` 从声明状态整体重算派生状态，然后才释放锁。

收益：

- **增量 == 重算**（需求：运行期图变化的结果与从空白重建完全一致）由
  构造保证——派生状态就是声明状态的纯函数，不存在增量维护漂移的可能。
  `TestIncrementalEqualsRebuild` 直接复制声明状态重算并 `DeepEqual` 比对。
- **撤销级联自动正确**：移除一个来源后重算，仅剩该来源的下游标签自然
  消失，有其他独立来源的自然保留；无需维护反向依赖计数。
- **原子性**：重算与变更同属一个临界区，外部只能观察到变更前或变更后
  的完整状态（`TestRevocationIsAtomic`）。

代价：变更成本为 O(网络规模)。本模块的约束只要求**访问判定**成本与
网络规模无关（见 2.4），变更侧的全量重算是可接受的交换。

### 2.2 标签继承 = 可达性不动点（集合语义）

对每个标签，从直接附着的类型出发，沿该标签可用的（已声明传播且未被
阻断的）有向边做 BFS 可达性计算。集合语义天然满足：

- **多路径收敛**：同一标签经多条路径到达同一类型，结论是该标签存在
  与否的唯一布尔值，与路径枚举顺序无关；
- **环安全**：visited 集合保证终止，结果与环的存在无关；
- **阻断点**：被阻断的边不参与遍历；未经过阻断点的独立路径不受影响。

「全部路径被阻断」集合（`typeBlocked`）= 忽略阻断时的可达集 − 实际可达
集，在同一趟重算中物化，供错误分类 2 使用。

### 2.3 授权裁决：最近距离优先，同距拒绝优先

角色 R 对标签 T 的有效结论：收集 R 经父链可达的全部允许/拒绝声明及其
继承距离（直接声明 = 0），**最小距离**处的声明生效；该距离上允许与
拒绝并存时**拒绝优先**。四种组合的唯一裁决：

| 组合 | 裁决 | 依据 |
|---|---|---|
| 直接允许 vs 直接拒绝 | 拒绝 | 同距离，拒绝优先 |
| 直接允许 vs 继承拒绝 | 允许 | 距离 0 < 距离 ≥1 |
| 继承允许 vs 直接拒绝 | 拒绝 | 距离 0 < 距离 ≥1 |
| 继承允许 vs 继承拒绝 | 拒绝 | 最近距离处拒绝优先 |

主体级综合：任一有效角色的显式拒绝覆盖所有允许（deny-override）。
实例级综合：全部标签均允许才放行；任一标签显式拒绝 →
`explicit-deny-override`；否则任一标签无允许结论 → `missing-grant`
（默认拒绝）。所有综合都是集合聚合，与标签登记顺序、授权登记顺序无关
（`TestFinalCombinationAcrossTags` 以相反顺序重建验证）。

### 2.4 判定成本与网络规模无关（可观测证明）

判定时不做任何图遍历：实例标签 = 其对象类型的物化标签集的一次查表；
主体结论 = 其直接角色的物化授权表的若干次查表。成本为
O(实例标签数 + 主体角色数)。`Decision.Stats`（`TraversalStats`）把实际
遍历量作为返回值暴露，`TestTraversalCostIndependentOfNetworkSize` 在
网络扩大 100 倍后断言计数器按位相等——这是不依赖实现细节的黑盒证据。

### 2.5 错误分类与固定优先级

`DecisionError.Class` 按固定唯一优先级汇报：

1. `ClassNotFound` — 主体/实例/标签不存在；
2. `ClassAllPathsBlocked` — 标签继承路径全部被阻断（`CheckTag`）；
3. `ReasonExplicitDenyOverride` — 显式拒绝覆盖隐式允许（作为拒绝判定
   的 Reason 汇报，而非 error）；
4. `ClassRoleCycle` — 角色层级存在循环继承，授权来源不可确定。

裁决顺序的实现规则：先检查存在性；再检查阻断；然后用**非循环角色**
计算结论——若能确定显式拒绝覆盖则按类 3 汇报；否则若主体任一角色
的祖先闭包含环则报类 4。循环角色的授权表仍被物化（BFS 有 visited 集
合，必然终止），但判定时被排除，因为其来源不可确定。

判定是纯读操作（`RLock`），不触碰任何派生状态、角色层级或时钟；引擎
内部不持有任何时钟（`TestDeniedDecisionHasNoSideEffects` 比对拒绝前后
全部派生状态）。

### 2.6 并发：单读写锁实现可串行化

所有变更取写锁、所有判定取读锁，每个调用都是原子的，因此任意并发
执行线性可串行化——必然等价于某个串行顺序。审计日志在锁内追加，
事件顺序即串行顺序。

## 3. 被放弃的方案

- **增量维护派生状态（反向依赖图 + 级联失效）**：能降低变更成本，但
  在「多父、多路径、环、阻断、双来源撤销」叠加下正确性极难论证，且
  需求明确要求增量结果与从头重算一致——全量重算使该性质平凡成立。
  若未来变更成为瓶颈，可在保持「声明状态为唯一事实源」的前提下引入
  分标签的增量重算作为纯性能优化。
- **查询时遍历（每次判定即时 DFS）**：省掉物化，但判定成本随网络规模
  增长，直接违反遍历开销约束。
- **拒绝全局优先（deny-overrides-everything，不看距离）**：语义更简单，
  但会使「直接允许 vs 继承拒绝」裁为拒绝，违背直觉上「更具体的声明
  应当胜出」的期望，且无法区分四种组合。当前规则对四种组合给出明确
  且不矛盾的结果。
- **声明时拒绝成环**：在 `AddRoleParent` 时拒绝引入环可以让错误更早
  暴露，但需求把「角色层级循环」列为判定时的错误类别，故允许声明、
  在物化时检测、判定时按优先级汇报。
- **链接类型级的全局传播资格**（链接类型本身可传播任意标签）：表达力
  弱于按 `(tag, linkType)` 声明，且「移除某条链接类型的传播资格」在
  当前模型中有直接对应（`RevokePropagation`）。

## 4. 验证方法（本地可复现）

```bash
go test ./...            # 全部单元/差分/并发/统计测试
go test -race ./...      # 竞态检测下的并发串行性
go vet ./... && gofmt -l .
```

- **差分测试**（`ontology/naive_test.go` + `differential_test.go`）：
  独立维护的朴素参照实现使用与主实现不同的算法（逐查询 DFS 可达性、
  简单路径枚举求最近距离），随机生成关系图与声明序列（200 种子 ×
  150 步，每 5 步全量比对实例标签集与随机三元组的 Authorize/CheckTag
  判定、Reason 与错误类别），逐项对照。
- **遍历开销证明**：`stats_test.go` 以返回值中的计数器做黑盒断言。
- **并发**：`concurrency_test.go` 在并发读写下验证最终派生状态与无读
  压力的孪生引擎逐位一致，并验证单变更级联的原子可观察性。
- **审计**：`audit_test.go` 验证每次调用的输入、输出与标签/角色依据
  完整落日志。

## 5. 模块布局

| 文件 | 职责 |
|---|---|
| `ontology/types.go` | 公共类型：方向、效果、判定依据、遍历统计 |
| `ontology/errors.go` | 错误类别与固定优先级 |
| `ontology/engine.go` | 声明状态、全部变更 API、锁与重算钩子 |
| `ontology/propagate.go` | 标签传播/阻断/全阻断集合的物化 |
| `ontology/grants.go` | 角色有效授权物化与层级环检测 |
| `ontology/authorize.go` | Authorize / CheckTag、综合规则、判定统计 |
| `ontology/audit.go` | 审计日志接口与内存实现 |
| `cmd/server` | JSON/HTTP 演示服务（含种子场景） |
