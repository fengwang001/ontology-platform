# 变压器容量预约系统 — 设计说明

## 模块划分（package transformer）
- `types.go`：状态机（占位中/已确认/已失效/已取消/已完成/已释放）、错误类别（声明序即拒绝次序）、结构化错误。
- `occupancy.go`：时刻槽占用表 `slotMap`（每馈线一份、变压器总和一份、仅已确认一份）与容量表（有序数组+二分）。
- `system.go`：System 骨架、时钟推进与落定、快照与性能计数器。
- `ops.go`：创建/确认/释放/改约；两级校验按时刻升序扫描，首个违例时刻即返回，同级先报馈线。
- `capacity.go`：容量记录登记；先以"仅已确认"占用校验，拒绝则报首个超出时刻；接受后逐时刻按创建时刻从晚到早取消占位。

## 关键取舍
- 占用按整数时刻槽存 `map[time]int`：校验/占用开销 O(区间长度)，与不相交预约数严格无关；
  容量表二分 O(log R)。两者用计数器（SlotVisits/CapCompares）在测试中验证，而非墙钟时间。
- 到期时刻=创建时刻+固定占位时长，随 ID 单调，故到期占位用 FIFO 队列；完成用最小堆+惰性删除。
  推进开销只与本次弹出条目数相关（摊还 O(1)/预约），测试用 Settled/SettlePops 验证。
- 全局互斥锁串行化所有操作：天然满足"并发等价于某串行顺序"与"相同序列重放结果相同"；ID 单调分配。
- 占位即占容量，确认不再校验；容量下调对已确认（拒绝变更）与占位（接受后取消）不对称处置。
- 已开始的已确认预约仅允许提前结束（起点/功率不变，终点∈[当前时刻, 原终点]），终点=当前时刻立即完成。
- 确认已失效占位报"占位已到期"、确认已取消报"已取消"，其余终态操作报"状态不允许"，使各类别可达。
- 区间非法统一定义为 end<=start 或 start<当前时刻（已开始的已确认预约走提前结束特例）。

## 被放弃的方案
- 差分数组+线段树/treap：区间 max 查询为对数级，实现重，且"严格不随规模增长"不如时刻槽直接。
- 无锁并发/分片锁：收益低，串行等价语义与确定性重放难保证。
- 容量表也用时刻槽展开：时间无上界，内存不可控，故保留有序数组+二分。

## 本地验证
- `go test ./transformer/ -v`：定向边界用例（端点相接、到期确认、双级同亏报馈线、改约排除自身、
  容量下调拒绝/取消、生效时刻等于预约起点、提前结束、拒绝次序、并发不变量）。
- `go test ./transformer/ -run TestDifferentialRandom -v`：8 种子×300 步随机序列与逐时刻朴素模型对拍，
  逐条打印输入/输出/判定依据，每步比对全部预约状态。
- `go test -race ./transformer/`；`go vet ./...`；`gofmt -l .`。
