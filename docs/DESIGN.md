# 优先级与公平性准入控制器设计说明

包路径：`apf/`（admission priority & fairness）。本文档记录模块划分、关键取舍、
被放弃的方案与本地验证方法。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `apf/errors.go` | 六类错误的可区分类型，声明顺序即优先级（参数非法 > 时钟回退 > 无匹配 > 席位不可满足 > 队列已满 > 排队超时）。 |
| `apf/config.go` | 配置结构、合法性校验、按份额的名义席位分配（向下取整 + 余量按份额降序/名称升序逐席补齐）。 |
| `apf/classify.go` | 流分类：规则编译（按优先级数值、名称排序）与首条命中匹配；流标识按用户或命名空间。 |
| `apf/level.go` | 单个受限级别的运行时状态：流分组队列、流间轮转、队首阻塞出队、超时驱逐堆。 |
| `apf/heap.go` | 按 (截止时间, 序号) 排序的最小堆，支持懒删除。 |
| `apf/controller.go` | 控制器：准入、完成释放、热更新、注入时钟、维护（驱逐+出队）的统一编排；互斥锁保证可串行化。 |
| `apf/naive.go` | 朴素参照模型：相同语义、纯切片线性扫描实现，仅用于差分测试。 |

## 语义要点与关键取舍

### 时钟与维护（maintenance）

- 时间完全由调用方注入。控制器记录 `lastTime`（最近一次**被接受**操作的时刻），
  任何更早时刻的操作报时钟回退且不产生任何副作用。
- 每个参数合法、时钟合法的操作开始时，先执行维护：驱逐等待时长达到超时（左闭，
  `deadline <= t`）的等待者，并触发因此解除阻塞的出队。这保证“超时的失效在下一次
  任何操作之前体现”。
- **被拒绝的请求不改变任何准入状态**：不入队、不占席位、不推进轮转游标，也不推进
  `lastTime`。需要说明的解释：维护（超时驱逐及其引发的出队）被建模为“时间流逝”的
  效果而非请求自身的效果，因此即使请求随后被拒绝，维护的结果仍然保留；但
  `lastTime` 不前进，后续不早于最后被接受时刻的操作依然合法。

### 流间轮转

- 每个受限级别维护“由空变非空”次序的流链表 + 哈希表索引。轮转游标是单个链表元素，
  出队只考察游标选中的流的队首；放不下则整个级别停止（队首阻塞）。
- “上一次被服务的流”按**流身份**追踪（`lastServed` 键）：若该流变空后又重新变非空，
  它排到轮转次序末尾，游标随之指向新元素。这是差分测试抓出来的真实分歧——按链表
  位置锚定会在流重新入列时错误地回到队首。

### 复杂度

- 入队：哈希表定位流 O(1) + 堆插入 O(log n)。
- 出队/完成：每次出队一个请求 O(1) 链表操作；堆中的失效条目懒删除，均摊 O(log n)。
- 超时驱逐：每个超时者 O(log n)，不扫描全队列。
- 均不随流总数或等待请求总数线性增长。`Controller.ProbeCount()` 导出堆关键比较
  次数，测试用它验证 O(W log W) 上界（见 `apf/perf_test.go`）。

### 热更新

- 整份替换；先校验，非法则整体不生效（且不占时钟）。
- 级别状态按名字存续：在途请求不打断、不重新分类（`Lease` 持有级别状态指针）；
  已排队请求留在入队时的级别，但出队受新名义席位约束；新配置中消失或变为豁免的
  级别名义席位视为 0，其排队请求在更新时即以“席位不可满足”拒绝。
- 更新后对所有级别补一轮出队（名义席位可能变大）。

### 并发

单一互斥锁串行化所有操作。票据（`Ticket`）结果通道缓冲为 1 且恰好投递一次，
因此锁内通知永不阻塞。任意并发调用的结果等价于锁决定的某个串行顺序。

## 被放弃的方案

1. **虚拟时间（virtual time）公平队列**（类似 Kubernetes APF 的 R 值）：实现与推理
   成本都高，而规范要求的是“由空变非空次序 + 上次服务流之后”的显式轮转，用链表
   游标即可精确表达，故放弃。
2. **出队时跳过放不下的队首、尝试后续流**：规范明确要求队首阻塞即全级别停止，
   跳过会改变可观察行为，放弃。
3. **被拒绝操作的事务化回滚**（维护也撤销）：需要撤销已投递的票据通知，复杂度
   高且与“超时须在下一次操作前体现”冲突；改为把维护建模为时间效果（见上）。
4. **超时扫描全队列**：O(n) 且随等待者线性增长，违反性能要求，改用最小堆 + 懒删除。
5. **每个流独立 goroutine/锁**：难以保证全局可串行化与精确的时钟语义，放弃，
   采用单互斥锁 + 注入时钟的确定性模型。

## 本地验证方法

```bash
# 单元测试（规则次序、余量分配、豁免、不可满足、队列已满、FIFO/轮转、
# 队首阻塞、超时边界、热更新、错误优先级、时钟回退）
go test ./apf/ -v

# 与朴素模型的随机差分对照（默认 40 种子 × 300 操作；可用环境变量放大）
APF_DIFF_SEEDS=500 APF_DIFF_OPS=800 go test ./apf/ -run TestDifferentialRandom -v

# 竞态检测全量
go test -race ./...

# 性能上界验证（堆比较次数 ≤ 8·W·⌈log2 W⌉，与流数无关）与基准
go test ./apf/ -run 'TestPerf' -v
go test ./apf/ -run xxx -bench .
```

差分测试会打印每次操作的输入、实际输出与判定依据（操作后各级别的
占用/名义席位、等待者数、流轮转次序），失败时可直接定位分歧操作。
