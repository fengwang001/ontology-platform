# 模块打包器死代码裁剪分析器 —— 设计说明

## 1. 目标与范围

给定模块图、入口集合与各模块副作用声明，求解：

- 最终**被引入**的模块集合；
- 最终**必须保留**的声明集合及保留原因（`entry-export` / `referenced` / `side-effect`）；
- 对非法输入与无法解析的导入，按可区分类别、按规定次序只报告第一处错误。

结果是满足所有保留规则的**最小不动点**。

## 2. 模块划分（单一职责）

| 包 | 职责 |
| --- | --- |
| `dce/model` | 纯数据模型：`Module` / `Declaration` / `Import` / `Export`，副作用三态，`Snapshot` 深拷贝 |
| `dce/dceerr` | 错误类别（7 类）与可机读定位信息 |
| `dce/validate` | 构造期检查：类别 1（登记时）与类别 2/3/4（快照上） |
| `dce/resolver` | 只读快照上的导出解析，全部记忆化，含星链展开与三类解析错误 |
| `dce/analyzer` | 保留规则的最小不动点（worklist）、原因优先级、绑定后检、日志接口 |
| `dce/registry` | 并发安全登记表、入口固定的只读会话、快照隔离与校验编排 |
| `dce/cmd/example` | 端到端可运行示例 |
| `dce/dce_test` | 场景测试、并发/快照测试、复杂度计数测试、朴素模型随机差分 |

依赖方向严格单向：`registry → {analyzer → resolver → model}`，`validate → model`，
`dceerr` 无内部依赖。

## 3. 导出解析（`resolver`）

### 3.1 数据组织

每个模块惰性建立索引：

- `explicit map[name]Export`：本地声明导出 + 具名重导出（通配重导出不占名）；
- `stars []target`：通配重导出目标，按登记次序。

### 3.2 解析规则

1. 名字命中 `explicit`：本地导出定位到本模块声明；具名重导出沿
   `(target, foreignName)` 继续。
2. 未命中 `explicit`：沿星链 DFS 收集该名字的全部候选最终声明。
   - 候选去重后恰一个 → 成功；
   - 多个不同声明 → `ambiguous export`；
   - 无候选且链上有错误 → 返回该错误；
   - 无候选无错误 → `missing export`。
3. 具名重导出维护链上 `(module,name)` 集合，回到已经过项 → `reexport cycle`。
4. 纯星链回溯（星 DFS 路径上回到已访问模块）**不报错**，该路径停止贡献：
   环上的名字不是任何一次具名跳转引入的，不构成“重导出链回到经过的名字”。
5. 本地导出与具名重导出总是优先于星链；星链不转发 `default`。

### 3.3 记忆化与复杂度

- 具名解析结果按 `(module,name)` 记忆化；**每个槽位至多真正解析一次**
  （`Stats.NamedResolves`）。
- 星链 DFS 用调用内 `onStack`/`seen` 去重，配合 `Stats.StarExpansions` 计数；
  星视图 `StarDecls(mod)` 按模块只计算一次。
- 入口/通配导入的“名字宇宙”由一次星链 DFS 得到，避免逐名字重复展开同一星链。
- 总工作量：具名解析 O(名字槽位数)，星链 DFS 在每次解析/星视图中每模块只访问一次；
  最坏输出相关项（多个星链对同一声明的重复转发）按结果规模线性。

可验证性：`Result.Stats` 与 `Result.ResolverStats` 暴露真实计数，测试断言
`DeclProcessed ≤ 声明总数`、`ModulesScanned ≤ 模块总数`、
`NamedResolves ≤ 模块数 × 名字宇宙规模`，并用 100/400 节点链验证 4 倍规模下
各计数增长不超过线性余量（见 `linearity_test.go`）。

### 3.4 一个刻意记录的边界取舍

解析是递归同步执行的，记忆化条目的 `visiting` 状态只存在于调用栈内；
跨链观察到的 `visiting` 只会发生在“另一棵具名链恰好回到当前未完成槽位”的
结构性重入，此时返回 `reexport cycle`，结果与遍历/入口次序无关。
纯星链环由星 DFS 的已访问集合吸收，永不被误报为环。

## 4. 最小不动点（`analyzer`）

### 4.1 规则到算子的映射

- 入口模块：直接引入；其全部**有效**导出解析到的声明以 `entry-export` 保留
  （歧义/缺失/环名不是有效导出，入口处不报错）。
- 被引入模块的全部导入语句都参与：
  - 目标模块“有”副作用 → 引入目标，其中带副作用声明以 `side-effect` 保留；
  - 目标模块“无”副作用 → 不因纯副作用导入引入；只有其中声明因
    `entry-export`/`referenced` 保留时才引入；
  - 绑定（含 `*`）解析到的声明以 `referenced` 保留。
- 保留声明的引用：本地声明直接保留；否则查本地导入绑定再解析。

### 4.2 worklist

两个队列：`modQueue`（新引入模块，导入只扫描一次）与
`declQueue`（新保留声明，每个 `(module,decl)` 只入队一次）。
原因映射 `keep[key]reason` 只允许按
`entry-export < referenced < side-effect` 升级；原因升级不改变引用闭包，
因此声明无需二次处理。队列排空即最小不动点——每条规则都是单调的，
worklist 从空集出发恰好收敛到最小解。

### 4.3 解析错误的处理时机

求不动点期间，无法解析的具名绑定**不产生任何引用**（`*` 绑定天然不报错）。
得到被引入集合后，再按**模块标识升序、绑定登记次序**对被引入模块的全部绑定
做一次解析检查，命中第一处 `missing/ambiguous/cycle` 即整体失败、不返回部分结果。
这样错误次序与不动点遍历顺序解耦，严格满足题意。

## 5. 构造期检查的优先级（`validate`）

1. `invalid argument`：空标识、模块内声明名重复、导入本地名重复、导出名重复；
2. `duplicate module`；
3. `unknown module`（导入目标、重导出目标；入口未知在求解时归入本类，且优先报告）；
4. `undefined reference`：声明引用既非本地声明也非本地导入绑定。

类别 1 在 `Register` 时同步拒绝（自包含检查），被拒绝登记先做深拷贝再校验，
**绝不改变登记状态**；类别 2 同样在登记时拒绝。类别 3/4 依赖完整图，
在 `Solve` 的快照上按“类别 → 模块标识升序 → 登记次序”统一报告第一处，
从而在多调用方交错登记时仍给出与串行化等价的确定结果。构造期检查全部先于解析检查。

## 6. 并发与快照

- `Registry` 以互斥锁保护 map 与登记次序；登记对象深拷贝入库。
- `NewSession` 在锁内深拷贝当前全部模块并固定入口去重列表；
  `Solve` 只读该快照。后续登记、调用方对原对象的修改都不影响既有会话。
- 多次 `Solve` 彼此无共享可变状态（解析器为每次求解新建），可并发。
- 串行等价性：所有判定只依赖会话时刻的模块集合，与登记调用的交错方式无关；
  错误次序按标识与登记次序，而非 goroutine 调度次序。

## 7. 日志

`analyzer.Logger` 记录每次输入（入口）、模块引入依据、每条保留声明的原因与
判定依据、绑定错误与最终输出。提供 `TextLogger`（可读文本）与 `NopLogger`。
差分测试可通过 `DCE_DIFF_LOG` 将每张随机图、引擎输出落盘以便复盘。

## 8. 被放弃 / 未采用的方案

- **反向依赖图 + SCC/Tarjan**：可以统一处理导入环，但对“副作用三态、
  星链歧义、原因优先级”的组合规则反而更绕；worklist 直接表达规则且天然最小解。
- **逐名字递归展开星链且不记忆化**：实现最简单，但星链上模块会被重复访问，
  最坏平方级；改为名字宇宙一次 DFS + `(module,name)` 记忆化。
- **在不动点遍历途中收集并比较绑定错误**：错误次序会依赖遍历顺序；
  改为不动点后对被引入模块做有序后检。
- **构造期全部错误延后到 Solve**：虽然也满足优先级，但被拒绝登记可能短暂落库，
  且无法向登记调用方即时反馈；故类别 1/2 即时拒绝、3/4 快照统一报告。

## 9. 本地验证

```bash
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache
go test ./...                 # 全量
go test -race ./...           # 并发安全
go vet ./... && gofmt -l .    # 静态检查与格式
go run ./dce/cmd/example      # 端到端示例（日志打印到 stderr）

# 近线性计数验证：
go test -run TestNearLinearWork -v ./dce/dce_test
```

朴素参考模型位于 `naive_test.go`，独立按题目规则递归解析、反复整体迭代到
包含/保留/原因都不再变化，与产品 `resolver`/`analyzer` 不共享实现代码。
