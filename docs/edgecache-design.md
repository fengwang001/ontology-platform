# 大对象分片缓存设计说明

包：`edgecache`。实现内容分发边缘节点的大对象分片缓存：对象按固定大小
切片缓存，字节范围请求部分命中，只对缺失的连续切片段回源，并处理对象
版本变化、并发请求与容量约束。源站访问完全通过调用方注入的 `Source`
接口完成。

## 核心结构

- **切片键** = (对象键, 版本标识, 切片下标)。版本标识直接参与键的构成，
  因此不同版本的切片天然隔离，版本变化时按对象键作废旧版本切片即可。
- **元信息**：每个对象键缓存一份 (版本标识, 总长度)。首次访问某键时先
  回源一个切片（探取）学到版本与总长度，之后才能判定范围是否可满足。
- **LRU**：一条双向链表保存全部缓存切片（队首为最近访问），配合哈希表
  实现 O(1) 命中判定与访问顺序维护——命中即 `MoveToFront`，与缓存中的
  切片总数无关。
- **pin**：被未完成请求引用的切片 `pins++`，淘汰时从队尾扫描并跳过被
  pin 的切片。命中在加 pin 的同时刷新访问顺序。
- **singleflight**：`inflight` 表记录进行中的单切片回源，同一切片的并发
  缺失只回源一次；等待者共享结果（数据、版本、错误）。

## 一次请求的流程

1. **参数校验**（不依赖总长度）：键非空、范围写法合法、边界非负。
   后缀长度为零、终点小于起点在此直接判为范围不可满足（原因可区分）。
2. **元信息未知则探取**：起点类写法探取起点所在切片（该切片几乎必然
   被需要），后缀写法探取切片 0。探取本身也走 singleflight。
3. **范围判定**：按总长度把三种写法换算为闭区间；起点不小于总长度判
   不可满足；终点超出截到末尾；后缀作用于零长度对象得到合法空应答。
4. **容量检查**：所需切片数 > C 则报容量不足。检查先于命中判定与任何
   数据回源，因此被拒绝的请求不刷新访问顺序、不改变缓存、不回源
   （唯一的例外见下文“取舍”第 2 条）。
5. **命中判定与缺失段合并**（单个临界区内完成）：命中切片加 pin 并刷新
   顺序；相邻且无人回源的缺失切片合并为一个回源段并登记 singleflight；
   已被命中切片隔开的缺失段自然分成多次回源。
6. **锁外回源**：每个连续缺失段一次源站调用。源站应答在锁内原子生效：
   版本变化则作废旧版本切片、更新元信息、写入新切片、唤醒等待者；
   失败只唤醒等待者，不写缓存。
7. **版本重判**：任一切片的应答版本与本次请求所依据的版本不同，则释放
   全部 pin，按新版本的总长度与内容重新判定一次（回到第 3 步）。重新
   判定最多一次，再次出现版本变化报版本震荡。
8. **组装应答**：按切片顺序拼接请求范围内的字节，逐切片标明来自缓存
   还是本次回源，最后释放全部 pin。

## 错误与优先级

参数非法 > 范围不可满足 > 容量不足 > 回源失败 > 版本震荡。

优先级由检查顺序保证：参数校验最先；范围判定先于容量检查；容量检查
先于数据回源；同一次尝试内先汇总回源错误再检查版本变化。范围不可满足
的三种原因（起点越界、零后缀、终点小于起点）通过 `RangeError.Reason`
区分，且都可用 `errors.Is(err, ErrRangeNotSatisfiable)` 归类。

## 并发与串行等价

全部缓存状态（元信息、切片、LRU、inflight）由一把互斥锁保护；源站调用
在锁外进行，其结果在锁内原子生效。每个请求的关键决策（读到哪个版本、
哪些切片命中、由谁回源）都在单个临界区内完成，因此并发调用的结果等价
于某个串行顺序。回源失败时，同一 singleflight 调用上的所有等待者都收
到回源失败，失败不写缓存，inflight 登记被清理，不相关对象不受影响。

## 容量与淘汰

- 淘汰策略：LRU，从队尾淘汰最久未访问的切片；被 pin 的切片跳过。
- 若某时刻全部切片都被 pin（并发请求合计引用超过 C），允许缓存暂时
  超容，待引用释放后的下一次淘汰再回落到 C 以内——单个请求所需切片数
  已在第 4 步限制为不超过 C，因此不会因此死锁。
- 命中判定、访问顺序维护、pin/unpin、单切片插入均为 O(1)；淘汰单次
  最坏 O(pin 住的切片数)，版本作废为 O(C)（以容量为上界）。

## 回源次数上界（可验证）

一次请求的回源次数 = 探取次数（元信息未知时为 1，否则为 0）+ 各次尝试
的连续缺失段数之和。串行情形下等号成立；并发情形下，若缺失切片已被
其他请求登记回源，本请求只等待不重复回源，实际回源次数只会更少。
随机对照测试对每一步断言真实缓存与模型的回源次数严格相等、且等于
“探取 + 缺失段数”，即为该上界的可验证证明。

## 关键取舍与被放弃的方案

1. **单互斥锁 + singleflight**，放弃“每切片一把锁/条件变量”的细粒度
   方案。后者正确性论证（尤其版本作废与淘汰的交互）复杂得多，而回源
   在锁外进行，锁内只有 O(1) 的内存操作，单锁不是瓶颈。
2. **元信息未知时先探取再判容量**。容量检查承诺“被拒绝的请求不回源”，
   但总长度未知时无法得知所需切片数，必须先回源一次学到总长度。取舍：
   元信息已知时严格满足“不回源、不改缓存、不刷新顺序”（测试覆盖）；
   元信息未知时允许这一次不可避免的探取，探取切片本身也会被缓存复用。
   曾考虑“按请求上界直接拒绝”（如起止写法按未截断长度估算），会因
   截断而误拒合法请求，放弃。
3. **等待并发回源的切片计为“来自缓存”**。该切片并非本请求回源，串行
   等价意义下它就是一次命中；这也让逐切片来源标记与串行模型一致。
4. **命中即刷新 + pin 的切片仍在 LRU 链表中**。曾考虑“pin 时摘下链表、
   unpin 时插回队首”，但这会把 pin 期间新插入的切片排到它前面，违反
   “命中即刷新”的语义（命中时刻应立即可见）。现方案命中时
   `MoveToFront`、pin 只影响淘汰扫描，语义与 O(1) 兼得。
5. **源站应答做契约校验**（切片数量与对象末尾一致、仅末切片可不足
   S），违反契约按回源失败处理，避免把损坏数据写入缓存。
6. **同一请求的多个缺失段串行回源**，放弃并行回源。串行实现简单且
   回源次数上界清晰；段数通常很小，延迟收益有限。

## 本地验证方法

```bash
# 全量测试（含 1200 组随机序列对照）
go test ./edgecache/

# 竞态检测
go test -race ./edgecache/

# 查看随机对照的逐步日志（输入、输出、回源计数等判定依据）
go test -v -run TestRandomAgainstModel ./edgecache/ | less

# 指定种子复现某一组随机序列
go test -v -run 'TestRandomAgainstModel/seed=42' ./edgecache/

# 代码检查
gofmt -l . && go vet ./...
```

测试覆盖：切片边界与差一字节、跨切片部分命中与间隔缺失段、相邻缺失
合并、总长度为切片整数倍与零、版本变化作废旧切片并重判、重判后不可
满足、版本震荡、并发同切片单次回源、失败不入缓存且不影响不相关请求、
容量恰等于所需与差一、容量拒绝不回源不改缓存不刷新顺序、错误优先级、
pin 保护、LRU 淘汰与命中刷新、回源次数上界，以及与独立朴素模型对照
1200 组随机序列（每组 15–29 步，含换版本、回源中途翻版本、注入失败）。
