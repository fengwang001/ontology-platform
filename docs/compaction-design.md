# 分层压实任务选择与安装服务设计

## 模块划分

- `compaction/types.go`：文件、配置、计划、计划结果和日志接口等公共契约。
- `compaction/interval.go`：字节序比较与非零层区间 AVL 树；树节点维护子树最大右端点，用于区间剪枝。
- `compaction/selection.go`：配置校验、`math/big.Rat` 精确评分与按“分数降序、层号升序”的稳定排序。
- `compaction/plans.go`：零层/非零层起点、输入扩张、边界闭合、下一层纳入、在途冲突改选和计划占用。
- `compaction/install.go`：安装前校验、直接下移约束、目标层不变量检查、原子提交和取消。
- `compaction/service.go`：并发互斥、文件登记、层状态、错误分类和日志转发。
- `compaction/snapshot.go`：测试与审计使用的深拷贝只读快照。

## 核心规则

### 评分与选层

- 零层分数为 `文件数 / ZeroTrigger`。
- 非零层分数为 `层内字节和 / (FirstNonZeroTarget * TargetMultiplier^(layer-1))`。
- 所有分数用 `math/big.Rat` 比较；测试中覆盖分数恰为 1 与略小于 1，避免浮点舍入。
- 最后一层只作为目标层，不参与候选。
- 选择分数最大且不小于 1 的层；分数并列取层号较小者。
- 没有层达标是正常空计划，不返回错误。

### 零层计划

零层文件允许任意重叠。起点固定为编号最小的零层文件，随后反复纳入与当前合并区间重叠（端点相等也算）的所有零层文件，直到闭包稳定。零层不需要做同层端点闭合扩张，因为起点之后的输入定义本身就是区间重叠闭包。

### 非零层计划

非零层文件按 `(MinKey, MaxKey, ID)` 保持有序。起点为：

1. 层从未压实：取最小 `MinKey` 中编号最小的文件。
2. 有上次终点：优先取 `MinKey > lastEnd` 的最小文件。
3. 严格大于终点的文件不存在：回绕到最小 `MinKey` 的文件。

确定起点后，只沿该层有序文件的立即前驱和后继闭合端点：

- 已选文件的 `MinKey == 相邻未选文件.MaxKey`；
- 或已选文件的 `MaxKey == 相邻未选文件.MinKey`。

闭合迭代到稳定，保证同一用户键跨两个相邻文件的版本不会被劈开。使用“立即相邻”很关键：相同左端点的点文件不应仅因键值相等而误判为端点版本链。

### 下一层纳入

源层输入闭合后，计算源层输入的闭区间并集，在目标层 AVL 中查询所有与该区间重叠（含端点相等）的文件。目标层输入单独执行同样的有序端点闭合。目标层闭合扩大的范围只影响目标层输入集合，不回头扩大源层输入。

当且仅当计划总共只有一个源层输入文件且目标层没有任何重叠文件时，计划类型为 `move-down`；目标层仅有端点相接文件时会纳入该文件，因此是 `rewrite`。

### 在途冲突与改选

计划在完全构建成功之前不写任何状态。若起点、重叠扩张或闭合过程中遇到已被未完成计划占用的文件，本次候选层立即放弃，并按评分顺序尝试下一达标层。所有层均因不达标或占用无法生成时返回空计划。

计划接受后立即占用其全部输入。取消计划释放占用，不更新终点。安装失败也保持占用和终点；调用方可重试安装或取消。

### 安装

安装按以下顺序返回最靠前的错误类别：参数非法、文件不存在、文件已被占用、计划不存在、层不变量被破坏。所有检查完成后才修改状态；因此任何失败都不会删除输入、加入输出、释放占用或更新起点终点。

成功安装时：

1. 删除所有输入文件；
2. 将输出文件加入目标层；
3. 更新 AVL 和有序层切片；
4. 将源层 `lastEnd` 更新为本次输入文件中的最大 `MaxKey`；
5. 删除计划并释放占用。

重写输出可以重新使用被本计划消耗的输入 ID；直接下移必须恰好一个输出，且保持输入的区间和字节大小不变。

## 复杂度与可验证性

非零层目标重叠查询使用 AVL 区间树：

- BST 键为 `(MinKey, MaxKey, ID)`，树高为 `O(log n)`；
- 每个节点保存子树最大右端点；
- 若子树最大右端点小于查询左端点，整棵子树剪枝；
- 若节点左端点已大于查询右端点，不再进入其右子树。

返回 `k` 个文件时复杂度为 `O(log n + k)`，不随层内文件总数线性增长。`TestIntervalOverlapQueryIsSublinear` 构造 16 到 1024 个节点，断言树高的 AVL 上界，并记录单结果查询访问节点数；规模翻倍时访问数增长显著低于线性。

## 并发与确定性

服务用单一互斥锁串行化所有写操作和计划构建，使并发调用等价于某个全局串行顺序。计划 ID 在锁内单调分配；文件、计划和占用 map 只在锁内访问；计划和快照中的字节串均深拷贝，避免调用方后续修改入参影响内部状态。

相同注册、创建、安装和取消操作序列会产生相同计划 ID、输入 ID、区间和状态转移。随机模型测试使用固定 PCG seed，可完整重放。

## 放弃或未采用的方案

- **浮点分数**：实现简单，但无法证明“恰等于 1”和极大字节总和下的比较稳定，故放弃。
- **每层线性扫描目标重叠文件**：规则简单但违反“目标层查询不得随总数线性增长”的要求，只保留在独立朴素测试模型中作为参照。
- **每个计划一把锁或读写锁细粒度并发**：可以提高吞吐，但占用、改选、安装和终点更新跨多文件，锁协议复杂且容易产生不可复现交错；当前优先保证强一致与可审计。
- **在闭合中按 AVL 后继直接扩展**：AVL 的内部后继受 `(MinKey, MaxKey, ID)` 影响，不总等价于用户区间链上的立即相邻文件；生产实现保留 AVL 做重叠查询，另维护有序切片专门做闭合和起点判定。
- **先写临时计划再失败回滚**：更容易记录部分轨迹，但会短暂暴露占用；当前选择纯构建、成功后一次提交占用。

## 本地验证

```bash
# 若 shell 未配置 Go PATH
export PATH=/usr/local/go/bin:$PATH
export GOCACHE=/tmp/go-cache-ontology

go test ./...
go test -race ./...
go test -v ./compaction
go vet ./...
gofmt -l .
```

测试内容包括：

- 分数恰为 1、略小于 1 与并列取低层；
- 零层端点相等纳入；
- 非零层双向闭合、连锁闭合和安装后回绕；
- 起点占用导致改选，以及改选后仍冲突返回空计划；
- 直接下移与下一层仅端点相等的重写区别；
- 安装违例整体不生效；
- 取消释放占用但不改变起点终点；
- 20 条固定 seed、每条 100 个操作的独立朴素模型对照；
- 并发创建、登记和取消的 race 测试；
- AVL 查询访问计数的子线性验证。

## 日志

调用方可向 `NewService` 传入 `OperationLog`。每次登记、计划创建、安装和取消都记录操作名、输入、输出/错误以及判定依据。测试日志在失败时输出完整随机操作序列，包括 seed、输入文件、计划输入集合、错误类型和具体决策原因，可直接复现“本次压哪些文件、为什么”。
