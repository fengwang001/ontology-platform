# 联合类型流敏感窄化分析器 — 设计说明

## 目标与范围

对由**赋值、条件分支、提前返回**构成的结构化程序做流敏感（flow-sensitive）
窄化分析：回答"在某个程序点（每条语句有调用方给定的唯一标识，可取语句前/
语句后两侧）、某个变量被窄化成了什么类型"，并对非法使用给出**可区分**的错误。

代码位于 `narrowing/`，按职责拆为六个互相协作的模块：

| 文件 | 职责 |
| --- | --- |
| `types.go` | 归一化联合类型：成员集合、吸收规则、相等性、隶属判断 |
| `typeexpr.go` | 调用方类型语法（`TypeExpr`）与畸形校验（重复属性名、NaN） |
| `program.go` | 语句/条件 AST 定义（纯数据，无行为） |
| `errors.go` | 错误分类、优先级与平局裁决 |
| `analyze.go` | 流敏感分析器：环境变换、条件真假环境、汇合、错误收集 |
| `result.go` | 不可变分析结果与 O(1) 查询 |

## 类型系统

内部表示是**归一化的成员集合**（`Type{members map[string]Member}`）：

- 嵌套联合在构造时即被展平（表示层不存在"联合的联合"）；
- 重复成员按规范键去重；
- 数字/字符串字面量被同联合中的原子 `number`/`string` 吸收；
- 布尔没有独立表示：`boolean` 就是 `true | false` 的联合，因此布尔拆分
  （`b === true` 的假环境剩 `false`）无需特殊代码；
- 空联合即 never；单成员联合在表示上自然等同该成员；
- 类型相等 = 归一化成员集合相等，实现为规范键字符串比较（O(类型规模)）。

`-0` 在字面量构造时归一为 `0`；`NaN` 字面量视为畸形输入。

"成员属于类型"（赋值兼容性、判别属性包含判断都复用它）定义为：
字面量成员被对应原子成员吸收，或成员键直接命中；对象类型只做精确匹配，
不做宽度子类型——规范未要求对象子类型，这是有意的简化。

## 分析器

### 环境

环境 = 变量名 → 窄化类型的**不可变**映射；`nil` 环境表示不可达（任一变量
被窄化为 never 时整个环境坍缩为不可达）。不可达环境不参与汇合；逐变量并集
只在两侧均可达时进行。`return` 把当前路径标记为终止，终止路径不进入汇合。

### 条件

每个条件把环境分成真/假两个环境（`evalCond`）。叶子条件是对单个变量成员
集合的逐成员变换（保留/删除/替换，如真值判断把原子 `number` 在假环境替换为
字面量 `0`）。`!` 交换两个环境；`&&`/`||` 按从左到右短路定义：

- `A && B`：真环境 = 在 A 真环境中取 B 真环境；假环境 = A 假环境 ∪（A 真
  环境下的 B 假环境），并集按变量逐个进行；
- `A || B` 完全对偶。

### 错误

四类错误，优先级：参数非法 > 不可访问属性 > 缺少判别属性 > 不可赋值；
同类取程序次序（前序遍历序号）最先者。实现上**收集全部错误再按
（类别， 次序， 求值顺序）取最小**，而不是遇到即返回——因为类别优先级
高于程序次序，先遇到的错误未必是要报告的错误。任一错误使整次分析失败，
不产生部分结果。

参数非法类（未声明变量、畸形类型、重复语句标识）在**静态校验阶段**收集，
与可达性无关；其余三类是流敏感的，只在**可达环境**中检查（不可达代码中的
非法赋值/属性访问不报，见"取舍"）。

## 结果与查询复杂度

分析完成后，每条语句的前/后程序点各保存一份环境快照（`map[语句ID]map[变量]Type`）。
查询 = 常数次哈希表查找，开销只与被查询变量的窄化类型规模相关：

- 不随语句总数增长（快照在分析期一次性建好，查询期零遍历）；
- 不重新分析（结果不可变，无任何惰性计算）；
- **可验证**：`Result.QuerySteps()` 暴露内部步数计数器，每次查询恰前进
  常数步；`TestQueryCostAndConcurrency` 对 50 条与 5000 条语句的程序断言
  步数完全相同。

结果不可变且无任何共享可变状态，因此：同一结果可被任意多调用方并发查询，
多个分析可并发进行，效果等价于某个串行顺序（由 `-race` 测试验证）。

## 关键取舍

1. **非关系型抽象（逐变量独立）**。汇合按变量逐个取并集，不保留变量间的
   相关性。后果：分析器是可靠**上近似**——它可能把具体执行不可达的点判为
   可达（汇合后变量组合实际不可同时成立），但绝不会把可达点判为不可达、
   也绝不会漏掉具体可能的值。差分测试据此按单向检查（朴素可达 ⇒ 分析器
   可达，且具体值被窄化类型覆盖）。
2. **流敏感错误只在可达代码中报**。不可达分支里的非法赋值/属性访问不产生
   错误（环境已坍缩，无成员可检查）；参数非法类错误与可达性无关，总是报。
3. **对象属性不做深度窄化**。判别属性条件按整个对象成员过滤，不改写成员
   内部的属性类型（`{k: 1|2}` 在 `k===1` 真环境中保持原样）。这符合题面
   规则，也避免属性路径窄化带来的别名复杂度。
4. **真值判断对原子 number/string 的真环境保持原样**（即使 `0`/`""` 在
   原子类型内）。这是题面规定的有意不精确，实现与之一致。
5. **错误收集后统一裁决**而非快速失败，代价是分析出错程序时多做些无用功，
   换来优先级语义的简单与可测试。

## 被放弃的方案

- **按需/惰性分析（查询时才沿控制流传播）**：被否。查询复杂度将依赖程序
  规模，且"不可变结果 + 并发查询"需要额外的记忆化同步，无法满足
  "查询开销只与窄化类型规模相关"的硬要求。
- **持久化数据结构共享环境（如 HAMT）**：被否。变量数很小，每语句一次
  浅拷贝的代价可忽略；普通 Go map + 不可变约定更简单，且查询就是原生
  map 查找，步数可精确计数。
- **遇到第一个错误即返回**：被否。类别优先级高于程序次序，快速失败会
  报出低优先级的先遇错误。
- **关系型/析取域（保留变量间相关性）**：被否。实现与规范复杂度都显著
  上升，而题面汇合规则明确是逐变量并集。
- **把布尔建成独立原子类型**：被否。"布尔 = true|false 联合"直接由表示
  落地，布尔拆分、真值判断等规则全部自然成立，少一类特判。

## 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin

# 全量测试（含竞态检测；随机差分测试的输入/输出/判定依据在详细日志中）
go test -race -v ./narrowing/ 2>&1 | less

# 只看随机程序差分测试的日志（每次输入程序、逐点窄化结果、判定依据）
go test ./narrowing/ -run TestRandomProgramsAgainstNaiveModel -v

# 查询复杂度断言（50 条 vs 5000 条语句的程序，查询步数必须相同）
go test ./narrowing/ -run TestQueryCostAndConcurrency -v

# 代码检查
gofmt -l . && go vet ./...
```

测试覆盖：

- `types_test.go`：联合归一化（展平/去重/吸收）、never 与单成员联合、
  布尔即二字面量联合、对象类型相等、隶属关系、`-0`/`NaN`；
- `analyze_test.go`：假分支对字面量与原子类型的不对称处理、布尔拆分、
  真值判断对数字/字符串（原子与字面量）的收窄、宽松相等双命中、判别
  属性真/假环境、`&&`/`||` 短路汇合、提前返回后的汇合、不可达判定
  （与"有结果"和"未知标识"都可区分）、赋值后窄化重置；
- `errors_test.go`：四类错误各自的触发、跨类优先级、同类最先者、不可达
  代码不报流敏感错误、查询步数恒定、并发查询与并发分析（`-race`）；
- `naive_test.go`：独立朴素模型——枚举声明类型的全部具体取值、在具体
  状态集合上执行程序；300 个随机程序逐点对照（可达性方向、具体值被
  覆盖、窄化结果不越出声明类型），日志打印每次输入程序、逐点输出与
  判定依据。
