# 泵站集水池多泵水位控制器

## 模块划分

- `pumpstation/config.go`：只负责构造期配置校验，拒绝泵数、阈值单调性、干运行/恢复线、溢流线和时长约束错误。
- `pumpstation/hysteresis.go`：纯函数计算水位滞回目标台数，不读写泵状态。
- `pumpstation/pump.go`：维护单泵状态、当前运行区段、累计运行时长和停机时刻。
- `pumpstation/scheduler.go`：按最短停机、起泵间隔、最短运行和运行时长均衡规则扫描候选泵。
- `pumpstation/evaluate.go`：处理水位上报、干运行、溢流、常规评估，以及冲突优先级。
- `pumpstation/operations.go`：处理故障上报、维修恢复、投入/解除检修。
- `pumpstation/snapshot.go`：提供不可变状态快照，便于观察和测试。

## 关键规则

1. 目标台数由启线、停线和上一次目标滞回决定；故障或检修导致可用台数下降时立即钳制目标台数。
2. 常规评估每次最多变更一台。需要起泵时先过滤可用、未运行、满足最短停机和起泵间隔的泵，再取累计运行时长最短、编号最小者。
3. 需要停泵时先过滤运行中且满足最短运行时长的可用泵，再取累计运行时长最长、编号最大者。
4. 水位不高于干运行线时立即停止所有运行泵并锁定；水位必须严格高于恢复线才解除，解除时目标台数从 0 重新经当前水位滞回计算。
5. 水位不低于溢流线时启动所有当前可用且未运行的泵，不应用最短停机、起泵间隔或每评估一台限制；溢流期间禁止停泵。
6. 故障立即停止运行泵，不受最短运行约束；维修恢复把停机计时起点设为恢复时刻。
7. 投入检修立即将泵移出可用集合；运行中的泵若已满足最短运行时长则停止，否则继续运行，后续水位上报每次检查一次。干运行锁定期间投入检修立即生效。
8. 所有公共方法由同一个互斥锁保护，拒绝操作在任何写入前返回，因此并发结果等价于某种合法串行顺序，且失败不会改变时钟、滞回、累计时长或泵时刻。

## 关键取舍

- 只保存当前状态和泵时刻，不保存事件历史；每次评估只扫描固定长度的泵数组。
- 溢流优先级高于检修延迟停止和常规停泵；只要仍在溢流线及以上，运行中的检修泵保持运行，离开溢流后再按常规节奏处理。
- 干运行保护优先级最高；配置允许干运行线与溢流线不相交，但现实配置应让恢复线远低于最低停线。
- 故障和检修是显式状态操作，也推进控制器时钟。这样同一逻辑时间不会并发修改同一台泵，所有泵时刻都可确定复现。
- 返回结果中的 `Reason` 记录本次输入、目标台数、候选约束和实际动作依据；测试用 `-v` 可打印完整判定链路。

## 被放弃的方案

- 不保存事件日志后再重放：会让评估开销随历史增长，无法满足历史长度无关要求。
- 不为每台泵起 goroutine 或定时器：最短运行/停机约束只需要时刻差判断，异步定时器会引入并发不确定性，也不利于固定时刻复现。
- 不在故障或检修操作中自动启动替代泵：规格规定只有水位上报触发评估；自动追赶会让一次状态操作产生不透明的起泵动作。
- 不按泵编号固定轮换：规格明确以累计运行时长为第一选择键，编号仅用于打破并列。

## 复杂度与可验证性

- 配置校验和每次水位评估均为 `O(n)`，其中 `2 <= n <= 8`；额外空间为 `O(n)`。
- 控制器不保存历史上报，内存占用不随调用次数增加。
- `BenchmarkReportLevelHistory100` 和 `BenchmarkReportLevelHistory100000` 在相同固定状态下对照单次评估；两次基准的 `ns/op`、`B/op` 和 allocs 应基本相同。
- `TestRandomSequencesAgainstNaiveModel` 使用固定种子生成 80 组随机序列，并与测试内独立编写的朴素模型逐动作、逐泵累计时长对照。
