# 跨实例批量更新的联合版本前置判定 — 设计说明

## 问题

本体平台需要支持一次批次更新多个实例，其中每项变更以"目标实例当前
必须恰好处于指定版本"为前置条件。批次内所有前置条件构成一次**联合
判定**：要么整批生效，要么整批拒绝；判定必须先于任何修改完成，拒绝
路径对外部观察者而言必须与批次从未发生不可区分。

## 核心方案：有序两阶段锁（ordered 2PL）

每个实例一把互斥锁。批次执行流程（`ontology/store.go` 的
`Store.ApplyBatch`）：

1. **重复声明检查**：批次内同一实例出现多次即拒绝
   （`OutcomeDuplicatePrecondition`）。纯内存检查，不触碰存储，
   因此 `Reads = 0`，且判定顺序必然先于版本判定。
2. **有序加锁**：把批次项按实例 ID 排序后依次加锁。所有批次遵循同一
   全局加锁顺序，因此不会死锁。锁全部持有期间就是"同一个逻辑时刻"：
   任何与本批次共享实例的其他批次，其持锁区间与本批次必然不重叠。
3. **联合版本判定**：在持锁区间内一次性读取全部相关实例的当前版本，
   与各自声明的前置版本逐一比较。任一不满足即整批拒绝
   （`OutcomeVersionConflict`），读到的版本记入判定日志的 `Observed`
   字段作为判定依据。
4. **基数约束预演**：在内存副本上应用关联增删，只检查本批次实际触及
   的（实例, 链接类型）对。违例即整批拒绝
   （`OutcomeCardinalityViolation`），不写回任何状态。
5. **整体提交**：应用属性与关联变更，每个实例的版本号按**各自独立的
   序列** +1（不统一、不绑定），取提交序号 `CommitSeq`。

### 为什么这满足各项硬性要求

- **一次性判定**：所有版本读取发生在持有全部相关实例锁的区间内，
  区间内这些实例的版本不可能被其他批次改变，不存在"读完又变"的窗口。
- **交集争夺恰好一个成功**：两个批次共享某实例时，对该实例的锁把它们
  的持锁区间串行化；先完成提交者推进了版本，后者的联合判定读到的必然
  是新版本，与其声明的旧前置版本不符，整批拒绝。
- **拒绝无痕**：拒绝路径只读不写；判定日志（`Decision`）是存储的
  元数据而非实例状态，实例的版本、属性、关联、时钟均不变。
- **可串行化**：持锁区间两两不重叠（对相交批次而言），在持锁区间内
  取全局序号 `Tick`，则按 `Tick` 排序即为一个等价串行顺序。差分测试
  正是按此顺序在朴素模型上重放并逐批比对。
- **开销与实例总数无关**：判定只触及批次声明的实例，`Decision.Reads`
  恒等于 `len(Items)`。该计数随每条判定记录输出，是不依赖额外对外
  暴露状态的可验证证据（`TestReadCostIndependentOfStoreSize` 在
  2 万实例的存储上验证 Reads 不随总数增长）。

## 被放弃的方案

- **全局单锁**：正确性最简单（`ontology/model.go` 的 `Model` 即此
  实现，保留为差分对照的参照模型），但所有批次串行，无关批次也互相
  阻塞，不满足并发吞吐要求。
- **乐观并发（CAS 循环）**：读全部版本→校验→逐实例 CAS。多实例的
  "读-校验-写"无法原子完成，需要检测到冲突后重试，冲突重时存在活锁
  /饥饿；且"恰好一个批次成功"的语义需要额外的回滚路径，违背"拒绝
  无痕"的简洁性。
- **先改后回滚（影子写入 + undo）**：拒绝路径需要补偿写，期间其他
  读者会看到中间态，违背"判定必须先于任何修改完成"与"拒绝无痕"。
- **统一批次版本号**：给整批分配一个共同版本会破坏各实例版本序列的
  独立单调性，被明确要求禁止。

## 判定日志与重放核验

每个批次（无论成败）产生一条 `Decision` 记录：批次 ID、完整前置条件
（`Items`）、判定依据（`Observed` 实际读到的版本、`Reads` 读取次数、
`Detail` 描述）、逻辑时刻 `Tick`、提交序号 `CommitSeq`（仅成功）。
`Store.Decisions()` 返回完整日志。重放方法：按 `Tick` 排序后在
`Model` 上依次执行同一批 `Batch`，逐条比对 `Outcome` 与 `Observed`，
并比对所有实例最终快照——`TestDifferentialAgainstNaiveModel` 即此
流程的自动化。

## 本地验证方法

```bash
# 全部测试（含竞态检测）
go test -race ./...

# 只看差分对照测试的详细输出
go test -race -v -run TestDifferential ./ontology

# 静态检查
gofmt -l .
go vet ./...

# 运行演示
go run ./cmd/server
```

注意：本机 Go 构建缓存若指向只读目录，需
`export GOCACHE=/tmp/gocache`。
