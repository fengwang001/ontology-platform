# 对象生命周期状态机 — 设计说明

本包（`lifecycle`）实现题目要求的对象生命周期子系统：对象类型声明状态集合
与允许的迁移；每条迁移由动作触发，前置条件可引用实例属性、经由链接连接的
实例数量与这些实例的状态；迁移规则、链接基数约束、属性校验钩子三者在
**同一个处理单元**内协同判定；支持互斥迁移、链式触发、跨实例钩子联动与
终态保护；并发触发严格串行等价。

代码位于 `lifecycle/`，独立的朴素参照模型位于 `lifecycle/naive/`。

## 1. 关键取舍

### 1.1 “一个处理单元”= 一次 `Execute(...)` 调用

一次 `Execute` 接收一个批次（一个或多个迁移请求），它们构成一个处理单元：

- 先在只读快照上**乐观展开计划**，确定需要锁定的实例集合；
- 按实例 ID 升序获取每实例互斥锁（避免死锁），再取 Store 读锁；
- 在锁内以最新状态**重建权威计划**（乐观阶段之后可能已有别的单元提交），
  若发现新的关联实例则扩大锁集合重试；
- 在同一个“生效后投影”（`view`）上完成全部判定；
- 全部通过后在单个 Store 写锁临界区内提交，并给所有被改动实例打上同一个
  单元时钟戳；任一环节失败则根本不进入提交。

因此不存在“状态已迁移而属性/链接尚未满足约束”的中间时刻：判定与生效
看到的是同一份投影。

### 1.2 生效后投影（overlay view）

`evaluator.go` 的 `view` 在真实 Store 之上叠加本单元的暂定状态、属性与链接
增删：

- 前置条件在“触发实例自身迁移生效前”求值，但投影已包含同单元内上游环节
  的暂定结果，因此同一链上的判定彼此一致；
- 属性校验钩子（`AttrBound`）、**迁移后**链接基数（`CardinalityBound`）
  与跨实例状态钩子（`Hook`）都在暂定推进之后、在同一投影上求值；
- 迁移后基数使用的是投影（即迁移生效后）的真实链接数量，杜绝“先迁移后
  发现超限”。

### 1.3 链式触发与循环检测

`planner.go`：

- 先注册根请求对应的步并做仲裁；
- 再**分层**展开 `Cascades`（沿出边找到的每个邻居都必须随之执行指定规则），
  每轮基于当前胜出步集合重新仲裁，直到闭包稳定；
- 循环用三色 DFS 在**任何一环生效之前**标记（`engine_cycle.go` 的
  `diagnoseCycle` 还会在“假设整链生效”的投影上检查是否存在比
  `ErrCycle` 优先级更高的问题，有则从高报告）。

环被检测到时整批拒绝，不依赖任何递归深度/计数上限，也不会产生任何
状态、属性、链接或时钟变化。链中任一环节失败时，归属根整链不提交，
效果上等价于按与生效相反的顺序整体撤销（因为本单元从未写回）。

### 1.4 互斥与仲裁

- 同一处理单元内，一个实例至多有一个胜出迁移步；
- 两条互斥迁移（同 `MutexGroup`）或任意两条汇聚到同一实例的根请求，按
  调用方声明的 `Priority` 仲裁，数值小者优先；平手时批次声明顺序靠前者
  优先——**不依赖请求到达/调度时间**；
- 落败根最终报 `ErrMutex`；但若存在比互斥更高优先级、且与“该迁移本身能否
  触发”相关的错误（未声明/前置条件/循环），则按更高优先级报告。基数、
  跨实例钩子、终态属于**胜出迁移自身**的责任，不会让落败根改报这些类别。

### 1.5 级联与直接根汇聚

当一个实例既被直接请求、又会被另一条级联链到达时：

- 直接根优先，级联边在该汇聚点被丢弃（该邻居由其自身请求负责迁移），
  级联发起根不会因此被拒；
- 多条级联汇聚到同一非直接根节点时，先到者拥有该节点，其它链共享该
  被级联目标，不产生额外的落败根。

### 1.6 终态保护

`TerminalsList` 中声明的状态为终态：

- 终态实例不允许再迁移（规则的 `From` 通常也不包含终态，因此会先以
  `ErrUndeclared` 报告）；
- 不允许修改属性；
- 不允许新增链接，**但允许删除已有链接**；
- 拒绝不改变任何可观察状态（含时钟戳）。

### 1.7 并发与串行等价

- 每个实例一把互斥锁，按 ID 升序获取；Store 读写锁只在获取实例锁之后再
  获取，提交路径为“实例锁 → Store 写锁”，判定路径为“实例锁 → Store
  读锁”，锁序一致，无环；
- 同一实例的并发请求被串行化为某一种合法的顺序，最终状态/属性/链接必然
  对应其中一个串行执行（见 `TestConcurrentSameInstanceSerializable`）；
- 彼此无链式关系的不同实例使用不相交的实例锁集合，可以真正并行、互不
  阻塞（见 `TestConcurrentDifferentInstances`）。

### 1.8 判定开销不随历史增长

引擎从不遍历任何“历史迁移记录”：前置条件只读当前属性、当前邻接表；链式
展开只访问本单元涉及的实例。单次判定成本随**本单元实际涉及的关联实例
数量**增长，与该类型历史上发生过多少次迁移无关。Store 中也不存在迁移
历史表。

## 2. 错误分类与固定优先级

`errors.go`：数值越小优先级越高，多条件同时命中时报告最小者：

| 码 | 名称 | 含义 |
|----|------|------|
| 1 | `UNDECLARED` | 目标状态/迁移规则未声明，或当前状态不允许该规则 |
| 2 | `PRECONDITION_FAILED` | 前置条件不成立（含属性校验钩子） |
| 3 | `MUTEX_REJECTED` | 同单元内被更高优先级迁移仲裁胜出 |
| 4 | `CARDINALITY_VIOLATION` | 迁移后链接基数越界 |
| 5 | `CROSS_INSTANCE_HOOK_REJECTED` | 跨实例钩子：被连接实例状态不满足 |
| 6 | `CASCADE_CYCLE` | 链式触发形成循环（生效前检测） |
| 7 | `TERMINAL_PROTECTED` | 终态实例的改动尝试 |

被拒绝的迁移不改任何实例的状态、属性、链接或时钟戳。

## 3. 朴素参照模型（独立实现）

`lifecycle/naive/` 是一份**不共享任何实现代码**的朴素模型：

- 一把全局大锁串行化所有请求；
- 每次批次都在世界快照副本上逐步模拟，任何环节失败就丢弃副本（天然整体
  撤销），全部通过才用副本替换真实状态；
- 循环同样用三色 DFS 在生效前检测；
- 失败步会回退其暂定的状态/属性/出边，保证后续步不会看到终将被拒的中间态。

对拍测试 `TestDifferentialRandomized` 随机生成类型配置、链式结构与请求
序列，逐批断言两个模型的**错误码、全部实例状态、属性 v 与所有 edge 链接**
完全一致。对拍生成器在 DAG 森林上取样（每节点至多一条入边、只选无入边
的根作为直接请求），从而聚焦链式触发、扇出、钩子、基数、互斥；纯循环、
多链汇聚等边角结构由固定用例单独、确定性地覆盖。

## 4. 被放弃的备选方案

- **数据库/事务框架**：题目只要求库内子系统，引入外部依赖会掩盖关键的锁
  序与原子性推理，故仅用内存 Store + 显式锁。
- **“先就地生效、失败再补偿”**：补偿难以保证跨实例时钟一致，且容易出现
  可观察的中间态；改为“投影判定 + 单临界区提交”，拒绝路径天然零副作用。
- **按历史记录计算基数/前置**：违反“开销不随历史增长”的要求，且历史表
  本身需要一致性维护；所有判定只读当前态。
- **用递归深度上限截断循环**：题目明确禁止；改为生效前三色 DFS 检测。

## 5. 本地验证

```bash
go test ./...                      # 全量用例（含随机对拍）
go test -race -count=10 ./...      # 竞态与串行等价
go vet ./... && gofmt -l .
```

决策日志可通过 `lifecycle.NewWriterLogger(os.Stdout)` 打开，打印每次迁移的
输入、逐项判定依据与 ACCEPT/REJECT 结果。
