# 对象生命周期状态机与校验钩子触发范围子系统 — 设计说明

## 1. 模块划分

三个 Go 文件即题目要求的三个协作模块，均位于包 `ontology/ontology`：

| 文件 | 职责 |
| --- | --- |
| `errors.go` | 错误归一化：四类错误码、固定优先级、统一构造与断言入口 |
| `hooks.go` | 钩子按阶段/转移注册，解析一次转移的触发范围（O(命中数)） |
| `lifecycle.go` | 对象类型声明（阶段、允许关系、终态）、实例管理、转移串行化执行 |

测试侧另有独立参考实现 `tests/naive/`（朴素模型），它不 import 本体包，
内部用切片保存全部转移关系与全部钩子、每次全量遍历，作为差分测试的对照真值。

## 2. 关键数据结构

- 允许转移关系：`map[edgeKey]struct{}`，`edgeKey{from,to}` 为复合键，
  关系判定 `ObjectType.Allows` 为一次哈希查表；自转移 `(s,s)` 与普通转移同构，
  因此「自转移必须显式声明才合法」这一语义无需特判。
- 钩子表两张索引：
  - `transitions map[edgeKey][]Hook`：具体转移钩子（含自转移钩子）；
  - `entries map[string][]Hook`：进入阶段钩子。
  - 同一目标的多钩子保存在切片中，注册序即触发序。
- 实例 `Instance`：`current`、成功轨迹 `history`、钩子触发记录 `fireLog`，
  各带一把 `sync.Mutex`；`Manager` 用自身互斥锁保护实例 map。

## 3. 一次转移的判定与执行次序

`Manager.Transition` 严格按以下次序，**只返回第一个命中的原因**：

1. 参数非法：实例不存在、目标阶段未声明（`ErrorInvalidArgument`）；
2. 起始阶段为终态（`ErrorTerminal`）——在查关系、跑钩子之前短路，
   故终态（含转到自身）时**一个钩子都不会触发**；
3. 转移关系未声明（`ErrorTransitionNotAllowed`）；
4. 钩子校验失败（`ErrorHookFailed`，带首个失败钩子 ID）。

全部检查与执行在**实例锁内**完成：拿到锁后读取 `from := current`，
因此并发请求看到的起始阶段一定是它们在串行顺序中实际位置的阶段，
不可能两个请求同时基于旧 `from` 成功。阶段提交是全部钩子通过后的唯一一次写，
不存在中间阶段。

## 4. 钩子触发范围与顺序

- 解析 = 两次哈希查表：`transitions[(from,to)]` 与 `entries[to]`，
  拼接顺序恒为「具体转移钩子（注册序）→ 进入钩子（注册序）」。
- 自转移：进入钩子只看 `to`，故 `(s,s)` 时照常触发；
  具体转移钩子只在显式注册过 `(s,s)` 时才出现在切片中，
  既不会因阶段相同被默认跳过，也不会被默认触发。

## 5. 失败回滚与提交语义

钩子失败时：阶段与成功轨迹不变；对已成功执行、声明为
`CommitOnSuccess`（随转移提交）的钩子，按触发的**逆序**调用其 `Compensate`，
并在触发记录中留下补偿事实；声明为 `CommitImmediately`（一经产生即落定，
如校验日志已外发）的副作用不撤销。是否补偿完全由钩子自身声明决定，
状态机不臆测副作用内容。

## 6. 并发模型与确定性

- 串行化粒度选择**每实例一把锁**：全局大锁也能保证正确性，但会把互不相关
  实例的转移也串行化；每实例锁在满足「同一实例请求可线性化」的前提下保留并行度。
- 可线性化的可观测判据：成功转移数 == 该实例成功轨迹长度，且轨迹相邻项首尾相接；
  每个成功结果回报的 `from` 与轨迹记录一一对应。`tests/concurrency_test.go`
  用 32×40 并发请求显式断言这些不变量。
- 确定性：声明、钩子、请求序列确定后，串行执行不存在任何随机/时间相关分支，
  同一序列重放得到完全相同的拒绝原因序列、轨迹与触发记录
  （`TestReplayDeterminism`）。

## 7. 复杂度性质及其可验证证明

性质：解析一次转移应触发哪些钩子，时间/空间只与两次哈希查表和实际命中数有关，
与全部转移关系数、全部钩子数无关，即 O(实际命中数)（期望意义）。

证明方式（实现自选，本项目给出三重证据）：

1. **结构性计数**：`HookRegistry.ResolveProbed` 返回 `Probe.CellsTouched`，
   恒等于 `2 + len(具体命中) + len(进入命中)`。`TestResolveComplexityProof`
   把注册表从 3 个钩子灌到 100 003 个钩子（50 002 条具体关系），
   对同一固定转移断言 `CellsTouched` 恒为 5。计数与「是否扫描了整张表」是
   直接矛盾的——全量扫描必然触碰全部单元，而计数恒定。
2. **基准对照**：`BenchmarkResolve*`（哈希索引，100/10 000/100 000 钩子）
   均为约 70–100 ns/op；朴素模型 `BenchmarkNaiveResolve*` 为
   0.65 µs → 42 µs → 468 µs，线性恶化。
3. **差分测试**：在随机大规模声明下与朴素全量遍历模型逐条结果一致，
   证明「少看」没有漏掉任何应命中的钩子。

## 8. 关键取舍与被放弃的方案

- **放弃全局串行化锁**：实现最简但牺牲跨实例吞吐；改为每实例锁，
  正确性论证成本仅增加「不变量断言」，已在并发测试中覆盖。
- **放弃在转移执行时线性扫描钩子/关系**：朴素、显然正确但不满足复杂度要求；
  改为双哈希索引，并用独立朴素模型长期差分以防索引维护出错。
- **放弃钩子失败时「自动回滚一切副作用」**：副作用可能已外发，状态机无法撤销；
  改为显式两档提交语义，由钩子声明并提供补偿回调。
- **放弃把自转移当特殊状态**：统一用 `(s,s)` 关系键与注册条目表达，
  避免「相同阶段就跳过/就触发」的隐式行为。
- **放弃终态作为软标记（允许转出但警告）**：题目要求硬拒绝且优先于钩子，
  故终态检查置于关系与钩子之前并直接短路。
- 声明期校验：构造 `ObjectType` 时引用未声明阶段的关系/终态直接按参数非法拒绝，
  选择「快速失败」而非静默忽略。

## 9. 本地验证方法

```bash
# 环境：Go 1.26+（本机 go 在 /usr/local/go/bin，构建缓存可指向 /tmp）
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache

go test ./... -race -v                       # 全量用例并打印输入/输出/判定依据
go test ./tests/ -run TestRandomDifferential # 18000 条随机请求与朴素模型逐条对照
go test ./tests/ -run TestResolveComplexityProof -v
go test ./tests/ -run XXX -bench 'BenchmarkResolve|BenchmarkNaiveResolve' -benchtime=200000x
gofmt -l . && go vet ./...
```

测试中每个场景均通过 `fmt.Printf`/`t.Logf` 打印「输入、实际输出、判定依据」，
差分测试前 3 个场景的前 12 步逐条打印，其余 17 000+ 条静默对照、失败即全量转储。
