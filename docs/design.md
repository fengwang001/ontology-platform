# 多路径发送侧调度器 — 设计说明

事件驱动、无时钟。每个变更事件在状态变更后立即执行一次发送决策，返回本次
新发出的段（连接级序号、长度、子流、是否重新注入）。实现见 `mptc/scheduler.py`，
另有一份完全独立、直白重写的朴素参考模型 `mptc/naive.py` 用于差分测试。

## 数据模型

- 连接序号按写入顺序从 0 连续编号；一次 `write` 按 `M` 切段，尾段可短于 `M`，
  段只在写入内部产生，不跨多次写入合并。
- 子流在途 = 该子流已发未被子流确认的段队列，按**实际发送顺序**保存为
  `(seq, length)` 双端队列，`inflight_bytes` 为其字节和。重新注入会使该队列在
  连接序号空间不连续，因此子流确认只按当前在途段的**字节前缀和**判定边界。
- 新数据待发队列 `unsent`（FIFO deque）；重新注入队列 `reinject` 为
  `(seq, length)` 最小堆，外加一个成员集合去重。重新注入优先于新数据。
- `acked_seq`：连接级累计确认边界（从 0 起的连续字节数），单调不减。
- `sent_max_end`：已发送范围的最高右端点，单调不减，作为连接确认的合法上限。
- `window` / `have_window_ad`：最新通告窗口；首次连接确认到达前窗口视为 0，
  即没有通告之前不发送新数据（安全缺省）。

## 发送决策（每个事件后运行）

1. 惰性丢弃重新注入堆顶已被连接确认整段覆盖的副本（判定
   `seq + length <= acked_seq`）。
2. 是否存在任一**活跃普通**子流；存在则本轮所有选择都排除备用子流——注意是
   “不存在活跃普通”而不是“普通暂时全满”。
3. 每次取队首：重新注入非空取最小 `seq`，否则取新数据队首。
4. 新数据还要满足连接窗口：`seq + length <= acked_seq + window`；不满足即停止
   （新数据连续，队首即最低未发送序号，挡住队首即挡住全部后续）。
5. 在活跃且 `cwnd - inflight >= length` 的候选中按 `(rtt_ms, sid)` 取最小。
6. 无候选则停止，后续段不得越过队首（严格队头阻塞，对两类队列都成立）。

## 失效、重新注入与重复副本

- 子流失效：遍历其在途，把**尚未被连接确认整段覆盖**的段按连接序号升序放入
  重新注入堆（用集合保证一个序号在待发重注队列中至多一份），清空在途并标记
  失效。失效事件对已失效子流是空操作（不报错）。
- 重新注入段不受连接窗口约束，但仍受选路（活跃、cwnd、角色）约束。
- 题面“不得再选择该失效子流”的字面效果在本设计中自然成立：失效后在途被清空、
  重注只走其他活跃子流；该子流恢复后窗口/在途重置为初始值。由于重注段发出后
  即不在重注队列中，它不会再回到任何已恢复的原在途队列。
- 同一连接序号可同时存在于两个活跃子流的在途（原发与重注）。连接确认只推进
  `acked_seq`，**不**释放任何子流的在途；两份副本分别由各自子流确认释放。
- 连接确认已覆盖、但仍在重注队列等待的副本在发送决策前被丢弃，永不发送。

## 确认与窗口

- 子流确认按“本次确认字节数”解释：
  - `0` 合法（无操作，仍触发发送决策）；
  - 超过当前在途字节数 => `ack_out_of_range`；
  - 未超过但不等于某个在途段前缀和 => `ack_not_segment_aligned`。
  释放的是发送顺序上的前若干整段。
- 失效子流的任何确认（哪怕数值越界）一律静默忽略、不改任何状态、不报错。
- 连接确认：`ack_seq < acked_seq` => `stale_ack`（配合更小窗口也不生效，事件
  整体拒绝）；`ack_seq > sent_max_end` => `invalid_param`（确认不能越过已发
  范围）；窗口可缩小，缩小不撤回已发数据，只限制之后的新发送；`ack_seq` 与
  当前值相等时仅更新窗口。

## 错误优先级（固定）

`invalid_param` → `subflow_not_found` → `stale_ack` →
`ack_not_segment_aligned` → `ack_out_of_range`。

所有参数检查先于状态查找/变更；任何被拒绝事件在抛异常前不修改任何状态
（异常路径统一在加锁区内、变更动作之前完成校验）。

## 并发

所有公共事件在同一把 `threading.Lock` 下原子完成“校验 + 变更 + 发送决策”，
因此并发调用的可观察结果等价于某个串行顺序（线性一致）。无时钟、无后台线程。

## 复杂度与“不随队列/历史增长”的论证

设 S 为子流数（连接配置量），k 为某事件实际移动/释放的段数，R 为当前等待重新
注入的段数。

- 被拒绝事件：所有校验在任何状态单元触碰之前完成，touch 计数为 0，与队列长度、
  历史长度均无关。`tests/bench_complexity.py` 在 1k/10k/100k 字节待发队列下
  实测 1000 次拒绝事件耗时恒定、touch 恒为 0。
- `write`：只触碰本次新建的 `ceil(len/M)` 段；新数据入队 O(1)/段。
- 发送决策：每发出一段扫描 S 条子流 O(S)，停止条件不扫描剩余队列；因此
  O(S·emitted)，S 独立于队列与历史。
- 子流确认：边界检查与释放只遍历被确认前缀（k 段），O(k)。
- 失效：遍历该子流当前在途 O(k)；重注入堆 push 为 O(log R)/段。
- 连接确认：推进边界为 O(1)；丢弃已覆盖重注副本每段只发生一次（O(log R)/段，
  计入该段被处理的总成本，摊还 O(1)）。

被放弃的方案：

1. **全量重排**：每次事件后扫描全部待发段与全部子流重建调度（朴素模型
   `naive.py` 的做法）。语义最直白但每事件 O(队列×子流)，直接违反复杂度要求，
   只保留为差分测试的判据。
2. **重注段用有序批合并**：曾考虑把同一次失效产生的有序批整体入堆并在边界
   变化时做多路归并，以得到严格 O(1) 摊还入堆；但批之间会因连接确认/重复失效
   产生覆盖、空洞与再插入，合并指针需要可回退，最坏可导致重复扫描。最终采用
   段级最小堆 + 成员集合：push/pop 为 O(log R)，而 R 仅统计“当前”等待重注的
   段（有上界、随事件处理不断出清），每段入堆/出堆各一次，实际与理论均简单
   可证；单事件不扫描待发队列、不扫描历史这一硬约束由 touch 计数量化保证。
3. **用连接序号偏移做子流确认边界**：最初在子流上维护累计字节锚点，但重注后
   在途段在连接序号空间不连续，锚点与前缀和不再一致（差分测试立刻抓到释放
   错误）。已删除该锚点，确认只认当前在途段前缀和。

## 本地验证

```bash
# 全部定向测试 + 1100 组随机差分（每组 120 事件）
python3 -m unittest tests.test_scheduler tests.test_differential -v

# 生成逐步差分日志（输入、双方输出、判定依据）
python3 -m tests.difftest --cases 1100 --steps 120 --log diff.log

# 复杂度经验验证
python3 -m tests.bench_complexity
```

最近一次本地结果：19 个 unittest 全部通过；1100×120 随机事件差分零分歧
（134,200 行日志，逐行打印输入、输出与 `out_eq/err_eq/state_eq` 判定依据）；
拒绝事件在 1k–100k 待发字节下平均耗时约 0.65 µs 且不增长。

## 关键取舍汇总

- 首次窗口通告前不发送（窗口缺省 0）；通告只能通过连接确认事件给出。
- 连接确认按累计字节边界解释，允许理论上的尾段内确认；只有**整段**被覆盖时
  才丢弃重注副本或免重注。常规“按段累计”的事件序列与该规则完全一致。
- `add_subflow` 重复标识、空写入、非正 RTT、cwnd<M、布尔冒充整数等均判
  `invalid_param`；失效/恢复的重复调用是空操作而非错误（幂等）。
- 数据内容不参与调度，实现不保存载荷字节，仅记录段长度。
