# 远程控车指令网关 — 设计说明

## 1. 职责划分

```
internal/gateway/
├── types.go        词汇表：枚举（档位/电源/锁/指令类型/状态/拒绝原因）、
│                   请求与结果结构、Config（含自然日换算 dayOf）
├── clock.go        网关级单调逻辑时钟（原子变量，无锁 CAS）
├── precond.go      规则表：前置条件与互斥矩阵（纯函数，无副作用）
├── idempotency.go  幂等存储：按 (提交者, 请求编号) 分片，支持并发占位
├── vehicle.go      单车辆状态机：上报、维护（过期/唤醒超时）、提交、回执、查询
└── gateway.go      门面：参数校验、拒绝次序编排、车辆路由、诊断接口
cmd/server/         HTTP JSON 演示服务（薄适配层，不含业务规则）
```

协作关系：`Gateway` 是唯一入口，按固定次序做拒绝判定（参数 → 时刻 →
车辆 → 幂等），再把车辆相关的判定（互斥 → 前置 → 唤醒配额）委托给目标
`vehicle`；`vehicle` 借助 `precond.go` 的纯函数表与 `clock` 完成判定。
规则（前置/互斥）与机制（生命周期/并发）分离，改规则不动机制。

## 2. 关键设计取舍

### 2.1 逻辑时钟 + 先检查后提交（check-then-commit）

所有带时刻的操作共享一个网关级单调时钟（`atomic.Int64`）。每个车辆操作
在该车辆的互斥锁内按以下顺序执行：

1. 惰性维护（过期、唤醒超时）——只由时间驱动，等价于任何串行序中
   "时间先走到 t" 的效果，即使后续拒绝也无害；
2. 全部拒绝检查（只读，不落地任何变更）；
3. `clock.tryAdvance(t)` CAS 推进时钟——这是唯一的提交点；
4. CAS 成功后才落地变更（消耗配额、登记指令、写幂等记录）。

因此**被拒绝的提交天然不留痕**：拒绝发生在任何变更之前。CAS 失败
（其他车辆并发推进了时钟）时按时刻回退拒绝，同样无副作用。

### 2.2 每车辆一把锁，而非全局锁或 actor

同一车辆的操作由 `vehicle.mu` 串行化；不同车辆持有不同的锁，互不阻塞。
跨车辆仅有的共享点是：

- 逻辑时钟：原子 CAS，无锁；
- 幂等存储：64 分片，按 (提交者, 请求编号) 哈希分片加锁；
- 车辆注册表：`sync.Map`。

被放弃的方案：

- **全局大锁**：实现最简单，但不同车辆互相阻塞，违反要求；
- **每车辆 goroutine + channel（actor）**：语义等价，但顺序性论证、
  背压与关闭生命周期都更复杂，且查询需要同步往返；锁更简单可证；
- **真实定时器驱动过期/唤醒超时**：逻辑时钟系统用真实时间会引入
  不可测试性与竞态；惰性维护（每次操作时把事件推进到操作时刻）
  语义等价且完全确定。

### 2.3 幂等：并发占位记录

幂等键为 (提交者, 请求编号)，内容为 (车辆, 类型, 有效期) 的规范化串。
同键并发提交时，先到者在分片内放入 pending 记录；后到者若内容相同则
等待其完结——原提交被受理则按重放返回原指令，原提交被拒绝则重新占位
（被拒绝的提交不占用幂等键）。记录自受理起保留固定时长，**超过**保留
时长（严格大于）后同键视为新请求；替换过期记录后若提交最终被拒，
旧记录会被恢复，保证诊断计数与"记录只属于被受理的提交"一致。

### 2.4 唤醒配额与共享唤醒

- 每车每自然日（`dayOf = floor((t + offset) / 86400)`，向下取整兼容负
  偏移）记录已发起的唤醒次数；跨日时计数随日序号变化自然重置；
- 唤醒一经发起即消耗配额，失败不退还（含下发前前置失效的情形）；
- 唤醒进行中到达的需唤醒指令挂入该唤醒的等待集合，共享且不耗配额；
- 唤醒超时（`now > startedAt + timeout`，严格大于）仍无上线上报时，
  等待集合中所有在途指令一起以唤醒失败终结；
- 收到非休眠上报视为上线：对等待指令逐条**重新评估前置条件**后下发，
  不满足者以前置失效终结。

### 2.5 语义边界的明确约定（规格有歧义处的取舍）

| 主题 | 约定 |
|---|---|
| 陈旧判定 | `now - lastReport > 阈值` 才陈旧，恰等于不算 |
| 指令过期 | `受理时刻 + 有效期 <= now` 即过期，恰等于已过期 |
| 唤醒超时 | `now > 发起时刻 + 超时` 才失败（"超过"取严格大于） |
| 幂等保留 | `now > 受理时刻 + 保留时长` 后同键视为新请求 |
| 状态未知 | 从未上报或已陈旧；有前置条件的指令按不满足处理 |
| 未知状态的唤醒 | 无法确认车辆醒着，保守地按"需要唤醒"处理 |
| 车辆未知 | 未注册（未显式注册且从未被接受上报）的车辆 |
| 被丢弃的上报 | 序号 ≤ 已接受最大序号：不改变状态，也不推进时钟 |

### 2.6 受理开销与历史无关（O(1)）及验证

受理与状态判定路径上只使用：

- `map[string]*Command`（按 ID 索引，O(1)）；
- 定长数组 `[7]int` 按类型计数在途指令，互斥检查固定 7 次比较（O(1)）；
- 过期最小堆只含**在途**指令（数量受有效期窗口约束，与历史总量无关），
  已终结指令惰性弹出；
- 幂等分片哈希表（O(1)）。

历史指令总数只影响内存占用（已终结指令须保留以支持迟到回执计数与
查询），不影响受理路径的时间复杂度。验证方式：

1. `TestAcceptanceCostIndependentOfHistory`：同一车辆 10 万次受理-回执，
   比较首/末 1 万次的平均耗时（实测约 1.37µs vs 1.29µs）；
2. `BenchmarkSteadyState/history_{0,1000,100000}`：不同历史规模下稳态
   ns/op 基本平坦（残余差异来自 map 规模对缓存的影响，非常数因子增长）；
3. 代码走查：受理路径无任何对历史指令的遍历（见上表）。

## 3. 生命周期与判定流水线

提交判定严格按序：参数非法 > 时刻回退 > 车辆未知 > 幂等冲突 >
互斥冲突 > 前置不满足 > 唤醒配额耗尽（`TestRejectOrder` 逐项构造
同时违反两条规则的请求验证优先级）。

指令状态机：

```
            需唤醒                        唤醒完成(上线上报)
受理 ──────────────────► 已受理(等待唤醒) ──────────────┐
  │                                                    ▼
  │ 无需唤醒                              下发前再评估前置 ──► 已下发 ──► 回执成功/失败
  └─────────────────────────────────────────────────────┘         │
  ├─ 任意在途时刻到达有效期末刻 ──► 过期                            │
  ├─ 下发前前置不满足 ──► 前置失效                                   │
  └─ 唤醒超时 ──► 唤醒失败（共享同一唤醒的指令一起终结）              │
终结后到达的回执 ──► 迟到回执（计数可查询，不改终态） ◄───────────────┘
```

## 4. 测试策略

- **边界单元测试**（`gateway_test.go`）：陈旧恰等于阈值、有效期末刻、
  跨日/带偏移日界的唤醒配额、共享唤醒一起失败、7×7 互斥矩阵全组合、
  幂等键过期后重用（含恰等于保留时长的边界）、迟到回执计数、
  被拒绝提交不留痕（时钟/快照/幂等计数三重对比）、拒绝次序、
  下发前前置失效且配额不退还、序号丢弃、时刻回退等；
- **随机对照测试**（`model_test.go` + `naive_test.go`）：朴素模型独立
  编写（切片+线性扫描+单线程），40 个种子 × 1500 个随机操作 × 3 套
  配置（含 0 阈值、0 超时、负时区偏移等极端配置），逐操作对比返回值
  与拒绝原因，每 100 步对比全量车辆快照、时钟与幂等记录数，
  日志打印每步的输入、输出与判定依据（`go test -v` 可见）；
- **并发测试**（`concurrency_test.go`，`-race` 下运行）：同键并发提交
  恰好受理一次；多车辆混合并发后校验在途数等不变量；
- **性能验证**（`bench_test.go`）：见 2.6；
- **HTTP 层**（`cmd/server/main_test.go`）：端到端走通
  上报→提交→唤醒→下发→回执→迟到回执→幂等重放→拒绝。

## 5. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin   # 如 go 不在 PATH
go build ./...
go vet ./...
gofmt -l .
go test ./...                    # 全量测试
go test -race ./...              # 竞态检测
go test -v -run TestRandomAgainstNaiveModel ./internal/gateway/  # 查看对照日志
go test -bench BenchmarkSteadyState -benchtime 20000x -run XXX ./internal/gateway/
go run ./cmd/server -addr :8080  # 启动 HTTP 演示服务
```

HTTP 接口示例见 `cmd/server/main.go` 包注释与 `README.md`。
