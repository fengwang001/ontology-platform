# 基于角色与标签的访问控制模块 — 设计说明

## 1. 模型总览

- **标签不直接授予实例**。标签通过 `Attachment` 挂在对象类型上，通过
  `Propagation{Tag, LinkType, Direction}` 声明沿链接类型在对象类型关系
  网络中传播（下游 = 沿边方向，上游 = 逆边方向），深度不设上限。
  实例通过其所属对象类型继承标签。
- **角色对标签授权**。`Grant{Role, Tag, Allow|Deny}` 直接声明在角色上；
  角色可有多个上级角色，主体的有效授权 = 其全部直接角色及其上级闭包
  上的声明集合。
- **判定**。`Decide(subject, instance)` 对实例携带的全部标签逐一裁决并
  综合；`DecideTag(subject, instance, tag)` 做标签维度判定。

## 2. 关键取舍

### 2.1 传播计算：全量重算 + 原子快照替换（放弃增量维护）

每次影响物化视图的变更（边、挂载、传播、阻断、授权的增删）都触发一次
**从空白状态的全量重算**，结果整体原子替换（`rebuildLocked`）。

- 由此“增量维护结果 == 从头重算结果”是**构造性成立**的，无需额外证明；
- 撤销（移除挂载 / 移除传播资格）的级联语义自动正确：重算后仍存在的
  标签必然仍有独立来源，消失的必然是所有来源都被撤销；
- 原子性由单写锁 + 整快照替换保证，外部不可能观察到部分更新的中间态。

被放弃的方案：**增量传播维护**（只重算受影响子图）。它需要在多父、
多路径、含环图上维护每个 (类型, 标签) 的来源引用计数与反向依赖索引，
撤销时的级联删除正确性极难论证，且正是“增量与重算偏差”风险的来源。
全量重算把正确性论证压缩到一个单调不动点算法上。

代价：单次变更成本为 O(全部声明)。对象类型/链接类型/标签/角色/主体/
实例的纯声明不触碰视图，已跳过重算（语义严格等价）。若未来声明规模
成为瓶颈，可在保持“重算即真相”的前提下做内部增量化，接口与语义不变。

### 2.2 传播算法：工作队列不动点（环安全、顺序无关）

`computeSnapshot` 把 (对象类型 × 标签 × 来源 × 传播声明子集) 作为有限
状态空间，来源集合只增不减，因此：

- 关系图中的环不会导致不终止（状态空间有限且单调）；
- 结果与路径枚举顺序无关（不动点唯一）；
- 多路径继承同一标签自然收敛为“存在与否 + 来源集合”的唯一结论。

**阻断点** `Block{ObjectType, Tag}`：该类型自身仍携带标签，但不再向外
传播。语义等价于“路径可终止于阻断点，但不得穿过阻断点”。

同时计算一份忽略全部阻断点的 **shadow 可达性**，用于在判定时区分
“标签的全部继承路径被阻断”（优先级 2 错误）与“标签本就不会到达”
（不构成约束）。

### 2.3 授权裁决：显式拒绝优先（deny-overrides）

允许与拒绝均可来自直接声明或上级继承，四种组合的裁决表：

| 允许 | 拒绝 | 结论 |
|---|---|---|
| 直接 | 直接 | 拒绝 |
| 直接 | 继承 | 拒绝 |
| 继承 | 直接 | 拒绝 |
| 继承 | 继承 | 拒绝 |

即：存在任何显式拒绝（无论来源）即拒绝；否则存在允许即允许；否则
默认拒绝。该规则对四种组合给出唯一且不矛盾的结果，且与声明登记
顺序无关（对集合取存在性，而非按序扫描）。

被放弃的方案：**就近优先**（直接声明覆盖继承声明）。它在“直接允许 +
继承拒绝”时放行，会让上级角色的安全兜底（如实习生禁用机密标签）
被下级角色的局部声明静默击穿；deny-overrides 与 XACML 的
deny-overrides 组合算法一致，语义更易审计。

### 2.4 多标签综合：全允许才允许（conjunction）

实例携带多个标签时，主体对**全部**标签均被允许才允许访问；任一标签
被拒绝则整体拒绝。综合对标签集合取合取，不依赖标签在实例上的记录
顺序或授权表登记顺序。多个标签同时出错时，按固定优先级汇报（见 2.5），
同优先级取标签名字典序最小者，结果确定。

被放弃的方案：任一允许即放行（过宽）、按标签优先级排序裁决（引入
额外的顺序维度，违反顺序无关要求）。

### 2.5 错误分类与固定优先级

判定错误按如下唯一优先顺序汇报：

1. `subject_or_tag_not_found` — 主体、标签（或实例）不存在；
2. `all_paths_blocked` — 标签的全部继承路径被阻断（shadow 可达但
   实际未携带）；
3. `deny_overrides_allow` / `explicit_deny` — 显式拒绝优先于隐式允许；
4. `role_hierarchy_cycle` — 角色层级存在循环继承，无法确定授权来源。

角色环在判定时以三色标记检测（声明时允许成环，因为环是否影响某次
判定取决于主体实际的角色闭包）。环不使遍历不终止；存在拒绝结论时
按优先级先报拒绝。

被拒绝的判定只读取状态：不修改标签继承、角色层级，也不触碰任何时钟
（有 `TestDeniedDecisionHasNoSideEffect` 守护）。

### 2.6 并发：单读写锁串行化

全部变更持写锁，全部判定持读锁。任意并发调用的结果等价于按锁获得
顺序串行执行的结果（线性一致性由互斥直接保证）。判定路径上的快照
是整体替换的，读者要么看到旧快照要么看到新快照，不会看到中间态。

被放弃的方案：细粒度锁 / 无锁数据结构。在本模块的读写比例与规模下，
单锁的吞吐已足够，而正确性论证成本最低。

### 2.7 判定开销与总规模无关（可观测证明）

判定只读取：(a) 目标实例所属对象类型的物化标签来源集合；(b) 主体
角色闭包。两者都不随对象类型/链接类型总规模增长。

可观测证明手段：每次判定返回 `Decision.Stats{TagSourcesVisited,
RoleNodesVisited}` 并写入日志；`TestDecisionCostIndependentOfGraphSize`
在保持目标子图不变的情况下把背景图放大两个数量级，断言两项计数
逐值相等。该证明只依赖公开输出，不依赖实现细节。

## 3. 日志与审计

每次判定输出一条结构化日志（`log/slog`），包含：输入（主体、实例、
标签）、最终输出（允许与否、原因分类、说明）、裁决依据（每个标签的
来源挂载点与途经传播声明、每条角色授权证据及其直接/继承属性）、
以及开销计数。

## 4. 测试策略与本地验证

- **单元测试**（`engine_test.go`）：多路径收敛、声明顺序无关、传播
  阻断、环终止与稳定性、上游传播、允许/拒绝 × 直接/继承全组合、
  多标签综合、撤销级联（挂载与传播资格两类）、增量==重算、错误
  优先级、拒绝无副作用。
- **差异测试**（`diff_test.go`）：`NaiveEngine` 是独立维护的朴素参照
  实现（简单路径枚举 + 递归角色扫描，不做物化）。40 个随机种子 ×
  150 步随机变更序列，每步之后对全部主体 × 实例 × 标签逐项对照
  `Decide` / `DecideTag` 的结论与原因分类。
- **规模测试**（`scale_test.go`）：见 2.7。
- **并发测试**（`concurrency_test.go`）：`-race` 下混合并发变更与
  判定；无变更时并发判定结果逐字段一致。
- **日志测试**（`logging_test.go`）：校验日志包含输入、输出与裁决
  依据。

本地验证命令：

```bash
go test ./...            # 全量测试
go test -race ./...      # 竞态检测
go vet ./... && gofmt -l .
go run ./cmd/server      # 演示（JSON 日志输出到 stdout）
```
