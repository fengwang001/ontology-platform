# 临床检验室内质控系统设计说明

## 模块划分

- `qc`：生产实现。`system.go` 负责登记、时钟、状态机、报告生命周期和互斥；`rules.go` 负责五条质控规则、严格阈值和连续计数；`errors.go` 定义稳定错误码。
- `naive`：独立朴素参照模型。每次判定重扫该项目校准后的完整运行序列，报告追溯也从候选报告列表逐项检查，不共享生产代码中的状态压缩逻辑。
- `qc` 测试：确定性边界、状态恢复、报告拦截、错误优先级、并发竞态、1500 组随机重放和两档规模对照。

## 关键状态

- 每个水平只保存三个连续值：同侧连续点数、同侧且超过 1σ 的点数、同侧且超过 2σ 的点数，以及当前侧符号。
- 偏离量为零会将该水平三个计数全部清零；异侧会从当前点重新开始计数。
- 项目还保存是否存在当前校准周期内的非失控运行、最近一次非失控运行时刻、恢复计数和报告追溯游标。
- 校准将两个水平序列清零、项目立即恢复在控，并把“当前校准周期内是否已有非失控运行”重置为否。靶值、标准差以及历史报告本身不变。

## 判定取舍

- 所有阈值均使用整数与整数乘法，严格大于才算超过；恰等于 `k*SD` 不触发对应失控规则。
- 五条规则按需求顺序计算并追加。规则二、四可能由低或高任一水平触发，但每种规则在结果中最多出现一次。
- 规则三只看本次运行两个水平是否异号且各自严格超过自己的 2σ。
- 触发任一规则为失控；无触发但任一水平严格超过 2σ 为警告；其余为正常。警告和正常都是非失控运行。
- 恢复只接受连续两次“无规则且非警告”的运行。任一警告或失控立即清零恢复计数；第二次合格运行的时刻恢复在控。

## 报告拦截与追溯

- 出报告依次检查参数、时钟、对象存在、在控状态、是否有非失控运行、有效期。有效期判断为 `now-lastNonOOC > validFor`，所以恰等于有效期仍可出具。
- 失控期间不出具新报告，且被拒绝的报告不进入任何列表或索引。
- 项目从在控转入失控时，从该项目当前校准周期对应的候选报告起点扫描至列表末尾，但只标记“严格晚于上一非失控运行时刻且不晚于失控运行时刻”的报告。
- 校准后若尚无新的非失控运行，随后首次失控会标记全部项目报告；已有非失控运行后，报告切片追加顺序与时钟单调保证后续报告都在候选尾部。
- 追溯复杂度为与本次实际候选报告数成线性关系，不使用全局报告表，也不扫描无关项目。

## 并发与确定性

- 一个互斥锁串行化全部写操作和快照读取，因此并发调用等价于某个确定的锁获取顺序。
- 全局保存最近一次被接受操作的 `now`。任何参数错误、时钟回退、对象不存在或业务拒绝都在修改状态前返回，不推进时钟。
- 固定随机种子重放同一操作序列，生产模型与朴素模型逐操作比较错误、结果规则、正常/警告/失控结果以及全部报告状态。
- 随机对照测试使用 `-v` 时打印每一步输入、生产输出、朴素输出及错误，日志示例可重定向到文件保存。

## 复杂度验证

- 单次质控运行只读取固定数量的每水平计数器，不读取历史运行数组。规模测试分别以 1,000 和 100,000 的历史计数构造状态，比较单次判定耗时。
- 追溯测试分别构造 1,000 和 100,000 份本次待标记报告，记录总耗时和每份平均耗时；结果随待标记报告数线性增长，与历史运行总数无关。
- 生产实现保留 `runs []QCRecord` 是为了审计可追溯和测试快照；它不参与五条规则判定。

## 被放弃的方案

- 放弃为所有历史运行建立滑动窗口队列：规则五虽看似需要十点，但只需要同侧边计数；异侧或零点已经满足重置条件，队列会把判定变成历史长度相关。
- 放弃追溯时二分报告时间：报告按单调时钟追加且只需从当前校准周期候选尾部开始；二分虽可搜索时间，但无法同时表达校准后“全部报告”的游标语义。
- 放弃每个项目独立时钟：需求要求不得小于“上一次被接受操作”的 now，测试也按全局操作流理解，因此使用系统级单调时钟。
- 放弃在生产规则判定中复用朴素扫描模型：这样会失去 O(1) 判定，也会让随机对照失去独立性。
