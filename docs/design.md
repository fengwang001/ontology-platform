# 车载诊断故障码（DTC）生命周期管理器 — 设计说明

## 1. 模块划分

实现位于 `dtc` 包，按职责拆分为相互协作的小模块；`dtctest` 包提供独立编写的朴素模型，仅供测试对照。

| 文件 | 职责 |
| --- | --- |
| `dtc/config.go` | 配置定义与合法性校验（去抖步长/判定线、确认/愈合/清除循环数、暖机阈值） |
| `dtc/errors.go` | 可区分错误类型 `ErrorKind` 与 `Error`，检查次序固定 |
| `dtc/events.go` | 事件类型与事件结构（点火开/关、监测上报、环境采样、诊断仪清除） |
| `dtc/debounce.go` | 去抖器：循环内去抖值与判定的升降、钳制与清零 |
| `dtc/dtc.go` | 单个故障码的生命周期状态（持久字段 + 循环内暂态） |
| `dtc/freezeframe.go` | 全车唯一冻结帧槽位：占用、按严重度替换、释放 |
| `dtc/manager.go` | 管理器：事件校验（按优先级）、事件应用、点火关循环结算、查询、并发串行化 |
| `dtctest/naive.go` | 朴素参考实现：保留全部历史，每次查询从头重放，复杂度随历史增长 |

协作关系：`Manager` 持有全部 `dtcState` 与唯一 `freezeFrameSlot`；监测上报先经 `debouncer`
判定，再驱动 `dtcState` 的待定/发生次数/冻结帧捕获；点火关时 `Manager` 统一做循环结算
（连续失败循环、暖机判定、愈合、自动清除）。

## 2. 关键取舍

- **增量计数器，不存历史**：每个故障码只保存待定/确认/愈合标志、发生次数、连续失败循环数、
  无故障暖机数与循环内暂态；暖机判定只保留本循环的最低/最高冷却液温度。单次监测上报为 O(1)，
  点火关结算为 O（已登记故障码数），与历史循环总数无关。朴素模型（`dtctest`）故意保留全量历史
  并重放，作为正确性对照与复杂度反例。
- **单互斥锁串行化**：所有公开方法（`Handle`/`Snapshot`/`Snapshots`/`RegisterDTC`）在同一把
  `sync.Mutex` 下执行，并发调用天然等价于某个串行顺序。放弃"每故障码一把锁"的分片方案：
  冻结帧是全局唯一资源，跨码竞争不可避免，分片锁收益小而死锁风险与复杂度高。
- **先校验、后变更**：五类检查（参数非法 > 时刻/里程回退 > 事件顺序 > 未登记 > 状态不允许）
  全部在应用事件之前完成，因此被拒绝的事件不会改变任何状态，无需回滚机制。
- **冻结帧归属按码判定**：查询"是否拥有冻结帧"即"槽位占用者是否为该码"。槽位被他人占用时，
  仅当新码严重度严格更大才替换；占用者本人再次进入待定时更新快照（同一码的新的失败应当
  记录最新环境）。释放（自动清除/诊断仪清除）后槽位置空，不自动让给他人。
- **冻结帧环境值取"最近已知"**：车速/冷却液温度取最近一次环境采样（跨循环保持，符合物理
  意义），里程取失败判定事件的里程；暖机统计则只看本循环内的采样。
- **愈合后计数延续**：已愈合历史码的"无故障暖机数"不清零、继续累计，达到自动清除阈值时彻底
  清除（状态归零、释放冻结帧）；其间任何失败在失败判定时刻立即清零并重新待定，连续失败循环
  数从零开始。
- **诊断仪清除保留登记**：清除的是状态、历史与冻结帧；故障码目录（编号/严重度登记）属于配置
  而非状态，予以保留，清除后监测上报仍然合法。清除时刻里程记为清除基准，
  查询返回"当前里程 − 清除基准"。
- **暖机判定在点火关进行**：循环内只累积最低/最高温度，点火关时判定
  `最高−最低 ≥ 温升阈值 且 最高 ≥ 终温阈值`，与"是否暖机在点火关时才确定"一致。

## 3. 被放弃的方案

- **事件溯源 / 全量历史存储**：内存随历史线性增长、结算随历史变慢，且规范明确要求结算开销
  与历史无关；仅在对照模型中采用。
- **每故障码细粒度锁**：冻结帧全局竞争与"诊断仪清除全量状态"都需要跨码一致性，细粒度锁
  引入锁序问题，放弃。
- **以循环首次采样作为暖机基准**：规范明确"较循环内最低采样"的温升，故采用循环内最低值。
- **自动清除后保留墓碑记录**：规范要求"彻底清除"，故状态全部归零，不保留痕迹。

## 4. 本地验证方法

```bash
# 单元测试（去抖恰线、同循环失败-通过-失败、监测未完成、确认/愈合差一与恰满足、
# 暖机恰等阈值、冻结帧相等/更高替换、清除释放、愈合再失败、错误优先级、并发）
go test ./dtc/ -v

# 随机对照：100 个种子 × 500 个事件，与朴素模型逐步比对错误类别与全部快照
go test ./dtc/ -run TestRandomSequencesVsNaiveModel -v

# 复杂度两档对照：历史 2k 与 200k 循环后的点火关结算耗时对照（日志打印两者）
go test ./dtc/ -run TestSettlementCostIndependentOfHistory -v
go test ./dtc/ -bench BenchmarkIgnitionOffSettlement -benchtime 1000x

# 竞态与静态检查
go test -race ./...
go vet ./...
gofmt -l .
```
