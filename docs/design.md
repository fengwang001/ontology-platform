# 本体链接路径权限查询设计说明

## 模型

实现位于 `ontology` 包：

- `Graph` 保存对象、对象类型、链接、链接类型、非负代价与邻接表。
- `Policy` 校验权限组、成员关系、对象类型声明和链接类型声明。
- `Authorizer` 持有一个原子替换的不可变权限快照。
- `ShortestPath` 在 Dijkstra 搜索中逐条候选链接执行覆盖判断。

## 覆盖规则

每次判断按固定次序执行：

1. 权限主体标识非法时直接返回 `ErrInvalidSubject`。
2. 查询链接类型层：主体所属权限组中，只要存在该链接类型声明，就只取最高优先级声明。
3. 链接类型层没有声明时，分别查询源对象类型和目标对象类型；若两端都有声明，按最高优先级比较，同优先级时拒绝优先。
4. 两层都没有可用声明时默认拒绝。

最高优先级组内若有允许和拒绝矛盾，合并结果恒为拒绝。该规则先在策略快照编译阶段按主体、类型预解析，查询时只读取主体相关 map，不扫描全部权限组。

链接类型层是整条链接的具体声明，因此只要存在即覆盖源、目标对象类型默认值，不与对象类型层再次混合优先级。

## 快照与并发

`Authorizer.UpdatePolicy` 编译出新的不可变 `policySnapshot`，再通过 `atomic.Pointer` 原子发布。路径查询开始时读取一次快照指针，随后整条路径的所有候选判断都使用该快照；并发变更只影响之后发起的查询。

这给出明确的可串行化语义：把每次声明变更视为一个原子事务，把每个查询视为在发起时刻读取最后一次已提交声明的只读事务。

## 最短路径

搜索只访问从源点可达的候选分支：

- 代价使用 Dijkstra，因为链接代价为非负数。
- 同代价时按对象标识序列的字典序选择。
- 每扩展一条候选链接都重新调用覆盖判断；链接层、源对象类型和目标对象类型都来自该候选链接本身。
- 被拒绝的链接不进入距离松弛。

没有任何允许链接能形成完整路径时返回 `PathUnreachable`。`PathAmbiguous` 保留为 API 状态，用于未来允许“同优先级冲突不按拒绝优先合并”的策略模式；本需求明确规定拒绝优先，所以在合法输入下不会返回歧义，这保证普通拒绝导致的不可达与未合并的歧义状态在接口上可区分。

## 内部度量

`PathResult` 内部记录：

- `EvaluatedLinks`：本次搜索实际调用覆盖判断的候选链接数。
- `EvaluatedLinkTypes`：这些候选链接中出现的链接类型去重数。
- `EvaluatedObjectTypes`：进入对象类型层判断的源/目标对象类型去重数；链接类型层命中时不额外计入对象类型。

这些字段不对普通调用者公开，但同包测试可以直接断言。计数只随 Dijkstra 实际触达的候选分支和路径长度增长，不遍历权限组总数，也不扫描与源点无关的对象和链接。

策略快照构建是一次性 O(M+D)，其中 M 是成员关系数、D 是声明数；单次查询不随权限组总数增长。

## 关键取舍

- 采用主体维度预编译快照，而不是查询时扫描所有权限组，避免查询成本随组总数增长。
- 采用不可变快照而不是给整张策略加锁，避免长查询阻塞声明更新，也避免查询中途读到混合状态。
- 邻接表按目标对象 ID、链接类型 ID、链接 ID 排序，保证候选遍历和测试结果稳定。
- 不把审计轨迹和度量放入公开业务返回字段，防止调用者依赖内部验证结构。

## 放弃的方案

- 查询时逐组扫描声明：实现简单，但复杂度直接依赖权限组总数，不满足要求。
- 全局读写锁：能保证一致，但并发更新会阻塞查询，也容易在后续扩展中产生锁持有期过长的问题。
- 路径搜索完成后统一鉴权：可能把无权限链接用于中间状态，无法满足“遍历每一条候选链接之前”判断的要求。
- 同代价任选一条路径：实现简单，但不能给出唯一确定结果。
