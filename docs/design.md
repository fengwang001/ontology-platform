# 电商多仓库存可承诺量查询与订单承诺系统 — 设计说明

## 模块划分

系统位于 `atp/` 下，按职责分为五个相互协作的包：

| 包 | 职责 |
| --- | --- |
| `atp/clock` | 单调时钟：只被“被接受的操作”推进，拒绝回退。 |
| `atp/reject` | 统一的拒绝原因类别与错误类型，定义拒绝优先级顺序。 |
| `atp/inventory` | 库存状态：现货、计划入库、预留最小堆与滚动和；可承诺量计算；预留生命周期（确认出库、释放、懒过期）；订单索引。 |
| `atp/order` | 承诺引擎：参数校验、订单行依次模拟分配、缺货分类、拆分上限判定、成功落账。 |
| `atp/service` | 门面：互斥锁串行化、时钟推进规则、拒绝优先级编排、只读查询、统计与不变量检查。 |

依赖方向单向：`service → order → inventory → clock/reject`，无循环依赖。

## 关键语义与取舍

### 时钟

- 每个变更类操作携带时刻 `now`；`now < 当前时钟` 报时钟回退，相等允许。
- 只有被完全接受的操作才推进时钟；任何被拒绝的操作不改变状态与时钟。
- 查询只读，不推进时钟；查询承诺时刻早于当前时刻报参数非法（规格明确要求与时钟回退区分）。

### 可承诺量（ATP）

某仓某商品在承诺时刻 `t` 的 ATP = 现货 + 到货时刻 `<= t` 的未确认计划入库 − 当前时刻仍有效的预留。
预留在 `now < 到期时刻` 时严格有效，恰到到期时刻即失效。

### 预留的懒过期（核心取舍）

每个 `(仓库, 商品)` 的预留按到期时刻组织为**最小堆**，另维护一个
**仍有效预留总量的滚动和**。ATP 计算只读滚动和（O(1)），并在堆顶做
懒过期清理：弹出所有 `到期时刻 <= now` 的记录并扣减滚动和。

- 每条失效预留**最多被弹出考察一次**，此后从堆中移除、不再出现，
  满足“失效预留不得被反复考察”。
- 已确认出库/已释放的预留成为堆中墓碑（不再计入滚动和），随懒清理移除。
- 可验证性：`Inventory.Stats()` 暴露 `examined`（考察的预留记录数）与
  `sweeps`（扫描次数）两个计数器。`TestReservationExaminationBounded`
  断言：在 5000 条已失效预留之后，单次承诺的考察数为常数级；且全局
  `examined <= 历史预留总数 + sweeps`（每次扫描至多多看一条未到期堆顶）。

### 缺货分类

对缺货行：总供给 = 所有仓库（现货 + 全部未确认计划入库），忽略预留与
到货时刻；再扣除**本订单前面行已占用**的同商品数量，剩余不足为
**永久缺货**，否则为**暂时缺货**。多行同时缺货时，永久缺货优先于暂时
缺货（与拒绝优先级一致），同类报下标最小行。

### 拆分与仓库选择

- 不允许拆分：选 ATP 足够的仓库中优先序号最小者（并列按 ID，保证确定性）。
- 允许拆分：按优先序号由小到大依次尽量取用，满足即止；**不做回溯**，
  仓库数超限即报拆分过多，不为凑上限改用其他方案（规格明确禁止）。
- 上限按**整张订单**涉及的不同仓库数计算，与是否允许拆分无关。

### 确认出库时的现货非负保证

承诺时 ATP 可能包含“已到货但尚未确认”的计划入库。若确认出库时该入库
仍未确认，直接扣现货会变负。取舍：确认出库前先把 `到货时刻 <= now` 的
未确认入库**折叠**为现货（对任何 `t >= now` 的 ATP 不可观测，因为两侧
都计入），再扣减。由不变量 `ATP(now) >= 0` 可证折叠后现货足够扣减。

### 订单号生命周期

- 同一订单号存在**仍有效**预留时再承诺 → 订单重复；预留到期后可重用。
- 确认出库：订单不存在 → 订单不存在；预留已到期 → 预留已过期（二者可区分）。
- 释放预留：订单不存在**或已到期** → 订单不存在（规格要求）。

### 并发与确定性

门面用一把互斥锁串行化所有操作，结果等价于某个串行顺序；仓库选择只
依赖排序切片（不依赖 map 遍历序），相同操作序列重放得到完全相同的
发货仓分配（`TestDeterministicReplay`、随机对照测试双重验证）。

## 被放弃的方案

- **每次操作全量扫描过期预留**：考察次数随历史订单总数线性增长，
  违反“不得随历史增长”的要求，放弃，改用最小堆懒过期。
- **拆分回溯/装箱优化**：试图用更少仓库凑单。规格明确“不得为凑够
  上限而改用其他取用方案”，放弃，坚持按优先序贪心。
- **确认出库时现货不足即拒绝**：规格未定义该错误，且会破坏
  “确认出库只需区分不存在/已过期”的语义，放弃，改用到货折叠。
- **分仓分商品细粒度锁**：提升并行度但引入跨仓订单的锁排序与
  确定性难题；当前单锁串行已满足“等价于某个串行顺序”，放弃。
- **预留到期即主动清除（定时器）**：引入额外并发源与非确定性，
  且规格要求按当前时钟判定，懒过期已足够，放弃。

## 本地验证方法

```bash
# 全量测试（含竞态检测）
go test -race ./...

# 查看随机对照测试的逐步日志（输入、输出、判定依据）
go test -v -run TestRandomizedDifferential ./atp/service

# 查看预留考察次数有界性的度量输出
go test -v -run TestReservationExaminationBounded ./atp/service

# 运行演示程序
go run ./cmd/atpdemo

# 代码检查
gofmt -l .
go vet ./...
```

测试构成：

- `atp/service/service_test.go`：定向测试——预留恰到到期与差一秒、
  到货时刻恰等于承诺时刻、两类缺货区分与多行优先级、拆分仓库数
  恰等于上限与超一、同订单多行互相影响、到货确认不重复计入、
  时钟回退、订单重复、释放/确认错误区分、拒绝优先级、查询规则、
  确定性重放。
- `atp/service/bounded_test.go`：预留考察次数有界性证明、并发承诺
  的串行等价性与不变量。
- `atp/service/model_test.go` + `random_test.go`：独立编写的朴素模型
  （切片全扫、保留全部历史）与正式实现对拍，40 个随机种子 ×
  300 步操作序列，逐步比对输出并校验不变量，日志打印每步输入、
  输出与判定依据。
