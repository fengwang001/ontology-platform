# 支付预授权额度账务系统 — 设计说明

包路径：`ontology/preauth`。入口类型 `preauth.System`，线程安全。

## 1. 领域模型

- 卡账户 `account`：`credit`（信用额度）、`posted`（已入账余额）、
`lastNow`（最后一次被接受操作的时刻）、一个到期表 `expirySchedule` 与
授权映射 `auths`。
- 授权 `authorization`：`authorized`（累计授权额）、`captured`（累计捕获）、
`refunded`（累计退款）、`expiresDay`（有效期截止日，含当天）、终态标记
`state ∈ {active, voided, finalized}`。“已过期”不落盘，由 `now > expiresDay`
实时推导。
- 可用额度（任何时刻）：

```
available(now) = credit - posted - Σ 有效授权的剩余持有(now)
剩余持有(授权)   = max(0, authorized - captured)，且仅在授权有效时计入
```

金额为正整数最小货币单位（`int64`），时间为整数天。

## 2. 关键不变量

1. 同一账户内全部修改都持有该账户的互斥锁，`posted` 与持有的增减在同一
临界区同步生效，外部不可能观察到“只入账一半/只减持有一半”。
2. `available ≥ 0` 恒成立；任何会使其为负的操作整笔拒绝、零副作用。
3. `lastNow` 只被“被接受的操作”推进；被拒绝操作不改任何字段、不入堆、
不推进时钟。
4. 授权编号全局唯一（含已终结授权），在 `idOwner` 注册表中永久留痕；
但只有被成功创建的编号才会登记，因此“因其他原因被拒绝的创建”所用编号
之后仍可使用。

## 3. 到期与持有：最小堆 + 非破坏性读

这是系统的核心，也是“查询不随历史增长”的关键。

每个授权在账户的最小堆 `expiryHeap` 中至多有一条“当前活条目”
`(day=到期日, amount=当前持有额)`。

- 创建：`place` 推入 `(expiresDay, amount)`。
- 增量：`replace` 把旧条目标 `dead`，推入 `(新到期日, max(0,newAuthorized-captured))`。
- 捕获：`reduce` 把活条目金额减少 `fromHold`（钳制不为负）；超出剩余持有
的部分不进持有条目，而通过 `posted` 占用可用额度。
- 撤销/终捕：`release` 把当前条目标 `dead` 并从持有合计扣除。

`dead` 条目是惰性删除：留在堆中，遇到折叠时才真正出堆。

### 3.1 两种折叠

- **持久折叠 `transientFold(now)`（接受时）**：取出堆顶所有 `day < now` 的
条目，活条目从 `holdTotal` 扣除，水位 `horizon = now`。这只在一次操作
通过全部校验、确定被接受时发生，因此“过期释放”随第一个跨过到期日的
被接受操作自动落账，无需任何后台任务。
- **非破坏性读 `peekHolds(now)`（校验与查询时）**：临时取出到期前缀并扣减，
读出 `holdTotal` 后通过 `undoFold` 把条目原样压回、恢复金额与水位。
查询不推进水位、不改变堆。

所有“可能被拒绝”的校验（额度、容差、已终结、调低额度）都先基于
`peekHolds`/临时折叠观察 `now` 时刻的有效持有；一旦拒绝就 `undoFold`，
保证零副作用；一旦接受则保留折叠结果（等同提交）。这同时满足了
“过期只取决于已接受操作与 now”与“被拒绝操作不改状态”。

### 3.2 复杂度证明（可验证）

令某账户授权数为 `A`。

- 每个授权在堆中最多因为增量替换而新增条目；对该授权的一次成功捕获/
撤销/终捕只会改其当前条目的金额或置 `dead`，不新增。
- 任意条目一旦在某次持久折叠中出堆，就永久消失。
- 活条目总数等于“当前仍有效的授权数”，与历史授权数无关；`dead` 条目也
会在下一次折叠到其 `day` 时被清出。
- 因此：
  - 查询 `Available` 只临时弹出 `day < now` 的堆顶前缀。持久水位之后，
这些都是真正到期的条目；在稳态（存在周期性被接受操作）下，前缀长度不
随历史增长，摊销 `O(1)`，最坏为当前有效授权数 `O(A_active)`，与
历史总数无关。
  - 注册表 `idOwner`/`accounts` 的定位是 `O(1)` map 查询，与全部账户数无关。

经验验证见 `TestQueryComplexityIndependentOfHistory`：历史授权从 2k→32k
（16 倍），单次查询耗时恒定在约 190ns，且折叠后堆中活条目为 0。

## 4. 操作语义与错误优先级

校验顺序（严格按此，只报第一个错误）：

- 一般操作：参数非法 → 时钟回退 → 编号重复（仅创建）→ 授权不存在 →
授权已终结（含过期）→ 超容差 → 额度不足。
- 退款：参数非法 → 时钟回退 → 授权不存在 → 超出可退额。
- 创建授权额外要求账户存在（不存在账户归为参数非法）。

要点：

- 有效期：创建/增量日 `d` 起 E 天，截止日 `d + E - 1`，当天有效，
`d + E` 起过期。增量在过期前最后一天也照常重置。
- 增量仅按增量额占用额外可用额度，不重复计算原持有；增量后容差上限按
新的累计授权额重算，已捕获额不变。
- 捕获 `amount`：
  - `fromHold = min(amount, remaining)` 由持有承担；
  - `extra = amount - fromHold` 必须由当前可用额度承担（否则额度不足），
成功后该授权剩余持有为 0，之后捕获全部来自可用额度；
  - 累计捕获上限 `floor(authorized * (1 + bps/10000))`，超限报超容差
（优先于额度不足）；
  - 终捕成功后剩余持有立即释放、授权终结。截止日当天捕获有效，次日报已终结。
- 撤销只释放剩余持有，不动已捕获；终结后不可再捕获/增量/撤销。
- 退款只减 `posted`、增 `refunded`，不恢复持有、不改状态/有效期、不受
容差影响；可退额 `captured - refunded`；已终结（含过期、终捕、撤销）
授权仍可退。
- 调低信用额度：`newCredit - posted - holds(now) < 0` 则整笔拒绝。

## 5. 并发模型

- 固定锁序：先 `registryMu`（注册表）后账户 `mu`，绝不反向，避免死锁。
- 注册表仅在创建授权时短暂嵌套持有；`lookup` 先在注册表取出账户指针即
释放注册表锁，再只持有目标账户锁完成全部读写，缩小临界区。
- 不同账户完全并行；同账户操作互斥，故结果等价于某种串行交错。
- `go test -race` 下并发测试通过（`TestConcurrentNoNegativeAvailable`）。

## 6. 被放弃 / 权衡过的方案

- **后台定时扫描过期任务**：放弃。过期必须“不依赖任何操作触发”，且要在
任意 now 精确复现；后台任务引入时间耦合与额外故障面。改为查询/操作时
惰性折叠。
- **给每个授权持久化“已过期”状态**：放弃。过期是 `now` 的纯函数，落盘
会让同一笔数据在不同 now 下产生矛盾状态；改为实时推导 + 堆折叠持有。
- **拒绝操作也折叠时间**：第一版曾如此实现，随机差分测试暴露其会让被拒
操作间接移动时间轴（例如一次额度不足的创建“顺便”释放了别的过期持有），
违反“被拒绝操作零副作用”。最终改为：校验用非破坏性 `peekHolds`，只有
接受才持久折叠。
- **查询复制整堆再排序**：可行但内存/常数更差，且语义上查询期间堆本就
被账户锁保护，直接“临时弹出—恢复”更简单，两者复杂度同阶。
- **把超额捕获也留在持有条目里（负金额）**：曾导致过期时负金额被错误加
回额度；现统一为剩余持有钳制非负，超额部分只走 `posted`。

## 7. 文件结构

- `errors.go`：可区分的哨兵错误。
- `types.go`：`Status`、`AuthView`、`AccountView`、`Config`。
- `expiry.go`：到期最小堆、持有合计、持久/非破坏性折叠。
- `account.go`：账户与授权内部结构、可用额度与视图推导。
- `system.go`：`System` 对外操作、锁序与校验顺序。
- 测试：`edge_test.go`（边界用例）、`naive_test.go`（独立朴素模型 oracle）、
`diff_test.go`（随机差分，打印输入/输出/判定）、`concurrency_test.go`
（并发与确定性重放）、`perf_test.go`（查询复杂度实测）。

## 8. 本地验证

```bash
go test ./...
go test -race -v ./preauth/
go test -v -run TestQueryComplexity ./preauth/   # 复杂度实测，含日志
go vet ./...
gofmt -l .
```

`TestRandomDifferential` 默认 2000 个随机种子（多账户、随机时钟前进/回退、
随机创建/增量/捕获/终捕/撤销/退款/调额/查询），逐步把每个操作的输入、
生产实现与朴素模型的输出打印到日志，任一不一致即整段转储，便于复现。
