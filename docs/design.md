# 受权限约束的图遍历环检测服务 — 设计说明

## 问题重述

本体平台上的每条链接附带一个权限标签，调用方只能看到自己标签集合
范围内的链接。遍历服务必须满足：

1. 环路检测在**完整图**（含不可见链接）上判定，不能只在可见子图上判定；
2. 判定结果返回给调用方时，不得泄露不可见链接的任何属性或连接对象标识，
   只允许泄露「存在性」本身；
3. 并发修改下，单次遍历等价于在某个确定快照上执行，
   且图结构与权限标签共享同一快照时点；
4. 祖先序列核对次数不随图总规模线性增长，且可测试验证。

## 核心语义

### 遍历模型

从起始对象出发做有向 DFS，深度上限为路径上的链接数。在每个对象上
考察**全部**出边（无论可见与否），对每条出边 `l: N -> T` 按序判定：

| 条件 | 判定 | 对调用方可见的输出 |
| --- | --- | --- |
| `T` 在当前路径祖先集合中，且 `l` 可见 | 真实环路 | `CYCLE` 边，含链接 ID/标签/目标（目标本就在可见路径上） |
| `T` 在祖先集合中，且 `l` 不可见 | 真实环路 | `CYCLE(hidden)` 标记，零属性 |
| `T` 不在祖先集合中，且 `l` 不可见 | 部分不可见 | `HIDDEN-EXT` 标记，零属性 |
| `T` 不在祖先集合中，且 `l` 可见 | 正常扩展 | 完整边信息 + 子树 |

同一节点上的不可见标记**去重**（至多各一条）：数量本身也属于
「存在性之外」的信息，多条不可见链接只产生一条标记。

### 三类终止的区分

- **真实环路终止**（`TermCycle`）：由完整图结构决定，与调用方权限无关。
  因此所有调用方对同一条可观察路径前缀得到一致的成环结论。
- **部分不可见**（`TermHidden`）：不可见延伸本身不成环、也未被截断，
  调用方看到可见前缀加「是否成环未知」标记。遍历**不越过**不可见链接
  继续深入——越过之后的所有内容对调用方本来就完全不可感知，
  继续遍历只会徒增成本并扩大泄露面。
- **正常返回**：完全可见且不成环的路径原样返回；深度截断不产生任何
  额外标记，与不需要核对完整图的实现输出完全一致。

### 错误次序

四类错误互斥，判定次序硬编码在 `Snapshot.Traverse` 入口，不随内部
实现变化：

1. `ErrStartNotFound` — 起始对象不存在；
2. `ErrEmptyCallerLabels` — 调用方权限标签集合为空；
3. `ErrInvalidMaxDepth` — 深度上限非正整数；
4. `ErrStartInvisible` — 起始对象对调用方完全不可见
   （没有任何一条关联链接的标签在调用方集合内）。

### 快照一致性

`Store` 用一把 `sync.RWMutex` 串行化所有写操作（加链接、删链接、
改标签）。`Snapshot()` 在**同一次读锁临界区**内把图结构与权限标签
一起深拷贝为不可变视图，因此二者必然取自同一时点。遍历只读快照，
与并发写完全隔离；结果中携带快照版本号，可回溯到某个已提交状态。

### 祖先核对的复杂度

当前路径上的对象集合用哈希表（`map[ObjectID]struct{}`）维护，
每扩展一条链接恰好做 **1 次** O(1) 祖先核对（`Stats.AncestorChecks ==
Stats.ExpandedLinks` 恒成立）。核对次数只随遍历实际触及的链接数增长，
与图中对象、链接、权限标签种类的总数无关。

## 关键取舍与被放弃的方案

### 放弃：先按权限过滤、再在可见子图上判环

这是最常见的直觉方案，但它会放过只能借助被隐藏链接才能闭合的真实
环路（需求的核心反例）。本设计改为「全图遍历 + 输出过滤」：判定永远
基于完整图，过滤只发生在结果物化阶段。

### 放弃：对不可见成环路径返回「未知」而非「成环」

若把隐藏链接闭合的环路也标为「是否成环未知」，则同一真实环路对不同
权限的调用方会给出不同结论，违反一致性要求，也会让调用方在事实上
已经成环的方向上继续扩展。本设计让完整图判定结论对所有调用方一致，
差异只体现在「能说出多少细节」。

### 放弃：遍历期间持有读锁

遍历全程持 `RLock` 也能保证一致性，但长遍历会阻塞所有写操作，且把
一致性时长与遍历耗时耦合。快照拷贝以一次 O(V+E) 的拷贝换取遍历期间
的零锁占用与明确的时间语义（结果必然对应某个已提交版本）。

### 放弃：持久化数据结构 / MVCC 多版本保留

只保留「当前版本 + 按需拷贝快照」而非完整多版本历史。遍历只需要
开始时刻的一个时点，保留历史版本会增加内存与实现复杂度，却无对应
需求。若未来需要「在旧版本上重放遍历」，可在 `Store` 外加版本日志，
不影响遍历核心。

### 放弃：为不可见链接逐条生成标记

逐条标记会泄露不可见链接的**数量**。去重为「存在/不存在」两种标记后，
泄露面被压缩到需求允许的最小集合（存在性）。

### 放弃：线性扫描祖先序列判环

每跳 O(深度) 的扫描使单次遍历的祖先核对次数随深度平方增长，且与图
规模产生可观测的耦合。哈希集合把每跳核对降为 O(1)，并通过
`Stats.AncestorChecks` 计数器把该性质变成可测试的不变量。

## 本地验证方法

```bash
# 全量测试（含竞态检测）
go test -race ./...

# 关键验证点与对应测试：
# - 隐藏链接闭合成环的终止与信息隐藏   TestHiddenCycleTermination
# - 两类标记共存                       TestHiddenAndCycleCoexist
# - 多调用方差异与一致性交叉验证       TestCallerConsistency
# - 并发改结构+改标签的快照一致性      TestSnapshotIsolation / TestSnapshotImmutable
# - 朴素实现随机对照（800 场景）       TestNaiveDifferential
# - 祖先核对次数不随总规模增长         TestAncestorCheckBound / TestAncestorCheckPerHopConstant
# - 判定日志完整性                     TestTraversalLogging
# - 错误次序                           TestErrorOrder

# 演示程序
go run ./cmd/server
```

`TestSnapshotIsolation` 的证明方式：所有写操作经互斥锁串行提交，
因此已提交状态构成全序 S0..Sn；测试记录每个已提交状态的快照并预先
算出合法结果集合，随后断言每个并发遍历结果都落在该集合内、且携带
的版本号对应某个真实已提交状态。

`TestAncestorCheckBound` 的证明方式：构造一族遍历形状完全相同、但
对象/链接/标签种类总量成倍增长（0x..8x）的图，断言祖先核对计数在
全族上恒定，且恒等于实际扩展的链接数（每跳恰好一次）。
