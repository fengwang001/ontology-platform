# 属性权限随类型版本迁移联动：设计说明

## 目标与边界

本实现提供一个进程内线性化网关，模拟对象类型版本、属性 lineage 与属性级权限的联动。它重点保证判定语义和状态回滚，不依赖外部数据库或分布式事务。

每个属性同时有：

- `Identifier`：请求中使用的当前名字，可因弹性重命名变化。
- `LineageID`：跨版本稳定的标识符，权限绑定该值。

因此“保留标识符延续”的重命名只替换版本结构中的 `Identifier`，不复制或移动权限；旧名字立即从当前版本索引中消失。

## 核心数据结构

- `TypeVersion` 保存版本号、当前属性列表和 `Identifier -> LineageID` 索引。
- `typeState.attrPolicy` 是版本化权限快照：版本 -> 主体 -> `LineageID+操作` -> 状态。
- `typeState.typePolicy` 是版本化类型权限快照：版本 -> 主体 -> 操作 -> 状态。
- `attrHistory` 与 `typeHistory` 是只追加审计事件，不参与线上权限判定。
- 对象值以 `LineageID` 为键存储，重命名后原值和权限自然延续，废弃字段不会出现在当前投影中。

## 演进规则

每次 `EvolveObjectType`：

1. 先在临时属性列表上执行重命名、废弃、收紧约束和新增。
2. 任一属性不存在、重命名目标冲突、约束非法时直接返回错误，不创建新版本。
3. 将当前版本的权限 map 深拷贝到新版本键。
4. 最后发布新版本号并追加不可变 `TypeVersion`。

授权和吊销只修改当前版本快照；历史版本快照不再改变。重新授权会在当前版本清除同一主体、lineage、操作上的吊销态，但不会改写历史版本和审计记录。

## 写判定

写路径顺序固定：

1. 对象存在性：不存在返回 `object_not_found`。
2. 提交版本必须等于当前版本，否则返回 `version_stale`，不检查权限、不触碰对象。
3. 对每个提交字段解析当前版本标识符，旧名或废弃名返回 `property_identifier_not_found`。
4. 逐字段独立计算权限；类型写授权在未吊销时覆盖字段，否则查看属性授权。
5. 应用类型统一写策略：
   - `reject_object`：只要任一字段无权限或被吊销，整次写入失败，状态零修改。
   - `ignore_field`：无权限字段进入 `Ignored`，其余字段正常写入。

写策略在类型创建时确定，`ConfigureWritePolicy` 拒绝同时选择两种策略。为了保持版本语义清晰，策略修改是一个独立的类型管理操作，不混入属性演进事务。

## 读判定与投影

读路径先检查对象和类型读吊销。类型读授权在未吊销时覆盖全部属性；否则逐属性独立查看属性读授权。没有任何可读属性时结果可以是空对象，而不是零值或掩码。投影只包含当前版本仍存在的属性：

- 不返回零值、`null` 或掩码。
- 不以投影后的对象重新执行 required schema 校验。
- 当投影因权限而移除字段时，结果标记 `PartialView=true`。
- 对象本来未存储的字段不会被误报成权限移除。

显式类型级读吊销返回 `type_permission_denied`；普通缺少类型读授权不会提前短路，因为同一对象上仍可能存在属性级读授权。

## 吊销优先与版本并集

同一主体、属性、操作在多个版本中的授权由版本快照天然形成版本区间并集。每个快照只保存该版本的最终状态；某版本若被吊销，状态为 `revoked=true, allowed=false`，即使相邻版本已授权，该版本仍判无权限。

选择物化快照而不是线上扫描区间，有三个原因：

- 判定不需要归并区间或处理重叠/空洞。
- 历史版本不会被后来的授权/吊销意外改写。
- 演进时复制当前权限即可保持 lineage 延续。

## 线性化与失败原子性

网关使用一个容量为 1 的 channel 作为全局互斥临界区。所有版本演进、授权、吊销、对象写入和读取都在获取该锁后执行，读访问的是发布后的不可变版本和 map 快照，因此并发结果等价于某个全局串行顺序。

写路径在修改对象前完成对象、版本、标识符和全部字段权限检查；失败路径直接返回，不执行赋值。类型演进也先构造临时数据，成功后才发布版本。

被放弃的方案：

- 每个对象一把锁：不能证明权限变更与类型演进的全局顺序，也可能出现跨类型交错的中间态。
- 读写锁：读期间若允许演进或授权修改 map，需要复杂的不可变引用协议；本任务规模更重视强语义。
- 每次扫描审计区间：语义直观但不满足规模无关的线上性能要求。

## 规模无关的性能证明

`PermissionView(type, subject, version)`：

- 通过 `versions[version-1]` 读取 1 个版本记录。
- 直接索引 `attrPolicy[version][subject]` 和 `typePolicy[version][subject]`，访问当前版本的主体权限 map。
- 不读取 `attrHistory` 或 `typeHistory`，也不遍历其他版本。

返回值显式给出：

- `AccessedVersionRecords=1`
- `AccessedPermissionRecords=0`

这里的“历史权限记录”指只追加审计事件；当前版本快照是判定索引，不计作历史记录扫描。除了构造返回视图时枚举该版本当前属性外，历史版本数和历史权限事件数都不会出现在访问路径中，因此访问的历史记录数量为与规模无关的常量。

写判定同样只访问当前类型版本、当前对象和当前版本权限快照，不扫描历史版本或审计事件。

## 错误分类

- `object_not_found`
- `version_stale`
- `type_permission_denied`
- `property_identifier_not_found`
- `permission_revoked`
- `attribute_permission_denied`
- `write_policy_conflict`
- `invalid_input`

所有业务错误使用 `*ontology.Error`，通过 `Kind` 字段区分，调用方不应解析错误文案。

## 判定日志

每个公开操作记录 `DecisionLogEntry`，包含动作、输入、输出、依据和错误。测试通过 `WithDecisionLogHook` 将日志打印到 `t.Logf`。写日志的 `Reason` 包含判定顺序、类型权限、允许字段、拒绝字段、吊销字段和类型策略。

## 本地验证

建议使用：

```bash
GOCACHE=/tmp/ontology-go-cache go test -race -v ./...
GOCACHE=/tmp/ontology-go-cache go vet ./...
```

重点测试：

- 重命名后旧名失败、新名继承权限。
- 废弃后线上授权失败但审计记录仍存在。
- 吊销覆盖授权并集，且不会追溯删除此前合法值。
- `reject_object` 拒绝后对象状态不变。
- `ignore_field` 只跳过无权限字段。
- 随机操作序列与独立朴素模型对照。
- 并发测试加 `-race` 验证线性化实现无数据竞争。

朴素模型故意每次扫描全量事件和版本，只作为测试 oracle；不要在生产路径使用。
