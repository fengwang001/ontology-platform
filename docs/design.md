# 动态标签属性级权限模块 — 设计说明

## 问题与模型

对象实例是否携带某个敏感标签，由该实例若干属性的**当前取值**按声明的
判定规则实时计算得出。标签携带状态是每次判定时按需重算的结论，系统中
不存在任何持久化的标签状态或标签缓存，因此"属性值已更新但标签状态未
更新"的中间态在构造上就不可能存在——这是本设计最根本的取舍：

> **派生状态不落盘。** 持久化的只有属性值的版本历史；标签、权限结论
> 永远是读取路径上的纯函数 `f(属性值@快照, 规则集, 授权表)`。

## 核心机制

### MVCC 与快照（可重复读）

- 全局提交时钟 `clock`（uint64），每次成功写入 `clock++` 并把所有变更
  属性以 `(version, value)` 追加到各自的版本链。
- 快照 = 创建时刻的时钟值。快照 `s` 上读属性 `a` = `a` 的版本链中提交
  版本 `<= s` 的最后一条记录。该规则只依赖时钟值，与并发写入的交织
  方式无关，因此确定且可复现。
- 垃圾回收：每条版本链保留最近 `keepVersions` 个版本外加一条"基底"
  记录；可读水位 `lowWater` 取各链基底版本的最大值（单调不减）。版本
  低于水位的快照报 `SnapshotExpired`。

### 原子性与可线性化

全部操作（写、规则变更、授权表变更、各快照下的读）在同一把互斥锁下
串行化。权限判定先于 `clock++`，被拒绝的写入不推进时钟、不改任何值。
任意并发调用的结果因此必然等价于某个串行顺序。

### 判定规则与求值

- 规则是表达式树：`Attr`（属性引用）、`TagRef`（引用其他标签的携带
  状态）、`Const`、比较/逻辑运算。
- `And`/`Or` **不短路**：求值路径不依赖属性取值，既消除了经求值形状
  推断取值的侧信道，也让单次判定的属性读取数成为静态可界定的量。
- 单次判定内对标签结果做备忘（`TagRef` 共享子图只求值一次）。
- 求值类型错误按"不携带"处理，错误细节（可能携带着值信息）不向外
  传播。

### 冲突合并规则（确定、顺序无关）

对主体在某属性上的最终结论：

1. 实例未携带任何标签 → 允许（标签只施加限制）；
2. 任一携带标签的适用授权为 `Deny` → 拒绝（deny-wins）；
3. 否则任一适用授权为 `Allow` → 允许；
4. 携带了标签但无任何适用授权 → 拒绝（封闭世界）。

合并输入是"携带标签集合 × 适用授权集合"，不含任何顺序信息，因此
结论与规则求值顺序、授权登记顺序均无关（测试以两种相反登记顺序
验证全部 3×3 组合）。

### 防泄漏

判定规则始终基于属性**真实取值**求值，与发起主体的可读权限无关；
但判定结果只有允许/拒绝二值，错误信息为静态字符串，判定日志不记录
任何属性取值。测试断言日志全量字段中不出现秘密取值。

### 错误类别与固定优先级

`UnknownAttribute` > `CyclicDependency` > `SnapshotExpired`。
规则集在 `ReplaceRules` 时整体校验（全量校验、原子替换、失败无副
作用）；读取路径上未知属性检查先于快照解析。多错误同时成立时按
上述唯一优先级汇报。

### 判定开销的可观测证明

`TagState`/`Decision` 暴露 `AttrReads` 计数：一次标签判定实际读取的
属性数量。测试证明：登记 100 条无关规则前后，同一判定的 `AttrReads`
不变，且等于该规则（含 `TagRef` 传递闭包）静态引用的属性数。这给出
了不依赖实现细节的可观测证据：开销只与实际参与判定的属性数量相关。

## 被放弃的方案

- **标签状态物化 + 写入时失效**：写入路径需要反向索引"属性 → 引用它
  的规则"，且物化值与快照语义冲突（旧快照需要旧标签状态，等于又引入
  一套标签的 MVCC）。复杂度远高于按需重算，还被需求明确禁止（不得
  依赖可能过期的缓存值）。
- **读写锁分离（读路径 RWMutex 读锁）**：判定日志是每次调用的必需
  副作用，读路径也要写日志，读锁收益不成立；单互斥锁更简单且显然
  可线性化。若未来读远多于写，可先把日志改为无锁通道再评估。
- **短路求值**：省下少量属性读取，但让求值路径依赖取值（侧信道），
  且使 `AttrReads` 变成数据相关的量，削弱开销证明的确定性。
- **许可优先（allow-wins）合并**：任一标签误配 `Allow` 即可绕过其他
  标签的拒绝，不满足敏感标签场景的安全直觉；deny-wins 是行业标准。

## 本地验证方法

```bash
go test ./ontology          # 单元测试：翻转/快照/合并组合/错误优先级/开销/防泄漏/日志
go test -race -v ./ontology # 竞态检测 + 并发快照稳定性
go test -run TestDifferential ./ontology  # 与朴素参照实现的随机差分对照
go vet ./ontology && gofmt -l .
```

差分测试在 12 个随机种子 × 1500 步随机操作序列（写入/快照/规则变更/
授权变更/GC/读取）上，将引擎输出与独立编写的朴素参照实现逐项对照。
