# 事件溯源孤儿追溯判定子系统 — 设计说明

## 1. 问题与目标

本体平台需要以事件溯源方式重建"对象 + 链接"网络在任意历史时刻 `T` 的状态，
并在重建中回答一个追溯性问题：对象 `o` 在 `T` 时刻是否**实质上已成孤儿**——
按级联清理规则，其全部必需链接被撤销后本应被级联处理，但事件流中并不存在
明确记录这次级联处理的事件。规则本身允许版本调整，且调整可以追溯适用于
更早的历史时刻，因此判定不能只看事件流表面记录。

## 2. 概念模型

- **事件流**（`Event`）：仅追加。类型含链接类型创建、对象创建、属性赋值、
  链接建立、链接撤销、显式孤儿标记（`EvObjectMarkedOrphan`，即级联清理流程
  留下的记录）。每条事件带历史时刻 `Time`、可选因果前驱 `After`、存储分配的
  追加序号 `Seq`。
- **规则版本账本**（`RuleVersion`）：`RuleSpec` 声明各对象类型的必需链接类型
  与宽限期 `GracePeriod`；每次调整产生新版本，可声明 `Retroactive`。
- **判定**（`Determine(Query{Object, At, Version})`）：纯函数式输出
  `Determination`，不改动事件流与账本。

## 3. 关键语义规定

### 3.1 历史时刻的规则版本治理（核心取舍）

**规定**：历史时刻 `T` 的孤儿判定整体依据"治理 `T` 的规则版本"
`G(T) = 满足 (EffectiveFrom <= T 或 Retroactive) 的最新版本`。

- 非追溯版本只治理 `[EffectiveFrom, 下一版本 EffectiveFrom)` 内的时刻；
- 追溯版本治理其生效时刻之前的全部历史，并作废先前版本对历史的治理权；
- 判定请求必须显式声明依据版本；声明版本不等于 `G(T)` 时报
  `ErrRuleVersionVoided`；
- 该规定对所有 `T` 方向一致，且 `G(T)` 只取决于账本内容，与请求发起的
  物理时间无关——同一 `(T, Version)` 在调整前后重复判定，结论完全一致
  （幂等性由"判定是纯函数 + 线性化快照"共同保证）。

### 3.2 孤儿判定算法

在对象 `o` 的相关事件切片（`Time <= T`）上按 `G(T)` 的 `RuleSpec` 重放：

1. 跟踪活跃必需链接集合（仅 `From == o` 且类型必需的链接计入）；
2. 曾建立过必需链接、且当前全部撤销时，记归零起点 `zeroSince`
   （避免"空真"：从未建立过必需链接的对象永不成孤）；
3. `orphanDue = zeroSince + GracePeriod`；`orphanDue <= T` 时本应成孤；
4. 归零区间内重新建立必需链接会中断区间，再次撤销以新区间起算。

### 3.3 追溯孤儿的呈现规则

| 状态 | 含义 |
| --- | --- |
| `NotOrphan` | 规则不要求成孤 |
| `OrphanConfirmed` | 本应成孤，且事件流在 `zeroSince` 之后存在显式 `EvObjectMarkedOrphan` |
| `RetroOrphanDormant` | 本应成孤，无显式标记，且 `orphanDue` 之后无任何正常活动 |
| `RetroOrphanWithActivity` | 本应成孤，无显式标记，但 `orphanDue` 之后（`<= T`）仍发生属性赋值或新链接建立；结论中逐条列出这些活动 |

`RetroOrphanWithActivity` 与 `OrphanConfirmed` 是不同状态：前者表示
"追溯上应孤但实际仍在被使用"，绝不与真正被级联清理过的孤儿混同。
恰好落在 `orphanDue` 时刻的活动不算"之后"（严格大于）。

### 3.4 错误分类与优先级

| 优先级 | 错误 | 触发条件 |
| --- | --- | --- |
| 1 | `ErrRuleVersionVoided` | 声明版本在判定的线性化点已不治理 `T` |
| 2 | `ErrAmbiguousOrder` | 同刻并列事件触及同一实体且无 `After` 链定序 |
| 3 | `ErrDanglingReference` | 切片引用了尚未创建的链接类型/对象/链接 |
| 4 | `ErrTimeBeforeFirstAppearance` | `T` 早于对象首次出现 |

同一请求同时具备多类条件时只报优先级最高者。任何错误都不会对事件流
或规则账本产生可观察改动（判定全程只读；审计日志是独立设施）。

**检查范围（取舍）**：`Determine` 的错误检查范围是与该对象相关的事件切片
（这是复杂度保证的前提）；`RebuildNetwork` 检查 `Time <= T` 的全量前缀。
无法归属到任何对象的悬置撤销（撤销从未创建的链接）只会在全量重建时报告。

**同刻歧义的判定规则**：同刻事件只有**触及共同实体**（同一对象/链接/链接
类型）时才需要定序——不同实体的事件可交换，不影响重建结果。定序依据是
组内 `After` 链的传递闭包。

### 3.5 并发与线性化

`Store` 用单一 `sync.RWMutex` 保护全部状态：追加、规则调整持写锁，
判定/重建持读锁。每个操作在锁内原子完成，因此任意并发操作集合的可观察
结果等价于按锁获得顺序串行执行（可线性化）。全局操作序号 `opSeq` 标记
每个操作的线性化点；规则版本记录其 `CreateSeq`，审计记录携带判定的
`Seq`，使得"判定时声明版本是否已被作废"可在事后精确复核
（见 `TestConcurrentMixedOperationsLinearizable`）。

### 3.6 复杂度保证

追加事件时维护**按对象的增量索引**（每个对象只挂自己的相关事件；
链接事件挂在两个端点对象下，自环去重；撤销事件经链接元数据归属，
链接未创建时暂存并在创建时补挂）。`Determine(o, T, v)` 只扫描 `o` 的
自身事件，开销为 `O(o 自身事件数)`，与网络累计链接创建/撤销事件总量无关。

**独立验证方式**：每次判定输出 `EventsScanned`（实际检视条数）并写入审计
日志；`TestDetermineCostIndependentOfNetworkSize` 在填充对象 0/100/1000/
10000 四种规模下断言 `EventsScanned` 与判定结论完全不变；
`BenchmarkDetermine` 显示网络总量增长 100 倍时单次判定耗时近似平坦
（本机实测 ~690ns → ~640ns）。

### 3.7 审计

每次判定（无论成败）追加一条 `AuditRecord`：查询输入、声明版本、
判定时治理版本、结论状态或错误码、`EventsScanned`、线性化序号。
审计日志独立于事件流与规则账本，供事后核查与对照。

## 4. 被放弃的方案

- **按撤销事件逐个适用规则版本**（非追溯=只约束调整后的撤销）：
  当必需性定义在两次版本间变化时，同一次判定要混用多个版本解释同一条
  事件流，归零区间的定义变得含糊，且难以保证幂等。放弃，改为以"历史
  时刻"为治理粒度（§3.1），语义单一、可穷举测试。
- **MVCC 多版本快照**：为每个版本调整保留事件流快照。内存开销随版本数
  线性增长，而单锁 + 纯函数判定已满足线性化与幂等，无需引入。
- **向量时钟/混合逻辑时钟**：完整因果追踪对"同刻并列"判定是过度的；
  采用单前驱 `After` 链 + 实体冲突检测即可表达所需的定序信息。
- **追加时即校验引用/顺序**：会使四类错误无法在重建时按优先级统一报告，
  且写入路径与查询路径语义耦合。放弃，写入仅做 ID 唯一性校验。
- **全量前缀作为判定检查范围**：会使单次判定开销随网络总量线性增长，
  直接违反复杂度要求；改为按对象切片（§3.4）。

## 5. 测试策略

- `boundary_test.go`：追溯/非追溯两种调整 × 查询时刻在调整前/后 × 声明
  新旧版本的穷举矩阵；宽限期边界；重链接中断区间；空真防护；幂等性。
- `presentation_test.go`：追溯孤儿四种呈现状态及活动列表、网络重建输出。
- `errors_test.go`：四类错误各自触发、两两组合时只报高优先级、
  错误无副作用、审计覆盖。
- `differential_test.go`：300 个随机种子的操作序列（追加/调整/判定混合），
  引擎结果与独立朴素重放模型（`orphan/naive`，不共享判定逻辑）逐条对照。
- `concurrency_test.go`：`-race` 下并发判定结果一致；混合并发操作的
  审计记录通过线性化点复核。
- `complexity_test.go`：`EventsScanned` 不变量 + 基准测试。

## 6. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin   # Go 1.26+
go test ./...                          # 全量测试
go test -race ./orphan/...             # 竞态检测
go test ./orphan/ -run TestDetermineCostIndependentOfNetworkSize -v  # 复杂度不变量
go test ./orphan/ -bench=BenchmarkDetermine -benchmem -run=NONE      # 复杂度基准
go run ./cmd/server                    # 端到端演示
gofmt -l . && go vet ./...             # 格式与静态检查
```
