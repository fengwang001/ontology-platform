# 受权限约束的图遍历环检测服务 — 设计说明

## 1. 问题与目标

本体平台上，链接（对象之间的有向边）附带权限标签。调用方仅持有一个
标签集合，只能看到标签命中的链接；对未命中标签的链接及其连接对象
“完全不可感知”。遍历服务需要在这一可见性约束下做环检测，但：

- 环判定必须基于**完整图**，不能只在可见子图上判定，否则会放过
  “只能借助隐藏链接闭合”的真实环路。
- 返回内容必须严格做信息隐藏：不可见链接的 ID、标签、连接对象标识
  一律不得出现在结果中；只允许在可见前缀边界给出聚合性标记。
- 对同一条完整图真实环路，所有调用方（只要能观察到其前缀）必须得到
  一致的“成环终止”结论，不因权限不同而出现成环/不成环的分歧。

## 2. 核心模型与取舍

### 2.1 图与可见性

- 图为有向图；`Link{ID, From, To, Label}`，对象为字符串 ID。
- **链接可见**：`link.Label ∈ caller.Labels`。
- **对象可见**：该对象是至少一条可见链接的端点（`incident` 索引）。
  对象本身不另设独立可见性属性，避免“双事实源”不一致。
- 起始对象对调用方不可见，等价于它不与任何可见链接关联。

### 2.2 两类判定分离

服务内部把两件事彻底分开：

1. **完整图环判定（权限无关、权威）**：沿完整图游走，只要某跳目标命中
   当前游走祖先序列，即判定真实环路并终止该方向。环判定先于深度截断
   （深度边界上闭合的最后一跳仍是环）。
2. **可见性投影（权限相关、仅影响返回形态）**：把完整图结论翻译成
   调用方可接收的路径与标记。

因为环判定从不读取调用方标签，所以同一完整图路径对所有调用方的
“是否成环”结论天然一致；标签只改变调用方能看到前缀的长度。

### 2.3 四种路径判定

| Verdict | 含义 |
| --- | --- |
| `NonCyclic` | 完全可见且完整图上不成环，正常返回完整路径 |
| `VisibleCycle` | 完全可见，末跳在完整图上闭合真实环 |
| `HiddenCycle` | 可见前缀之后的不可见延伸在剩余深度内闭合真实环，止于边界 |
| `PartialInvisible` | 可见前缀后存在不可见延伸，剩余深度内不闭合，成环未知 |

`HiddenCycle` 与 `PartialInvisible` 是两类**不同**标记，绝不混用：
前者是权威的成环终止；后者只是“此处有不可见延伸，是否成环未知”。

### 2.4 为什么在“可见前沿节点”上做聚合

若对每条不可见出边各返回一条结果，就会向调用方泄露隐藏链接的数量、
各自去向等超出“存在性”的信息。因此规定：

- 遍历只沿**可见链接**枚举路径。
- 在每个可见前沿节点，对“所有首跳不可见的延伸”做**一次聚合判定**：
  - 任一延伸在剩余深度内闭合真实环 ⇒ 该前沿给 `HiddenCycle`；
  - 否则只要存在不可见出边 ⇒ 给 `PartialInvisible`；
  - 不存在不可见出边 ⇒ 无隐藏标记。
- 同一“前沿节点 + 可见前缀”至多一个隐藏标记，标记中不含任何
  隐藏链接/对象字段。

不同可见前缀到达同一前沿节点时，前缀本身是可见信息，分别保留
（按“前沿 + 完整前缀”聚合）。

### 2.5 深度语义

`MaxDepth` 为允许经过的最大跳数（正整数）。

- 第 d 跳在 `d ≤ MaxDepth` 时可完成。
- 环判定优先：即使该跳恰好用满深度，只要闭合祖先仍是真实环。
- 到达深度上限的可见末端：无隐藏出边则记 `NonCyclic`；有隐藏出边时
  因已无剩余跳数可闭合，记 `PartialInvisible`（不误报环）。

## 3. 快照一致性

`GraphStore` 采用 **copy-on-write + 不可变快照**：

- 图结构（对象、链接）与权限标签（`Link.Label`）同处一个状态对象；
  任何修改（加边/删边/改标签）都在锁内整体替换状态并令版本号 +1。
- 遍历开始时取一次 `Snapshot()`，之后所有读取都落在该不可变快照上，
  结构与标签**物理上来自同一时点**，不可能“结构取自一个版本、标签取自
  另一个版本”。
- 存储保留历史版本（`SnapshotAt(version)`），测试据此回放遍历声称
    绑定的版本，与该版本上的朴素实现逐条核对。

并发进行中的遍历继续持有旧快照，天然快照隔离，无需长事务或 MVCC 额外
设施。

## 4. 性能不变量与可验证方式

要求：单次遍历中用于完整图环判定的“祖先序列核对”次数，不随图中
对象、链接、权限标签种类总数增长而线性增长。

实现方式：

- 环判定原语是对“当前游走祖先哈希集合”的 **O(1) map 查询**，
  从不对全图对象或全部标签做线性扫描。
- 计数器 `AncestorChecks` 只在该 map 查询处递增，可在日志与返回中核对。
- 隐藏区探索成本只取决于**剩余深度与隐藏区分支**，与全图总量解耦；
  这是为判定隐藏环所必须触及的最小集合。

可复现证明（`TestAncestorChecksIndependentOfTotalSize`）：固定与遍历
相关的小可达子图，把完全无关的对象、链接从 16 放大到 8192（标签种类
从 3 增到 514），断言核对次数恒定。`go test -v` 会打印每档的
objects/links/labelKinds/checks 对照表。

## 5. 错误与判定次序

四类错误互斥，按固定次序只报第一类（见 `Service.traverseSnapshot`）：

1. `ErrStartNotFound`：起始对象不存在；
2. `ErrEmptyLabels`：调用方权限标签集合为空；
3. `ErrInvalidDepth`：深度上限非正整数；
4. `ErrStartNotVisible`：起始对象对调用方完全不可见。

次序由代码顺序硬性固定，并由 `TestErrorPrecedence`（含组合冲突用例）
锁定。

## 6. 被放弃的方案

- **只在可见子图上环检测**：直接违反“不得放过隐藏链接闭合的真实环”，
  否决。
- **对每条不可见出边各返回一条隐藏结果**：会泄露隐藏边数量与去向，
  违反“只允许告知存在性”，改为前沿节点单标记聚合。
- **对象独立 ACL + 链接标签两套可见性**：产生双事实源，容易不一致；
  统一为“可见链接端点即可见”。
- **遍历中实时读当前图并加锁**：结构与标签可能跨时点、且长读阻塞写；
  改为单次不可变快照。
- **环判定用祖先数组线性查找**：核对成本随路径/全图线性增长；改为
  O(1) 祖先哈希集合，并以计数测试锁死该不变量。
- **隐藏区做全图环分析（SCC 等）后再裁剪**：会触及大量无关结构且可能
  间接泄露信息；改为从前沿出发、受剩余深度约束的最小探索。

## 7. 本地验证方法

```bash
# 需 Go 1.26+（本仓库 go.mod 要求）
go test ./...
go test -race -v ./...

# 只看性能不变量对照表
go test -run TestAncestorChecks -v ./...

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

测试文件与覆盖点：

- `service_test.go`：隐藏环终止与信息隐藏、PARTIAL 与 CYCLE 共存、
  多权限交叉一致性、错误次序、完全可见非环路径、日志依据。
- `differential_test.go`：400 组随机图/标签/深度上与朴素实现逐条对照。
- `snapshot_test.go`：结构与标签并发修改的快照一致性、固定快照抗污染。
- `performance_test.go`：祖先核对次数相对全图总量的不变量复现。
