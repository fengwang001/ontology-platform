# 专业技术职称评审会务服务 — 设计说明

## 1. 范围与总体取舍

本服务（Go 包 `review`）管理一次职称评审从评委抽取、分轮表决、
中途回避替补、结果宣布、公示异议到终局生效的完整生命周期。

核心设计目标按优先级排列：

1. **唯一、可精确复现**：评委构成在任何输入下只有一个确定结果；
   票决门槛用整数精确表达，不依赖浮点。
2. **留痕可还原**：每一票、每一版评委构成、每一次结算都不可变保存，
   可按任一历史版本还原当时有效票集合。
3. **并发等价于串行**：所有修改在同一把互斥锁内原子完成。
4. **失败零副作用**：被拒绝的操作不改变任何状态，也不推进服务时钟。

## 2. 领域模型

- `Reviewer{ID, Unit, Group}`：评委编号、单位、专业组。
- `Applicant{ID, Unit}`：申报人。
- 回避事实按申报人增量保存为三个集合：
  - `relations`：登记的直接亲属/师生关系（每次调用建立一条直接边，
    双向语义在"申报人→评委"方向落地；题目限定直接关系，不做传递闭包）；
  - `requests`：已受理的回避申请；
  - `autoAvoid`：该申报人以往**已作废**评审中任过评委的人。
  - 同单位回避在查询时用单位相等即时判定。
- 评委对申报人须回避，当且仅当四条来源命中任一（`recusalSources`）。

评审状态机：

```
投票中(第一轮) ──通过/不通过──▶ 公示中 ──(期满且异议不成立)──▶ 终局通过/不通过
     │ 复议带                    │
     └─▶ 投票中(复议) ───────────┤
                                   └──(异议成立)──▶ 作废（原评委进入 autoAvoid）
任何投票阶段发生无法替补的回避 ──▶ 中止
```

## 3. 关键决策

### 3.1 抽取唯一性：字典序最小的贪心

要求：全部无需回避、恰为 n（奇数）人、各专业组不低于下限；
在所有可行集合中，编号升序排列后**字典序最小**者唯一。

算法（`selection.go`）：将可行候选按编号升序排列，逐个决定取/不取。
取当前编号 x 时，先用"各组后缀候选计数"判断剩余名额是否还能补齐
（总数与每组下限同时检查）；能补齐就取 x，否则跳过。
后缀计数一次预处理，每次决策 O(组数)，整体 O(K log K + K·G)。

正确性要点：字典序最小集合的第 i 个元素，正是"取了它之后仍存在解"
的最小候选；可行性判定只依赖后缀计数，故贪心无回溯且结果唯一。
测试中以独立的组合全枚举暴力模型（`brute_test_helper_test.go`）
对随机库配置交叉验证两者结果一致。

### 3.2 抽取成本不随历史评审总数增长（可验证）

回避前科**不**通过遍历历史评审计算，而在评审作废时增量写入
`applicantState.autoAvoid` 这一 map；抽取时对每位候选只做 O(1) 查表。
因此抽取只遍历当前评委库（K 人），与 `reviews` 的大小无关。

可验证方式有两层：
- 结构性：`drawPanel` 的调用链不读取 `s.reviews`，评审对象也不
  反向参与回避判定（同单位/关系/申请/前科全部在申报人侧）。
- 行为性：`TestDrawCostIndependentOfHistory` 向 `autoAvoid` 注入
  0 条与 1000 条"前科"，两次抽取同规模面板，断言耗时无数量级劣化，
  且结果在大量前科堆积后仍确定为最小可行编号段。

### 3.3 票决门槛（整数精确表达）

设总人数为 n（始终奇数），赞成数为 a。弃权计入 n、不计 a。

- 第一轮：
  - 通过：`a ≥ ⌈2n/3⌉`（`ceilDiv(2n,3)`）；
  - 不通过：`a ≤ ⌊n/2⌋`；
  - 否则进入复议。
  三段互不重叠且覆盖全部整数（奇数 n 下 ⌊n/2⌋ < ⌈2n/3⌉）。
- 复议：`2a > n` 为通过（严格过半），否则不通过。

每次结算在 `RoundResult.Reason` 留下与公式一一对应的判定依据，
例如"第一轮：赞成 3 ≤ floor(5/2)=2 不成立且 3 < ceil(10/3)=4，进入复议"。

### 3.4 中途回避、替补与版本

- `HandleRecusal` 仅在投票阶段受理；评委须此刻确实命中回避来源。
- 退出者全部已投票置 `voided`（记录不删除），并释放其占用。
- 替补仍遵循"保持其余评委不变、整组满足下限、替补编号最小"的
  唯一性：若剩余面板在离组上已不缺额，替补可取任意组的最小可行者；
  否则替补必须来自离组。这正是题目替补规则的精确化，且结果唯一。
- 每次替补生成一个不可变 `PanelVersion`；评委加入时记录其版本号。

**已宣布结果不会在投票阶段被推翻**：投票阶段唯一"已完成一轮"的
情形是第一轮落入复议（此时尚未宣布）。此时回避退出会：
1. 推翻该第一轮结算（`Superseded=true` 留痕）；
2. 回到第一轮，只等替补补投；其余评委的票仍然有效，无需重投；
3. 重结算后若再入复议，开启复议的新一"幕"（episode）。

"幕"是为了让"同一评委在新一轮重新投票"与"一轮一票不可改"共存：
旧复议幕的票全部留痕但不参与新幕结算，评委在新幕可再次投票，
不被判重复投票。题目要求"复议由全体评委重新投票"，该机制精确满足。

**票补齐前不得宣布**：结算只在当前轮有效票数 == 当前面板人数时
自动触发，因此替补未投票前，任何轮次都不会产生新结果。

### 3.5 按历史版本还原有效票

`EffectiveVotesAtVersion(rid, version, round)` 规则：
投票者属于该版本名单即可计入。退出者的票在其退出时刻之后的版本中
因"人已不在名单"自然排除；在其仍在组的历史版本中，票按当时事实
有效。老评委的票跨版本延续，替补者投的票带其加入版本号。
这保证"按任一版本可还原当时有效票集合"，且历史版本永不被改写。

### 3.6 公示与异议

- 宣布时刻 `t0` 即最后一票（触发结算）时刻；公示区间为
  `[t0, t0+7×24h)`——整整七个自然日，**结束时刻本身不再受理异议**
  （`at.Before(end)` 为受理条件）。
- 受理、裁定、终局三者互斥且各只发生一次：
  - 受理后未裁定，期满也不得终局；
  - 裁定不成立，结果在 `t0+7d` 这个时刻方生效（恰好等于即可）；
  - 裁定成立，评审整体作废，当前版本全体评委写入 `autoAvoid`，
    对该申报人以后的任何抽取自动回避。
- 终局前的结论一律称"待生效"，任何时刻都可从状态读出，不提前暴露为终局。

### 3.7 错误优先级与零副作用

错误类别及判定顺序固定为：
参数非法 → 时钟回退 → 申报人或评审不存在 → 状态不允许 →
无权限 → 评委不足 → 重复投票。

实现上每个操作严格按此顺序短路返回。关键细节：
- `checkClock` **只比较不写**，操作通过全部校验、即将落盘时才
  `advanceClock`，因此被拒绝操作不会推进时钟（`TestRejectedOperationChangesNothing`）。
- 投票路径中"非本评审评委"（含编号在评委库中不存在）统一报
  无权限，且该判定在重复投票之前，与题目"非本评审评委投票报无权限"
  及优先级一致。
- 抽取失败发生在任何占用写入之前，故"评委不足不占用任何评委"。

### 3.8 并发模型

单一 `sync.Mutex` 串行全部读写操作。操作粒度小、无 IO、无回调重入，
不存在持锁等待，故不会死锁。所有时间戳由调用方提供并做单调校验：
多个操作允许使用同一时刻（只拒绝严格回退），因此并发调用方无需
协调时间先后即可得到合法交错；结果等价于某个串行顺序，且因
抽取/结算均确定，相同操作序列重放结果完全相同
（`TestReplayDeterminism`、`TestConcurrentEquivalentToSerial`）。

## 4. 被放弃的方案

- **为每位评委做关系图传递闭包**：题目明确关系仅限直接关系，
  传递闭包既超范围又易引入歧义，放弃。
- **回避时扫描全部历史评审推断前科**：成本随历史评审数增长，直接
  违背性能约束；改为作废时增量写集合。
- **用浮点 `float64(a)/n` 与 2/3、0.5 比较**：在边界上有舍入风险，
  改为纯整数比较（`3a≥2n`、`2a>n`），并用 `ceilDiv` 表达"三分之二
  向上取整"。
- **回避后要求全体评委重新投当前轮**：题目只规定票作废与替补补投；
  让未退出评委重投会破坏"一轮一票不可更改"。故仅替补补投，
  旧票延续有效；第一轮已被宣布的情形在本状态机中不存在（见 3.4）。
- **把多幕复议建模成两条独立评审**：会割裂留痕与版本连续性；
  用 episode 在同一评审内隔离旧幕，更贴合"重新投票但同一评审"。
- **乐观锁/CAS 提升并发**：本服务操作轻量，单锁最简单且足以满足
  "可串行化"要求，复杂度不值得。

## 5. API 一览

| 方法 | 说明 |
| --- | --- |
| `AddReviewer` / `AddApplicant` | 登记评委 / 申报人 |
| `RegisterRelation` | 登记直接亲属/师生关系（对称、仅直接） |
| `AcceptRecusalRequest` | 受理回避申请 |
| `IsRecused` | 查询是否回避及命中来源 |
| `CreateReview` | 唯一抽取并创建评审（失败不占用） |
| `Vote` | 当轮投票（票齐自动结算） |
| `HandleRecusal` | 中途回避退出 + 唯一替补（无法替补则中止） |
| `AcceptObjection` | 公示期内受理异议（结束时刻不受理） |
| `AdjudicateObjection` | 异议裁定（成立作废/不成立待期满） |
| `Finalize` | 公示结束时刻终局生效 |
| `GetReview` / `Versions` | 状态快照 / 全部历史版本 |
| `VoteRecords` | 每位评委每一票的留痕（含作废、旧幕） |
| `EffectiveVotesAtVersion` | 按历史版本还原当时有效票集合 |

所有写操作第一个有效参数均为调用方提供的时间戳（单调，只许前进）。

## 6. 本地验证方法

```bash
# 环境：Go 1.26.5（/usr/local/go/bin）
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/go-cache   # 本机默认缓存目录只读时使用

# 全量测试 + 竞态检测
go test -race -count=1 ./...

# 覆盖率
go test -cover ./...

# 静态检查与格式
go vet ./...
gofmt -l .

# 差分测试逐行日志（每步输入、两侧输出、判定留痕）
REVIEW_DIFF_LOG=1 go test ./review/ -run TestDifferential -v
```

测试覆盖（与需求条目对应）：

- 门槛边界：`TestSettleRound1Thresholds`（⌈2n/3⌉ 与 ⌊n/2⌋ 恰等/差一）、
  `TestReconsiderStrictMajority`（复议严格过半）；
- 弃权影响：`TestAbstentionCountedInTotal`；
- 回避四来源：`TestRecusalFourSources`；
- 替补补齐前不得结算、版本还原、推翻重开：
  `TestSubstitutionMidRoundAndVersionTrace`、
  `TestSubstitutionReopensSettledRound`、`TestNoSubstituteAborts`；
- 公示期末刻与异议互斥：`TestPublicityBoundaryAndObjectionMutex`、
  `TestObjectionNotAcceptedAtEndInstant`、`TestUpheldObjectionMakesReviewersAvoid`；
- 抽取唯一性：`TestDrawLexicographicallyMinimum`（对拍暴力枚举）、
  `TestDrawUniquenessAndRecusal`；
- 拒绝优先级与零副作用：`TestErrorPriority`、
  `TestRejectedOperationChangesNothing`；
- 并发等价：`TestConcurrentEquivalentToSerial`（`-race`）；
- 朴素模型随机差分：`TestDifferentialAgainstNaiveModel`
  （300 条随机操作序列，逐步比对返回、错误类别与最终全状态）；
- 重放确定性：`TestReplayDeterminism`；
- 历史无关性能：`TestDrawCostIndependentOfHistory`。
