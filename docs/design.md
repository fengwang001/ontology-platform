# 本体链接图分页遍历器 — 设计说明

## 1. 问题与语义

从单个起点对象出发，沿链接类型允许的方向做邻域扩展，返回对象分页：

- **深度上限 `MaxDepth`**：起点为第 0 层；到达 `MaxDepth` 的对象不再展开。
- **扇出上限 `MaxFanout`**：单个对象在某一层的“有效后继”按对象标识排序，
  只保留前 `MaxFanout` 个；被裁掉的后继在本次遍历的**任何一页**都不出现，
  也不能通过续读标记重新纳入。
- 两个上限彼此独立：扇出裁剪发生在每一层的展开上，深度裁剪发生在最后一层。

三态截断（`TruncationReason`）：

1. `complete`：限制下应纳入的对象已全部返回；
2. `fanout`：存在因扇出上限被排除的对象；
3. `depth`：无扇出裁剪时，边界对象在无深度限制下本有直接后继。

二者同时成立时只报 `fanout`（优先级 `fanout > depth > complete`）。

## 2. 关键取舍

### 2.1 固定遍历顺序：BFS，层内按对象标识排序

邻域结果在**任何分页开始之前**一次性计算成权威序列 `neighborhood.order`：

- 层顺序由 BFS 保证（深度小的先返回）；
- 同层按对象 ID 字典序，保证结果与链接插入顺序无关、确定可重放；
- 全局“首次出现”去重（多路径/环/平行链接只计一次）。

分页只是对该序列做窗口切片，续读标记记录偏移量。这样分页逻辑不可能
影响“哪些对象属于本次遍历”，也天然保证同标记重放得到相同结果。

**被放弃的方案**：每页惰性展开一层。问题是页大小与层边界不对齐时，
续读需要在“层内恢复迭代游标”，游标状态复杂且极易在并发变更下漂移；
而本任务的邻域规模本身被 `depth × fanout` 严格限制（见 2.5），
一次性计算的代价上界与单页相同，因此选择更简单可证的整序+切片。

### 2.2 MVCC 快照锚定续读标记

- `Store` 每次变更（增删对象/链接/类型）都通过**写时复制**产生一个新的
  不可变 `Snapshot`（单调 `epoch`）；历史快照保留在 `history` 中。
  变更在写锁内以“克隆当前 → 修改 → 提交”串行执行；读快照用读锁。
- 续读标记携带 `epoch`，续读时通过 `SnapshotAt(epoch)` 取回**标记生成时**
  的快照继续。之后的新增/删除既不混入结果，也不导致报错。
- 唯一的报错情形：锚定快照已不可追溯（被 `PruneHistory` 释放），
  或锚定快照中的起点不存在（`ErrTokenObsolete`）。
  起点在锚定快照**之后**被删除不影响续读。

**被放弃的方案**：标记只存起点 ID，续读时读当前图。该方案无法满足
“快照之后的增删不得混入”，在深度/扇出随图变化时甚至无法解释偏移量。

### 2.3 续读标记格式

`base64url(JSON{epoch,start,maxDepth,maxFanout,offset}).base64url(HMAC-SHA256)`：

- 载荷对调用者不透明但防篡改：HMAC 密钥在每个 `Traverser` 创建时随机生成，
  跨进程/跨遍历器的标记以及任何被修改的标记都在解析阶段得到
  `ErrTokenInvalid`（归入“参数非法”，拒绝次序最高）。
- 续读请求中 `MaxDepth/MaxFanout` 传 0 表示沿用标记内参数；
  显式传非 0 但与标记不一致按非法处理（不同参数的“续读”无定义）。

### 2.4 权限先于扇出

每个节点展开时先枚举候选边，依次应用：

1. 链接遍历权（`CanTraverseLink`）——无权限的链接当作不存在；
2. 目标对象存在性权限（`CanSeeObject`）——不可见对象当作不存在；
3. 已访问去重；

通过以上过滤的才计入扇出名额。因此不可见对象不可能挤占真实可见对象的
名额（对应回归测试 `TestPermissionDoesNotConsumeFanout`）。

拒绝判定次序严格为：

1. 参数非法（负深度/负扇出/空起点/标记格式不合法）；
2. 首次请求：起点无存在性权限 → `ErrForbidden`；
3. 续读请求：锚定快照缺失或快照中起点不存在 → `ErrTokenObsolete`；
4. 正常分页。

### 2.5 访问度量与“与总图规模无关”

`Metrics{ObjectsVisited, LinksExamined}` 只统计本次请求实际触达的对象
与链接。要让链接检查量不随节点总度数增长：

- 邻接表在**提交时按目标对象标识排序**（出边按 `to`、入边按 `from`）；
- 出/入两个有序序列在遍历时做二路归并，得到全局按目标 ID 有序的边流；
- 展开某节点时扫描到第 `MaxFanout+1` 个**有效后继**即停止
  （多扫的 1 个仅用于确认发生了扇出截断）。

被访问对象数上界为 `1 + F + F^2 + … + F^D`，链接检查量为
`O(F × 已访问对象数)`，即 O(`F^(D+1)`) 量级，与图中无关部分的规模无关。
`TestMetricsIndependentOfGraphSize` 在同一邻域外挂 0 与 3000 个噪声对象/
3000 条噪声链接，断言度量完全不变且满足上界。

## 3. 并发模型（可串行化）

- 所有变更互斥、原子提交新快照，等价于排成一个串行顺序；
- 首次遍历原子读取“当前快照”并把其 `epoch` 写入标记；
  因而同一标记在任何串行顺序中都锚定到唯一确定的时点，不会因并发请求
  而漂移（`TestConcurrentSameTokenReplay`、
  `TestConcurrentPaginationAndMutation` 在 `-race` 下验证）。

## 4. 与朴素模型的随机对照

`oracle.go` 是独立实现的朴素穷举模型：链接全部装在无序列表里，每次展开
全量扫描、全量收集后排序截断，与生产实现共享尽量少的代码。
`TestRandomDifferential` 在固定种子下生成 400 组随机配置
（对象数、正/逆/双向链接、ACL 隐藏对象与封禁链接、深度、扇出、页大小），
对两种实现逐页对照对象集合、顺序与截断原因，并校验：

- 分页拼接 == 朴素整序结果；
- 截断原因一致；
- 同一标记重放结果一致；
- 每次请求的输入/输出/续读标记/截断原因写入 JSON 审计日志
  （路径由 `ONTOLOGY_TRAVERSAL_LOG` 指定，缺省写入测试临时目录）。

## 5. 本地验证

```bash
go test ./...                 # 全量测试
go test -race ./...           # 含竞态检测
go test -v -run TestRandomDifferential ./ontology
ONTOLOGY_TRAVERSAL_LOG=/tmp/trav.json go test -run TestRandomDifferential ./ontology
go vet ./... && gofmt -l .
```

覆盖的边界：扇出/深度同时截断的优先级、快照跨变更稳定性、
权限不占扇出名额、起点在续读期间被删除、深度 0、扇出 0、
环与平行链接去重、正/逆/无向方向语义、标记篡改与参数不一致。

## 6. 已知取舍

- 快照为内存写时复制，历史版本会占用内存；`PruneHistory` 提供显式回收，
  被回收版本上的标记按 `ErrTokenObsolete` 拒绝。
- 链接代价 `LinkType.Cost` 已在模型中保留，当前上限按“跳数”而非累计代价；
  若后续需要代价受限遍历，应作为独立维度加入，避免与深度/扇出语义耦合。
