# 承运商运价合同：运费计算与结算系统 — 设计说明

## 1. 模块划分

系统按职责拆为五个包，依赖方向单向向下：

| 包 | 职责 | 不负责什么 |
| --- | --- | --- |
| `freight/model` | 领域类型（合同、运单、费用明细）、参数校验、稳定错误码 | 不做存储、不做计价 |
| `freight/store` | 合同集合、`(承运商,线路,等级)` 车道的时间区间索引、二分定位 | 不理解金额规则、不加锁 |
| `freight/pricing` | 纯函数计价：计费重量、累进阶梯、最低收费、三类附加费 | 不选合同、不持有状态 |
| `freight/ledger` | 每运单“最近报价”与“结算快照”，结算后金额固化 | 不关心合同如何变化 |
| `freight/system` | 对外门面：并发串行化、拒绝优先级、多承运商询价、操作日志 | 不重复实现计价规则 |

分层带来的直接好处：计价是无状态纯函数，可被朴素模型逐字段差分；结算语义集中在
`ledger`，“合同变更不改已结算金额”只需读懂一个结构体；并发正确性集中在 `system` 的一把锁。

## 2. 关键数据约定

- 时刻是离散整数 `model.Time`，不使用墙钟时间。生效区间统一为左闭右开 `[lo, hi)`，
  因此“取等”行为可精确测试：`lo` 命中、`hi` 不命中；相接 `[a,b)[b,c)` 合法且 `b` 命中后者。
- 重量统一为**克**（`int64`），尺寸统一为**毫米**，体积 = 长×宽（mm³），金额统一为**整数分**。
- 体积折算系数 `VolumeFactor` 的量纲是 mm³/克，例如 1000 表示 1cm³ 折算 1 克。
- 计重单位 `BillingUnit`（克）。重量阶梯各档边界必须以计重单位为刻度、首档从 0 开始、
  档与档首尾相接、末档上界为 0 表示 +∞。这些约束在参数校验阶段强制，保证累进计价没有
  “空档”或歧义。

计费重量规则（与主流物流口径一致）：

```
rawVolumeWeight = ceil(体积 / VolumeFactor)          // 克
volumeWeight    = ceil(rawVolumeWeight / 单位) * 单位
chargeable      = ceil(max(实际重量, volumeWeight) / 单位) * 单位
```

即“先比较实际重量与体积重量，再统一向上取整到计重单位”。

## 3. 计价规则

1. **承运范围判定先于一切费用计算**，且使用**实际重量**与**实际单边**，
   不使用体积重量/计费重量。`MaxSide == 0` 表示单边不限。
2. **累进基础运费**：计费重量落入各档的部分分别乘该档单价后求和，
   绝不“整体按所落档单价”。每档的计量单位数同样向上取整到计重单位，明细逐档输出。
3. **最低收费**：`baseAfterMinimum = max(基础运费, 最低收费)`，恰等时不提升。
4. **燃油附加费**：只作用于提升后的金额，`ceil(baseAfterMinimum * 千分比 / 1000)`。
5. **偏远附加费**：只看**终点区域**是否在清单内（定额）。
6. **两项超限附加费相互独立**：
   - 任一边**实际尺寸**严格大于单边阈值 → 收超大附加；
   - **计费重量**严格大于计费重量阈值 → 收超重附加；
   两条同时成立各收各的，阈值取等不触发。
7. 合计 = 提升后基础 + 燃油 + 偏远 + 超大 + 超重。

所有乘除都走 `math/big.Int` 做溢出检查，溢出按参数非法拒绝，而不是静默回绕。

## 4. 合同选择与拒绝优先级

合同选择只看**运单揽收时刻**，与计价调用时刻无关，因此补录历史运单也能复现当时费用。

- 运单计价（指定承运商）拒绝链固定为：
  **参数非法 → 无合同 → 时刻未覆盖 → 超出承运范围**。
  “无合同”（该承运商该线路该等级一份合同都没有）与“时刻未覆盖”（有合同但此刻落在空档）
  通过两个错误码严格区分。
- 合同添加拒绝链：**参数非法 → 区间重叠**。重叠判定为
  `lo1 < hi2 && lo2 < hi1`，相接不算重叠；任何重叠都在临时候选列表上先校验、后提交，
  失败时库内状态字节不变。同 ID 添加即修订；修订只允许改价格/区间，不允许改承运商/线路/等级。

## 5. 复杂度论证：为什么不随合同总数扫描

- `store` 以 `(承运商, 起点, 终点, 等级)` 为键，每个车道维护一份按 `EffectiveAt` 升序、
  两两不重叠的切片。查询用 `sort.Search` 找“最后一份 `EffectiveAt <= t`”的合同，
  再判一次 `t < ExpiresAt`。比较次数为 `ceil(log2(k))`，`k` 为**该车道**合同数，
  与其他车道合同数完全无关（先哈希定位车道，再车道内二分）。
- 另维护 `(线路,等级) -> 承运商集合` 的二级索引，多承运商询价无需遍历全部合同即可枚举
  已知承运商。
- 阶梯计价只遍历计费重量实际跨过的档：在找到重量所落末档后立即停止，
  代价只与“跨档数”有关；档数规模增长只体现在跨档数上（题设允许的唯一规模维度）。
- `freight/store/store_complexity_test.go` 以探针计数给出**可验证**证据：
  4096 份相接合同下单次定位比较次数 ≤ 12，且在另一车道注入 4096 份干扰合同后计数不变；
  若实现退化为线性扫描，该断言立即失败。

## 6. 并发与结算一致性

- `system` 用一把 `sync.RWMutex` 串行化所有状态变更与计价/结算（询价走读锁，
  纯计算且不写台账）。因此任何并发交错都等价于某一合法串行排列；
  “同一运单在任一串行位置至多结算一次”由 `ledger.Settle` 在临界区内
  “检查已结算标记 + 写入快照”原子完成。`-race` 下有专门的高并发测试。
- 结算固化：`ledger` 对每个运单保存两个槽位：
  `latest`（最近一次报价，未结算时随再次计价刷新）与 `settled`（结算瞬间深拷贝的快照）。
  结算后任何新增/修订合同都只影响后续报价，**没有任何代码路径会回写 `settled`**；
  已结算运单仍可再次计价，但只更新 `latest`。随机差分测试在整条操作序列结束后
  再追加合同变更，逐个核对固化快照不变。

## 7. 多承运商询价

`System.Quote(QuoteRequest)`：

- 承运商列表为空时自动取该 `(线路,等级)` 下所有有合同的承运商；
- 成功项按总价升序、总价相同按承运商编号升序；失败项（无合同/时刻未覆盖/超范围）
  以原因码单列在成功项之后，按承运商编号升序；
- 单家失败不影响别家；询价构造的是占位运单，**不写入台账、不改变任何状态**；
- 仅当询价公共入参本身非法（重量 ≤ 0 等）才整单拒绝。

## 8. 可观测性与可重放

- 每次操作生成一行 JSON：`seq / op / input / output`，失败时输出错误码与判定依据。
- 日志只包含操作序号与入参出参，**不含墙钟时间、随机数、map 遍历序、指针地址**；
  承运商枚举排序、JSON 固定键，因此同一操作序列在全新系统上重放产生字节级一致的日志
  （`TestReplayDeterminism`）。

## 9. 关键取舍与被放弃的方案

- **单把大锁 vs 每车道细粒度锁 / MVCC**：细粒度锁与版本链能提升写并发，但本题合同量级小、
  正确性论证与重放语义优先。单锁使“等价串行”成为锁的直接推论，代码更少、更易审计；
  询价用读锁且计价为纯计算，吞吐上未见瓶颈。若未来写多读多，可在 `system` 内部平滑替换为
  车道分片锁，对外语义不变。
- **结算存快照而非合同版本指针**：版本指针方案需要给每次计价保留合同版本与回收策略，
  且修订合同时必须保证旧版本不可变；直接深拷贝明细更小、更直白，从物理上杜绝改写。
- **时刻用整数而非 `time.Time`**：避免时区、单调钟、格式化带来的不可复现性，
  端点取等测试也更简单；接入真实系统时在边界做一次时间戳换算即可。
- **校验放在 model 而不是 system**：朴素模型与生产系统可以共用同一份参数语义，
  差分测试因此连非法输入的拒绝码都能对齐。
- **不持久化**：按题目要求聚焦内存态与重放；日志本身就是可重放审计链，
  如需落盘可在 `Logger` 后追加事件溯源存储，不影响核心模型。

## 10. 本地验证方法

```bash
export GOCACHE=/tmp/gocache        # 若 HOME 缓存目录只读
go test ./...                       # 全量测试（含 60 条 × 400 操作随机差分）
go test -race ./...                 # 竞态检测
go test -run TestRandomDifferential -v ./freight/freighttest
go test -run TestFindComplexity -v ./freight/store   # 复杂度证据
go test -cover ./...                # 覆盖率
gofmt -l . && go vet ./...
```
