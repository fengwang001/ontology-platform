# 包级变量初始化次序求解 — 设计说明

## 1. 问题与模型

会话按源码出现次序接受两类声明：

- **变量初始化单元**：左侧一个或多个变量（可含 `_`），同时初始化；右侧为初始化表达式直接提到的标识符集合。
- **函数声明**：函数名与函数体直接提到的标识符集合；函数本身无需初始化。

单元对变量的依赖是传递的：引用变量即依赖该变量；引用函数则依赖该函数体能到达的全部变量，并沿函数间引用继续传递。函数可相互递归。预声明标识符视为永远就绪。允许前向引用，名字是否存在只在求解时判定。

次序规则逐字执行："在尚未初始化的单元中，反复选取源码次序最靠前、且所依赖变量已全部完成初始化的单元，其全部变量视为同时完成"。

## 2. 模块划分

实现位于 `initsession/`，每个文件职责单一：

| 文件 | 职责 |
| --- | --- |
| `ident.go` | 标识符词法规则：ASCII 字母数字下划线、不得以数字开头、空白标识符 `_` 判定。 |
| `errors.go` | 可区分错误类型 `Error`/`ErrorKind`（非法参数、重名、未声明、初始化环）及构造器。 |
| `model.go` | 纯数据模型：单元、函数、名字归属、全局声明次序日志、返回结构。 |
| `session.go` | 并发安全会话：登记校验、重名判定、RWMutex 保护、快照入口。 |
| `solve.go` | 快照求解主流程：未声明引用检查、最小堆调度、环收集、结果装配。 |
| `closure.go` | 函数传递依赖闭包：变量编号、记忆化集合、小并大合并。 |
| `scc.go` | 函数调用图 Tarjan 强连通分量（迭代式，避免递归栈），产出逆拓扑序。 |
| `heap.go` | 以单元源码下标为键的最小堆。 |
| `stats.go` | 可验证开销统计 `Stats`（随每次 Solve 独立返回）。 |

## 3. 关键流程

### 3.1 登记

1. **先做全部参数校验**：空左侧、非法变量名、非法函数名、函数名为 `_`、引用集合中存在非法标识符或 `_`。参数非法一律优先于重名。
2. 校验通过后取写锁，再做重名判定：与预声明、已接受变量/函数冲突，或同一单元内两个非空白变量同名，拒绝。
3. 通过才构造对象、写命名表、追加到列表与全局声明次序日志。拒绝路径不触碰任何字段，因此不占源码位置。

空白标识符不进入命名表，因此同名判定天然忽略 `_`，每次出现都是独立变量。

### 3.2 求解快照

`Solve` 在读锁下构造不可变 `snapshot`（浅拷贝切片与命名表；已发布的 `*unit`/`*fn` 此后不再被修改），随即释放锁，在快照上完成全部分析。登记只追加新对象、从不修改旧对象，所以快照与并发登记互不干扰，求解不可能看到登记到一半的单元，也不修改会话。

### 3.3 未声明引用（优先级最高）

按**全局登记次序**（单元与函数交错的 `decls` 日志）扫描每个已接受声明（含永远不会被引用的函数）。一个声明的右侧若存在既非变量/函数也非预声明的名字，即报错；报告全局次序最早的声明，以及该声明中字典序最小的坏名字。只要存在未声明引用，就不再做环判定。

### 3.4 函数传递依赖闭包

- 每个非空白变量按（单元次序、左侧位置）分配稠密 `int32` 编号。
- 在函数调用图上跑 Tarjan SCC：同一 SCC 内函数相互可达，共享同一份闭包（成员直接变量引用之并 ∪ 后继 SCC 闭包之并）。
- SCC 按**逆拓扑序**产出，处理某分量时其后继闭包已就绪；集合合并采用**小并大**（小集合元素二分插入大集合），每个变量编号最多被搬运 `O(log F)` 次。
- 每个函数体只遍历一次；一个函数被任意多单元引用时只是复用同一 SCC 闭包（`FunctionCacheHits` 按引用计数），不做逐引用者的重复展开。

函数递归（包括相互递归）由 SCC 正确处理，递归本身不报错；只有"变量依赖成环且无法选单元"才是初始化环。

### 3.5 调度（次序与环）

次序规则等价于以"单元依赖单元"为边的 Kahn 过程，并用源码次序最小堆打破并列：

- 初始对每个单元做一次就绪检查，入度（所依赖的未完成单元数）为 0 者入堆。
- 每轮从堆顶取源码下标最小的单元完成，沿**反向边**只通知依赖它的单元：被通知者入度减一并再检查一次，归零则入堆。
- 不存在"每轮重扫全部剩余单元"：就绪检查次数 = 单元数 + 实际反向通知数，为 `O(N + E)`；堆操作总计 `O(N log N)`，总体随单元数与引用关系总数近线性增长。

依赖边有两个细节：

- **自环保留用于调度**：单元直接或经函数引用自己的变量时，入度包含自身，永远无法就绪，正确表现为环；而返回的依赖集合按规格排除自身变量与 `_`。
- 多变量单元只提供"被实际到达的变量"：若只引用同单元组里的某个变量，只依赖那一个，而非整组。

堆弹尽且仍有未完成单元时即为初始化环。所有未完成单元都无法完成（不在环闭包上的单元本会随后完成），收集它们的非空白变量，按**单元登记次序、再按左侧位置**排列（空白标识符不报告）。

## 4. 关键取舍

- **SCC + 逆拓扑小并大，而非朴素记忆化 DFS**。朴素 DFS 在链式函数图上做集合 union 仍是 `O(F²)` 级拷贝；SCC 归并把每个编号的搬运次数压到 `O(log F)`。递归正确性也由 SCC 一揽子保证，避免手写 in-flight 状态出错。
- **显式反向边 + 最小堆，而非字面逐轮扫描**。字面规则要求"每轮选最靠前的可选取单元"，其结果与 Kahn + 源码次序优先队列完全一致（堆顶永远是当前全局最小的就绪下标），但后者没有每轮 `O(N)` 扫描。
- **全局声明次序日志 `decls`**。单元与函数在两个切片里分别编号，但未声明引用的"登记次序最早"必须跨两类声明比较，因此追加一条混合次序日志，解决先单元后函数扫描会错误的问题。
- **统计随 `Solve` 返回而不是挂在会话上**。并发求解各自独立计数，避免共享可变状态；测试可直接断言工作量上界。

## 5. 被放弃的方案

- **朴素记忆化 DFS 展开函数闭包**：实现简单，但在长函数链/共享函数场景集合重复拷贝，近线性承诺无法成立，弃用。
- **逐轮全量扫描就绪性**：与规格文字最贴近、最不易错，但最坏 `O(N²)` 次检查（逆序依赖链每轮只有一个就绪）。仅保留在测试的朴素参照模型中用于差分对照，不用在实现里。
- **位图（bitset）闭包**：合并是 `O(N/字长)`，但要返回的依赖集合本身可能达到 `O(N²)` 的输出规模（每单元都可能依赖很多变量），位图既不能消除输出成本，又使名字排序结果后处理更繁琐，弃用；改用有序 `int32` 切片 + 小并大。
- **Tarjan 递归版**：Go 默认栈在极深函数链上有增长成本，改为显式栈迭代实现。
- **细粒度读写分离的无锁结构**：规格只要求串行等价与一致快照，RWMutex + 不可变快照已足够，复杂度不值得。

## 6. 并发语义

- 登记串行化于写锁；求解取读锁构造快照后无锁分析。
- 结果等价于所有已接受操作按某个全序串行执行：快照即某一时刻的已接受前缀，求解不会读到登记进行中的中间态（对象在锁内完整构造后才发布）。
- 多次 `Solve` 可并发且互不影响，`Stats` 每次独立。

## 7. 开销特性与可验证方式

| 特性 | 界 | 验证 |
| --- | --- | --- |
| 函数闭包计算 | 每个函数恰好计入一次（SCC 成员合并） | `Stats.FunctionClosuresComputed == 函数数`；`TestComplexityCounters/shared_function_closure` 中 500 个引用者只有 2 次计算、500+ 次缓存命中。 |
| 函数被大量单元引用 | 引用者只共享闭包，不重复展开 | 同上；`BenchmarkSharedClosure`（n=1000→4000 时间近似 4 倍）。 |
| 调度检查 | `ReadyChecks ≤ Units + ReverseNotifications` | `TestComplexityCounters/no_round_rescan`（逆序链 300，断言线性上界；朴素逐轮扫描要约 `n(n+1)/2` 次）。 |
| 总体 | `O((N+E) log N)` 时间、`O(N+E+输出)` 空间 | 基准 `BenchmarkReverseChain`、`BenchmarkSharedClosure`（`go test -bench .`）。 |

说明：返回结果本身要求为每个单元给出传递依赖集合，输出规模可能为 `O(N²)`，这是规格所需；内部展开与选取过程不再额外叠加二次因子。

## 8. 本地验证方法

```bash
# 需要 Go 1.26+；若 go 不在 PATH：
export PATH=$PATH:/usr/local/go/bin
# 若默认构建缓存目录只读：
export GOCACHE=/tmp/gocache

go test ./...
go test -race ./...            # 并发登记/求解交错，竞态检测
go test -v ./initsession       # 逐条输入/输出/判定依据日志
go test -bench . -benchmem ./initsession
go vet ./... && gofmt -l .
```

每次测试的输入、输出与判定依据同时写入测试日志（`-v` 可见）和 `initsession/testdata/logs/initsession-trace.log`。
