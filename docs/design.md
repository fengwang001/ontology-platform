# 属性级权限随对象类型版本迁移联动网关 — 设计说明

## 1. 目标与范围

在本体平台（对标 Palantir Foundry Ontology）中实现一个判定网关，使已授予的
**属性级读/写权限**能够随对象类型（Object Type）的版本演进正确联动：

- 新增属性：新标识符从新版本起存在，旧版本区间上的权限条目不自动覆盖它。
- 收紧类型约束（`tighten`）：标识符不变，权限继续生效。
- 弹性重命名（`rename`）：**保留标识符**，只改显示名；权限按标识符延续自动继承，
  引用旧名字一律报“属性标识符不存在”。
- 属性废弃（`deprecate`）：标识符从新版本快照整体移除，其上权限立即线上失效、
  不可再被查询用于判定，但历史权限记录不删除，仍可经审计接口读取。

同时强制：

- 写时策略（`reject_whole` 整条拒绝 / `ignore_field` 整体忽略）**类型内全局唯一**，
  演进时不得切换，试图混用报 `write_policy_conflict`。
- 读时对无权限属性做**整体移除式投影**（不返回零值/掩码），允许结果缺少必需属性，
  并以 `partial_view=true` 明确标记。
- 并发可线性化；被拒绝操作不改变对象、版本号或权限记录的任何部分。

## 2. 核心模型

| 概念 | 载体 | 关键不变量 |
| --- | --- | --- |
| 类型版本 | `TypeVersion`（不可变，只追加） | 版本号严格递增；演进绝不改写旧快照 |
| 属性 | `Attribute{ID, Name, Kind, Required}` | `ID` 是跨版本稳定标识符；`Name` 可随重命名变化 |
| 权限条目 | `PermissionEntry`（不可变流水） | 绑定主体、标识符、操作、版本区间；grant/revoke 区分 |
| 权限视图 | `permView`（每 类型×主体 一条） | 授权区间并集、吊销区间并集，随流水增量物化 |
| 对象 | `Object` | 字段一律按稳定 `AttrID` 落盘；记录 `schema_ver` |

### 2.1 版本区间语义

- 区间为闭区间 `[from,to]`；`to=0` 表示**开放区间**，随“当前最新版本”延伸。
- 同一 `(主体, 属性, 操作)` 上的多条授权取**区间并集**（`unionIntervals` 做
  相邻段合并、开放段吞尾）。
- 显式吊销单独维护吊销并集；判定式为
  `allowed(v) = grants.contains(v) && !revokes.contains(v)`，
  即**吊销优先于授权**，即使授权并集覆盖该点，只要落在吊销区间内就判无权限。
- 允许预置“未来版本起点”的授权（`from_ver` 可大于当前版本）：记录立即物化，
  但只有在对应版本真正到达后才参与判定。这是为了支持“先配权、后演进”的运维
  习惯；被放弃的替代方案是禁止未来起点（在差分测试中被证明过于不便）。

### 2.2 标识符解析（请求引用 -> 属性）

请求字段的 key 既可以是标识符也可以是**当前名字**。解析顺序：

1. 在当前版本按 `AttrID` 精确命中；
2. 否则按当前 `Name` 命中；
3. 都不中则 `attr_not_found`。

因此：旧名字、已废弃标识符、从未存在的标识符全部报同一类
`attr_not_found`，绝不退化为权限错误。对象字段存储统一规范化为 `AttrID`，
重命名后数据无需搬迁。

## 3. 判定流程

### 3.1 写

1. **对象不存在**（仅对已有对象的写）-> `object_not_found`。
2. **版本校验**：`schema_ver` 必须等于类型当前最新版本；否则 `version_expired`，
   整次拒绝、零状态变更（不解析字段、不看权限）。
3. **标识符解析**：对提交的每个字段解析引用；任一不存在 -> `attr_not_found`，
   整条失败、零状态变更。
4. **逐属性权限判定**（互相独立，单字段被拒不影响其他字段的判定）：
   属性级写授权或类型级（`*`）写授权成立则可写；被拒原因区分为
   `revoked`（存在覆盖该版本的授权且被同属性吊销覆盖）与 `permission_denied`。
5. **按类型统一策略处理**：
   - `reject_whole`：存在任一被拒字段 => 整次失败，对象、版本、权限全部不变；
   - `ignore_field`：跳过被拒字段，其余字段写入，返回 `ignored_fields`。

建对象（`CreateObject`）复用同一条判定路径，因此被整条拒绝时对象根本不会创建。

### 3.2 读

拒绝优先级固定：**对象不存在 > 版本过期（写时强校验，读始终基于最新版本视图）
> 类型级无读权限 > 属性级**。

1. 对象不存在 -> `object_not_found`。
2. 类型级门槛：持有覆盖当前版本的类型级读授权（`*`，同样受吊销挖洞约束），
   或对任一**当前存活**属性持有读授权；否则 `type_no_permission`。
3. 逐属性独立判定，构造全新对象：存活且可读（类型级或属性级）的字段才投影；
   无权限或已废弃的字段**整体移除**。有移除即 `partial_view=true`，
   允许缺少必需属性，不触发 schema 违反。

## 4. 规模无关的性能要求与可验证证明

要求：计算“给定主体在给定版本下对某类型的权限视图”，所访问的历史权限记录数与
历史版本记录数不得随历史版本总数或权限条目总数增长。

### 4.1 方案

- **授权/吊销在写入瞬间增量物化**到其 `(类型, 主体)` 的 `permView`（一次
  O(区间段数) 的区间并集合并，段数在本模型下为小常数）。
- 在线判定只访问：1 条类型当前状态记录 + 1 条该主体的视图记录。
  **不扫描版本链，不扫描权限流水**；历史数据只服务审计与朴素重放。
- 每次判定访问的记录数由 `AccessCounters` 显式计数。

### 4.2 可验证方式

`TestViewAccessIsScaleIndependent` 在两档规模（V/P = 10 与 80）下构造历史，
复位计数器后执行两次权限视图计算，硬性断言：

```
PermissionRows  == 0   // 不触碰任何历史权限条目
VersionRecords  == 0   // 不触碰任何历史版本记录
ViewRecords     == 2   // 每次判定恰好 1 条视图记录，与规模无关
```

规模翻倍而计数不变，即对“与规模无关”给出可重复执行的机器证明。
审计查询 `AuditPermissions` 刻意扫描流水（审计不在性能保证范围内）。

## 5. 并发正确性

网关以单一互斥锁串行化所有读写请求：

- 任意交错执行都等价于某个全局串行顺序（linearizable）；
- 每次判定看到的状态对应该顺序的某个确定前缀，不存在“授权变更与版本演进
  交错”的中间态；
- 被拒绝路径在持锁段内不执行任何写入（对象/版本/权限三不变），
  因此拒绝天然无副作用。

被放弃的方案：按类型分片锁 + 视图原子指针切换。它能提升吞吐，但需要额外证明
跨主体授权（`*`）与对象判定的跨片一致性，在本任务中收益不抵风险；
全局锁让并发正确性可由代码结构直接审计。`TestConcurrentSerializable` 与
`-race` 用于回归。

## 6. 错误类别（彼此可区分）

| 类别 | 触发情形 | HTTP 状态（参考） |
| --- | --- | --- |
| `object_not_found` | 对象不存在（最高优先级） | 404 |
| `version_expired` | 写携带版本不是当前最新版本 | 409 |
| `type_no_permission` | 无类型级且无任一存活属性的读授权 | 403 |
| `attr_not_found` | 标识符废弃、引用旧名字、从未存在 | 404 |
| `revoked` | 授权点被显式吊销区间覆盖 | 403 |
| `write_policy_conflict` | 试图在同类型内混用两种写策略 | 400 |
| `permission_denied` | 属性级无权限（非吊销） | 403 |

所有错误都是带 `ErrorKind` 的 `*DecisionError`，用 `ErrorKindOf(err)` 判别，
类别不会互相误报。

## 7. 审计与决策日志

- `AuditPermissions(type, subject, attr)` 返回不可变权限流水（含已废弃标识符
  条目），只追加、不删除、不修改；这些条目不参与线上判定。
- 每次判定（创建类型/演进/授权/吊销/读/写/审计）都写入 `DecisionLogEntry`，
  包含 `Input`、`Output`、`Reason`（依据的版本、区间并集、策略与移除字段）。
  HTTP 层经 `GET /decisions` 暴露。

## 8. 被放弃/未采纳的方案

- **每次判定全量重放流水**：实现最简单、天然正确，但访问量随历史线性增长，
  违背性能要求。保留为 `naiveModel`，专门用于随机差分测试。
- **读时按版本快照裁剪授权区间**：授权区间已经显式带版本轴，重复裁剪只会
  增加复杂度；统一用“区间包含 + 标识符当前是否存活”两个维度。
- **重命名时迁移/复制权限条目**：会制造重复授权与并集膨胀。采用“标识符不变、
  名字可变”，权限零迁移。
- **类型内允许逐次切换写策略**：规范明令禁止；切换请求直接冲突报错。
- **拒绝时返回零值或掩码字段**：会让调用方无法区分“真实空值”与“被投影”，
  且容易诱发把掩码当数据回写。改为整体移除 + 部分视图标记。

## 10. 代码地图

- `ontology/model.go`：领域模型与请求/结果结构。
- `ontology/errors.go`：可区分错误类别。
- `ontology/store.go`：版本链、权限流水、区间并集、增量物化视图、访问计数器。
- `ontology/gateway.go`：类型生命周期、授权/吊销、读写判定、审计、日志、串行锁。
- `ontology/naive.go`：独立朴素重放参照模型（仅测试使用）。
- `ontology/*_test.go`：语义、区间、并发、性能常数、随机差分测试。
- `cmd/server/main.go`：最小 HTTP/JSON 网关。
