# 字段演进兼容性校验机制 — 设计说明

## 目标

判断一次对象类型字段定义的变更，能否在**不迁移既有实例数据**的前提下被新版本的读写路径安全接受。本文档记录关键取舍、被放弃的方案与本地验证方法。实现位于 `ontology/` 包。

## 总体结构

```
FieldChange ──► Classify（六类互斥分类）
            ──► Checker.Check（纯函数判定，产出 Decision）
            ──► Engine.Commit（打包提交：逐项判定 → 汇总 → 原子生效/整体拒绝）
            ──► Engine.Write（按当前定义校验写入）
Engine 用一把互斥锁把全部 Commit/Write 排入全序日志（LogEntry），
Naive 是独立的朴素串行参考实现，用于并发正确性对照。
```

## 关键设计

### 1. 六类互斥的变更分类（`ontology/change.go`）

分类按固定优先级裁决，保证**唯一归属**：

1. `Old == nil` → 按是否带默认取值分为「新增带默认 / 新增不带默认」；
2. `New == nil` → 删除字段；
3. 类型不同 → 改变取值类型（**类型变化优先于约束变化**，因为跨类型的约束无可比性）；
4. 约束解集严格缩小 → 收紧；严格扩大 → 放宽；
5. 约束解集互不包含（不可比）→ **保守归入收紧**，强制全量存活实例校验；
6. 其余（仅默认值/可空标志变化）→ 无实质变更，但仍需做引用方漂移检测。

约束语言被刻意限制为**包含关系可判定**的子集（数值区间、字符串最大长度、枚举集合），`Constraint.Implies` 即解集包含判定。

### 2. 逐类兼容性规则（`ontology/checker.go`）

| 类别 | 规则 |
|---|---|
| 新增带默认 | 始终兼容；读路径对缺失取值回填默认值 |
| 新增不带默认 | 允许缺失则兼容；不允许缺失则不兼容，**除非携带回填规则**（提交时对全部存活实例执行） |
| 收紧约束 | 扫描全部存活实例，**任一**既有取值不满足新约束即整体不兼容，不因违反数量少而放行 |
| 放宽约束 | 始终兼容，不扫描实例（`CheckedInstances == 0` 可验证） |
| 改变类型 | 全部存活实例的既有取值必须能被**无损重解释**为新类型取值；规则由类型自身声明（`ValueType.ReinterpretTo`），判定为精确往返比较（如 `int64→float64→int64` 恒等），**不做近似比较** |
| 删除字段 | 对实例数据兼容；残留取值随定义一并移除 |

不兼容原因用位掩码 `IncompatCategory` 暴露四类：`InstanceConstraintViolation`、`IrreversibleTypeConversion`、`MissingValueNotAllowed`、`ExternalSemanticDrift`。一次打包提交命中多类时**全部返回**。

### 3. 外部引用方语义漂移（`ontology/refs.go`、`ontology/field.go`）

链接类型与动作通过 `FieldReference` 登记对字段的引用，并声明依赖维度（`Dependency`：类型/约束/默认值；**存在性变化对任何引用方必然构成漂移**，故不在维度之列）。引用建立时捕获字段语义快照 `FieldSignature`；判定时与变更后的签名对比，凡依赖维度变化即判定漂移——即使实例取值校验通过，整次变更仍不兼容。变更被接受后，引用方快照对齐到新版本。

### 4. 打包提交的原子性（`ontology/engine.go`）

`Commit` 在临界区内先对全部变更**逐项独立判定**（只读、不改状态），汇总后：任意一项不兼容 → 整体拒绝、**零状态变化**（测试用前后快照 `DeepEqual` 核对）；全部兼容 → 一次性应用（含回填与类型重解释）。不存在部分生效的中间状态。

### 5. 存活实例开销与历史总量无关（`ontology/store.go`）

`InstanceStore` 只维护存活索引（`map[type]map[id]*Instance`）；逻辑删除与迁移会**物理移除**条目。校验器只能通过 `EachLive` 遍历，因此检查次数 ≤ 当前存活总数。`TestLiveCountBound` 以 7 存活 + 8000 已删除/迁移验证 `CheckedInstances == 7`。

### 6. 线性化（`ontology/engine.go`、`ontology/naive.go`）

- 全部 `Commit`/`Write` 在同一把互斥锁内完成「判定 + 生效 + 追加日志」，日志序号即全序；
- 一次写入的校验与落库在同一临界区，必然对应全序中某个确定时刻的字段定义；
- 提交采用 **CAS 基线**：`Old` 必须与当前定义完全一致，否则拒绝，避免并发提交基于过期定义互相覆盖；
- `TestConcurrentCommitsAndWritesMatchNaive` 用 4 提交方 × 6 写入方并发交织，再把全序日志重放到独立的朴素串行实现 `Naive` 上，逐条比对接受结果与不兼容类别，并比对最终字段定义与实例数据。

### 7. 判定记录（`Decision`）

每次判定记录：变更内容（`Change`）、分类（`Kind`）、检查依据（`Reason`、实际检查实例数、违反实例 ID、漂移引用方 ID）、结论（`Compatible`、`Categories`）与全序序号（`Seq`），供事后核对。

## 被放弃的方案

- **按违反比例放行收紧约束**（如 <1% 即通过）：与需求直接冲突，且会让读路径面对不确定的数据形状，放弃。
- **近似比较做类型转换判定**（如 `|a-b| < ε`）：不可逆且不可解释，改为类型自身声明的精确往返规则。
- **通用约束表达式 + SAT 求解包含关系**：约束语言一旦含析取/正则，包含判定复杂度失控；改用可判定子集，不可比时保守归入收紧。
- **变更时全量重写实例数据**（eager migration）：违背「不迁移既有实例数据」前提；新增带默认字段采用读路径回填，仅显式携带回填规则时才写数据。
- **多版本字段定义共存 + 读时协商**：读写路径复杂度高、语义含糊；改用单版本 + 原子切换 + 全序日志。
- **无锁乐观并发（CAS 循环）**：打包提交涉及多字段多实例，重试语义复杂；单互斥锁在本场景足够且可直接给出全序。

## 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin   # 如 go 不在 PATH
go test ./...                # 全量测试
go test -race -v ./ontology  # 竞态检测 + 详细输出
go test -run TestLiveCountBound ./ontology          # 存活实例开销上界
go test -run TestConcurrent ./ontology -count=10    # 并发对照（可重复多次）
gofmt -l . && go vet ./...   # 格式与静态检查
```

测试覆盖：六类分类的唯一性与边界（`classify_test.go`）、逐类兼容/不兼容边界与存活开销上界（`checker_test.go`）、打包提交的整体拒绝/零状态变化/全类别汇总（`batch_test.go`）、并发交织与朴素串行实现对照（`concurrency_test.go`）。
