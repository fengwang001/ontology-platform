# 对象生命周期状态机子系统 — 设计说明

## 1. 目标与范围

为本体平台提供一个进程内的对象生命周期状态机：对象类型声明状态集合、
终态与有向迁移规则；对象实例的状态迁移只能由动作触发；一次迁移的
前置条件、迁移后链接基数、跨实例校验钩子与级联随迁必须在**同一个处理单元**
（`Engine.Batch`）内协同求值并整体生效或整体不生效。

不包含：跨进程持久化、分布式事务、版本历史查询（这些都在接口边界之外，
且刻意不作为判定的依赖）。

## 2. 核心概念

- `Schema / ObjectType / Transition`：只读声明。一条迁移包含：
  - `Preconds`：前置条件（属性等值、出向链接计数区间、对端状态集合）；
  - `MaxCard`：**迁移生效后**的出向链接基数上限；
  - `Hooks`：迁移生效后对每条链接对端的状态要求；
  - `Cascades`：迁移后对处于给定状态的对端强制触发的随迁；
  - `MutexGroupID`：互斥组标记。
- `Store`：实例与链接的内存存储。链接是带类型的有向边
  `(type, from, to)`，其邻接表归出端实例“属主”所有。
- `Engine.Batch(ops)`：处理单元。单元内操作按调用方声明顺序逐一规划；
  任一操作被拒绝，整个单元不生效；全部通过才提交。
- `Logger`：接收每次迁移的输入、逐条判定依据（basis）与最终结果。

## 3. 一次处理单元的执行流程

1. **无锁快照规划**：从每个实例的原子版本指针加载当前版本，构造私有
   工作视图 `workView`（基底 + 稀疏 overlay）。
2. 按声明顺序规划每个操作：
   - 迁移在**私有推演视图**上做 DFS：根环 → 级联环；每环立即看到上游
     迁移后的真实状态/链接；DFS 任一环失败即丢弃私有视图，真实状态
     零改动。
   - 非迁移操作（改属性、增删链接）同样只改工作视图。
3. 收集本单元涉及的全部实例（含级联对端），按 ID 字典序加实例锁。
4. 持锁原子重取版本并与规划基底做指针比较：若期间被其他单元改动，
   释放锁并整体重规划（乐观重试，仅在真并发冲突时发生）。
5. **COW 提交**：为每个属主基于旧版本构造新版本（状态、属性、时钟戳、
   属主邻接表），原子替换版本指针；推进逻辑时钟并为被改动实例盖戳。

### 3.1 链式触发与“先检后生效”

- 级联在私有推演视图上完成**整棵树的展开与校验**后才并入单元视图，
  因此不存在“先迁一个再发现下游不行”的中间态。
- 循环检测沿 DFS 递归路径（`visiting` 集合）完成：
  - 对端仍在当前递归路径上（无论它此刻状态如何）即判 `CodeCycle`；
  - 检测在该环状态被并入单元视图之前完成，不靠计数上限截断。
- 两条级联分支收敛到同一实例：同一条迁移幂等只生效一次；不同迁移
  互相冲突，按 `CodeCycle` 拒绝。

### 3.2 迁移后基数与跨实例钩子

两者都在“本环及其全部级联已在私有视图生效”之后求值，看到的是
**迁移后的真实链接状态**（同批新增的链接计入基数）。基数失败
（`CodeCardinality`）优先于钩子失败（`CodeHook`）报告。

### 3.3 终态

终态实例：拒绝任何迁移、属性修改与“参与新增链接”（任一端点为终态
即拒绝）；**允许删除已有链接**（终态可以解绑，但不能再被绑定）。
终态保护失败报 `CodeTerminal`，且拒绝不改变时钟戳。

## 4. 错误类别与固定优先级

多类错误同时成立时，严格按下列顺序报告最高优先级者：

| 优先级 | Code                | 含义                                   |
| ----: | ------------------- | -------------------------------------- |
| 0 | `CodeUnknown`       | 目标状态/迁移规则未声明（含源状态不匹配） |
| 1 | `CodePrecondition`  | 前置条件不成立                           |
| 2 | `CodeMutex`         | 互斥迁移被拒绝                           |
| 3 | `CodeCardinality`   | 迁移后链接基数超限                       |
| 4 | `CodeHook`          | 跨实例钩子联动拒绝                       |
| 5 | `CodeCycle`         | 链式触发检测到循环/冲突                   |
| 6 | `CodeTerminal`      | 终态实例的改动尝试                       |

互斥的取舍：判定放行哪一条**不看到达时间**，只看调用方在处理单元中
声明的操作顺序（`mutexUsed[instance][group]=opIndex` 先占先得）。

## 5. 并发控制（串行等价 + 独立实例不阻塞）

- 每个实例一把锁，永远按 ID 字典序加锁 → 不存在加锁环（无死锁）。
- 全局 `RWMutex` 只保护“实例注册表”这张 map；锁序单向：
  **RLock（取槽指针） → 实例锁**，提交路径不反向申请全局写锁，
  逻辑时钟与批次序号用原子计数。
- 读路径（规划、公共查询）经**原子版本指针**无锁读旧版本；提交用
  copy-on-write 发布新版本，旧版本永不就地修改。
- 两个实例集合不相交的单元不共享任何锁，真正并行；同一实例的并发
  单元经实例锁串行化，叠加乐观重试，最终状态严格等价于某个合法串行序。

## 6. 复杂度：为什么不依赖历史迁移次数

判定过程中**没有任何结构记录历史迁移**。工作视图只持有：

- 本次涉及实例的状态/属性 overlay（大小 = 涉及实例数）；
- 属主出向邻接表（大小 = 这些实例当前的出边数）。

一次迁移的代价 = O(级联树上实例数 + 这些实例相关链接数)，
与该类型历史上发生过多少次迁移无关。`Store` 中也不存在迁移日志；
审计需求由 `Logger` 旁路输出，不参与判定。

## 7. 关键取舍

1. **私有视图整体推演，而非边迁边锁边校验。** 后者需要分布式式的
   补偿逻辑，且容易把“已经可见的中间态”暴露给其他单元；私有视图
   天然保证原子性，回滚只是“丢弃视图”。
2. **COW 版本 + 属主邻接，而非全局一把锁。** 全局锁实现最简单，但
   违背“独立实例并发不阻塞”的硬要求；属主邻接把链接的并发域
   精确收敛到出端实例，配合原子指针实现无锁读。
3. **乐观重试，而非两阶段锁扩展。** 级联对端在规划前无法完全预知，
   采用“规划 → 锁涉及集合 → 版本比对 → 冲突重规划”，冲突只在真
   并发改动同一实例时发生，无冲突路径无额外串行点。
4. **基数/钩子只看“出向属主邻接”。** 双向计数需要双向锁定两端，
   扩大加锁集合且与“基数以本实例出向链接为准”的声明语义一致，
   因此不引入反向索引的锁定成本。
5. **时钟戳只在提交时推进。** 被拒绝单元既不改状态，也不推进时钟，
   满足“拒绝不留任何可观察痕迹”。

## 8. 被放弃的方案

- **全局单锁串行一切**：语义正确但无法满足“不同实例并发互不阻塞”，
  只保留在独立朴素参考模型 `internal/naive` 中作为对拍基线。
- **边生效边压 undo 栈的生产路径**：曾用于链式回滚，但“部分环已在
  真实存储生效”在锁释放边界上有暴露中间态的风险；改为私有视图推演后，
  生产路径只有 COW 提交，undo 栈仅保留给测试 failpoint 验证回滚顺序。
- **全局链接表 + 大锁**：会让任意两个新增链接的单元互相阻塞，放弃，
  改为属主邻接表。
- **用深度计数上限防循环**：需求明确禁止，改为递归路径三色检测，
  在任何一环生效前完成。
- **在实例对象上原地修改字段**：与无锁读天然冲突（data race），
  改为版本不可变 + 原子指针。

## 9. 朴素参考模型（对拍基线）

`internal/naive` 是与生产实现**零代码共享**的独立实现：

- 一把全局锁串行所有操作；
- 每一步立即生效并压入逆操作栈，任一失败立即按逆序撤销整批；
- 级联用递归 + 路径集合检测循环；基数/钩子在递归返回时按
  迁移后状态校验。

它故意“更笨但显然正确”，用于和生产实现对拍随机生成的初始结构与
操作序列（见 `TestDifferentialRandomized`、`TestCascadeStructuresDifferential`、
`TestConcurrentSerialEquivalence`）。

## 10. 本地验证方法

```bash
# 单元测试（功能 + 对拍）
go test ./...

# 竞态检测
go test -race ./...

# 覆盖率
go test -coverprofile=/tmp/cover.out ./...
go tool cover -func=/tmp/cover.out

# 静态检查
go vet ./...
gofmt -l .

# 演示（打印每次迁移的输入/判定依据/结果）
go run ./cmd/demo
```

测试矩阵：

- `TestPreconditionDecision` 前置条件判定；
- `TestMutexPriority` 互斥按声明顺序放行；
- `TestPostCardinality` 迁移后基数的正确时机（同批新增计入）；
- `TestHookReject` 跨实例钩子联动拒绝；
- `TestCascadeCommit / TestCascadeRollback` 链式整体生效与反向撤销；
- `TestCascadeCycle` 循环在生效前检测拒绝；
- `TestTerminalProtection` 终态全面保护 + 允许删链接 + 时钟戳不变；
- `TestConcurrentSameInstanceSerializable`、
  `TestConcurrentTransitionsSameInstance`、
  `TestConcurrentIndependentInstances` 两种并发场景的串行等价；
- `TestDifferentialRandomized` 与朴素模型随机对拍（120 组场景）；
- `TestConcurrentSerialEquivalence` 并发结果等价于某个随机串行序；
- `TestCommitRollbackOrder` failpoint 验证撤销顺序与生效顺序相反。
