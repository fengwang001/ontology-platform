# 特种设备检验周期与超期管控系统 — 设计说明

## 模块划分

| 模块 | 职责 |
|---|---|
| `calendar` | 整数日序号 ↔ 公历日期换算；日历月加法（目标月无对应日号取该月最后一天） |
| `domain` | 类别、类别配置、状态、检验结论、错误种类（声明顺序即优先级）等纯类型定义 |
| `index` | 按类别分桶的 `(到期日, 编号)` 有序索引，区间查询 O(log n + k) |
| `system` | 核心服务：全部生命周期操作、错误优先级判定、并发串行化、预警与可使用判定 |
| `naive` | 独立编写的朴素模型（全表扫描、直白逻辑），仅用于差分对照测试 |
| `cmd/server` | 演示程序：顺序执行典型操作并打印输入、输出与判定依据 |

## 关键设计决策

### 日期表示
- 日期为整数日序号（day 0 = 1970-01-01，可负），换算采用 Howard Hinnant 的
  civil 算法，与起点选择无关地支持任意公历年份。
- 日历月加法：先换算到公历 (y, m, d)，月份进位后日号越界时取目标月最后一天
  （如 2024-01-31 + 1 月 = 2024-02-29）。

### 状态机
- 状态：`在用 / 封存 / 停用 / 报废`（报废为终态）。
- 检验不合格：立即转停用（封存中检验不合格同样转停用，封存终止）；到期日不变；
  复检合格恢复在用。
- 封存计时用**锚点**而非累计天数：封存时记录 `SealAnchor = 封存日`；
  封存期内每次检验把 `SealAnchor` 移到检验日。启封时顺延 `启封日 - SealAnchor`，
  因此封存期检验重算过的到期日天然不会被重复顺延，无需额外标记。
- 启封保障检查：顺延后 `剩余有效天数 = 新到期日 - 启封日 + 1`（含两端），
  小于类别最小保障天数则拒绝，对象保持封存。

### 检验到期日规则
- 合格：检验日 ∈ `[原到期日 - 提前窗口, 原到期日]`（含两端）→ 以原到期日为基准
  加一个周期；否则（过早或已超期）以检验日为基准。
- 有条件合格：取合格规则结果与 `检验日 + 整改限期` 的较早者。不引入“整改中”
  状态——整改完成后再次检验合格即按合格规则以当前到期日为基准重算，语义自然闭合。

### 索引与复杂度
- 到期索引按类别分桶（类别集合固定为 4），每桶一个按 `(到期日, 编号)` 排序的
  切片；插入/删除二分定位，区间查询两端各一次二分，只访问命中前缀/区间。
- **索引成员 = 状态为“在用”的对象**。封存、停用、报废对象在状态转移时被移出
  索引，恢复在用时才重新插入。因此预警扫描量严格正比于命中条数，
  已超期对象也被区间下界二分排除，不会进入扫描。
- 预警查询：每类桶查 `[date, date + 该类预警提前天数]`，合并自身命中与
  “设备被附件触发”（触发附件须挂在在用设备上）；排序键为触发到期日
  （设备仅被附件触发时取触发附件最早到期日），并列按编号升序。
- 可使用判定只遍历该设备的附件集合，开销 O(该设备附件数)。

### 并发
- 全部操作在单个 `sync.RWMutex` 下执行：变更操作取写锁，查询取读锁。
  并发调用因此等价于某个串行顺序（即锁的获得顺序）。
- 时钟（`lastDate`）只被**被接受的变更操作**在推进；查询（`Warn`/`Usable`）
  不检查回退也不推进时钟；被拒绝的操作不改变任何状态与时钟。

### 错误优先级
- `domain.ErrKind` 的声明顺序即优先级：参数非法 > 日期回退 > 对象不存在 >
  已报废 > 状态不允许 > 条件不满足。每个操作按固定顺序检查：
  参数 → 时钟 → 存在性/报废 → 状态 → 业务条件。多对象操作（挂接）按
  参数顺序（先设备后附件）逐个做存在性/报废检查。
- 归类约定：编号冲突、类别不匹配、负日期、整改限期缺失等属参数非法；
  重复封存、对未封存对象启封、重复挂接属状态不允许；超期封存、启封保障
  不足、附件超期/封存/停用被挂接属条件不满足。

## 被放弃的方案

1. **全局单一有序索引（不分桶）**：各类别预警提前天数不同，全局索引只能按
   最大窗口取候选再过滤，候选集可能远大于真实命中数，复杂度证明变弱。
   类别固定为 4，分桶代价为零，故放弃全局索引。
2. **堆结构维护到期日**：堆不支持 O(log n) 的任意删除（对象改期/封存/报废
   频繁），需要懒惰删除加定期重建，复杂度与正确性都难论证，改用以二分定位的
   有序切片（比较次数 O(log n)，搬移 O(n) 但只影响变更操作，不影响查询上界）。
3. **“整改中”显式状态**：会增加状态机维度（与封存/停用的组合爆炸），而有条件
   合格的语义完全可以由“较早到期日 + 再次检验重算”表达，故放弃。
4. **封存累计天数计数器**：记录“已封存天数”并在检验时清零，与锚点方案等价但
   需要多维护一个不变量；锚点方案把“检验后只顺延检验之后的天数”变成
   一次减法，更不易出错。
5. **使用登记拒绝时返回错误**：拒绝是正常业务结果而非系统错误，且题目要求
   给出结构化原因，故用 `(accepted, *UseDenial, error)` 三返回值区分
   “判定不通过”与“操作错误”。

## 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache

# 全部单元测试（含月末推算、窗口边界、到期日当天/次日、有条件合格、
# 封存顺延、保障天数不足、封存期检验后启封、附件转移、报废脱离、
# 错误优先级、预警排序）
go test ./...

# 随机差分对照：6 个种子 × 5000 步随机操作序列，
# 正式实现 vs 朴素模型逐步对照，日志打印输入/输出/判定依据
go test -v ./naive/ -run TestDifferential

# 复杂度两档对照（1 万 vs 10 万对象）：
# index 包断言比较/访问次数为对数级；system 包对照墙钟耗时
go test -v ./index/ -run TestRangeComplexity
go test -v ./system/ -run 'TestWarnScales|TestUsableScales'

# 并发（等价串行 + 无数据竞争）
go test -race ./system/ -run TestConcurrent

# 演示
go run ./cmd/server
```
