# 行政许可并联审批服务 — 设计说明

包路径：`permit`（module `ontology`）。纯 Go，无第三方依赖。

## 1. 模型与术语

- 时间为**整数日序号**；初始化时给定非工作日集合，所有“N 日”均指**工作日**。
- 许可类型 `PermitType`：若干环节 `StageDef`，每环节含部门、法定时限（工作日数 `DueWorkdays`）、
  前置集合（必须构成 DAG）、是否适用超时默认通过 `AutoPass`。
- 一件许可 `permitCase`：保存定义快照与一条**只追加、不可变的事件日志**。
- 全局时钟单调：变更操作的日序号不得早于已见最大值，否则报 `clock_rollback`。
  **查询不推进也不受时钟约束**——可对受理日之后任意历史时刻回放。

### 状态枚举（`StageStatus`）

`未启动 / 办理中(Active) / 补正中(Paused) / 已通过 / 不通过 / 已撤回 / 因他环节终止而未启动(Blocked)`。

整件结论 `CaseOutcome`：`办理中 / 准予许可 / 不予许可 / 已撤回`。

## 2. 时限计算（关键不变量）

- **启动日**：无前置环节＝受理当日；其余＝全部前置均通过的当日（最后一个前置通过日）。
- **起算日**＝启动日的**下一工作日**；启动当日不计入时限。
- **届满日**＝从起算日起数满 `DueWorkdays` 个工作日的那个工作日；**届满当日办理仍有效**。
- 工作日计数对每个“计时段”分别计算：
  - 首段（启动段）：`(startDay, …]`，不含启动当日，起算日是其下一工作日；
  - 暂停段在“要求补正当日”闭合（暂停当日**已计入**已用时限）；
  - 恢复段：`[resumeDay, …]`，**恢复当日计入**。
- **恢复后剩余时限 ＝ 暂停时尚未用掉的额度**；届满日随当前计时段平移，
  且只由“进入该段时的剩余额度”决定，因此即使已超时也能还原出真实届满日。

### 补正

- `要求补正` 暂停该环节计时；补正期限＝通知日的下一**日序号**起的固定 `SuppWorkdays` 个工作日，
  期限最后一日（含）之前提交即恢复；**晚一日**（期限届满后的下一工作日触及）视为不通过。
- 仅暂停该环节自身；并行环节时限不受影响。
- 每环节补正次数上限 `SuppLimit`，超限后只能通过/不通过。

### 超时

- 非自动环节：届满日之后仍未办结 → 标记 `overtime`，保持待办；之后仍可手动办结，
  **超时标记一旦置上永不清除**（暂停/办结都保留）。
- 自动通过环节：届满日之后被任一操作/查询**触及**时惰性视为通过，
  **通过时刻＝届满日的下一工作日**（即使实际触及日更晚，通过时刻仍回溯到该工作日）。

### 整件终局

- 任一环节不通过：其在依赖图上的**后代环节永不启动**（`Blocked`），
  与被拒环节无依赖关系的并行环节及其后继照常启动、办理，但其结果不再改变结论；
  终局为不予许可，终局时刻＝首个不通过日。
- 全部通过：准予许可，终局时刻＝最后通过环节的通过时刻。
- 申请人终局前撤回：所有未办结环节停止（未启动/在办/暂停→已撤回），已办结结果保留可查。
- 终局后一切办理一律 `state_not_allowed`。

## 3. 关键取舍：事件溯源 + 惰性派生

系统**不在时间流逝时主动改写状态**，而是：

1. 变更操作（受理/办理/补正提交/撤回）经校验后，仅向该许可追加一条不可变事件（带全局 `seq`）。
2. 对任意历史时刻 `day` 的查询，调用纯函数 `derive(case, day)`：
   - 重放 `event.day <= day` 的事件；
   - 定点迭代完成“满足前置即启动 / 补正逾期视为不通过 / 超时默认通过”三类**惰性派生**，
     直至当日状态稳定；
   - 再计算封锁传播与整件终局。

由此得到的性质：

- **精确可复现**：`derive` 是纯函数，相同事件序列在相同 `day` 必然得到相同快照；
  查询任意历史时刻与按相同操作序列得到的实际状态一致。
- **并发等价串行**：所有变更在一把互斥锁内完成“校验+追加事件”，
  并以原子自增 `seq` 定序，因此并发结果等价于某个串行顺序；被拒绝的操作不追加事件、不改状态。
- **开销与在办许可总数无关**：一次时限判定/超时处理只遍历**本许可**的环节与**本许可**事件，
  是 O(本件环节数 × 本件事件数)，不扫描其他许可。
  `BenchmarkProgressScaling` 显示在办许可从 100→4000 时单件查询分配恒为
  `1368 B / 10 allocs`，用时基本恒定（仅 map 散列常数变化）。

## 4. 错误类别与优先级

按下列优先级只报第一个（见 `errors.go` 与各操作的校验顺序）：

1. `invalid_param`（参数非法，最先；且非法参数不推进时钟）
2. `clock_rollback`（时钟回退）
3. `not_found`（许可或环节不存在）
4. `state_not_allowed`（已办结/已撤回/整件已终局等）
5. `no_permission`（非本环节所属部门）
6. `prereq_not_passed`（前置未全部通过 / 后代被封锁）
7. `supplement_limit`（补正次数超限，最后）

被拒绝的操作在任何状态变更之前返回，因此**不改变状态、时限与时钟**。

## 5. 被放弃的方案

- **后台定时器/定时任务轮询**：会引入“系统是否在某日运行”的副作用，使历史回放依赖运行时机，
  无法对任意历史时刻精确复现；且轮询成本随在办许可总数增长。改为惰性派生。
- **在每个许可上维护实时倒计时并随时间推进递减**：暂停/恢复/跨非工作日极易产生离一错误，
  且并发更新复杂。改为按计时段对工作日区间做可重入的纯计数。
- **全局首个不通过日一刀切封锁所有未启动环节**：会误杀与被拒环节无依赖关系的并行链路。
  差分测试发现该错误，最终严格按依赖图后代传播封锁。

## 6. 朴素参考模型（差分测试预言机）

`naive_model.go` 是**独立编写**的参考实现：显式逐日 `tick` 的状态机，逐工作日扣减剩余额度，
不调用 `derive`/计时段公式（仅复用 `Calendar` 工作日原语）。两者算法路径不同：

- 正式实现：事件溯源 + 区间工作日计数 + 定点派生；
- 朴素模型：逐日推进 + 每环节整数剩余额度 + 当日定点启动。

`TestRandomDifferential` 生成随机非工作日集合、随机 DAG、随机补正参数与随机操作序列
（默认 2000 条序列 × 120 步），在每个探测时刻逐环节比对状态/超时/剩余时限与整件结论、终局时刻，
并比对每个操作被两模型拒绝的**错误类别**。分歧时打印完整定义、非工作日与逐步日志。

## 7. 本地验证

```bash
export PATH=$PATH:/usr/local/go/bin:$PATH
go test ./...                      # 全量（默认含 2000 条随机差分序列）
go test -race ./...                # 竞态检测
go test ./permit/ -run TestRandomDifferential -v   # 查看每条序列的判定日志
go test ./permit/ -bench BenchmarkProgressScaling -benchtime=2000x  # 开销不随许可总数增长
go vet ./...
gofmt -l .
```

`WithLogger` 可注入日志器；测试中的日志打印每步输入、输出（含 REJECT）与判定依据
（启动环节、状态、剩余时限、超时、整件结论与终局时刻）。
