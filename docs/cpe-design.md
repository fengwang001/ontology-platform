# 执业资格继续教育学分周期核算服务 — 设计说明

包路径：`ontology/cpe`。本文档记录核心语义决策、关键取舍、被放弃的方案与本地验证方法。

## 1. 领域模型

- **时间**：整数日序号。服务维护逻辑时钟 `lastNow`，仅被接受的操作可推进；
  `now < lastNow` 报 `时钟回退`，被拒绝的操作不改变任何状态与时钟。
- **周期**：首个周期为 `[发证日, 发证日+周期长度)`，之后每个周期左闭右开、首尾相接，
  第 k 周期为 `[发证日+k*L, 发证日+(k+1)*L)`。周期网格固定，不随宽限/续期平移。
- **学分记录**：类别（必修/选修/线上）、学分数（正整数）、取得日、出具机构。
  取得日不得晚于登记时的 `now`（否则参数非法）。重复登记键 = 机构+持证人+取得日+类别，
  仅统计**未撤销**的记录（撤销后可重新登记同键记录）。
- **更正/撤销**：仅出具机构可操作；`now - 登记时now <= 更正窗口`（恰等允许）。

## 2. 计入与达标

- 计入量：必修、选修各自封顶；线上计入量 `≤ 必修封顶后 + 选修封顶后`。
  多约束并存时取使总计入量最大者——由于必修/选修上限与线上约束单调，
  先各自封顶再约束线上即为最优（贪心=最优），见 `cpe/accounting.go`。
- 达标：总计入量 ≥ 周期总要求 且 必修计入量 ≥ 必修最低要求。
- **结转**：`min(总超额, 选修计入+线上计入-max(0,总要求-必修计入), 结转上限)`，
  即仅选修/线上超额部分可结转，必修超额不结转；宽限期内补足的周期结转恒为 0。
  结转量计入下一周期选修类原始累计，同样受选修上限约束。

## 3. 归属规则（登记时刻决定，归属后不变）

操作被接受前先推进状态机（`advanceTo`），再按当时状态归属：

- 当前周期 Open：取得日落在本周期区间 → 计入本周期；否则不计入。
  例外（严格按题面"一律不计入"）：上一周期曾进入宽限期，取得日属于其宽限窗口、
  且登记时刻已越过宽限结束时刻 → 不计入任何周期。
- 当前周期 Grace：取得日落在本周期区间或宽限窗口内 → 计入本未达标周期。
- 取得日属于已关闭周期 → 记录保留（可更正/撤销），但不计入任何周期。

## 4. 状态机与关键取舍

每个持证人是一个小状态机：`Open → (达标) Closed/下一周期`、`Open → (未达标) Grace →
(补足) Closed/续期`、`Grace → (届满未达标) Expired`。证书失效后仅可重新注册为新持证人
（同一 ID、新一代 generation，原学分不继承，旧记录 ID 失效）。

关键取舍：

1. **先推进后应用（advance-first）**：操作被接受前先把状态机推进到该操作的 `now`。
   周期 k 的关闭核算只包含 `now < 周期末` 的被接受操作（及宽限规则），与操作交错无关，
   保证"相同操作序列重放结果完全一致"。
2. **关闭即冻结**：周期关闭（达标/宽限补足/失效）后结果不可变。更正/撤销只影响
   尚未关闭周期的增量聚合；对仍处开放周期的记录做更正/撤销，核算结果与
   "一开始就是更正后的值"完全一致（有专门等价性测试）。对已关闭周期的记录更正
   仍被允许（窗口内），但不改变已冻结结果——这是冻结语义的必然推论，已在文档明示。
3. **惰性推进 + 只读派生**：周期闭合由时间阈值驱动，与操作内容无关，因此在被接受操作时
   才物化（`advanceTo`）；拒绝路径与查询一律在轻量副本上派生（`derive`），
   被拒绝的操作不改变任何状态。逻辑时钟只随被接受操作前进，不存在"墙钟"概念。
4. **O(1) 增量聚合**：每周期维护各类原始累计（`Tally`），登记/更正/撤销只做 O(1)
   增减；关闭周期存于仅追加、元素不可变的切片；快照 = 切片头拷贝 + 当前周期值拷贝，
   O(1) 生成。核算开销与历史记录总量无关（见 §6 的可验证证明）。
5. **历史查询**：每次被接受操作追加一条快照（now 单调不减），
   `GetAccountingAt` 二分查找最后一个 `now ≤ asOf` 的快照，再在副本上确定性派生到
   `asOf`。由于两次操作之间状态只是时间的确定函数，派生结果与当时实际一致。
   快照跨换发（generation）保留，因此可查询失效前各代的真实核算结果。
6. **并发**：单一互斥锁串行化全部操作（含查询），天然满足"等价于某个串行顺序"；
   审计日志记录锁内实际顺序与每步结果，测试据此重放验证等价性。

## 5. 被放弃的方案

- **纯事件溯源（每次查询全量重放）**：语义最直白，但周期核算开销随历史总量线性增长，
  违反性能约束。仅保留为测试中的独立朴素模型（`cpe/differential_test.go`）做差分对照。
- **关闭周期可被更正追溯改写**：会导致已关闭周期、结转、后续周期乃至失效判定级联
  重算，且与"历史查询须与当时实际一致"直接冲突，放弃；改为关闭即冻结。
- **操作先应用后推进（apply-then-advance）**：`now ≥ 周期末` 的登记会落入即将关闭的
  旧周期，是否计入取决于是否有其他操作先触发推进，语义依赖交错顺序，放弃。
- **按持证人分锁**：全局时钟（`lastNow` 单调性）与审计顺序需跨持证人一致，分锁后
  仍需全局协调，复杂度高于收益；单锁已满足串行等价要求。
- **宽限窗口取得日学分自然归入下一周期**：与题面"宽限期结束时刻之后补登的、取得日
  属于宽限期内的学分一律不计入"冲突，故实现为题面的字面规则（见 §3 例外）。

## 6. 本地验证方法

```bash
# 全部测试（边界单测 + 随机差分 + 并发等价 + 确定性重放 + 开销无关性）
go test ./cpe/

# 竞态检测
go test -race ./cpe/

# 随机差分日志（每步输入、输出与判定依据）
go test ./cpe/ -run TestDifferentialRandomOps -v

# 开销与历史无关：计时断言 + 基准对照
go test ./cpe/ -run TestAccountingCostIndependentOfHistory -v
go test ./cpe/ -run XXX -bench Benchmark -benchtime 20000x
```

可验证性说明：

- **开销证明**：`TestAccountingCostIndependentOfHistory` 在同一周期内累积 4 万条记录，
  断言晚期单操作耗时不超过早期的 5 倍（实测比值 ≈0.6–1.5，为缓存常数因子）；
  `BenchmarkRegisterCreditHistoryScaling` 提供 prefill=0 与 prefill=50000 的对照基准。
  实现上核算路径只读写当前周期的 `Tally` 与 O(1) 快照，无任何随历史增长的扫描。
- **正确性证明**：`cpe/differential_test.go` 是独立编写的朴素模型（事件溯源 + 全量
  重放 + 独立重写的核算数学），`TestDifferentialRandomOps`/`TestDifferentialSweep`
  用随机操作序列（含非法参数、回退、跨周期大跳、换发）逐步比对错误类别、记录 ID、
  全部持证人的当前视图与随机历史时刻视图，日志打印每步输入、输出与判定依据。
- **并发等价**：`TestConcurrentEquivalence` 并发执行后按审计日志的串行顺序重放，
  逐步结果与最终状态必须完全一致；`-race` 下通过。

## 7. API 一览

- `NewService(Config)`：配置含周期长度、总要求、必修最低、必修/选修上限、宽限天数、
  结转上限、更正窗口天数。
- `RegisterHolder(holderID, issueDate, now)`：注册；失效后可同 ID 重新注册为新一代。
- `RegisterCredit(holderID, category, credits, earnedDate, org, now) (recordID, error)`。
- `CorrectCredit(holderID, recordID, org, newCredits, now)` / `RevokeCredit(...)`。
- `GetAccounting(holderID)` / `GetAccountingAt(holderID, asOf)`：当前与历史核算视图。
- `AuditLog()`：全部操作（含被拒绝）的审计日志，用于重放与并发等价验证。
- 错误类别（按检查优先级）：参数非法 > 时钟回退 > 持证人或记录不存在 > 状态不允许
  > 重复登记 > 超出更正期限 > 证书已失效。
