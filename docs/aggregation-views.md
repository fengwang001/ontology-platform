# 聚合视图子系统设计说明

## 1. 目标与模型

一个聚合视图（`ViewDef`）声明：

- 分组对象类型 `GroupType`；
- 被聚合对象类型 `AggType`、被求和的数值属性 `ValueProperty`；
- 把被聚合实例连到分组实例的链接类型 `LinkType`；
- 多分组归属贡献策略 `Contribution`（必填，无隐式默认）。

视图结果对每个分组维护 `(Sum, Count)`：`Sum` 是当前真实归属于该分组、且
属性处于“存在”状态的全部实例的属性值之和；`Count` 是参与求和的实例数。

属性“不存在”（`Optional.Present == false`）与取值为零严格区分：不存在时
贡献为零且不计入 `Count`；值为零时计入 `Count` 且对 `Sum` 贡献零。

### 多分组归属策略

一个实例可经多条同类型链接同时归属多个分组，视图必须显式声明贡献方式：

- `PolicyFullEach`：对**每个**当前所属分组各贡献完整值（直接满足“不允许
  静默只算入一个分组”）。
- `PolicyDenyMulti`：禁止同时多归属；第二次归属以 `ClassPolicyRejected`
  被拒绝且不改任何状态，唯一现有归属贡献完整值。

> 关键取舍：没有提供“按归属数均摊”这类隐式加权，因为它会让一次归属变化
> 触及该实例的全部分组（更新数量随归属数变化），与“归属改变只触及常数份
> 聚合结果”冲突。若未来需要，应作为新的显式策略而不是默认行为。

## 2. 包结构

- `ontology/`
  - `model.go`：视图定义、可选值、聚合结果、内部成员/分组状态。
  - `errors.go`：固定错误类别与优先级。
  - `store.go`：底层对象 / 链接 / 属性存储原语 + 成员版本号 + 单元快照。
  - `engine.go`：引擎、原子处理单元（快照/恢复）、变更日志。
  - `engine_ops.go`：六个操作与查询。
- `naive/recompute.go`：独立朴素全量重算参考模型，只依赖 `Store` 读原语，
  与引擎不共享任何派生状态或代码路径。
- `changelog/log.go`：把每次变更的输入、受影响分组、判定依据与前后值打印
  成固定格式日志。
- `ontology/engine_test.go`、`ontology/differential_test.go`：测试。

## 3. 增量维护算法

引擎为每个视图维护两份派生索引（从不被外部写入）：

- `member[aggID] = {groups[], contrib[group], present[group], memberVersion}`：
  实例当前归属及每条归属的**已缓存贡献**；
- `group[groupID] = {sum, count}`：分组聚合结果。

所有变更只做局部增量，绝不重扫无关分组：

- **属性写入**：读旧值，对 `member[aggID].groups` 中每个分组加
  `delta = new-old`，`count += present(new) - present(old)`，并更新缓存。
  触及分组数等于该实例当前归属数，与其他分组大小无关。
- **加链接**：新分组加当前值（一份）。
- **删链接**：旧分组按缓存的“最后已知贡献”扣除（一份）。
- **原子迁移 `Reparent`**：同一处理单元内旧分组扣除缓存贡献、新分组加上
  当前值，正好两份。
- **删分组**：断开指向它的全部链接，删除该分组聚合文档；被聚合实例对象
  与属性不受影响。
- **删被聚合实例**：按每条当前归属的缓存贡献从相应分组扣除，再删除对象，
  全部在同一处理单元内。

### 为什么“归属改变恰好常数份”且不依赖分组大小

删/加一条链接时，被修改的聚合文档恒为该链接两端的分组（迁移为旧、新两
份）。贡献直接从被迁移实例的缓存 `contrib[group]` 读取，无需枚举目标分组
的成员；成本只与被迁移实例的链接数有关，与目标分组当前成员总数无关。测
试 `TestReparentConstantTouches` 断言 `TouchedCount == 2`，且该断言不随
任何分组成员数变化。

### 属性变化与归属变化为何不会错配

每个操作都在引擎互斥锁内作为一个处理单元串行执行，底层存储写入与派生聚
合更新位于同一临界区，因此全部历史等价于某个串行顺序。属性写入按“当前
归属集合”更新；迁移按“迁移时读到的值”搬移。两种次序都不会出现旧值计入
新分组或新值留在旧分组（`TestConcurrentWriteAndMoveSerializability`）。

## 4. 并发归属冲突

每个 `(LinkType, aggID)` 维护单调递增的 `memberVersion`，任何增删该实例
链接的操作都使其 +1。`Reparent` 采用乐观并发：调用方先读版本，提交时若
版本已变则以 `ClassConcurrentConflict` 拒绝且**不产生任何状态变化**（版本
检查在所有写入与失败钩子之前）。因此两个并发迁移到不同分组时恰好一个成
功、一个被拒绝（`TestConcurrentReparentOneWinner`）。

## 5. 原子处理单元与回滚

`runUnit` 执行前对派生状态与底层存储各取一份深快照；单元内若任何一步失
败（`txnPanic`）或失败钩子触发（`abortErr`，用于在提交前注入故障），两
份状态整体恢复，错误归类为 `ClassTxnFailed`。因此“属性写一半 / 只扣未加
/ 只加未扣”的中间状态对外不可见。`TestProcessingUnitRollback` 同时校验
聚合与底层属性都回到单元前的值。

## 6. 错误分类与固定优先级

| 类别 | 优先级（小者优先） | 触发 |
| --- | --- | --- |
| `ClassGroupMissing` | 100 | 分组实例不存在 |
| `ClassTypeNotParticipating` | 90 | 被聚合实例不属于视图声明的被聚合类型 |
| `ClassPolicyRejected` | 85 | 视图策略禁止该配置（DenyMulti 下二次归属） |
| `ClassConcurrentConflict` | 80 | 迁移的成员版本不匹配被拒绝 |
| `ClassTxnFailed` | 70 | 处理单元内更新失败，整体回滚 |
| `ClassInvalid` | 10 | 其他非法请求 |

多条件同时成立时返回优先级最高者。校验顺序固定为：分组存在性 → 类型参
与 → 策略 → 版本冲突；冲突被拒时单元不进入更新阶段，也不会触发事务失败
（`TestErrorPriority`）。

## 7. 查询一致性

`Query` 在同一锁内读取派生聚合文档；每个提交单元对底层数据与派生状态是
原子的，且增量更新保持

`group[g].sum = Σ_{当前链接(m,g) 且 属性存在} value(m)`

（加/删链接与属性变化都只是该式两边的局部差量），所以任意时刻查询都等
价于对当前真实数据的全量重算。`TestDifferentialRandomOps` 在每条随机操
作后都用独立朴素模型逐分组交叉验证，并在结束时整体对拍。

## 8. 被放弃的方案

- **查询时全量重算**：简单但属性变化要重扫分组，违背“只更新当前归属分组
  / 常数触达”；仅保留为独立参考模型。
- **按归属数隐式均摊贡献**：一次归属变化会波及该实例全部分组，更新数量
  不再是常数，放弃。
- **MVCC / 时间戳排序**：对单机库内子系统是不必要的复杂度；单处理者 +
  成员版本号乐观 CAS 已给出串行等价与“一胜一拒”语义。落到分布式存储时，
  处理单元对应一个可序列化事务，CAS 对应基于成员版本号的条件写入。
- **异步事件最终一致修正聚合**：会暴露查询偏差窗口，违背“任意时刻查询与
  当时底层数据一致”，放弃。

## 9. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin
go test ./... -race -count=1                       # 全量 + 竞态检测
go test ./ontology -v -run Differential -count=1   # 对拍并打印变更日志
go vet ./...
gofmt -l .
```

测试覆盖：多分组贡献、DenyMulti 拒绝、不存在与零值区分、常数触达断言、
属性写/迁移并发串行等价、并发迁移一胜一拒、两类删除级联、处理单元回滚、
错误固定优先级，以及 1200 步随机增删改写与朴素全量重算的逐步交叉对拍。
