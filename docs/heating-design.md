# 城市供热管网阀门隔离与停供影响推演服务 — 设计说明

## 模块划分

实现位于 `heating` 包，按职责分为五个协作模块：

| 文件 | 职责 |
| --- | --- |
| `heating/model.go` | 领域类型（节点类别、阀门状态、管段端）与可区分错误 |
| `heating/network.go` | 管网状态：拓扑/阀门变更、供热状态（hot）维护、并发控制 |
| `heating/isolation.go` | 隔离域推演（只读，两阶段算法） |
| `heating/impact.go` | 停供影响计算（只读，局部 BFS + 分量判定缓存） |
| `heating/execute.go` | 执行隔离与修复完成（全有或全无、引用计数恢复） |

另有 `heating/naive` 独立朴素参考模型，仅供随机对照测试使用。

## 关键取舍

### 隔离域算法：两阶段不动点

第一阶段从目标管段出发扩展隔离域：域内管段某端若已关闭则该方向不相通，
跳过；否则对每个相通的邻接管段，其在此端的阀门缺失或卡死在开时，把该
邻接管段并入域中（热源节点的端不在此扩展）。第二阶段对**最终**域的边界
收集需关闭的阀门：域外邻接管段在边界端的阀门（开则列入待关集合，已关/
卡死在关视为已满足）；域内管段位于热源节点的端必须关闭该端自身阀门，
缺失或卡死在开则报无法隔离。

之所以分两阶段：第一版在扩展过程中顺带收集阀门，随机对照测试发现结果
依赖扩展顺序（某邻接管段“是否已在域中”随顺序变化），违反“结果对同一
状态唯一”。改为先求最小不动点、再对最终域边界收集后，结果与顺序无关。

### 边界阀门的归属

边界处关闭的是**域外邻接管段**那一端的阀门，域内管段自身端上的可动阀门
不需要关闭（规格要求）。唯一例外是热源节点：热源直接向节点注入热量，
关闭邻接管段挡不住，必须关闭域内管段自身在热源端的阀门，否则无法隔离。

### 停供影响的语义

“失去供热的用户”取**增量语义**：当前有热、隔离生效后无热的用户入口。
当前已无热的用户（例如因其他进行中的隔离）不计入。叠加影响通过两点
保证：假想状态在当前状态（含其他泄漏与阀门状态）之上叠加；判定“此前
是否有热”使用由写操作维护的 hot 快照。

### 推演的局部性

规格要求推演开销只与受影响区域相关。为此：

- 每次写操作后从热源做全网 BFS 重算 hot（写操作不受局部性约束）；
- 推演只做两次局部遍历：隔离域不动点（只碰域及边界管段）与停供影响
  BFS（只从域及边界触及的节点出发）；
- 影响 BFS 用“分量是否含热源”的判定缓存：含热源的分量一旦遇到热源
  或命中缓存即提前退出，不会扫描全网。

`Plan.ExploredSegments/ExploredNodes` 暴露推演访问量，
`TestSimulationLocality` 用两档规模（链长 300 与 2400）验证访问量完全
相等。

### 执行与修复

- `ExecuteIsolation(seg, expected)` 在同一临界区内重新推演并校验
  `expected`（调用方此前推演得到的待关集合，可传 nil 跳过校验）；
  不一致则报 `ErrValveStateChanged`，整体拒绝，状态不变。
- 每次隔离记录 `needs`（边界全部需关阀门，用于跨隔离引用计数）与
  `closed`（本次实际关闭的阀门）。阀门上有 `closedByIsolation` 标记，
  区分“隔离关闭”与“他人手工关闭”。
- `CompleteRepair` 撤销泄漏标记；对不再被任何活动隔离需要、且
  `closedByIsolation` 为真、当前确为关的阀门恢复为开。手工关闭与
  卡死在关的阀门因此都不会被误开。

### 并发

单个 `sync.RWMutex`：写操作与执行/修复持写锁，推演持读锁。所有公开
方法的效果等价于某个串行顺序；推演在临界区内完成，读到一致快照。

## 被放弃的方案

- **推演时临时做全网前后两次 BFS 求停供影响**：实现最简单（朴素模型即
  如此），但开销随全网规模增长，违反局部性要求，仅保留为对照模型。
- **扩展过程中顺带收集边界阀门**：如上所述结果依赖扩展顺序，被两阶段
  算法取代。
- **用并查集/动态连通性结构维护全网分量**：能进一步加速影响判定，但
  支持删除（拆管段、开阀门）需要复杂的动态连通性算法，收益不成比例。
- **修复时只按 `closed` 集合恢复**：共享边界阀门的场景下，后执行的隔离
  并未“关闭”已关的共享阀门，若只按 `closed` 恢复，最后一个隔离结束时
  无人重开共享阀门。改为按 `needs` + `closedByIsolation` 标记恢复。
- **停供影响取全量无热用户**：与“失去供热”的语义不符，且会重复报告
  其他隔离已影响的用户，采用增量语义。

## 本地验证方法

```bash
# 全部测试（单元 + 随机对照 + 局部性 + 并发）
go test ./heating/

# 竞态检测
go test -race ./heating/

# 查看随机对照日志（输入、输出与判定依据）与局部性证明
go test -v -run 'TestDifferential|TestSimulationLocality' ./heating/

# 两档规模推演耗时基准
go test -bench BenchmarkSimulate -run xxx ./heating/
```

测试覆盖：环网失一路仍有热、边界卡死在开/缺阀导致域扩大、卡死在关无需
操作、域扩展到热源端无法隔离、两个隔离共享边界阀门后先后修复、抢修管段
拆除拒绝、手工关闭阀门修复不误开、错误固定次序、执行全有或全无、推演
只读且确定、40 组随机拓扑 × 百余操作与朴素模型逐步对照、两档规模局部
性、并发混合调用与同一管段并发执行/修复。
