# 分页游标图遍历设计

## 目标

服务在首次请求时创建确定快照，之后同一条游标链上的所有页面都只读取该快照。调用方每次提交批次大小和运行模式；模式在首次请求确定，后续请求不得修改。

支持两种限额模式：

- `SILENT_DROP`：某一跳候选数超过该跳限额时，超额候选被丢弃，返回中没有标记。
- `EXPLICIT_TRUNCATION`：同样丢弃候选，但返回一个 `TruncationMarker{Hop, Dropped}`，指出跳号和丢弃数量。

## 数据模型

- `Graph`：带读写锁的可变图，保存对象、链接和每个对象的出边索引。
- `Snapshot`：创建时深拷贝对象、链接和出边索引；后续增删改不影响已有快照。
- `ResultItem`：一个遍历结果，包含 `Hop`、对象，以及到达该对象的链接；起始对象的 `Link` 为空、`Hop=0`。
- `Page`：包含本页结果、截断标记、下一页游标和是否完成。

## 遍历顺序

遍历是确定性的广度优先遍历：

1. 起始对象作为第 0 跳第一个结果。
2. 每跳按上一跳前沿的对象顺序扩展。
3. 同一对象的出边按链接 ID 字典序排列。
4. 先得到该跳全部候选，再应用该跳限额。
5. 限额之后再做全局对象去重，并形成下一跳跃前。

先限额后去重是有意选择：`Dropped` 表示被跳限额排除的原始扩展候选数，而不是去重后剩余数量。这使静默丢弃和显式截断看到的是同一结果集合，只相差元数据。

## 快照与并发修改

首次请求在服务互斥锁内只调用一次 `Graph.Snapshot()`，并把不可变快照存入遍历会话。之后：

- 删除对象或链接不会改变本遍历已经保存的结果。
- 新增对象或链接不会进入本遍历。
- 下一页不需要按当前图重新解析位置。
- 只要游标属于该会话且序号正确，就能从保存的流式遍历状态继续。

这满足“全部页面等价于在确定快照上一次性遍历后再切页”。快照的代价是保留遍历所需的旧对象和链接；在本实现中快照直接深拷贝整图，优先保证语义简单和可验证，适合作为库级参考实现。

## 游标

游标 token 是：

```text
base64url(JSON{traversal_id, sequence}).base64url(HMAC-SHA256(...))
```

服务端会话保存：

- 不可变快照；
- 首次确定的模式、跳限额和最大跳数；
- 当前流式 BFS 引擎；
- 下一个允许的序号；
- 已处理页序号和计数。

游标不保存返回历史，也不通过重放旧页确认位置。每个有效下一页请求只按 `traversal_id` 定位一次会话，再比较一次单调序号。因此确认“哪些内容已经返回”的历史记录访问量是每请求 O(1)，不随已返回条数增长。

序号比较同时拒绝：

- 伪造或签名错误游标；
- 其他服务实例或其他遍历的游标；
- 已使用游标；
- 指向已返回位置之前的旧游标。

最后一页提交后序号仍推进；再次使用最后一次请求游标会因序号不匹配被拒绝，不会重新开始遍历。

## 分页和截断标记

页面循环只按结果项填充批次大小。截断标记是独立事件，不占结果项位置，也不改变批次大小。标记在对应跳的结果之后自然出队：

- 若标记在当前页填充期间到达，就放在当前页。
- 若当前页刚好在标记前填满，标记保存在引擎预读项中，下一页第一个返回。

批量填满后使用只读预读判断是否真的结束。若预读到结果或标记，返回下一页游标；若没有事件，则最后一页标记 `Complete=true`。

## 错误次序

固定错误码与判定次序：

1. 首次请求：起始对象不存在，返回 `START_OBJECT_NOT_FOUND`。
2. 提供游标时：游标无法解析、签名错误、快照会话未知或序号不匹配，返回 `INVALID_CURSOR`。
3. 批次大小不是正整数，返回 `INVALID_BATCH_SIZE`。
4. 后续页模式与首次模式不同，返回 `MODE_CHANGED`。

对后续页，游标错误先于批次大小，批次大小先于模式变更。实现中对应分支顺序固定，不依赖内部 map 迭代。

## 并发

`Service` 使用一个互斥锁串行化分页会话的创建、游标校验、页面推进和日志追加。`Graph` 自身另有读写锁保护结构修改和快照创建。因此：

- 同一条游标链的并发请求只会有一个请求匹配当前序号，其余请求被拒绝；
- 不同遍历互不等待对方遍历逻辑，只在短暂服务临界区上同步；
- 页面推进与图修改可以并发，但每个遍历读取自己的不可变快照；
- 所有成功页面都能视为存在某个全局顺序，在该遍历开始快照上被依次切出。

## 被放弃的方案

- **游标只保存对象 ID/链接 ID**：对象或链接删除后会失效，也无法在并发插入后恢复相同顺序，因此放弃。
- **每页从活图重新计算到 offset**：读取量随已返回条数线性增长，且并发修改会破坏去重和完整性，因此放弃。
- **游标保存完整返回 ID 集合**：可恢复性较好但状态随结果数线性增长，无法满足历史记录 O(1) 的要求，因此放弃。
- **MVCC 增量引用计数**：适合生产级大图，可减少快照拷贝，但实现复杂；当前目标是清晰可验证的参考语义，故采用深拷贝快照。

## 可验证性

测试使用固定随机种子，复现图结构和遍历参数：

- 删除测试：首页后删除后续对象和链接，后续页面仍返回快照中的对象、链接且不重复。
- 模式对照：相同图、相同限额分别验证静默模式无标记，显式模式给出跳号和丢弃数。
- 游标安全：覆盖格式错误、跨服务游标、已使用游标和旧游标。
- 模式锁定：第二页提交不同模式被拒绝。
- 并发交织：首页确定快照后，后续页与图修改并发执行，再与朴素快照实现对照。
- 随机预言机：大量固定种子随机图，对照 `FullTraversal` + `ChunkFullTraversal` 的独立朴素实现。
- O(1) 历史记录：`HistoryChecks()` 统计全局和每次遍历的会话定位次数，断言第 N 页之后仍为 N-1 次。
- 日志：`Logs()` 深拷贝每次请求的入站游标、模式、返回结果和截断标记。
