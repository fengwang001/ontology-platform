# 动作副作用补偿回滚子系统 — 设计说明

## 1. 问题模型

一次动作声明若干条**副作用分支**：

- 分支之间是 DAG 依赖：`B.DependsOn=[A]` 表示 B 必须等 A
  **完全生效**（全部子操作成功）后才能开始；无依赖的分支相互
  独立，可任意交织并发。
- 分支内部是顺序子操作列表，严格按声明顺序生效。
- 分支失败条件：内部任一子操作失败，**或**任一上游分支最终失败。
  上游失败沿依赖边向下游传播，下游一个子操作都不会启动。
- 补偿顺序是正向依赖的逆向拓扑：被依赖分支必须等所有直接/间接
  下游都补偿完成后才可补偿；分支内按已生效子操作**逆序**。

## 2. 关键数据结构

| 结构 | 职责 |
| --- | --- |
| `Graph` | 对象图，以 `key -> int64` 建模可原子修改的属性单元；原语 `Get/Add/Snapshot`。 |
| `Operation` / `Inverse` | 子操作与其逆操作接口；`Apply` 失败必须不留改动，`Undo` 可单独注入失败。 |
| `Executor` / `Action` | 声明校验、正向并发调度、补偿门禁与状态机。 |
| `LockManager` | 跨动作的键级严格两阶段锁，保证动作间可串行化。 |
| `Logger` | 每次补偿尝试的输入/结果/判定依据日志钩子。 |

### 2.1 补偿门禁：O(1) 的剩余下游计数

对每条分支维护原子计数：

```
remainingDownstream[b] = 依赖 b 且尚未完成补偿的直接下游分支数
```

它就是"逆向依赖图"上 b 的入度。初始化时按声明计数；每当某个下游
分支完成补偿，只沿它自己的 `DependsOn` 列表给各上游计数减一
（触达边数 = 该分支声明的依赖数，与全图分支总数无关）。

- 判断 b 能否开始补偿：`remainingDownstream[b] == 0`，**一次原子
  读，O(1)，不遍历分支集合**。等待时阻塞在 b 自己的广播 channel
  上（计数与 channel 在同一把快照锁下读取，杜绝漏唤醒）。
- 基准实测（`BenchmarkCanCompensate`）：10 条分支约 21 ns/op，
  10000 条分支约 15 ns/op，开销不随后者增长。

### 2.2 正向调度

每条分支一个 goroutine。等待上游时读取上游结果（`outcomeMu`
读写锁保护），未决则阻塞在该分支的 `doneCh` 上：

- 全部上游 `succeeded` → 顺序执行本分支子操作；每成功一步登记
  `appliedStep{index, inverse}` 到本分支的已生效栈。
- 任一上游失败 → 本分支记 `KindUpstreamFailure`（含触发上游名），
  立即结束，不启动任何子操作。
- 子操作失败 → 记 `KindOperationFailure`（含子操作下标与原因），
  该分支后续子操作不再执行。

任一失败后，`Execute` 自动执行全图补偿；全部成功则动作保持生效，
  调用方负责 `Release()`（或后续按需直接补偿）。

### 2.3 补偿调度

- **无依赖关系的分支允许并发补偿**（明确结论）。理由：
  1. 语义上无先后约束，需求不限制其相对次序；
  2. 对象图访问受键级锁约束，键集不相交的分支物理并行；
  3. 冲突键上的参考原语是 `Add`（交换 + 结合），任意交织净效应
     相同，因此并发终态必然等价于"存在至少一个合法拓扑顺序逐一
     补偿"的终态，与各分支相对快慢无关。
- 有依赖的分支在门禁处阻塞；门禁放行后在 `compMu` 上抢占，
  保证同一分支的逆操作只执行一次（自动补偿与外部直接补偿竞争时
  后到者等待完成广播，共享失败记录，不重复撤销）。
- 分支内逆序逐个 `Undo`。
- 某个逆操作失败后**继续**执行剩余逆操作（best-effort），每个
  失败单独成为一条 `KindUndoFailure`（分支名 + 子操作下标 +
  原因），因此多分支、多子操作的补偿失败互不遮蔽。

> 取舍：逆操作失败后继续执行剩余逆操作，而不是中止本分支补偿。
> 这样能保留最多的失败定位信息（需求明确要求失败信息完整不遮蔽），
> 语义上对应"每个逆操作只对自己负责的那一步生效/失败"。此时该
> 分支仍被标记为补偿完成并放行其上游的门禁——因为门禁表达的是
> "下游已无更多补偿动作会发生"，而不是"下游已完全恢复"。未恢复
> 的残留值由汇总报告中的 `KindUndoFailure` 精确指出，交由上层
> 人工或更高级 Saga 处理。

### 2.4 直接补偿请求的拒绝

`Action.DirectCompensate(branch)`：

1. 先做门禁判定（O(1) 计数 + 本分支状态）；若仍有下游未补偿，
   返回 `KindCompensationOrderViolation`，错误信息列出仍阻塞的
   直接下游；**不执行任何逆操作、不改变任何计数与对象图**。
2. 每次拒绝也写一条日志（`allowed=false result=rejected`，
   `reason=blocked-by=[...]`）。
3. 放行则获取动作键锁（与其他动作串行化）→ 逆序补偿 → 释放。

### 2.5 动作间并发：严格两阶段锁

`LockManager.LockAll` 在动作开始前按**键名字典序**一次性获取其
触碰的全部键锁，动作（含自动补偿）结束后统一释放：

- 有序加锁 ⇒ 不可能形成加锁等待环 ⇒ 无死锁；
- 键集冲突的动作在锁上串行，冲突可串行化等价于某个串行顺序；
- 键集不相交的动作完全并行。

### 2.6 环检测

`Declare` 在获取任何锁、触碰对象图之前完成：名字唯一性、依赖
引用合法性、DFS 三色标记找环（返回从入环点回到自身的名称路径）。
任一失败直接返回，被拒绝声明不产生任何可观察改动。

## 3. 错误分类与固定优先级

数值越小优先级越高；多条件同时满足时 `Report.Kind()` 取最高优先级
类别，但**全部**错误仍逐条保留在 `Report.Errors`，可用
`Report.ByKind` 分别取回：

| 优先级 | 类别 | 含义 |
| --- | --- | --- |
| 1 | `KindDependencyCycle` | 声明环被拒绝（任何生效之前） |
| 2 | `KindUpstreamFailure` | 分支因上游失败被动失败 |
| 3 | `KindOperationFailure` | 子操作自身生效失败 |
| 4 | `KindCompensationOrderViolation` | 违反补偿顺序的直接请求被拒绝 |
| 5 | `KindUndoFailure` | 逆操作执行失败 |

## 4. 被放弃 / 未采用的方案

- **全局单一补偿队列按拓扑序串行撤销**：实现简单且天然有序，但
  放弃了无依赖分支间的并行度，不符合"独立分支可任意交织"的模型，
  也无法暴露真实并发下的交织问题。保留为独立参考实现（见下）。
- **每次询问门禁时遍历全部分支检查下游状态**：O(B) 且在大动作上
  随分支总数线性增长，被 O(1) 剩余入度计数取代。
- **逆操作失败即中止本分支后续撤销**：会遮蔽同分支剩余逆操作的
  成败信息，不满足"失败信息完整不遮蔽"，故放弃。
- **用 `context` 级联取消下游**：会把"被动失败"与"被取消"两种
  语义混在一起，且无法保留精确的上游来源；改为显式上游结果广播。
- **跨动作共享全局分支注册表**：需求要求不同动作的依赖互不可见、
  互不影响；依赖状态严格保持在每个 `Action` 实例内，跨动作只通过
  对象图键锁这一最小公共面交互。

## 5. 朴素串行参考模型（差分对拍）

`naive.go` 与生产实现**不共享任何调度/状态机代码**，只共享
`Graph.Add` 原语：

- Kahn 拓扑排序（名字字典序破平局，可复现）作为固定合法顺序；
- 单线程逐条分支、逐子操作正向生效并记录故障；
- 补偿时把全局已生效栈整体逆序撤销——这天然同时满足
  "分支内逆序"与"被依赖者最后补偿"。

随机用例（`TestDifferentialAgainstNaiveModel`，400 轮）生成只允许
`i 依赖 j<i` 的随机 DAG（结构性保证无环），每步独立注入正向失败
与逆操作失败，比较两种实现的：对象图终态、自身失败集合、被动
失败集合、逆操作失败集合（多重集，按分支+下标定位）。

## 6. 本地验证方法

```bash
# 全量测试
go test ./...

# 竞态检测 + 重复执行（并发放大）
go test -race -count=5 ./...

# 查看每次补偿尝试日志（输入/结果/判定依据）
go test -run TestIndependentBranches -v ./...
go test -run TestDifferentialAgainstNaiveModel -v ./...

# O(1) 门禁基准：10 与 10000 条分支应同量级
go test -bench=BenchmarkCanCompensate -benchtime=1000000x -run '^$' ./compensation/

# 静态检查与格式
go vet ./...
gofmt -l .

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
```
