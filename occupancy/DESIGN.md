# 占道施工许可审查服务 · 设计说明

1. 模块划分：`types.go`（模型/操作/事件）、`errors.go`（可区分错误码与优先级）、
   `index.go`（按起点有序的区间 treap）、`rules.go`（同路段/绕行/走廊判定）、
   `service.go`+`operations.go`+`events.go`（串行化编排、抢占、延期、撤销、查询、日志）、
   `naive.go`+`naive_ops.go`（独立朴素全量重判模型，仅供差分测试）。
2. 并发：单一 `sync.Mutex` 串行化所有读写，可并发调用，结果等价于某个全局串行顺序；
   不追求锁分段，因为正确性与可复现性优先于吞吐。
3. 区间索引：每路段一棵按 `(start,key)` 有序的 treap，节点带子树 `maxEnd`/`minStart`。
   相交枚举用两端剪枝；点查沿 BST 下降到 `start<=t` 的路径，只对可能命中的
   左子树用 `maxEnd<=t` 剪枝。访问量为 O(log N + k)，k=该路段在 t 之后仍结束的
   片段数，与历史许可总数无关。基准测试见 `BenchmarkQueryVsHistory`。
4. 关键取舍：所有历史片段保留在 treap（不物理 GC 出树），以支持任意历史时刻点查；
   “不随历史增长”靠剪枝而非删除，避免了“删掉就查不到历史”的矛盾。
5. 冲突判定严格按错误码次序短路：同路段→绕行→走廊，故多类同立只报同路段；
   参数/时钟/路段/许可等校验在业务冲突之前。
6. 绕行对称：配置期预计算反向绕行表；正（全封闭挡绕行路段）反（绕行上游挡本路全封闭）
   两条规则都在每次申请时对全量既存许可判定，故与申请次序无关。
7. 走廊：对走廊内既有常规许可在候选时段做起止事件扫描求并发峰值，恰等于上限允许；
   应急许可豁免绕行与走廊，只受同路段车道数约束。
8. 应急受理：先收集并摘除同路段相交的常规已批许可→只与其他应急做车道数检查；
   检查失败原样放回（被拒不改状态）。通过后按原批准序逐份顺延：未开始整体平移、
   已开始截断并将前段归档为历史事实、剩余顺延；逐份用完整常规规则重审，先处理者
   新占用影响后处理者；失败转待重排。应急片段在重审期间作为既存占用参与同路段求和。
9. 延期：只对新增部分 `[oldEnd,newEnd)` 按新申请规则审查（本许可旧时段天然既存），
   缩短不审查；被拒不改原许可、不推进时钟。
10. 撤销：物理移除当前占用并置 Revoked，查询按许可状态过滤；不自动放行历史被挡申请。
11. 被放弃方案：(a) 用时间轮/分桶把过期片段搬走——破坏任意历史时刻查询；
    (b) 区间树+删除式 GC——删除后历史不可复现；(c) 每路段维护差分事件数组——
    点查需前缀和且抢占/撤销/顺延会改写历史事件，复现复杂且易错。
12. 可复现：treap 优先级由片段键确定性派生；接受操作记事件、许可记状态变迁；
    相同操作序列（含操作时刻）重放得到完全相同的状态历史。
13. 本地验证：`go test ./...`、`go test -race ./...`、
    `go test -run TestRandomDifferential -v ./occupancy`（40 随机种子×1500 操作
    与朴素模型对照）、`go test -bench BenchmarkQueryVsHistory -run '^$' ./occupancy`
    证明查询开销不随历史增长。
