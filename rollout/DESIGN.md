# 灰度放量流量切分器 — 设计说明

## 1. 目标与范围

在稳定版本（stable）与灰度版本（canary）之间按可复现规则切分请求，
支持分阶段放量、指标闸门自动晋级/留级/回滚、同标识归属稳定、
会话粘性、人工开始/重置/降级。时钟由调用方注入（毫秒），
不读取系统时钟，因此全部行为可在测试中确定性复现。

代码位于 `rollout/`：

- `config.go`：配置与校验、错误哨兵。
- `types.go`：版本、状态、判定来源、评估结果等枚举与快照。
- `hash.go`：标识 -> 归属位置。
- `sticky.go`：粘性记录的 map + LRU 双向链表存储。
- `rollout.go`：`Splitter` 主体（状态机、路由、观测、评估、并发）。
- `doc.go`：包文档。
- `*_test.go`：边界单测、朴素参考模型、1200 组随机差分序列、基准。

## 2. 关键取舍

### 2.1 归属位置：FNV-1a 64 位散列取模

- `Position(id) = FNV-1a64(id) mod 10000`，纯函数、无状态、跨进程一致。
- 取模在 `2^64 mod 10000 = 7536` 个余数上有约 `2^64/10000` 个原像，
  其余余数多一个，相对偏差约 4e-13，工程上视为均匀；
  单测用 10 万标识做 10 桶 ±3% 均匀性粗检。
- 放弃一致性哈希环：需求是“同一标识在固定比例下归属恒定”，
  单散列即可；哈希环引入环点维护与额外的实现/测试复杂度，且
  “比例只增不回退”的单调性由取模阈值天然保证（位置 < 比例）。
  若未来需要“每个阶段独立选桶、并严格保持已放量集合不缩”，
  可在位置之上再叠加阶段位掩码，不影响当前接口。

### 2.2 路由优先级

严格按规范短路：

1. 已回滚：直接 stable + `force_stable`，**不读也不写**粘性；
   进入回滚态时清空全部粘性。
2. 未过期粘性（`0 <= now - atMs < L`，左闭右开）：沿用记录版本，
   并把该记录的时刻刷新为 `now`（LRU 头）。
3. 否则按比例：`Position(id) < ratio => canary`，并写入/刷新粘性。

关键点：粘性读取是纯查找，不改 LRU 顺序；命中后才 `touch` 刷新。
过期记录不在读取时删除（无收益，且会使 lookup 变成写操作），
在该标识下次路由时被按比例结果覆盖；容量淘汰只在插入时发生。

### 2.3 粘性淘汰：map + `container/list`

- 查找/刷新/插入/淘汰均摊 O(1)；记录条数恒不超过 P（P=0 表示禁用）。
- “最久未被路由”由链表序（front=MRU, back=LRU）精确表达，
  刷新时刻即 MoveToFront，淘汰永远取 Back。不依赖时间戳比较，
  同一时刻多次路由也有确定顺序。
- 放弃“定时扫描过期”：过期与否只在路由点判定即可，避免后台协程、
  额外时钟与生命周期管理，也避免扫描成本随 P 增长。

### 2.4 评估与精确比较

评估顺序（持锁）：时钟校验 -> 非 Running/驻留未满 `DwellNotMet`
-> 灰度样本 < G `Insufficient` -> 错误率闸门。

- 驻留：`now - enteredAt >= D`，恰好相等视为满（单测覆盖 D-1/D）。
- 样本：恰为 G 才判定，G-1 返回样本不足，两种“不晋级”都不累计失败、
  不清窗口，下一次评估可复用窗口内样本（规范未要求此时清窗，
  保留样本才能在同一驻留窗口稍后成功判定）。
- 错误率比较全程整数（`math/big`），不使用浮点：
  - 稳定无请求时其错误率按 0 处理；
  - 判定 `gc/gn <= sc/sn + T/10000` 交叉相乘：
    - `sn > 0`：`gc*10000*sn <= sc*10000*gn + T*gn*sn`
    - `sn == 0`：`gc*10000 <= T*gn`
  - `<=` 保证“恰好等于稳定 + 容差”判通过（单测有恰好相等、
    差 1 个万分之一即失败两组）。

通过：清零失败累计与窗口；非末阶段 `idx++` 并以 `now` 重算驻留；
末阶段进入 Completed，比例保持末阶段值。
失败：失败累计 +1；达到 F 立即回滚（清粘性、清窗、清累计）；
否则留级——清窗并把驻留起点重设为 `now`（单测验证通过清零累计）。

### 2.5 状态机与人工操作

- NotStarted --Start(t)--> Running(idx=0, enter=t)
- Running --pass 末阶段--> Completed；--连续 F 次失败--> RolledBack
- RolledBack 只有 Reset 可离开；Completed/NotStarted/Running 均可 Reset。
- Downgrade 仅 Running 且 idx>0：idx--，窗口/失败累计清空，
  enter 重算，**粘性原样保留**（单测覆盖降级后粘性仍生效）。
- 观测在非 Running 下静默忽略（不报错），但仍先做时钟校验：
  被接受（含被忽略）的调用携带的时间戳会更新时钟基线，
  被拒绝的调用不改变任何状态与时钟。

### 2.6 错误优先级

所有带时间戳的方法固定按 **参数非法 > 时钟回退 > 状态不允许**
检查；`Observe` 的版本枚举非法在加锁前即返回参数非法。
错误哨兵：`ErrInvalidArgument`、`ErrClockRewound`、`ErrIllegalState`，
用 `errors.Is` 判断。`Reset()` 无参数、无错误（任何状态可用）。

### 2.7 并发模型

单一 `sync.Mutex` 保护全部可变状态，锁内只有 map/链表/整数运算，
无 IO、无回调。每个方法整体持锁，因此并发历史必然等价于
“按获取锁的顺序排列”的某条串行历史（线性化点即锁获取点）。
放弃分片锁/RWMutex：读路径也会刷新粘性（写 LRU），读写并不对称，
单锁最简单且不会自锁；吞吐成为瓶颈时可再按标识分片。

### 2.8 “开销不随历史请求总数增长”如何保证与验证

- 观测只维护当前窗口 4 个计数器，O(1) 且无历史留存；
  阶段切换/失败留级/回滚/重置即丢弃窗口。
- 路由只触及 1 个 map 项与至多 P 个链表节点的链表；
  历史请求再多，粘性记录也被 P 封顶，不存在随请求增长的结构。
- 基准 `BenchmarkRouteBoundedByP`（P=16/256/4096）展示热路径
  耗时不随前置种子请求数变化；`BenchmarkObserve` 为纯计数开销。
- 并发安全由 `go test -race` 验证。

## 3. 被放弃的方案

- **浮点错误率**：边界（恰好等于稳定+容差）会出现 0.1+0.2 类误差，
  放弃，改整数交叉相乘；计数理论上可超 int64，用 `math/big` 杜绝溢出。
- **后台 TTL 清理协程**：需要额外生命周期/时钟注入，且成本随 P 变；
  改为惰性判定（路由点比较，插入点覆盖/淘汰）。
- **时间戳堆/队列做淘汰**：需求是“最久未被路由”，LRU 链表是其
  标准数据结构；时间戳只决定过期，不决定淘汰先后（同时刻多路由
  会带来平局歧义，链表序没有此问题）。
- **读多写少用 RWMutex**：粘性命中也要刷新时刻与 LRU 位置，
  实质是写；单互斥锁更直接。
- **Reset 保留时钟基线**：规范要求“清空除配置外的全部状态”，
  时钟回退基线也属运行态，故一并清空，使重置后旧时间戳可复用。

## 4. 本地验证方法

需要 Go 1.26+。若 `go` 不在 PATH（本机在 `/usr/local/go/bin`），
先 `export PATH=$PATH:/usr/local/go/bin`；若默认构建缓存只读，
设置 `export GOCACHE=/tmp/gocache`。

```bash
# 全量测试（含竞态检测）
go test -race ./...

# 随机差分（1200 组 x 250 事件），-v 打印前三组逐步日志：
#   每步输入、real/naive 输出与判定结果，末尾汇总日志字节数
go test -race -run TestDifferentialRandomSequences -v ./rollout

# 复杂度基准
go test -bench . -benchmem -run '^$' ./rollout

# 静态检查与格式
go vet ./...
gofmt -l .
```

差分测试中的朴素模型（`naive_test.go`）用切片线性扫描、
独立的状态转移代码与独立的分数比较重新实现规范，
与生产代码不共享内部逻辑；两者逐条比较返回值、错误、
状态、窗口计数以及粘性记录的内容与 LRU 顺序。
