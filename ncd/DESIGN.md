# 车险无赔款优惠等级续保定级引擎 — 设计说明

## 模块职责
- `engine.go`：配置校验、全局时钟、互斥锁串行化入口、各操作的拒绝次序。
- `insured.go`：被保人状态（年度链、出险、追补、保单审计）、年度二分定位、追溯重定级。
- `grading.go`：单年度等级升降裁定纯函数（升一/降二/三次归零/保护抵首次）。
- `errors.go`：可区分错误码，声明顺序即拒绝优先级。

## 关键取舍
- 年度记录内增量维护有责次数与保护标志，常规续保只读上一年度汇总，O(1) 与历史
  长度无关；用 `LastOpSteps` 探针在测试中证明（10 年与 2000 年历史访问数同为 1）。
- 迟报/撤销/补购保护后只重算事故年度之后的年度（探针验证访问数 = 后续年度数）；
  之前年度输入不变，结论必然不变，故无需重算。
- 重定级与在案等级逐年比较：降低产生追补（新保费减旧保费），升高只更新不退费；
  首年（含中断清零年）标记 base，等级恒 0 不参与重算，中断后历史年度仍可归因迟报。
- 续保窗口外按方向区分：早于左端报「续保窗口外」，晚于右端视为中断清零（成功），
  否则「续保窗口外」永不触发，与拒绝次序中它的存在矛盾。
- 保护只抵消降级不转为升级：有有责出险即不满足「无有责出险升一级」。
- 保护作用于购买日所在年度；若已提前续保出未来年度，购买后重算可能使其升高。
- 全局一把互斥锁换取可线性化语义：并发结果等价于锁获得顺序的串行执行。
- 时钟为引擎级整数天，只允许前进；被拒操作在任何状态变更前返回，不留痕。

## 被放弃的方案
- 按被保人分锁：提升并发度但引入跨被保人时钟一致性与死锁风险，收益不明确。
- 事件溯源重放：每次查询全量重放，语义最简但续保 O(历史) 不满足性能要求。
- 撤销时冲销已产生追补：与「升高不退费」规则冲突，故追补记录保留、只回滚等级。

## 本地验证
- `go test ./ncd/`：规则单测（窗口取等/中断清零/门槛取等/降四级/三次归零/最高级/
  保护语义/迟报追补/升高不退费/撤销等价/转移继承/拒绝次序逐对/被拒不留痕）。
- `go test -race ./ncd/`：并发迟报与续保等价于某串行顺序、多被保人并发一致。
- `go test -run TestDifferentialRandom -v ./ncd/`：8 组种子各 400 步随机序列，
  与独立朴素模型逐步对照等级轨迹与追补，日志含输入、输出与判定依据。
- `go test -run 'TestRenewalCost|TestRecomputeScope' -v ./ncd/`：性能探针证据。
