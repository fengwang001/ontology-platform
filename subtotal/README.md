# subtotal：多级小计的增量维护与撤回

`subtotal` 包对带两个分组维度（`Dim1`、`Dim2`）的行流做**三级**分组，
在增量写入/撤回的同时持续维护每一级的计数（count）与求和（sum），
并输出可被下游按序重放的变更日志。

入口类型见 `subtotal/store.go`，实现见 `subtotal/engine.go`、`subtotal/view.go`。

## 三层分组

| 层级 | 常量 | 键 | 删除规则 |
| --- | --- | --- | --- |
| 1 明细组 | `LayerDetail` | `(Dim1, Dim2)` | 计数归零即从映射删除 |
| 2 第一维小计 | `LayerSub1` | `Dim1` | 计数归零即从映射删除 |
| 3 总计 | `LayerTotal` | 固定汇总占位（`Change.Grand=true`） | 恒保留，空状态为 `{0,0}` |

- 每条增量依次更新三层，顺序恒为 **1 → 2 → 3**。
- `upsert` 插入新行或按行 ID 覆盖旧行；覆盖写被实现为「先原子撤回旧行贡献，
  再加入新行贡献」，因此每层的日志**先负向后正向**。
- `delete` 撤回一条**当前确实存活**的行。
- 内容与现有行完全相同的重复 `upsert` 是幂等 no-op，不产生任何日志。

## 变更日志（Change）

每条 `Change` 携带：

- `Seq`：进程内单调连续编号；
- `Layer`：层级号 1/2/3；
- `Dim1`/`Dim2`：该变更所属组的维度值（总计层恒为 `nil` 且 `Grand=true`）；
- `CDelta`/`Delta`：计数与求和的正负增量（撤回为负、加入为正）；
- `Count`/`Sum`：应用该条后该组的**新**计数与求和；
- `Created`：组此前不存在、由本条新建；
- `Removed`：组计数因本条归零而被删除（此时只输出这一条负向撤回）。

一致性契约：

- **任意已提交增量前缀**的日志，用 `Replay` 重放后三层自洽
  （小计 = 名下明细之和，总计 = 全部明细之和，无计数 ≤ 0 的组）；
  注意自洽边界是「整条增量」，单条增量内部允许短暂出现先删后建的中间形态。
- 下游对同一初始空状态按序应用日志，结果与维护方当前状态、
  以及对存活行集 `BatchRecompute` 的批量重算**完全一致且可复现**。

## 空值语义

- `Dim1`/`Dim2` 为 Go 的 `nil` 指针表示**真实的空值取值**，正常参与分组键
  （例如 `(NULL, NULL)` 与 `(NULL, "b")` 是两个不同明细组，但同属 `NULL` 小计组）。
- 内部键为值类型 `Key1{V, Null}` / `Key2{A, ANull, B, BNull}`，
  显式的 `Null` 标志避免空值与任何字符串碰撞，也不使用指针做 map 键。
- 总计的「全部」是第三种东西：`Grand=true` 的汇总占位，
  与某一维取 `NULL` 的真实分组严格区分。

## 组的保留规则

- 计数归零：明细组/小计组**立即删除**，变更带 `Removed=true`，只输出撤回。
- **计数 > 0 但求和为 0 的组必须保留**（例如 +10 与 -10 同行组）。
- 总计占位永不删除；没有任何行时为 `{count:0, sum:0}`。
- 金额 `Amount` 为 `int64`，允许负数；求和/计数发生 `int64` 溢出会整体拒绝。

## 非法输入与错误类别

非法输入被**整体拒绝**，返回 `*RejectError`，其 `Code` 取下列互不相同的值：

| Code | 触发条件 |
| --- | --- |
| `MALFORMED_INCREMENT` | `op` 不是 `upsert`/`delete`，或行 ID 为空 |
| `ROW_ID_NOT_FOUND` | `delete` 的行 ID 当前不存活 |
| `DETAIL_GROUP_LIMIT` | 接受该 upsert 会使明细组数超过 `New(limit)` 上限（按组数而非行数；`<=0` 不限） |
| `AMOUNT_INVALID` | 任一层计数/求和发生 `int64` 溢出，或计数会变负 |

提交采用两阶段实现：先在影子状态上完整推演整条增量并生成日志，
任何非法情形都在触碰真实状态**之前**返回。因此每次被拒都满足：
存活行集、三层映射、总计、已输出日志、`Seq` 序号**全部不变（失败不留痕）**。

## 并发

- `Commit` 持写锁，与一切访问互斥；`View`/`Log`/`Rows`/`SelfCheck` 持读锁，
  可被多个执行体并发调用。
- 不变量在任意已提交时刻成立：小计与总计恒等于明细组对应之和。
  并发测试配合 `go test -race` 验证无数据竞争。

## 本地验证

```bash
# 常规测试（测试会用 t.Logf 打印每步输入、输出日志与判定依据）
go test -v ./subtotal

# 竞态检测（含多执行体并发提交/撤回/视图/自检）
go test -race -v ./subtotal

# 全量
go test ./...
go vet ./...
gofmt -l .
```

测试覆盖：空值分组、求和为零但计数非零的组保留、撤回与组删除、
覆盖写迁移与幂等、四类非法输入、拒绝前后状态/日志逐条不变、
每个日志前缀重放自洽、与批量重算一致，以及并发读写一致性。
