# 拥堵收费结算服务 — 设计说明

1. 模块：`types.go`（类型/错误分类）、`zones.go`（区域注册表与嵌套校验）、
2. `billing.go`（按日全量重算纯函数）、`service.go`（操作 API、时钟、争议）、
3. `billing.go` 与 `service.go` 内含记账/车牌/日志等辅助；包文档置于 `types.go`；测试 3 个文件
   （`congestion_test.go` 边界用例、`naive_test.go` 朴素模型、`diff_test.go` 随机差分与基准）。
4. 关键取舍：结算 = 事件存档 + 纯函数重算。每次变更只对受影响自然日整体重算，
5. 不做增量差分，从根上保证“资格早存在”与“追溯后补登记”结果逐分一致。
6. 进入内层时候选登记顺序固定为“触达区域优先，外层按区域 ID 字典序”，
7. 使同分钟多事件可精确复现；判定依据全部写入 `ChargeLine.Reason`。
8. 金额用整数最小单位；居民折减免 = `ceil(费×减免比例/分母)`，日封顶在折扣后逐笔判定。
9. 台账语义：入账与退款都是带符号调整，恒有 `当日应付 = Σ 调整金额`，
10. 退款/补收的 Before/After 可逐笔复核；争议关闭单独记一笔 `dispute_close` 差额。
11. 争议冻结只冻结“值与依据快照”，事件与资格照常收录，关闭时一次性重算，
12. 结果与争议从未发生相同。
13. 追溯期只约束“确有事件且被新区间覆盖”的最早自然日：`登记时刻 - 追溯天数 ≤ 该日结束`。
14. 资格区间按类别（居民再按登记区域）判重叠，左闭右开；首尾相接允许。
15. 车牌变更在变更时刻即生效（恰等于进入时刻归新车牌）；资格挂在车辆上。
16. 并发：单把互斥锁串行全部状态变更，等价于某串行顺序；无锁读不需要，简单可证。
17. 时钟：服务只接受时刻 ≥ 上次被接受操作；被拒操作先于任何状态修改返回，零副作用。
18. 错误只报次序最靠前一类：非法参数 → 时钟回退 → 车辆/区域不存在 →
19. 嵌套非法 → 资格重叠 → 超追溯期 → 争议已存在/不存在。
20. 查询性能：事件按车按日分组（`dayEntry`），查询只读当日桶 + 当日台账，
21. 不扫描全量历史；基准见 `BenchmarkQueryHistory100/10000`（均约 0.7–0.8µs）。
22. 被放弃方案一：增量计费在进入时固化折后金额——会让追溯/封顶重算难以保持一致。
23. 被放弃方案二：每区域每车锁提升并发——本题写冲突集中且要求强可串行化，不值得。
24. 被放弃方案三：跨夜收费时段——会把单次进入拆到两个自然日，与“按进入时刻归属”
25. 的自然日语义冲突，故收费时段限制在当日 [00:00,24:00) 内。
26. 朴素对照模型 `naive_test.go` 独立实现逐日全量重算，不调用生产代码；
27. 随机差分测试 40 个种子、每序列 220 操作，逐步比对金额、逐行、台账不变式。
28. 操作日志：`Service.SetLogger` 后逐条打印操作名、接受/拒绝、错误类别与入参。
29. 本地验证：
30. `go test -race ./...`
31. `go test -run TestRandomDifferential -v ./congestion`（随机对照）
32. `go test -bench=BenchmarkQueryHistory -benchmem ./congestion`（查询不随历史增长）
33. `gofmt -l . && go vet ./...`
34. 重播一致性：`TestReplayDeterminism` 用相同序列跑两遍，比较全部日的金额与明细。
35. 已知边界：区域以离散网格单元集合表示嵌套关系；时区使用配置的固定/本地时区，
36. 不处理夏令时跳变；争议只能“开一次、关一次”，关闭后重开按业务拒绝。
37. 文件数：新建 `.go` 共 7 个（生产 4：types/zones/billing/service；测试 3）。
38. 不变式（任何串行位置）：`应付 + 已退 - 已补 = 以当前事件与资格一次性重算结果`，
39. 台账中即 `Σ 调整 = 应付`；关闭争议后与“无争议世界”完全相同。
