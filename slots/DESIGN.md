# 机场起降时刻协调系统 — 设计说明

## 模块划分
- `types.go`：配置、申请、系列、单元格键、历史键、快照、统一错误码与拒绝次序。
- `coordinator.go`：协调器、时钟、公司/申请、截止时一次性三段式分配。
- `operations.go`：返还（含等候名单补位）、交换、周登记。
- `usage.go`：使用率、达标判定、航季结算、确定性快照。
- `reference.go`：按同规则独立写成的朴素模型（线性扫描，无共享索引）。
- 测试：`helpers/usage/allocation/operations/rejection/diff/perf`。

## 关键取舍
- 时间用绝对 `time.Time`；周由 `SeasonStart + (w-1)*WeekLength` 推出，窗口终点取闭。
- 占用维护 `map[cellKey]int`：单元格“能否再分配”为 O(1)，不随系列总数/总周数增长。
- 新进入者持有数用 `map[airline]int` 计数，判定 O(1)；交换时同步增减。
- 等候名单按 `(星期几,小时段)` 分桶且按提交序有序；返还只扫该桶并只试覆盖该周者，
  一次返还最多补一个系列，开销只随该桶名单长度增长。
- 保留额是逐格可变计数：历史满足后按 `floor(剩余/2)` 初始化，每满足一个新进入者减一；
  普通阶段用“容量-已占-当前保留额”判定，从而保留额未被新进入者用完时仍被保护。
- 使用率仅遍历该系列周集合：豁免与“返还截止（取闭）前返还”不计分子分母；
  未登记在结算时按未执行（占分母不占分子）；分母为零视为达标。比较用整数交叉相乘。
- 历史申请之间若超容量，在任何落盘前整批校验，冲突即参数非法、状态不变。
- 所有变更经同一把互斥锁串行化；等时刻合法（只拒绝严格更早），故并发结果等价于某串行顺序。

## 被放弃的方案
- 放弃“申请即实时占容量”：无法表达截止时一次性的历史优先/保留额重算。
- 放弃为补位建跨桶全局索引：一次返还只影响一个桶，全局索引增复杂度且无收益。
- 放弃浮点使用率：边界（恰等于达标比例）用整数精确判定。

## 拒绝次序
参数非法 > 时钟回退 > 公司或系列不存在 > 阶段不符（申请已截止/航季已结算/周已执行）
> 登记超期 > 重复登记 > 容量不足；被拒绝操作不推进时钟、不改任何状态。

## 本地验证
```bash
go test ./slots/                 # 全场景 + 200 组随机差分
go test -race ./slots/           # 并发安全
go test -run=NONE -bench=. ./slots/   # O(1)/O(周数) 性能证据
```
随机脚本逐步经 `log` 打印输入、输出与判定依据；主模型与朴素模型逐步比对快照。
