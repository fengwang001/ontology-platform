# 抑制指令处理器设计说明

## 模块职责

- `model.go`：公共输入输出模型、指令种类和问题类别。
- `processor.go`：线程安全登记、参数校验、重复指令拒绝和判定快照复制。
- `snapshot.go` / `active.go`：判定阶段的内部不可变快照与区间状态。
- `analysis_state.go`：线性扫描所需索引和候选集合。
- `analysis_engine.go`：语义判定，包括区间配对、归属选择、未使用和未闭合报告。
- `sort.go` / `report.go`：线性排序和最终输出顺序。

## 关键语义取舍

1. **“全部”是独立标签**：不会展开为具体规则。诊断只同时检查规则名对应的具体标签槽和“全部”槽，二者互不修改状态。
2. **标签在登记时规范化**：空标签列表等价为 `["全部"]`；重复标签只保留第一次出现。重复指令以行号、种类、规范化标签集合和理由完全一致判定。
3. **标签级问题按优先级短路**：缺理由、无目标行、未知规则依次判定；未生效标签不产生抑制，也不参与“未使用”。
4. **同一指令内具体规则优先于“全部”**：当指令行和登记次序相同，具体规则标签先于“全部”；不同指令仍按指令行号、登记次序比较。
5. **只有归属者算使用**：命中但输掉归属的指令仍可能报“未使用”。区间按整个区间是否有任一诊断归属给 opener 判定；全文件按整个文件范围判定。
6. **未闭合是指令级附加问题**：同一禁用指令即使带多个标签，也只报一条“未闭合区间”，并可与标签级问题并存。

## 线性判定流程

1. 复制一致快照，注册期间的锁在快照复制后释放。
2. 按行做稳定基数排序；诊断先只按行排序，输出时再按完整键排序。
3. 预注册全文件指令，因为其作用范围不受所在行影响。
4. 按行扫描：
   - 处理本行指令，维护每个标签的 `active[tag]`。
   - 本行 / 下一行候选写入点索引。
   - 诊断仅 O(1) 查询两个区间槽、两个点槽和两个全文件槽：具体规则与“全部”。
5. 选出归属者并标记使用；没有归属者的诊断进入保留列表。
6. 扫描结束后，仍活跃的区间产生未闭合问题；候选集合中未被标记使用的有效标签产生未使用问题。

## 复杂度与可验证性

- 登记：均摊 O(1)，标签去重与标签数成正比。
- 判定准备：基数排序为 O(I + D + L)。
- 判定扫描：每条指令按标签总数处理一次；每条诊断只查询常数个 map 槽，因此单条诊断的抑制判断不随指令总数增长。
- 输出排序：诊断和问题均使用稳定计数/基数排序，整体 O(I + D + L)，字符串规则名按字节桶排序。
- 空间：O(I + D + K)，其中 K 是有效指令标签总数。

基准 `BenchmarkDecide` 使用 100、1000、10000 三组输入，可观察耗时随诊断数与指令数近似线性增长。

## 并发与一致性

`RegisterDiagnostic` 和 `RegisterDirective` 使用同一把互斥锁串行化。`Decide` 使用读锁复制诊断、指令、规则集合和配置；复制完成后在快照上无锁分析。因此判定与并发登记可线性化为某个已接受登记集合的串行顺序，被拒绝的登记不会改变状态，重复调用 `Decide` 对同一已接受状态返回一致结果。

## 放弃方案

- **每诊断遍历全部指令**：实现直观，但单诊断成本随指令数线性增长，不满足判定查询 O(1) 槽位访问要求。
- **把“全部”展开成所有规则**：会错误影响具体规则状态，也无法表达“全部”和具体规则互不影响；测试中有专门对照。
- **最终用比较排序输出**：实现简单但总体为 O(n log n)。当前用计数/基数排序保持近线性，并通过稳定排序保留重复诊断的登记顺序。
- **在判定时原地读取共享切片**：会与并发登记冲突。当前改为深拷贝快照，保证只读、可重复和无数据竞争。
