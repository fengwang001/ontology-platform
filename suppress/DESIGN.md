# 抑制指令处理器 — 设计说明

## 1. 职责划分

实现位于 `suppress` 包，按职责拆成四个协作模块：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 领域模型 | `model.go` | 诊断、指令、种类、问题类别、判定结果等类型与优先级定义；无状态逻辑。 |
| 登记会话 | `registry.go` | 线程安全的诊断/指令登记：参数校验、完全重复检测、标签规范化去重、读多写少锁与一致快照。 |
| 覆盖索引 | `coverage.go` | 按标签独立做禁用/启用配对（含取等边界、重复禁用、孤立启用、未闭合），预计算点/区间/全文件三类覆盖索引，提供 O(log N) 命中查询。 |
| 判定编排 | `evaluate.go` | 对快照逐诊断查归属、统计“使用”、按优先级汇总标签级与指令级问题、按契约排序输出。 |

另有独立参照模型 `naive_test.go`（仅测试使用），以“逐行逐标签推演开关状态”的朴素方式独立计算同一结果，用于随机差分对照。

## 2. 关键语义与取舍

1. **“全部”是独立标签，不展开。** 覆盖索引与开关状态都以标签字符串为键；
   每条诊断至多独立查询两个键：其具体规则名与 `全部`，再在两个候选间按统一胜负键取唯一归属。
   因此“启用 B”绝不影响 `全部` 对 B 的抑制。
2. **区间用半开整数区间 `[disableLine, enableLine)` 表示。**
   禁用行含、启用行不含（取等边界自然满足）；未闭合区间右端取 `totalLines+1`，即含末行。
   配对按 `(行号, 登记次序)` 扫描全部指令：同一行上多条指令严格按登记次序配对
   （同行先启用再禁用时，启用为孤立、禁用另开区间）。
3. **归属胜负键 `(指令行号, 登记次序, 具体优先于全部)`。**
   具体优先于全部仅在同一指令内部作为最后一级；跨指令仍先比行号再比登记次序。
   点类/区间/全文件三类候选都折算成同一个胜负键，命中逻辑只有一处。
4. **“使用”只认归属者。** 诊断被唯一归属后，只有归属的 `(指令,标签)` 槽位记为已使用；
   同样覆盖该诊断但未获归属的标签在其作用范围内未抑制任何诊断，报未使用。
   这与“一条诊断只算被其归属者抑制”的契约一致。
5. **问题按槽位归并。** 标签级问题写入 `(指令登记序, 标签)` 槽位，槽位内按
   `缺理由 < 无目标行 < 未知规则 < 重复禁用 < 孤立启用 < 未使用` 的优先级只保留一条；
   未闭合区间是指令级问题（空标签），与标签级问题并存，且排序时排在该指令所有标签级问题之前。
6. **缺理由的处理最优先且最彻底。** 要求理由且理由为空白时，指令在配对扫描前即被跳过：
   不开/关任何区间、不产生覆盖；每个标签槽位（含未知标签）报缺理由，且不再产生其他问题。
7. **登记即规范化。** 空标签列表规范化为 `[全部]`；重复标签保留首次出现。
   重复判定基于 `(行号, 种类, 标签集合, 理由)`，标签集合与书写次序无关；
   参数非法先于重复判定。被拒绝登记在持锁前/不追加状态，绝不改变会话。

## 3. 并发模型与一致性

- `Session` 用一把 `sync.RWMutex` 保护内部切片与去重集合。
  登记取写锁；判定先在读锁下复制出一份 **不可变快照**（诊断切片、指令切片逐项深拷贝标签），
  随后释放锁在快照上纯函数式计算。
- 因为判定只读某个已接受操作序列前缀的副本，多个调用方并发登记、判定与登记并发进行时，
  结果等价于所有已接受操作按某一串行顺序执行；同一快照上重复判定结果一致。
- 正确性以 `go test -race` 下的并发测试（`TestConcurrentRegistrationAndEvaluation`）验证。

## 4. 复杂度与“可验证”的依据

设 D 为诊断数，M 为指令的标签出现总数（指令数 × 平均标签数），N 为指令数。

- 预计算：指令排序与各标签结构整理合计 `O(N log N)`；配对扫描 `O(M)`。
- 判定每条诊断：对两个标签各做至多三次二分（点数组、区间数组、全文件数组），
  为 `O(log N)`，**不随指令总数线性增长**；全部诊断 `O(D log N)`。
- 总判定开销 `O((D + M) log N)`，随指令数与诊断数之和近线性；内存 `O(D + M)`。

可验证手段：

- 代码层面：命中查询集中在 `coverageIndex.lookup`，内部只有 `sort.Search`，没有对指令的遍历；
  评审可直接核对该函数不存在随 N 增长的循环。
- 基准层面：`go test -bench=. ./suppress/` 对比 N=1000 与 N=4000（指令与诊断各 4 倍）。
  实测总耗时约 1.31ms → 7.13ms（约 5.4 倍），与 `O((D+M) log N)` 的理论倍率
  `4 × (log 4000 / log 1000) ≈ 4.8` 同量级；单诊断平均开销约 1.3µs 且随 N 上升非常缓慢，
  反证了“逐诊断扫描全部指令”的 `O(D·N)` 方案（该方案此处应放大到约 16 倍以上）。

## 5. 被放弃的方案

- **逐诊断暴力扫描全部指令**：实现最简单、与朴素模型同构，但单诊断 `O(N)`、总量 `O(D·N)`，
  明确违反“判定一条诊断不得随指令总数线性增长”的要求，仅保留在测试侧作为朴素参照模型。
- **差分数组 / 逐行开关数组**：以行号为轴做差分可得到 `O(totalLines + M)` 的区间覆盖，
  但按标签开数组在标签稀疏时浪费内存，且需要逐行物化开关状态，点类与区间类还要分通道合并；
  最终选择“按标签的点 map + 不相交区间 + 全文件列表”，与语义里“区间按标签独立配对”一一对应，
  归属候选天然携带指令身份，未使用统计也更直接。
- **判定期间持锁**：实现省事但使长判定阻塞登记；改为快照 + RLock 复制，换取读写并发。
- **把“全部”展开成所有已知规则**：看似省一次查询，但展开后的标签与具体标签相互影响
  （无法表达“启用具体规则不影响全部”），且规则集合变化会改变历史指令语义，与题设相悖，放弃。

## 6. 本地验证方法

需要 Go 1.26+（本机 Go 在 `/usr/local/go/bin`）。构建缓存建议指向可写目录：

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache

go test ./...                 # 全量测试
go test -race ./...           # 竞态检测
go test -v ./suppress/        # 查看每次输入/输出/判定依据日志
go test -bench=. ./suppress/  # 复杂度基准
go vet ./...
gofmt -l .
```

测试组成：

- `cases_test.go` / `cases2_test.go` / `cases3_test.go`：覆盖禁用区间取等边界、
  同行多指令、“全部”独立性、重复禁用/孤立启用（含同行启用再禁用）、各类未使用、
  未知规则混合、缺理由整条失效、末行下一行指令、未闭合区间、多命中归属、
  输出排序与重复诊断稳定性、登记错误优先级与“拒绝不改变状态”。
- `diff_test.go`：4000 组随机输入，与 `naive_test.go` 的独立朴素模型逐字段对照，
  前若干组及触发重复拒绝的样例会在 `-v` 日志中打印完整输入、输出与归属/问题依据。
- `concurrent_test.go`：8 路并发登记 + 并发判定的 `-race` 测试，以及 N=1000/4000 基准。
