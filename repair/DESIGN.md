# 设计说明

1. `Service` 用单把互斥锁串行化所有读写，提供线性化语义；容量和唯一承接关系都在同一临界区维护。
2. 时间只随成功接受的操作单调推进；非法、不存在、无权、状态错误在推进前判定，不产生副作用。
3. 固定错误次序为：参数非法、时钟回退、实体不存在、状态不允许、无候选、权限不足；不同方法只在适用位置报对应错误。
4. 队列为二叉堆，键为等级降序、提交时刻升序、工单 ID 升序，保证出队稳定且与总工单总数无关。
5. 候选承包商直接遍历承包商表，检查工种、楼栋、紧急标志、拒绝历史和容量。
6. 候选排序为在手数升序、最近完成时刻升序、登记序号升序；三个键完全确定。
7. 紧急抢占只在普通候选为空时发生；承包商必须满员且持有至少一份未确认非紧急工单。
8. 抢占只退回候选承包商手中派单时刻最晚的未确认非紧急工单；同一时刻以工单 ID 大者为最晚。
9. 抢占受害者保留原提交时刻、等级和拒绝历史，重新进入同一优先堆，因此后续次序完全由原规则决定。
10. 主动拒单和响应逾期都复用同一回队、拒绝计数、黑名单和升级路径，避免两套语义漂移。
11. 同一承包商拒绝同一工单只记录一次黑名单，但每次新的承包商拒单都增加累计次数。
12. 累计拒单达到 `R` 后升一级、拒绝计数清零，并以升级时刻作为新等级起点；紧急等级不再升级。
13. 响应时限从派单时刻起算，完成时限从确认时刻起算；时刻 `due` 仍允许操作，`due+1` 才逾期。
14. 响应和完成逾期分别由两个小根堆惰性触发；查询携带的 `now` 也会推进可见状态。
15. 完成逾期只把状态改为逾期并记录事件，不改变等级和承包商。
16. 停用承包商后，未确认在手工单立即回队；已确认或已完成逾期的工单保留至完成。
17. 撤销先检查状态和提交者，再推进时间；已确认、已逾期、已完成、已撤销都不可撤销。
18. 放弃为工种/楼栋建立多级索引的方案：当前选择器只遍历承包商，正确性更直接，且已满足复杂度要求。
19. 放弃全局定时线程：所有结果均由操作携带的整数 `now` 决定，惰性处理保证确定性和可重放。
20. 放弃分片锁：容量约束跨工单耦合，单锁最简单且避免两阶段锁定的抢占死锁。
21. 复杂度证明：一次派单只扫描承包商集合，不扫描全部工单；堆操作为 `O(log Q)`。
22. 抢占额外扫描仅发生在候选承包商的在手映射中，单名承包商至多扫描其容量上限 `C` 次。
23. 因此单工单选取为 `O(W + C + log Q)`，其中 `W` 为承包商数，`Q` 为队列长度，不含系统总工单数 `T`。
24. `DispatchNext` 可能跳过多个无候选队头，最坏为 `O(Q(W+C+log Q))`，但每个被检查工单仍不依赖系统总历史工单量。
25. 本地验证：`go test ./...`、`go test -race ./...`、`go vet ./...`。
26. 随机对照日志：`REPAIR_TEST_LOG=1 go test -run TestNaive -v ./repair`。
