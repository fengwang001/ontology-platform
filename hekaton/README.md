# Hekaton 式乐观多版本事务引擎

`hekaton` 包实现一个确定性的乐观多版本并发控制（MVCC）内核：读者在创建者
进入预备态后即可推测性读取其写入并记下提交依赖；依赖事务提交时按事务号
次序连带提交，依赖失败时级联中止全部依赖者。所有方法可并发调用，内部以
单一互斥锁串行化，结果等价于某个合法串行顺序。

## 数据模型

- 构造 `New(K)`：`1 <= K <= 64`，越界返回 `ErrInvalidK`，整体拒绝。
- 每键初始有一个已提交版本：值 `0`，创建者为虚拟已提交事务 `0`（ET=0）。
- 全局时钟 `n` 初值 0；`Begin()` 令 `n++`，新事务 `RT=n`，事务号从 1 起
  独立递增（与时间无关）。
- 事务态：活跃 `Active` / 预备 `Prepared`（有结束时间 ET）/ 已提交
  `Committed` / 已中止 `Aborted`。
- 版本三元组 `(value, creator, ender)`，ender=0 表示无结束者。创建者已
  中止的版本是垃圾，扫描时直接跳过；结束者已中止视为无结束者。

## 可见性判定表

`Read(t,k)` 自新到旧扫描版本，第一个“起点且终点均可见”的版本即为所得。

**起点（创建者）**

| 创建者状态 | 条件 | 起点可见？ |
| --- | --- | --- |
| 是 t 自己 | — | 可见 |
| 活跃（他人） | — | 不可见 |
| 已中止 | — | 不可见（版本为垃圾，直接跳过） |
| 预备 / 已提交 | `ET < RT` | 可见 |
| 预备 / 已提交 | `ET >= RT` | 不可见 |

**终点（结束者，起点可见后才检查）**

| 结束者状态 | 条件 | 终点可见？ |
| --- | --- | --- |
| 无结束者（ender=0） | — | 可见 |
| 是 t 自己 | — | 不可见 |
| 活跃（他人） | — | 可见 |
| 已中止 | — | 可见（记号视为无结束者） |
| 预备 / 已提交 | `RT < ET` | 可见 |
| 预备 / 已提交 | `RT >= ET` | 不可见 |

注意两处比较方向相反：起点是“创建者的 ET 严格小于读者 RT”，终点是
“读者 RT 严格小于结束者 ET”。所有边界相等均不可见。

## 提交依赖的产生

依赖是一条有向边 `t -> c`（t 依赖 c），仅指向处于预备态的他人事务：

1. `Read`：命中版本的创建者 `c` 是处于预备态的他人（其版本通过起点
   `ET < RT` 判定），t 推测读到该值，并记录 `t -> c`。
2. `Write`：取最新非垃圾版本 V。若 V 由 t 创建则原地改值；否则当
   V 无有效结束者、其创建者非活跃且 `ET < RT` 时，新建版本（创建者
   t）并把 V 的结束者置为 t；V 的创建者处于预备态时记录 `t -> c`。

写条件不满足即为写冲突：t 立即中止并级联（`Write` 返回中止列表，不是
错误）。

## Precommit / Finish 与依赖解除

- `Precommit(t)`：`n++`，t 转预备，`ET=n`，返回 ET。
- `Finish(t)`：预备且未 Finish 的 t 标记已 Finish；依赖为空则立即提交，
  否则等待，返回 nil。
- 提交推进：提交 t 后，t 的依赖者按事务号升序解除对 t 的依赖；活跃态
  依赖者仅移除边；预备且已 Finish、依赖恰好为空者并入待处理集合；反复
  取集合内最小事务号者提交。`Finish` 返回本次产生的提交次序。

该规则保证多层依赖链按拓扑（同层按号升序）一次性提交，且可精确复现。

## 级联中止范围

`Abort(t)`（活跃或预备）以及写冲突中止，以 t 为起点沿“依赖我的”
（dependents）边传递闭包，全部直接与间接依赖者一并中止——包括活跃态
依赖者（它可能仅因一次推测读而产生依赖）。结果按事务号升序返回。

中止时拆除所有与受害者关联的依赖边，因此事务终结后依赖集合为空；
受害者创建的版本成为垃圾，其作为结束者留下的记号随之失效（仍按
“结束者已中止即无结束者”解释），后续扫描与写入自然跳过垃圾版本。

已提交事务不可能依赖未终结事务，故级联不会触及已提交事务。

## 拒绝顺序（被拒绝不改变任何状态）

构造时 K 越界整体拒绝。其余调用按以下顺序只报第一个错误：

1. 事务号不存在：`ErrUnknownTxn`
2. 状态不符：`ErrInvalidState`（Read/Write/Precommit 须活跃；Finish 须
   预备且未 Finish；Abort 须活跃或预备）
3. 键越界（Read/Write）：`ErrKeyOutOfRange`

写冲突中止与级联属于正常结果，不是拒绝。

## API

| 方法 | 返回 |
| --- | --- |
| `New(k int) (*Engine, error)` | 引擎或 `ErrInvalidK` |
| `Begin() int` | 新事务号 |
| `Read(t, key int) (int, error)` | 可见版本值 |
| `Write(t, key, x int) ([]int, error)` | nil=成功；写冲突时返回级联中止列表 |
| `Precommit(t int) (int, error)` | ET |
| `Finish(t int) ([]int, error)` | 本次提交次序；等待时为 nil |
| `Abort(t int) ([]int, error)` | 级联中止事务号升序列表 |

## 本地验证

```bash
# 全部测试（含 2000 组随机序列与朴素参考模型的差分对照）
go test ./hekaton

# 竞态检测 + 多轮重复
go test -race -count=2 ./hekaton

# 查看逐步日志（输入、引擎输出、朴素输出、每步判定依据）
go test -v -run TestDifferentialAgainstNaive ./hekaton

# 全仓
go test -race -v ./...
gofmt -l . && go vet ./...
```

差分测试中的每个序列都会：逐步比较输出与完整状态指纹、校验“每键至多
一个无有效结束者的非垃圾版本且必为最新者”、序列结束后重放校验无推测
残留（已提交事务在非自写键上读到的恰为 ET<RT 的最大 ET 已提交创建者
的值）、重叠已提交事务不写同一键、终结事务依赖清空，并在全新引擎上
重放确认确定性。
