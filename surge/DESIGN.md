# 设计说明（<=40 行）

1. 包 `surge` 四个职责清晰的模块：供需账本（`regionState.capacity/pending`）、档位状态机（`Evaluate`/`targetTier`）、订单骑手锁定结算（`orderState.lockedTier/riderEligible`、`account`）、并发协调（`System.mu`）。
2. 供需只维护两个整数计数，所有账本变更点（上线/下线/移动/派单/完成/创建/取消）就地 +/-1，O(1) 更新，不存在遍历骑手或订单的路径。
3. 档位评估只读本区域两个计数：运力 0 且待派>0 视为无穷大直接取最高档；0/0 取基础档；其余用 `float64(pending)/float64(capacity) >= 阈值`，等号成立即升档。
4. 目标档>当前档立即跨多档上调并清零下调计数；<当前档累计确认，达 `DownConfirmations` 后只降一档并清零；=当前档清零计数。仅档位真正变化时追加一条 `TierEvent`。
5. 订单在创建瞬间把当前档位快照到 `LockedTier`，之后档位迁移对它无影响；倍率与补贴都只索引锁定档。
6. 补贴资格在派单瞬间固化为 `riderEligible = 骑手进入本区时刻 <= 订单创建时刻`（等号算合格），避免骑手派出后再移动/下线污染结算；不合格记 `WaivedLate` 条目且金额为 0。
7. 时钟为单变量 `now`，每个被接受操作成功后才更新；参数/对象/状态错误先判，时钟回退在通过参数检查后判；拒绝操作零副作用。
8. 错误统一为带 `ErrorCode` 的 `*Error`，覆盖 17 个可程序化区分的类别，`CodeOf` 与 `errors.As` 均可判别；派单资格严格按 不在线→不在本区→持单已满 次序。
9. 并发采用单一互斥锁串行全部变更：这是被放弃“分区域细粒度锁”方案后的取舍——细粒度锁需为骑手跨区与共享时钟引入多锁排序，复杂度与死锁风险高，而题目瓶颈是正确性与可复现，粗锁已保证任意交错等价某串行序且持单绝不超限。
10. 放弃为待派订单维护集合：只需计数；放弃倍率强制单调：倍率作为独立可选配置 `Multipliers`，缺省取“基础档 1.0、加价档 i 取其触发阈值”，避免对业务语义过度假设。
11. `NaiveModel` 是独立的事件溯源实现：只存原始操作日志，每次操作前从头 O(n) 重放重建骑手/订单/计数/档位/账目，数据结构与代码路径与正式实现不同，作为差分预言机。
12. 性能以基准可验证：`BenchmarkEvaluateScales` 在骑手/订单数 1→10000 时评估稳定在约 30ns/op；`BenchmarkDispatchScales` 在平台订单 100→100000 时派单+完成不随总量增长。
13. 本地验证：`go test ./...`、`go test -race ./surge`、`go test -run TestDifferential -v`（逐步输入/输出/判定依据写入 `/tmp/surge-diff.log`）、`go test -run Benchmark -bench=.`。
