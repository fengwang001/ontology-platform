# 修订表达式解析与消歧服务 — 设计说明

1. 模块：`trie.go` 十六进制基数树（子树终端计数 size）；`object.go` 对象库=map+树；
2. `refs.go` 直接/符号引用、reflog、引用名基数树索引；`expr.go` 无状态文法解析；
3. `resolve.go` 单一 RWMutex 下的首段消歧、逐段导航、类型约束、最短缩写；`errors.go` 裁决码。
4. 关键取舍：解析全程持有读锁，天然得到"某瞬间完整状态"快照，串行化等价性由锁推出，
5. 不做 lock-free/MVCC——写少时一把锁最简且可证明正确；写多读少时可再演进为不可变快照指针。
6. 前缀匹配与最短缩写走基数树：`countPrefix`/`findUnique`/`shortestUnique` 均 O(40)，
7. size 随插入在祖先路径上加一，只增不删，故同一对象的最短缩写单调不减、旧缩写永不多义。
8. 短名补全：先基数树精确查全名（命中即豁免引用/标识歧义），再按命名空间次序拼接精确查，
9. 复杂度只依赖短名与命名空间数，与引用总数无关；放弃全表扫描与 map 枚举方案。
10. 符号引用值以 `ref:` 前缀内联于同一 map；设置先试写再沿链探环，成环即回滚，保证"整体拒绝"。
11. reflog 为每直接引用的前置追加切片，索引 0=当前；日志段执行后结果标记为"非引用"，
12. 因此再遇日志段裁决「非引用不可用日志」，与"仅引用名可用日志"的语义一致。
13. 导航段无副作用求值；错误严格按给定次序返回，段下标随文法解析确定首个失败段。
14. 剥标签对非标签是无副作用成功；结果类型约束在所有导航之后，AutoPeel 只在此时作用一次。
15. 对象写入做引用完整性校验（树/父/标签目标须已存在），使导航永不遇到悬空目标；
16. 同标识重复写幂等、内容冲突拒绝；SetRef 的目标也须在库中，引用永不悬空（失败按不存在）。
17. 放弃的方案：每节点 map 的 16 叉非压缩树（空节点多、缓存差）、全局计数器线性扫描（违规模标）、
18. 解析时加锁复制全库（大库昂贵）、为缩写做 LRU 缓存（只增库下缓存失效复杂且无必要）。
19. 并发验证：三 goroutine 交叉写/解析/缩写，断言 `main` 与其第一父、符号 HEAD 始终自洽，
20. 并在 `-race` 下通过；每个解析的自洽性只可能在原子瞬间成立，即串行等价的可观测证据。
21. 正确性验证：独立朴素模型（map/切片线性扫描 + 独立环检测），40 轮随机库 × 数百随机表达式
22. 与随机类型约束逐条比对错误码、候选数与结果 id；差分测试曾实际抓出 trie size 传播缺陷。
23. 规模验证：200 与 20000 对象下前缀计数+缩写基准约 1.2×（非 100×），实证与总数解耦。
24. 本地验证：`go test -race -v ./...`；单测 `go test -run TestRandomDifferential ./...`；
25. 规模用例可 `-short` 跳过；`go vet ./...` 与 `gofmt -l .` 应无输出。
