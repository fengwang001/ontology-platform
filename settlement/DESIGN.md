# 光伏余电上网月度结算引擎 — 设计说明

1. 模块：`month.go`（月份/间隔对齐/错误类别）、`model.go`（参数、价格、读数、额度笔、月结果、生效阶梯表）、`credits.go`（额度小顶堆+逐月结算纯函数）、`engine.go`（并发引擎、登记、封账、试算）；测试为 `engine_test.go`、`naive_test.go`、`concurrency_test.go`。
2. 时间一律 UTC：间隔起点 `time.Time`，以引擎 `epoch` 为网格原点、`intervalSeconds` 为步长（必须整除 86400），月份归属无歧义、结果可复现。
3. 全整数：电量 Wh、功率 W、单价 分/Wh，金额=Wh×单价；间隔能量上限=功率×间隔秒/3600（整除，取等不剔除）。
4. 参数/单价为「生效月阶梯表」：二分取最后一个 `from<=月`；更改仅允许 `from>最近封账月`，否则报「月份已封账」。
5. 月结算固定顺序：逐间隔超限剔除 → 月度上限分档（上限外按余电单价付款）→ 可计入逐度抵扣当月下网 → 净下网按（到期月,存入月）堆序用历史额度，不足计费 → 净余存入一笔 → 到期月≤本月的剩余按本月余电单价付款清零。
6. 额度堆只含「未用尽且未到期」笔：用尽即弹出，每月封账末弹出到期笔；封账开销只取决于当月间隔数与被触碰笔数，不随已封账月数/死笔数增长。
7. 到期月恰等于封账月的笔本月仍可抵扣（仅严格早于本月者跳过），抵扣之后再统一到期付款。
8. 额度不得在存入当月使用：使用判据含「存入月<当月」。
9. 封账校验次序：格式/取值非法 → 已封账 → 顺序错误 → 全月间隔缺失（带最早缺失起点）；锁内先校验后落状态，拒绝不改任何状态。
10. 未封账查询克隆最后封账月的额度堆后逐月试算（无数据月按全零），只读不写持久堆；改参数即时反映，余额不变。
11. 并发：单引擎一把 `sync.Mutex`，所有操作原子，等价于某个串行顺序。
12. 放弃方案一：每产消者一把锁——可提高多产消者并行，但无可测吞吐收益且增加可串行化论证负担。
13. 放弃方案二：额度用数组/链表——死笔无限累积，历史抵扣 O(历史笔数)，违背性能要求。
14. 放弃方案三：试算结果缓存——未封账月数据/参数可变，失效复杂；按需重算更简单，封账才是热路径。
15. 朴素模型 `naiveModel` 独立重写结算，任何月从起点全量扫全部读数与全部额度（O(历史)），与生产代码零共享计算逻辑，降低同源错误风险。
16. 不变量一：Σ可计入 = Σ当月自抵 + Σ历史抵扣 + Σ到期付款 + 活动余额；不变量二：每月下网=当月自抵+历史抵扣+计费；每次封账后断言。
17. 确定性：月结果为值类型，随机差分固定种子；同一操作序列重放逐字段相等。
18. `MonthResult` 同时输出原始/剔除/上限外/自抵/存入/历史/计费/到期各档电量与两笔金额，便于对账。
19. 错误为 `SettlementError{Kind}` 四类并实现 `errors.Is/As` 哨兵；数据缺失携带最早缺失间隔。
20. 本地验证：`go test -race ./...`；边界用例在 `engine_test.go`；差分为 `TestRandomDifferential`（6 固定种子 ×1200 操作）。
21. 性能证据：`TestCloseScaling` 实测封第 1/24/48 个月约 35µs/24µs/26µs（日志输出），无随历史月数增长的分量；`TestHeapContainsOnlyLiveLots` 断言死笔不留堆。
22. 操作日志：`SETTLE_LOG=1 go test ./settlement -run TestRandomDifferential -v` 打印每条输入、双方输出与判定依据；分歧时无条件转储完整操作日志。
