# 结算引擎设计说明
模块（`settlement/`，7 个实现文件）：`errors.go` 八类错误与固定优先级；
`engine.go` 单互斥锁串行化 + 全局单调时钟（拒绝不推进时钟）；
`assignment.go` 配置强校验、档位二分、人员/主体状态；`extension.go`
延期事件扫描线 + 懒删除最大堆；`deadline.go` 个人/小组延期授予、撤销
与封顶；`group.go` 建组、首次提交前加入、关闭前退出快照；
`submission.go`/`settlement.go` 多版本提交、指定、按成员结算与冻结。

关键取舍：可见性定义为 `grantAt < t <= revokeAt`，授予/撤销严格对称
（同刻授予+提交互不可见、同刻撤销+提交仍可见），保证不回溯。多次延期
取 max 不取和；封顶用独立 alive 堆看全部未撤销授予（含未激活）。提交
瞬间固化主体截止（仅小组延期，决定主体有效性）与每成员个人截止
（小组/个人延期取大，存入版本快照）；撤销与后授予不回溯历史版本，
结算纯读快照故不可变。小组版本超档只影响主体/显式指定；成员凭个人
延期使同版本入档仍可作为其评分版本。退出按 leftSubjNo 截断；晚加入
以“快照含该成员”的首版本为边界；指定号映射到成员可见子序列。

开销证明：档位判定 `sort.Search` 为 O(log |Tiers|)，只依赖档位数。
每个授予/撤销事件一生只被单调游标消费、入/出懒删除堆各一次，总代价
O(E log E)；单次取值是已固化状态堆顶 O(1)，不随作业延期总数扫描；
提交只 advance(now) 一次，各成员读同一固化状态。仅被接受的提交
append 并赋 len+1，拒绝不 append，故主体版本号从 1 起连续无洞。

被放弃方案：每次线性扫描全部延期（O(E)，违背开销要求）；区间树/线段树
（本题只需当前最大值，过度设计）；浮点扣分比例（舍入误差，改用基点）。

本地验证：`GOCACHE=/tmp/gocache go test ./settlement/ -race -count=1`
（边界、错误优先级逐对、1500 组与独立朴素模型的随机对照及逐步日志、
并发串行化）与 `go vet ./settlement`。
