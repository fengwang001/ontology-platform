# 合同版本叠加与自动续签服务 — 设计说明

包 `contract` 实现主合同 + 补充协议的签署、生效、撤销、终止与自动续签，
支持按任意整数日序号查询每条条款的有效值及其来源，并保证：
并发调用等价于某个串行顺序、相同操作序列重放结果完全一致、
单条款有效值查询开销不随该合同累计协议总数增长。

## 操作模型

- 一切操作（含查询）经 `Service.Apply(Op)` 进入，携带整数日序号 `now`。
- `now` 不得小于上一次**被接受**操作的 `now`，否则报 `时钟回退`；
  被拒绝的操作不改变任何状态与时钟。
- `Service` 内一把互斥锁把操作串行化；每个操作连同结果追加到内存日志
  （`Service.Log()`），`Replay(ops)` 可在全新服务上重放，结果逐步一致。
- 错误类别按固定优先级只报第一个：
  `参数非法 > 时钟回退 > 合同或协议不存在 > 状态不允许 > 授权失效 > 缺少会签 > 签署超期`。
  实现上每个 handler 严格按此顺序校验；其中"参与方是否合同双方、条款是否在合同内"
  等依赖合同存在的参数校验属于语义层参数非法，安排在存在性检查之后、状态检查之前。

## 关键取舍

### 1. 每条款物化段时间线（而非全量扫描）

每个条款维护一条物化时间线：按起始日升序的段 `(start, value, source)`，
查询即二分查找最后一段 `start <= day`，开销 `O(log k)`，
`k` 为该条款自己的段数，**与合同累计协议总数无关**（包内比较计数器
`queryComparisons` 供测试验证，见 `TestQueryCostIndependentOfAmendmentCount`：
未触及条款 0 次比较；条款上 2000 份协议时约 10 次；合同总协议数翻倍后不变）。

- 协议生效（双方签完、锁定条款还需会签）时，实际生效日
  `effDay = max(声明生效日, 签署完成日[, 会签日])`，
  将其修改的各条款自 `effDay` 起标记为脏。
- 撤销协议生效时，沿"撤销链"（目标、目标撤销的对象……）把链上所有
  修改类协议触及的条款标记为脏。撤销状态判定 `revokedAt` 沿撤销图递归
  （边恒指向更早创建的协议，必然终止），再撤销自然恢复被撤销协议的效力。
- 重建时收集候选变化日（触及该条款的协议的生效日 ∪ 其撤销状态可能翻转的日子），
  逐日求胜出者：生效日最晚；并列取签署完成时刻（全局操作序号）较后者；
  无胜出者取主合同原值。段在 `(值, 来源)` 变化处切分，因此来源查询同样精确。
- 合同提前终止于 `T` 时，所有条款自 `T+1` 标脏，重建忽略 `effDay > T` 的事件，
  即"终止日之后的协议一律不生效，当日及之前已生效的保持"。

### 2. 惰性续签游标（而非即时物化）

续签可无限连续发生，无法即时物化，故采用惰性游标：

- 缓存安全性：影响某日有效值的事件（签署完成、会签），其操作日必不晚于该日
  （`effDay >= 各完成事件日`）；时钟单调，因此**到期日 `E < 已提交时钟` 的
  续签判定结果不可变**，可安全缓存（`computeRenewals`）。
- `[已提交时钟, 目标日]` 区间内的判定用只读模拟（`viewAt`），不落缓存，
  因此未来日查询与当日尚未最终确定的判定也不会污染缓存。
- 到期日 `E` 的判定取 `E` 当日有效值：自动续签开关非 0、续签期长度 > 0，
  且不存在接受日落在 `(上一到期日, E - 提前天数]` 窗口内的不续签通知
  （恰等于提前天数算及时；通知不跨任期）。满足则从 `E+1` 起续签一期。
- 续签历史查询只含 `到期日 < now` 的记录（`now` 当日的判定尚未最终确定，
  当日后续操作仍可能改变当日有效值），这是"可精确复现"的直接推论。

### 3. 操作日志即重放凭证

`Op` 是自描述值类型，日志记录全部操作（含被拒绝的）及其结果。
由于被拒绝的操作不改变状态与时钟，按日志重放必逐步一致；
并发测试以此证明"并发等价于某个串行顺序"（日志顺序即该顺序）。

## 被放弃的方案

- **全局统一时间线**：所有条款共享一条版本序列。查询任一条款都要扫描
  全局版本，开销随合同累计协议总数增长，违反复杂度要求，放弃。
- **每次查询全量扫描协议表**：实现最简单（朴素模型即如此），
  但单条款查询为 `O(协议总数)`，不满足要求；它降级为测试参照物。
- **即时（eager）续签物化**：在到期日到达时主动推进合同状态。
  需要外部时钟驱动，且续签可无限连续，无法预先物化；惰性游标更精确。
- **事件溯源 + 每次查询从头重放**：天然支持重放，但查询成本过高；
  保留其"操作日志可重放"的优点，状态推导仍用增量结构。
- **签署超期作为显式状态迁移**：超期是派生事实
  （`now > 首签日 + 窗口`），显式迁移会让"被拒绝操作不改变状态"复杂化；
  改为在第二方签署时惰性判定并拒绝。

## 语义边界（明确约定）

- 查询也携带 `now` 并参与时钟推进；合同起始日之前的有效值查询返回主合同原值。
- 变更类操作要求合同在 `now` 处于在期状态（未开始、已届满、已终止均拒绝）。
- 撤销要求目标协议"此前已生效"：已签完、（如需）已会签、生效日 `<= now`；
  已签完但缺会签时报`缺少会签`，未签完或生效日未到报`状态不允许`。
- 撤销协议本身不修改条款，无需会签。
- 续签期长度 `<= 0` 视为不续签；不续签通知以接受操作的 `now` 为通知日。
- 提前终止以操作 `now` 为终止日，需合同在期；终止后只允许查询。

## 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin   # 如 go 不在 PATH
export GOCACHE=/tmp/gocache           # 默认缓存目录只读时

# 全量测试（定向边界 + 随机对照 + 并发等价 + 开销证明）
go test ./contract/ -count=1

# 竞态检测
go test ./contract/ -race -count=1

# 查看随机对照每步的输入/输出/判定依据日志
go test ./contract/ -run 'TestRandomDifferential/seed=1' -v

# 单项边界场景
go test ./contract/ -run TestNoticeExactAdvanceDays -v

# 查询开销证明（比较计数器输出）
go test ./contract/ -run TestQueryCostIndependentOfAmendmentCount -v
```

测试构成：

- `contract_test.go`：11 组定向边界测试——生效日恰等、同日多协议取舍、
  撤销与再撤销、授权有效期两端、签署超期恰等、缺会签后补会签、
  不续签通知恰等提前天数、续签期长度来自被修改条款、提前终止后协议、
  拒绝优先级、单条款查询开销证明。
- `naive_test.go` + `random_test.go`：独立编写的朴素模型
  （全量扫描、逐任期重推演），8 个种子 × 1500 步随机操作序列逐步对照，
  日志打印每步输入、输出与判定依据；每个序列末尾做整序列重放校验。
- `concurrency_test.go`：8 goroutine 并发混合操作，
  以操作日志重放证明串行等价与重放确定性（`-race` 下通过）。
