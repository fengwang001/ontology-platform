# rwlock：顺序临时节点读写锁协调模型

`package rwlock` 是 ZooKeeper 顺序临时节点读写锁配方的确定性协调模型：
所有状态变更在一个互斥量内串行化，因此并发调用等价于某个串行顺序，
相同操作序列重放得到完全相同的序号、zxid、ws 与授予事件列表。

入口类型：`Coordinator`，构造参数 `New(C)`，`C` 为每把锁现存子节点上限
（`1 ≤ C ≤ 10^6`，越界 panic）。

## 序号、zxid 与 ws 的分配

- 会话：`Open()` 创建，编号从 1 起全局递增，初始存活；过期后编号不复用。
- 锁：以非空字符串命名，首次使用（`Create`）时自动建立；每把锁维护独立的
  子节点序号计数 `cs`，初值 0。
- `Create(sid, lock, kind)`：`kind` 为 `R` 或 `W`。成功时取 `n = cs`，随后
  `cs++`；**序号永不复用**，只随 `cs` 单调递增，与现存子节点个数无关。
  每次成功创建领取一个全局 `zxid`（全局计数器先加一后取值，初值 0）。
  子节点按序号排序，排序与 kind 无关。
- 观察登记序号 `ws`：全局计数器，初值 0；每登记一次观察先加一后取值。
  观察是一次性的；一个等待者同一时刻至多有一个观察，重新评估并改观察其他
  节点时领取新的 `ws`，旧登记撤销。
- 每次成功的 `Release` 删除领取一个 zxid；`Expire` 的每个子节点删除各领取
  一个 zxid。被拒绝的操作不改变任何子节点、观察以及 `zxid/cs/ws`。

## 持有与观察规则

节点创建（以及被通知后的重新评估）时按以下规则判定，子节点集合取“评估
当时”的现存节点：

- 写者 `W`：自己的序号是现存子节点中最小者（即不存在任何更小的现存节点，
  任意 kind）则持有；否则观察**序号小于自己的最大者（任意 kind）**，即紧邻
  前驱。
- 读者 `R`：不存在序号小于自己的 `W` 子节点（等待中的写者也算）则持有；
  否则观察序号小于自己的写者中的最大者（最近的前置写者，不必是紧邻前驱）。

不变量：任一时刻同一把锁的持有者要么全是读者，要么恰为一个写者；每个等待者
恰有一个指向现存子节点的观察；所有观察登记的总数等于等待者总数。

## 删除、通知与重新评估次序

`Release(sid, lock, kind, n)` 删除自己的子节点（对等待中的请求即取消等待）：

1. 领取删除 zxid；若被删者自己也在等待，先从其观察目标的登记列表中撤销。
2. 快照该节点的观察者列表（按 `ws` 升序），删除节点及其观察登记。
3. 按快照中的 `ws` 升序逐个重新评估：结果可能是持有（产生授予事件），也可能
   是改观察另一个现存节点并领取新的 `ws`。重新登记的等待者使用新 ws，在同一
   轮中不会被再次通知。
4. 授予事件 `Grant{Lock, Seq, Kind, Session, DeleteZX}` 严格按通知次序追加；
   同一次删除触发的多个授予（常见于多个读者）共享同一个删除 zxid。

等待者只在被通知时才重新评估；已持有者在被删除前状态不再变化。删除一个被
`k` 个存活等待者观察的节点，恰好触发 `k` 次重新评估，与锁的总规模无关。

## 会话过期

`Expire(sid)` 不是幂等操作，顺序为：

1. 校验（会话不存在 → `ErrNoSession`；已过期 → `ErrExpired`）。
2. 先把会话标记为过期，并**撤销该会话全部子节点登记的观察**（其等待中的
   子节点此后不再是任何节点的观察者）。
3. 收集该会话的全部子节点，按**创建 zxid 升序**（跨锁）逐个删除，每个删除
   各领取一个 zxid，删除后同样按 ws 升序通知其他会话的观察者。
4. 因为观察先撤销，过期会话自己的等待者即使在删除次序中“轮到”，也绝不会被
   授予；它们随后作为普通子节点被删除。

## 拒绝次序

- `Create`：参数非法（`lock` 为空或 kind 非 R/W）→ 会话不存在 → 会话已过期 →
  已满（现存子节点数 `≥ C`）。
- `Release`：参数非法（`lock` 为空、kind 非法或 `n < 0`）→ 会话不存在 →
  会话已过期 → 节点不存在（锁不存在 / 序号不存在 / kind 不匹配）→ 非所有者。
- `Expire`：会话不存在 → 会话已过期。

## 数据结构与开销

- 每把锁的现存子节点存于带子树统计的 AVL 树：键为序号，附加 `size` 与子树内
  最大写者序号 `maxW`。
  - 写者找紧邻前驱：一次前驱查询。
  - 读者找最近前置写者：利用 `maxW` 的一次下降；随后一次按序号查找登记观察。
- 非导出计数器记录每次评估访问的树节点数（`probes`）与每次删除的重评次数
  （`lastReevals`）。测试断言每次评估的访问数不超过
  `4*ceil(log2(n+1))+4`（`n` 为该锁子节点数）；在 n=100 与 n=10000 的纯写者
  等待链上释放队首时通知数恒为 1（实测最大评估探测：n=64 时 13、n=8192 时 27，
  界分别为 32、60）。

## API 摘要

- `New(c int64) *Coordinator`
- `Open() int64`
- `Create(sid int64, lock string, kind Kind) (Result, error)`
  - `Result{Seq, ZXID, Held, Watching, WS}`；持有时 `Watching=-1, WS=0`。
- `Release(sid int64, lock string, kind Kind, n int64) ([]Grant, error)`
- `Expire(sid int64) ([]Grant, error)`
- `Holders(lock string) []Node` / `Children(lock string) []Node`（序号升序快照）
