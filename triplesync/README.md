
# triplesync：稳定 id 三方目录同步计划器

`triplesync` 比较三份快照——基线 `B`、本地 `L`、远端 `R`——产出两个方向
的确定性动作清单与冲突清单。条目的身份是稳定的整数 id（`≥1`），重名、改
位、改内容都不会改变身份。

## 数据模型

- `Snapshot`：`map[id]Entry`；`Entry{Parent, Name, Dir, Hash}`。
- `Parent=0` 表示根，否则必须指向同快照内的目录条目。
- 文件 `Hash` 非空；目录 `Hash` 必须为空；`Name` 非空且不含 `/`。
- 同一 `(Parent, Name)` 字节精确唯一；父链无环。深度 = 祖先个数。
- 同一 id 在三份快照中的 `Dir` 必须一致：与基线不一致者非法；基线没有
  的新 id 两侧不一致时判远端非法。

## 属性级三方判定

每个 id 在三份快照中各有一个状态（不存在或存在）。两个独立属性：

- 位置：`(Parent, Name)`；
- 内容：`Hash`（目录没有内容属性）。

某侧“改变”某属性，当且仅当该属性相对基线不同；基线不存在而该侧存在时，
该侧的全部属性都算改变。逐条 id 判定：

- 仅一侧改变：把该侧的状态推给另一侧，产生 `Create`、`SetLoc`、
  `SetHash` 或 `Delete`。
- 两侧都改变且结果相同：无动作。
- 一侧删除、另一侧改变了任一属性：`DeleteModify` 冲突。
- 两侧都存在时按属性独立判定：某属性两侧都改且不同 → `Loc` 或
  `Content` 冲突；只有一侧改则照常推送。因此“本地改内容、远端改名”会
  同时产生两个方向的两个动作。
- 两侧都已删除：无动作。

冲突属性不产生任何动作。`Conflicts` 按 id 升序；同 id 内依次为
`DeleteModify`、`Loc`、`Content`。

## 目录删除否决与复活

目录 `D` 在 X 侧被删除、Y 侧相对基线完全未变（即一次将向 Y 推送
`Delete` 的单边删除）时：

1. 先计算每侧执行完自己所有原始动作后的状态（含对侧推送过来的新建/移入
   条目），但候选目录自己的待定删除暂时挂起。
2. 候选按其在 Y 侧执行前的深度从深到浅逐个判定：
   - 执行完 Y 侧动作后仍有存活条目以 `D` 为 `Parent` → **否决**：不向 Y
     删除 `D`，反而向 X 侧 `Create D`，位置取 Y 侧现状；
   - 否则删除成立，该目录从两侧活集中消失。
3. 被否决而存活的子目录会使其祖先目录同样被否决（多级级联）。
4. 被复活目录下 Y 侧新建或移入的条目仍按各自规则正常推送。

## 同名消解

对每一侧执行完全部动作（含复活）后的状态：

1. 若同一 `(Parent, Name)` 有多个条目，保留 id 最小者；
2. 其余条目按 id 升序改名为 `Name + ".c" + id`（十进制）；
3. 若新名字仍与同 `Parent` 下现有条目重名，就在末尾继续追加 `x`
   （`a.c5`、`a.c5x`、`a.c5xx` …）直到不重名；
4. 已改名者立即参与后续重名判定（逐轮处理直到无重名）。

改名在动作清单中体现为：

- 该条目本来就要 `Create`：`Create` 的 `Name` 直接是新名；
- 否则若已有一条 `SetLoc`：改写其 `Parent/Name`；
- 否则追加一条 `SetLoc`。

最后检查两侧执行后的最终状态：含环、悬挂 `Parent` 或仍有重名，则整次
`Plan` 拒绝并返回 `ErrMergeInvalid`。

## 动作排序

每个方向（`ToLocal` 作用于本地、`ToRemote` 作用于远端）的顺序固定：

1. 全部 `Create`：按执行后深度升序，同深度按 id 升序（保证父先于子）；
2. `SetLoc`、`SetHash`：按 id 升序；同 id 先 `SetLoc` 后 `SetHash`；
3. 全部 `Delete`：按执行前深度降序（子先于父），同深度按 id 升序。

## 错误与并发

- 基线非法：`ErrBadBase`（`NewPlanner` 时判定）。
- 本地 / 远端非法：`ErrBadLocal` / `ErrBadRemote`，本地优先于远端，
  二者都先于 `ErrMergeInvalid`。
- `Commit`：先执行 `Plan`；有冲突返回 `ErrHasConflicts`，基线不变；
  否则基线更新为“本地执行完 `ToLocal` 后的状态”。任何被拒绝的调用都
  不改变基线；`Plan` 自身也从不修改基线。
- 所有方法均可并发调用；相同输入永远产生字节级相同的清单。

## 本地验证

```bash
# 需要 Go 1.26+；如 go 不在 PATH：
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache   # 仅当默认缓存目录只读时需要

# 全量测试
go test ./...

# 竞态检测
go test -race -count=1 ./...

# 2000 组随机三份快照与朴素参照实现对照，并输出完整日志
# （含每次的 B/L/R 输入、逐 id 判定依据、否决与改名记录、最终清单）
go test ./triplesync -run TestDifferential2000 -v
# 日志写入：/tmp/triplesync_diff.log

go vet ./...
gofmt -l .
```

测试构成：

- 两个规格例子（否决、同名改名）；
- 位置/内容分属两侧的合并；
- 四类冲突（`DeleteModify`、`Loc`、`Content` 及排序组合）；
- 多级否决级联、删除深度排序；
- 同名多方消解与 `.c5` / `.c5x` 追加链；
- 合并态含环拒绝、校验器对环/悬挂/重名的直接覆盖；
- `Commit` 冲突拒绝、被拒不改基线、成功后基线推进；
- 2000 组随机三份快照与按规则逐步书写的朴素实现逐字段对照；
- 32 goroutine 并发 `Plan` + `-race`。
