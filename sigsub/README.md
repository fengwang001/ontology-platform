# sigsub — 多线程进程信号投递子系统

`sigsub` 模拟一个多线程进程的信号投递：区分进程级（共享）与线程级（私有）
待处理信号，标准信号合并、实时信号带数据排队并受配额限制，支持忽略冲刷、
目标线程选择、固定优先级取出与处理函数期间的屏蔽字叠加。

## 基本概念

- 信号编号 1..64：1..31 为标准信号，32..64 为实时信号；9 为强杀信号
  （不可屏蔽、不可忽略、不可 `SetAction`）。
- 同步信号集合 `{4, 7, 8, 11}`；默认忽略集合 `{17, 23, 28}`。
- 屏蔽字为 `uint64`，第 s 位（从 1 计）对应信号 s；强杀位在任何屏蔽字中
  永远被清除（构造、`AddThread`、`SetMask`、处理函数叠加时均清除）。
- 构造 `New(L, leaderMask)`：L 为实时信号排队总配额（0..1000，越界整体
  拒绝），并创建组长线程（tid 1）。`AddThread` 依次创建 tid 2、3…，
  至多 64 个线程，线程永不删除。

## 待处理的两份结构、合并与排队

待处理信号分**共享份**（进程级，`Send`）与**每线程私有份**（线程级，
`SendTo`）：

- 标准信号在每份内用一个位表示；同一份内再次到达则**合并**
  （返回 `SendMerged`，合并计数 `Lost()` 加一）。不同份互不影响：同一信号
  可以在共享份与某线程私有份各有一个实例。
- 实时信号在每份内按编号各维护一条 **FIFO 队列**，每个条目携带 `value`。
  所有份中实时条目总数记为 **RTQ**（`RTQ()`），任何时刻 `RTQ <= L`；
  达到配额时入队报 `ErrAgain`（这是 `ErrAgain` 的唯一来源）。

## 忽略语义与冲刷

有效处置为忽略 = 动作为忽略，或动作为默认且信号在默认忽略集合内。

- `Send`/`SendTo` 时若有效处置为忽略**且**判定线程（`Send` 看组长，
  `SendTo` 看目标线程自己）未屏蔽该信号，则直接丢弃（返回 `SendDropped`，
  不改任何状态）；被屏蔽时正常入队，之后解除屏蔽在 `Deliver` 时被丢弃
  （计入该次 `Deliver` 的 `Discarded`）。
- `SetAction` 使有效处置变为忽略时，立即从共享份与每个线程私有份**冲刷**
  该信号的全部实例（含实时队列全部条目，RTQ 相应减少）。

## 目标线程选择与游标

`Send`（进程级）入队后选择目标线程：

1. 信号为 9 或组长未屏蔽该信号 → 目标为组长，`curr` 不变；
2. 否则从游标 `curr`（初值 1）起按线程编号循环扫描，第一个未屏蔽该信号
   的线程为目标，并把 `curr` 置为它；
3. 全部屏蔽则无目标（返回 0），信号仍留在共享份。

`SendTo` 的目标恒为该线程。已丢弃与已合并不改变 `curr` 与待处理。

## 取信号的优先级（Deliver）

`Deliver(tid)` 先检查强杀：共享份或任一线程私有份中有 9 待处理则进程终止，
返回 `(已终止, 9)`。否则循环取信号：

1. 先看该线程**私有份**中未被其屏蔽的信号：同步信号集合中编号最小者优先；
   没有同步信号则取编号最小者（实时信号取该编号队首）；
2. 私有份没有可取的，才按同一规则看**共享份**（因此编号较大的私有信号
   先于编号较小的共享信号）。

取出后按有效处置：忽略 → 丢弃（`Discarded` 加一）并继续循环；默认 →
进程终止并返回 `(已终止, sig)`；处理函数 → 压栈并返回处理函数编号、信号、
value、来自共享还是私有、`Discarded`。无可取时返回 `(无, Discarded)`。
取信号用位运算（`math/bits`），不逐个扫描 64 个编号；循环取信号与压栈
在同一把锁内完成，是一个原子步骤。

## 处理函数期间的屏蔽字叠加与恢复

进入处理函数时把当前屏蔽字压栈，新屏蔽字为
`旧屏蔽字 | 附加屏蔽字 | sig 自身位`（`nodefer` 为真则不并自身位），
并清除强杀位。处理函数内调用 `SetMask` 是整体替换当前值。`Sigreturn`
弹出并恢复最近一次压栈的屏蔽字（LIFO），因此处理函数内的 `SetMask`
会被随后的 `Sigreturn` 覆盖；栈空报 `ErrNoHandler`。

## 错误与顺序

错误可区分且每个操作只报第一个（按该操作列出的顺序）：参数非法
（`ErrInvalidParam`）、线程不存在（`ErrThreadNotExist`）、线程过多
（`ErrTooManyThreads`）、进程已终止（`ErrProcessTerminated`）、无处理函数
（`ErrNoHandler`）；`ErrAgain` 只来自实时信号超配额。已丢弃与已合并是结果
而非错误。被拒绝的操作不改变任何待处理、屏蔽字、栈、`curr`、RTQ 与合并
计数。进程终止后一切变更操作报 `ErrProcessTerminated`，查询仍可用。

## 复杂度计数器 examined

`SetAction` 的冲刷只考察该信号的位与队列：非导出计数器 `examined`
不超过（线程数 + 1）+ 被冲刷条目数，与其他信号上排队的条目数无关。

## 不变量

- 任何时刻 `RTQ <= L` 且等于所有实时队列条目总数；
- 标准信号在同一份内至多一个实例；
- 强杀位不出现在任何屏蔽字中；
- 每次 `Deliver` 返回的信号都不在返回前该线程的屏蔽字内；
- `Sigreturn` 次数不超过成功的处理函数进入次数；
- 成功入队数恒等于被投递数、被丢弃数、被冲刷数与仍待处理数之和；
- 所有操作可并发调用，结果等价于某个串行顺序；相同操作序列重放得到
  完全相同的返回值与状态。
