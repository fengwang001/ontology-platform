# 财产险再保险分出引擎设计说明

## 模块划分（reins 包，8 个 .go 文件）
- `treaty.go` 三份合约条款与校验（比例 1..99、线数正、恢复次数非负）。
- `policy.go` 保单登记与分出结构：先成数，剩余在自留额内归净自留，
  超出部分分给溢额但不超过 自留额*线数，再超出整单拒绝。
- `claim.go` 赔款按保额基准同比例切分，分向下取整，尾差归净自留。
- `xl.go` 事故聚合与超赔层：事故按编号聚合，按 (时刻, 编号) 排序消耗
  总能力（层限额*(恢复次数+1)），恰等于自留点不触发。
- `engine.go` 门面：单一互斥锁串行化全部入口，固定拒绝次序。
- `errors.go` 可区分的错误类别（Code）。

## 关键取舍
- 每个事故缓存 `capBefore`（排序在前的事故已消耗能力），晚报插入或撤销
  只从下标 >= 插入点起重算，更早事故不动；`Stats().RecomputedEvents`
  提供可验证证据（TestRecomputeScopeLimitedToInsertionPoint）。
- 事故内层承担分摊：按各赔款净自留比例向下取整，尾差按赔款号字典序
  逐分补齐，与赔款到达次序无关，保证结果只取决于赔款集合。
- 同一事故编号的赔款时刻若不一致，取最小值作为事故时刻（输入本应一致），
  使撤销/乱序下结果仍确定。
- 承保区间以天计，第 d 天覆盖 [d*86400, (d+1)*86400) 秒。
- 保单/赔款用 map 索引，登记与切分为 O(1)，不随保单总数增长。

## 被放弃的方案
- 平衡树/跳表存事故：切片+二分已满足重算范围要求，复杂度不值得。
- 按赔款到达顺序分摊层承担：破坏「只取决于赔款集合」。
- 每次全量重算：违反重算范围限于插入点之后的要求。

## 本地验证
- `go test -race -v ./reins/`：单元测试覆盖全部规定场景；
  TestRandomOrderMatchesNaiveModel 以独立朴素模型对照随机乱序+撤销序列，
  日志打印输入、输出与判定依据。
- `go test -run XXX -bench . ./reins/`：证明登记与切分开销为 O(1)。
