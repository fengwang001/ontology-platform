# 静脉用药配置中心排程与稳定期判定 — 设计说明

本包 `pivas` 实现一个可精确复现的 PIVAS 排程内核。所有状态由一把互斥锁保护，
方法的外部行为等价于按调用完成顺序串行执行；相同操作序列重放得到完全相同的
批次划分、开始/完成/送达时刻。

## 1. 模块划分

- `errors.go`：错误码与优先级。错误严格按
  参数非法 → 时钟回退 → 药品不存在 → 禁忌配对 → 溶媒不兼容 → 避光冲突 → 无可行安排 → 状态不符
  的顺序只返回第一个。
- `catalog.go`：版本化药品目录。药品条目按版本追加（写时复制的版本链），
  禁忌对为哈希集合。医嘱保存受理时的目录版本号，按版本二分回查，目录变更不追溯。
- `config.go`：运送时长、配置时长对照、洁净台、药品/禁忌的登记与时钟推进。
- `schedule.go`：稳定期、有效期、按时判定，以及医嘱静态校验。
- `accept.go`：候选安排的只读模拟（普通加入 / 紧急连锁顺延 / 新开批次）与候选比较。
- `order.go`：受理主流程、候选枚举、裁决与提交；避光冲突的延迟判定。
- `cancel.go`：取消未开始医嘱、空批次回收、查询。
- `system.go`：数据结构与系统构造。

## 2. 关键语义与取舍

### 时间边界
- 有效期：`deliver < ready + 稳定秒数`。**恰到期视为已失效**，故用严格小于。
- 按时：`deliver <= dueAt`。**送达恰等于要求时刻视为按时**，故用非严格。
- 批次可加入性：`start < now` 才算已开始。`start == now` 时刻批次仍可编入/取消，
  与“恰等于视为按时”的边界口径一致。

### 稳定期
- 同一存放方式下，整袋稳定秒数取该袋内各药品该方式稳定秒数的最小值。
- 系统为每个候选批次分别评估室温与冷藏，选择送达最早的存放方式；
  冷藏医嘱必须使用冷藏运送（运送时长按存放方式分别配置），未配置冷藏运送时
  冷藏候选直接不可行。
- 送达时刻并列时取室温（确定性取舍，仅影响不可区分的输出字段）。

### 避光
- 医嘱内含任一须避光药品，则整袋必须避光；批次按“溶媒 + 外袋形态”二元编组。
- 避光冲突作为错误码，仅在搜索失败、且存在一个“除外袋形态外本可接纳”的
  同溶媒未满未开始批次时返回；否则归为无可行安排，保证避光冲突优先级高于无可行安排。

### 批次与台
- 批次 = 同台 + 同溶媒 + 同外袋形态；数量不超过台容量。
- 配置时长取自与数量一一对应、随数量严格递增的对照表。
- 相邻批次间必须满足 `next.start >= prev.end + clearGap`。
- 新批次开始时刻取该台时间线上最早可行间隙；已开始的历史前缀由每台 `head`
  游标惰性跳过。

### 裁决键（全部并列时的总顺序）
1. 送达时刻最早；
2. 台编号字典序最小；
3. 已存在批次优先于新开批次；
4. 同档内批次序号最小。

### 普通 vs 紧急加入
- 所有可行性模拟都是**只读试探**：在局部变量上推算新的开始时刻，不落任何状态；
  只有选定最优候选后才在 `commit` 中一次性写状态。被拒绝操作因此天然不留痕迹。
- 普通医嘱加入既有批次：延长后不得侵占紧随其后的批次（`newEnd+gap > next.start`
  即否决），从而保证同台任何后续批次开始时刻不变。
- 紧急医嘱允许连锁顺延：从目标批次起依次以 `prevEnd+gap` 后推，每个受影响批次内
  的全部医嘱都必须仍满足有效期与按时；任一违约则该候选作废。
  若顺延会撞上已开始（或已结束）批次，同样否决。

### 取消
- 已开始（`start < now`）医嘱取消报状态不符。
- 取消只缩减批次数量与时长；批次开始时刻**绝不提前**。批次空则回收，
  其后批次时刻保持不变。

## 3. 被放弃的方案

- **每次目录变更全量克隆快照**：实现简单但注册 N 个药品是 O(N²)，在 10^5 药品规模
  下不可接受。改为版本链追加 + 二分回查，注册 O(log N)、按版本查询 O(log N)，
  当前版本查询 O(1) 最坏（取切片尾部）。
- **在批次对象上就地试探顺延再回滚**：容易遗漏回滚路径、破坏“拒绝不改状态”。
  改为纯函数式模拟，只有提交阶段写状态。
- **受理时扫描全部历史批次**：违反“开销不随历史已完成批次总数增长”。改为每台
  维护 `head` 游标，扫描范围仅为当前未开始批次。
- **把避光冲突放在搜索前硬性拦截**：会误伤“本就只能新开批次”的情形（新开批次总能
  选对形态）。改为搜索失败后再判定是否仅被外袋形态卡住。

## 4. 复杂度声明（可验证）

- 禁忌配对判定：医嘱内 k ≤ 6 种药，两两哈希查找 O(k²) = O(1)，
  与目录禁忌对总数无关。基准 `BenchmarkIncompatibilityLookup` 对照 10³ 与 10⁵ 对，
  单次受理耗时基本一致（约 2.30µs vs 2.34µs）。
- 受理开销：候选枚举只遍历各台 `head` 之后的未开始批次，
  与历史已完成批次总数无关。基准 `BenchmarkAcceptWithManyFinishedBatches`
  对照历史 100 与 10000 批次，单次受理约 0.90µs vs 0.97µs，基本持平。
  实现上每台以二分把“历史/未开始”分界（`advanceHead`）快进，并以全局
  `batchByID` 索引做 O(1) 批次反查，因此受理与查询均不随历史批次数线性增长。

## 5. 测试

- `edge_test.go` / `schedule_edge_test.go`：有效期恰到期与晚一秒、送达恰等于要求
  时刻、室温/冷藏取舍与缺冷藏运送、避光编组、容量恰满、清场间隔恰好够与差一秒、
  目录变更不追溯、取消后不提前、取消已开始报状态不符、紧急成功与整体拒绝、
  普通加入不移动后续批次、已开始批次不可加入。
- `urgent`/连锁相关边界同样以确定性数值用例覆盖。
- `diff_test.go`：1500 组随机操作序列（每组最多 40 步：受理/取消/新增禁忌/变更药品），
  与完全独立的朴素参考模型 `naive_test.go` 逐步对照错误码与全部医嘱的
  台、批次、开始/完成/送达/有效期、存放方式、外袋、按时标志；`-v` 打印每步输入、
  输出与判定依据。
- `bench_test.go`：两档复杂度对照基准与并发受理（`-race`）一致性测试。
