# 设计说明：机场出租车蓄车池虚拟排队

## 关键取舍
1. 单把互斥锁串行化全部状态变更：并发结果等价于按抢锁顺序的某串行历史；
   规则重、吞吐要求未量化，简单可复现优先。
2. 每候机楼一条双链表队列 + `driver->node` 索引；优先段恒在普通段之前，
   段内按 (入池时刻, 司机标识) 有序插入——同刻入池无论调用先后结果都确定。
3. 位置查询 = 从队首线性遍历到该节点，遍历步数经 `LastPositionScan` 暴露；
   步数 ≤ 当前队长，与历史入池总数无关，测试“先制造大量历史再查”可证。
4. 爽约是时钟驱动的确定性推进：任何被接受操作先把 `deadline <= at`
   （取等即逾期）的放行司机判爽约；`Arrive` 对本人单独判定以精确报
   “到达已逾期”。禁入自 deadline 起算，禁入期恰结束（`at == banUntil`）可入。
5. 短途凭证在入池时评估、发放时刻即 TTL 起点；每日次数按配置时区切自然日。
   发放先于满员/禁入检查，故被拒不消耗、时效照走（短途机会本身被消费）。
6. 优先名额满：第一次按普通入队且凭证保留（restrictedAttempts=1），
   第二次仍受限即作废；过期凭证（入池时刻 == 过期时刻）按普通入队并清除。
7. 调剂只选队首为普通司机的备选队列；选择键 (队首入池时刻, 候机楼标识)，
   最小者胜出；调剂放行使用独立的调剂时限。
8. 错误用哨兵 + `OpError{Kind}` 表达，`errors.Is` 可分类，判定顺序固定：
   参数非法 → 时钟回退 → 候机楼 → 司机 → 禁入 → 在队 → 满员 → …；
   另补“放行中不可离队/不在队列中”两类，列在规范十类之后。
9. 被拒绝操作不写时钟、不改队列/凭证；只有被接受操作推进单调时钟。

## 被放弃的方案
- 每队列独立锁：调剂与全局爽约扫掠需跨队列原子，多锁易死锁、复现复杂，放弃。
- 平衡树/顺序统计树做 O(log n) 位置查询：需求只要求“不随历史增长”，
  线性遍历当前队列已满足且可直接验证，额外复杂度不值得。
- 惰性爽约（仅查询本人时判定）：会让“队列里还挂着已爽约司机”造成
  满员/调剂判定歧义，改为任何接受操作统一推进，语义无歧义。
- 入池时要求调用方传凭证 ID：凭证由系统按短途记录隐式发放更贴近题意，
  且天然避免客户端伪造；改用 `CompleteTrip` 记录离开时刻与距离。

## 本地验证
- `go test ./taxipool -v`：14 组边界用例（取等边界、两次受限、调剂、
  字典序、位置步数等）。
- `go test ./taxipool -run TestRandomDifferential -v`：40 种子 ×300
  随机操作，与独立朴素切片模型逐步比对错误类别、全部队列快照、
  司机状态、位置；日志含每条操作的输入、输出与判定依据。
- `go test -race ./...`：竞态检测；`gofmt -l .`、`go vet ./...` 干净。
