# initorder 设计说明

包级变量初始化次序求解会话的设计与实现记录。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `ident.go` | 标识符词法：合法标识符与空白标识符 `_` 的判定。 |
| `errors.go` | 四类可区分错误（哨兵 + 结构体载荷），供 `errors.Is/As` 判定。 |
| `session.go` | 会话状态与登记：校验（非法优先于重名）、命名空间、并发锁。 |
| `solve.go` | 求解器：未声明检查、SCC 传递依赖、堆式贪心选取。 |
| `naive_test.go` | 规格的朴素直译模型，仅用于差分测试。 |

## 关键取舍

### 传递依赖：沿函数折叠 SCC，遇变量即止

单元对变量的依赖“沿函数传递、遇变量停止”：引用变量 `x` 只依赖 `x`
本身，`x` 所在单元的其他依赖由该单元自己负责。因此对函数引用子图做
Tarjan 强连通分解，把相互递归的函数折叠为一个分量，按分量逆拓扑序
（Tarjan 天然汇点先出）一次性算出每个分量可达的变量集合 `D(C)`。
被大量单元引用的函数只展开一次（`solveStats.FuncExpansions` 恒等于
函数个数，与引用者数量无关，`TestSharedFuncExpandedOnce` 验证）。

### 选取过程：前驱计数 + 最小堆，而非逐轮扫描

规格要求每轮取“源码次序最靠前且依赖均已完成的单元”。实现为每个单元
维护未满足前驱计数（直接引用的变量数 + 直接引用的函数分量数），计数
归零即进入按登记次序排序的最小堆；每完成一个单元，沿“变量 → 等待者”
反向边递减计数。每轮弹出堆顶即规则要求的单元，无需扫描全部剩余单元。
反向边总量为引用关系总数加传递依赖输出总量，堆操作每单元一次。

### 自身引用与环

单元（直接或经函数）引用自己的变量时，该变量计入前驱计数但永远不会
完成，因此自然形成环；求解失败时按源码次序报告全部未完成单元的
非空白变量。报告用的依赖集合则按规格剔除自身变量与空白标识符。

### 并发：读写锁 + 快照求解

登记持写锁，求解持读锁且不改写会话状态（所有中间结构在求解内部分配）。
因此并发执行等价于所有已接受操作按某个全序串行执行，求解永远看到
一致快照，不可能看到登记到一半的单元（登记在锁内先完整校验、再一次
提交状态变更）。

### 错误优先级

- 登记：先校验参数非法（空变量列表、非法标识符、空白函数名、引用含
  空白），再查重名；被拒绝的登记不产生任何状态变更，也不占用登记次序。
- 求解：先按登记次序扫描全部声明（含无人使用的函数）查未声明引用，
  通过后才检测初始化环。

## 被放弃的方案

- **全图 SCC（单元也参与）**：把单元节点一并做强连通分解可直接判环，
  但单元节点的出边会让“可达变量集合”把变量所在单元的间接依赖也算进
  来，与“沿函数传递、遇变量停止”的语义不符，且逐单元展开反向边会失去
  近线性保证。故只对函数子图做 SCC。
- **每轮扫描剩余单元**：实现最简单（朴素模型即如此，保留在测试中作
  对照），但每轮 O(剩余单元) 的扫描在单元数大时是平方级，放弃。
- **依赖集合用位图/共享切片压缩**：可减少内存，但会让结果类型不再
  自描述，且排序输出的构造更复杂；输出总量本身已是复杂度下界，放弃。

## 复杂度

设声明数 `D`、引用关系总数 `R`、传递依赖输出总量 `S`（各单元依赖集合
与函数分量可达变量集合的大小之和）。求解耗时 `O(D + R + S)` 量级：
图构造与 Tarjan 为 `O(函数数 + 函数引用数)`，每个函数体只展开一次，
选取过程每单元一次堆操作。`S` 是输出本身的下界。基准
`BenchmarkSolveSharedFunc`、`BenchmarkSolveChain` 显示单元数翻倍时
耗时近似翻倍。

## 本地验证方法

```bash
# 全部测试（含朴素模型差分、并发交错）
go test ./initorder/

# 竞态检测 + 详细日志（随机用例会打印每次输入、输出与判定依据）
go test -race -v ./initorder/

# 开销特性：共享函数只展开一次的计数断言 + 基准
go test ./initorder/ -run TestSharedFuncExpandedOnce -v
go test ./initorder/ -run XXX -bench .

# 静态检查
gofmt -l initorder/ && go vet ./initorder/
```
