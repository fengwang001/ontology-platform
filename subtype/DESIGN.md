# 递归命名类型的结构化子类型判定器 — 设计说明

## 模块划分

包 `ontology/subtype` 按职责划分为五个相互协作的模块：

| 文件 | 职责 |
| --- | --- |
| `types.go` | 类型表达式的数据定义（封闭接口 `Type` 及十个实现）、打印与便捷构造函数。纯数据，无逻辑。 |
| `errors.go` | 可区分的错误类别（`ErrorKind`）、携带相关名字的 `Error` 类型、哨兵错误（支持 `errors.Is`）。 |
| `validate.go` | 静态校验：表达式合法性（nil、对象属性名重复）、静态可达名字收集、未定义引用检测、无保护循环检测。 |
| `check.go` | 子类型判定核心：共归纳算法（假设帧 + 缓存失效）与全部结构规则，附可验证统计信息。 |
| `registry.go` | 并发安全的注册表：登记（先校验后提交）、判定入口（错误优先级、定义快照）。 |

依赖方向：`registry` → `validate` / `check` → `types` / `errors`，无环。

## 核心算法：按需共归纳 + 假设帧失效

判定取**最大解**（共归纳语义）：遇到正在判定且尚未得出结论的同一对
命名类型时视为成立。实现要点：

- **假设只针对 (引用, 引用) 对**。非引用的一侧只做结构分解、严格变小；
  单侧引用展开后另一侧仍严格变小。由于无保护循环已在判定前被拒绝
  （所有定义都是收缩的），任何无限下降都必须重复某个 (左名, 右名) 对，
  因此只需对命名对维护假设栈与缓存即可保证终止。
- **假设帧（frame）**。每开始判定一对命名类型就压入一帧，记录该帧打开
  期间写入缓存的所有条目。帧关闭时：
  - 结果为 true：假设得到证实，帧内条目并入父帧（对更外层假设仍是暂定的）；
  - 结果为 false：假设被推翻，帧内条目**全部作废**——它们可能依赖了
    被推翻的假设。被推翻的对本身缓存为 false（对自身的假设是乐观的，
    失败即确证），但仍记入父帧以待更外层裁决。
- 这保证了"判定过程中得出的中间结论不得因所依赖的假设后来被推翻而被
  错误地复用"。`TestAssumptionInvalidation` 构造了一个若不作废缓存就会
  给出错误答案的用例。

## 关键取舍

- **命名对数量上界取"并集的两两组合"**。可写属性的不变性检查会交换
  左右两侧（互为子类型），因此命名对的两个分量都可能来自任一侧可达的
  名字。上界为 `|可达名字并集|²`，由 `Stats.PairBound()` 给出，
  单测与随机测试逐轮断言 `DistinctPairs ≤ PairBound()`。
- **缓存失效采取保守作废**：帧失败时作废该帧期间的全部条目，即使其中
  某些条目实际上并未依赖被推翻的假设。这只损失少量重算，换来简单的
  健全性论证；不同命名对的总数不受影响。
- **联合不做对象成员分配**（明确规定）：`{a} | {b}` 与 `{a?, b?}` 之类
  需要分配律才能成立的关系不成立，测试锁定该行为。
- **空联合即底类型**：左侧空联合空量化成立，右侧空联合无成员可选不成立，
  与底类型规则一致。
- **判定时（而非登记时）检查未定义引用与无保护循环**：登记必须允许
  前向引用，因此这两类检查推迟到判定，且对两侧**静态可达**的全部命名
  定义检查（而非只检查判定实际走到的部分），各自报告字典序最小名字。
- **错误优先级**：登记时参数非法 > 重复定义；判定时参数非法 > 未定义
  引用 > 无保护循环。被拒绝的登记在持锁提交前完成全部校验，不改变状态。
- **并发语义**：`sync.RWMutex` 保护定义表；判定在读锁下**拷贝快照**后
  释放锁再计算，拷贝时刻即线性化点。登记与判定可并发，结果等价于某个
  串行顺序；判定不阻塞其他判定，也不长时间阻塞登记。

## 被放弃的方案

- **Kleene 迭代直接求最大不动点**：从全部命名对为真开始单调递减迭代至
  不动点。正确且简单，但会检查大量与本次判定无关的命名对，且无法自然
  回答"实际检查了哪些对"，与按需语义不符，故仅将其思想用于朴素对照模型
  的燃料上界论证。
- **归纳（最小解）判定**：遇到重复命名对时返回 false。实现更简单但语义
  错误——`A = {next: A}` 与 `B = {next: B}` 这类同构无限类型会被判为
  互不相关，不符合题目要求的最大解。
- **朴素 Amadio–Cardelli 缓存（只缓存成功、不作废）**：在假设被推翻后
  会复用依赖该假设的中间结论，存在健全性漏洞（见
  `TestAssumptionInvalidation`），被假设帧失效机制取代。
- **登记时校验未定义引用/无保护循环**：与前向引用（先登记、后补全）
  直接冲突，放弃。
- **判定全程持有读锁**：实现更简单且天然一致，但一次昂贵判定会阻塞所有
  登记；快照拷贝以少量内存换取并发度，且线性化点清晰。

## 正确性与复杂度论证要点

- **终止性**：无保护循环被拒绝后，所有定义都是收缩的（每个自引用都经过
  对象或函数构造子）。判定沿 (引用, 引用) 对的假设栈下降，栈中命名对
  互不重复，而命名对总数有限（≤ 并集平方），故必终止。
- **命名对上界**：`checker.seen` 记录本次判定实际检查过的不同命名对，
  其元素取自两侧可达名字并集的笛卡尔积，故 `DistinctPairs ≤ |并集|²`。
  缓存使命中对不再重复展开，不会随递归深度指数增长。
- **与朴素模型的一致性**：朴素模型把递归展开到 `|并集|² + 1` 层后比较
  （超过该深度的路径必然重复某个命名对，按共归纳视为成立，与主判定器
  的假设规则一致）。随机测试以 5000 余轮对照验证两种实现结果一致。

## 本地验证方法

```bash
# 全部测试（含 5000 轮随机对照）
go test ./subtype/

# 查看随机对照的逐轮日志（输入、输出、判定依据）
go test ./subtype/ -run TestRandomCrossCheck -v
go test ./subtype/ -run TestRandomRecursiveCrossCheck -v

# 竞态检测（并发登记与判定）
go test -race ./subtype/

# 静态检查与格式
go vet ./...
gofmt -l .
```
