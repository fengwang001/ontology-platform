# 电表换表与读数衔接引擎 — 设计说明

## 模块划分
1. `model.go`：`Meter`/`Mount`/`Reading`/`QueryResult` 纯数据。
2. `errors.go`：六类错误与固定优先级（参数非法 > 不在挂接期 > 与已有读数冲突 > 读数冲突 > 不合理 > 无读数）。
3. `segment.go`：相邻读数翻转判定（后值 < 前值恰补一圈）、倍率、时长上限（取等通过）与溢出安全乘法。
4. `store.go`：每表一棵按时刻排序的 treap，插入/删除/查找/前驱后继均 O(log n)，并提供范围遍历 O(k+log n)。
5. `engine.go`：挂接、换表、登记、乱序插入、估算替换/删除、跨表查询；单 `sync.Mutex` 串行化。

## 关键取舍
- 翻转只允许 0 或 1 次；乱序插入用「拆分两段翻转数之和 == 原区间翻转数」做守恒校验，拒绝多圈解释。
- 换表时刻两侧各写一条实抄读数；查询区间按半开归属（旧表含右端、新表含左端），换表时刻自身不产生用电。
- 所有写操作「先全量校验、后一次性提交」，拒绝路径不触碰任何结构；估算->实抄是原地改节点。
- 并发用单互斥而非细粒度锁：语义最强（任意调度等价某串行序）、实现无死锁面；登记热点仅 O(log n)。
- 上限比较与跨表求和均做 int64 溢出保护（18 位表 + 大倍率时乘积可能溢出）。

## 性能（如何验证）
- 登记/替换/删除只访问 treap 一条根叶路径及前驱、后继，复核区间至多 2 个，与读数总数无关。
- 查询：挂接历史按安装时刻有序，二分定位起止挂接（不随历史表数线性增长）；
  每只经过的表用 `iterateRange` 只访问区间内读数，不触及其余读数或其他供电点。
- `bench_test.go` 在 1k/10k/100k 读数下实测追加与小区间查询仅呈对数增长。

## 被放弃的方案
- 有序切片存读数：乱序插入/删除 O(n)，违反「不随读数总数增长」。
- 每翻转一圈累加成整数圈数：无法支持乱序守恒校验，且会掩盖矛盾数据，放弃。
- 多把锁按供电点/电表拆分：换表跨两只表需确定加锁序，收益小且易死锁，放弃。
- 估算读数独立旁表：会让查询与翻转守恒漏掉估算区间，改为与实抄同树、仅类型不同。

## 本地验证
```bash
go test -race -count=1 ./...
go test -v -run TestDifferentialRandom ./meterengine   # 打印每条输入/输出/判定依据
go test -bench=. -run=^$ ./meterengine                  # 复杂度实测
go vet ./...
```
`differential_test.go` 内的朴素模型用有序切片线性重扫全部规则，
对 2000 组随机操作序列逐条比对错误类别、查询用电量、估算标记，并做三点可加性终检。
