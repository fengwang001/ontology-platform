# 尾部采样器设计说明

## 结构
- `span`：缓冲项纯数据（lastSeen、spanID 集合、错误标记、最大时延），不含策略。
- `policy`：纯函数，按 Error → Latency → Prob/Sampled out 定序判定，不知配额与缓存。
- `sampler`：参数校验、缓冲堆、决定缓存、配额窗口、Ingest/Tick；全局互斥锁，
  并发调用等价于某个串行顺序；所有状态只在锁内变更，重放同一输入序列得同一决定清单。

## 关键取舍（含被放弃的方案）
1. 缓冲满时驱逐 (lastSeen, traceID) 最小者并立即决定，而非拒收新跨度。
   拒收会丢掉新 trace 的首个跨度，破坏"每个被接受跨度恰好落入四个出口之一"的守恒；
   降级决定让旧 trace 以已有数据定论（带 Evicted 标记），新 trace 照常入缓冲，吞吐不中断。
2. Error/Latency 必保留类占用配额（u+1）但不受配额约束（u 可超 Q）。
   放弃"必保留类不占配额"：错误 trace 免费会挤占 Prob 类的保留空间，放大整体采样率；
   放弃"必保留类受配额约束"：错误 trace 可能被 Budget 丢弃，违背可观测性初衷。
   现方案语义最简单：Prob 类只在 u<Q 时保留，其余一律 Budget，完全可复现。
3. 缓存过期后迟到跨度成为新 trace 的碎片，而非无限期记忆。
   无限期记忆等价于无界状态，违反资源上限；Td/Cmax 把记忆成本界定在常数级。
   碎片 trace 重新走完整策略、可能得到不同决定——这是有界记忆的固有代价，
   换来缓存大小与查找成本均可预测。
4. 缓存淘汰取 (decidedAt, traceID) 最小者：最旧决定的迟到跨度多已到达，价值最低，
   且与过期语义方向一致。曾考虑随机淘汰，因不可复现而放弃。

## 数据结构
- 缓冲：map + 最小堆 (lastSeen, traceID)。驱逐 O(log n)，绝不线性扫描；
  Tick 只弹出堆顶到期项，考察数 = 决定数 + 1（最后一次窥视堆顶），用非导出计数器断言。
- 缓存：map + 最小堆 (decidedAt, traceID)。写入时先弹出全部到期项，再按需淘汰至 Cmax。
- 惰性过期：读缓存时 decidedAt+Td ≤ now 即视为不存在，不主动清理，留给写入路径清理。

## 本地验证
- `go test ./tailsampler/... -v -race`：行为用例 + 随机序列与朴素模拟对照 +
  守恒不变量（被接受跨度 = 决定跨度 + 在缓冲 + LateKept + LateDropped）+ Tick 考察计数。
- `gofmt -l . && go vet ./...`。
