# 导出映射解析器设计说明

`exports` 包实现模块包导出映射（exports map）的解析：给定一张导出映射表
与一次导入请求（子路径 + 活动条件集合），决定请求落到哪个内部目标，
或给出可区分的错误类别。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `errors.go` | 错误类别 `Kind` 与统一错误类型 `Error`，`KindOf` 提取类别 |
| `target.go` | 目标模型（字符串 / 禁止 / 条件映射）与构造期递归校验 |
| `table.go` | 表的构造、键形态校验、不可变索引的构建 |
| `select.go` | 键选择：精确查找 + 通配索引，附 probes 计数器 |
| `resolver.go` | 解析器：请求校验、目标递归解析、原子换表 |

协作关系：`Resolver` 持有 `atomic.Pointer[ExportTable]`；`Resolve` 先校验
请求，再从当前表选择键，最后沿目标树递归解析。各层只依赖下一层的
只读数据，解析全程无写操作。

## 关键取舍

### 键选择索引：前缀 -> 后缀 两级哈希

通配键 `P*S` 命中请求 `R` 的条件是 `R` 以 `P` 开头、以 `S` 结尾且中间
至少一个字符；裁决规则是先比 `P` 最长、再比整个键最长（即 `S` 最长）。
构造期把通配键组织为 `map[前缀]map[后缀]条目`；解析时把请求的所有前缀
（从长到短）与所有后缀（从长到短）做哈希查找，第一个命中即最优解。
查找次数上界为 `O(L^2)`（`L` 为请求长度），**与表中键总数无关**。

### 不可变表 + 原子指针换表

表一经构造不可修改，`Resolver` 用 `atomic.Pointer` 持有当前表。每次
`Resolve` 只在入口加载一次指针，因此并发换表时每次解析完整地看到
旧表或新表之一，结果等价于某个串行顺序（线性一致）。`Replace` 先完整
构造并校验新表，校验失败直接返回错误，旧表不受任何影响。

### 字符串目标留到解析期校验

目标合法性依赖通配匹配段（替换后才检查），而构造期无法预知匹配段，
因此字符串目标一律在解析期校验，非法时报 `KindInvalidTarget` 且不回退。
构造期只校验与请求无关的性质（键形态、条件名、default 位置、重复项、
空条件映射）。

### 错误即控制流

目标递归解析用 `*Error` 的 `Kind` 区分三种向上传播的行为：
`KindNoMatchingCondition` 在条件映射层被吞掉并继续尝试后续条件；
`KindForbidden` 与 `KindInvalidTarget` 直接穿透到顶层。这与规格中
"禁止/非法目标不回退、无匹配继续试"的语义一一对应。

## 被放弃的方案

- **前缀树（trie）做通配匹配**：后缀约束仍需逐节点过滤，实现复杂且
  常数更大；两级哈希在相同渐近界下更简单。
- **按后缀长度排序的线性扫描**：同前缀下后缀数量可随表规模增长，
  无法满足"开销不随键总数增长"的要求，放弃。
- **读写锁保护可变表**：换表需持写锁重建索引，解析会被长换表阻塞；
  不可变表 + 原子指针使解析完全无锁。
- **构造期校验字符串目标**：对含星号键的目标无法判定（匹配段未知），
  统一推迟到解析期，避免两套校验规则。

## 本地验证方法

```bash
# 全部测试（含竞态检测）
go test -race ./exports/

# 差分测试日志：打印每次输入、输出与判定依据
go test -run TestDifferential -v ./exports/

# 复杂度基准：100 ~ 100000 键下解析耗时应大致恒定
go test -run xxx -bench=Scaling -benchmem ./exports/
```

复杂度另有两重可验证保证：

1. `TestLookupComplexityIndependentOfTableSize` 用 `select.go` 中的
   probes 计数器断言：10 键与 20000 键的表解析同一请求，哈希查找
   次数完全相等。
2. `BenchmarkResolveScaling` 实测不同规模表的解析耗时（本机实测
   100 键约 290ns、100000 键约 260ns，差异在噪声范围内）。
