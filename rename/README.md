# rename —— 重命名检测器

`rename.Detector` 先登记一次变更中被删除与新增的文件，`Detect` 时按固定的两个阶段、
固定排序键把删除文件与新增文件配对成重命名。结果只取决于文件集合（路径与内容），
与登记顺序无关；并发的登记/检测等价于某个串行顺序。

## 构造与错误优先级

- `New(T, Cap)`：相似阈值 `T` 为 1..100 的整数，`Cap` 为登记文件总数上限且 ≥ 1。
- 构造错误按顺序只报第一个：`T` 非法 → `ErrInvalidThreshold`；`Cap` 非法 →
  `ErrInvalidCapacity`。
- 登记错误按以下优先级只报第一个（被拒登记不改变会话状态）：
  1. `ErrFrozen`：`Detect` 已调用，会话冻结；
  2. `ErrEmptyPath`：路径为空；
  3. `ErrPathExists`：该路径已登记（删除侧与新增侧合并查重）；
  4. `ErrCapacityReached`：两侧登记总数已达 `Cap`。
- 没有任何登记就调用 `Detect` 不报错，返回三个空切片的结果。

## 行与相似分

- 内容按 `'\n'` 切行，每行包含结尾的 `'\n'`；没有结尾换行的末行也算一行；
  空内容为零行。因此 `"a\n"` 是一行 `"a\n"`，`"a"` 是一行 `"a"`，二者不算相同行。
- 公共字节数 `C`：对每种不同的行，取其在两文件中出现次数的较小者，乘以该行字节数，
  求和。
- 相似分 `s = ⌊C × 100 / max(删除文件字节数, 新增文件字节数)⌋`（整除向下取整，
  例如 `⌊99.9⌋ = 99`）。

## 阶段一：精确配对（分固定为 100）

按内容逐字节相同分组，对每个内容组：

1. 先按文件名（最后一个 `/` 之后的部分）分子组；每个子组两侧各按完整路径字节序
  （字典序）排列，依次一一配对，直到其中一侧用完；
2. 组内剩余的删除/新增文件，各按完整路径字节序排列后依次一一配对，直到一侧用完。

## 阶段二：相似配对

只考察阶段一结束后仍未配对的删除/新增文件的全部组合：

1. 丢弃 `s < T` 的组合（`s == T` 保留）；
2. 候选按排序键依次取出：`(s 降序, 文件名相同优先于不同, 删除路径升序, 新增路径升序)`；
3. 两端当前都未被占用才配对成功，已占用的组合跳过。

输出：`Renames` 为 `(From, To, Score)` 列表并按来源路径升序；`UnpairedDeleted`、
`UnpairedAdded` 分别列出两侧落单路径，各自升序。

## 剪枝依据

公共字节数不可能超过较小文件，因此
`s ≤ ⌊min × 100 / max⌋`。若该上界 `< T`，则真实分数必然 `< T`，直接剪枝、不计算
`C`。非导出计数器 `commonComputed` 记录实际计算 `C` 的次数；测试在大小悬殊的集合上
断言它恰好等于「未被剪枝的组合数」（另用不剪枝的朴素实现计数对拍）。

## 并发与只算一次

所有登记与 `Detect` 由同一把互斥锁串行化，因此并发调用等价于某个串行顺序。
`Detect` 对结果做记忆化：重复或并发调用共享同一结果、配对算法只执行一次，
由非导出计数器 `detectRuns`（测试断言为 1）证明。

## 本地验证

```bash
go test ./...
go test -race -v ./rename/        # 竞态检测 + 全部用例
go test -v -run TestRandomDifferential ./rename/  # 2000 组随机对拍，日志含输入/输出/判定依据
go vet ./...
gofmt -l .
```

测试覆盖：同内容多对多同文件名先配、分数恰等于/低于 T、`⌊99.9⌋ = 99`、末行有无换行
视为不同行、两个新增竞争同一删除（高分者得）、同分文件名相同者优先、剪枝计数、
冻结后登记被拒、登记顺序无关、并发登记与并发 `Detect`，以及与不剪枝朴素实现的
2000 组随机对拍。
