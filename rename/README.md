# rename — 可撤销的批量重命名执行器

`rename` 包把一组「旧名 → 新名」映射在同一命名空间中按**同时生效**的语义拆成
单步改名执行，任何一步都不会覆盖已存在的名字，批次整体可撤销。

核心类型：

- `Namespace`：并发安全的名字集合，`Snapshot()` 供读者观察完整状态。
- `Executor`：串行提交批次（`Submit`）并撤销最近一次成功批次（`Undo`）。
- `Rename{Old, New}`、`FailureHook`（测试用步骤故障注入）。
- 错误类型：`ValidationError`（五种可区分 `Reason`）、`ExecError`、`UndoError`。

## 同时生效与校验

映射按“同一瞬间全部生效”理解，因此互换两名（`a→b, b→a`）天然合法；
`Old == New` 视为无操作，直接丢弃。

以下情形在执行前整体拒绝，返回 `*ValidationError`，命名空间**不改任何名字**。
判定顺序固定，与映射项给出顺序无关：

1. `empty_name`：旧名或新名为空。
2. `duplicate_old`：同一旧名出现两次。
3. `duplicate_new`：两个旧名映射到同一新名（自映射不参与冲突）。
4. `old_not_found`：旧名在命名空间中不存在。
5. `new_already_occupied`：新名已存在，且它不是本批中会被搬走的旧名。

## 执行顺序推导

把非自映射映射看成一张功能图：每个节点出度至多为 1（`old → new`）。
图的每个连通组件要么是**链**，要么是**环**。

- **链**（如 `a→b→c→d→e`，其中 `e` 原本不存在）：从最靠近末端的节点开始搬，
  即 `d→e, c→d, b→c, a→b`。先搬走占用目标的名字，保证每一步执行时目标名不存在。
  链不需要临时名。
- **环**（如互换 `a↔b`）：必须借一个临时名破环。

各链与环按其包含的**字典序最小名字升序**处理；环内从该最小名字先改为临时名。
因此步骤序列与映射项的输入顺序无关（`TestOrderIndependence` 固化了这一性质）。

## 破环与临时名规则

对环（以 `[s, …, p]` 表示，`s` 为环中最小名，`next(s)` 为其后继）：

1. `s → tmp`（最小名先搬到临时名，腾出 `s`）；
2. 沿环把前驱依次搬入空出的名字：`p → next(p)` …；
3. `tmp → next(s)`（临时名搬到最终目标，临时名不再残留）。

每个环**恰用一个**临时名。临时名为调用方给定前缀拼最小非负序号
（默认前缀由 `NewExecutor` 传入，如 `__tmp_0`、`__tmp_1` …），选择标准：

- 不被当前命名空间占用；
- 不与本批出现的任何名字（旧名或新名，含自映射名）相同；
- 多个环按组件最小名升序，依次领取最小的可用序号，被占用/冲突就顺延。

读者通过 `Namespace.Snapshot()` 永远观察不到临时名：整个批次在同一把写锁内
完成，对外只呈现批次之前或之后的完整命名空间。

## 失败回滚与撤销

- `FailureHook(stepIndex, from, to)` 在每步生效前调用；返回错误则该步视为失败。
  失败步不生效，此前已完成步骤**按逆序撤回**，命名空间逐项复原，
  失败批次不会登记为“最近成功批次”。
- `Undo` 只作用于**最近一次成功批次且只能一次**：撤销后记录清空，
  再次 `Undo` 返回 `UndoError{Reason: "nothing_to_undo"}`。
- 最近一次成功批次之后若又有新的成功批次，撤销作用于新批次；更早的批次
  不再可单独撤销。不含任何实际改动的批次（空批次或全部自映射）不登记撤销记录。
- 撤销动作本身同样在写锁内一次完成，撤销后命名空间逐项复原。

批次由 `Executor` 内部互斥锁串行生效；并发提交不会交错，并发读者只见完整快照。

## 日志

执行器通过 `log/slog` 记录输入、推导结果与判定依据：

- `batch submitted`：原始输入映射；
- `plan derived`：确定性步骤序列、使用到的临时名；
- `batch committed`：输入、最终 `output` 快照、步骤数与 `basis`；
- `step failed; batch rolled back`：失败步与逆序撤回动作；
- `batch rejected`：拒绝原因（五种 `Reason` 之一）与详情；
- `batch undone`：撤销的逆序动作与复原后的 `output`。

## 本地验证

```bash
# 全量测试
go test ./...

# 竞态检测 + 重复执行（验证并发串行化与读者隔离）
go test -race -count=3 ./...

# 详细日志（可看到输入、步骤序列、临时名、输出与判定依据）
go test -v ./rename/

# 覆盖率
go test -cover ./...

# 格式与静态检查
gofmt -l .
go vet ./...
```

覆盖场景见 `rename/executor_test.go`：互换与自映射、长链、十个互不相交环
恰用十个临时名、临时名占用顺延、第 k 步注入失败后的复原、撤销与重复撤销、
五类校验拒绝、输入顺序无关性、并发批次 + 并发读者、日志内容。
