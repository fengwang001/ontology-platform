# 持久卷与卷声明绑定控制器

本包实现一个内存中的确定性 PV/PVC 绑定控制器，入口是 `NewController` 与 `Controller`。

## 模块划分

- `types.go`：领域模型、状态、回收策略与绑定模式。
- `errors.go`：带优先级的错误码：参数非法、对象不存在、状态冲突、无满足的卷、容量不足。
- `model.go`：规格校验，以及对外输入的防御性复制。
- `candidate.go`：单一候选谓词、标签/访问模式/预留/节点约束判断，以及立即绑定选卷。
- `controller.go`：对象生命周期、互斥、状态机、重评估、回收、扩容和一致性自检。
- `assignment.go`：延迟联合绑定的最优指派与字典序决胜。
- `flow.go`：最小费用最大流，用于求最小总浪费完美匹配。
- `view.go`：只读快照，避免调用方持有内部可变对象。

## 关键规则

立即绑定在创建或卷事件后执行。待处理声明按名称升序逐个评估；候选在相同存储类索引中扫描，先按容量升序、再按卷名字典序选择。立即绑定时不应用节点约束。声明指定卷名后只等待该卷，即使存在其他候选也不改选。

延迟绑定只在 `BindDelayed(nodeName, claimNames)` 中发生。参与声明必须全部是未绑定的延迟声明。节点约束在该阶段生效。先构造声明到候选卷的二分图，以“卷容量减请求容量”为边费用，用最小费用最大流求最小总浪费；再按声明名称升序，逐个尝试将当前声明锁定到卷名字典序最小且仍可达到最小总浪费的卷。该两阶段方法保证全有或全无，并得到总浪费相同条件下的逐位字典序最优指派。

删除已绑定声明时清除预留名称；`Delete` 回收策略删除卷，`Retain` 使卷进入 `Released`。已释放卷不会出现在候选中，只有 `ResetVolume` 能显式恢复为可用。扩容只允许已绑定声明提高请求容量；超过卷容量返回容量不足，降低或不变返回参数非法。

## 关键取舍

- 选择单一控制器互斥锁而不是分片锁：状态规则跨卷和声明联动，单锁使串行等价性直接、可审查；测试用竞态检测验证并发安全。
- 立即绑定按存储类维护索引：选卷只遍历同存储类卷，不随无关存储类数量增长。性能测试用内部候选检查计数直接断言 10000 个无关卷时只检查 2 个同存储类卷。
- 延迟绑定不用逐个贪心：贪心可能因共享卷抢占而失败；最小费用流保证“若存在同时满足全部声明的指派则成功”。
- 字典序决胜没有编码成单个大整数费用，避免容量和对象数增长导致溢出；先求最小浪费，再逐位锁定并重新验证可行性。

## 被放弃的方案

- 全量扫描所有卷：实现简单，但立即绑定复杂度随无关存储类卷数增长，不满足性能要求。
- 贪心延迟绑定：每一步选择当前最小或字典序最优卷，可能让后续声明无卷，无法满足联合指派必须成功的要求。
- 把浪费和字典序压成单个数值：需要超大整数或固定基数，容量较大时有溢出风险，也难以解释。
- 读写锁细粒度保护匹配过程：联合绑定需要跨多个卷和声明原子提交，复杂锁顺序容易引入死锁或双重绑定。

## 一致性

`CheckConsistency` 验证：

- 声明只指向存在且处于已绑定状态的卷；
- 每个已绑定卷恰好有一个反向声明；
- 存储类索引记录完整且正确；
- 一个卷不会被两个声明同时绑定。

所有公开写操作成功返回前都会执行自检；测试辅助函数在每次操作后再次调用。

## 本地验证

```bash
GOCACHE=/tmp/go-cache /usr/local/go/bin/go test -v ./pvbinding
GOCACHE=/tmp/go-cache /usr/local/go/bin/go test -race ./pvbinding
GOCACHE=/tmp/go-cache /usr/local/go/bin/go vet ./...
```

`-v` 会打印每次测试操作的输入、实际输出和判定依据。随机差分测试使用固定种子 `1、17、1616、2026、9181`，独立朴素模型全量扫描候选、按声明名排序立即绑定，并用全排列枚举延迟联合指派，再与生产实现逐步比较错误码、绑定、容量和卷状态。
