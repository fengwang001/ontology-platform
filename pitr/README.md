# pitr — 带时间线分叉的时间点恢复（PITR）

`pitr` 包依据**基础备份**、**归档日志段**与**时间线历史**，为“在目标时间线
上恢复到目标位置”选出基础备份与回放计划并执行恢复。恢复的结果与在该时间
线上直接执行到目标位置的状态一致。

所有位置都是非负整数（类似 LSN），位置区间一律采用**左闭右开** `[start,end)`。

## 核心概念

- **时间线**：除初始时间线 `1` 外，每条时间线记录父时间线 `Parent` 与分叉位
  置 `Fork`。分叉位置之前的历史取自父时间线，分叉位置（含）之后取自身。
- **日志段**：按所属时间线与左闭右开位置区间归档（`Segment{Timeline,Start,End}`）。
- **基础备份**：记所属时间线与“已含位置的上界” `End`，即备份已包含所有
  `p < End` 的位置（`Backup{Timeline,End}`）。
- **目标模式**：
  - `ExcludeTarget`：回放 `备份上界 <= p < 目标位置`，回放窗口为 `[B,target)`；
  - `IncludeTarget`：额外回放目标位置本身，回放窗口为 `[B,target+1)`。

## 生效时间线的推导

对目标时间线沿 `Parent` 向上追溯到时间线 `1`，得到祖先链
（根在前、目标在后）。祖先链切分出互不重叠的生效区域：

```
区域 i = 时间线 chain[i]，在位置区间 [chain[i].Fork, chain[i+1].Fork) 生效
最后一个区域 = 目标时间线，在 [target.Fork, +∞) 生效
```

回放某个位置 `p` 时，只能使用“在该位置生效的时间线”的段：即祖先链上满足
`Fork <= p` 的最深一条时间线。旧时间线在分叉点**之后**的段即使覆盖了这些位
置也不得使用（段在规划时会按生效区域右端点裁剪；段中间发生分叉时，分叉点
即第一个缺口位置）。

## 规划（Plan）

1. 由 `(target, mode)` 得到回放终点 `end`（不含目标为 `target`，含目标为
   `target+1`）。
2. 按下列固定顺序只报第一个失败原因：
   1. **目标时间线不存在**：`ErrTimelineNotFound`；
   2. **目标超出已归档末端**：`end` 超过祖先链上所有归档段的最远端点，
      `ErrBeyondArchive`；
   3. **无可用基础备份**：`ErrNoBackup`；
   4. **日志有缺口**：从备份上界到 `end` 不能被各生效时间线的段连续覆盖，
      返回包装错误 `fmt.Errorf("%w at position %d", ErrLogGap, gap)`，
      `gap` 为第一个未覆盖位置（用 `errors.Is(err, ErrLogGap)` 判断）。
3. **备份可用条件**：备份 `(t,B)` 可用当且仅当
   - `t` 在目标时间线的祖先链上；
   - `B` 落在 `t` 对该目标的生效区间内（`B >= fork(t)`；不晚于下一区域分叉，
     允许恰好等于分叉点——此时备份只含共享历史，也可作为子时间线起点恢复
     的基础）；
   - `B <= end`（不超过回放终点）。

   在所有可用备份中取 **`B` 最大者**；`B` 并列时取**时间线编号更大者**
   （分叉点并列时子时间线胜出）。
4. 选定备份后，按位置从低到高回放 `[B,end)`；同一生效时间线上相邻/重叠的
   段会合并成一个确定性的回放步骤（`PlanStep`）。对同一份登记状态，`Plan`
   永远返回逐项相同的计划。

## 恢复（Recover）与新时间线分叉位置

`Recover` 在同一把互斥锁内完成“规划 + 执行 + 登记”，因此：

- 规划失败或登记规则被拒绝时**不新建时间线、不改变任何登记**；
- 成功后创建新时间线：
  - `ID = 当前最大时间线编号 + 1`；
  - `Parent = 目标时间线`；
  - `Fork = plan.ReplayEnd`，即**第一个未回放的位置**
    （不含目标模式下是目标位置本身，含目标模式下是 `target+1`；
    空回放时就是所选备份的上界）。

时间线登记规则：分叉位置**早于**（严格小于）其父时间线自身分叉位置的登记
将被拒绝并返回 `ErrForkBeforeParentFork`（等于允许）；父不存在返回
`ErrParentNotFound`，重复 ID 返回 `ErrTimelineExists`。

## 并发

- `RegisterTimeline` / `AddSegment` / `AddBackup` / `Plan` / `Recover` 均可
  并发调用；
- `Plan` 使用读锁，登记、归档与恢复使用写锁；
- 并发 `Recover` 在临界区内分配新编号，得到的新时间线编号**互不相同且连续**。

## 日志

`NewStore(logger)` 传入 `io.Writer` 后，每次操作都会打印：

- **输入**：操作名与全部关键入参；
- **输出**：成功或拒绝；
- **判定依据**：选中的备份、每步回放区间、错误顺序命中的原因、缺口位置或
  新时间线编号等。

传 `nil` 表示丢弃日志。

## 本地验证

```bash
# 全部测试
go test ./...

# 竞态检测 + 详细输出
go test -race -v ./pitr

# 重复执行（验证编号连续与计划确定性）
go test -race -count=5 ./pitr

# 覆盖率
go test -coverprofile=coverage.out ./pitr
go tool cover -func=coverage.out

# 格式与静态检查
gofmt -l .
go vet ./...
```
