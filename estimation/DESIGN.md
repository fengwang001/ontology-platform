# 团队估点投票会话服务 — 设计说明

`estimation` 包实现可精确复现的团队估点（计划扑克）投票会话：隐藏投票、
揭示时机、收敛/分歧判定、轮次上限与强制取值，在成员进出与计时到期下
均确定性可重放。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `types.go` | 公共词汇：`Card`（含两张特殊牌哨兵）、`Role`、`Phase`、`ResultKind`、`RevealOutcome`、`PeekView`、`Status` 与参数合法域常量 |
| `errors.go` | 错误类别 `ErrCode`（声明顺序即报告优先级）与唯一错误类型 `Error` |
| `deck.go` | 牌组校验（2–20 张互异正整数、严格递增）与成员资格判断 |
| `ballot.go` | 计票簿 `ballotBox`：投票/撤回/改角色/离开时增量维护分布计数 |
| `reveal.go` | 揭示判定 `Deck.evaluate`：共识/收敛/分歧/无有效票/强制取值/终局无结果，下中位计算 |
| `session.go` | 会话状态机与全部操作：统一校验流水线、惰性到期、自动揭示、并发串行化 |

依赖方向：`session` → `ballot`/`reveal` → `deck` → `types`/`errors`，无环。

## 关键取舍

### 1. 惰性到期，而非后台定时器
到期（`roundStart + T`，恰等于视为已到期）不启动任何 goroutine：每个操作
与查询在通过参数与时钟检查后、执行自身逻辑前先调用 `expireIfDue`，在
**到期时刻**（而非当前 now）揭示。到期时无人投票按无有效票处理。

理由：结果只由操作序列决定，相同序列重放完全一致；没有定时器调度抖动，
也不需要注入时钟接口。被放弃的方案：后台定时器主动揭示（不可复现、
引入并发噪声）；每个操作显式传入“是否检查到期”标志（把责任推给调用方，
易漏）。

### 2. 增量计数器，而非揭示时遍历
`ballotBox` 在 Vote/Unvote/Leave/SetRole 时维护：牌分布 `dist`、数值牌
总数 `numeric`、有票数值牌种数 `distinct`、已投人数（`votes` 键数）。
配合 `Session.voters`（在室投票者数）：

- Vote/Unvote/自动揭示判断均为 **O(1)**，与参与者总数无关；
- 揭示只扫描牌组（≤20 张）求最小/最大位置与下中位，分布是计数器副本，
  代价 **O(牌组大小)**，与参与者总数无关。

被放弃的方案：揭示时遍历全体成员统计（违反性能约束）；用堆/平衡树维护
中位数（牌组上限 20，顺序扫描已足够且更简单）。

### 3. 统一校验流水线，错误只报第一个
每个操作依次执行：参数非法 → 时钟回退 → **到期处理** → 调用者不在会话 →
权限不足 → 状态不允许 → 无人投票。被拒绝的操作不改变任何状态与时钟；
但按规范，通过参数与时钟检查的操作即使随后被拒，也已先完成到期处理
（此时操作返回中同时携带揭示结果与错误）。时钟只在操作被完全接受后
推进到其 now；`Peek` 作为查询校验时钟但不推进时钟。

### 4. 主持人身份与成员身份分离
创建者是主持人，但不自动成为成员；主持人须 `Join` 后才能投票。主持人
专有操作（Start/Reveal/Revote）只校验 `user == host`，不要求成员资格；
主持人 `Leave` 仅失去成员身份，保留主持人权限。被放弃的方案：主持人
隐含为成员（则“主持人也可作为投票者加入”无从谈起）。

### 5. 特殊牌用负值哨兵
`CardUnsure = -1`、`CardBreak = -2`，与一切合法数值牌（正整数）天然
不相交，牌组校验无需额外避让。特殊牌计入已投人数与分布，不进入
`numeric`/`distinct`，不参与统计与排序。

### 6. 状态机：Idle → Voting → Revealed → (Voting | Idle)
共识/收敛/强制取值/终局无结果使议题结束（回到 Idle，可 Start 新议题，
轮数重置、投票清空、成员保留）；分歧/无有效票且轮次未尽进入 Revealed，
只能 Revote 进入下一轮。严格按规范，Revealed 状态下不允许 Start
（不可跳过未用尽的分歧轮次直接开新议题）。

### 7. 单互斥锁串行化
所有方法可并发调用，锁内完成“校验流水线 + 状态变更”，效果等价于某个
串行顺序；每轮至多揭示一次由状态机保证（揭示后即离开 Voting）。

## 本地验证方法

```bash
# 全部测试（含 ≥1500 组随机序列与朴素模型对照、重放确定性）
go test ./estimation/

# 竞态检测
go test -race ./estimation/

# 查看对照测试日志（输入操作、输出、判定依据、覆盖统计）
go test -run TestModelAgainstNaive -v ./estimation/

# 性能证明：同一基准在 participants=1e3/1e4/1e5 下 ns/op 应基本持平
go test -run xxx -bench=. ./estimation/
```

实测（linux/arm64）：Vote 在 1k/10k/100k 参与者下均为 ~63 ns/op；
揭示判定 ~207 ns/op（最坏情形 ~400 ns/op），均与参与者总数无关。

测试分层：

- `session_test.go`：定向覆盖规范列出的全部场景——时限恰等于与差一秒、
  自动揭示由离开/改角色触发、特殊牌计入已投但不计入统计、相邻与不相邻、
  偶数张下中位、轮次用尽与未用尽、无有效票两条路径、新议题重置、
  揭示前零泄露、错误优先级、被拒操作不改状态与时钟、被拒操作仍先做到期
  处理、权限与成员规则、20 万参与者规模、并发冒烟。
- `model_test.go`：独立朴素模型（揭示时全量遍历重算）与生产实现逐操作
  对照 1500 组随机序列，每组额外重放一次验证确定性；断言随机序列实质性
  覆盖全部结果类别、触发方式与错误码。
- `bench_test.go`：上述性能基准。
