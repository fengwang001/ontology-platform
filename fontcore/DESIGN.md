# fontcore 设计说明（≤40 行）

1. 单包五模块：`types/errors`（契约）、`rangeset`（字符范围索引）、
   `family`（登记+三维匹配）、`engine`（时钟/加载期/回退/整形）、`naive`（暴力对照）。
2. 并发：一把 `sync.Mutex` 串行化登记、推进、加载报告、整形。
   锁内逻辑确定且无阻塞，故并发结果恒等于某一合法串行序；触发时刻取首次入锁时刻，每人脸至多一次。
3. 复杂度：先把所有人脸区间并成不相交公共段（构建一次），每段建一棵中点区间树。
   覆盖判定 = 段二分 `O(log S)` + 区间树 `O(log R + k)`，不随人脸/区间总数线性扫描；
   匹配仅在覆盖候选 `k` 上比较排序键。`TestPerformanceNotLinear` 用候选恒为 1
   与查询节点数 ≤ `log2(n)+2` 可验证这两点。
4. 匹配：宽度 → 倾斜 → 字重字典序键；宽度 `2*距离+偏向位`（仅等距时偏向位起决定）；
   倾斜 0 一致 / 1 正常合成斜体 / 2 禁止反向；字重 (组, 距离) 编码三段规则；
   全并列以登记序（faceID）兜底。
5. 期：阻塞期/交换期长度来自 `Config`；边界左闭右开，一律 `t < end`。
   阻塞/交换的交换期无限；回退两期有限；可选无交换期，期满立即永久回退且迟到完成不替换。
6. 显式 `Failed` 立即结束阻塞占位并永久回退；`Loaded` 只在对应最终边界前才允许替换。
7. 回退：按声明顺序取首个“已就绪且覆盖”的族，在其已加载人脸中做同一套匹配；
   回退路径绝不触发任何加载；全无覆盖则最后手段标记。
8. 整形：逐字符得 (族, 人脸, 时期, 合成斜体)，相邻四元组相同者按字节偏移合并为段。
9. 错误六类用哨兵 + `errors.Is` 区分；入口按“参数→时钟→族→人脸→重复→加载状态”校验，
   任何拒绝都在校验通过前返回，不触碰登记/时钟/加载表。
10. 被放弃方案：(a) 每码点位图——省查询但构建/内存随码点空间爆炸，且难支持多不相交区间；
    (b) 全局单区间树混放多人脸——范围不同的人脸会在枢轴列表交叉，裁剪复杂；
    改用“公共段 + 段内树”，语义直观且每段树内 id 不重复；
    (c) 每族细粒度锁——规范只要可串行化，单锁更可证且临界区极短。
11. 阈值相等（low==high）的边界归属规范未明：定为等于点归入低段（先向下），
    朴素模型与引擎共用此取舍并在测试中固定。
12. 本地验证：`go test -race ./fontcore/`（竞态）、
    `TestRandomDifferential`（80 种子×300 步双模型逐字符/触发/错误类别对照）、
    各策略期末恰等时刻、宽度双侧、斜体单向、字重三段、并发一致性等用例；
    `SetLogger(log.New(...))` 打印每次输入、输出与触发/判定依据。
