# 麻醉与精神类药品专用账册 — 设计说明

## 1. 模块划分与职责

代码全部位于 `narledger/` 包，模块单一职责、通过 `Ledger` 编排协作：

| 文件 | 职责 |
| --- | --- |
| `errors.go` | 错误类别 `ErrorCode` 与 `OpError`。类别数值顺序即题面要求的报错优先级。 |
| `clock.go` | 单调时钟：记录已接受操作的最大 `now`；`check` 只判定回退，`advance` 只在操作被接受后推进。 |
| `logger.go` | 逐步日志（线程安全）：每个操作的输入、ACCEPT/REJECT 输出与判定依据。 |
| `auth.go` | 授权名单：左闭右开区间 `[start,end)` 的登记、提前撤销、时刻有效性。 |
| `batch.go` | 批次账面：批号唯一性、余量、效期；入库/销毁累计量与每药品 FEFO 堆。 |
| `heap.go` | 可按批号 O(log n) 删除的 FEFO 索引堆（效期 → 入库序号）。 |
| `order.go` | 领用单据：状态机 `OPEN → SETTLED | OPEN → DISCREPANCY → SETTLED`、分批记录、结清期限。 |
| `department.go` | 科室：OPEN 计数、差额集合、逾期集合与按期限排序的索引堆；锁定 O(1) 摊还判定。 |
| `validate.go` | 参数取值域与两名复核人的统一校验（人数/同一人/申请人本人/授权）。 |
| `ledger.go` | 操作编排：按错误优先级串行校验、原子提交，`sync.Mutex` 保证并发等价于某串行顺序。 |
| `snapshot.go` | 确定性快照、快照深度比对、账面不变量独立核验。 |

## 2. 关键判定规则

- **效期**：`now < expireAt` 才可发；`now == expireAt` 即过期。过期批次不计入可发库存，但账面保留直到销毁；退回可以进入已过期批次（账面增加，但仍不可发，只能销毁）。
- **授权**：同一人可登记多条 `[start,end)` 区间；撤销在 `at` 处把覆盖区间收口为 `[start,at)`、删除未来区间，历史区间保留；`at` 起立即失效，已完成的领用/销毁不受影响。
- **复核**：两名复核人必须都非空、互不相同、都不是申请人（仅领用）、在 `now` 均授权有效。
- **选批**：FEFO——效期最早优先，效期相同按入库序号（入库先后）；可跨批次；全有或全无，单据记录每个批次分出量。
- **未结清上限**：每科室同时最多 3 张 `OPEN`；`DISCREPANCY` 不计入。
- **结清**：`used + returned + residue == qty` 结清；`< qty` 转差额待处理并记录差额；`> qty` 拒绝且单据不变。已用量/残液量不回账面；退回量回原批次。
- **退回回补顺序**：按该单据 FEFO 分出顺序逐批回补（先分出的批次先回补），回补量不超过该批原分出量。这是题面未细化处的取舍，见 §5。
- **期限与锁定**：期限为领用时刻 + 86400 秒，`now == deadline` 仍在期内，`now > deadline` 才逾期；逾期单可补结。科室锁定当且仅当存在逾期 `OPEN` 或 `DISCREPANCY` 单据；锁定随时间在任何读写路径的 `refresh` 中自然体现，无需专门触发操作。
- **销毁**：数量不超过批次当前账面余量；两名授权复核人见证；未过期批次也可销毁；不可逆。
- **错误优先级**（只报第一个）：参数非法 → 时钟回退 → 复核人（人数/同一人/本人）→ 复核人授权无效 → 对象不存在 → 状态不符 → 科室锁定 → 超过上限 → 库存不足 → 数量超出。

## 3. 性能设计与可验证性

### 3.1 选批不随历史批次数增长

每个药品维护一个 **FEFO 索引堆**，堆中只放「当前可发且余量 > 0」的批次：

- 批次库存耗尽时立即出堆；批次过期（在领用时发现堆顶 `expireAt <= now`）立即出堆；
- 批次被退回恢复余量且仍未过期时重新入堆；
- 已耗尽/已过期批次只保留在批次总账 map（账面要求），不再进入选批路径。

一次领用从堆顶顺序取出，直到取满，因此触及节点数等于**实际分出批次数**（加被识别为过期的堆顶，每个过期批次在其生命周期内最多被弹出一次）。库存不足时，选批期间弹出的节点全部回插，账面与索引均恢复到操作前，保证「拒绝不改变任何状态」。

### 3.2 锁定判定不随科室历史单据数增长

每科室维护：

- `openCount`：当前 `OPEN` 数（上限判定 O(1)）；
- `overdue` 集合：已过期限的 `OPEN` 单据；
- `discrepancy` 集合：差额待处理单据；
- `dueHeap` + `duePos`：**只含当前 OPEN 单据**的期限小顶堆，支持结清时 O(log n) 摘除。

`refresh(now)` 只把堆顶 `deadline < now` 的单据移入 `overdue`。每张单据入堆一次、出堆一次，故任何锁定判定的总扫描量对该科室全部历史是 O(单据数)，单次摊还 O(1)，与历史总数无关。并发同刻结清时位置映射可能已被 `refresh` 弹出，摘除路径用「id 校验」惰性丢弃陈旧下标。

### 3.3 两档规模对照

`TestComplexityProof`（`go test ./narledger/ -run TestComplexityProof -v`）在
`N = 1 000` 与 `N = 100 000` 两档下构造同一药品 N 个历史批次、同一科室 N 张历史单据，然后：

- 断言 FEFO 选批 `DispenseTouched() == 1`（只分出 1 个批次，触及节点恒为 1）；
- 与「全量扫描全部批次求可发库存」的朴素做法对照耗时；
- 断言 BIGDEPT 期限堆已清空、锁定判定耗时不随 N 增长。

本机一次实测（arm64）：

```
规模=  1000: 选批触及=1 选批 3.7µs  朴素全量扫描  76.8µs 锁定判定  1.8µs
规模=100000: 选批触及=1 选批 3.2µs  朴素全量扫描 6886µs  锁定判定 23.9µs
```

历史批次扩大 100 倍，朴素扫描扩大约 90 倍，而优化实现选批触及恒为 1。

## 4. 并发、重放与不变量

- 所有公开方法以同一把 `sync.Mutex` 串行化临界区；阻塞发生在所有校验之前，因此并发调用的结果等价于某个合法串行顺序（`go test -race` 通过）。
- 被拒绝的操作不修改任何字段，也不推进时钟（包括 FEFO 索引弹出，已在失败路径回插）。
- `Snapshot()` 导出全部批次账面与单据状态的确定性结构；同一操作序列在两个账册重放，`EqualSnap` 必须完全一致（差分测试对每一步结果码、两份快照做比对）。
- `CheckInvariant()` 独立从单据重新汇总累计领出/退回，逐药品核对：
  `账面总量 = 入库总量 − 销毁总量 − 累计领出量 + 累计退回量`。

## 5. 关键取舍与被放弃的方案

- **放弃全局惰性过期扫描**：最初设想在「时钟推进」时统一把到期批次移出堆。但一次**被拒绝**的操作（例如库存不足）如果先移动了索引，就违反「拒绝不改变状态」。改为在选批路径弹出 + 失败回插；接受时弹出是最终生效的索引维护。
- **退回回补采用 FEFO 顺序而非按比例**：按整数比例在小数量下有歧义且不可复现；按原分出顺序逐批回补确定、简单，且保证每批回补不超过原分出量。
- **授权允许登记多条/可交叠区间**：贴近现实中分段授权；撤销按区间切割而不是整人布尔位，历史区间得以保留，撤销时刻边界可精确复现。
- **锁定判定不用每次全量扫描单据**（朴素模型正是如此，仅用于对照）；堆 + 集合方案把成本限制在活跃数据规模。
- **只读查询也校验时钟回退**：题面要求 `now` 不得小于上一次被接受操作；查询不推进时钟，但早于时钟的查询报时钟回退，避免用查询探测历史。
- **差额处理与销毁都不改变业务库存**（销毁只减批次余量，差额处理完全不动账），由不变量核验兜底。

## 6. 本地验证方法

```bash
# 本仓库 Go 构建缓存默认目录在部分沙箱中只读时：
export GOCACHE=/tmp/gocache

go test ./...                      # 全量
go test -race ./narledger/         # 竞态
go test ./narledger/ -run TestComplexityProof -v   # 规模/复杂度两档对照
go test -cover ./narledger/
gofmt -l . && go vet ./...
```

差分对照：`TestDifferentialVsNaive` 使用固定种子生成 **1500 组**随机操作序列，
与独立朴素模型 `naive_test.go`（全量扫描、无堆/计数器）逐操作比对错误码，
序列结束后比对完整快照、锁定判定与账面不变量，并在第二个独立账册上重放比对。
逐步日志（每步输入、输出、实际/朴素判定依据）写入：

```
/tmp/narledger-diff/diff.log
```
