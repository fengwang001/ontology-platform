# raid5 — 带分布式奇偶校验的条带化块卷

`package raid5` 实现一个 RAID-5 语义的块卷：N（≥3）块成员盘，每条带
N−1 个数据块 + 1 个 XOR 校验块；校验块按条带在各盘间轮转分布。支持
单盘失效后的降级读写、换盘后台重建，以及写入途中断电后的一致性恢复，
不存在传统 RAID-5 的“写洞”数据丢失。

代码入口：

- `raid5/layout.go`：盘/条带映射与 XOR 工具
- `raid5/disk.go`：成员盘抽象与文件实现（失效/换盘/重建进度持久化）
- `raid5/journal.go`：只追加意图日志（意图 + 提交，CRC 保护）
- `raid5/volume.go`：卷状态、打开恢复（两种重放规则）
- `raid5/io.go`：正常态整带写/读-改-写、降级整体写、降级读
- `raid5/control.go`：失效、换盘、后台重建、关闭
- `raid5/errors.go`：可区分的拒绝原因

## 1. 布局推导

设成员盘号为 `0..N-1`，条带号 `s ≥ 0`。

- 校验盘位置（题目指定的左对称轮转）：

  `P(s) = N-1 - (s mod N)`

  即 s=0 时校验在最右盘，之后每条带左移一盘，回绕。
- 数据块从校验盘的下一块盘起依次排列并回绕，第 k 个数据块
  （k = 0..N−2）位于：

  `D(s,k) = (P(s) + 1 + k) mod N`

- 连续逻辑块号 `b` 映射：

  `stripe = b div (N−1)`，`slot = b mod (N−1)`，`disk = D(stripe, slot)`

N=4 示例（P 为校验）：

| 条带 | 盘0 | 盘1 | 盘2 | 盘3 |
|-----|-----|-----|-----|-----|
| s=0 | d0  | d1  | d2  | P   |
| s=1 | d1  | d2  | P   | d0  |
| s=2 | d2  | P   | d0  | d1  |
| s=3 | P   | d0  | d1  | d2  |

每条带恰好使用每块盘一次。

## 2. 写入规则与读-改-写公式

条带恒成立的不变量：`P = d0 XOR d1 XOR … XOR d(N-2)`。

- **整条带写入**：覆盖全部 N−1 个数据块，无需读旧值：

  `P_new = d0_new XOR … XOR d(N-2)_new`

- **部分条带写入（读-改-写，RMW）**：只覆盖集合 W 中的数据块。
  由 `P_old = XOR(所有旧数据)`，把被改块的旧贡献换为新贡献：

  `P_new = P_old XOR d_old XOR d_new`（对每个被改写块连异或）

  即只需读旧校验与被改块的旧数据，与未改块无关。

写盘顺序（每步都 fsync）：

1. 追加意图记录（条带号 + 覆盖位图）并落盘；
2. 写新数据块；
3. 写新校验块；
4. 追加提交记录并落盘。

## 3. 写洞（write hole）成因

传统 RAID-5 的一次小写要分别写数据块与校验块，两者不在同一原子介质上。
若断电发生在“新数据已落盘、新校验未落盘”（或反过来）之间，重启后
`P ≠ XOR(数据)`：条带进入不一致状态，且系统无法判断哪个块是新、哪个是
旧；此后再失效一块盘，用错误校验重建出的块就是损坏数据——这就是写洞。

本实现用**写前意图日志 + 确定性恢复规则**消除写洞：写任何数据/校验之前
先把“打算改哪个条带”持久化。重启时发现某条带有意图而无提交，就按下面
第 4 节的规则把条带收敛到唯一一致状态。

## 4. 两种状态下的恢复规则

打开卷时扫描日志（记录有 magic、长度与 CRC32；写了一半/撕裂的尾记录
直接视为不存在）。只需要处理最后一条“有意图、无提交”的记录。

- **正常态（无盘失效）**：意图只记录条带号与覆盖位图，不携带数据。
  重启后数据块与校验块可能停在旧旧/新旧/新新任意组合，但**数据块上的值
  永远是某个完整块的旧值或新值，不会撕裂**。恢复直接以现存全部数据块
  重算校验并写回：

  `P := XOR(现存所有数据块)`

  这样条带一定满足不变量。若数据已写新则保留用户新数据；数据未写则
  保留旧数据——不存在“校验是新、数据是旧”的错误组合。

- **降级态（一块盘已失效，含重建中）**：降级写时无法读到失效槽，
  先用其余 N−1 块 XOR 还原它，得到条带完整新内容（全部新数据 +
  新校验），**意图记录同时携带这些内容**。落盘顺序：

  1. 追加携带整带新数据与新校验的意图并 fsync；
  2. 把全部新块写到所有存活盘（含换入新盘的对应槽，写即标记已重建）；
  3. 追加提交。

  重启恢复时对未完成意图**整体重放**：把意图中的每个块写到对应存活盘。
  因此无论断电在步骤 2 的哪个时刻，重启后条带都是同一个完整新状态，
  已确认（已形成意图）的写入不丢，不变量恒成立。

重放完成后日志截断清空。已提交的意图无需处理。

## 5. 降级读与换盘重建

- **降级读**：目标块所在盘失效时，读取同条带其余 N−1 块（其余数据块 +
  校验块）逐字节 XOR，即得目标块；任意两块同时不可用返回
  `ErrDoubleFault`。
- **换盘**：`ReplaceDisk` 只能针对当前失效盘，且无重建在进行；新盘为
  全零空盘。重建在后台按条带号顺序进行：
  `缺失块 = XOR(其余盘同条带块)`，写入新盘并把条带号追加到
  `.rebuilt` 进度文件。
- **重建不中断服务**：每条带有独立互斥锁，同条带读写串行、不同条带
  并发。重建对某条加上锁；重建期间对该条带的降级写会直接把正确的新块
  写入新盘并记录进度，重建循环跳过已完成槽。
- **已重建块立即参与读取**：新盘 `ReadBlockForRebuild` 对已重建槽
  返回新值，未重建槽返回 `ErrDiskDead`，读路径随即改走 XOR。
- **重建中断续建**：`.rebuild` 标记 + `.rebuilt` 进度持久化。重开卷
  若发现失效标记已消失但重建标记仍在，自动恢复重建并跳过已有进度；
  全部完成后清除标记。

## 6. 拒绝规则（不写任何盘）

下列操作在触碰任何盘之前整体拒绝，错误可 `errors.Is` 区分：

| 场景 | 错误 |
|------|------|
| 逻辑块号越界 / 空写 / 块长度不对 | `ErrBlockOutOfRange` |
| 盘号越界 | `ErrDiskIndexOutOfRange` |
| 已有一盘失效，再标记另一盘 | `ErrTwoDisksFailed` |
| 对未失效盘换盘重建 | `ErrRebuildHealthyDisk` |
| 重建进行中再次发起重建 | `ErrRebuildInProgress` |
| 需要两块以上才能恢复 | `ErrDoubleFault` |

## 7. 确定性

成员盘为定长文件、新盘零填充、重建按条带号顺序、意图提交后日志在打开
时截断、进度文件按完成顺序追加。给定相同的写入序列与相同断电点，
重新打开后各数据盘、标记文件与日志内容逐字节相同（见
`TestFileDiskCrashDeterminism`）。

## 8. 本地验证

```bash
# 全量测试（含文件盘端到端、竞态检测）
go test -race -v ./raid5

# 竞态 + 覆盖率
go test -race -coverprofile=/tmp/cov.out ./raid5
go tool cover -func=/tmp/cov.out

go vet ./...
gofmt -l .
```

测试覆盖（日志中打印输入、输出与判定依据，用 `-v` 查看）：

- `TestLayoutMapping`：N=3/4/5 每条带校验盘/数据盘映射表；
- `TestPartialWriteCrashEachStep`：N=3/4/5 部分条带写在意图后、数据后、
  校验后、提交后四个断电点崩溃并重开，校验不变量与数据保留规则；
- `TestDegradedWriteReplay`：降级写在各断电点崩溃，意图携带新数据+新
  校验，重开整体重放；
- `TestRebuildConcurrentWriters`（N=3/4/5）：重建期间多 goroutine
  并发写 + 持续读，重建完成后逐带校验；
- `TestRebuildResumeAfterCrash`：重建中断续建结果与连续重建逐字节相同；
- `TestFileDiskFailReplaceRebuild`：文件盘 `.dead/.rebuild/.rebuilt`
  标记的持久化与清理；
- `TestFileDiskCrashDeterminism`：同序列同断电点两次运行各盘逐字节相同；
- `TestRejectReasons`：四类拒绝场景及“被拒绝不写盘”快照比对。
