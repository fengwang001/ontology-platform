# iblt：可逆布隆查找表（IBLT）集合对账草图

`iblt` 包把两个副本的键集合各自写入草图，相减后剥离出各自独有的键，
使对称差的恢复结果、失败判定与错误类别可精确复现。键为 `uint64`。

## 草图结构

草图有 `m` 个格子，`m` 必须为 3 的正整数倍，均分为三段，每段 `m/3` 格。
每格存三个分量：

- `count int64`：计数（带符号累计）
- `keyXor uint64`：键异或
- `checkXor uint64`：校验异或

## 位置与校验的计算

`mix(z)` 为 splitmix64 最终混淆（乘法按 uint64 回绕）：

```
z ^= z >> 30; z *= 0xBF58476D1CE4E5B9
z ^= z >> 27; z *= 0x94D049BB133111EB
z ^= z >> 31
```

- 键 `x` 的第 `i` 个位置（`i = 0,1,2`）：
  `i·(m/3) + (mix(x + (i+1)·0x9E3779B97F4A7C15) mod (m/3))`
- 校验值：`g(x) = mix(x ^ 0xD6E8FEB86659FD93)`

`Add(x)` 对三个位置的格子各令计数 `+1`、键异或 `x`、校验异或 `g(x)`；
`Remove(x)` 对同样三格令计数 `-1`，键与校验同样异或（不检查键是否存在，
只是带符号累计）。`Subtract(a, b)` 返回新草图：逐格计数相减、键异或与
校验异或分别相异或。

## 纯格子与剥离次序

`Decode(limit)` 在草图的**副本**上剥离，不改变原草图：

1. 从格子下标 0 起顺序扫描，选第一个**纯格子**：计数为 `1` 或 `-1`
   且 `g(keyXor) == checkXor`。
2. 计数为 `1` 的键记入「仅 a 侧」，计数为 `-1` 的键记入「仅 b 侧」；
   随后从副本中撤销该键（计数 `1` 执行 `Remove` 的效果，计数 `-1`
   执行 `Add` 的效果），再回到下标 0 重新扫描。
3. 没有纯格子时停止。停止时所有格子的三个分量全为 0 才算成功，
   返回两个升序键列表；否则报不可解码。

注意：计数为 0 而分量非零的格子不是纯格子；计数为 1 但校验不匹配
（多个键挤压在同一格）也不是纯格子。

## 错误优先级

所有被拒绝的操作整体失败、不产生副作用，错误可用 `errors.Is` 区分：

| 错误 | 触发条件 |
| --- | --- |
| `ErrInvalidSize` | 构造时 `m` 不是 3 的正整数倍 |
| `ErrSizeMismatch` | `Subtract` 的两个草图 `m` 不同（不产生结果） |
| `ErrNegativeLimit` | `Decode` 的 `limit` 为负（最先判定） |
| `ErrLimitExceeded` | 即将记入第 `limit+1` 个键（优先于不可解码） |
| `ErrNotDecodable` | 同一键被重复剥离（先于超限判定），或停止时格子有残留 |

`Decode` 只报第一个错误：先判 `limit` 为负，其后按剥离过程中先发生者
（重复键 → 不可解码；第 `limit+1` 个键 → 超出上限）。

## 并发语义

`Add`、`Remove`、`Subtract`、`Decode` 均可并发调用，结果等价于某个串行
顺序。`Subtract` 对两侧各取快照（按内部 id 顺序加锁），同一草图自减合法
且得到全零草图，不会死锁。`Decode` 返回的列表不与内部状态别名。
