# 配送围栏与动态收缩：设计说明

1. 模块拆分：`range.go` 范围/环距（环距→单元的不可变表，判定 O(1)）；
   `shrink.go` 平台事件、区域有效等级与恢复时刻；`order.go` 订单状态机；
   `system.go` 时钟、拒绝次序与全部操作的并发协调；`errors.go` 可程序化区分的错误码。
2. 有效等级=max(覆盖该时刻的平台事件等级, 商家等级)，有效半径=max(0, 基础半径-有效等级)，
   环距≤有效半径可达（恰等于仍可达）。区间左闭右开，右端点事件不再计入。
3. 事件索引：未开始事件进 start 最小堆；已提升事件按等级分桶，每桶是“生效结束时刻”最小堆，
   桶顶过期/世代失效即弹，最高非空桶即最大等级。每条目至多入堆、出堆一次。
4. 终止=世代号+1 的不可变快照方案：旧快照成为惰性墓碑；开始前终止在提升时按截断边界发布。
5. 恢复时刻查询在堆的**克隆视图**上向后扫描，避免预读污染单调推进的主索引（曾因此出错，已加隔离测试）。
6. 性能：一次可达判定为一次哈希查表 + 一次整数比较，与基础范围单元总数无关；
   等级来自当前活跃桶，已结束事件的堆条目被裁剪，不随历史事件数增长（见 TestPerformanceConstant）。
7. 并发：单把互斥锁串行化所有操作，故等价于某串行顺序；接单的可达校验与落库在同一临界区。
8. 时钟：被接受操作更新最大时刻，更早时刻报 ErrClockRollback；被拒绝操作不改动任何状态。
9. 接单收缩：可达性在接单时刻重校，暂时不可达则拒绝并将订单置“因收缩取消”终态；
   已接单订单此后不受任何收缩影响；改址按当时等级校验，仅一次，被拒不改原地址。
10. 不可达二分：不在基础范围=永久不可达；在范围内但环距>有效半径=暂时收缩不可达，错误码/枚举可区分。
11. 放弃方案一：全局按等级排序的单一最大堆——过期的高等级条目会压住后面有效低等级条目而无法安全弹出。
12. 放弃方案二：读写锁/RWMutex——读路径会惰性推进堆状态，本质有写副作用，单锁更易证明线性一致。
13. 放弃方案三：恢复查询复用主索引推进——会破坏“当前时刻”语义，改为克隆视图。
14. 朴素对照 `NaiveSystem`：每次有效等级线性扫描该区域全部事件、可达性扫描全部单元，独立实现。
15. 差分测试随机生成 120 条种子、每条约 300 个操作（含回溯时间、回溯终止、嵌套/重叠事件、改址、取消），
    逐步比对错误码、返回值与订单终态。
16. 日志：`go test -run TestDifferentialRandom -v` 打印每步输入、两模型输出与判定依据。
17. 本地验证：`go test ./...`、`go test -race ./...`、`go vet ./...`、`gofmt -l .`。
