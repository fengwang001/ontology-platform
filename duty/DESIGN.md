# 设计说明（机组值勤时限与排班合规）

1. 模块划分：`types.go`（配置/值勤期/结论）、`rules.go`（时段、单次上限、休息、资质纯函数）、
   `rolling.go`（滚动窗累计数学）、`system.go`（状态、变更操作、拒绝次序、并发锁）、
   `query.go`（最早可报到时刻）；测试中 `naive_test.go` 为独立朴素模型。
2. 并发等价串行：单一互斥锁包住全部变更操作，天然可线性化；值勤期 ID 由单调计数器分配，
   拒绝操作不推进时钟、不改状态，重放同一操作序列结论一致。
3. 拒绝次序严格按题给 12 类顺序短路；滚动类错误返回使超限的最小整数窗起点。
4. 滚动 7/28 日判定（关键取舍）：累计时长 F(w) 是窗起点 w 的分段线性函数，斜率只在
   `a-win,a,b-win,b` 四类折点跳变。因此不必逐分钟扫描，只需在折点间按斜率推进，
   上升段首个越界点用 `ceil((cap+1-F)/slope)` 精确求出。这是相对“逐分钟枚举”放弃
   的直观方案；后者在 28 日（40320 分钟）规模下虽仍可接受，但折点法给出常数级判定。
5. 判定成本：先用二分定位插入位置，再只纳入与相关窗有交的值勤期。任意滚动窗内的
   值勤期数量被“累计上限 ÷ 最短可能休息约束”界定为配置常数，故每次判定访问的
   值勤期数为常数；与人员总数无关（按 personID 直接索引）。诚实说明：插入位置的
   二分是 O(log H)（H=该人员历史数），这是为保持内存有序做出的唯一非严格常数项。
6. 延长：临时替换终点后复用同一套滚动/休息/资质检查，保证“延长后重新成立”；
   “7 日内至多一个延长值勤期”化为两区间 `min(end)-max(start) < W7` 的判据。
7. 最早可报到时刻（关键取舍）：可行性是报到时刻 s 的分段线性/分段常数谓词，折点来自
   相邻值勤期的端点与休息、滚动窗四类折点与候选区间两沿的对齐、时段边界及候选解除
   时刻跨边界；枚举全部折点后逐一判定，首个可行点即精确最小值，并以一个保证空旷的
   远期上界保证终止。放弃了“逐分钟扫描”的实现方案（保留在朴素模型中做差分基准）。
8. 被放弃方案：按归属日整天累计（不符合“按重叠长度”要求）、为每人维护固定分钟数组
   （内存随时刻无上界）、树堆/跳表（插入 O(log H) 但实现复杂且无法消除 log 项）。
9. 本地验证：`go test ./...`（边界、拒绝次序相邻对、并发）、`go test -race ./...`；
   `TestDifferentialRandom` 对 300 组随机配置×140 步随机操作与朴素模型逐项比对，
   逐步输入/输出/依据写入 `duty/fuzz_trace.log`；`TestRollingMathAgainstBrute` 对
   2000 组随机区间集比对折点法与逐窗枚举。
