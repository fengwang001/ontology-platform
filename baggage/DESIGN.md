# 联程行李中转与超重计费 — 设计说明

## 模块划分
- `types.go`：领域类型与统一错误（`ErrCode` 声明顺序即拒绝次序）。
- `allowance.go`：额度归属——首个跨区域航段承运人，否则首航段承运人。
- `through.go`：直挂拆分——清关/跨记录/停留越界（闭区间外）即新托运段。
- `fee.go`：单段计费——计件（超件+超重叠加）、计重（合并池+会员本人抵扣）、绝对上限拒收。
- `system.go`：`System` 主体——参数校验、时钟、拒绝次序、记录存取、互斥锁串行化。
- `naive_test.go`：独立朴素模型 + 3000 组随机比对（日志含输入/输出/判定依据）。

## 关键取舍
- 额度、拆段、计费全部做成纯函数，只依赖入参（行程、行李、配置、注册表），
  因此“每段费用等于单独办理该段”天然成立，重放必然可复现。
- 计重合并模型：会员额外重量先抵扣本人（`max(0, w-extra)`），剩余再共享免费池；
  该式与“顺序分配池”等价，朴素模型用后者独立实现以交叉验证。
- 全局单互斥锁串行化所有变更操作，换取线性化语义与零竞态，拒绝路径不推进时钟。
- 超重拒收按“段顺序 × 行李全局序号”扫描，报第一件超限；拒收前不落任何状态。

## 被放弃的方案
- 按航段逐个累计费用再合并：会破坏“一段托运一次计费”的语义，改为先拆段再逐段计费。
- 读写锁 + 原子时钟：拒绝操作不推进时钟的要求使读路径也必须观测一致状态，简化为单锁。
- 把会员额外额度并入公共池：与“不转移”规则冲突，放弃。

## 性能与可验证性
- 办理开销 = O(航段数 + 旅客数 + 行李数)，只经 map 做 O(1) 查询，
  与历史记录数、机场总数无关；`System.iterOps` 对全表迭代计数，
  `TestCostIndependentOfHistory` 断言 500 次办理后计数恒为 0。

## 本地验证
- `go test ./baggage/`：全部针对性用例（额度归属、停留闭区间、清关/跨记录、
  制式切换、超件超重叠加、合并差异、会员不转移、恰等于截止、拒绝次序相邻对）。
- `go test -race ./baggage/`：并发办理等价于串行。
- `go test -v ./baggage/ -run TestNaiveComparison`：随机比对并打印每步依据。
