# 事务作用域调度内核 — 设计说明

## 模块划分（idb/ 下 6 个实现文件）
- `errors.go`：九类可区分错误（八类必备 + Aborted），拒绝次序在文档注释中固化。
- `store.go`：MVCC 对象仓库，每键一条按提交序号递增的版本链。
- `scheduler.go`：调度队列，只保留排队与运行中事务；判定规则集中于此。
- `transaction.go`：事务/请求/升级事务句柄，覆盖写缓冲、显式提交与中止。
- `connection.go`：连接生命周期，关闭时批量取消未开始事务、放行已开始事务。
- `kernel.go`：数据库注册表、打开/删除队列、版本变更编排、锁外回调与自动提交。

## 关键取舍
- 单一全局互斥锁：所有公开操作在锁内变更状态，天然等价于某串行顺序；
  用户回调统一排入队列在锁外执行（`finish` 循环），避免持锁回调死锁。
- MVCC 版本链：提交只在本事务写过的键上追加版本，开销与无关键数无关；
  只读快照 = 开始时刻的提交序号，无需拷贝数据。
- 调度器只存未结束事务：开始判定开销随活跃事务数增长，与已结束事务数无关。
- 排队请求逐个执行、每个请求的回调链跑完再执行下一个，保证链式请求顺序。
- 关闭连接时先快照再批量取消（取消期间不调度），保证"关闭时尚未开始"语义确定。
- 版本变更在仓库集合的浅拷贝上进行，中止即丢弃拷贝，整体回滚。

## 被放弃的方案
- 整仓库 copy-on-write 提交：提交开销随仓库键数增长，违反性能要求。
- 持久化数据结构（HAMT）：正确但复杂度远超 MVCC 版本链的收益。
- 每请求新 goroutine / 事件循环 actor：串行等价证明与测试确定性都变差。
- 可重入锁（回调内直接重入内核）：Go 无原生支持，易死锁，改为锁外回调队列。

## 本地验证
- `go test ./idb/ -v`：13 类规定场景 + 错误拒绝次序 + 两个性能证明（计数器白盒断言）。
- `go test -race ./idb/`：含 8 线程并发冒烟与 150 种子 × 400 步随机对照。
- 随机对照：内核（增量调度 + MVCC）与朴素模型（全量扫描 + 深拷贝快照）
  逐步比较事务状态、请求结果与已提交数据；日志打印输入、输出与判定依据。
- `gofmt -l idb/` 与 `go vet ./idb/` 保持干净。
