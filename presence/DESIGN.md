# 多设备在线状态聚合与订阅通知服务 — 设计说明

## 1. 模块划分

实现位于 `presence` 包，按职责拆分为四个文件：

- `types.go`：对外值对象。`Status`（离线/离开/忙碌/在线，数值即聚合优先级）、
  `DeviceInfo`、`QueryResult`、`Notification`、`DrainResult`。
- `errors.go`：可区分的拒绝错误（参数非法、时钟回退、不存在、设备过多、
  重复订阅、订阅自己、拉黑自己），并提供 `IsStateError`。
- `state.go`：纯数据结构与无锁算法。
  - `device`：单台设备，带堆下标与“续租来源操作序号”`originSeq`；
  - `expiryHeap`：按到期时刻排序的最小堆（同刻按续租操作到达序）；
  - `userRec`：每用户全部状态（设备、堆、隐身、拉黑集、入/出订阅边）；
  - `sub.emit`：可见态相对上一条已通知值变化才入队，保证同目标前后相接。
- `service.go`：并发控制、惰性到期、操作语义、通知合流与上限。

## 2. 关键数据结构与不变量

- 设备数 ≤ 8。设备记录在“未到期”期间存活；到期或主动下线即从 map 与堆中删除。
- 聚合优先级 `在线 > 忙碌 > 离开 > 离线`，由数值大小直接取最大值。
  无设备时离线。每次设备变更后 `recompute` 重算（设备 ≤ 8，O(1)）。
- 可见性按观察者独立：本人恒看真实值；他人在“对方隐身”或“被对方拉黑”时
  恒看离线，否则看真实聚合值。
- 每条订阅（viewer→target）维护 `last`（订阅起始可见值或上一条已通知值）
  与独立队列 `pending`。仅当新可见值 ≠ `last` 才入队，因此：
  - 隐身/拉黑期间真实变化不会产生通知；
  - 解除时只揭示当前态，绝不补发历史积压（没有积压可补）。

## 3. 惰性到期与时间戳语义

到期不触发任何回调。任何操作入口调用 `advance(u, now)`：

```
while 堆顶到期时刻 <= now:          // 恰等于视为已到期
    弹出设备、删除、计数-1、重算聚合
    对该用户每个订阅者按“当前可见态”发事件，生效时刻 = 设备到期时刻
```

要点：

- 到期事件盖的是**到期时刻**，不是处理时刻；切换类操作（Report/Offline/
  隐身/拉黑）盖**操作 now**。
- 由于每个会改变 `u` 的操作都先 `advance`，切换提交时不可能还有更早的
  到期未生效，因此惰性重放出的“当时隐身/拉黑标志”就是到期时刻真实生效的标志。
- `advance` 只消费到期堆，**不写用户操作时钟 `lastNow`**；`lastNow` 仅在
  操作被接受后才更新为该操作的 now。

### 同一时刻排序

合流排序键为 `(生效时刻, 类别, 来源操作全局到达序)`：

1. 生效时刻升序；
2. 同刻“到期事件”先于“切换事件”（显式布尔比较，不依赖序号巧合）；
3. 再按发起操作的全局到达序 `seq`。到期事件的 seq 取**续租它的那次
   Report** 的到达序，而非惰性处理时刻，从而等价于某个全局串行顺序。

一次 `Drain` 可交出多个不同到期时刻的通知；同一目标内后一条的前态必等于
前一条的新态（由 `emit` 的 `last` 机制保证）。

## 4. 操作时钟与拒绝次序

拒绝严格按序，只报第一个：

```
参数非法 > 时钟回退 > 用户/设备不存在（Report 对未知用户自动创建；
新设备在 8 台上限时报“设备过多”）> 状态不允许（重复订阅、订阅自己等）
```

- `lastNow` 为该用户上一次**被接受**操作的 now；`now` 单调，相等允许。
- 跨用户操作（Block、Subscribe、Unsubscribe、Query、Drain）要求**所有参与
  用户**的时钟不回退。这样可拒绝“用更早的 now 去观察/订阅一个已在更晚时刻
  被修改的用户”，避免读到“未来状态”。
- **被拒绝操作不改任何状态与时钟，也不部分应用惰性到期。** Offline 在
  `advance` 之前先对“应用到期后的逻辑视图”判定：目标用户不存在 / 时钟回退 /
  目标设备不存在或已到期，都直接拒绝；只有全部通过才 `advance` 并提交。
- Drain 在修改任何队列前，先按固定加锁顺序锁定全部目标分片并统一预检时钟，
  任何一个回退则整体拒绝、零副作用（all-or-nothing）。

## 5. 订阅语义

- `Subscribe(viewer, target, now)`：重复订阅、订阅自己拒绝且错误可区分；
  订阅以**订阅时刻的可见值**初始化 `last`，不产生通知。
- `Drain(viewer, now)`：先对 viewer 及其全部订阅目标做惰性到期，再把每个
  (viewer,target) 队列中的新事件按上述排序键跨目标合流，返回后清空队列。
- 每观察者积压上限 1000：合流后超出时丢弃最早的，并在**下一次** Drain 的
  `Dropped` 中标注丢弃条数；该标注只出现一次。
- `Query(viewer, target, now)`：先惰性处理，返回可见态与未到期设备数；
  本人查询额外返回各设备状态（按设备 ID 排序，保证确定性）。

## 6. 并发模型与可串行化

- 用户按 FNV-1a 哈希分散到固定数量分片（默认 64），每分片一把互斥锁。
- 多用户操作按**分片索引升序**加锁，杜绝任意调用组合下的死锁。
- Drain 逐目标锁定、逐目标推进（到期只写该目标内部的队列，不需要同时持有
  viewer 锁），与 Subscribe 不会形成锁环。
- 全局单调的原子 `seq` 提供与某个全局串行顺序一致的同刻 tie-break。
  因而并发调用的结果等价于某个按 `seq` 排列的串行执行。

## 7. 复杂度（可验证）

- Report/Offline/SetInvisible/Block：仅触达本用户（Block 多触达被拉黑方做
  存在性检查），设备堆 ≤ 8，O(1) 期望；与全体用户数、订阅总数无关。
- Query：触达 viewer 与 target 两个分片，O(1)（本人设备列表 ≤ 8）。
- Drain：与 viewer 自己的订阅数 `k` 以及实际到期的设备数 `e` 成正比，
  O(k + e + m log m)（`m` 为本次真正返回的通知条数）；与全体用户数、全体
  订阅总数无关。到期处理只弹出真正到期的设备，不扫描全堆。

可验证方式：

- `go test -bench=. -benchmem ./presence/`：在预置 1 万与 100 万无关用户下，
  `BenchmarkReport`/`BenchmarkReportScale` 的 ns/op 与 allocs/op 不随用户数
  增长（实测约 120–150 ns/op、1 alloc/op）；`BenchmarkDrain` 对 8 个订阅
  约 0.9–1.0 µs/op。
- 到期成本由最小堆保证只与实际到期数有关，差异测试中大量“无到期 Drain”
  均为空操作。

## 8. 测试

- `edge_test.go`：到期恰等于 / 差一秒；聚合优先级与 Offline；8 台上限与
  到期槽位惰性回收；时钟回退拒绝且不污染状态；隐身期间真实变化不通知、解除
  不补发；拉黑/解除同理；订阅错误可区分；一次 Drain 交出多条不同到期时刻
  通知且跨目标按生效时刻合流；同刻到期先于切换；积压超 1000 丢最早并仅标注
  一次。
- `naive_test.go`：独立**朴素模型**。它不用堆、不做惰性聚合，而是记录全部
  已接受事件，并以“离散事件重放 + 每订阅增量设备状态机”重算每个订阅者的
  可见序列；按 `(生效时刻, 到期先于切换, 操作到达序)` 排序，并维护每订阅的
  已交付游标与 1000 条上限。
- `diff_test.go`：`TestNaiveDifferential` 对两实现喂入 **1500 组**随机操作
  序列（6 用户、9 类操作、含回退/拒绝/跨用户乱序时间），逐操作比对错误类别
  与 Query/Drain 的可见结果、计数、丢弃数，并断言通知按生效时刻非降序。
  设置 `PRESENCE_LOG=<file>` 会把每组的**输入、输出与判定依据**写入日志；
  `PRESENCE_RUNS=n` 可调整组数。
- `conc_test.go`：高并发混合操作，配合 `go test -race` 验证无数据竞争、
  无死锁。

## 9. 关键取舍与被放弃的方案

- **放弃全局用户表 + 全局锁**：简单但所有写串行、随用户数膨胀。改为哈希
  分片 + 升序加锁，获得水平并发且无死锁。
- **放弃“到期后台扫描/定时器”**：会引入额外线程、唤醒成本与时钟耦合，且
  难以精确复现“生效时刻早于处理时刻”。改为入口惰性弹出，时间戳直接记录
  到期时刻，结果与任何调度时机无关、可精确重放。
- **放弃“切换时给所有订阅者主动推送长连接”**：题目只要求 Drain 拉取模型。
  队列按 (viewer,target) 存放，解除隐身/拉黑天然只暴露当前态。
- **放弃“解除时补推历史”**：可见性被遮蔽期间根本不入队，既满足“不补发”，
  也避免无界积压；解除后最多一条（当前态不同才发）。
- **放弃按设备 ID 作为同刻 tie-break**：那会依赖数据而非操作到达序。改用
  来源操作的全局到达序，并以显式“到期先于切换”类别位兜底，保证可线性化。
- **拒绝操作的原子性**：一度在 Offline/Drain 中“先 advance 再判定”，导致
  被拒绝操作也弹出了到期设备/推进了时钟。差异测试（如 seed 3/341）捕获后，
  改为“先按到期后逻辑视图完成全部拒绝判定，再提交惰性效果”，并让
  `advance` 与操作时钟更新解耦。

```bash
# 常规测试
go test ./...

# 竞态 + 全部用例（含 1500 组差异对照与并发压测）
go test -race -count=1 ./...

# 仅跑差异对照并落日志（输入/输出/判定依据）

  go test -run TestNaiveDifferential -v ./presence/

```
