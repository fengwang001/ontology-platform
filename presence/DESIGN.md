# presence 设计说明

多设备在线状态聚合与订阅通知服务。纯 Go 实现，无外部依赖，通过一把互斥锁把
所有并发调用串行化到内部状态机，因此结果严格等价于某个串行顺序；锁内不做 I/O，
临界区很短。

## 数据模型

- 每用户一个 `user`：`devices map[id]*devRec`、在线计数 `online`、三态计数
  `counts[online|busy|away]`、隐身开关、订阅者集合 `subscribers[viewer]→最近已通知可见态`。
- 设备记录 `{status, expires}`；`expires = 上报时刻 + T`。恰等于 `expires` 视为已到期。
  设备主动 `Offline` 或到期后记录仍保留（设备标识槽位不回收），`expires` 置 `-1`，
  因此同一用户生命周期内设备标识总数恒不超过 8；对同一标识重新 `Report` 视为续租。
- `blocks[owner]set(who)` 存拉黑关系。
- 每个观察者一个 `viewerState{queue, dropped}`：有界通知积压（≤1000）。

## 惰性到期：环形时间轮

租约时长 `T ∈ [1,3600]` 固定。用一个长度 `T+1` 的环形数组（时间轮）保存到期条目：

- 续租时把条目放入槽 `exp mod (T+1)`，槽头用 `slotAt` 记录其对应的绝对到期时刻，
  以区分不同轮次；同一槽内条目按全局递增的续租序列号 `seq` 排列。
- 每个操作入口（含 `Report/Offline/SetInvisible/Block/Unblock/Subscribe/Query/Drain`）
  在校验通过后调用 `expireDue(now)`，把游标从当前水位推进到 `now`，逐槽触发到期。
- 挂租约都由不晚于游标的上报产生，到期时刻必落在 `(cursor, cursor+T]`；若 `now`
  远超该窗口，窗口内不可能有条目，直接把游标跳到 `now`，因此入口扫描不会随时钟
  跨度增长。
- 旧续租的条目在触发时通过“设备当前 `expires` 是否等于该条目到期时刻”判为陈旧而跳过，
  续租与下线都不需要回删旧条目（惰性删除）。

每次到期以**到期时刻**（而非处理时刻）为通知生效时刻；同一槽内按续租 `seq` 升序，
从而保证“同一时刻到期先于切换、切换之间按到达次序”——到期事件的 rank 恒早于同刻
的切换事件（切换事件在 `expireDue(now)` 之后才追加，生效时刻同为 `now`，但到期已先物化）。

## 聚合与可见性

- 真实聚合：`counts[online]>0 → online；否则 busy>0 → busy；否则 away>0 → away；否则 offline`。
- 可见性按观察者独立计算：
  - 本人：恒为真实聚合值（隐身与拉黑不影响本人）。
  - 他人：目标隐身或观察者被拉黑 → offline；否则真实聚合值。

## 通知生成与抑制

- `Subscribe` 先 `expireDue`，再以订阅时刻的可见值作为该观察者的起始已通知值，
  起始不产生通知。重复订阅、订阅自己分别返回 `ErrAlreadySubscribed`、`ErrSubscribeSelf`。
- 每次状态变化（`Report/Offline` 或到期导致的聚合变化、隐身切换、拉黑/解除）都调用
  发射逻辑，对目标的每个订阅者独立计算其当时可见值：
  - 与该观察者“最近已通知值”相同 → 不产生通知；其记忆值同步为当前可见值，
    从而隐身/拉黑期间的真实变化被静默，**解除时不会补发**积压。
  - 拉黑关系下：`Block` 当下若可见值变为 offline，该条“变离线”通知仍投递给被拉黑者；
    此后拉黑期间的任何变化不投递；`Unblock` 当下按新可见值决定是否投递。
    隐身切换当下同理（变离线 / 恢复都应可见）。
- 每观察者队列上限 1000：超出丢弃最早一条并累加 `dropped`；`Drain` 返回当前积压与
  自上次 Drain 以来的丢弃条数，随后清空队列与计数。
- 通知序列不变式：对同一目标，相邻两条通知状态必不同（前后相接）；整体按
  `(生效时刻, rank=到期先于切换, seq)` 有序。跨目标通知按生效时刻穿插，由各观察者
  独立队列统一承载。

## 拒绝次序与原子性

错误严格按以下优先级只报第一个：

1. 参数非法（空标识、越界 now、非法租约等）；
2. 时钟回退（`now < 已接受操作水位`）；
3. 用户/设备不存在（`Report` 对未知用户在被接受时才自动创建；设备超 8 报过多；
   对已知用户的未知设备 `Offline` 报设备不存在）；
4. 状态不允许（重复订阅、订阅自己、拉黑自己、重复拉黑、未拉黑解除等）。

非法设备状态（非在线/忙碌/离开）归入“不存在之后、状态不允许之前”一档，返回独立的
`ErrInvalidStatus`。任何被拒绝操作都在产生副作用（含惰性到期）之前完成全部校验，
因此不会推进时钟、不创建用户/设备、不物化到期。

## 关键取舍

- **环形时间轮而非全局最小堆**：早期方案用“每设备一个堆条目”的全局最小堆，能正确
  排序，但 `Push/Pop` 为 O(log 在线设备数)，单次 `Report` 会随全体用户数轻微增长，
  不满足“开销不随全体用户数增长”。固定租约使环形时间轮的入桶/触发均为摊还 O(1)，
  基准显示 1 千到 1 百万用户下单次续租约 200–290ns。代价是结构依赖“租约时长固定”，
  若未来要支持每用户可变租约，需要回退到分层时间轮或桶键小顶堆。
- **计数器而非每次遍历设备**：每用户维护三态计数与在线数，聚合 O(1)；到期/续租/下线
  对计数做增量维护。
- **发射 fanout 与订阅者数量成正比，而与全体订阅总数无关**：订阅关系挂在被订阅目标上，
  只有该目标的订阅者会被遍历；单个观察者 `Drain` 只访问自己的队列。
- **记忆值即抑制器**：不为隐身/拉黑期间缓存“待补发”事件，从根上保证解除后不补发，
  也避免无界积压。
- **设备标识槽位不回收**：保证“至多 8 台设备”是对生命周期内标识总数的硬约束，语义更
  简单可复现；下线后可用同一标识重新上报。

## 被放弃的方案

- 全局到期最小堆：正确但带 log(设备数) 因子，已由环形时间轮取代。
- 为每个观察者保存完整事件历史再在 Drain 时过滤：存储随事件总量增长，无法满足
  “单个观察者 Drain 开销不随订阅总数增长”与积压上限要求。
- 隐身/拉黑期间缓存事件以便解除后补发：与“不补发积压”需求直接冲突，放弃。

## 复杂度

- `Report`：O(1) 摊还（时间轮入桶 + 计数更新；发射成本 O(该用户订阅者数)，为必需 fanout）。
- `Query`：O(1)（本人设备列表 O(设备数 ≤ 8)）。
- 单个观察者 `Drain`：O(本次到期涉及条目数 + 返回通知数)，与全体用户/订阅总数无关。
- 到期处理：只遍历真正到期的条目（加至多 T 个槽的游标推进窗口，T≤3600）。

## 本地验证

```bash
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache GOPATH=/tmp/gopath
go test ./... -race
go test -run TestDifferential -v ./presence     # 1500 组随机差分
go test -bench . -run '^$' ./presence           # 扩展性基准
```

- 边界用例：到期恰等于与差一秒、一次 Drain 多条乱序到期、隐身/拉黑期间不通知且解除
  不补发、同刻到期先于切换、积压溢出标注、拒绝次序、设备上限等，见
  `presence_edge_test.go`、`presence_edge2_test.go`。
- 差分测试 `differential_test.go` 生成 1500 组随机操作序列（小租约以高频制造到期、
  含时钟回退尝试），同时驱动生产实现与独立朴素模型 `naive_test.go`，逐步比对每个操作
  的错误与结果（含 Query 全字段与 Drain 通知序列、丢弃计数），并把每步输入、输出、
  双方结果写入 `presence/differential_run.log`，失败时给出 run/seed/step 定位。
- 朴素模型不做任何增量优化：维护只追加事件日志（report/offline/expire/invis/block/
  unblock），所有可见状态都通过对事件日志的纯回放得到，与生产实现的数据结构完全独立，
  可有效交叉验证而非共享同一错误假设。
- `concurrent_test.go` 在 `-race` 下并发压测，`scaling_bench_test.go` 给出扩展性证据。
