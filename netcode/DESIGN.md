# netcode：服务端权威输入处理与客户端预测对账 — 设计说明

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `types.go` | 共享契约：`Config`（W/K/M/P）、`Move`、`Receipt`/`Status`、`Ack`、`Error`/`Reason` |
| `rules.go` | 唯一步进规则 `applyStep`（单步上限拒绝 + 截断到 `[0, W]`），服务端、客户端、对账三方共用，保证结果可精确复现 |
| `server.go` | 服务端仲裁：登记玩家、接收输入入列、`Tick` 按配额统一下发、产出确认 |
| `client.go` | 客户端预测：本地序号分配、提交即预测、确认过滤与应用 |
| `reconcile.go` | 对账：以权威位置为起点重放未确认输入 |

## 关键不变式

- 每个玩家的待处理队列序号连续（`processed+1 .. maxReceived`），因为缺口接收被拒绝，序号空间无洞；因此队列用普通切片即可，无需堆或平衡树。
- 玩家待处理队列为空 ⟺ 不在 `active` 列表中。`Tick` 只遍历 `active`，而每个活跃玩家每 Tick 至少处理 1 个输入，故 Tick 开销 ≤ O(处理输入数)，与空闲玩家数无关。
- 只有"被接受"的接收会推进 `maxReceived`（重复/缺口/积压已满都不推进），所以任何 `seq <= maxReceived` 的重复输入此前一定是被接受的，幂等返回 `{Duplicate, Previous: Accepted}` 无需保存历史接收结果。
- 客户端只接受 `ProcessedSeq` 严格更大的确认；权威位置是"处理完序号 n 之后"的确定性快照，因此同一确认集合以任意次序（含重复）应用后，最终由最大 `ProcessedSeq` 的确认决定基准，重放是确定性的，结果一致。

## 关键取舍

- **域内拒绝用返回值、参数非法用 error**：`delta==0`、`seq<1`、玩家未登记、时钟回退属于调用方错误，返回 `*Error`；重复/缺口/积压已满属于正常协议结果，用 `Receipt.Status` 表达。检查顺序即声明顺序：非法参数（delta→seq→玩家）> 时钟回退 > 重复 > 缺口 > 积压已满，只报第一个；任何被拒绝的接收/回退的 Tick 不改变任何状态（含时钟）。
- **被拒绝输入也消耗配额并推进已处理序号**：与服务端规则一致，确认中用 `Rejected` 集合携带本 Tick 被拒序号；客户端重放时跳过被确认拒绝的序号。
- **截断视为接受**：`applyStep` 返回 `accepted=true`，不进入 `Rejected`。
- **客户端内存与单次对账开销都是 O(未确认输入数)**：确认到达即丢弃已确认前缀，历史输入不再触碰；`rejected` 集合只保留 `> lastAcked` 的防御性条目并随时剪枝。
- **确定性**：`active` 列表按激活顺序、压缩时保持相对顺序，同一串行调用序列重放得到完全相同的确认序列（`TestServerDeterministicReplay` 验证）。并发调用由互斥锁串行化，等价于某个串行顺序。

## 被放弃的方案

- **为每个序号持久化接收结果表**：用来支持"重复幂等返回此前结果"。放弃，因为只有被接受的接收才推进 `maxReceived`，重复序号的此前结果恒为"已接受"，持久化只会带来随历史增长的内存。
- **客户端保留全部历史、每次从最近确认重放**：语义最简单，但单次对账开销随历史总长增长，违反性能要求；改为只保留未确认后缀。
- **待处理队列用堆/有序映射**：序号天然连续，切片 + 头指针已足够，堆只会增加常数与复杂度。
- **客户端缓存全部乱序确认再排序**：只需"只接受更大 `ProcessedSeq`"一条规则即可收敛，缓存乱序确认没有必要（旧确认不含新信息）。
- **Tick 内对全体玩家扫描**：被主动玩家集合 `active` 替代，否则 Tick 开销随玩家总数增长。

## 本地验证方法

```bash
# 单元测试 + 1500 组随机消息交错与朴素模型对照（-v 可见每组输入/输出/判定依据日志）
go test -v ./netcode/

# 竞态检测（并发等价于某个串行顺序）
go test -race ./netcode/

# 性能证明：
#   BenchmarkTickIdlePlayers —— 0/1k/100k 空闲玩家下 Tick 的 ns/op 基本持平
#   BenchmarkApplyAck        —— 开销随未确认窗口（10/100/1000）线性增长，与历史无关
go test -run=NONE -bench=. ./netcode/

# 静态检查
gofmt -l netcode/ && go vet ./netcode/
```

随机对照测试（`TestRandomInterleavings`）的模型是独立编写的朴素实现
（`mServer` 每 Tick 扫描全部玩家、`mClient` 保留全量历史重算），与真实
实现共享的只有类型定义；逐步比较接收回执、确认流（按玩家排序）、每次
确认后的预测位置，收尾阶段重发被积压拒绝的输入并送达全部确认后，断言
预测位置 == 权威位置、未确认列表为空、偏差为 0、已确认序号一致。
