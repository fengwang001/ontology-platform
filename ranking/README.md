# 增量排名维护器

`ranking.Maintainer` 按以下全序维护元素：

1. 分数降序。
2. 分数相同时，唯一标识升序。

因此每个元素都有稳定且唯一的位次，插入和删除会立即重排。

## 三种序号

- `Position`：全序中的位次，从 1 开始；所有元素的位次互不相同，始终构成 `1..N` 双射。
- `Rank`：竞赛排名，等于严格高于当前元素的元素数量加 1。同分元素共享同一个 `Rank`，下一个更低分数会产生空洞。
- `DenseRank`：稠密排名，等于严格高于当前元素的互异分数数量加 1。同分元素共享同一个 `DenseRank`，不同分数之间没有空洞。

例如分数为 `10, 10, 10, 8, 8, 7` 时：

| 分数 | Position | Rank | DenseRank |
| --- | --- | --- | --- |
| 10 | 1, 2, 3 | 1 | 1 |
| 8 | 4, 5 | 4 | 2 |
| 7 | 6 | 6 | 3 |

## 增量规则

- 插入元素后，全序中位于其后方的元素 `Position` 加一；这包括同分数但唯一标识更大的元素。
- 插入元素后，只有分数严格更低的元素 `Rank` 加一；同分组内的并列元素仍共享排名。
- 插入已存在的新分数时，后方元素的 `DenseRank` 加一；插入到已有分数分组时不改变稠密排名。
- 删除元素后，位于其后方的元素 `Position` 减一；`Rank` 按剩余人数重新计算。
- 只有删除某个分数上的最后一个元素时，后方元素的 `DenseRank` 才减一。

## 错误与并发

`Insert` 和 `Delete` 对错误输入返回可判定的哨兵错误：

- `ErrEmptyID`：标识为空；插入和删除都拒绝。
- `ErrDuplicateID`：插入的标识已存在。
- `ErrIDNotFound`：删除的标识不存在。

错误在修改前返回，不会改变任何元素的三元组；调用方可在失败后继续使用维护器。使用 `errors.Is` 判断错误类型。

`Get`、`List` 和 `SelfCheck` 使用读锁，可彼此并发调用；插入和删除使用写锁与其他操作互斥。`List` 返回快照切片，调用方不会持有内部状态。`SelfCheck` 检查排序、索引、位次双射、竞赛排名和稠密排名。

## 本地验证

如果当前 shell 找不到 Go，可使用本机路径：

```bash
export PATH=/usr/local/go/bin:$PATH
export GOCACHE=/tmp/go-cache-ontology
```

运行普通测试：

```bash
go test ./...
```

查看测试输入、结果和判定依据：

```bash
go test -v ./ranking
```

执行竞态检测：

```bash
go test -race -v ./ranking
```

静态检查：

```bash
gofmt -l .
go vet ./...
```
