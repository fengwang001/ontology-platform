# 充电站功率分配与排队控制器 — 设计说明

1. 模块：`types.go`/`errors.go` 领域模型与六类哨兵错误；`station.go` 状态、事件、互斥锁与快照；`allocator.go` 分配；`clock.go` 推进结算。
2. 并发：单把 `sync.Mutex` 串行化全部操作，天然等价于某一串行顺序，`-race` 下验证。
3. 分配：优先类别先分，剩余给普通类别；类别候选池为“原充电者（插枪序）+ 原等待者（插枪序）”。
4. 分摊：整数水位法，未封顶者均分剩余，逐轮把达到自身上限者封顶；余量按插枪序每台 +1。
5. 不可行挤出：低于最低功率者中先等待者后充电者、同状态最晚插枪；每挤一台释放后重分，循环至全部达标。
6. 滞回取舍：规格的字面挤出规则在“同类别新车到达、新车最低功率高”时会挤掉老充电车，与滞回条冲突。
7. 取舍：按显式滞回条优先——该触发下若只有充电者不达标，改挤池中最晚插枪的等待者，老充电车功率不降。
8. 普通类别充电者仅在总上限下降、优先类别实际用量增加（更高类别到达/恢复）或自身被调低优先级时可被挤；由 `maySuspendChargers` 控制。
9. 被调低优先级的车本轮按等待者入池（插枪序不变），故可被挤；调高者进入优先类别候选。
10. 推进：不逐秒模拟，计算每台在充车辆 `ceil(剩余/功率)`，与下一个上限变更、终点取最小值跳跃。
11. 跳跃后结算：同时刻充满按插枪序逐台置满并立即重分；随后生效同时刻的上限变更（充满先于上限）。
12. 电量在累计时按剩余钳制，保证充满车电量恰等于需求、其余车等于 Σ功率×时长。
13. 定时上限变更保存在按 (时刻, 登记序) 有序切片；过去时刻的请求按固定次序拒绝（参数>时钟）。
14. 性能：事件只遍历存活会话 map；拔枪即删会话，开销与已结束会话数无关（基准 10 万历史会话验证）。
15. 推进一次跳跃 O(存活车)，区间整体 O(充满次数×存活车 + 变更数)；10^6 秒无充满约 7µs。
16. 被放弃：按秒推进的仿真（秒数敏感）、浮点份额（破坏整数余量与可复现性）、按需求比例分配（不符合“未封顶者均分”）。
17. 朴素模型 `naive_test.go` 独立实现：逐单位轮询发放份额、逐秒重放，与实现无共享逻辑。
18. 验证：`go test ./station/` 定向场景；`go test -race`；300 组随机操作序列与朴素模型逐步状态对照。
19. 日志：`STATION_LOG=/tmp/x.log go test -run TestRandomAgainstNaive -v ./station/` 打印每条输入、输出、判定依据。
20. 基准：`go test -bench . ./station/`；覆盖率约 90%；`go vet` 与 `gofmt` 干净。
