# chain —— 周期任务链端到端时延分析器

对具有“释放即读取、延后写出”语义（LET / 逻辑执行时间及其固定响应时间推广）
的周期任务链，计算最大/最小反应时间与最大数据年龄，并可在不影响其它链的前提下
搜索相位使最大反应时间最小。

实现位于本包：

- `chain/timing.go`：周期/超周期与反应时间、数据年龄的纯计算。
- `chain/analyzer.go`：任务与链注册表、参数校验、`Analyze`、`Tune`，
  全部方法在同一把 `sync.RWMutex` 下执行，并发调用等价于某个串行顺序。
- `chain/naive.go`：按规范逐字写成的朴素基准——展开若干超周期内的全部作业，
  按时间顺序处理“释放读取 / 写出”事件，传播外部采样标记，再对每个整数 `x` 取值。

## 任务与链

任务编号为非空、不超过 32 字节的字符串；周期 `T∈[1,1000]`；相位 `0≤φ<T`；
写延迟 `1≤w≤T`。`w=T` 即逻辑执行时间（LET）语义；`w<T` 相当于固定响应时间的
隐式通信（作业在释放后 `w` 时刻即写出）。全局最多 16 个任务。

任务 `τ` 的第 `j` 个作业（`j≥0`）：

- 释放并读取输入：`r = φ + j·T`
- 写出输出：`r + w`

链 `τ1→…→τn`（`2≤n≤6`，任务互不相同）中，`τ1` 读取外部采样。

## 可见性规则

一个在时刻 `u` 写出的值，对释放时刻 `r≥u` 的读取可见，**同一时刻可见**
（`r=u` 时下游在该时刻释放的作业即可读到）。因此朴素模拟在同一时刻先处理
写出事件、再处理释放读取事件；“晚 1”释放（`r=u+1` 且中间没有其它写出）则
必须等下游下一周期作业，不可见。

## 反应时间 Reaction

对整数 `x`：

1. `τ1` 取释放时刻不小于 `x` 的第一个作业，记释放 `r1`、写出 `t1=r1+w1`；
2. 对 `k≥2`，`τk` 取释放时刻不小于 `t_{k-1}` 的第一个作业，记 `rk`、`tk=rk+wk`；
3. `Reaction(x) = tn − x`。

令 `Φ=max φk`，`H=lcm(T1,…,Tn)`。反应时间以 `H` 为周期（所有释放/写出
时刻在一个超周期后整体平移 `H`，且 `Φ` 之后每个任务都已有作业），因此只取

```
x ∈ [Φ, Φ+H)  （整数，端点 Φ 与 Φ+H−1 都计入）
```

`MaxReaction`、`MinReaction` 分别为该区间上 `Reaction(x)` 的最大、最小值。

## 数据年龄 Age

对整数 `x`：

1. 对 `τn` 取满足 `r+w≤x` 的最后一个作业；
2. 对 `k=n−1,…,1`，取 `τk` 满足 `r+w≤`（`τ_{k+1}` 所取作业的 `r`）的最后一个作业；
3. `Age(x) = x − r1`。

取区间

```
x ∈ [W, W+H)，W = Φ + 2·ΣTk
```

`W` 的两个 `ΣT` 余量保证：第一次选取时 `τn` 必已写出过、且沿链反向回溯到 `τ1`
时每一级都有“写出时刻不晚于下一级释放”的作业（冷启动的前一两个周期作业不会
被错误地当作不存在）。在该区间内年龄模式同样以 `H` 为周期，故一个区间即可
得到稳定的最大值 `MaxAge`。本实现与朴素对拍均验证 `MaxAge ≡ MaxReaction`，
且每个 `x` 的 `Reaction`、`Age` 都不小于 `Σwk`，`Σw ≤ MinReaction ≤ MaxReaction`。

## Tune：相位优化

`Tune(链)` 只允许修改 `τ2,…,τn` 的相位，`τ1` 固定，`w` 与链组成不变：

- 穷举 `φ2∈[0,T2)`、…、`φn∈[0,Tn)` 的全部组合（按该顺序即字典序）；
- 取 `MaxReaction` 最小者；并列时取相位向量字典序最小者；
- **仅当**最优值严格小于当前 `MaxReaction` 才提交；当前已最优（即使存在
  并列的其它相位向量）时保持不变，返回 `Changed=false`，“调整后”各值
  与调整前完全相等。

提交等价于逐个调用 `SetPhase` 到同一组相位（测试 `TestTuneEqualsSetPhase`
逐字段比对两种路径的最终状态）。

规模限制：链的 `H` 必须 ≤5000，否则 `AddChain`/`Analyze`/`Tune` 拒绝；
`Tune` 另要求 `T2·T3·…·Tn ≤ 1000`（与 `H` 无关，仅限制穷举空间）。
若链上任何任务同时出现在另一条链中，`Tune` 以“共享”拒绝，且不修改任何状态。

## 拒绝原因与顺序

被拒绝的操作不改变任务、链与相位。区分如下哨兵错误（用 `errors.Is` 判断），
并按此顺序只返回第一个：

1. `ErrInvalidArgument`：编号为空/超 32 字节、数值越界（T、φ、w）、链长不在
   2..6、链名为空；
2. `ErrNotFound`：任务或链不存在（链引用了不存在的任务）；
3. `ErrDuplicate`：任务编号重复、链内任务重复、链名重复；
4. `ErrCapacityFull`：任务数已满 16；
5. `ErrTooLarge`：`H>5000`，或 Tune 时 `T2·…·Tn>1000`；
6. `ErrInUse`：`RemoveTask` 时任务仍在某条链中；
7. `ErrShared`：`Tune` 时链与其它链共享任务。

## 可复现性

- 所有查询只依赖当前参数，与调用历史、调用次序无关；同一参数重复调用结果相同；
  相同操作序列重放得到完全相同的结果。
- 随机测试使用固定种子（反应/年龄对拍 `seed=20261003`，Tune 对拍
  `seed=424242`），日志逐行打印输入、快速算法与朴素算法的输出及判定依据：
  `chain/differential.log`（2000 组）、`chain/tune_differential.log`（300 组）。
