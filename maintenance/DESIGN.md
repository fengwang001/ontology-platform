# 设计说明（物业维修派单服务）

1. 模块：`errors.go`（六级固定优先错误）、`queue.go`（工单二叉堆）、
2. `contractors.go`（候选/抢占选择与受害单）、`dispatch.go`（派单泵、超时结算、
3. 拒单回队与升级）、`operations.go`（注册/提交/确认/拒/完/撤/停用/查询）、
4. `service.go`（Service、时钟、实体模型）；测试三文件。
5. 队列用二叉堆，键为(等级降,提交时刻升,序号升)。队首无候选即出堆暂存、
6. 本拍结束再放回，天然实现“不阻塞后续”且不改变相对次序。
7. 已撤销等陈旧堆条目出堆即丢弃；同一工单升级时若已在堆中则原地重定位，
8. 绝不追加第二个指针（这是随机对照中真实抓到并修掉的堆序 bug）。
9. 承包商在手数 = `holds` 大小（完成/撤销/回队同步删除），另设 `pending`
10. 仅存未确认在手单；抢占受害者只在 `pending` 中线性扫描。
11. 选承包商对承包商 ID 表线性扫描取最优(在手数,从未完成优先,最近完成时刻,序号)；
12. 每步判定 O(1)，抢占扫描只碰容量有界的 `pending`。故选取开销 = O(C·K)，
13. C 为承包商数、K 为容量，与系统工单总数 N 无关；`TestSelectionCostIndependentOfOrderCount`
14. 用纯操作计数（N 从 64→1024 计数不变，C 翻倍才增长）与 benchmark 双重证明。
15. 时限以“派单时刻”为零点重算；升级后下一次派单按新等级重起两个时限。
16. 逾期判定严格 `now > due`：恰等仍可确认/未逾期，超一个单位才触发。
17. 响应逾期=拒单回队（计入累计、锁死该承包商、走升级）；完成逾期只置
18. 逾期子状态并发一次事件，等级与承接关系不变，仍可完成。
19. 紧急抢占：满手+工种+楼栋+接受紧急+`pending` 含非紧急单者可抢；
20. 受害单为派单最晚（同时刻序号大）的非紧急未确认单；候选多人按派单同序。
21. 升级在第 R、2R… 次拒单发生，封顶紧急；紧急单拒单只计数不再升级。
22. 超时/升级/逾期均在任何携带 now 的变更操作开头用 `settleLocked` 惰性结算，
23. 按工单序号顺序处理保证确定；查询只读不改，仅投影 now 下应有状态。
24. 并发：单一 `sync.RWMutex` 包住“校验+结算+变更”整段，错误在任何状态
25. 修改前返回，故被拒操作零副作用；结果等价于某串行序，杜绝超容量与双派。
26. 错误固定次序：参数非法→时钟回退→不存在→状态不允许→无候选→权限不足。
27. 被放弃方案：按工种/楼栋建多级索引选最优——实现复杂且本题候选扫描已
28. 与 N 无关，线性扫描更易证明与对照；定时器/后台 goroutine 主动超时——
29. 破坏“以操作携带 now 判定、可重放”，改为惰性结算；事件用带序号切片
30. 而非 channel，保证相同输入产生完全相同的事件序列。
31. 朴素模型（`naive_model_test.go`）独立用 map/切片线性重述全部规则，
32. 与实现零代码共享；`differential_test.go` 以固定 40 种子各 180 步随机
33. 操作逐步对照输入、两侧输出、全量工单/事件状态，日志经 `go test -v` 打印
34. 每步判定依据。
35. 本地验证：`go test -race ./maintenance/`（含并发安全后验：无超容量、
36. 无同一工单双派、holds 与 assignedTo 一致）、`go vet ./...`、`gofmt -l .`、
37. `go test -run BenchmarkSelectContractor -bench . ./maintenance/`。
