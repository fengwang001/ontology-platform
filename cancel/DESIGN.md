# 即时配送取消责任与退款分摊 — 设计说明

## 模块划分
1. `types.go`：阶段、责任方、金额构成与构造参数（纯值对象与校验规则）。
2. `errors.go`：11 类可程序化区分错误，错误即拒绝原因，被拒操作不改任何状态。
3. `ledger.go`：退款拆分与四方账目；以“支付后平台持有资金池 `Paid+Coupon`”为记账基准，四方之和恒等于资金池。
4. `arbitration.go`：订单状态机与责任裁决，输出责任方、判定依据与账目方案。
5. `system.go`：全局单调时钟、统一拒绝次序、争议到期最小堆、并发互斥与对外操作。

## 关键取舍
- 单一互斥锁串行化全部状态变更：并发结果等价于某串行序，同单至多一次落地由 `landed` 标志在锁内保证；放弃了分片锁（收益小、易破坏跨单时钟语义）。
- 争议到期用按右端点排序的最小堆 + 每窗口唯一序号惰性删除；普通操作只弹出 `end<t`，`Advance(t)` 弹出 `end<=t`，从而“右端点声明不允许、右端点取消仍待决、右端点到期落地”三件事可精确区分。放弃了后台定时器（不可重放）与全量扫描（随终结订单增长）。
- 时刻允许相等（全局单调而非严格递增），被接受操作携带时刻 `< now` 才报时钟回退。
- 账目直接给四方最终余额（平台可为负），违约金与空跑补偿作为独立转移并入各方余额，保证一条等式同时容纳退款与转移。
- 用户有责时券折算 `floor(Coupon*borne/Goods)` 归商家、余数归平台；用户现金承担以实付为上限（零实付部分退款不为负）。
- 接单前用户取消的退款承担方定为平台（商家尚未介入；与“用户无责”由商家/平台承担两种情形一致）。
- 骑手取消不是“落地”：回退到已接单、清空骑手、计数+1，可再派再取消。
- 确定性：裁决不读环境随机量；相同操作序列在相同全局序下结果一致。

## 本地验证
- `go test ./...`：边界取等、券折算取整与余数、零实付、改派再取消、各阶段守恒、错误次序、并发唯一落地。
- `go test -race ./...`：50 组并发取消交错竞态检测。
- `go test -run TestNaiveDifferential -v`：300 组随机操作序列与独立朴素模型（全量扫描到期）逐步差分，日志打印每步输入、输出/错误码与判定依据。
- `go test -bench BenchmarkCancelWithManyOrders`：预置 1 万终结订单后单笔裁决耗时不随总量增长（约 760ns/op）；`TestExpiryCostIndependentOfClosedOrders` 验证到期只弹出堆条目、不扫描已终结订单。
