# 文档同步与诊断迁移器 — 设计说明

包路径：`docsync`（module `ontology`）。纯 Go 实现，零第三方依赖。

## 1. 概念与坐标约定

- 文档是 Unicode 文本，仅 `U+000A` 分行；`U+000D` 是普通字符。行数 = 换行符数 + 1，空串视为一行空行。
- 列以 **UTF-16 码元** 计；增补平面字符（rune ≥ 0x10000）占 2 个码元。内部一切偏移都使用 UTF-16 码元偏移（0 起）。
- 位置 `(line, character)` 合法：`0 ≤ line < 行数` 且 `0 ≤ character ≤ 该行码元数`，且 `character` 不得落在增补字符的代理对中间。错误可区分：
  - `ErrOutOfBounds`：行不存在或列超过行长；
  - `ErrInsideSurrogatePair`：行存在、列不越界，但正好落在代理对中间。
- 范围 `[start,end)` 两端都须合法，且 `start ≤ end`（按偏移比较）。

## 2. 模块划分

| 文件 | 职责 |
| --- | --- |
| `utf16.go` | UTF-16 码元计数、rune↔码元、行布局（惰性）、位置/偏移/范围的校验与换算；错误类型。 |
| `rope.go` | 不可变风格的 **treap rope**：文本以字符串块存储，子树携带 UTF-16 长度与换行数；分裂/合并/切片/替换均为 `O(log n + k)`；带访问计数。 |
| `diag.go` | 诊断双 treap 索引：按起点、按终点各一棵；子树懒平移（lazy delta）、范围相交枚举、登记顺序键；失效清单。 |
| `document.go` | `Service`：版本号、`sync.RWMutex`、变更校验（拒绝优先级）、编辑应用、诊断失效与迁移、快照查询、位置/偏移换算 API。 |
| `naive.go` | 朴素参照模型（整篇字符串 + 整段诊断切片，按偏移线性推演），仅供测试差分。 |

### 2.1 为什么是 treap

需求要求“位于编辑起点之前的文本行与诊断不得被逐个访问或改动”，且位置/偏移换算不得随行数线性增长。平衡树天然提供按码元偏移的分裂：

- 文本 rope：编辑只分裂出 `[s,e)` 三段并替换，`s` 之前的块只读路径上的 `O(log n)` 个节点，绝不枚举；位置↔偏移沿树下降 `O(log n)`（行定位见 2.3）。
- 诊断索引：平移通过子树根的懒 `delta` 一次性作用于整段键区间，`s` 之前的诊断节点不被下钻。

被放弃的方案：

1. **整串 + `strings.Split` 行切片**：每次编辑重建行数组，`O(行数)`；且 UTF-16 列需逐 rune 扫描，直接违反性能条款。
2. **Piece table + 行表**：行表仍需在编辑时对受影响行做插入/删除（平衡 BST 可行），但诊断仍需第二套索引；两套异构结构的一致性与懒平移不如统一用 treap 直接。
3. **B 树 / 持久化数组**：常数与实现复杂度更高；treap 用固定随机优先级即可，且范围分裂与懒标记最顺手。
4. **诊断存切片逐诊断迁移**：最直观，但每次变更 `O(诊断总数)`，违反性能条款。测试中的朴素模型保留了这种实现作为差分参照。

### 2.2 rope 结构

节点：

```go
type ropeNode struct {
    text           string // 叶节点文本块（不含内部聚合）
    left, right    *ropeNode
    priority       uint64
    codeunits      int    // 子树 UTF-16 码元数
    newlines       int    // 子树内 '\n' 数
    lineStarts     []int  // 仅叶节点：块内每个 '\n' 之后的偏移（惰性生成）
}
```

操作：`split(root, k) -> (a,b)`（按码元偏移切，切点在增补字符代理对中间的情况由上层校验排除）、`merge(a,b)`、`replace(s,e,t)` = `merge(merge(a, newLeaf(t)), c)`。

不可变性：所有变更先在“计划”阶段完成校验，然后一次性重建根；写锁内替换。旧节点继续被快照查询使用（COW：被修改路径上的节点复制，未触及的子树共享）。

### 2.3 行定位为什么不是 O(行数)

`positionToOffset(line,col)`：沿 treap 用每个子树的 `newlines` 聚合作二分下降，找到包含第 `line` 个换行边界的叶块（`O(log n)` 个节点；大块内部再用块级 `lineStarts` 做二分，块大小有上界 `maxLeafBytes`，过大的块在替换路径上被重切）。然后在该块内按 rune 扫描到 `col` 个码元（单块内 `O(块大小)`）。

`offsetToPosition`：下降时累加左子树的码元数与换行数，落到叶块后单次 rune 扫描统计行内码元。整体 `O(log n + 块大小)`，不随总行数增长。

### 2.4 诊断索引与懒迁移

每条诊断 `{start, end, severity, message, seq}`（`seq` = 登记次序）同时存在两棵 treap 中：

- `byStart`：键 `(start, seq)`；
- `byEnd`：键 `(end, seq)`，节点额外维护子树内最小 `start`（`minStart`），用于相交剪枝。

区间键的整体平移：`addDelta(root, lo, hi, d)` 对“键完全落在 `[lo,hi)` 的整棵子树”在根上打 `delta += d`，推时传播给左右孩子；分裂/合并路径上 push。平移成本只覆盖受影响键区间的边界路径与失效枚举出的节点，不枚举之前/之后的诊断。

## 3. 变更（change）语义

一次 `Change(baseVersion, edits)`，所有编辑范围相对变更前文档（同时坐标）。

拒绝优先级（任一不满足即整体拒绝，文档与诊断均无任何可观察变化）：

1. `baseVersion != version` → `ErrStaleVersion`；
2. 任一端点位置越界 → `ErrOutOfBounds`；
3. 任一位置落在代理对中间 → `ErrInsideSurrogatePair`；
4. `start > end`（在重叠检查之前，登记诊断时同样适用）→ `ErrInvalidRange`；
5. 编辑两两重叠 → `ErrOverlappingEdits`。

重叠定义按题意：正长度区间的正长度相交才算重叠；相接（前一个 `end ==` 后一个 `start`）允许；多个插入（空范围）落同一点允许，并按给定次序串联；插入点恰为另一非空编辑的 `start`/`end` 允许。实现上把编辑按 `(start, 长度)` 稳定排序后只比较相邻对：

- 前一编辑非空且 `prev.end > cur.start` 即重叠；
- 空编辑 `end==start` 永不造成重叠。

全部校验通过后：版本 +1，rope 按排序后的编辑依次切分替换（相邻编辑互不影响，因为坐标都相对原文，且不重叠）。

## 4. 诊断迁移的形式化规则

诊断范围 `[a,b)`（`a ≤ b`，允许 `a == b`）。编辑 `[s,e)` 替换为文本 `T`，记 `L = e-s`，`tl = len16(T)`，`d = tl-L`。

### 4.1 端点独立映射（存活诊断用）

单个编辑把旧偏移 `p` 映射为：

```
若 L > 0：
    p < s          → p
    p == s         → s
    s < p < e      → 不会出现在存活诊断的端点（该诊断已失效，见 4.2）
    p >= e         → p + d        （p == e 移到 s+tl，即替换文本之后）
若 L == 0（插入，点 s）：
    p < s          → p
    p == s（起点） → s + tl       （“s=a 整体后移，不包含新文本”）
    p == s（终点） → s            （“s=b>a 不包含”；空诊断的终点语义见下）
    p > s          → p + tl
```

**空诊断 `a==b==s` 且该点有插入**：题意同时给出“s=a 整体后移（空诊断同此）”和“同点多插入对终点全部不生效”。单插入时按整体后移，映射为 `(s+tl, s+tl)`；**同一点连续多个插入** 时，端点独立规则显式优先：起点吃到该点全部插入长度、终点吃到 0 —— 但这会产生 `start>end`。因此规定：空诊断在同点多插入后保持为一个合法空范围，取“起点规则”的结果 `(s+Σtl, s+Σtl)`（等价于把该点的整组插入视作一次插入，空诊断整体后移到整组新文本之后）。这是题目两条规则唯一的冲突点，此处选择“结果必须始终是合法范围 + 空诊断跟随插入点后沿（LSP 语义）”。

多个编辑（同时坐标）等价于：把编辑按原文顺序（同点按给定次序，插入排在该点替换边界的确定次序）逐个作用于端点；由于编辑不重叠，端点不会穿过另一个编辑的内部。同点多插入自然退化为上一段的整组处理。

### 4.2 失效判定（仅非空编辑 L>0）

诊断失效当且仅当：

- `a < e 且 s < b`（正长度相交），或
- 空诊断 `a==b` 且 `s < a < e`（严格落在删除区间内部；落在边界 `a==s` 或 `a==e` 不失效）。

即：相接（`b==s` 或 `a==e`）不失效；正长度重叠哪怕一个码元也失效。失效时把诊断从两棵索引移除，追加到失效清单 `(versionAfter, seq)`，版本为变更成功后的版本。已失效诊断不再迁移、不可恢复。

### 4.3 在双 treap 上的执行

一次变更（已排序编辑 `edits`，互不重叠）：

1. 对每个非空编辑，用 `byEnd` 枚举满足 `b > s` 的候选，再以 `byStart.minStart` 子树剪枝，判定 `a < e`（含空诊断严格内部规则）。枚举只下钻可能相交的子树；被剪枝子树只访问其聚合字段。
2. 收集全部失效诊断（跨编辑去重：一个诊断不可能与两个不重叠的编辑正长度相交），记录 seq，从两棵树删除，写入失效清单。
3. 存活端点平移：以编辑在原文上的区间为界，对两棵树分别打懒 delta：
   - 旧偏移区间 `[0,s)`：delta 0；
   - 点 `s`：起点树加 `tl`（插入时；非空替换不加），终点树按 4.1 的端点角色处理；
   - 旧偏移 `[e,∞)`：加 `d`；
   - 插入点 `s` 之后（不含点）：加 `tl`。

   利用“同点插入整组”合并：同一点的连续插入合并为总长度一次作用，避免对同一节点反复 push。

## 5. 并发与快照

- `Service` 内一把 `sync.RWMutex`：所有变更/登记取写锁，查询取读锁。可线性化：每个接受的操作在锁内有唯一串行点；过期的并发变更只有基版本匹配当前版本的那一个能成功，其余 `ErrStaleVersion`。
- 快照查询 `Snapshot()` 在锁内拷贝出版本号、完整文本（rope 遍历为字符串）、有效诊断切片（按 `(start,end,seq)` 遍历 `byStart`）、失效清单（按 `(失效版本,seq)`）。四者来自同一版本，不撕裂。文本构建与索引遍历期间不释放读锁。
- 排序规则与题意一致：有效诊断 `(start,end)` 升序、并列按登记次序；失效清单按失效版本、再按登记次序。

## 6. 复杂度（n=码元数，m=编辑数，k=受影响诊断数）

| 操作 | 时间 | 编辑点之前的行/诊断访问 |
| --- | --- | --- |
| 变更文本 | `O(m log n + 新文本)` | 仅 `O(log n)` 路径节点 |
| 诊断失效/迁移 | `O(m log D + k log D)` | 被剪枝子树只读聚合字段 |
| 位置↔偏移 | `O(log n + 块大小)` | 不随行数增长 |
| 快照 | `O(n + D)`（仅查询本身的输出规模） | — |

每个节点带 `touchCount` 计数器（测试可重置/读取）：性能测试构造“超大前缀 + 小编辑/大量前置诊断”，断言小编辑触达的节点数有界（`O(log n)` 量级），而朴素模型的计数随规模线性增长，从而可验证地证明非平凡访问界限。


随机差分：每轮用同一操作序列同时驱动 `Service` 与 `NaiveModel`，逐版本比对文本、版本、有效诊断、失效清单、位置/偏移换算结果；每次输入、输出与判定依据（接受/拒绝原因、失效集合、端点平移前后值）写入日志文件。
