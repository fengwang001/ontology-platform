# 假设性历史动作预检（hypcheck）设计说明

本包为本体平台提供一种**只读**的假设性重新预检：给定历史时刻 `at` 与一个假设当时执行的
动作调用，重新演算该动作在 `at` 时刻会经历的全部校验钩子，给出“允许 / 拒绝”裁决；
若允许，给出本会产生的状态改变**意图**（不落地）。演算依据 `at` 时刻生效的钩子版本与
权限继承快照，而非当前最新状态。

代码入口：`hypcheck.Engine`；独立对照模型：`hypcheck.NaiveReplay`。

## 1. 时间模型与边界取舍（关键决策）

- 所有真实操作（类型定义、钩子发布/绑定、继承边、授权、状态写入、身份变更）都是
  **只追加事件**，提交时获得全局串行序号 `Seq`。调用方提供的 `At` 必须单调非递减。
- 版本区间统一解释为**左闭右开 `[from, until)`**：
  **在切换边界时刻 `T` 发生的版本切换，时刻 `T` 一律取新版本一侧。**
  这条规则对钩子版本、继承边、授权、身份、对象状态完全一致，所有边界判定方向唯一。
- 选择“取新侧”的理由：提交即生效（commit-takes-effect）语义对并发提交最自然，
  且“时刻 `T` 的调用”直觉上应看到“`T` 已提交”的事实。被放弃的“取旧侧（右开的镜像）”
  会使边界时刻的调用看不到同刻已提交事件，直觉相反且易引发双写歧义。
- 逻辑时间用 `int64` 而非墙钟：墙钟回拨 / 同刻乱序会破坏线性化；逻辑提交时刻可复现、
  可在测试中穷举。墙钟到逻辑时间的映射属于上游提交层职责，本包只消费单调时间。

## 2. 存储与 as-of 查询（成本取舍）

需求硬约束：单次预检重建快照的开销**不得随系统累计版本演进总次数线性增长**。

采用**不可变（路径复制）AVL 树 + 版本根数组**：

- 每个事件提交在每个存储上产生一个版本根；未变更的存储以 `tick` 复用当前根。
  因此任意全局时刻在版本数组中都有对应根，as-of 查询是：
  1. 在版本根数组上二分定位 `t`（`O(log V)` 次指针比较，V 为事件数）；
  2. 在不可变树内按键路径读取（`O(log K)`，K 为当前键数）。
- 写放大为每存储每事件一个根指针 + 一条 `O(log K)` 复制路径；旧版本永不被修改，
  旧快照天然并发安全，预检在 `RLock` 下零拷贝读取。
- “版本记录探测次数”被严格计数为 `PrecheckResult.Probes`：一次 as-of 根定位记 1 次
  探测（树内按键走路径属于结构内导航，不计为“版本记录探测”）。预检的 `Probes`
  是参与存储数的**有界常数**（当前约 6–8，见输出），与历史总变更次数无关。

### 可被独立验证的方式

1. `TestProbeCostSublinear`：在事件总量 100 / 1000 / 10000 三档下断言 `Probes`
   **完全相等**且不超过文档上界（64），并打印实测值。
2. `BenchmarkPrecheck`：`noise_1000` 与 `noise_100000` 两档 `ns/op` 基本持平
   （实测数百 ns 量级，100× 历史只带来二分多约 7 次比较）。
   复现：`go test -bench BenchmarkPrecheck -run '^$' ./hypcheck/hypchecktest`。
3. 代码层：`snapshotMap.rootAt` 是唯一探测点，每次调用 `stats.probe()` 恰好一次，
   可直接审计调用点数量。

### 被放弃的方案

- **每键一条版本小链表 + 扫描**：实现简单，但 as-of 要么线性扫描全历史，要么需要
  额外全局索引；且“枚举某刻所有边”困难。放弃。
- **整树拷贝快照（每事件深拷贝整张图）**：语义最直观，但写成本 `O(K)` 随对象规模增长，
  且总存储 `O(V·K)`。放弃。
- **只存 delta、查询时回放**：读成本对历史线性，直接违反需求。放弃。
- **物化“当前态” + 归档表回查**：当前态快但历史路径复杂、归档与在线路径容易语义漂移。
  不可变树让在线与历史走**同一段代码**，从根上避免漂移。

## 3. 钩子版本演进与绑定

- 钩子以 `hookID` 标识身份，`PublishHook(at, hookID, phase, HookVersion{Version, Spec})`
  在 `at` 发布/替换该 ID 的版本；同一 ID 在不同时刻可有不同 `Version` 与 `Spec`。
- 绑定是独立维度：`BindHook(at, typeID, hookID, phase)` 把当时已发布的钩子纳入某类型
  某阶段集合；`UnbindHook` 移除（历史版本仍保留）。同一 `(type,hook)` 再绑另一阶段即迁移。
- as-of 解析：先在绑定树取 `t` 时刻该类型的绑定集合（AVL 前缀区间扫描，
  `O(log K + 命中数)`），再对每个 `hookID` 在发布树取 `t` 时刻版本；按 `hookID` 升序演算，
  保证同集合下失败顺序确定。绑定存在但当时尚未发布（悬空绑定）视为该刻无此钩子。

内置钩子均为**确定性纯函数**，这是“与真实历史完全一致”可验证的前提：

| SpecKind | 阶段 | 拒绝条件 |
|---|---|---|
| `pre.deny_param_equal` | pre | 参数等于给定值 |
| `pre.deny_state_equal` | pre | 冻结快照中键等于给定值 |
| `post.deny_state_equal` | post | 读取前置冻结快照判定 |
| `post.deny_intended_set` | post | 意图集合将把某键写成给定值 |

## 4. 权限继承快照

- 身份（principal）存在性、继承边（`parent -> child`）、直接授权（`node,typeID -> bool`）
  各自是独立版本化存储，全部按 `at` as-of 重建。
- 判定从调用者出发沿**当时激活**的边向上 BFS（边物理键为 `child\x00parent` 以支持
  子→父前缀区间查询）；到达的每个节点查询其对该类型的直接授权，任一有效即允许。
- 完整 `PermTrace`（遍历到的祖先、走过的边及各自生效时刻、查询过的授权点）写入结果与
  审计记录，可逐条复核“为什么允许 / 为什么拒绝”。
- 环图安全：BFS 带 visited 集合；失效边会出现在快照记录中（含生效时刻），但**不沿其遍历**。

## 5. 前置 / 后置阶段与聚合规则（明确规定）

- 阶段顺序固定：**权限闸门 → 前置钩子（hookID 升序）→ 意图渲染 → 后置钩子（hookID 升序）**。
- **前置阶段一旦失败，后置阶段绝不被演算**（短路）。因此前置失败与后置失败
  **在任何请求下都不会同时出现**；即便 `CollectAll=true` 也不跨阶段聚合。
  这是因为后置判定依赖“前置已通过后才存在的意图集合”，跨阶段聚合会语义不自洽。
- `CollectAll=false`（默认）：遇**首个**失败即停，只报 1 条；权限闸门排在最前。
- `CollectAll=true`：聚合**本阶段内**全部失败。规定权限失败与前置钩子失败同属前置阶段，
  故该模式下二者可一并报告（测试 `TestPermissionFailureAggregatesWithPreHooks` 锁定该规则）。
- 后置阶段读取前置阶段冻结的只读快照 `frozenState` 与意图集合；**后置不得修改冻结快照**，
  意图是独立结构，绝不回写快照（代码上 `frozenState` 仅暴露 `get`）。

## 6. 四类错误与固定优先级

| 类别 | 含义 |
|---|---|
| `E1_TYPE_UNDEFINED` | `at` 早于动作类型被定义的时刻（含无定义） |
| `E2_HISTORY_GAP` | 钩子版本或权限快照因历史数据缺失（压实截断）无法重建 |
| `E3_CALLER_UNKNOWN` | 调用者身份在 `at` 尚不存在 / 当时已注销 |
| `E4_BAD_PARAMS` | 参数违反当时生效的结构约束 |

- 同一次预检同时满足多类时，**严格按 E1 > E2 > E3 > E4 只报告一类**，
  该优先级对所有请求一致（`ErrorPriority` + `TestErrorPriority` 锁定）。
- 结构约束（E4）按**当时类型版本**的 schema 校验：缺必填、类型不符、出现未声明字段都算违规。
- 任何错误路径都在 `RLock` 下纯读，不写状态、不写版本记录、不改继承关系；
  日志序号在大量预检前后保持不变（`TestPrecheckIsReadOnly`）。

### 历史缺口（压实）语义

系统支持 `Compact(horizon)` 丢弃 `< horizon` 的明细事件，但必须固化一份**保留束** `Manifest`：

- 类型/身份的诞生索引（用于在缺口之前仍能区分 E1/E3 与 E2）；
- 切点处的完整世界基线（当时的类型定义、钩子发布、绑定、边、授权、对象状态），
  使 `at >= horizon` 的快照重建结果与压实前**逐字节等价**。

规定：

- `at < horizon` 且类型在诞生索引中确认“当时尚未定义” → **E1**；
- `at < horizon` 且无法从保留束判定（如类型在缺口内生灭、或非诞生索引覆盖的查询维度）→ **E2**；
- 身份同理（E3 与 E2 的区分）。宁可保守报 E2，也不在缺数据下猜测允许/拒绝。

## 7. 线性化与并发

- 所有真实写操作在单一互斥锁内追加日志并物化；预检在 `RLock` 下读取一致的不可变快照。
- 每次预检结果等价于：把所有真实调用与版本演进按其全局序号串行执行后，
  在该预检 `At` 切下的快照上独立演算的结果。`PrecheckResult.LinearSeq` 记录本次所见的
  线性化点，审计记录同样保存该点，可事后复算。
- 探针统计是**请求级局部对象**（`ProbeStats`），不跨预检共享，保证并发只读无数据竞争
  （`go test -race` 通过；曾经的共享计数器缺陷由该测试发现并修复）。

## 8. 审计（事后核查）

- 每次预检追加一条 `AuditEntry`：请求输入、结论、依据的类型版本、每个钩子版本、
  权限快照（祖先/边/授权/生效时刻/授权来源）、前置/后置失败、意图、`LinearSeq`、`Probes`。
- 条目以 `prevHash` 形成 **SHA-256 哈希链**（`AuditHash` / `MemoryAuditor.Verify`），
  任何对输入、依据或结论的中途篡改都会使链校验失败。
- 审计追加本身是预检唯一的“写”，且只写审计存储，绝不触碰对象状态 / 版本 / 继承。

## 9. 与朴素重演模型的等价性

`NaiveReplay` 是**独立第二实现**：它不使用 AVL、二分、任何缓存，而是对每次预检从日志
起点**线性扫描全部事件**，用普通 map 重建 `at` 世界后直接判定。两个实现只共享
“需求语义函数”（schema 校验、钩子求值、阶段顺序、错误优先级），状态构建路径完全独立。

`TestRandomDifferential`（40 个固定随机种子，每种子数百次操作 + 上百次跨时刻预检）
逐条比较两者的稳定签名（裁决、错误类、钩子版本集合、权限来源、阶段失败、意图集合）。
该差分测试在开发中实际抓出并修复了：同刻多键版本覆盖、边/绑定区间上界、
失效边误遍历等真实缺陷。

## 10. 本地验证方法

```bash
# 全量测试（含边界穷举、聚合规则、错误优先级、只读性、压实、差分对照）
go test ./...

# 竞态检测（验证并发线性化与无共享写）
go test -race ./...

# 覆盖率（当前语句覆盖率约 89%）
go test -coverpkg=ontology/hypcheck -coverprofile=cov.out ./...
go tool cover -func=cov.out | tail -1

# 成本独立验证（Probes 不随历史总量增长）
go test -run TestProbeCostSublinear -v ./hypcheck/hypchecktest
go test -bench BenchmarkPrecheck -run '^$' ./hypcheck/hypchecktest

# 可运行演示
go run ./cmd/demo

# 静态检查 / 格式
go vet ./... && gofmt -l .
```

## 11. 范围与未做的事（明确取舍）

- 钩子是内置确定性规格，未提供用户任意代码 / 外部副作用钩子：任意代码无法保证
  “与历史完全一致”地重演（依赖、实现都会变）。需要时应以确定性策略 DSL 扩展 `SpecKind`。
- 未实现真实动作的落地执行器（Apply）：本子系统职责是只读预检；意图已结构化输出，
  落地器应在另一写路径复用同一判定后提交，不在本包范围。
- 压实是显式管理操作，未实现自动保留策略（TTL / 容量驱动），策略应在上层封装。
- 时间为逻辑时间；物理时间戳的单调映射、跨节点时钟一致性由上游提交层保证。
