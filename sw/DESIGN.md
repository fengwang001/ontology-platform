# 服务 Worker 注册与版本更新协调器 — 设计说明

## 模块划分
- `errors.go`：六类可区分错误的哨兵值；各操作按 参数→时钟→注册→版本→状态→频率 的固定次序检查。
- `scope.go`：按路径段组织的作用域 trie，负责最长前缀归属；匹配步数只随 URL 段数变化。
- `version.go` / `registration.go`：版本四态（安装中/等待中/激活中/冗余）与注册的三个槽位。
- `client.go`：客户端及其受控版本指针。
- `coordinator.go`：全部公开操作；一把互斥锁把所有操作串行化，天然等价于某个串行顺序。

## 关键取舍
- 单互斥锁串行化，而非每注册一个 actor：跨注册的时钟与不变量更简单，正确性优先于吞吐。
- 作用域匹配用语义 trie（按段），查找代价 O(URL 段数)，与注册总数无关；用 `LastMatchSteps` 计数器
  在测试中确定性证明，避免脆弱的耗时断言。清单用哈希表，每次请求恰好一次探测（`LastManifestProbes`）。
- 时钟由调用方注入（每个操作带 `now`）：可复现时钟回退与间隔边界；只有被接受的操作才推进时钟。
- 最小更新间隔按注册记录上次成功检查；脚本地址变化触发的检查绕过间隔但仍刷新检查时间。
- 接管全部客户端 = 转移该注册所有版本（含历史冗余版本）上的客户端，与 clients.claim() 语义对齐。
- 清单继承在接管瞬间一次性拷贝旧激活版本清单中新版本未声明的条目；之后旧清单即随版本冗余而冻结。
- 待移除注册不参与新归属，匹配时跳过并回退到更短的存活作用域；最后客户端离开时整体冗余并摘除。

## 被放弃的方案
- 排序作用域列表 + 二分：查找 O(log N) 仍随 N 增长，且插入删除要搬移，不满足"与注册数无关"。
- 版本事件回调/异步状态机：测试与模型对照难以确定串行点，改为同步方法调用。
- 全局（而非按注册）更新间隔：多作用域互相限流，语义不符。
- 允许冗余版本清单继续可读：与"冗余即终态"冲突，一律回退网络标记。

## 本地验证
- `go test ./sw/ -race -count=1`：场景测试 + 不变量 + 并发串行化。
- `go test ./sw/ -run TestModelDifferentialRandomOps -v`：与独立朴素模型对照 8 种子 × 1500 随机操作，
  日志逐条打印输入、输出与判定依据，结束后全状态快照 DeepEqual。
- `go test ./sw/ -run 'TestMatchSteps|TestManifestProbes'`：规模无关性的确定性证明。
- `go test ./sw/ -run xxx -bench .`：导航与请求在 100→100000 注册、16→65536 清单条目下耗时持平。
