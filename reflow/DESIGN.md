# 渲染树布局失效与重排内核 — 设计说明

1. 模块：`errors.go`（四类可区分错误与拒绝次序）、`types.go`（ID/模式/尺寸/变更/计数）、
2. `tree.go`（盒树、属性修改、插入/移除/移动、并发互斥、显式与隐式提交入口）、
3. `dirty.go`（边界判定与脏标记传播）、`commit.go`（最小子树重排）、`naive.go`（朴素全量模型）。
4. 两类标记：`selfDirty`（自身脏）与 `subDirty`（子树含脏）。自身脏同时置子树含脏，
5. 再沿祖先逐跳铺子树含脏，到达并标记最近布局边界即止；边界=隔离&&宽固定&&高固定，根恒为边界。
6. 关键取舍：结构变动（插入/移除/移动）把承载点到边界的祖先链全部置自身脏，
7. 因为“子列表变了”不应被“父重算后尺寸恰好不变”所短路；纯属性修改才走逐跳尺寸传播。
8. 重排算法：每个含脏边界内，先后序重算全部自身脏节点（同父按序），再逐跳闭包传播尺寸变化——
9. 某父重算后尺寸不变即在该跳终止，变化传到边界即止；边界固定尺寸且始终最后重算，变化不外散。
10. 边界按 id 排序，全局重算次序因此确定；嵌套边界各自独立重排，外层不清内层标记。
11. 摘下的子树不参与提交、标记冻结到重新插入；重插入/跨边界移动时按新位置把未被边界封住的脏重传播。
12. 边界身份改变：失去身份则把封存的子树脏继续上传；获得身份只入集合，不撤回已上传标记。
13. 度量查询遇 `pending` 做隐式提交，重算集合/次序与显式提交完全一致；无修改查询直接读数。
14. 并发：单把可重入互斥量串行一切公开操作，故结果等价于某串行顺序；提交钩子可制造同 goroutine 重入。
15. 被放弃的方案一：每个属性修改即全树打标——传播开销随整树规模，被“只走到最近边界”取代。
16. 被放弃的方案二：提交时全树扫描找脏——干净节点数会进入复杂度，被“含脏边界集合+脏门控后序”取代。
17. 被放弃的方案三：引用计数/版本号精细推断重排集——实现复杂且移动语义易错，用脏标记闭包更可复现。
18. 复杂度可验证性：`Stats.MarkPropSteps` 只计祖先传播跳数，`RecomputeVisits` 只计真正重算节点，
19. `TestPerformanceProof` 断言加 2000 棵干净子树不增加重算数，且传播步数差恰为到边界的深度差。
20. 正确性验证：40 组随机操作序列同时驱动增量内核与独立朴素模型，逐节点比对错误类别与提交后尺寸，
21. 并在每个提交点用测试侧独立全量重算（`fullRecompute`）再对照，覆盖含摘下/重插入/跨边界移动。
22. 本地验证：`PATH=$PATH:/usr/local/go/bin go test -race ./...`、`go vet ./...`、`gofmt -l .`。
