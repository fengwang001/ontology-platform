# 加密随机数（密钥版本，序号）分配器

`allocator` 包为每个租户单调发放 `(密钥版本, 序号)`，保证任何
`(租户, 密钥版本, 序号)` 在**并发、持久化失败、崩溃恢复**下永不重复。

## 模型与不变量

- 注册成功后从 `(版本 1, 序号 0)` 起；每版本序号范围为 `0..N-1`，用尽进入下一版本并从 0 起；版本数至多 `V`。
- 任意成功发放的 `(版本, 序号)` 全局唯一。
- 无崩溃、无预留失败时，每个版本内成功发放的序号恰为从 0 起的连续前缀。
- 每次崩溃浪费（预留但从未发放）的序号不超过批大小 `B`。

## 高水位与批预留推导

持久化层只保存一条记录：高水位 `(Version, NextSeq)`，含义是
「版本 `Version` 中 `[0, NextSeq)` 已预留」。

设当前持久化/内存高水位为 `(v, s)`：

1. 若 `s >= N`，当前版本已全部预留完，目标先推进到 `(v+1, 0)`；若此时 `v == V`，报 `ErrKeysExhausted`。
2. 本批大小 `batch = min(B, N - s)`：**一批不跨版本边界**，所以版本末批可能被截断为剩余数量（例如 `N=5,B=4` 时两批为 `4,1`）。
3. 新目标水位为 `(v, s + batch)`，通过条件写（CAS，仅当持久化当前值仍为旧水位时才推进）落盘。
4. 只有目标水位落盘成功（或按未知失败被视同落盘）后，内存「已预留」水位才前进；序号只从已预留范围内发放。

内存中为每个租户维护两条水位：

- `reserved`：已预留到的位置（可发放上界）；
- `issued`：已发放到的位置（下一个待发放序号）。

发放必须满足**同版本内** `issued.NextSeq < reserved.NextSeq`；当 `issued` 已跨入下一版本而
`reserved` 还停在上一版本的满水位时，二者不能直接比较 `NextSeq`，必须先为新版本预留。

## 崩溃恢复起点

崩溃时内存态丢失，只信任持久化高水位 `w`。新进程执行 `Recover`：

```
reserved = issued = w
```

即从高水位之后继续发放；`w` 以下、崩溃前尚未发放的预留序号**一律作废**。
由于每批至多 `B` 个且上一批要么完整落盘、要么完全没落盘，一次崩溃浪费的序号严格不超过 `B`。
作废产生空洞，但不影响唯一性：作废区间永远不可能在之后被再次发放。

## 两种预留失败的区别

`CompareAndSwapReserve` 返回三态：

| 结果 | 含义 | 内存 `reserved` | 内存 `issued` | 本次分配 | 下一次行为 |
| --- | --- | --- | --- | --- | --- |
| `ReserveOK` | 确定已落盘 | 推进到目标 | 不变 | 继续发放新范围 | 正常 |
| `ReserveFailed` | **确定未落盘** | 不变 | 不变 | 返回 `ErrReserveFailed` | 以同一旧水位重新预留，可能重新拿到相同序号 |
| `ReserveUnknown` | **结果未知（可能已落盘）** | 推进到目标 | 跳到目标（整批作废） | 返回 `ErrReserveUnknown` | 从该批之后重新预留 |

传输层返回 `error` 时无法确定落盘与否，按保守策略归入 `ReserveFailed` 处理（要求底层
Store 在能确定超时时改用 `ReserveUnknown`）。

三态错误（`ErrReserveFailed`、`ErrReserveUnknown`、底层 error）都与业务校验错误
（`ErrEmptyTenant`、`ErrTenantNotFound`、`ErrKeysExhausted` 等）通过 `errors.Is` 可区分。
分配时的判定顺序固定为：空租户 → 未注册 → 版本用尽（在访问持久化层之前判定）。

## 并发

每个租户一把互斥锁。当一批耗尽且已有一次预留进行中时，后来的并发调用者
**加入同一次预留**（在完成信号上等待），不会各自向持久化层请求重叠范围：

- 预留成功：等待者被唤醒后从同一新范围内领取不同序号；
- 预留失败（确定/未知）：所有等待者本次分配一起失败，由调用方决定是否重试。

唯一性论证：序号发放与水位推进都在租户锁内；预留范围靠 CAS 互不重叠；
未知失败只向前跳空，从不回退，因此任何交错下都不会发出两个相同的 `(版本, 序号)`。

## 本地验证

```bash
go test -race -v ./allocator
go test -race -count=10 ./allocator        # 反复跑以压并发时序
go test -cover ./allocator
go vet ./...
```

测试覆盖：版本边界批截断、崩溃后从高水位继续、每次崩溃浪费 ≤ B、
未知失败与明确失败的差异、最后版本未知失败后耗尽、校验顺序、多租户隔离、
百并发无重复、并发共用一次预留、相同操作序列 + 相同故障脚本结果确定。
日志通过 `Logger` 接口打印每次操作的输入、输出与判定依据（默认输出到 stderr）。
