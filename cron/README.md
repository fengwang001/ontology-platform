# cron — Cron 触发时刻计算器与错过触发判定控制器

纯 Go 实现，无外部依赖。时间为自 `2000-01-01 00:00`（星期六）起的
整数分钟，支持年份 2000–2199，公历闰年规则（100 的倍数非闰、400 的
倍数闰）。

## 表达式语法

五个字段以**单个空格**分隔，依次为：

| 字段 | 取值 |
| --- | --- |
| 分 | `0-59`（60 个值） |
| 时 | `0-23`（24 个值） |
| 日 | `1-31`（31 个值） |
| 月 | `1-12`（12 个值） |
| 周 | `0-6`，`0` 为星期日，`7` 非法（7 个值） |

每个字段是逗号分隔的非空项列表（允许重复项，结果为集合并集），每项为：

- `*`：字段全部取值；
- `a`：单个值；
- `a-b`：闭区间，要求 `a <= b`；
- `*/s`：从字段最小值到上限、步长 `s`；
- `a/s`：等价于 `a` 到字段上限、步长 `s`（如 `5/20` 得 5、25、45）；
- `a-b/s`：区间内按步长取值。

步长 `s` 必须在 `1` 到该字段取值个数之间。字段文本以 `*` 开头即带
通配标志（`*` 与 `*/2` 都算；`1,*` 这种字段文本不以 `*` 开头，不算）。

解析报错顺序：字段个数不为 5 → 按分、时、日、月、周及项出现顺序，
每项依次为语法错误（空项/非法字符）、取值越界、范围反向、步长非法，
报第一个违规。切分严格按单个空格，不合并连续空格，因此连续空格产生
空字段并报语法错误。

## 日与周的组合规则

月份必须匹配。日与周的组合：

- 日字段与周字段**都不**带通配标志时，当天满足日集合**或**周集合
  任一即可（OR）；
- 否则须**同时**满足日集合与周集合（AND）。

例：

- `0 0 13 * 5`：13 日或周五 → 2000-01-07（五）、01-13（四）、01-14（五）；
- `0 0 */2 * 5`：奇数日且周五 → 2000-01-07、01-21（14 日是偶数不触发）；
- `0 0 29 2 *`：2096-02-29 之后的下次是 2104-02-29（2100 不闰）；
- `0 0 31 2 *`：永无触发。

## API

```go
func ToMinute(y, mo, d, h, mi int) (int, error)
func FromMinute(t int) (DateTime, error)   // DateTime 含 Weekday（0=周日）
func Parse(spec string) (*Spec, error)
func NextFire(spec *Spec, t int) (int, error)
```

`NextFire` 返回严格大于 `t` 的最小匹配分钟。`t` 之后
`4000*1440` 分钟内无匹配、或匹配超过 2199 年末时返回
`ErrNoNextFire`。时间参数越界返回 `ErrInvalidTime`。

算法不逐分钟扫描：按整天推进（未导出的 `Spec.daySteps` 记录最近一次
`NextFire` 检查的天数，用 `Spec.DaySteps()` 读取，上限 4001），并在每个
已定位的日内直接在时、分集合中跳到下一个值。

## 控制器 Job

```go
func NewJob(spec string, created, d int, policy Policy) (*Job, error)
func (j *Job) SetSuspend(b bool)
func (j *Job) Sync(now int) (SyncResult, error)
func (j *Job) Finish(taskID, now int) error
```

- `d`：`-1` 无截止；否则窗口长度 `0..1e9` 分钟。
- `policy`：`Allow`（总是新建任务）、`Forbid`（有活动任务则跳过）、
  `Replace`（先终止全部活动任务再新建）。
- 初始：上次调度时刻 `L = created`，活动任务集合 `A` 为空，任务编号
  从 1 起递增，Sync 水位初值为 `created`。

### 窗口与只补最近一次

`Sync(now)` 的窗口是满足

```
t > L 且 t <= now 且 (d != -1 时 t >= now-d)
```

的全部触发分钟：`t == L` 不计、`t == now` 计、`t == now-d` 计。
窗口内触发数 `n`：

- `n == 0`：无事发生；
- `n > 100`：返回 `ErrTooManyMissed`，**不改变任何状态**；
- 否则只取窗口内最大的 `t*`（只补最近一次）：
  - `Allow`：新建任务；
  - `Forbid`：`A` 非空则跳过（`Skipped` 加一），否则新建；
  - `Replace`：终止 `A` 中全部任务（`Replaced` 加被终止数）后新建。
- 新建或跳过后都令 `L = t*`。

挂起：`SetSuspend(true)` 期间 `Sync` 无事发生但仍推进水位；恢复时不
补偿，错过的触发由之后的 `Sync` 按窗口判定（挂起期间不推进 `L`）。

`Sync` 报错顺序：时间非法 → 时钟回退（`now` 小于上次成功 Sync 的
水位）→ 错过太多。被拒绝的操作不改变 `L`、`A`、计数与水位。每次
`Sync` 最多调用 `NextFire` 102 次（未导出的 `Job.nfCalls` 供测试
验证）。`Finish` 对不存在或已结束的任务返回 `ErrTaskNotFound`。

所有方法持互斥锁，可并发调用，结果等价于某个串行顺序；相同操作序列
重放得到完全相同的触发时刻、任务编号与计数。
