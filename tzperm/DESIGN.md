# tzperm：时间类属性的属性级权限校验子系统

## 1. 问题与不变量

每次查看请求涉及三个互不相同的时区来源：

1. **录入时区**：属性取值在录入时标注的地点时区；
2. **地区默认时区**：对象所属地区的默认时区，定义允许按生效时间版本化迁移；
3. **查询者时区**：发起查询主体所在的时区。

系统必须对所有请求保持同一条基准选取规则，且该规则在跨越夏令时切换、
地区默认时区版本迁移、查询者时区变化时都不摇摆：

> **归一化基准恒为“被归一化的那个绝对时刻所在地区当时生效的默认时区定义”。
> 录入时区只用于把原始本地读数解码为绝对时刻；查询者时区只记录、不参与判定。**

### 1.1 历史值在地区迁移后使用哪一版定义

明确规定：

- 属性值先由**录入时标注的不可变时区定义**解码成 UTC 绝对时刻；
- 随后选取**该绝对时刻**（而不是当前查询时刻）生效的地区默认时区版本
  作为“值基准”；
- 窗口判定作用于“查询时刻”，因此选取**查询绝对时刻**生效的地区默认时区
  版本作为“查询基准”。

对同一条历史记录：其绝对时刻一旦确定便不再改变，地区版本列表只追加/整体替换、
不修改历史版本，所以值基准是其绝对时刻的纯函数。无论在迁移后多久、由谁
重新判定，结论一致。新增版本不会重写历史版本（见 4.3），这是稳定性的
结构性保证，而不是依赖“当前时间”的偶然结果。

### 1.2 夏令时切换日本地读数的歧义

时区以“按绝对时刻排序的偏移切换点”直接建模（`ZoneRules.Transitions`），
不依赖宿主 tzdata，保证测试可复现。本地读数 → 绝对时刻的映射在歧义处
采用与调用方无关的固定策略：

- **gap（春季跳过）**：被跳过的读数向前平移到跳变后第一个合法时刻；
- **overlap（秋季重复）**：选择两个绝对时刻中**较早**的一个；
- 其余情况唯一。

状态（`WallExact/WallGap/WallOverlap`）进入审计记录，但不出现在对外响应中。

## 2. 时间窗口与边界语义

窗口为地区本地时间的每日窗口（`WindowRules.StartSec/EndSec`）：

- `End > Start`：普通同日窗口；
- `End < Start`：跨本地午夜窗口；
- `End == Start`：全天窗口。

边界统一为**半开区间 `[Start, End)`**：起始边界在窗口内，结束边界在窗口外。
跨午夜窗口中，午夜既是前一天的结束边界（排除），也是新一天的开始边界
（包含），仍由同一条规则消歧。

归一化后的“墙钟秒”按**向下取整除以 86400** 得到本地日起点与秒数
（`SecondsOfDay`）。对 23/24/25 小时的夏令时日本地日，除法规则完全相同，
不为 DST 切换日设置任何特例。

## 3. 错误分类、优先级与信息不泄露

四类互不相同的错误代码：

| 代码 | 触发条件 |
| --- | --- |
| `ATTR_DEPRECATED` | 属性在当前对象类型版本（含累积历史版本）已被废弃 |
| `REGION_ZONE_UNDEFINED` | 值时刻或查询时刻不存在生效的地区默认时区定义 |
| `WINDOW_RULE_INVALID` | 查询时刻没有生效的窗口规则版本，或规则端点非法 |
| `QUERIER_IDENTITY_MISSING` | 查询者身份缺失，无法确定查询者（时区） |

多个错误同时成立时，按固定优先级**只返回一个**：

`ATTR_DEPRECATED` > `REGION_ZONE_UNDEFINED` > `WINDOW_RULE_INVALID` > `QUERIER_IDENTITY_MISSING`

理由：模式层废弃是对象内禀事实，最先执行；基准时区不可解析时后续一切
无定义；窗口规则必须先结构合法才轮到主体身份；查询者缺失是最贴近调用方
的条件。

**不泄露**：对外类型 `Outcome` 只有 `RequestID/Decision/ErrorCode` 三个
字段（测试通过反射枚举全部导出字段，确保不含任何归一化数值、时区名、
窗口边界）。所有敏感细节只进入受控的审计通道 `AuditSink`。错误文案为
固定字符串，不拼接任何参数。拒绝与四类错误使用同一响应形状，调用方不能
通过字段有无推断窗口位置或时区。

已知边界（显式放弃的部分）：本实现不承诺消除纯时序侧信道（例如不同错误
分支耗时差异）；若威胁模型要求，应在 API 层统一填充响应并做常量时间化。

## 4. 并发与复杂度

### 4.1 线性一致性

`Store` 使用**单一读写锁**。变更（地区定义、窗口规则、对象、模式）整体
替换已排序的不可变切片；`Engine.Check` 在**写锁**内完成读快照、归一化、
判定、审计写入。因此：

- 每个操作的临界区互不重叠；
- 互斥锁获取顺序本身就是一个合法的全序；
- 每个操作观察到的都是某个全序前缀的状态，输出等价于按该全序串行执行。

被放弃的方案：MVCC / RCU + 细粒度锁（读者可并发但证明复杂、GC 负担大）、
无锁原子指针（仍需处理多键快照的原子可见性）。当前吞吐模型是“判定本身
纳秒级、临界区极短”，单一锁最简且可证；压力测试 `TestConcurrentLinearizableSafety`
在读写混跑下验证无撕裂状态。

### 4.2 单次判定成本不随地区版本总数线性增长

生效版本查找为二分（`lookupEffective`），O(log n)，并**统计每次比较次数**：

- `TestLookupCostNotLinear` 在 16…65536 版本下断言比较次数 ≤ ⌊log2 n⌋+1；
- `TestEndToEndComparisonCounts` 在 4096 版本下端到端比较引擎二分计数与
  朴素线性扫描计数，确认引擎远小于朴素值；
- `BenchmarkCheckVsVersionCount` 在 64/4096/262144 版本下 ns/op 基本持平。

### 4.3 不可变历史与迁移

录入时区按指针引用不可变 `ZoneRules`；地区版本通过 `ZoneVersion{EffectiveFrom, Zone}`
整体发布。一次“调整地区默认时区”即发布新版本，不修改旧版本；查询引擎
按生效时刻选择版本。这样新定义不会改变对历史记录的归一化结论。

## 5. 审计与逐条复核

每次判定生成一条 `Record`，包含：输入（对象/属性/录入读数/录入时区/
查询者/查询时刻）、值绝对时刻与 wall 状态、两处基准时区名、查询归一化
墙钟、窗口边界、是否命中、最终结论，以及引擎二分比较数、朴素模型比较数
与两者是否一致。可注入任意 `AuditSink`（默认提供内存实现）。这是事后
复核与成本独立验证的统一数据面。

## 6. 被放弃的关键方案

- 用宿主 tzdata（`time.Location`）：历史定义版本化无法表达、测试不可重复；
  改为自包含的偏移切换表。
- 以查询时刻选择历史值基准：会导致结论随迁移推进而摇摆，被显式否决。
- gap/overlap 按“查询者所在地区习惯”消歧：破坏基准唯一性，改为全局固定策略。
- 半开区间改为闭区间：跨午夜窗口在午夜点会同时属于两天，无法给出单一
  结论，因此统一半开。
- 多错误全量返回：会泄露“系统走到了哪一步”，被优先级单选取代。
