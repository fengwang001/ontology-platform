# 时间依赖路网最早到达查询（`timetable` 包）

边的通行耗时随出发时刻分段变化，边可被封闭，并可随时间发布新的耗时
通告。包支持任意等待、历史版本查询、确定的紧边路线，并以非导出计数器
`Result.Popped` 度量单次查询的搜索规模。

## 数据模型与取值范围

- 节点数 `N ∈ [1, 5000]`，编号 `0..N-1`；边数上限 `E ∈ [1, 100000]`。
- 所有时刻为 `0..10^9` 的整数；系统时钟 `now` 初值 `0`，版本号初值 `0`。
- 边编号从 `1` 起严格递增；被拒绝的 `AddEdge` 不消耗编号。允许平行边，
  不允许自环。
- 剖面为 1..32 个分段 `(offset, cost)`：首段 `offset=0`，偏移严格递增，
  `cost ∈ [1, 10^6]` 或 `-1`（封闭），最后一段延伸至无穷。

## 通告记录与版本

- `AddEdge(u,v,profile)` 登记一条 `eff=0` 的记录。
- `Announce(edge, eff, profile)` 追加记录：
  - `eff < now` 拒绝（`ErrRetroactive`），不能改写已经过去的时刻；
  - `eff` 不得小于该边最后一条记录的 `eff`（否则 `ErrOutOfOrder`）；
  - `eff` 等于最后记录的 `eff` 时**替换**：旧记录不删除，只记下替换时
    的版本 `replacedAt`；替换不增加记录条数（不占 64 条上限）；
  - `eff` 更大时追加；每条边未被替换的有效记录至多 64 条。
- 每次被接受的 `AddEdge` 与 `Announce` 使版本加一；`Advance` 不加。
- `Advance(t)` 单调推进时钟，`t < now` 报 `ErrClockRollback`。

### 记录如何解释为边的耗时函数

一条记录 `(eff, profile)` 的第 `i` 段在绝对时刻 `eff+offset_i` 起、到
下一段起点前有效；记录的最后一段原本延伸到无穷，但如果后面还有下一条
记录，则在**下一记录的 `eff` 处被截断**。因此在某历史版本 `ver` 下：

- 边在 `addedAt <= ver` 时可见；
- 记录在 `addedAt <= ver` 且（未替换或 `replacedAt > ver`）时可见；
- 可见记录按 `eff` 非降排列，相邻记录首尾相接，边在出发时刻 `t` 的耗时
  取“可见的最后一条 `eff <= t` 的记录”剖面在 `t` 处的分段值。

编译快照（`snapshot`）时把可见记录展开、裁剪成首尾相接的有序分段
`[start,end)`，`end=∞` 表示末段。记录边界恰好落在某剖面分段起点时，
后一记录覆盖该单点，合并后仍为严格分段。

## 任意等待下的到达函数

允许在节点任意等待，边 `e` 的最早到达函数为

```
arr_e(t) = min { t' + cost_e(t') | t' >= t，且 t' 不在封闭段 }
```

**推导。** 每个开放分段内 `cost` 是正常数，所以 `t' + cost(t')` 随 `t'`
严格递增；在该分段内部取最小值只能取该分段允许的最小出发时刻。从 `t`
出发，这个最小值要么是：

1. `t` 本身（当 `t` 落在某个开放分段内）；
2. `t` 之后每个分段（可能来自后续通告记录）的起点。

封闭分段内不能开始通行，直接跳过；若 `t` 之后所有分段都封闭，则该边在
`t` 之后不可用。逐一比较上述候选即可，无需枚举整数时刻。例如剖面
`[(0,10),(20,2)]` 在 `t=8`：立即走得 `18`，等到 `20` 走得 `22`？
实际比较的是 `8+10=18` 与 `20+2=22`；而题面示例是 `t=8` 到节点 1 后
再走边 2（`d(1)=13`），`13+10=23` 对 `20+2=22`，故等到 20。

每个候选分段还返回其出发时刻；路线重建时在取得最小到达的候选里取**最小
整数出发时刻**作为该段 `Dep`。

## 最早到达搜索（时间依赖 Dijkstra）

到达函数满足 FIFO（先到不劣）：在开放分段随 `t'` 递增、封闭只可向后
等待，因此“标签取最小值 + 按标签弹出确定”的 Dijkstra 仍然正确。

- 松弛：`d(b) = min(d(b), arr_e(d(a)))`；
- 目标 `g` 取得临时标签后，弹出严格大于 `d(g)` 的节点时立即停止，
  等于 `d(g)` 的节点仍要确定（可能是 `g` 的紧边前驱）；
- `Result.Popped` 是被确定（弹出）的节点数，故
  `Popped <= |{ x : d(x) <= d(g) }|`，搜索在目标确定后立即终止，
  不是对全路网求最短路。测试 `TestGridPopped` 在 300×300 网格
  （90000 节点）目标邻近出发点时 `popped=56`，并用独立的全量标签
  计算逐一核对上述上界。

## 紧边与路线取法

边 `(a,b)` 当且仅当 `arr_e(d(a)) == d(b)` 时为**紧边**。紧边只从较早
确定的节点指向较晚确定的节点，构成 DAG。在所有 `s -> g` 的紧边路径中：

1. 先取边数最少；
2. 边数相同取边编号序列字典序最小。

实现分两阶段：

- 阶段 A：在紧边 DAG 上按弹出顺序 DP 出最少边数 `hops`；
- 阶段 B：按边数分层，给每个节点在最少边数的紧边入边中选键
  `(前驱字典序秩, 末边编号)` 最小者；同层键排序去重后分配的秩恰为
  等长边编号序列的字典序。

路线沿 `predNode/predEdge` 回溯；每段重新用到达函数取最小整数出发时刻
`Dep` 与对应 `Arr`。空路线（`s == g`）到达时刻即 `t0`。路线上每段
`Arr <=` 下一段 `Dep`，末段 `Arr == d(g) == Result.Arrival`。

## 错误原因与校验顺序

错误以 `*timetable.Error` 返回，`Code` 可取：

`ErrInvalidArgument`、`ErrEdgeLimit`、`ErrNoSuchEdge`、`ErrRetroactive`、
`ErrOutOfOrder`、`ErrRecordLimit`、`ErrClockRollback`、
`ErrVersionNotYetCreated`、`ErrUnreachable`。

- `AddEdge`：参数非法（含 `u==v`、剖面非法）→ 边数已满。
- `Announce`：参数非法 → 边不存在 → 追溯过去 → 记录乱序 → 记录已满。
- `Advance`：参数非法 → 时钟回退。
- `EarliestArrival`：参数非法 → 版本尚未产生（`ver > 当前版本`）→
  不可达。`ver` 缺省为当前版本；`t0` 可以早于 `now`（使用所有现有记录）。

被拒绝的操作不改变路网、记录、`now`、版本与边编号。

## 并发与可复现

- 所有变更在互斥锁内完成“检查 + 提交”，查询在读锁内取不可变快照
  （剖面被拷贝保存），等价于某串行顺序，查询看不到登记一半的通告。
- 对任何已产生的 `ver`，查询只依赖 `<= ver` 的不可变记录；之后的追加、
  替换、`Advance` 都不影响其结果。`TestVersionVisibility` 与
  `TestConcurrency` 对此做了前后逐字比对，`-race` 下无竞争。

## 本地验证

```bash
go test ./...                         # 全量
go test -race ./...                   # 竞态
go test ./timetable -run TestRandomDifferential -v   # 2000 组随机对照（带日志）
go test ./timetable -run TestGridPopped -v           # 300x300 网格 popped
gofmt -l . && go vet ./...
```

`TestRandomDifferential` 对 2000 组随机小路网同时跑服务与按时间展开的
朴素逐时刻 DP（枚举 `t0` 之后每个分段起点、Bellman 风格松弛），在有限
时刻视野内逐字对照到达时刻、边序列与每段出发时刻，并核对 `popped`
上界；日志打印每组输入（节点、边、起终、`t0`、版本）、双方输出与判定。
