# 差异记录重放校验组件 — 设计说明

包路径：`ontology/replay`

## 问题

灾难恢复场景：手头只有一份灾难前的良好快照（`Snapshot`）和一份差异记录
（`DeltaLog`，含变化序列与声明的目标状态）。需要判定：把差异记录重放到
快照之上，能否**确证**得到与灾难发生时刻本应达到的状态等价的结果；并在
失败时明确区分三类互不相同的原因。

## 三类失败与固定优先级

| 优先级 | 判定 | 含义 |
|---|---|---|
| 1 | `InconsistentDelta` | 差异记录自身内部不自洽 |
| 2 | `PreconditionFailed` | 重放所需前提环境（良好快照）不满足 |
| 3 | `NotEquivalent` | 重放结果与差异记录声明的目标状态不等价 |

判定顺序固定为 1 → 2 → 3，命中靠前类别后立即返回，不再继续。理由：

- **自洽性最先**：若差异记录自身都不可信（内部矛盾、顺序错位），用它驱动的任何后续判定都没有意义；且自洽性校验只依赖差异记录与快照结构层，不依赖环境，结论最确定。此阶段失败时**整体拒绝，绝不开始重放**。
- **前提环境其次**：记录自洽后，才有意义询问"这份记录是否产生自这份快照所代表的环境"。重放在覆盖层（见下）上进行，应用失败即环境不一致。
- **等价性最后**：只有重放完整成功，比较重放结果与声明目标才有意义。

## 阶段划分与职责

| 文件 | 职责 |
|---|---|
| `check.go` | 差异记录自身自洽性校验（含结构层/实例层相对顺序核对） |
| `replay.go` | 前提环境校验 + 受控重放（逐条应用，含约束重新核对） |
| `compare.go` | 重放结果与声明目标的逐项等价性核对 |
| `overlay.go` | 覆盖层工作状态（copy-on-write），支撑并发安全与复杂度上界 |
| `engine.go` | 对外入口，按固定优先级编排三阶段 |
| `reference.go` | 朴素参照模型，用于随机对照测试 |

## 关键取舍

### 1. 自洽性（阶段 1）与前提环境（阶段 2）的分界线

规则：**阶段 1 只使用差异记录本身与快照的结构层（类型/属性/约束定义），绝不读取快照的实例内容**（对象取值、链接键）。凡需要快照实例内容才能判定的检查——对象/链接是否存在、变化前状态是否与快照一致、快照中是否仍有引用——一律推迟到阶段 2，归为 `PreconditionFailed`。

由此，"差异记录声明更新一个快照中根本不存在的对象"在阶段 2 重放时被发现，判为 `PreconditionFailed`（题面明确要求）；而"差异记录先删除某对象再更新它"这类记录内部矛盾在阶段 1 判为 `InconsistentDelta`。题面两处表述的潜在重叠由此规则消解，且优先级保证命中靠前类别后不再继续。

### 2. 结构层/实例层相对顺序：模拟而非重排

阶段 1 按差异记录**声明的原始顺序**模拟结构层演化；实例层变化引用的结构（类型、属性、约束）必须在模拟到该条时已经生效，否则判为不自洽。组件**绝不自行调整顺序代为纠正**——顺序错位是差异记录自身的缺陷。

### 3. 约束的前向生效与重新核对

链接类型约束（内建 `uniqueSource`）在其结构层变化应用之后，对**后续**的实例层变化生效：每条 `AddLink` 在被应用到处时，基于当前有效结构重新核对约束。组件不会在结构层变化应用之前提前校验相关实例，也不会在约束生效后跳过重新核对直接采信后续实例变化。约束不追溯既往（在约束新增之前已存在的链接不重新校验），这是有意的语义选择。

### 4. 覆盖层（copy-on-write）重放：并发安全 + 复杂度上界

重放绝不物化快照副本，而是在覆盖层上进行：所有变更只写入覆盖层 map，读取时先查覆盖层再回退到快照（`overlay.go`）。因此：

- **原始快照零修改**：校验组件不持有任何可变共享状态，`Verifier` 零值即可用，并发调用结果确定且一致（`TestConcurrentVerifyDeterministic` 在 `-race` 下验证）。
- **开销与快照规模无关**：每条变化的处理是常数次 map 查询/写入。

### 5. 快照携带索引

引用完整性/约束检查（删除对象时是否仍有链接引用、删除类型时是否仍有实例、`uniqueSource` 计数等）需要全局信息。若每次现场扫描快照，开销随快照规模线性增长，违反复杂度要求。取舍：**快照携带其派生索引**（`SnapshotIndexes`，如同数据库检查点携带索引），校验组件只读使用并在覆盖层中维护增量，全部检查都是 O(1) 查询。索引缺失判为 `PreconditionFailed`（环境损坏）；索引内容受信任（校验索引本身需要 O(快照规模) 的重建，与复杂度要求冲突，文档化为本组件的信任边界）。

### 6. 等价性核对：逐项 + 基数

阶段 3 对声明目标中的每一项（对象类型、链接类型、对象实例、链接实例）逐一与重放结果比对；再用**基数（计数）核对**保证重放结果不存在目标之外的多余项。基数由覆盖层在重放过程中增量维护，因此无需遍历快照中未被触及的对象与链接。不一致位置按结构/对象/链接三类报告（`Mismatch.Category`），并排序保证输出确定。

### 7. 对象类型不可变

`UpdateObject` 不允许变更对象类型（类型变更应"先删后建"）。这消除了类型变更引发的链接端点类型级联校验问题，是明确的语义取舍。

## 被放弃的方案

- **整体深拷贝快照后重放**：实现最简单，但拷贝成本随快照规模线性增长，违反"开销只与差异记录规模相关"的要求。放弃，改用覆盖层。（朴素参照模型仍用此方式，作为对照。）
- **重放前先做一遍完整的前提预扫描**：可以做到"重放绝不中途停止"，但需要把每条变化的前提在快照原始状态上重新解释（前面变化的效应要逐条传递），实质是把重放做两遍，复杂且易错。放弃：前提检查融合在覆盖层重放中，失败即弃置覆盖层，原始快照不受任何影响。
- **目标状态只声明被触及部分**：无法支撑"全部对象实例/链接逐一核对"的等价性要求。放弃：差异记录声明完整目标状态。
- **校验组件现场重建快照索引**：可免除快照携带索引，但重建成本 O(快照规模)，违反复杂度要求。放弃。
- **差异记录自描述校验和/签名**：可强化"差异记录自身可信"的判定，但属于密码学完整性范畴，超出本题语义校验范围。未采用。

## 复杂度论证（可复核方式）

设差异记录规模为 D（变化条数 + 声明目标的项数），快照中未被触及的对象与链接总数为 N。三个阶段均不遍历快照整体：

- 阶段 1：逐条处理变化，每条为常数次结构层 map 查询 → O(D)。
- 阶段 2：每条变化为常数次覆盖层/索引查询与写入 → O(D)。
- 阶段 3：遍历声明目标（规模计入 D），逐项常数查询 + 常数基数比较 → O(D)。

复核方式：`Verifier.VerifyWithStats` 返回对原始快照的读取统计（`Stats`）。`TestCostIndependentOfUntouchedSnapshotSize` 固定同一份差异记录，将快照中未被触及的对象与链接从 3/1 增至 5003/5001，断言两次校验的读取统计**完全相等**——开销不随 N 增长，只与 D 相关。

## 本地验证方法

```bash
# 全部测试（含竞态检测）
go test -race ./replay/

# 随机对照测试（3000 个随机用例，主实现 vs 朴素参照模型）
go test ./replay/ -run TestRandomDifferential -v

# 将每次校验的输入、输出与判定依据写入 JSONL 日志
REPLAY_FUZZ_LOG=/tmp/fuzz.jsonl go test ./replay/ -run TestRandomDifferential

# 复杂度无关性证明
go test ./replay/ -run TestCostIndependentOfUntouchedSnapshotSize -v

# 静态检查
gofmt -l . && go vet ./...
```

测试覆盖：

- 结构层/实例层顺序错位（`TestInstanceChangeBeforeSchemaChange`）
- 快照缺失差异记录所依赖对象（`TestUpdateObjectMissingInSnapshot`）
- 结构/对象/链接三个层面各自单独不等价（`TestNotEquivalent{Schema,Object,Link}`）
- 约束新增与依赖它的实例变化紧邻出现（`TestConstraint*`）
- 结构层变化应用前不得提前校验实例（`TestNoInstanceCheckBeforeConstraintApplied`）
- 反复校验结果一致（`TestRepeatedVerifyDeterministic`）
- 并发校验结果一致且快照不被修改（`TestConcurrentVerifyDeterministic`，`-race`）
- 不自洽整体拒绝（`TestInconsistentDeltaRejectedAsWhole`）
- 判定优先级（`TestPriority*`）
- 与朴素参照模型在 3000 个随机组合上对照（`TestRandomDifferential`），并断言四类判定均被覆盖
