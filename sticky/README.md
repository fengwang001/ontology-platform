# sticky：消费组粘性分区分配

`sticky.Assignor` 在成员加入/离开时把固定编号集合（分区 `0..N-1`）重新分配给成员，
目标是**持有数均衡、分区迁移最少、结果确定可复现**。所有方法可被多个 goroutine
并发调用（内部 `sync.RWMutex` 保护）。

## 变更批

- `Apply(ctx, []Op)` 一次接收一批操作（`Join=true` 加入，否则离开），**先整体
  修改成员集合，再只做一次重分配**；批内永远不会出现中间态分配。
- 校验在任何状态修改之前完成：任一操作非法则**整批拒绝**，分配与代数均不变
  （失败不留痕）。校验基于批前成员集合计算批后的净效果，因此**与批内顺序无关**；
  “先离后加”同一成员允许（净效果为留组），“先加后离”同理（净效果为不在组）。
- 仅当批后成员集合确实发生净变化时才重分配并把代数 `Generation` 加一；空批或
  无净效果的批直接返回当前快照，代数不变。

## 配额

设分区数为 `N`、批后成员数为 `M`：

- 每个成员的**基础配额** = `floor(N / M)`；
- `N % M` 个**余数名额**按成员的“批前持有数”**降序**分配，持有数并列时按成员
  标识**升序**（批前持有数只统计批后仍在组的成员，新成员为 0）；
- 最终任意两成员持有数之差不大于 1。
- `M = 0`（最后一个成员离开）时所有分区变为无主，且该动作不产生迁移计数。

## 释放

1. 离开成员的分区先标记为无主；
2. 对持有数超过自身配额的成员，按**分区编号从大到小**扫描并释放，直到其持有数
   等于配额。扫描顺序对所有成员全局统一，保证结果确定。

## 补齐

无主分区按**编号升序**逐个处理：每个分区交给当前**配额缺口（配额 − 已持有）
最大**的成员；缺口并列时取**标识最小**者，然后更新其缺口再处理下一个分区。

## 迁移计数

`BatchResult.Migrations` = 批前有主、且批后持有者不同的分区个数（分区变为无主
不算迁移）。该算法在“持有数差不超过 1”的约束下使迁移数最小；测试
（`TestMigrationsMatchBruteForce`，300 个随机场景）通过穷举所有均衡分配的暴力
参照逐例核对迁移数相等。

## 确定性

- 成员排序、余数名额排序、释放扫描、补齐选人与分区扫描全部有确定的次序；
- 同一变更序列无论批内操作顺序如何，结果逐分区相同
  （见 `TestOrderIndependence`）。

## 边界

- 分区数可为 0：任何成员集合下分配均为空、持有数全 0。
- 成员数多于分区数时基础配额为 0，仅 `N` 个成员各持 1 个分区，其余成员持 0 个。
- 无成员时分区全部无主；再次有成员加入时按补齐规则重新分配。
- 重复离开同一成员（净效果已离开）允许，不报错。

## 错误类别

非法输入整批拒绝，返回 `*BatchError`（`errors.As` 可识别），其 `Reason` 为下列
互不相同的哨兵错误之一（`errors.Is` 可区分），并带首个违规操作的 `Index` 与
`Member`：

| 哨兵错误 | 触发条件 |
| --- | --- |
| `ErrEmptyMemberID` | 加入操作的成员标识为空串 |
| `ErrDuplicateJoin` | 同一成员在批内加入两次，或加入批前在组且批内未离开的成员 |
| `ErrLeaveUnknown` | 离开的成员批前不在组且批内也未加入 |
| `ErrMemberLimit` | 批后成员数超过 `NewAssignor` 指定的上限（`<=0` 表示不限） |

`ctx` 已取消/超定时 `Apply` 直接返回该 context 错误，同样不改变状态。

## 查询与自检

- `Assignment()`：返回 `成员 -> 分区编号升序列表` 的快照副本；
- `Generation()`：当前代数（每次有效重分配加一）；
- `Check()`：校验无主分区（有成员时）、分区不会被非成员持有、持有数极差不超过 1、
  成员数不超限。
