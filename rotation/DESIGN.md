## 模块划分
- `model.go`：`Region/Group/User` 拓扑、类别（免控/保底/普通）、六类拒绝错误。
- `orders.go`：指令簿。指令为 `[start,end)` 对齐窗口 + 按边界生效的等级时间线；
  `active` 仅保留未结束/未取消的指令，跨边界 `prune`，故有效等级查询不随
  已取消、已结束指令增长。
- `scheduler.go`：单调时钟与逐边界结算、选组与对账。一把互斥锁串行全部操作，
  并发等价于某个加锁顺序。
- `notify.go`：通知生成/撤回、确认、考核及只读视图。

## 关键取舍
- 时间为离散整数；区域各自有固定 `slotLen`，窗口必须对齐。
- 选组排序键为 `(累计被限时长, 组编号)`，等级只决定取前若干名。
- 边界两阶段：到达 `b` 先结算 `[b-L,b)`（计时、冻结决策），再按 `b` 时刻有效
  等级开放 `[b,b+L)`；时钟恰好停在 `b` 时该槽仍可被“恰在边界”的改级/取消
  对账，严格越过 `b` 才冻结并考核。这精确区分“恰在边界”与“边界后一刻”。
- 下一槽在开放时即预选并生成通知（排序用“投影累计”：在限组提前加一个时段长，
  与结算后真实秩一致），从而存在真实的开始前确认窗口；到达后仍按真实状态重算
  并与通知名单对账，撤组即撤回且不计考核。
- 改级/取消发生在槽内部时只从下一边界生效；起点早于当前槽下一边界的下指令
  报参数非法；取消早于窗口起点视同从未存在（删除），否则追加一条等级 0 时间线。
- 对账时保留组的取舍完全由排名决定，无随机、无遍历用户，保证可重放。

## 被放弃的方案
- “到达边界才发通知”：开始前确认窗口退化为空，无法表达“开始后确认报已过截止”。
- 为每槽运行时重算所有指令：无法满足有效等级不随历史指令数增长的要求。
- 每区域独立时钟：跨区域边界先后无法全局串行复现，故采用单一全局时钟。

## 性能（已在 `props_test.go` 验证）
- 选组 `O(G log G)`，`G` 为组数，与用户数无关（allocs 不随后者增长）。
- 通知只遍历被选组成员；有效等级只扫描 `active` 指令。

```bash
go test -race -v ./rotation/
```
场景测试覆盖编号平局、全选、边界改级/取消、叠加回落、免控与保底、
确认截止、换组拒绝、跨多边界结算、公平性与拒绝次序；
`TestNaiveDifferential` 对 400 条随机序列与逐槽朴素模型逐项对照，
失败日志逐条打印输入、输出与判定依据。
