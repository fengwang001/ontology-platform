# 设计说明（考场排考与调考引擎）

模块职责（scheduler 包，Go，零依赖）：
1. `calendar.go` 时段网格：slot = day*slotsPerDay + index，唯一单调；区间左闭右闭，跨日/越界在此判定。
2. `exam.go` 考试静态信息与时长：允许加时时长 = 标准 + ceil(标准*比例)，不足一段向上进位。
3. `conflict.go` 学生冲突：重叠 > 超门数 > 间隔不足（gap=后start-前end-1，等于下限合法），同类取最小学生。
4. `venue.go` 考场账目：每考场每时段单一占用；多考场容量和 >= 人数；延长学生按考场标识升序确定性就座，其考场在延长段同样占用。
5. `proctor.go` 监考账目与选人：每考场每时段 1 人；每人每日上限、同时段唯一。
6. `engine.go` 事务入口：安排/移动/互换/撤销/查询，单把互斥锁保证并发等价于某串行顺序。

关键取舍：
- 监考选用按日 Dinic 最大流精确求解（岗位→(监考,时段)→监考），不用“按标识贪心”——贪心会把可行方案误判为缺人；岗位/监考/边均固定排序，同状态同输入恒得同人选，与调用历史无关。
- 拒绝原因在事务校验中分阶段短路：非法参数 > 已安排 > 跨日越界 > 考场占用 > 容量不足 > 学生冲突 > 监考不足；错误携带原因码、归因学生、冲突类别、不合法考试方。
- 移动/互换先构造“自身旧占用已移除”的纯内存视图（学生索引、考场账目、监考账目均支持 skip），全部阶段通过后才一次性改账；任何失败零写入。
- 互换按考试标识升序做跨候选归因；两方都不合法时报标识较小一方。
- 撤销逐账目释放（考场、延长段、监考、学生索引）；未安排撤销返回独立错误码 exam_not_placed。

被放弃的方案：
- 贪心监考分配：反例（同一人先占满后导致后续本可由别人覆盖的岗位失败），改为最大流。
- 用全局 map 遍历查学生冲突：无法满足“判定开销只随该学生考试数增长”，改为每学生维护有序区间索引 `studentIndex`。

复杂度可验证：候选学生 s 的冲突判定只构造其个人区间列表（索引 `sidx.per[s]`，长度 k=该生考试数）做 O(k log k) 排序检测，不遍历其他考试、考场或时段；随机差分测试（`naive_test.go`，固定种子、60 场景 x 250 步）同时以独立朴素模型（全量重建 + 回溯匹配监考）逐步比对接受/拒绝、原因码、归因与全部学生占用，并打印每步输入/输出/判定依据。

本地验证：`GOCACHE=/tmp/gocache go test -race ./...`（若 go 不在 PATH：`export PATH=$PATH:/usr/local/go/bin`）。
