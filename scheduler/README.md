# scheduler — 抢占阈值调度器（单核离散步进模型）

单核、按 tick 离散步进的抢占阈值调度（Preemption Threshold Scheduling）模型，
带等待加成（防饥饿）与被抢占保护。相同的操作序列重放得到完全相同的运行序列
与完成时刻；所有方法可并发调用，结果等价于某个串行顺序。

## 构造与任务

```go
s, err := scheduler.NewScheduler(W, Bmax, M, Tmax)
```

- `W`：加成档宽，1 到 10^6；`Bmax`：加成上限，0 到 1000
- `M`：保护次数，1 到 1000；`Tmax`：在册任务上限，1 到 10^6
- 构造参数越界时整体拒绝，返回 `ErrInvalidConfig`

`Add(id, p, th, w)`：任务在当前 `now` 到达，领取到达序号 `seq`（从 1 起），
`wt=0`、`pc=0`，初始就绪。`id` 为正整数，`p` 在 0..255（越大越高），
`th` 在 `p..255`，`w` 在 1..10^6。拒绝按顺序只报第一个错误：
参数非法（`ErrInvalidTask`）→ 任务已存在（`ErrTaskExists`，含运行中与就绪，
已完成的编号可复用）→ 已满（`ErrFull`，在册数不小于 `Tmax`）。
被拒绝的 Add 不改变任何任务与 `seq` 计数。

## 有效优先级与屏蔽值

- 有效优先级：`e = p + min(Bmax, floor(wt / W))`，其中 `wt` 为等待计数。
- 候选 `σ`：就绪任务中 `e` 最大者，并列取 `seq` 小者。
- 运行者 `ρ` 的屏蔽值：`sh = th`；若 `pc >= M`（被抢占次数达到保护次数），
  `sh` 为无穷——此后一旦运行就不会再被抢占。

## tick 内三步次序（Step）

第 k 个 tick 开始时 `now = k-1`，依次执行：

1. **决策**（只用本 tick 开始时的 `wt`）：没有运行者且存在就绪任务时派发 `σ`
   （`wt` 置 0，不看阈值）；有运行者且 `e(σ)` **严格大于** `sh` 时，`ρ` 回到
   就绪（`pc` 加一、`wt` 置 0），`σ` 被派发（`wt` 置 0）。
2. **执行**：运行者剩余工作量减一，其余就绪任务 `wt` 各加一；运行者剩余为 0
   则完成于时刻 `now+1` 并移出在册。
3. **时钟**：`now` 加一。

`Step()` 返回本 tick 的运行者编号（空转为 0）与完成者编号（无为 0）。
`Step` 不会被拒绝；没有任务时空转并使 `now` 加一。两次 `Step` 之间到达的
任务，在下一个 tick 的决策中 `wt=0`，但在该 tick 的执行步就累计 `wt`。

## 等待计数与保护规则

- `wt` 在派发与被抢占时都清零；处于就绪的每个执行步加一。
- 加成按 `floor(wt/W)` 计算并封顶 `Bmax`；`Bmax=0` 时无加成。
- `pc >= M` 的任务屏蔽值为无穷，一旦运行就不会再被抢占。

## 实现要点

- 就绪集合用索引堆（`e` 降序、`seq` 升序）维护，决策只取堆顶，
  每次决策的候选比较数（非导出计数器 `examined`）为 O(1)；
  加成提升通过按 tick 分桶的事件懒应用，摊还 O(1)。
- `wt` 不显式存储：记录清零时刻 `epoch`，`wt = now - epoch`。
- 规模测试显示就绪任务 100 与 10000 两档（含全部任务同时越过加成档）下，
  平均每次 `Step` 的 `examined` 之比为 1.0（要求小于 4，线性扫描约 100）。
