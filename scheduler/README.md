# 偏移区间追踪调度器（`scheduler`）

可动态拆分、带批确认（bounded-ack）的偏移区间追踪调度器。登记半开偏移区间，
按步进领取偏移批，按分数把剩余工作拆分为新区间；批被确认之前压住保持值，
维护只进不退的输出水位线。所有操作可并发调用，结果等价于某个串行顺序。

## 区间、批、next 与完成

- **区间**：半开区间 `[from, to)`，有编号 `id`（从 1 起；`Add` 与 `Split`
  共用同一个递增计数器，编号不复用）。`to` 在拆分后可能缩小。
- **next**：下一个未领取偏移，初值为 `from`。`next == to` 称为**领完**。
- **批（batch）**：`Process(id, n)` 每次成功领取 `k = min(n, to-next)` 个
  连续偏移 `[next, next+k)`，产生一个新批；批号 `b` 全局从 1 起递增，
  批属于领取它的区间，状态为未确认或已确认。领取后 `next += k`。
- **完成**：区间**领完**且其全部批都已确认。每个区间内每个偏移至多被领取
  一次；已完成区间不再被任何操作改变，已确认批不再改变。

## 拆分点公式与取整方向

`Split(id, num, den)`（`0 ≤ num ≤ den`，`1 ≤ den ≤ 10^6`）只拆分**尚未领取**
的尾部：

```
rem  = to - next
keep = max(1, ceil(rem * num / den))
sp   = next + keep
```

- 拆分**基于 `next` 而非 `from`**：已经领取的批永远留在原区间。
- **向上取整**：`ceil(x) = floor((rem*num + den - 1) / den)`。
  例如 `rem=7, num=1, den=2`：`7/2 = 3.5`，`keep=4`，`sp=next+4`；
  `rem=10, 1, 3`：`3.33… → 4`；而整数情形（`rem=8, 1, 2`）仍为 `4`，
  不是四舍五入的巧合。
- `num=0` 时 `keep=max(1,0)=1`，仍保留至少 1 个偏移。
- `rem=1` 时任何分数都有 `keep=1`，故 `sp==to`。
- 若 `sp >= to`，返回“无法拆分”（`ErrCannotSplit`），这是**正常结果**，
  不改变任何状态（编号计数、区间、批、W 均不变）。
- 否则原区间变为 `[from, sp)`，新区间为 `[sp, 原to)`（`next=sp`、无批、
  编号取下一个计数）。拆分在同一把锁内完成，是原子步骤：任何观察者都看
  不到“原区间已缩小但新区间尚未登记”的中间状态。原区间已有的批不受影响，
  拆分前后两区间合起来覆盖的偏移集合完全相同。
- `rem*num` 可达 `10^15 × 10^6 = 10^21`，超出 int64，实现使用
  `math/big.Int` 完成乘法与向上取整。

## 保持值（hold）与输出水位线（W）

- 区间保持值

  ```
  hold = min(next, 该区间全部未确认批的起点中的最小值)
  ```

  - 没有未确认批时 `hold = next`。
  - **批确认前 hold 不前进**：`Process` 推进 `next`，但只要新批未确认，
    hold 仍是最早未确认批的起点。
  - 领完但仍有未确认批的区间**未完成**，`hold` 为其最小未确认批起点，
    继续压住水位。
  - 乱序确认后面的批时 hold 不动；确认最早的未确认批后，hold 跳到下一
    个未确认批的起点；全部批确认后 hold 跳到 `next`。
  - 完成的区间不参与 hold；hold 单调不减。

- 输出水位线：`W` 初值为 0。每个被接受且改变状态的操作（`Add`、`Process`、
  `Split`、`Ack`）之后：

  ```
  若存在未完成区间： W = max(W, min{ 所有未完成区间的 hold })
  否则：             W 不变（不跳到无穷）
  ```

  因此 W 只进不退，且始终不大于任何未完成区间的 hold。
- **Add 与水位线**：要求 `0 ≤ from < to ≤ 10^15` 且 `from ≥ W`，否则按
  “参数非法”→“低于水位线”的顺序拒绝（只报第一个原因）。`from == W`
  恰好允许；`from == W-1` 拒绝。加入一个 hold 低于其他区间最小 hold 的
  新区间时（其 `from` 仍需 ≥ W），W 不回退。

## 拒绝原因与顺序（彼此可区分）

| 操作 | 判定顺序（只报第一个原因） |
| --- | --- |
| `Add(from,to)` | 参数非法 → 低于水位线 |
| `Process(id,n)` | 参数非法 → 无此区间 → 区间已领完 |
| `Split(id,num,den)` | 参数非法 → 无此区间 → 区间已领完（`sp>=to` 是正常的 `ErrCannotSplit`） |
| `Ack(b)` | 参数非法 → 无此批 → 批已确认 |
| `Progress(id)` | 无此区间 |

被拒绝的操作不改变任何区间、批、编号计数与 W；“无法拆分”同样如此。

## 数据结构与 holdProbes

- 一把 `sync.Mutex` 串行化全部公开操作，天然给出某个合法的串行顺序。
- 全局“未完成区间 hold 最小堆”：每个区间的 hold 变化后压入带版本号 `ver`
  的新堆项，旧项惰性失效（区间完成或 `ver` 过期）。
- 每区间“未确认批起点最小堆”：确认批时仅置标记；若被确认的不是堆顶
  （乱序确认），堆中惰性保留；堆顶是已确认批时才连续弹出失效项。
- 非导出计数器 `holdProbes` 统计“求最小 hold”时**查看（peek/pop）**的
  堆项数，包括被惰性丢弃的失效项；`Push` 内部的 sift 比较不计入。
  因此每个操作的探测数与未完成区间总数、单区间未确认批数无关：一次操作
  至多查看常数个有效堆项（≤ 4）加上本次丢弃的失效项数，且每个失效项只
  会被丢弃一次。测试在 10/10000 个未完成区间与单区间 10/10000 个未确认
  批四种规模下断言同一个 `Process` 与同一个 `Ack` 的探测增量完全相等。

## 本地验证

```bash
# 全部测试（普通模式）
go test ./...

# 竞态检测与详细输出
go test -race -v ./scheduler

# 打印随机差分日志（输入、输出、W、探测数与判定）
SCHED_LOG=/tmp/sched_diff.log \
SCHED_LOG2=/tmp/sched_exhaust.log \
  go test ./scheduler -run TestRandom

# 静态检查与格式
go vet ./...
gofmt -l .
```

`TestRandomDifferential` 与 `TestRandomExhaustDifferential` 各用 2000 组
随机操作序列与朴素模拟（每次重扫全部区间与全部批求最小 hold）逐步对照
返回值、拒绝原因、每个区间的 `from/to/next/remaining/未确认批数` 与 W。
