# sps — 带版本历史的增量单源最短路维护

`sps`（shortest-path service）在**有向正权图**上随着边的新增、改权与删除，
持续维护源点 `s` 到每个节点的最短距离与一条确定的最短路径父边，并在每次
更新后报告距离/父边发生变化的节点集合，同时保留最近 `K` 个版本的距离历史。

## 构造与对象

```go
svc, err := sps.New(N, s, Emax, K)
```

- `N`：节点数，`1 ≤ N ≤ 2000`，节点编号 `0..N-1`。
- `s`：源点，`0 ≤ s < N`，恒有 `d(s)=0`，且源点无父边。
- `Emax`：存活边数上限，`1 ≤ Emax ≤ 100000`。
- `K`：历史版本保留数，`1 ≤ K ≤ 64`。

边有编号 `id`，从 1 起**严格递增、删除后不复用**；被拒绝的 `AddEdge`
不消耗编号。允许平行边，不允许自环（`u == v`）。权重为整数，
`1 ≤ w ≤ 10^6`。

## 紧边与父边

- `d(v)` 为源点到 `v` 的最短路长度；不可达时无距离（内部用 `INF` 表示）。
- 一条存活边 `(u,v,w)` 当且仅当
  `d(u)`、`d(v)` 均存在且 `d(u)+w == d(v)` 时称为**紧边**（tight edge）。
- 对可达且非源点的 `v`，其**父边**是所有指向 `v` 的紧边中**编号最小**的那条；
  源点无父边，不可达节点无父边。
- 因为权重恒正，任何指向源点的边都满足 `d(u)+w > 0 = d(s)`，故**永不为紧边**。
- 沿父边回溯必然到达源点，且沿父边的权重之和恰好等于 `d(v)`。

这两个定义只依赖当前图，因此更新报告在任何正确实现下都唯一确定。

## 更新与变更报告

三个更新方法都是并发安全的，返回 `*UpdateResult`：

```go
svc.AddEdge(u, v, w)    // 新边编号在 result.EdgeID
svc.SetWeight(id, w)    // 设成原权重也被接受
svc.RemoveEdge(id)

type UpdateResult struct {
    Version  int   // 更新后的新版本号
    EdgeID   int   // 仅 AddEdge 使用
    DChanged []int // 距离发生变化的节点（含可达性翻转），升序
    PChanged []int // 距离不变且可达、但父边编号变化的节点，升序
    Examined int   // 本次更新扫描的边条数（非导出计数器口径，见下）
}
```

版本号初值为 `0`（只有 `N` 个孤立节点的图）。每一次**被接受**的
`AddEdge / SetWeight / RemoveEdge` 都使版本号加一，无论是否真的改变了
距离或父边；`SetWeight` 设成原权重同样加一。

报告口径（两列表互斥、均按节点编号升序）：

- `DChanged`：更新前后距离不同的节点，包括由可达变不可达、由不可达变可达。
  距离发生变化的节点**只**出现在 `DChanged`，即使它的父边同时改变。
- `PChanged`：更新前后都可达、距离相等、但父边编号变化的节点。

### 受影响集合的传播规则

算法只在“真正可能改变答案”的局部区域工作，而不是整图重算。

**变短 / 新增（decrease）**：设边 `e=(u,v,w)`。

- 若 `u` 不可达，或 `d(u)+w > d(v)`，无影响。
- 若 `d(u)+w == d(v)`，`e` 恰好变紧；距离不变，仅当其编号比 `v` 当前父边
  更小时把 `v` 记入 `PChanged`。
- 若 `d(u)+w < d(v)`（含 `v` 原不可达），`v` 的距离必然下降；从 `v` 出发做
  Dijkstra 式松弛，距离严格下降的节点沿出边继续传播。传播途中距离不变、
  仅因新紧入边编号更小而更换父边的节点计入 `PChanged`。

**变长 / 删除（increase）**：只在被改边在修改前是紧边时才可能有影响。

- 若终点 `v` 仍有别的紧入边，则 `d(v)` 不变，至多把父边切到编号最小的紧边，
  可能只产生 `PChanged=[v]`。
- 若 `v` 失去全部紧入边，把 `v` 放入受影响集合 `A`，并沿“旧紧出边”传播：
  一个后继若**所有**紧入边都来自 `A` 内，则它也失去全部紧边，加入 `A`；
  若它仍有来自 `A` 外节点的紧入边，则它是**边界节点**，距离不变、不继续
  传播，但父边可能切换（计入 `PChanged`）。注意这不是“父边树整棵子树”：
  有独立紧入边的后继不会被连带。
- 对 `A` 以所有 `A` 外可达节点为多源做一次局部 Dijkstra 重算；重算后距离
  变大或变不可达的节点进入 `DChanged`，距离相等而父边变化的进入 `PChanged`。
- 原本非紧边的增权与删除不改变任何距离与父边。

### examined：不是整图重算的证据

`UpdateResult.Examined` 是本次更新实际读取过的边条数（非导出计数器在每次
更新中归零）。设

- `S = DChanged ∪ PChanged`，
- `F` 为与 `S` 中任意节点关联的全部入边与出边，
- `H` 为 `F` 中各边“另一端节点”的入边总数，

则在 `S` 非空时实现保证

```
examined ≤ 4·(|F| + |H|) + 8
```

界只依赖受影响区域的邻接规模，与图的总边数无关。`S` 为空时，判定一条紧边
是否存在替代紧边仍需读取其终点的入边表，这属于常数级局部检查。

## 查询

```go
svc.Dist(v)    // (distance int64, reachable bool, err)
svc.Parent(v)  // (edgeID int, exists bool, err)
svc.Path(v)    // 从源到 v 的父边编号序列；不可达返回 ErrUnreachable
svc.Version()  // 当前版本号
svc.DistAt(v, ver) // 历史版本 ver 下的距离与可达性
```

## 版本历史

- 版本 `0` 是构造后的空图（仅 `d(s)=0`）。
- 每次被接受的更新写入一个新版本，只保留最近 `K` 个更新版本的距离快照
  （环形缓冲）。
- `DistAt(v, ver)`：
  - `ver > 当前版本` → `ErrVersionFuture`（版本尚未产生）；
  - `ver < 最旧保留版本` → `ErrVersionStale`（历史已过期）；
  - 否则返回该版本下 `v` 的距离。版本 `0` 仅在它仍处于保留窗口
    （即 `当前版本 < K`）时可查，更早则报 `ErrVersionStale`。

## 错误与优先级

错误以哨兵值暴露，可用 `errors.Is` 区分：

- `ErrInvalidArgument`：构造参数越界、节点越界、`u==v`、权重越界、
  `DistAt` 节点越界。
- `ErrEdgeNotFound`：`SetWeight / RemoveEdge` 的编号从未分配或已删除。
- `ErrCapacityFull`：`AddEdge` 时存活边数已达 `Emax`。
- `ErrVersionStale` / `ErrVersionFuture`：历史版本过期 / 版本尚未产生。
- `ErrUnreachable`：对不可达节点调用 `Path`。

优先级：

- 更新操作按 `参数非法 → 边不存在 → 容量已满` 只报第一个
  （容量检查发生在获取写锁后、参数检查之后）。
- `DistAt` 按 `节点非法 → 版本尚未产生 → 历史已过期`。

被拒绝的操作不改变图、版本号、边编号分配与历史。

## 并发语义

服务内部用 `sync.RWMutex` 保护：更新串行化（持写锁完成“改图 + 局部重算 +
落版本快照”全过程），查询持读锁，因此查询要么看到更新前的完整状态，要么
看到更新后的完整状态，绝不会读到只完成一半的更新。所有更新与查询可被
并发调用，整体等价于某个串行顺序。

## 本地验证

```bash
# 全量测试
go test ./...

# 竞态检测（含并发更新/查询压力测试）
go test -race ./sps

# 详细日志：打印每组随机序列的输入、逐步输出与判定依据
go test ./sps -run TestRandomAgainstNaive -v

# examined 局部性（2000 vs 100000 边，末端只波及 3 个节点）
go test ./sps -run TestExaminedLocality -v
```

测试构成：

- `service_test.go`：题目给定 8 步完整示例、错误优先级、拒绝不耗编号、
  同权重改权仍升版本。
- `scenario_test.go`：紧边增权有替代（仅父边变）、唯一紧边连带后继、
  后继另有未受影响紧边而不连带、父边按编号切换规则、降权恰好变紧、
  降权传播、可达性翻转、平行边、`Path`、历史窗口边界。
- `random_test.go`：**2000 组随机更新序列**，每组逐步与“每次更新后整图
  Dijkstra 重算距离与父边”的朴素实现（`naive_test.go`）对照，逐节点核对
  距离、父边、路径自洽性、`DChanged/PChanged` 报告以及 `DistAt` 全部保留
  版本；日志中打印输入参数、每步操作、输出报告和判定依据。
- `locality_test.go`：`examined` 上界核对、长链局部性（不同图规模相差
  ≤ 8），以及并发 + race 测试。
