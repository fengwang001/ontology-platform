# 多成员镜像块卷：成员故障、世代仲裁与部分重同步

包 `mirror` 实现一个固定成员数（2–4）、固定逻辑块数的镜像块卷，
覆盖写入、读取、成员故障、脏区记录、按世代仲裁的部分/全量重同步，
以及全部成员掉线后的权威成员选取。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `errors.go` | 六类可区分错误及其上报优先级（声明顺序即优先级） |
| `types.go` | 成员状态枚举、卷/成员快照（可复现状态的外化形式） |
| `dirtylog.go` | 单成员脏区记录：哈希集合 + 上限 + 超限丢弃 |
| `member.go` | 成员个体：数据、故障世代、状态迁移、重同步计划 |
| `volume.go` | 卷核心：写入、读取、报告故障、快照、逐块操作计数 |
| `resync.go` | 重新加入（世代仲裁/权威选取）与批量推进 |

协作关系：`Volume` 持有若干 `member`；非在线成员持有一份 `dirtyLog`；
重同步中的成员额外持有升序 `plan` + `pending` 集合。所有公开方法经
`Volume.mu` 串行化。

## 关键取舍

- **单互斥锁串行化**。所有操作在锁内完成，天然满足"并发调用等价于
  某个串行顺序"。成员数最多 4、写路径不碰块级全局结构，锁内工作极小，
  不需要更复杂的读写锁或无锁方案。
- **脏区用哈希集合而非位图**。登记 O(1)、计数 O(1)，写入开销只随成员数
  增长；部分重同步选块时对脏区排序，开销 O(d log d) 只随脏区块数 d
  增长。位图方案登记也是 O(1)，但选块需扫描全部块，违反复杂度约束。
- **重同步计划 = 升序切片 + 游标 + pending 集合**。推进时从游标处顺序
  取块、跳过已被写入清除的项，单次推进 O(批上限)；重同步期间的写入
  直接落盘并 O(1) 清除 pending 标记，不改动 plan 结构。
- **重同步中成员的待同步集合即其脏区记录**。重同步中再次故障时原样
  保留（含超限标记），重新加入时按新故障世代继续做部分重同步，
  避免重复复制已同步的块。
- **全部故障恢复时把"其余成员一律全量"实现为强制置位 dropped**。
  权威成员重新加入时，把其余故障成员的脏区记录标记为已丢弃，
  复用既有"标签不等或记录无效 → 全量"的判定路径，不引入额外状态机分支。
- **拒绝的写入先预检后应用**。全部在线成员都写失败时直接报错返回，
  不做任何变更，从结构上保证"拒绝不留痕"（有测试做快照级比对）。
- **读只服务在线成员**。重同步中成员永不服务读，因此读不到任何
  尚未同步完成的陈旧值；在线成员数据一致性由协议不变式保证
  （存在重同步中成员时必有在线成员：最后一个在线成员故障会级联
  故障所有重同步中成员），并有随机测试逐操作断言。

## 被放弃的方案

- **按块位图脏区**：选块需 O(总块数) 扫描，违反"部分重同步选块只随
  脏区块数增长"的约束，放弃。
- **每次故障逐个成员递增世代**：规格要求一次写入中多成员同时故障
  世代只加一，故改为"先收集本次新故障、最后统一加一"。
- **重同步中成员重新加入时重启计划**：规格只明确"已在线重新加入报
  状态不符"。本实现对重同步中成员的重新加入同样报状态不符
  （重同步应通过推进接口完成），语义更简单且不与进行中的计划冲突。
- **读写锁分离**：读多写少场景下看似更优，但读路径本就只有一次
  数组索引，引入 RWMutex 只会增加复杂度，放弃。

## 复杂度与可验证性

- 写入：逐块操作 = 每个目标成员一次写，`BlockOps` 计数器断言
  一次写入恰为成员数次（`TestWriteCostIndependentOfBlocks`，
  块数 1e3 与 1e6 对比）；基准 `BenchmarkWriteBlocksScaling`
  显示 1e3/1e5/1e6 块下均为约 40 ns/op。
- 部分重同步：选块为脏区排序 O(d log d)，复制为 d 次逐块拷贝；
  `TestPartialResyncCostIndependentOfBlocks` 在块数 1e3 与 1e6 下
  断言计数器增量恰为脏区块数；基准 `BenchmarkPartialResyncDirtyScaling`
  在固定 1e6 块下显示耗时随脏区大小（10/100/1000）增长。

## 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin
go test ./mirror/                 # 规格单元测试 + 模型对照 + 并发
go test -race -v ./mirror/        # 竞态检测；随机对照逐条打印输入/输出/判定依据
go test ./mirror/ -bench . -benchtime 10000x   # 复杂度基准
gofmt -l . && go vet ./...
```

随机对照测试（`TestModelRandomOps`）用 4 个种子各执行 1500 条随机操作
（写/读/报告故障/重新加入/推进，含偶发非法参数），每条操作同时作用于
被测实现与独立编写的朴素逐块模型，逐条比对错误类别、返回值与完整快照
（世代、各成员状态、故障世代、待同步块集合、全部块数据），并用 `-v`
打印每条操作的输入、输出与判定依据。
