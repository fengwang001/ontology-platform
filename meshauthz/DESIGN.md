# 服务网格工作负载授权策略评估器 — 设计说明

`meshauthz` 包实现一个进程内的服务网格工作负载授权策略评估器：
整份策略集原子发布、按版本评估、拒绝优先、无允许策略默认放行，
并为每次评估产出可审计的依据（命中的策略与动作、策略集版本）。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `types.go` | 请求、策略、规则、决定与依据的数据模型 |
| `errors.go` | 可区分、有优先级的错误类别（`invalid_argument` > `invalid_policy_set`） |
| `pattern.go` | 精确 / 前缀 `a*` / 后缀 `*a` / 全匹配 `*` 四种元素形式及其集合语义 |
| `validate.go` | 请求字段合法性校验；整份策略集校验（按提交次序报告第一个问题） |
| `match.go` | 编译后的规则、来源、操作、请求头条件对请求的匹配 |
| `snapshot.go` | 不可变的编译后快照，按命名空间 + 动作预分桶索引 |
| `store.go` | 版本化原子存储与决定算法（评估的唯一入口） |

依赖方向单向：`store → snapshot/match → validate/pattern → types/errors`，
便于逐层独立测试。

## 关键语义决策

- **适用范围**：策略命名空间等于请求目标命名空间或等于根命名空间，
  且选择器被目标标签满足（所列键值全部相等；空选择器匹配命名空间内全部
  工作负载）。目标命名空间就是根命名空间时只计一次，避免依据重复。
- **集合语义**：正集合为空则不限，非空则为或；否定集合非空时命中任一
  元素即否决；否定先于正集合判定。身份、命名空间、路径支持四种星号
  形式；方法精确比较且区分大小写（方法中的 `*` 只是普通字符）；端口为
  整数集合。
- **请求头条件**：头名不区分大小写（请求归一化时统一转小写），同名
  多值。头缺失时，要求值集合的条件不满足，仅有否定值集合的条件满足；
  值集合也为空的条件对缺失的头同样视为满足（空正集合"不限"的一致推论）。
- **空规则**（三部分全缺省）匹配全部请求；**空规则列表**的策略不匹配
  任何请求；策略命中当且仅当至少一条规则被满足。
- **决定次序**：适用拒绝策略任一命中 → 拒绝（依据列出全部命中的拒绝
  策略）；无适用允许策略 → 放行（依据决定部分为空）；有适用允许策略
  且任一命中 → 放行（列出全部命中的允许策略）；全部不命中 → 拒绝
  （决定部分为空）。审计策略不影响决定，命中者全部列入依据，按名称
  升序、同名按命名空间升序；决定部分同样排序，保证整份依据精确可复现。
- **请求合法性**（`invalid_argument`）：源/目标命名空间、方法、路径
  非空，端口 ∈ [1, 65535]，头名非空。源身份可为空（未认证）。评估先
  校验请求再触碰任何策略状态，因此参数非法永远优先于策略集问题。
- **策略集合法性**（`invalid_policy_set`）：名称、命名空间非空；名称
  在同一命名空间内唯一；动作合法；选择器键与条件头名非空；各集合元素
  非空；星号只能出现在开头或结尾、不得两端同时出现、单独一个 `*` 合法；
  端口 ∈ [1, 65535]。按提交次序报告第一个问题（`PolicyIndex`）。

## 原子发布与并发

策略集被编译为**不可变快照**，通过 `atomic.Pointer` 单次指针交换发布：

- `ReplaceAll` 在互斥锁下先完整校验 + 编译候选集，任何问题时整次替换
  不生效、版本不变；成功则版本单调加一并交换指针。
- `Evaluate` 只做一次原子加载作为线性化点，之后整个评估固定在某一
  完整版本上，绝不观察到替换进行到一半的状态。
- 任意并发调用因此等价于某个串行顺序；并发测试用"版本 → 提交集"注册表
  逐次核对每次评估的决定与朴素模型在该版本上的结果完全一致（`-race`
  通过）。

## 性能设计

快照内按 `命名空间 → {deny, allow, audit}` 预分桶。评估只访问目标
命名空间桶与根命名空间桶，与请求无关的命名空间中的策略数量完全不
影响评估开销；动作预分桶使"拒绝优先"不必扫描允许/审计策略。选择器
判定（纯 map 查找）先于规则匹配，进一步剪枝。

可验证性：`Store.ExaminedPolicies()` 暴露评估实际检查过的策略数，
`TestEvaluationCostIndependentOfIrrelevantPolicies` 断言无关策略从 0
增长到 10000 时该计数严格不变；
`BenchmarkEvaluateScalesFlat` 展示延迟平坦（本地实测 0/1k/10k 无关
策略时均约 5–7µs/op）。

## 被放弃的方案

- **RWMutex 保护可变 map**：读多写少下可行，但写临界区内编译大策略集
  会阻塞所有评估；不可变快照 + 原子指针使评估零锁、线性化点显而易见。
- **按标签选择器建倒排索引**：标签基数不可控，索引维护复杂；命名空间
  分桶已满足"与无关策略数量无关"的复杂度要求，桶内线性扫描的常数很小。
- **逐策略独立版本**：违背"整份策略集原子发布"的语义，版本向量也难以
  审计；整集单版本更简单且满足要求。
- **评估时惰性编译**：会把策略内容错误带入评估路径，违背"评估不得因
  策略内容失败"；所有校验与编译都在 `ReplaceAll` 时完成。
- **校验与编译合一**：`validatePolicySet` 与 `buildSnapshot` 目前都会
  编译一次（先校验后构建，重复一遍编译）。合一可省一次编译，但会让
  "纯校验"与"构建"耦合；编译开销只在替换时发生，评估路径不受影响，
  故保留清晰的职责划分。

## 本地验证方法

```bash
# 全部单元 / 差分 / 并发测试（竞态检测 + 详细日志，含每次操作的
# 输入、实际输出与判定依据）
go test -race -v ./meshauthz/

# 仅差分测试（300 轮随机策略集 × 10 随机请求，对照独立朴素模型；
# 种子固定为 20261007，日志首行打印，可复现）
go test -run TestDifferentialAgainstNaiveModel -v ./meshauthz/

# 性能证明：检查策略计数恒定 + 延迟平坦
go test -run TestEvaluationCostIndependentOfIrrelevantPolicies -v ./meshauthz/
go test -run=NONE -bench=. -benchtime=2000x ./meshauthz/

# 静态检查
gofmt -l . && go vet ./...
```
