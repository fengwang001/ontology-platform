# 临床检验标本系统设计

## 模块划分

- `system.go`：对外 API、错误码、输入校验和主工作流。
- `state.go`：申请项、标本管、目录版本数据和患者未终结项目的侵入式链表。
- `state_ops.go`：活性项目索引与稳定标识生成。
- `tube_ops.go`：管内项目枚举和拒收原因判定。
- `validation.go`：非空、正时长、溶血范围和全局时钟检查。

所有公开方法通过同一个 `sync.Mutex` 串行化。并发调用可按锁竞争的先后映射为某个串行历史；被拒绝的方法在任何状态写入前返回，因此不更新时钟、计数器、项目或管状态。

## 关键取舍

1. 项目在申请创建时复制目录要求。后续目录变更只影响新申请，已提交项目继续使用申请时快照。
2. 每个申请项保存申请号和优先级。拒收不创建新项目，因此重采天然继承原申请与优先级；它只更新原申请项的状态、拒收次数和最近待采集时刻。
3. 标本管保存自己的 `itemIDs`。签收和送出只遍历该列表，不扫描患者历史、全局项目或目录。
4. 患者未终结项目使用侵入式双向链表维护，终结或取消时 O(1) 摘除；查询只遍历未终结节点。
5. 项目拒收原因固定按“超时、冷链不符、溶血超限”计算第一个命中项，逐项独立更新，同管部分合格不会互相阻断。
6. 第三次拒收直接进入“终止”并摘除活性索引；因此累计拒收次数不可能继续增加，终止项目也不会回到“待采集”。
7. 取消已采集项目时同步清空管引用；管内无“已采集待签收”项目后立即标记作废。
8. 送出登记允许重复，最后一次写入覆盖前值；未登记运送方式不能签收。

## 被放弃的方案

- 拒绝时新增“重采申请单”：会改变申请号和优先级归属，也使跨申请合并的历史更难复现；改为原申请项状态回退。
- 只保存目录版本号、签收时再查版本表：虽然节省少量内存，但要求永久保留版本并增加跨对象引用；本系统选择在项目上复制不可变小快照。
- 查询时扫描全局项目后按患者过滤：历史越大越慢，不满足查询复杂度；改为患者活性链表。
- 签收时从患者维度查找项目：会把患者历史项目数带入复杂度；改为管内显式项目列表。
- 使用全局读写锁：查询会改变并读取全局时钟，且需求是强线性化；单把互斥锁更简单、确定性更强。

## 错误次序

每个操作先做参数校验，再进入临界区检查时钟，随后按对象存在性和该操作的业务约束报错。业务错误中按规格保持“重复申请、管类别不一致、状态不符、时间不合理”的优先次序。任何失败路径都发生在状态写入之前。

## 复杂度

设管内项目数为 `t`、某患者未终结项目数为 `a`：

- 签收：`O(t)` 时间、`O(t)` 返回结果临时空间；不读取目录，不扫描历史。
- 查询：`O(a log a)`（当前测试排序比较；生产遍历为 `O(a)`，输出保持链表插入顺序），不扫描历史。
- 申请：项目数最多 10，目录快照为常数级；活性查重随患者未终结项目数增长。
- 取消：`O(t)`，用于确认所在管是否还有可签收项目。

两档本地对照（历史项目和目录项目均为 10 对 1000，目标管均 1 项、查询患者均 0 个活性项）：

```text
BenchmarkSignScalesWithTubeItems/10-20       1000  374.0 ns/op
BenchmarkSignScalesWithTubeItems/1000-20     1000  970.1 ns/op
BenchmarkQueryScalesWithActiveItems/10-20    1000  137.1 ns/op
BenchmarkQueryScalesWithActiveItems/1000-20  1000  158.8 ns/op
```

耗时随机器波动，但两档管内项目数和活性项目数不变，增长不随历史或目录线性变化。

## 本地验证

```bash
GOCACHE=/tmp/go-cache go test ./...
GOCACHE=/tmp/go-cache go test -race ./...
GOCACHE=/tmp/go-cache go test -run '^$' -bench 'Benchmark(Sign|Query)' -benchtime=1000x ./specimen
```

随机对照测试包含 1500 组确定性序列，测试内朴素模型使用全量 map 扫描独立实现。每一步的输入、正式系统输出、朴素模型输出和拒收判定均写入 `t.TempDir()/random-sequences.log`；失败信息会打印该日志路径。
