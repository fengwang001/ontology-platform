# observedset：观察删除集合（OR-Set / Add-Wins Set）CRDT

`observedset` 实现了一个**无冲突复制数据类型**：多个副本各自独立增删元素，
通过两两合并同步状态。对同一元素的并发增删遵循**后加入者胜出（add-wins）**
语义，最终各副本收敛一致，结果只由状态决定、可复现。

## 数据模型

每个副本维护两部分状态：

- **添加记录** `adds: Tag -> element`：每次成功添加都产生一个全局唯一标签；
- **墓碑** `tombstones: set<Tag>`：记录已被“观察到删除”的标签。

标签 `Tag{ReplicaID, Counter}` 由“副本编号 + 该副本内单调递增计数（从 1 开始）”
组成。不同副本编号空间不相交；计数只在添加成功后才递增，因此同一标签全局至多
生成一次。

## 存活判定与集合成员

标签 `t` 对元素 `e` **存活**，当且仅当 `adds[t] == e` 且 `t ∉ tombstones`。

元素 `e` 在集合中，当且仅当它至少存在一个存活标签（`Explain(e)` 返回全部存活
标签，`Elements()` 返回去重、字典序排列的存活元素快照）。

## 添加规则

- `Add(e)`：分配下一个标签 `{本副本id, ++counter}`，写入 `adds`。
  空串元素、添加记录数超限都会被拒绝；**所有校验在计数递增之前完成**，
  被拒不消耗计数、不写入任何记录（失败不留痕）。
- 删除后重新添加会得到新标签，新标签不在墓碑中，因此重新生效。

## 删除规则

- `Remove(e)`：把 `e` **当前全部存活标签**加入墓碑——按标签删除，而不是按
  元素名删除。其它副本随后新增的标签不在其中，因此并发场景下**后加入者胜出**。
- 元素当前不存活（从未添加或已被删除且未重新加入）时整体拒绝
  （`ErrElementNotFound`），墓碑保持不变。

## 合并规则

- `MergeInto(dst, src)`：把 `src` 的添加记录与墓碑分别取**并集**写入 `dst`，
  **只修改目标副本**，来源副本不变；`dst == src` 是合法空操作（幂等）。
- 合并满足交换律与结合律，重复传播消息（包括墓碑先于对应添加记录到达）安全。
- 实现先在来源副本上取不可变快照、再锁目标副本，因此**互逆方向的合并可以
  同时进行，不会死锁**；增删、合并、判存在、查询与自检均可并发调用。

## 边界与错误类别

错误均为哨兵值，用 `errors.Is` 判别，五类互不相同：

| 错误 | 触发条件 |
| --- | --- |
| `ErrInvalidReplicaID` | `NewReplica` 编号为负数 |
| `ErrEmptyElement` | `Add`/`Remove` 元素名为空串 |
| `ErrElementNotFound` | `Remove` 一个当前不存活的元素 |
| `ErrTooManyAdds` | 本副本添加记录数达到上限（默认 `DefaultAddLimit = 2^20`，可用 `WithAddLimit` 配置） |
| `ErrNilReplica` | 操作或合并涉及 `nil` 副本 |

另有内部错误 `ErrInvariantBroken`（自检失败）与 `ErrTagConflict`
（同一唯一标签在双方对应不同元素，正常使用不会发生）。

任何一次被拒的调用都**整体不生效**：不新增添加记录、不新增墓碑、标签计数
不跳号。`Check()` 校验本副本标签计数恰好为 `1..counter` 且无重复、所有添加
记录元素名非空。

## 可观测性

可通过 `WithLogger` 注入 `Logger`，每一步都会打印：输入操作与参数、标签、
当前集合内容、成员身份判定依据（存活标签）与自检结果。

## 本地验证

```bash
# 全量测试（带竞态检测）
go test -race -v ./observedset

# 重复执行以排查调度相关问题
go test -race -count=20 ./observedset

# 全仓库测试 / 构建 / 静态检查
go test -race ./...
go build ./...
go vet ./...
gofmt -l .
```

测试覆盖：增删交错并与朴素 OR-Set 参照逐步对齐、合并的幂等/交换/结合律、
后加入者胜出的并发场景（含可复现性）、互逆方向合并的无死锁并发与最终收敛、
五类非法输入的可区分错误，以及拒绝后标签不跳号、超限不留痕。
