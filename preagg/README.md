# preagg：面向倾斜键的两阶段预聚合器

同一键的连续变更事件先在本地按条数缓冲，攒满阈值后再推给全局累计视图，
从而在键倾斜（热点键）场景下显著减少推送给全局视图的变更条数。

## 核心规则

### 本地缓冲（阶段一）

- 每个非热键在本地缓冲中维护两项状态：**待推送增量之和** `delta` 与**已攒条数** `count`。
- 事件到达时累入缓冲，不进入全局视图。
- 当某键已攒条数**达到阈值（含阈值本身）**时，立即把当前待推送增量之和
  作为**一条**变更推送给全局视图，清空该键缓冲，并把该键标记为**热键**。
- 即使多次增量正负抵消后总和为 0，攒满时仍会推送一条 `Delta: 0` 的变更，
  以保证推送记录从空重放能精确重建视图。

### 热键（阶段二）

- 同一批次内某键出现**两次及以上**，该键在该批结束后成为热键；
  批末晋升时先把该键缓冲中的待推送增量冲刷为一条推送，再标记热键，
  因此热键始终不残留缓冲。
- 成为热键后，每到达一条事件都**立即单独推送**给全局视图，不再攒批。

### 冲刷语义

- `FlushKey(key)`：显式冲刷单个键——若该键缓冲中尚有待推送增量，
  则作为一条变更推送并清空缓冲；**无条件**将该键移出热键集合
  （之后该键重新按普通键攒批）。返回值表示是否实际发生了推送。
- `FlushAll()`：全量冲刷——把所有尚有待推送增量的键按**字典序**逐个推送、
  清空缓冲，并把热键集合整体清空。
- 全局视图始终只包含已推送的增量，**不包含**本地尚未推送的缓冲；
  可用 `Pending()` 查看各键待推送增量。

### 非法输入（整体拒绝）

四类非法输入各自对应一个互不相同、可用 `errors.Is` 判定的哨兵错误：

| 场景 | 错误 |
| --- | --- |
| 阈值非正（构造函数） | `ErrInvalidThreshold` |
| 事件键为空 | `ErrEmptyKey` |
| 事件增量为零 | `ErrZeroDelta` |
| 空批次 | `ErrEmptyBatch` |

- 校验在任何状态修改之前完成；任一批内任一条被拒，则**整批不生效**，
  视图、缓冲、热键集合、推送记录均不留下任何痕迹，之后仍可正常使用。

## 不变量与并发

- 所有方法均受 `sync.RWMutex` 保护；`View` / `Pending` / `HotKeys` /
  `PushLog` / `Replay` / `Verify` 返回的都是快照拷贝，可并发只读。
- 不变量一（`Verify` 校验）：任意时刻对每个键
  `view[key] + pending[key] == 截至当前已喂事件的分组求和`。
  因此全量冲刷后，视图与“把所有已喂事件批量分组求和”逐键一致且可复现。
- 不变量二：`PushLog()` 从空视图开始按序重放（`Replay()`）
  必须精确重建当前 `View()`。

## API

```go
p, err := preagg.New(10)                 // 阈值必须为正
err = p.FeedBatch([]preagg.Event{        // 原子喂入一批（先整体校验）
    {Key: "a", Delta: 3},
    {Key: "a", Delta: -1},
})
flushed, err := p.FlushKey("a")          // 单键冲刷并移出热键集合
p.FlushAll()                             // 字典序全量冲刷
p.View()                                 // 全局累计视图快照
p.Pending()                              // 本地待推送增量快照
p.HotKeys()                              // 热键集合快照
p.PushLog()                              // 推送记录（有序）
p.Replay()                               // 从空重放推送记录
err = p.Verify()                         // 自检两条不变量
```

覆盖场景：阈值触发（含阈值本身）、热键批末产生、单键冲刷解除热键后恢复攒批、

推送记录重放重建，以及并发只读逐字段一致与并发读写交错自检。
