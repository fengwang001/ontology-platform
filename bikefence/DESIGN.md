# 电子围栏还车判定与跨围栏调度 — 设计说明

1. 模块：`geometry.go` 整数几何（射线法点在多边形、闭线段相交、包含）；
   `rtree.go` 静态 STR-R 树；`service.go` 错误码/登记/查询/时钟；
   `dispatch.go` 还车、奖励、疏散、认领、完成；`naive.go` 朴素参照模型；两个 `_test.go`。
2. 几何全程整数叉积（`math/big`），边界点逐边闭线段判定视为“在内”，无浮点误差、可精确复现。
3. 归属优先级：奖励区 > 禁停区 > 运营区，否则区外；嵌套只允许内围栏完全落入唯一运营区。
4. 点查询走 STR-R 树，访问节点数=`NodesVisited`，树高 O(log N)；证明方式：2000 围栏下
   实测访问节点远小于围栏数（`TestSpatialIndexSublinear`），对照朴素 O(N) 扫描结果一致。
5. 放弃均匀网格：围栏大小/密度不固定，网格会退化到线性；放弃动态 R 树：围栏登记后不可变，
   静态 STR 打包路径确定、重放完全一致。
6. 围栏车辆数用 `map[fence]int` 直接计数，查询 O(1)，不扫车辆；车只记录单一归属围栏。
7. 并发：单把互斥锁串行全部写操作，结果线性化；相同序列确定性重放（任务 ID 由单调序号生成）。
8. 时钟：只接受不小于上次接受操作的时刻；被拒操作不改时钟、状态、奖励次数。
   每次写操作先惰性 sweep 认领超时（`now-claimedAt >= timeout`，取等即释放，认领记录保留）。
9. 容量：运营区计数不含内部围栏，内围栏独立计数；任何串行位置计数 ≤ 容量，满员并发还车仅一成。
10. 奖励：key=`user|fence|配置时区自然日`，同日同区仅一笔；奖励与区外调度费互斥。
11. 调度：区外还车立即生成搬回默认运营区任务；内/外围栏达 `count*den ≥ cap*num`（取等触发）
    且无未完成疏散任务时，向同运营区内车辆最少、有空位的非禁停围栏派单；并列取最早登记。
12. 完成：上报落点经同一归属判定，区外/禁停区/满员均拒绝且任务保持处理中，车辆不动。
13. 错误按固定次序只报一类：参数非法→时钟回退→围栏/车辆/任务不存在→状态类→业务类（见 ErrorKind）。
14. 可观测：`Config.Log` 逐条打印输入、输出与判定依据；随机对照额外落盘 `bikefence/differential.log`。
15. 被放弃的更细锁/分段计数方案：围栏数量级下单锁更简单且无死锁，串行等价性可直接证明。
16. 本地验证：`go test ./bikefence/ -count=1`；竞态 `go test -race ./bikefence/`；
    `go vet ./bikefence/`；对照日志位于 `bikefence/differential.log`（4000 条随机操作）。
