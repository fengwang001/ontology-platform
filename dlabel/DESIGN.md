# 动态标签属性级权限模块 — 设计说明

包路径：`dlabel`（Go）。本模块为本体平台提供“按需实时计算”的敏感标签、
属性级读/写/可见性授权、可重复读快照与严格的并发一致性。

## 1. 需求到设计的映射

| 需求 | 设计决策 |
|---|---|
| 标签状态永远按需重算，不持久化 | 平台不存储任何标签状态；每次裁决在目标版本的不可变属性视图上由 `engine` 现算 |
| 写后立即生效、提交原子、无中间态 | 单一提交锁 `commitMu` 串行化全部变更；一次写只追加属性版本，版本号（逻辑时钟）+1；读者要么看到旧版本、要么看到新版本，标签与属性同版本计算，物理上不存在“值已改、标签未改”的状态 |
| 可重复读 + 确定且可复现的快照选取 | `Begin` 的线性化点是持提交锁读取当前版本的瞬间，快照固定为该版本号；属性按属性存为不可变追加版本链（二分查找），目录（规则/授权/类型）按版本存不可变快照；读者完全不持提交锁 |
| 多标签冲突的唯一、顺序无关合并 | deny-overrides + fail-closed；合并函数只接收集合聚合量 `{有结论, 有拒绝, 有允许}`，标签按名称排序遍历，结果与求值顺序无关 |
| 不可读属性仍参与判定且不泄露 | 引擎始终读取属性真实取值；普通主体的返回体只含 `Allowed/Value`，不含标签状态、判定依据、被拒属性的值或错误细节；标签状态查询（`TagCarried`）与裁决解释（`Explain`）仅管理员可用 |
| 三类错误固定唯一优先顺序 | ① 规则引用不存在的属性 `ErrMissingAttribute` → ② 标签规则循环 `ErrCyclicRule` → ③ 快照不可用 `ErrSnapshotUnavailable`（另见 §5） |
| 被拒绝操作无副作用 | 授权/规则检查全部在版本号递增之前完成；被拒绝时不推进版本、不追加属性、不改授权，仅写审计日志 |
| 并发写/规则变更/多快照读的串行等价 | 全部提交互斥；版本号即线性化顺序；读路径无锁访问不可变结构。`-race` 下并发测试与逐版本核对验证之 |
| 判定读属性数不随标签总数增长 | 静态计算“与本主体本次裁决相关的标签”，只对其依赖闭包求值；闭包内每个属性只读一次（去重记账）。由公开 API 观测证明（§6） |
| 审计 | 每次调用记录输入、最终输出、错误码、实际读取的属性集合与标签裁决依据（`AuditEntry`），被拒绝调用同样记录 |

## 2. 关键数据结构

- `mvccStore.current atomic.Int64`：单调递增逻辑时钟，即已提交版本号。
- 属性多版本：`实例 -> 属性 -> attrHistory[]`，每条 `{version, value}` 不可变、
  追加写；读路径在属性链上二分，`attrHistory` 自带 `RWMutex`，读多写一互不阻塞。
- 目录多版本：`catalogState`（对象类型、标签规则、授权表）整份不可变快照，
  按版本稀疏存放、永不回收（保证旧快照上的规则错误可复现）。
- 属性版本链按保留窗口 `WithRetainedVersions` 回收；低于
  `current - retain` 的快照读立即报 `ErrSnapshotUnavailable`。
- `Snapshot{version}`：一旦获取，所有读取固定在该版本。

写/规则/授权变更都严格遵循“校验 →（通过后）版本 +1 → 发布不可变数据”的顺序，
因此提交天然原子。

## 3. 规则模型

规则是布尔表达式树（`Expr`）：

- 叶子：属性比较（`=` `≠` `<` `≤` `>` `≥` `IS NULL` `IS NOT NULL`，
  支持 int/float/string/bool/null）、对同对象类型其他标签判定结果的引用、布尔常量；
- 组合：`Not / And / Or`（`And/Or` 短路，但不影响属性读取上限——参与判定的
  属性集合由静态闭包界定）。

规则可引用其他标签；规则图做 DFS 环检测。规则只在提交时变更，已提交的规则图
始终结构合法。

## 4. 合并规则（冲突解决）

对某主体在某属性上，收集所有“当前携带且对该属性给出读结论”的标签授权：

- 没有任何相关结论 → **拒绝**（fail-closed）；
- 至少一条拒绝 → **拒绝**（deny-overrides）；
- 全部允许 → 允许。

可见性同理（授权忽略属性范围，按标签合并）。该策略唯一、确定，且
`TestMergeAllCombinations` 枚举了 4 个标签 × 3 种结论（允许/拒绝/无授权）
的全部 3⁴=81 种组合逐一核对。

## 5. 错误优先顺序

规则类错误在“变更提交时”按以下顺序检查并整体拒绝（同一次 `ReplaceRules`
是原子事务）：

1. 非管理员 / 对象类型不存在；
2. 表达式结构非法（`ErrInvalidRule`）；
3. **引用不存在的属性（特权错误 ①）**；
4. 引用未知标签（`ErrUnknownTag`）；
5. **标签循环依赖（特权错误 ②）**。

读取时先检查 **快照是否可用（特权错误 ③）**，再在快照目录上求值；
由于已提交规则图合法，快照内只会在快照过期/被裁剪时遇到特权错误。
写入在候选后状态上做标签判定与授权，任何错误都使写入整体失效。

## 6. “判定开销只与参与判定的属性数量相关”的可观测证明

不依赖内部实现细节，通过两个公开观测点：

1. `Snapshot.Explain(...)`（管理员）返回 `AttrsRead`：本次裁决实际读取的属性列表；
2. `Platform.EvalCounters() (tagEvals, attrReads)`：跨调用累计的标签求值次数与
   属性读取次数。

实现机制（可独立验证的外部行为）：

- 先静态求“相关标签”：该主体拥有授权行、且授权属性覆盖被请求属性
  （含可见性授权）的标签；
- 再对这些标签按规则引用做静态依赖闭包；
- 只对闭包求值；每个属性在一次裁决中通过唯一入口 `engine.readAttr` 读取且去重。

`TestJudgmentCostIndependentOfTagCount` 在 202 个已登记标签下证明：
判定单个目标标签恒定只读 2 个参与属性，判定一个噪声标签只读 1 个属性，
与已登记标签总数无关。

## 7. 信息非泄露（不可读属性参与判定）

- 判定引擎不做“主体能否看到该属性”的判断，一律使用真实取值；
- 主体只能通过其被授权的属性的 `Allowed/Value` 观察世界；
  标签携带状态本身是一种派生信息，故 `TagCarried`、`Explain`、
  审计中的 `Basis/AttrsRead` 属于管理员/审计特权通道，不对普通主体开放；
- 拒绝时返回固定错误码（`ErrPermissionDenied`/`ErrNotVisible`），
  错误消息不含任何取值内容；被拒属性不触发取值返回。

设计上承认的残余信道：对“该主体被授权的属性”的允许/拒绝结论本身，
可能泄露驱动标签的隐藏属性的 1 比特信息——这是“按标签授权”语义的固有产物
（隐藏属性通过策略设计影响可见性是需求本身）。除该 1 比特策略结论外，
不泄露取值的任何其他信息。

## 8. 关键取舍与被放弃的方案

- **放弃持久化/缓存标签状态。** 缓存需要失效协议，且无法避免滞后窗口；
  多版本现算天然与快照一致，零失效成本。
- **放弃单一全局大锁包裹读路径。** 朴素参照实现（`naive_test.go`）正是这种方案，
  仅用于语义对照；生产实现用不可变版本链/目录快照，使读完全不阻塞提交。
- **选择 deny-overrides 而非 allow-overrides/多数票。** 安全场景默认从严；
  多数票语义含混且要求奇数标签，allow-overrides 会被任一宽松标签架空。
- **选择显式保留窗口而非无限保留。** 属性版本链会被回收；目录历史不回收
  （体量小且保证旧快照规则可复现）。快照过期是显式、确定性的错误。
- **放弃把标签状态暴露给普通主体。** 标签状态由不可读属性可推出，
  暴露等同于泄露属性；仅管理员通道可见。
- **授权按 (主体,标签) 覆盖式写入，与实例无关。** 授权是目录数据，
  同样版本化，旧快照看到旧授权。
- **跨类型标签引用不支持。** 标签是对象类型内的判定，简化环检测与闭包计算。

## 9. 本地验证方法

```bash
# 全量测试（含朴素参照差分、竞态检测）
go test -race ./...

# 仅差分测试（40 个随机种子 × 400 个随机操作）
go test -run TestRandomDifferential -v ./dlabel

# 复杂度可观测证明 / 冲突全组合
go test -run 'TestJudgmentCostIndependentOfTagCount|TestMergeAllCombinations' -v ./dlabel

# 并发：可重复读稳定性 + 串行等价性
go test -race -run 'TestRepeatableReadStableUnderConcurrentWrites|TestConcurrentOpsLinearizable' -v ./dlabel

# 覆盖率
go test -cover ./dlabel

go vet ./...
gofmt -l .
```

说明：构建若遇到默认 GOCACHE 只读，可 `export GOCACHE=/tmp/gocache`。

## 10. 文件索引

- `value.go`：可空标量值与比较语义；
- `rule.go`：规则表达式、构造器、静态校验、求值；
- `grant.go`：授权与 deny-overrides 合并；
- `store.go`：MVCC 版本链、目录快照、提交锁、版本回收；
- `engine.go`：标签闭包求值、相关标签裁剪、属性读取记账、授权裁决；
- `platform.go`：平台 API、写入原子提交、快照生命周期；
- `reads.go`：快照读取、管理员标签查询与 Explain；
- `admin.go`：规则/授权变更、环检测、错误优先级；
- `audit.go`：审计日志与记录格式；
- 测试：`dlabel_test.go`（翻转/不可见属性/无副作用等）、
  `concurrency_test.go`（并发与快照稳定性）、`complexity_test.go`（开销证明与冲突全组合）、
  `naive_test.go` + `diff_test.go`（朴素参照与随机差分）、`audit_test.go`。
