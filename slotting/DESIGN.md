# 货位分配系统设计说明

## 1. 模块划分

| 文件 | 职责 |
| --- | --- |
| `types.go` | 领域类型：`LocationID`（通道/层/位，字典序与相邻判定）、`Location`、`Pallet`、`LocationView`、品类与状态枚举。 |
| `errors.go` | 结构化拒绝原因 `Reason` 与 `AllocationError`，调用方用 `Reason()` 区分错误，不靠字符串匹配。 |
| `ledger.go` | 状态台账：货位静态属性、托盘档案、在位关系 `where`、商品→货位集合、深拷贝 `clone`。 |
| `index.go` | 空货位 sqrt 分块索引；块内按品类维护 skyline，且 skyline 只含“当前相邻安全”的空货位。 |
| `check.go` | 纯函数约束判定：品类、净高、承重、同货位混放（同商品/混批）、相邻易燃-食品隔离、容量，按优先级短路。 |
| `ops.go` | 锁内操作：参数校验、自动上架、指定上架、移库、取出、冻结、批量。 |
| `system.go` | 线程安全外观：`sync.RWMutex` 加锁、日志、只读快照查询。 |
| `logger.go` | 输入/输出/判定依据日志（`io.Writer` 注入，nil 静默）。 |

协作关系：`system` 只做加锁与日志，业务在 `ops`；`ops` 通过 `check` 判定、通过 `ledger` 落账、通过 `index` 找空位；
`ledger` 的每次在位变化都通知 `index.changed` 维护动态 skyline。模块单向依赖，无环。

## 2. 关键取舍

### 2.1 并发模型：单把读写锁 + 快照读

- 所有操作均为内存级微秒运算，单把 `sync.RWMutex` 即可线性化：写操作互斥，读操作持读锁。
- 查询在锁内把在位托盘列表拷贝成 `LocationView` 返回，因此调用方拿到的是某个已完成操作之后的一致快照。
- 移库在**深拷贝**上完成“释放原位 → 检查目标 → 放入目标”，提交时整体替换 `st`；失败丢弃拷贝。
  任何时刻外部状态要么全旧要么全新，同一托盘不可能同时占用或脱离两个货位。
- **被放弃的方案**：分段锁/无锁 MVCC。会给“相邻隔离”这种跨行不变量带来跨锁一致性复杂度，
  在本负载下没有吞吐收益，违背“避免过度设计”。

### 2.2 自动上架的两级选择

1. **同类候选**：遍历该商品当前在位货位集合（按字典序），只考虑仍有剩余容量者，逐个做完整约束检查，取首个通过者。
   考察数量只随“该商品的在位货位数”增长，与无关商品的托盘数无关。
2. **空位候选**：由分块索引给出字典序最小可行空货位。

### 2.3 空位索引：sqrt 分块 + 每品类 skyline（含相邻安全）

- 全部空货位按字典序分成大小约 `B=ceil(sqrt(N))` 的块（N<64 时 B=4，便于小规模稳定测试）。
- 每个块对每个允许品类维护一条 skyline：把块内货位点 `(净高 h, 承重 w)` 按 h 降序扫描，
  仅保留“承重创新高”的点，反转后得到 **h 升序、w 降序**的序列。
  查询 `(H,W)` 时二分定位第一个 `h≥H` 的点——它就是后缀（所有 h≥H 的点）中承重最大者，
  一次比较即可判定块内是否存在可行货位。
- **动态相邻隔离**：skyline 只纳入“当前相邻安全”的空货位（邻居没有冲突品类的在位托盘）。
  一次放入/取出/移库只改变某货位的在位集合，受影响的空货位只有它本身和位序号 ±1 的两个邻居，
  因此只需用 O(B) 重建至多 3 个块（`changed`），代价与总货位数无关。
  冻结货位不在索引中，但其在位托盘仍通过该机制让相邻空货位被排除。
- 查询顺序扫块（每块 O(1) 判定 + 二分），命中块后至多逐位确认 B 个货位，
  **考察货位数 O(sqrt(N))**，且不含与目标商品无关的在位货位。
- **被放弃的方案**：
  - 全量线性扫描：实现最简单，但考察数随 N 线性增长，不满足要求。
  - 按品类的平衡树 + 静态 skyline：无法表达相邻隔离这种动态约束，命中后可能连续被相邻规则拒绝，最坏退化 O(N)。
  - 段树 + 懒重建：最坏 O(log²N) 但实现复杂、重建时状态机容易出错；sqrt 分块的常数小、
    更新与查询边界都很好证明，契合“仓库货位静态、上下架频繁”的场景。

### 2.4 全有或全无

- 批量先做参数校验（空列表、空编号、批内编号重复，重复报**最小**失败下标），
  再深拷贝状态，在拷贝上逐托盘按序自动上架（每个托盘看到前面托盘的结果）；
  任一失败恢复旧状态，返回最小失败下标与可区分原因。

### 2.5 确定性

- 字典序完全由 `LocationID.Less` 定义；map 只做点查，凡需遍历（同类候选、查询返回集合）一律先排序。
- 相同操作序列在相同输入下产生完全相同分配；`TestReplayDeterminism` 固化该性质。

### 2.6 冻结语义

- 冻结立即把货位移出空位索引（若为空），此后不可自动/指定上架、不可作为移库目标；
  已有托盘保留，取出与移出不受限；冻结期间若腾空也不会重新进入索引。
- 解冻后：空货位重新进入索引；有货货位本来就只在同类候选里，无需额外处理。

## 3. 拒绝原因优先级

总体：参数非法 → 对象不存在（货位/托盘）→ 重复 → 各类约束 → 无可用货位。

指定上架 / 移库目标检查按题面顺序短路：
货位不存在 → 货位冻结 → 品类不允许 → 净高不足 → 承重不足 → 混放冲突 → 相邻隔离冲突 → 容量已满。
移库另在目标检查之前处理：托盘不存在、目标即原位。

边界采用题面语义：托盘重量/净高**恰等于**上限允许（`>` 才拒绝）。

## 4. 始终成立的不变量

- 任一货位在位托盘数 ≤ 容量、重量之和 ≤ 承重上限。
- 同货位托盘同商品；不允许混批时同批次。
- 易燃与食品托盘从不在相邻货位同时出现（放入方双向检查，移动在“已离开原位”的快照上检查）。
- 冻结货位不会新增托盘；`where` 与货位托盘列表互为一致账目。

## 5. 本地验证方法

```bash
go test ./...                     # 全量（含朴素模型随机差分，8 个种子×800 步）
go test -race ./...               # 竞态检测
go test -cover ./...              # 当前覆盖率约 92%
go test -run TestExaminedSublinear -v ./slotting
go run ./cmd/demo                 # 打印输入/输出/判定依据日志
```

`TestExaminedSublinear` 输出考察货位数（N=100→约 20，N=400→约 40，≈√N；
预置 399 个无关在位托盘后目标商品候选为空，考察数不随之增长），
是“考察货位数不随货位总数线性、不随无关在位托盘数增长”的可验证证据。

## 6. 测试清单

- 承重/净高恰等与超一、拒绝不改状态；容量 2 合并存放；不允许混批。
- 相邻隔离双向；冻结货位对隔离的持续约束与移出/解冻恢复。
- 移库失败两侧不变、目标即原位、成功路径。
- 批量失败不留痕、批内重复参数非法、成功批次。
- 拒绝原因优先级（含相邻先于容量、参数非法最先）。
- 重复注册/上架、托盘不存在、重放确定性、并发不变量与快照一致性。
- 与独立朴素模型（无任何索引、全量扫描）对照的大规模随机操作序列差分。
