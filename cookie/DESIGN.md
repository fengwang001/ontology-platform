# Cookie 存储内核设计说明

## 模块划分（7 个实现文件 + 2 个测试文件）
- `entry.go` 条目、SameSite 枚举、唯一键、路径整段匹配、分区键相等、过期判定
- `errors.go` 五类可区分错误（sentinel error，可用 errors.Is 判定）
- `store.go` 配置、统计、时钟、写入校验（固定拒绝次序）与落库
- `heap.go` 三类惰性堆：站点内 LRU 堆、过期最小堆、站点计数堆
- `evict.go` 索引维护、过期清扫、站点/全局容量淘汰
- `attach.go` 请求附带判定、同站规则、脚本读取接口
- `clear.go` 按站点 / 分区键 / 创建时刻区间（左闭右开）清除

## 关键取舍
- 单互斥锁串行化全部操作，天然满足"并发等价于某个串行顺序"；
  锁内无阻塞调用，临界区短。
- 按站点分桶索引：附带判定只扫描目标站点，开销与无关条目总数无关
  （由 `attachScans` 探针 + 基准双向验证）。
- 淘汰选择用惰性堆：条目被访问/覆盖时 gen 递增并压入新堆项，
  旧堆项弹出时校验 (seq, gen) 即弃，摊还 O(log n)，不随站点条目数线性增长；
  seq 为全局递增序号，防止同键条目删除重建后前代堆项被误判有效。
- 过期不主动清扫：严格按"被观察到才移除"，读取路径与容量路径各自
  清扫并计过期淘汰，保证三类删除计数守恒式恒成立。
- 覆盖同键条目保留创建时刻与序号，仅刷新其余字段与最近访问时刻；
  过期未清除的同键条目被覆盖视为复活，不触发淘汰。
- 过期时刻不晚于当前时刻的写入视为删除同键条目，计显式删除而非拒绝。
- 完全并列（最近访问与创建时刻均相同）按序号兜底，保证淘汰次序确定。
- Attach/ScriptRead 返回条目拷贝而非指针，调用方在锁外读取无竞态。

## 被放弃的方案
- container/list 经典 LRU：覆盖与按条件删除时节点定位繁琐，惰性堆更简单。
- 后台定时器清扫过期：违背"观察到才移除"语义，且引入额外并发。
- 外部平衡树依赖：标准库 container/heap 已足够，避免引入依赖。

## 本地验证
- `go test ./cookie/ -v` 单元 + 4000 步随机差分（日志含输入/输出/判定依据）
- `go test ./cookie/ -race` 并发不变量
- `go test ./cookie/ -bench .` 附带/淘汰性能基准
- `TestAttachCostIndependentOfBystanders` / `TestEvictionSelectionSublinear`
  用内部探针计数断言扫描量与站点规模、无关条目数无关。
