# PN-Counter（无冲突可增可减复制计数器）

`counter` 包实现一个支持并发的 PN-Counter CRDT。多个副本各自独立做
增/减操作，并通过两两合并同步；在任意合并顺序、重复合并、消息乱序到达的
情况下，所有副本最终收敛到同一个可复现的值。

## 数据模型

对 `n` 个副本，每个副本 `i` 维护两个长度为 `n` 的非负分量向量：

- `P[i][k]`：副本 `i` 已知的、由副本 `k` 产生的“增”量累计；
- `N[i][k]`：副本 `i` 已知的、由副本 `k` 产生的“减”量累计。

两向量只增不减（grow-only）。

## 增减规则

- `Inc(k, d)` 只执行 `P[k][k] += d`；
- `Dec(k, d)` 只执行 `N[k][k] += d`；
- 本地操作只改本副本自己的分量，不触碰其他副本，也不立即传播。

## 合并规则

`Merge(dst, src)` 对每个分量 `k` 逐分量取两侧较大者，并且**只改目标副本**：

```
P[dst][k] = max(P[dst][k], P[src][k])
N[dst][k] = max(N[dst][k], N[src][k])
```

- `Merge(x, x)` 是合法空操作（幂等）；
- 重复合并、乱序到达均无副作用（取 max 天然幂等）；
- 该合并满足交换律、结合律、幂等律，因此所有副本在充分合并后收敛到同一状态。

## 求值方式

任意副本 `i` 的值为增向量之和减去减向量之和：

```
value(i) = Σ_k P[i][k] − Σ_k N[i][k]
```

- 允许为负：减多于增时返回负数，不拒绝、不截断为 0；
- 使用 `math/big.Int` 精确求值，即使分量接近 `uint64` 上界也不溢出。

## 边界与上限

- `New(replicas, limit)`：`replicas` 必须为正；`limit` 为每个分量的闭区间
  上界，必须大于 0；不需要实际上限时传 `math.MaxUint64`。
- 任何会使分量超过 `limit` 的增、减或合并都被**整体拒绝**，不留任何状态变更。
- 合并取 max 不会缩小分量；若导入了在更大上限下产生的外部状态导致超过
  本计数器上限，合并同样被原子拒绝，而不是静默截断。

## 错误类别

所有失败都返回 `*OpError`（含操作名 `Op`、可区分的人类可读原因 `Reason`），
并可用 `errors.Is` 判别为以下互不相混的哨兵错误：

| 哨兵错误 | 触发场景 |
| --- | --- |
| `ErrInvalidArgument` | `New` 参数非法（副本数 ≤ 0、`limit` = 0） |
| `ErrUnknownReplica` | 副本编号越界（含负数、≥ 副本数） |
| `ErrNonPositive` | 增/减增量为 0（增量必须为正） |
| `ErrOverflow` | 操作会使某分量超过 `limit` |
| `ErrSelfInconsistent` | `SelfCheck` 发现向量长度错误或分量越界 |

拒绝先完成全部校验、后改状态，因此“失败不留痕”：被拒调用后快照与调用前
逐分量相同（测试 `TestRejectionCategoriesAndNoTrace` 校验）。

## 并发模型

- 每个副本一把互斥锁；增/减只锁本副本，`Value`/`ReplicaSnapshot` 读单副本。
- `Merge(dst, src)` 按副本编号**升序**加锁（与方向无关），因此
  `Merge(a,b)` 与 `Merge(b,a)` 同时进行也不会循环等待、不会死锁。
- `Snapshot`/`SelfCheck` 按全局升序一次性获取所有锁，得到一致时间点视图。
- 所有方法均可被多个 goroutine 并发调用。

## 本地验证

```bash
# 全部测试（带每步输入、各副本 P/N 向量、值与判定依据的日志）
go test -v ./counter/

# 竞态检测 + 重复运行（含并发增/减/合并/求值/快照/自检交错用例）
go test -race -count=3 ./counter/

# 静态检查与格式化
go vet ./...
gofmt -l .
```

测试覆盖：基础增减与负值、合并交换律/结合律/幂等、重复乱序合并、
非法参数五类错误及拒绝后状态不变、合并超限原子拒绝、高并发双向合并无死锁、
并发全操作与朴素参照（本地增减总账）收敛一致性，以及 `uint64` 满量程精确求值。
