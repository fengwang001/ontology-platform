设计说明（分时电价结算引擎）

1. 模块划分
   types.go    错误类别、领域类型、月键 monthKey、参数边界（秒级时刻、年份范围）。
   tariff.go   版本册：生效时刻排序、无缝覆盖整日校验、某时刻适用版本二分查找、时段下标。
   calendar.go 节假日集合 + 自然周末，日类型优先级 节假日>休息日>工作日。
   slicing.go  单区间切片与计价：在日界、月界、时段边界、版本生效时刻处切断。
   engine.go   并发引擎、读数/修正/删除、增量月份聚合、账单快照、封账冻结。
   测试侧      naive_model_test.go 为独立朴素参考实现，engine_test.go 为专项+随机差分，
               benchenc_test.go 为并发与基准。

2. 关键取舍
   - 时间一律秒级、固定 Location（默认 UTC+8），入站时刻按同一瞬间归一化，杜绝日界二义。
   - 金额单价用 千分之一货币单位/Wh（int64），金额 floor(电量*单价/1000)，
     电量与金额乘法用 math/big 防溢出；分摊 floor 后余量归区间最后一片，严格守恒。
   - 每片记录 (月, 日类型, 时段起点, 单价) 聚合桶；月份另存 totalWh/unbillable。
     查账只聚合当月桶，已封账月保存不可变快照，故查询与封账月数、其他供电点无关。
   - 登记读数仅产生一个新区间：切片+一次桶累加，摊还 O(1)，不扫描历史。
     修正用「先收集相邻下标→统一移除旧贡献→统一重建」，避免同点连改时索引错位。
     回溯版本/节假日变更按二分定位受影响区间做定向重切，而不是全量重算。
   - 并发用单一 sync.RWMutex：写互斥、读并行，天然等价于某串行顺序；放弃细粒度分片锁，
     因其对正确性（跨供电点的全局版本/节假日）无收益且易错。
   - 错误严格按 参数非法 > 月份已封账 > 时序错误 > 读数倒退 > 读数不足 判定；
     封账时先查不可计价片（ErrUnbillable）再查月末读数。任何拒绝都在校验全部通过后才落盘。
   - 封账冻结边界取「不晚于该月末的时刻」：月末锚点读数本身也不可改/删/重复登记，
     防止通过锚点改动跨月区间使已封账月份漂移。

3. 被放弃的方案
   - 每秒步进枚举：语义直观但无法处理亚秒与大跨度，性能不可接受，仅朴素模型思想借鉴。
   - 版本/节假日变更后全量重算：正确但违背登记开销与历史无关的要求，改为区间定向重切。
   - 区间内用 float 比例分摊：取整不确定、难复现，改为精确整数 floor + 末片余量。
   - 每供电点独立版本表：与「版本生效时刻全局唯一」冲突，版本与节假日保持全局。

4. 本地验证
   go test ./...                         全量（40 轮×400 随机操作差分，约 64000 次/轮批）
   go test -race ./tou/                 并发竞态
   TOU_SEED=<种子> go test -run TestDifferentialRandom ./tou/   失败可精确重放，日志在 /tmp/tou-diff-*.log
   go test -bench=. -run='^$' ./tou/    读数登记与账单查询基准
   差分日志逐条打印输入、输出（含拒绝类别）与判定依据。
