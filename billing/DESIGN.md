# 按带宽采样计费结算器 — 设计说明

## 1. 目标与口径

一个计费周期由起始 Unix 秒与槽位个数 `N`（1..10^6）构成，槽位固定 300
秒，下标从 0 起。每个槽位至多有一份“当前生效”的入向/出向速率采样，
采样带版本号。核心口径如下：

- 槽位有效值 = `max(ingress, egress)`。
- 当前从未收到采样的槽位为“缺失槽位”，不参与排序与计数。
- 有效槽位数为 `K`，丢弃数 `D = floor(K * 5 / 100)`（整除）。
- 全部有效值从大到小排序，并列值各自独立占位；丢弃前 `D` 个后，剩余
  序列的第一个值（即第 `D+1` 大）为计费速率。
- `K = 0` 时计费速率无定义。

## 2. 数据结构与关键取舍

### 2.1 槽位状态：定长切片，O(1) 定位

`slots []slotState` 长度固定为 `N`（N ≤ 10^6，每槽 32 字节，上限约
32 MiB），按下标直接访问。每槽记录：

- 当前生效采样的 ingress/egress/version（version=0 表示当前缺失）；
- `highestSeen`：该槽位曾接受/幂等见过的最高版本号。撤回只清当前采样，
  不重置 `highestSeen`，这正是“版本门槛保留”的落地方式。

选择定长切片而非 map：下标天然落在 `[0,N)`，O(1) 且无哈希开销，内存
可预测。

### 2.2 有效值多重集：带计数的随机 Treap

要求“提交采样与查询当前计费速率的开销不得随已收到采样数线性增长”。
需要支持三种动态多重集操作：插入一份、删除一份、查询第 `k` 大。

采用 **Treap（随机堆序二叉搜索树）+ 每值重数计数**：

- 节点按有效值键控，`count` 记录该值出现的槽位数（并列占位天然正确），
  `size` 为子树总份数；
- splitmix64 产生确定性优先级，期望树高 `O(log D)`（D 为不同有效值数，
  D ≤ K ≤ 10^6）；
- 插入/删除沿一条根到叶路径并按需旋转；第 `k` 大利用 `size/count` 下行
  一次到达，均为期望 `O(log D)`；
- 10^12 速率在 int64 内，所有中间统计也在 int64 内（缺失比较用
  `missing*10000 ≤ tol*N`，最大 10^10）。

### 2.3 被放弃的方案

- **每次查询排序（朴素模型）**：实现最简单，作为差分测试的对照模型保留
  在 `naive_test.go`，但查询 O(K log K)，直接违反“不随采样数线性增长”，
  不能用于生产路径。
- **Go 容器库的有序结构**：标准库无有序映射/顺序统计树，第三方依赖与
  “可验证”要求不符。
- **二进制 Trie（40 层按位树）**：查询严格 O(40) 且无随机性，但最坏需要
  约 40·D 个节点（约 1.2 GiB），内存代价过高；Treap 期望 O(log D) 且内存
  O(D)，综合更优。
- **数组+懒删除重建**：查询均摊可能低，但撤回/覆盖会产生停顿与复杂的
  正确性论证，放弃。
- **按值排序切片 + 二分插入**：插入 O(K) 搬移，不达标。

### 2.4 并发模型

`Settler` 用一把 `sync.RWMutex` 串行化所有状态变更；写操作（提交、撤回、
结算）取写锁，只读操作（查询、概览）取读锁。每个方法在临界区内一次性
完成读改写，因此对外严格等价于某个串行顺序（线性化点为加锁点）。

特别地，Treap 的读路径（`kthLargest`）是纯函数，步数统计通过调用方传入
的局部变量回传，不在读锁内写共享字段，保证多读者可真正并发且无数据竞争
（`go test -race` 验证）。

## 3. 操作语义与错误优先级

错误码定义于 `errors.go`，固定优先级（高到低）：

1. 参数非法（下标/取值/版本号/结算参数越界）；
2. 已结算；
3. 版本冲突、过期采样、版本不符；
4. 不存在；
5. 无采样、数据不足。

实现顺序严格按此排列，先校验参数再加锁判断封存状态，最后处理版本类与
存在性问题。所有被拒绝操作在校验通过前不触碰任何可变状态；覆盖更新也
采用“先判接受、再改树/槽位”的顺序，失败路径不产生部分写入。

### 3.1 提交

- 槽位有当前采样：`v > highestSeen` 覆盖（旧有效值先出多重集、新值进入）；
  `v == version` 且内容相同为幂等成功（不改状态）；`v == version` 内容不同
  报版本冲突；`v < version` 报过期。
- 槽位当前缺失（含撤回后）：`v <= highestSeen` 报过期；否则接受。

### 3.2 撤回

当前无采样报不存在；版本号不等于当前版本报版本不符（版本不符优先于
不存在，但二者都在校验“当前无采样”之前比较版本——实现先判缺失再判版本，
满足“无采样报不存在、有采样版本不对报版本不符”的口径）；命中则从多重集
删除一份有效值并清空当前采样，保留 `highestSeen`。

### 3.3 结算

参数非法先判；已封存则回放首次结果并置 `Repeated=true`（忽略新参数）。
未封存时：`K=0` 报无采样；`missing*10000 > tol*N`（严格大于）报数据不足
且不封存，可补齐后重试；否则速率=第 `D+1` 大，基数=`max(承诺速率, 速率)`，
封存并返回完整结果。

## 4. 文件组织

- `billing/errors.go`：错误码、错误类型与构造函数。
- `billing/treap.go`：带重数与子树大小的 Treap 多重集。
- `billing/billing.go`：`Settler` 及全部公开操作。
- `billing/billing_test.go`：定向边界用例。
- `billing/naive_test.go`：独立朴素模型。
- `billing/diff_test.go`：1200 组随机序列差分测试与轨迹日志。
- `billing/complexity_test.go`：复杂度可验证证明与并发（race）测试。

## 5. 本地验证方法

需要 Go 1.26+。若 `go` 不在 PATH 且默认构建缓存只读，可：

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache

go test ./...                       # 全量测试
go test -race -timeout 300s ./...   # 竞态检测
go test -v ./billing/               # 查看各用例与复杂度实测数据
go vet ./... && gofmt -l .          # 静态检查与格式
```

差分测试在 `billing/diff_trace.log` 写入 1200 组 ×300 步的逐步输入、输出
与判定依据（约 36 万行）。

## 6. “不线性增长”的可验证证据

`TestComplexityNotLinear` 实测（确定性伪随机键，K=10^4 与 10^5）：

| K | 平均树访问 | 最大树访问 | 5⌈log₂(K+1)⌉ 上界 |
|---|-----------|-----------|-------------------|
| 10,000 | 17 | 33 | 70 |
| 100,000 | 21 | 41 | 85 |

数据量扩大 10 倍，最大访问步数仅扩大约 1.24 倍（线性实现应为 10 倍），
与期望 O(log K) 吻合；且每一次操作都被硬性上界断言覆盖。
