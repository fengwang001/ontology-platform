# 跨源预检判定与缓存内核 — 设计说明

## 模块划分（cors 包，7 个 .go 文件）
- `types.go`：Origin（含不透明来源）、Request/Response、Decision、可区分错误（5 类 + 4 种预检子原因）。
- `clock.go`：手动单调时钟；负增量即时钟回退，拒绝且不改动。
- `classify.go`：请求分类。安全方法/安全头/安全响应头均预编译为哈希表，头值字符集预编译为 [256]bool。
- `cache.go`：预检缓存。键 =(来源, 目标, 凭据模式)；命中为 O(1) 哈希查找；淘汰仅在插入超容时触发。
- `engine.go`：协调五部分。单互斥锁串行化全部公开方法，天然等价于某串行顺序。
- `engine_test.go` / `model_test.go` / `bench_test.go`：单测、朴素模型对照、性能证明。

## 关键取舍
- 非安全头按"名字不在安全头集合"定义；名字安全但值越界的请求仍需预检，但不要求 Allow-Headers 覆盖它（规格未规定，取确定可复现的解释）。
- 过期条目惰性清理：命中判定只看 `now < expiry`（恰等视为过期），物理删除发生在插入超容或清除操作时，避免每次判定扫描全表。
- 合并只在旧条目未过期时发生；已过期条目被整体替换（新创建序号），语义简单确定。
- 合并时并集方法与头、过期时刻与通配标记取新响应值，创建序号与最近命中时刻保留旧值。
- 凭据包含时，响应通配（来源/方法/头/暴露）在入口处即折叠为无效，缓存里只存逐项集合，后续命中路径无需再判断凭据。
- 不透明来源带唯一编号，比较恒不相等；缓存键用编号区分，重定向链互不污染。
- 所有公开操作先校验后改状态，被拒绝的操作不改变缓存与时钟；拒绝次序由校验顺序硬编码保证。

## 被放弃的方案
- 锁分片/无锁缓存：正确性论证复杂，单锁已满足"等价于某串行顺序"，吞吐不是目标。
- 主动过期清扫（后台滴答）：引入额外线程与不确定性，惰性清理足够。
- 把值越界的安全头也算作非安全头：与"头集合按名字匹配"的缓存模型冲突，放弃。
- 预检失败记录负缓存：规格未要求，且会放大容量压力，放弃。

## 本地验证
- `go test ./cors/`：16 个单测覆盖规定场景（含四种失败次序、淘汰并列、按来源清除等）。
- `go test -race ./cors/`：并发等价性与数据竞争检测。
- `go test ./cors/ -run TestRandomAgainstNaiveModel -count=10`：与独立朴素模型对照随机序列。
- `go test ./cors/ -run=NONE -bench=.`：extra-config 0→4096、缓存 16→65536 条，单次判定耗时均不增长。
