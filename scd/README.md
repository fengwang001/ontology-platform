# scd —— 缓慢变化维历史区间维护

`scd` 包对可能**乱序到达**的维度变更事件，增量维护每个键的取值历史区间
（SCD Type-2）。历史与批量重算结果一致、区间良构，且与到达顺序无关、可复现。

## 核心概念

### 变更点（change point）

- 每个键维护一组变更点：`(生效时间, 值)` 或 `(生效时间, 删除标记)`。
- 变更点按生效时间**严格升序**排列，同一键的生效时间互不相同。
- 同一键同一生效时间的变更点**只保留后到者**：
  - 跨批次：新事件恰等于已有变更点时间时，**替换**该点（值或删除标记）；
  - 同批次内：同键同时刻的多个事件折叠为该批中**后出现**者。

### 区间生成

历史**完全由变更点集合决定**，与事件到达顺序无关：

- 按生效时间升序扫描变更点，每个**更新点**产生一个左闭右开区间
  `[t, next)`，其中 `next` 为下一个变更点的生效时间；
- 最后一个更新点的区间为 `[t, +∞)`（代码中以哨兵 `OpenEnd = math.MaxInt64` 表示）；
- **删除点不产生区间**，仅作为上一个区间的右端，形成查询不命中的“删除空隙”；
- 相邻两行值相同**也不合并**——一行严格对应一个更新点。

### 增量维护

- 生效时间落在某行**内部**的乱序事件**拆分**该行为两行；
  落在最早点之前则新开首行；恰等于已有变更点则替换该点；
- 单事件只在一个位置插入或替换变更点，该位置之外的区间首尾均不变化，
  因此区间可随变更点增量派生，无需全量重算；
- `Recompute(key, events)` 提供从原始事件的批量重算，测试中用于
  逐批比对增量结果，保证两者一致。

## 边界

- 合法生效时间范围：`[MinEffectiveTime, MaxEffectiveTime]`，即
  `[math.MinInt64, math.MaxInt64-1]`。上界预留一位给无界右端哨兵
  `OpenEnd`，保证任何区间长度为正。
- 时间点查询 `ValueAt` 遵循左闭右开：`t` 恰等于变更点时间时命中**该点**所在行；
  处于删除空隙或最早点之前时返回 `("", false)`。
- 每个键的变更点数受 `NewStore(maxPointsPerKey)` 上限约束。

## 错误类别（整批拒绝）

`Commit` 对一批事件**先校验、后应用**：任一事件非法则整批拒绝，
不改变任何变更点与历史（失败不留痕），并返回全部可区分原因：

| 原因代码 | 含义 |
| --- | --- |
| `EMPTY_BATCH` | 提交了空批次 |
| `EMPTY_KEY` | 事件键为空字符串 |
| `EMPTY_VALUE` | 更新事件（非删除点）的值为空 |
| `EFFECTIVE_TIME_OUT_OF_RANGE` | 生效时间超出允许边界 |
| `TOO_MANY_CHANGE_POINTS` | 提交后某键变更点数将超过上限 |

每个 `Rejection` 携带批次内下标、键、原因代码与可读消息；
`BatchRejectedError` 可汇总一次拒绝的全部原因。

## 并发

`History`、`ValueAt`、`CheckInvariants` 可与 `Commit` 并发调用：
读操作基于锁内快照，写操作串行提交。任意时刻每个键的历史区间升序、
任意两行不重叠、任意时间点至多命中一行；`CheckInvariants` 可随时自检这些不变量。

## 本地验证

```bash
# 全部测试（含竞态检测）
go test -race -v ./scd/

# 仅静态检查与编译
go vet ./... && go build ./...
```

测试日志（`go test -v`）会打印每一步的输入事件、提交判定、
历史区间快照与断言依据；`Store.SetLogger(w)` 可为库本身开启步骤日志
（替换点 / 拆分行 / 新开行 / 接受或拒绝原因）。
