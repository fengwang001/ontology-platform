# 团队估点投票会话 — 设计说明

本包 `planningpoker` 实现隐藏投票、主持人揭示、惰性到期、自动揭示、
轮次上限、收敛/分歧判定与末轮强制取值的投票会话。全部状态收敛在
单个 `Session` 内，一把互斥锁串行化所有入口，因此“并发调用结果等价于
某个串行顺序”。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `deck.go` | 牌组：数值牌严格递增校验、两张固定特殊牌、牌 ↔ 槽位下标映射 |
| `errors.go` | 六类被拒绝错误（参数/时钟/成员/权限/状态/无人投票）+ 已存在 |
| `session.go` | 不可变配置、全部状态字段、`NewSession` 入参校验 |
| `internal.go` | 时钟与惰性到期、自动揭示条件、揭示统计与结果判定、下中位、清盘 |
| `operations.go` | 九个入口操作与权限/状态机，槽位与集合的 O(1) 维护 |

`oracle_test.go` 是一份**完全独立**的朴素参照模型，不读取实现内部结构，
只按规格文字用 map 枚举全体成员；`diff_test.go` 生成随机配置与操作序列，
双跑实现与参照模型并逐操作比对。

## 关键状态与不变量

- `phase ∈ {Idle, Voting, Revealed, Ended}`：议题生命周期。
- `votersPresent`：在室投票者总数，任何阶段都保持准确。
- `votedVoters`：当前轮已投票人数（含特殊牌），投票阶段 O(1) 维护。
- `slotCounts[k]`：第 k 张牌当前票数。数值牌槽位 0..n-1，
  其后固定为 `uncertain`、`break` 两张特殊牌。
- `votedSet map[user]gen`：当前轮已投投票者席位（值为加入代次），
  随投票/撤回/离开/改角色 O(1) 增删。
- `revealedGen` / `revealedPresent`：揭示时通过**交换 map 引用**冻结的
  快照与“仍在室匹配席位”计数。

## 检查次序（只报第一个）

1. 参数非法（空用户、非法角色、牌不在牌组、配置越界）；
2. 时钟回退（`now < lastNow`）；
3. 惰性到期（通过参数+时钟检查后、执行操作本身之前）；
4. 调用者不在会话；
5. 权限不足（观察者投票、非主持人 Start/Reveal/Revote）；
6. 状态不允许（非投票阶段投票、议题已结束、不能 Revote、重复 Join）；
7. 无人投票（仅手动 Reveal）。

被拒绝的操作不改任何状态、不更新时钟；但到期处理一旦发生即为已接受的
状态推进，即使其后操作被权限/状态拒绝也已生效。

### 主持人身份

主持人身份独立于成员表：创建者天然是主持人，无需再 `Join`。若主持人
调用需要“在会话”的检查，则按“非主持人 → 是否成员 → 权限”次序处理。

## 到期（惰性）

- 截止时刻 = 轮开始时刻 + `T`，**恰等于**截止时刻即到期。
- 不在后台起定时器；每个操作与查询在自身执行前调用 `processExpire`。
- 到期即在**截止时刻**（而非操作时刻）揭示；到期无人投票按无有效票处理。

选择惰性而非后台定时器：状态只在被观察/操作时推进，避免计时器与锁竞争，
且使“相同操作序列重放得到完全相同结果”成为平凡性质。

## 自动揭示

`maybeAutoReveal` 只读两个整数：`votersPresent >= 1 && votedVoters ==
votersPresent`，判定 O(1)。触发源包括最后一张投票，以及使分母缩小的操作
（未投投票者离开、被改为观察者）。揭示时刻取使条件成立那个操作的 `now`。

## 结果判定（只统计数值牌）

- 无数值票 → 无有效票（轮尽则终局无结果）；
- 数值票全同 → 共识，取该值；
- 最大、最小数值牌在牌组中**位置相邻**（相差恰一位）→ 收敛，取较大者；
  注意是“牌组位置”相邻，不是数值差 1；
- 其余 → 分歧。

分歧或无有效票且轮数未尽可 `Revote`；轮尽时分歧 → 强制取值。

### 下中位

强制取值取全部数值票按牌组位置排序后的下中位：`target = (m-1)/2`
（0 起），偶数张时取靠前的一张。特殊牌不参与。

## 复杂度与可验证证明

- `Vote`/`Unvote`：常数次数组与 map 写，**O(1)**，不扫描成员。
- 自动揭示条件：两个整数比较，**O(1)**。
- 揭示统计：遍历 `slotCounts`（长度 = 数值牌数 + 2）与冻结一次 map
  引用，**统计部分 O(牌组大小)**，不遍历参与者。

被放弃的方案：曾在揭示时遍历成员构建“已投快照”，使揭示随参与者线性
（基准中 32k 人揭示耗时 4.47ms）。改为在投票过程中增量维护 `votedSet`、
揭示时只交换引用后，同规模降到约 4.4µs（约千倍），`BenchmarkVoteO1` 中
参与者扩大 32 倍（1k→32k）单次投票仅约 87ns→179ns（缓存噪声级）。

## 揭示后的在室快照与“同名重入”

`Peek` 在揭示后要返回“已投人数”，而成员可能继续离开/改角色，甚至
**离开后用同一用户名重新加入**。快照键值使用“加入代次”：离开/转观察者
对在室计数 O(1) 递减；同名重入得到新代次，不会匹配旧快照，避免被误计。

## 零泄露

揭示前任何查询只返回调用者本人的票与两个聚合计数（已投人数、在室投票者
总数），他人具体的牌既不出现在返回结构，也不参与日志。
