# 工业用户最大需量控制器 — 设计说明

## 1. 问题与口径

控制器以**滑动窗口平均功率**逼近合同需量：窗口长度 `W` 秒、滑差 `S` 秒，
窗口只在 `S` 整数倍的绝对时刻结束，因此任一时刻有 `W/S` 个互相重叠、
尚未结束的窗口。

- 上报区间 `(prev, now]` 内功率视为**恒定**，等于 `用电量/(now-prev)`。
- 预测：对每个活跃窗口，
  `已发生用电量 + 最近区间功率 ×(窗口结束-now) > 合同需量 × W` 即越限；
  任一窗口越限则整体越限，**恰好等于不算越限**。
- 窗口起点早于首次上报时刻的部分按**无用电（0）**计入，窗口长度恒为 `W`。

## 2. 模块划分

包路径 `ontology/demand`，每个文件职责单一、通过 `Controller` 协作：

| 文件 | 职责 |
| --- | --- |
| `config.go` | 配置结构与校验（正整数、`W` 是 `S` 整数倍）、重叠窗口数 |
| `errors.go` | 五类可区分错误及中文类别（参数/数据/回退/负荷不存在/状态不允许） |
| `frac.go` | 精确有理数（`big.Rat`）与整数分子表示，杜绝浮点边界误判 |
| `load.go` | 负荷静态属性、运行态（接入/锁定/状态切换时刻）、候选集合筛选 |
| `window.go` | 滑差切片**环形缓冲**、区间能量分摊、关窗水位、窗口能量查询 |
| `predict.go` | 活跃窗口预算、整数交叉相乘的越限判定、所需切除容量 |
| `shed.go` | 切除集合选择：背包求最小基数 + 同基数枚举三层并列规则 |
| `restore.go` | 顺序尝试恢复，首个失败即停止（不跳过） |
| `controller.go` | 并发互斥、上报校验/提交、评估编排、运维操作、峰值记录、日志 |

独立参考实现位于 `ontology/demand/naivemodel`：保留**全部上报历史**、
每次对每个窗口逐区间求交积分、子集全枚举，只用于随机对照，不做任何
环缓冲/增量技巧。

## 3. 关键取舍

### 3.1 环形切片 + 关窗水位（与历史长度解耦）

把时间按 `S` 切成切片，环容量恰为重叠窗口数 `N=W/S`。任一活跃窗口都
覆盖恰好 `N` 个连续切片，因此：

- 上报把区间能量按**重叠秒数线性分摊**进切片（区间内功率恒定）；
- 写入切片 `s` 前，关闭所有结束时刻 `<= s·S` 的窗口（其数据可能正存放
  在即将被覆盖的槽中）；区间落盘后再关闭所有结束时刻 `<= now` 的窗口。
  回调按结束时刻**升序**触发，保证峰值并列取较早者；
- 窗口能量只对 `N` 个切片求和。评估开销仅与**负荷数**和**重叠窗口数**
  相关，不随历史上报次数增长（见 §6 实测）。

切片能量存为**公分母下的整数分子**：上报功率本就是整数比
`energy/dur`，分摊后仍为有理数；不同区间分母不同时，用 LCM 把环整体
放大到统一分母（分母只在有限的上报区间形态间变化）。这样窗口求和是
整数加法，`prepare` 后每个窗口的余量 `slack` 也以整数分子保存。

### 3.2 预测的整数判定

越限条件
`occ + (P - x)·remain > limit`（`x` 为净切除容量，恢复为负）
等价于
`(pNum - x·pDen)·remain·slackDen > slackNum·pDen`。

全部用整数（为防溢出用 `big.Int` 做交叉相乘）比较，切除/恢复的每次
"假设可行"探测不再重新对切片求和，也不产生分数除法。

### 3.3 切除选择：最小基数 + 三层并列

1. 由预测器给出所需切除容量的精确值 `required`，额定为整数，取
   `minKW = ceil(required)`；
2. **0/1 背包 DP**（容量维度）求达到 `minKW` 的最少负荷数 `minCount`，
   复杂度 `O(负荷数 × 可切除总容量)`；
3. 仅在 `minCount` 这一层枚举组合，用后缀可达容量位集剪枝，按
   **优先级数字之和最大 → 编号序列字典序最小**选出唯一最优。

全部可切除负荷切除后仍越限时，切除全部并在结果中置 `StillExceed`。

### 3.4 恢复的"首个失败即止"

候选按优先级数字升序、同级编号升序；逐个累计恢复容量调用可行性判定，
一旦某负荷恢复后越限，**立即停止**，不尝试其后的任何负荷。同一次评估
只可能切除或只可能恢复，不会两者并存。

### 3.5 关键负荷与锁定

- 关键负荷 = 现有负荷中**优先级数字最小**者，永不进入切除候选；
- 锁定期间不参与切除；锁定一个**已断开**的负荷不会使其恢复（恢复候选
  排除锁定负荷）；解锁后立即恢复参与后续评估；
- 删除处于接入/断开态的负荷一律拒绝（故本实现中删除恒返回状态不允许，
  只在负荷不存在时先返回"负荷不存在"）。

### 3.6 并发等价串行

控制器用单把 `sync.Mutex` 串行化全部公开方法。所有状态变更（环、负荷、
峰值、最近上报时刻）都在临界区内完成，因此并发调用结果等价于某个合法
串行顺序。被拒绝的操作在校验阶段即返回，不触碰任何状态。

## 4. 错误次序

- 上报：**参数非法 > 数据非法 > 时刻回退**（先查时刻非负/能量非负，
  再查物理上限，最后查时刻严格递增）；
- 运维：**参数非法 > 负荷不存在 > 状态不允许**。

## 5. 被放弃的方案

- **浮点功率/能量**：在"恰好等于合同需量"和整数秒边界上会因舍入误判，
  放弃；统一用精确有理数，仅展示时转浮点。
- **保留全部上报历史、每次重算**：实现简单但评估随历史线性增长，
  仅保留为 `naivemodel` 用于交叉验证，不用于生产路径。
- **切除集合全子集 DFS**：在同容量负荷较多、需切多个时指数爆炸
  （实测单负荷场景下 2000 次评估耗时秒级）。改为背包定最小基数后，
  只枚举最小基数一层并配可达容量剪枝。
- **环上做绝对前缀和**：试图让窗口能量 O(1)，但槽绕回时累计基准被
  覆盖会产生负值且实现易错；改为公分母整数 + 每窗口 `N` 个整数相加，
  `N` 通常很小，正确性与性能都更稳。

## 6. 与历史长度无关的可验证证明

结构性论证：任何一次评估只访问

- `N=W/S` 个切片（窗口能量、活跃窗口），
- 负荷表 `L`（候选筛选、背包 `O(L·总容量)`、同层枚举），

不遍历任何历史上报；历史区间一旦分摊进切片即不再保留。

实测佐证（`TestHistoryLengthIndependence`，`W=600,S=10`，12 个负荷）：
在稳态分别对 **1,000** 与 **100,000** 条历史测量最后 2,000 次
"上报+评估"的平均耗时，二者处于同一量级（本机约 `130µs/次`，
比值 ≈ `0.94`，绝不随历史出现百倍线性增长）。

## 7. 本地验证方法

```bash
# 单元规则 + 随机对照 + 竞态
go test ./...
go test -race ./demand

# 与朴素模型的大量随机序列对照（默认 800 组，含非法上报与运维穿插）
go test ./demand/naivemodel -run TestRandomAgainstNaive -v

# 历史长度两档性能对照
go test ./demand -run TestHistoryLengthIndependence -v

# 带判定日志的演示
go run ./demand/cmd/demo
```

日志在 `WithLogger(log.Logger)` 时打印每次上报的**输入**（时刻、用电量、
区间功率）、**判定依据**（每个活跃窗口的预测未来电量与剩余余量、是否
越限）与**输出**（切除/恢复清单、是否仍越限、关窗实测均值、峰值更新）。
