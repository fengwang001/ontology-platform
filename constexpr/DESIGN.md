# 常量表达式求值器设计说明

本文档说明 `constexpr` 包的模块划分、关键语义取舍、被放弃的方案与本地验证方法。

## 1. 模块划分

各文件职责单一、通过明确定义的接口协作：

| 文件 | 职责 |
| --- | --- |
| `kind.go` | 值的四种“种类”：整数 / 有理数 / 布尔 / 字符串。 |
| `ctype.go` | 有类型常量的类型表：i8/i16/i32/i64/u8/u16/u32/u64/f64/bool/string，类型名解析、位宽、符号与取值范围。 |
| `value.go` | 不可变 `Value`：种类 + 可选具体类型 + `big.Int`/`big.Rat`/bool/string 载荷；跨边界一律深拷贝。 |
| `errors.go` | 可区分的错误分类（`EvalCode`）与错误对象。 |
| `represent.go` | 可表示性判定、显式/默认转换、512 位限制、有理数到 f64 的最近偶数舍入。 |
| `expr.go` | 结构化表达式树 `Expr`、构造器、运算符元数表与**纯结构合法性检查**。 |
| `ops.go` | 全部运算语义：类型撮合、算术、取余、位运算、移位、比较、逻辑、一元运算及单节点错误优先级。 |
| `eval.go` | 求值驱动：结构校验 → 名字解析 → 先子后父从左到右求值；提供 `Tracer` 轨迹钩子。 |
| `registry.go` | 并发安全的命名常量表：读写锁 + 写时复制的不可变快照；登记时求定并固定值。 |
| `expr_print.go` | 表达式的 S 表达式打印，供日志与调试。 |

测试分两层：手写边界/优先级/并发用例（`*_test.go`）与独立朴素模型对拍（`naive_*` + `random_*`/`diff*`）。

## 2. 核心模型

### 2.1 无类型 vs 有类型

- 字面量与未标注类型的命名常量是**无类型常量**，只有种类，无类型整数用任意精度 `big.Int`，有理数用精确 `big.Rat`（不做任何舍入）。
- `Conv(typeName, x)` 是显式转换节点；其结果是有类型常量。f64 常量的内部载荷仍是精确 `big.Rat`，双精度舍入值只在“可表示性检查”和 `Value.Float64()` 时才产生。
- 比较运算的结果恒为**无类型布尔**（即使两个操作数都有类型），因此可直接与无类型布尔做逻辑运算。

### 2.2 类型撮合（`coercePair`）

1. 两个有类型操作数：类型必须**完全一致**，否则 `type-mismatch`。
2. 恰有一方有类型：无类型一方先转换到该类型，转换错误（截断/越界/非法）在此产生。
3. 两个无类型：不转换，按种类运算。

移位是例外：移位量只按“值”要求约束，与左操作数不做类型撮合，结果跟随左操作数的有无类型。

### 2.3 种类与运算选择

- 整数 ÷ 整数 = 向零截断整除（`big.Int.Quo`），余数用与之配套的 `Rem`（余数与被除数同号）。
- 任一方是有理数种类 = 精确分数除法，结果恒为有理数种类（即使数学值恰为整数）。
- 取余、按位与/或/异或、按位取反、移位的**左操作数**只允许整数种类；“值为整数的有理数”不算整数种类。
- 字符串只支持加法（拼接）与六种比较（字节序）。

### 2.4 一元取负与按位取反

- 无类型整数与有符号整数的按位取反：`^x = -x-1`。
- 无符号整数的按位取反：在其位宽内按位翻转（与宽度掩码异或）。
- 对无符号整数取负：仅 0 合法，任何非零值必越界（不回绕）。

### 2.5 移位

- 左操作数必须是整数种类。
- 右操作数按值要求：非负整数且 `<= 1000`；为负、非整数或超限均报“非法移位”。右操作数允许是“值为整数的有理数种类”，因为要求落在值上。
- 左移结果在有类型语境下必须可表示；右移是**向负无穷**的算术右移 `floor(x/2^k)`（负数用 `QuoRem` 后再修正一次）。

### 2.6 可表示性

- 转整型：值必须恰为整数，否则报 `truncation`；整数部分落在 `[min,max]` 外报 `overflow`，二者严格可区分。
- 转 f64：经 4096 位精度的 `big.Float`，以 `ToNearestEven`（最近偶数）舍入；舍入结果为 ±Inf 报 `overflow`。
- 无类型整数：字面量与每个无类型中间结果的绝对位宽都不得超过 512，否则报 `constant-too-large`。有理数无此限制。

### 2.7 默认类型（`OpDefaultConv`）

需要具体类型的语境：整数→`i64`，有理数→`f64`，布尔→`bool`，字符串→`string`；已有类型的值原样通过。

## 3. 错误模型与优先级

错误分类（`EvalCode`，全部可区分）：
`invalid-argument`、`duplicate-name`、`unknown-name`、`type-mismatch`、
`illegal-op`、`divide-by-zero`、`truncation`、`overflow`、`constant-too-large`。

### 3.1 跨阶段优先级

求值分三个严格有序阶段，前一阶段的错误先于后一阶段返回：

1. **结构校验**（`validateStructure`，不做任何求值）：运算符与操作数个数不符、未知运算符、空节点、引用空名、未知类型名、字面量缺种类。
2. **名字解析**（`checkNames`）：先子后父、从左到右收集第一个未登记引用 → `unknown-name`。因此未知名字必然先于求值错误。
3. **求值**：先子后父、从左到右，返回第一个错误。

这样保证“未知名字优先于求值错误”无需借助短路式遍历顺序。

### 3.2 单节点优先级

在一个运算节点内部严格按以下次序检查：

1. 类型不匹配（两个有类型操作数类型不同）；
2. 非法操作（种类不支持、非法移位等；混合时无类型一方的转换也在此阶段前发生）；
3. 除零；
4. 不可表示（截断 / 越界 / 常量过大）。

### 3.3 非短路求值

逻辑与/或在应用运算符之前已经求值完所有子表达式（求值驱动统一先求全部子节点），所以被常规布尔短路跳过的分支里的除零等错误仍会被报告。

## 4. 并发与复杂度

- `Registry` 用 `sync.RWMutex` 保护；内部持有的是不可变 `snapshot`（一个 map）。
- 登记：在锁内做重复名检查、在**当前快照**上求值，全部成功后才复制 map、写入新条目并一次性发布（写时复制）。任何失败路径都不触碰已发布快照 → “被拒绝的登记不改变任何状态”。
- 求值与 `Lookup`：只取一次快照引用，之后在不可变 map 上无锁读取。线性化点是快照发布/读取，语义等价于某个串行顺序。
- 查询与引用均为 map 直达，**O(1)**，与已登记常量总数无关。
- 命名常量在登记时即求定为不可变 `Value`；表达式里的 `Ref` 在求值时只取该固定值，**不沿引用链展开**，因此与引用链深度无关。`Value` 进出登记表都深拷贝，外部无法污染内部状态。
- 复杂度结论由 `BenchmarkLookupIndependentOfSize`（100 vs 10000）与 `BenchmarkRefIndependentOfChain`（链深 10 vs 1000）以 ns/op 基本不变的方式给出可验证证据。

## 5. 关键取舍

- **f64 用精确分数做中间值**：有类型浮点常量折叠不采用 IEEE-754 逐步舍入，而是全程 `big.Rat`，仅在可表示性检查/读取时舍入到最近偶数。这满足“双精度浮点、舍入并列取偶、舍入到无穷报越界”，且避免逐步舍入带来的平台差异。这是对常量表达式场景的刻意选择。
- **比较结果恒为无类型布尔**：贴近“比较产出无类型常量、需要时再转换”的常规静态语义，也使有类型比较能自由参与无类型布尔逻辑。
- **三阶段求值**：用独立的结构校验与名字解析阶段换取清晰的错误优先级证明，避免“遍历时边解析名字边求值”带来的顺序耦合。
- **值不可变 + 边界拷贝**：换取并发安全与对外别名安全，代价是少量大整数拷贝。

## 6. 被放弃 / 未采用的方案

- **运行时用 `interface{}` 表示值**：放弃。弱类型载荷会把种类错误推迟成 panic，且难以保证“截断 vs 越界”的精确区分；强类型 `Value` 让非法组合在运算层显式报错。
- **引用在求值时递归展开命名表达式**：放弃。会让引用成本随链深增长，且登记表变更会影响旧引用；改为登记时求定固定值。
- **读写全程持锁**：放弃。会把求值串行化；改为快照无锁读，仅登记短时持锁。
- **用原生 float64 做 f64 中间运算**：放弃。无法表达精确分数，且 NaN/中间舍入难以界定“越界”；改用 `big.Rat` + 边界舍入。
- **短路逻辑运算**：按需求明确放弃，所有子表达式一律求值。

## 7. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache   # 若默认缓存目录只读

go build ./...
go vet ./...
gofmt -l .

# 全量测试（含 6000 例随机对拍）
go test ./...

# 竞态检测
go test -race ./...

# 查看每次随机输入/输出/判定依据
go test ./constexpr/ -run TestRandom -v

# 覆盖率
go test -cover ./constexpr/

# O(1) 复杂度证据
go test ./constexpr/ -bench . -benchmem
```

## 8. 测试覆盖对照

需求中的每一项都有对应用例：

- 无类型任意精度中间值落回范围 vs 有类型每步越界：`TestUntypedPrecisionVsTypedStep`。
- 整除 vs 精确除法的种类选择：`TestDivisionKindSelection`。
- 负数取余与右移取整：`TestRemainderAndShr`。
- 浮点并列取偶与舍入到无穷：`TestFloatRoundingTiesToEven`。
- 整数/有理数转换边界（截断 vs 越界可区分）：`TestConversionBoundaries`。
- 512 位边界（字面量与中间结果）：`Test512BitBoundary`。
- 短路分支里的错误仍报告：`TestNoShortCircuit`。
- 错误优先级（跨阶段与单节点、从左到右）：`TestErrorPriority`、`TestStructureInvalid`、`TestRegistryBasicAndPriorities`。
- 命名常量登记/拒绝原子性/固定值/引用链：`TestRegistry*`、`TestRegistryValueFixedAtRegistration`、`TestRegistryChainDepthO1`。
- 并发串行等价：`TestRegistryConcurrent`（`-race`）。
- 朴素模型随机对拍与逐次日志：`TestRandomDifferential`（4000 无类型）、`TestRandomTypedDifferential`（2000 有类型）。
