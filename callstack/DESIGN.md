# 调用栈管理子系统设计说明

1. 模块划分：`tailpos.go` 纯语法尾位置标注与槽位解析；`frame.go` 帧与保护区域、回溯快照；`eval.go` 求值与调用判定；`runtime.go` 帧栈、深度/配额、复用事务、异常传播、日志；`naive.go` 不复用的对照模型；`errors.go` 错误类别。
2. 尾位置是登记期一次性自顶向下标注的布尔位（`Call.Tail`），运行期判定只读字段，为 O(1)，与函数体大小无关。
3. 规则：函数体末调用、If 两分支末调用、Seq 末项为尾；参数位置、参与运算者、Try 受保护区内（含最末）一律非尾；Handler 末调用为尾。
4. 尾调用复用同一物理帧：替换局部数组、深度不变，原帧函数名不再出现；被省略数累加进保留帧的 `folded`，非尾调用入栈时归 0。
5. 帧身份 `id` 绑定保护区域；尾复用产生新 id，旧帧区域按 id 立即失效，异常不会被已替换帧的 Try 截获。
6. 复用是单临界区事务：所有失败校验（undefined>arity>quota）在改帧前完成，提交函数不会失败；因此配额不足时原帧参数/局部/回溯原样保留。
7. 尾调用豁免深度检查（不加深），但按“先释放旧帧再计新帧”做净增量配额检查；非尾调用深度与配额同时违例时报深度错误。
8. 异常用内部 panic 传播；非尾帧在展开 defer 中逐帧登记并弹出，尾链仅余的当前帧在顶层补登记，故未处理异常的路径含全部物理帧及各自折叠计数。
9. 一次顶层调用全程持互斥锁，统计与回溯在同一把锁内拷贝，读者只可能看到调用边界，杜绝半调用中间态；另用 `execMu` 串行化同实例调用、协调 Close。
10. 回溯每帧仅存一个折叠整数，读取为 O(物理帧数)，不随历史省略数增长。
11. 被放弃方案：用 AST 路径在运行期实时判定尾位置（开销随体增长，否决）；让尾调用也压帧再弹（无法保证常量栈深，否决）；读时加读写锁让步（会暴露半调用态，否决）。
12. 本地验证：`go test -race ./...`；覆盖语法正反例、深度/配额取等、复用事务回滚、折叠累加归零、异常跨省略帧、400 组随机程序与朴素模型对照、并发读取一致性与日志断言。
