# defassign 设计说明

## 模块划分
- `program.go` 程序结构登记：`Registry` 按注册序发节点 ID（即位置），树形 IR。
- `validate.go` 输入校验与错误：四类错误按固定次序拒绝（环 > 未声明变量 > 跳出非法 > 分支归属非法），出错即整体拒绝，无部分诊断。
- `cfg.go` 结构树 lowering 为 CFG；回边单独标记，供活性分析使用、被定值分析忽略。
- `flow.go` 路径状态传播：前向定值分析（DAG 拓扑序）+ 后向活性分析（含回边，迭代不动点）。
- `diagnose.go` 诊断生成、排序与确定性渲染；`checker.go` 为无状态门面，可并发。

## 关键取舍
- 状态用「路径切片」表示：每个程序点是一组 (决策 token 序列, 已赋值集合) 切片，
  汇合只做切片拼接，读取判定 = 检查全部切片。因此答案客观唯一，且每条
  「可能未赋值」诊断都能列出精确的到达路径。
- 汇合处不做逐变量求交（切片天然分离），故汇合开销与未涉及变量数无关；
  读取判定只扫描到达该点的切片数，与程序总长无关。两者由 `Stats` 计数器
  在 `perf_test.go` 中以对照实验客观证明（非计时，避免抖动）。
- 循环对定值分析忽略回边（上一轮赋值不可见），对活性分析保留回边
  （下一轮可能读取），两条规则由此各自一句话落地。
- 异常保护结构按题面语义建模：try 头 → 各处理分支 / 清理区（未处理抛出），
  体正常结束与处理分支结束也汇入清理区；清理区跳出则后续不可达。

## 被放弃的方案
- 位向量/集合交的经典定值分析：无法给出「到达路径」诊断，且汇合要扫描
  全部变量，不满足复杂度口径。
- 对循环做真正的不动点迭代：题面明确拒绝上一轮赋值，单遍即可，不动点
  反而引入近似。
- 抛边从体内每个点连出：语义等价于「进入前状态」，但会引入 O(体长) 条
  等价边，简化为从 try 头出发。

## 本地验证
- `go test ./defassign/`：语义单测（分支/常量条件/循环/跳出/异常结构/无效赋值/错误次序）。
- `model_test.go`：独立朴素模型（枚举全部执行路径逐步模拟）与随机程序对照，
  并打印每条输入、实际输出与判定依据（`go test -v` 可见）；含并发与逐字节确定性测试。
- `perf_test.go`：用 `Stats` 计数证明两条复杂度保证。
- `go test -race ./...`、`go vet ./...`、`gofmt -l .`。
