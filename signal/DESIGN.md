# 信号配时控制与绿波协调 — 设计说明

## 模块划分
- `signal/types.go`：相位、方案、请求状态、查询结果等公共类型。
- `signal/errors.go`：七类可区分错误，常量声明顺序即上报优先次序。
- `signal/engine.go`：事件驱动核心——槽（绿+清空）状态机、紧急服务四阶段、稳态整循环快跳。
- `signal/resync.go`：偏离量归一化与单循环绿时调整分配。
- `signal/controller.go`：互斥锁串行化的公开 API、校验次序、高水位状态快照。
- `signal/naive/`：独立编写的逐秒推进参照模型，仅用于对照测试。

## 关键取舍
- 相位槽 = 绿灯 + 清空，清空期归属该相位；循环在相位序号回绕时结束，
  方案变更与回归调整均在回绕瞬间生效，与"循环结束同一时刻"的查询/操作语义一致。
- 偏离量 = 当前相位实际起点与计划起点之差，归一化到 (-C/2, C/2]，半周期取延长方向。
- 回归每循环从设定绿时重新分配调整量（按相位序、受最小/最大绿约束、总量受上限），
  不跨循环累积工作绿时，避免分布漂移导致周期中段相位永远无法对齐。
- 紧急服务结束于目标相位清空结束；后继请求此刻开始服务，保证服务决策总落在绿灯起点。
- 连续跳相约束在受理时判定：以受理时刻循环序号与预测被跳相位，拒绝上一循环
  刚跳过相同相位的请求（保守但确定、可在受理点判定）。
- 被拒绝操作不留痕：全部校验在受理前完成；查询在状态副本上推进，
  真实状态只随被接受操作前进，时钟只记录最后被接受操作时刻。
- 查询 O(1)：无紧急活动、无待生效方案且循环干净（cleanCycle 且 steady）时按周期
  算术快跳；单次推进事件数 ≤ 排队服务数 + 回归循环数（≤C/2，方案参数有界）+ 2N + 1，
  与已过去循环数无关，由 TestQueryComplexityBound 的事件计数断言证明。

## 被放弃的方案
- 逐秒推进作为主实现：查询开销随时间增长，放弃，仅保留为对照模型。
- 工作绿时跨循环累积修正：相位级计划前缀无法对齐，偏离永不归零，放弃。
- 跳相约束推迟到实际跳变时判定：请求已受理无法再拒绝，放弃。

## 本地验证
- `go test ./...` 与 `go test -race ./...`：全部场景测试通过、无数据竞争。
- `go test ./signal -run TestRandomOpsAgainstNaive -v`：60 个种子随机操作序列与
  朴素逐秒模型逐步对照，日志打印每条操作的输入、输出与判定依据。
