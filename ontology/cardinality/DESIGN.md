# 链接关联基数约束：并发名额分配设计说明

## 1. 问题与目标

链接类型在某个基数约束作用域（链接类型 + 源实例 + 目标实例）上声明了
关联数量上限 `limit`。新建关联是一个两阶段过程：请求方先**预留**一个名额，
随后才把关联写入存储并**提交**（或在失败时**中止**）。

核心风险是"幻影"式基数绕过：多个并发请求各自读到"还有名额"，于是都获批，
最终关联总数超过上限。设计必须满足：

1. 进行中（已预留、未终结）的请求立即占用名额，即使它后来失败；
2. 失败释放必须原子且对新请求立即可见，被拒请求不自动重试；
3. 三类拒绝原因互斥且判定顺序固定：**基线冲突 > 已确认达上限 > 进行中占用**；
4. 严格同时争夺最后一个名额时恰好一成一败；
5. 判定开销只与当前进行中请求数相关，不随历史关联/请求总数增长；
6. 并发结果等价于某种串行顺序；
7. 被拒绝请求对关联关系、版本号、时钟零副作用；
8. 调用方中断（既不提交也不中止）的悬置请求有唯一的名额释放裁定依据；
9. 提供无需额外对外暴露状态即可验证的证据（审计日志与计数快照）。

## 2. 核心模型：预留即占位（reserve-hold-finalize）

每个作用域只维护两个纯计数与一个进行中集合：

- `committed int64`：已确认关联数，同时充当作用域逻辑时钟/基线版本，
  仅在成功 `Commit` 时 +1；进行中预留不推进版本；
- `inflight map[id]*reservation`：当前存活预留，每个预留带
  租约截止时刻 `deadline`；
- 判定瞬间剩余名额：`remaining = limit - committed - |live inflight|`。

一次 `Reserve` 在**同一把互斥锁的同一个临界区**内依次完成：

1. 回收全部 `deadline <= now` 的悬置预留；
2. 基线版本校验（`ExpectedV != committed` → 基线冲突）；
3. 已确认数达上限（`committed >= limit` → 已确认满）；
4. 剩余名额被进行中请求占用（`remaining <= 0` → 暂时性拒绝）；
5. 以上皆否则立即把本请求插入 `inflight`（占位），记录审计后返回。

由于"检查 + 占位"原子完成，最后一个名额在任意并发交错中只会被一个请求
拿到：锁保证临界区串行，先入者占位，后入者必然观测到 `remaining = 0`。

终结语义：

- `Commit(id)`：`inflight` 名额原子转为 `committed++`（版本 +1）；
- `Abort(id)`：仅从 `inflight` 删除，`committed` 与版本不变；锁释放后
  下一个到达的请求立即看到空出的名额。此前被拒的请求不会被唤醒重试
  （系统不持有等待队列）；
- `Commit/Abort` 对未知/已终结 ID 幂等返回 `false`，无副作用。

## 3. 调用方中断的唯一裁定依据：租约（lease）

悬置请求"何时不再占用名额"必须有唯一、可判定的依据，否则只能在
"永久泄漏名额"与"提前释放导致超卖"之间二选一。本设计采用
**单调时钟上的租约截止时刻**：

- 预留获批时返回 `deadline = now + ttl`；
- 存活条件严格定义为 `now < deadline`；`now == deadline` 即算可回收，
  边界无歧义；
- `Heartbeat(id, ttl)` 可在过期前置续截止时刻；一旦过期，预留不能复活；
- 回收在两个地方以**完全相同**的规则发生：
  - 惰性：任何 `Reserve/Commit/Abort/Heartbeat/Stats` 进入临界区时；
  - 显式：`Sweep()`，返回被回收 ID。

因此：在确证中断（时钟越过截止时刻）前绝不提前释放；一旦确证，
名额立即释放，不存在不确定窗口，也不会被永久占用。时钟被抽象为
`Clock` 接口，生产实现基于进程启动后的单调时间（免疫墙钟回拨），
测试用 `FakeClock` 确定性推进，从而可以精确重放"过期前一纳秒 /
恰好过期"的瞬时边界。

## 4. 互斥拒绝原因与判定顺序

| 顺序 | 条件 | ReasonCode |
| --- | --- | --- |
| 1 | 作用域未知，或 `ExpectedV != committed` | `ReasonBaselineConflict` |
| 2 | `committed >= limit` | `ReasonCommittedFull` |
| 3 | `limit - committed - inflight <= 0` | `ReasonInflightOccupied` |

顺序用单一临界区内的 `switch` 式短路保证：基线落后时即使名额已满也只报
基线冲突；已确认数满时即使有进行中占用也只报"已确认满"。未知作用域按
基线冲突处理，且**不隐式创建作用域**，保证拒绝路径零副作用。

## 5. 拒绝路径的零副作用与证据

需求同时要求"被拒绝不得改变任何时钟状态"和"完整记录可重放"。二者的
调和方式是区分**约束状态**与**审计设施**：

- 拒绝不会创建作用域、不插入预留、不修改 `committed`、不推进任何
  作用域/实例版本；被拒 ID 从未进入存活索引，对其 `Commit/Abort`
  是 no-op。外部可观察的约束状态与"请求从未发生"不可区分；
- `Manager.AuditLog()` 是专门的可验证设施：每次尝试（含拒绝与终结、
  过期回收）追加一条不可变 `Event`，其在日志中的追加位置就是严格
  单调的全局判定序号（不依赖任何额外业务计数器）。事件包含：
  到达时刻 `NowNanos`、完整 `Decision`（期望/观察版本、拒绝原因、
  `CounterSnapshot{committed, inflight, limit, remaining, seq}`）、
  事件后的 `committed/inflight` 计数与最终结果。

`CounterSnapshot` 与判定在同一临界区生成，是无需对外暴露任何额外
可变状态即可核验的证据：给定审计日志即可逐步重放每个判定。

## 6. 复杂度

- `Reserve`：`O(k)`，`k` = 当时全局存活预留数（过期回收扫描 +
  map 插入）；与该链接类型历史关联总数、历史请求总数无关。
  实际部署中 `k` 受并发度约束，且过期条目在每次临界区入口被清除，
  不会随历史累积；
- `Commit/Abort/Heartbeat`：`O(k)`（过期回收）+ `O(1)`（map 操作）；
- 存储：`O(当前存活预留数 + 审计保留窗口内事件数)`。

## 7. 串行等价性

所有状态变更都经过同一把锁，每个事件在临界区内被赋予全局审计序号。
任意并发执行交错都对应"按审计序号排列"的一个串行历史；该历史中每步
的计数与判定原因都由审计快照固定。测试用两个独立角度验证：

1. **朴素模型对照**：`NaiveOracle`（测试内独立实现的全局串行大锁模型）
   与 `Manager` 执行同一份随机脚本，逐步比对接受/拒绝原因、终结结果、
   过期收割集合与最终总数；
2. **审计重放**：真实多 goroutine 并发跑完后，把审计日志喂给
   `NaiveOracle` 逐步重放，要求每一步的 committed/inflight 与原因
   完全重现。

## 8. 关键取舍与被放弃的方案

- **放弃"读时计数 + 无预留"方案**：两阶段创建中，只在最终提交时检查
  无法感知尚未提交的他人尝试，必然幻影超卖。改为预留即占位。
- **放弃条件变量/等待队列重试**：自动唤醒重试会让"被拒"变成延迟决定，
  语义模糊且可能造成群惊；需求明确拒绝自动重试。被拒方收到明确原因后
  自行决定重试时机。
- **放弃分布式锁/事务 token 方案**：本任务是单进程内的基数仲裁器，
  单把互斥锁即可给出线性化语义且实现可审计；跨进程一致性（租约续约、
  fencing token）是清晰的后续扩展点，但不应为此引入当前不需要的复杂度。
- **选择租约而非引用计数/显式取消唯一论**：网络与调用方崩溃使显式
  Abort 不可靠；租约以单调时钟给出唯一裁定依据。边界采用
  `now < deadline` 存活（相等即过期），消除临界时刻歧义。
- **放弃按历史关联表实时 COUNT**：开销随关联总数增长，且无法计入
  进行中尝试。纯计数器 + 进行中集合使开销只取决于当前并发度。
- **审计序号复用日志追加位置**：避免为"拒绝也要有序号"而维护一个
  被拒绝请求也会推进的全局时钟（那会违反拒绝零时钟副作用）。
- **基线版本即 committed 计数**：进行中预留不推进版本，既符合"版本
  只反映已确认事实"，也让基线落后检测自然覆盖"他人已提交"的情形。

## 9. 代码结构

- `types.go`：作用域、原因码、判定、计数快照、审计事件等类型；
- `clock.go`：`Clock` 接口、`SystemClock`（单调）、`FakeClock`（测试）；
- `manager.go`：`Manager`（`EnsureScope/Reserve/Commit/Abort/
  Heartbeat/Sweep/Stats/Committed/AuditLog`）；
- `manager_test.go`：判定顺序、拒绝零副作用、租约边界、证据等单测；
- `concurrency_test.go`：单名额 N 方争夺、Abort 释放瞬时窗口、
  连续多轮不超限（`-race`）；
- `oracle_test.go`：独立朴素串行模型与随机脚本逐步等价性；
- `replay_test.go`：真实并发审计日志的逐步重放核验。

## 10. 本地验证

```bash
# 全量测试（若默认 GOCACHE 只读，可指定可写缓存目录）
GOCACHE=/tmp/gocache go test ./...

# 竞态检测 + 多轮重复
GOCACHE=/tmp/gocache go test -race -count=5 ./ontology/cardinality/

# 定向用例
GOCACHE=/tmp/gocache go test -race -v \
  -run 'TestConcurrentSingleSlotContention|TestAbortReleaseInstantWindow|TestRepeatedRoundsNeverOverLimit|TestRandomizedScriptMatchesNaiveOracle|TestConcurrentRandomAgainstReplay' \
  ./ontology/cardinality/

gofmt -l .
go vet ./...
```

随机脚本测试默认 300 个种子 × 每脚本 120 个操作；可通过提高试验次数
进一步加压力。所有时间相关用例均使用 `FakeClock`，无真实睡眠，确定性
可重放；真实并发用例使用墙钟 + 长租约（`time.Hour`）以排除意外过期。
