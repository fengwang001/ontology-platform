# 本体链接图环检测器设计说明

## 1. 范围与语义

`Graph.HasCycle(caller)` 判定的对象，**只是调用者当前权限下可见且可遍历的链接构成的子图**。
子图之外的对象与链接一律当作不存在：它们既不会被枚举，也不会影响任何结果或性能度量。

判定严格按下列固定次序执行（次序是语义的一部分）：

1. 参数校验：`caller` 为空或未登记 → `ErrInvalidCaller`（最高优先）。
2. 存在性过滤：剔除调用者没有存在性权限的对象，以及与这些对象关联的全部链接。
3. 遍历过滤：在剩余链接中剔除调用者没有遍历权限的链接。
4. 可见对象集合为空 → 直接返回“无环”（非错误）；否则在剩余有向图上判定环。

链接按其 `Direction` 展开为有向弧：

- `Directed`：仅 `Source → Target` 一条弧；
- `Bidirectional`：`Source → Target` 与 `Target → Source` 两条弧。

因此长度为 1 的自环（`u→u`）计入；同一对对象沿同一条双向链接的往返
（`u→v`、`v→u`）构成长度为 2 的环也计入；而单向链接的单条弧不构成环。
同一对象对之间的多重同类型链接在环判定中**去重**：它们展开出的是同一组
有向弧，因此只贡献一次，环证据中也不会出现重复对象。

## 2. 关键取舍

### 2.1 先取不可变快照，再判定（并发正确性）

`Graph` 内部用一把 `sync.RWMutex` 保护全部状态。`HasCycle` 在读锁内调用
`takeSnapshot` 一次性构建好过滤后的子图快照（对象列表、邻接表、度量），
随后释放锁并在**局部快照**上完成全部判定。写操作（增删对象/链接、权限
变更）取写锁。因此：

- 任意一次 `HasCycle` 看到的状态对应串行历史中的某一个确定时刻，不可能
  读到链接增删或权限翻转的中间状态；
- 多次只读 `HasCycle` 与并发写天然可线性化，不存在跨调用缓存结论，
  权限补齐后下一次独立调用立即看到“无环→有环”的变化。

放弃的方案：懒加载/带缓存的可见子图（需要失效协议，且容易延用旧结论）、
读写分别加细粒度锁（在本体规模下没有收益，却引入锁序风险）。

### 2.2 权限过滤只沿“调用者被授权的集合”枚举（复杂度保证）

存在性权限以 `caller → set[objectID]` 的倒排集合保存。`takeSnapshot`
第一步只遍历该调用者被授权且仍存在的对象，随后只枚举这些对象的关联链接
（`objLinks` 反向索引），完全不扫描全图对象表与全图链接表。由此，判定开销
只随调用者可见子图规模增长，向图中追加该调用者完全不可见的对象与链接时，
访问计数保持不变。`TestMetricBoundedByVisibleSubgraph` 以 3 个可见对象 +
2000 个不可见对象/链接验证了这一点。

放弃的方案：全表扫描后逐条判权限（会让“无权限”的对象也产生线性开销，
直接违反题面的度量要求）。

### 2.3 确定性的规范证据（与起始对象/访问顺序/历史无关）

环检测在去重后的有向图上，对按 ID 升序排列的每个根做 BFS，求以该根为
最小 ID 顶点的最短回到根的环；全局取**长度最短**、等长则取**规范旋转
（以环中最小 ID 为起点的唯一旋转）字典序最小**的环。最终输出统一转成规范
旋转。该规则只依赖当前拓扑与 ID 全序，与：

- 从哪个对象开始搜索、邻接表以什么顺序访问；
- 对象/链接创建的历史先后；
- 两次调用之间穿插了多少只读查询，

全部无关。同一状态下任意次调用返回的布尔值与证据序列逐一相同。证据本身是
一个简单有向环（顶点不重复、首尾闭合），因此天然是“环所涉及的最小对象集合
之一”——去掉其中任一顶点该环即被破坏，且不含任何无关对象。

选择最短环（BFS）而非 DFS 回溯任意环：任意 DFS 环对边/邻接顺序敏感；
最短 + 字典序的规范规则可直接论证其唯一性。放弃的方案：Johnson/SCC 后枚举
所有基本环再选（实现复杂、最坏情况环数量指数级，对本题没有必要）。复杂度为
O(V·(V+E))，V、E 均为可见子图规模。

### 2.4 内部度量

`CycleResult.VisitedObjects` / `VisitedLinks` 是内部可验证字段（文档注明不
构成对外语义承诺）：分别是第一步过滤后的可见对象数，与“第一步后保留、实际
被检查过”的两端皆可见的去重链接数（包含因缺少遍历权限在第二步被排除的
链接——这些链接确实被检查了）。随机对照测试中用独立 oracle 重放同一操作序列
并逐项核对这两个数字。

## 3. API

- 类型：`ObjectType`、`LinkType{ID, Direction, AllowSelfLoop, AllowMultiple}`、
  `Link{ID, Type, Source, Target}`、`Direction`（`Directed`/`Bidirectional`）。
- 变更：`AddObjectType` / `AddLinkType` / `AddObject` / `DeleteObject` /
  `AddLink` / `DeleteLink`。写链接时强制校验：未知类型、悬空端点、
  禁止自环、禁止同对象对重复同类型链接（双向类型的重复按无序对判定）。
- 权限：`RegisterCaller`、`GrantExist`/`RevokeExist`、
  `GrantTraverse`/`RevokeTraverse`。新链接不默认授予任何调用者遍历权限。
  对象/链接被删除时同步清理各调用者的授权集合。
- 判定：`HasCycle(caller) (CycleResult, error)`；
  `HasCycleWithView` / `VisibleArcs` 返回同一快照的只读弧视图，供内部验证
  证据与判定来自同一时刻，不改变判定语义。

## 4. 被放弃的方案汇总

- 无向图环判定：不满足方向语义（单向单弧不应成环、双向才允许往返）。
- DFS 三色 + 回溯边直接出证据：快但证据随遍历顺序变化，无法满足“证据逐一
  相同”的强确定性要求。
- 全量枚举基本环：最坏指数级，且还需额外的选择规则。
- 跨调用缓存可见子图/结论：与“权限变更必须被下一次调用立即感知”冲突。
- 全表扫描过滤：违反不可见规模不计开销的要求。

## 5. 本地验证方法

```bash
go test -race -v ./ontology/
go vet ./...
gofmt -l .
```

测试矩阵：

- `TestSelfLoop`：自环计入；撤销遍历权限后环消失；
- `TestBidirectionalRoundTrip`：单向不成环、双向往返成 2-环；
- `TestOnlyCycleLinkExcluded`：唯一闭合边无遍历权限时无环，补齐后立即有环；
- `TestExistFilterOrder`：即使有遍历授权，端点不可见时边先被存在性过滤剔除；
- `TestEmptyVisible` / `TestInvalidCaller`：错误/特殊结果次序；
- `TestParallelLinksNotDuplicated`：5 条平行双向链接只得到一个 2-环证据；
- `TestLinkTypeConstraints`：禁止自环/禁止多重链接的写入校验；
- `TestDeterminismAcrossCalls`：同一状态 20 次调用穿插只读查询，结果与证据逐一相同；
- `TestOrderIndependenceInternal`：直接打乱根顺序与邻接顺序，规范环不变；
- `TestMetricBoundedByVisibleSubgraph`：追加 2000 个不可见对象/链接后度量不变；
- `TestConcurrentLinearizable`：并发增删闭合边与 4×1500 次判定（-race），
  每次证据都由同一快照的弧支撑；
- `TestRandomDifferential`：400 轮随机对象/链接/方向/权限翻转序列，与两个
  独立朴素模型（Kahn 拓扑排序、染色 DFS）对照布尔结果，并用独立 BFS 核对
  最短环长度与度量，同时校验重复调用一致性。

每次对照调用的输入（可见对象数、候选链接数、调用者）、输出（是否有环）与
证据（环对象序列）记录于 `ontology/testdata/has_cycle_calls.csv`（7000+ 行）。
