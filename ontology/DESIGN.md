# 提交图合并基选择器

`ontology.Graph` 支持登记带父提交的提交，并查询任意两个提交的**全部**最佳公共
祖先（merge bases）。所有接口并发安全，登记与查询可被并发调用，结果等价于某个
串行顺序；相同的登记序列重放得到完全相同的结果。

## 数据模型

- `Commit(id, parents)`：`id` 为非空字符串；`parents` 含 0~8 个**互不相同且已
  登记**的提交 id。父必须先于子登记，故图天然是有向无环图（边由子指向父）。
- 无父提交为根。父列表的顺序不影响任何结果（世代号取 max、祖先关系与合并基
  只依赖父集合）。
- 提交是其自身的祖先（自反闭包）。

## 世代号（generation）

```
g(root) = 1
g(c)    = 1 + max(g(p) for p in parents(c))   // 非根
```

世代号沿父边严格递减：若 `a != b` 且 `a` 是 `b` 的祖先，则
`g(a) < g(b)`。因此：

- `g(a) > g(b)` 可立即判定 `a` 不是 `b` 的祖先（`IsAncestor` 与
  `containsLocked` 都以此剪枝）；
- 从某提交沿父边遍历时，只需进入世代号更小的父。

## 合并基定义

- 公共祖先集合：`CA(a,b) = Anc(a) ∩ Anc(b)`。
- 合并基：`CA` 中的**极大元**，即 `c ∈ CA` 且不存在另一个
  `c' ∈ CA` 使 `c` 是 `c'` 的真祖先。
- 结果全部返回，按 id 字节序（`sort.Strings`）升序。

直接推论：

- `a` 是 `b` 的祖先（含 `a == b`）时，结果恰为 `{a}`；
- 两端属于互不相连的组件（例如两棵独立的树）时 `CA` 为空，结果为空切片且
  不报错；
- 交叉合并（criss-cross）可有多个合并基。根 R 下 X、Y 两个子提交，
  `M1=merge(X,Y)`、`M2=merge(Y,X)` 时 `MergeBases(M1,M2) = {X,Y}`，
  R 虽是公共祖先但是 X/Y 的祖先，被支配而剔除。

## 算法与世代号剪枝

`MergeBases` 使用双向洪泛（与 Git `paint_down_to_common` 同一思路）：

1. 从 a、b 两端分别注入 `sideA`、`sideB` 标记，放入按世代号降序的堆
   （同世代按 id 升序，保证确定性）。
2. 弹出世代号最大的提交 c：
   - 若它同时带两侧标记，记为**候选公共祖先**，并**停止从该点继续洪泛**
     （其祖先经由 c 的可达性已被 c 代表）。
   - 否则把它拥有的标记仅传播给世代号严格更小的父；父若得到“新标记”就
     （重新）入堆。
3. 标记仍可能经由不经过任何汇聚点的旁路抵达更老的公共祖先。这些老候选一定
   是某个世代更大候选的祖先，故最后按定义做极大元过滤：候选 x 若以候选集合
   中任一其他候选 y 为后代（`x ∈ Anc(y)`），则剔除 x。

**剪枝依据**：世代号沿父边严格递减。

- 洪泛在汇聚点停止且只在“两端到汇聚点之间”的世代范围内活动，不会沿汇聚点
   之上的长历史上溯；
- 在线性主干（长度 N）末端分出两条各 10 个提交的分支时，只会访问两条分支的
   20 个提交加 1 个分叉点，共 **21 个**。非导出计数器 `visits`
   （测试经 `lastMergeBaseVisits()` 读取）证明 N=1000 与 N=100000 下遍历数
   完全相同（都是 21），与历史总长度无关。

正确性另由对拍兜底：测试内的朴素实现先求两侧全祖先集合、取交集、再逐点取
极大元，在 2000 组随机 DAG 的随机查询上与快速实现结果逐一一致。

## 错误优先级

错误为 `*ontology.Error`（可用 `ontology.AsError` 提取），其 `Reason` 字段给
出稳定、可区分的机器可读原因，`ID`/`Index` 给出触发位置。

`Commit` **严格按以下顺序只报第一个**，且被拒绝时图不发生任何改变
（校验全部通过后才写入）：

1. `empty id`：id 为空字符串；
2. `duplicate id`：id 已登记；
3. `too many parents`：父列表超过 8 个；
4. `duplicate parent`：父列表含重复（`Index` 为首次出现重复的最小下标）；
5. `parent not registered`：父未登记（`Index` 为最小下标）。

查询类接口对未登记 id 的原因彼此可区分，并遵循 **a 先于 b**：

- `Gen`：`gen: unknown id`；
- `IsAncestor`：`isancestor: unknown a` → `isancestor: unknown b`；
- `MergeBases`：`mergebases: unknown a` → `mergebases: unknown b`。

## 并发与重放

- 写操作取互斥锁，读操作（`Gen`、`IsAncestor`、`MergeBases`）取读锁；
  因此任意并发交织都等价于某个合法的串行顺序（可线性化）。
- 世代号在登记时一次性算好，登记后不可变；父列表做防御性拷贝，避免调用方
  后续修改切片影响图。
- 登记序列与父集合（而非父顺序）决定全部结果，故相同序列重放结果完全一致；
  同世代堆序按 id 升序，保证遍历顺序确定。

## 本地验证

```bash
# 需 Go 1.26+
go test ./...

# 竞态检测 + 详细日志（含随机对拍的输入/输出/判定依据、剪枝计数器）
go test -race -v ./ontology/

# 只看剪枝证明与 2000 组对拍
go test -v -run 'TestGenerationPruning|TestDifferentialAgainstNaive' ./ontology/

gofmt -l .
go vet ./...
```

测试覆盖：交叉合并 `{X,Y}`（不含 R）、a 是 b 的祖先、a==b、互不相连的根、
三父章鱼合并、世代号相等但互不相同/互不为祖先、Commit 拒绝次序与未登记 id
原因，以及 2000 组随机 DAG 与朴素实现的对拍（`-v` 日志打印每组输入、输出与
判定依据）。
