# 版本向量因果稳定墓碑回收器（`ontology` 包）

## 数据模型

- `Store` 维护 `n` 个副本（`New(n, logWriter)`）。
- 每个键保存且仅保存当前“赢家”条目 `Entry{Vector, Value, Tomb}`。
- 每个副本维护一个“已见最高向量”时钟 `clocks[r]`：任何被它接收的事件
  （即使因过旧而被忽略）都按**逐分量取最大**并入该时钟，因为该副本至少
  已经产出或追平了这个向量。
- `guards`（墓园林）记录每个被回收键在回收时刻的墓碑向量，用于挡住墓碑
  消失后才迟到、向量又不大于墓碑的旧事件，防止“已删键被旧事件复活”。

## 版本向量比较：分量顺序字典序

写入/删除携带长度为 `n` 的版本向量。比较两个向量时，从第 0 个分量开始
顺序比较，**第一个不相等的分量**决定新旧（lexicographic / 全序）：

- 新事件向量严格大于当前赢家向量 → 接受，覆盖旧值或墓碑；
- 相等（重复）或更小（迟到）→ 忽略，存储不变；
- 副本时钟不受此判定影响：无论接受还是忽略，时钟都照常逐分量取最大。

例（`n=3`）：当前 `[1,0,0]`，事件 `[0,2,0]` 虽然第 1 分量更大，但第 0
个分量已更小，整体是旧事件，被忽略；`[2,0,0]` 才是更新。

## 稳定向量

```
stable[c] = min over replicas r of clocks[r][c]
```

即各副本时钟**逐分量取最小值**。其含义：`stable` 上的每个更新都已被所有
副本见到。因为各时钟只按分量取最大、从不回退，所以稳定向量天然单调：
任意连续两次查询，后一次逐分量不小于前一次。

## 回收判定规则

`Reclaim()` 移除同时满足以下两个条件的条目：

1. 该条目是墓碑（`Tomb == true`）；
2. 墓碑向量**逐分量不超过**当前稳定向量：
   `forall i: vector[i] <= stable[i]`（分量偏序，不是字典序）。

判定安全的理由：稳定点之前的所有更新都已被全部副本见到，任何针对该键
且可能晚于删除的事件，其向量必在某个分量上大于稳定向量，从而不可能被误
回收；仍有分量超过稳定前沿的墓碑继续保留。返回值为本次移除的键，按字典
序排序；全部历史回收键可用 `ReapedKeys()` 查询（同样排序）。

被回收键的墓碑向量进入 `guards`：之后到达的事件若向量不大于该防护向量，
一律忽略（时钟仍推进）；只有严格更新的事件才能重新创建该键，并在创建时
清除防护，交回普通赢家条目负责冲突判定。因此旧事件既不能在墓碑存活期
复活已删键，也不能在墓碑回收后“凭空”重建它。

## 非法输入与批原子性

以下情况返回互不相同、可用 `errors.Is` 判定的哨兵错误：

- `ErrInvalidReplicas`：`New` 时副本数非正；
- `ErrReplicaOutOfRange`：事件副本编号越界（`r < 0` 或 `r >= n`）；
- `ErrNegativeVector`：向量含负分量；
- `ErrEmptyKey`：键为空串；
- `ErrVectorLength`：向量长度不等于副本数。

`Apply([]Event)` 先整批校验再落盘：批内任一条非法，整批不生效——条目、
副本时钟、稳定向量、已回收列表均不改变。

## 并发与自检

- 所有读写由单一 `sync.RWMutex` 保护；`StableVector`、`Reclaim`、`View`、
  `ReapedKeys`、`SelfCheck` 可与写入及彼此并发调用。
- `View()` 返回深拷贝快照（含时钟、条目、防护、稳定向量），调用方可任意
  修改；静止状态下并发只读得到的视图逐字段相同（`reflect.DeepEqual`）。
- 日志输出另用独立互斥保护，可直接传入 `os.Stderr` 或 `bytes.Buffer`。
- `SelfCheck()` 校验时钟/向量长度与非负、条目与防护向量不超过所有时钟的
  逐分量上界（任何被接受向量必曾被某时钟见过）、防护不与墓碑条目共存、
  回收列表严格有序。

日志会打印每次输入事件、接受/忽略/回收的结果及其判定依据（当前赢家、
时钟推进、稳定向量比较）。

## 本地验证

```bash
go test -race -v ./ontology/
go test -cover ./...
go vet ./...
gofmt -l .
```

用例覆盖：字典序覆盖与重复忽略、稳定向量逐点正确且单调、回收只移除被
稳定向量分量支配的墓碑且保留存活值与前沿墓碑、旧/迟到事件不复活已删键
（含回收后到达）、四类非法输入整批拒绝后四类状态均不变、16 个并发只读
视图逐字段一致（`-race`），并断言日志包含接受、忽略、回收、自检记录。
