# 属性取值规则的遮蔽与穿透 —— 设计说明

面向单继承对象类型体系：实例创建时绑定一个具体对象类型；读取/写入实例属性时，
需要沿继承链条确定“当前最终生效的取值规则”。本设计只处理单继承链条上的遮蔽
（shadowing）与穿透（fall-through），不涉及多继承的菱形合并。

代码位于 `ontology` 包：`ontology/ontology.go`、`ontology/errors.go`。

## 1. 数据模型

- 每个类型 `objectType` 只持有三样东西：父类型指针 `parent`、直接子类型集合
  `children`、以及**本类型自身显式声明过**的属性表 `props`。
- 继承到但未重新声明的属性**不复制**进子类型的 `props`，只在查找时沿链条向上走。
  这是“穿透”语义零成本且不可能出现副本不一致的关键。
- 每条声明是一个 `propState{origin, rule}`：
  - `origin` 记录属性最初定义处的祖先类型名（重新声明时原样透传，不改写）；
  - `rule` 包含一个全局单调分配的 `RuleID` 与允许取值集合 `Allowed`。
- 实例按属性保存完整写入历史 `[]HistoryEntry`，每条记录写入值、当时生效的
  `RuleID` 与全序序号。历史只追加，从不回改。

## 2. 规则查找（遮蔽与穿透）

`resolveLocked(start, property)` 从实例绑定的具体类型开始，沿 `parent` 逐跳上行：

1. 当前类型的 `props` 中存在该属性 => 命中，立即停止（**遮蔽**）；
2. 否则继续向上（**穿透**）；
3. 走到根仍未命中 => 属性在该链条上不存在。

“链条上第一个显式声明者”天然唯一：单继承链条是一条线性链，每个属性在每个类型
上至多一条声明，不存在两个并列候选，因此查找结果唯一确定。一次解析由
`Resolution` 给出：命中来源 `SourceType`、定义祖先 `OriginType`、最终 `Rule`，
以及实际遍历的 `Chain`（每个节点记录类型名、是否命中、是否定义处）。

父类型新增一次重新声明后，未自行重新声明的子类型下次查找时自然在新节点命中——
穿透语义使传播自动发生，无需任何主动失效/通知；而已自行重新声明的子类型会在更
靠近自己的节点先命中，因此不受父类型新声明影响。

## 3. 声明时子集约束

重新声明时先对“当前生效规则”做一次解析，再检查
`newAllowed ⊆ currentAllowed`（集合包含，允许相等）。任何当前规则不允许而新规则
允许的值都会导致声明被拒绝（`ErrValueSetWidened`），声明不写入、规则 ID 不分配、
审计不记录成功声明。约束在声明动作上闭环，不依赖任何实例写入来暴露。

## 4. 历史值不追溯

- 规则重新声明只改类型侧的声明表，不触碰任何实例历史。
- `Read` 返回属性最近一次历史写入的原值；读取前虽解析当前生效规则（写入审计
  记录），但**只用它记录、不用它校验历史值**，因此收紧后旧值仍可成功读取。
- 只有 `Write` 在追加历史前用当前生效规则做成员校验。

## 5. 密封类型与删除约束

- `CreateSubtype` 在链接父子前检查父类型 `sealed`，密封即在创建子类型的当下返回
  `ErrSealedParent`，不会等到子类型尝试重新声明时才暴露。密封的叶子类型上，
  属性规则对其自身实例必然最终生效（没有更晚辈可以遮蔽它）。
- `DeleteType` 在摘除前检查直接子类型集合 `children`：非空即返回
  `ErrTypeHasChildren`，从机制上杜绝物理删除中间类型造成链条指针断裂。只有末端
  （无直接子类型）才允许删除，删除时同步从父类型的 `children` 摘除。

## 6. 四类判定与优先级

对外区分四类结果：`ErrNotFound`（类型或类型-属性组合不存在）、
`ErrValueSetWidened`（重新声明扩大集合）、`ErrSealedParent`（在密封类型下建子类型）、
`ErrTypeHasChildren`（删除仍有子类型依赖的类型）。

所有写操作统一顺序：**先确认类型存在、再确认属性存在（需要时），然后才做其余
判定**。例如在密封类型上对一个不存在的属性做重新声明，得到的是 `ErrNotFound`
而不是“扩大”或“密封”错误——后三类的前提是类型与属性确实存在。

## 7. 复杂度论证

一次查找的步数 = 从具体类型到命中节点的跳数 + 1，至多为
“具体类型到属性定义祖先的实际深度 + 1”，记为 O(d)，d 为该属性在本链条上的
定义深度。循环体内只有 map 成员判断与父指针访问：

- 不遍历任何兄弟/旁支类型，与体系中类型总数、无关分支数量无关；
- `children` 只用于删除约束，不参与查找；
- 命中最近重新声明时提前停止，d 还会更小。

`TestResolveCostBoundedByOwnDepth` 用审计返回的链条长度实证：30 层深链上，
增加 500 个无关旁支前后遍历长度恒为 31；在第 10 层重新声明后缩短为 21。

## 8. 并发：可线性化

要求是并发的重新声明与实例读写交织时，每次观察都等价于某个全序串行执行。

采用两把锁：

- `mu sync.RWMutex` 保护类型图、声明表、实例与历史。写操作（建类型/定义/重新声明/
  删除/建实例/写值）取写锁，使所有状态变更天然互斥；读操作（解析/读值）取读锁，
  保证读到的链条与规则快照一致，不会观察到“换了一半”的状态。
- `auditMu sync.Mutex` + 单调序号 `nextSeq` 保护审计日志。读操作虽然共享读锁，
  但在“追加审计、分配序号”这一点上经 `auditMu` 相互串行。固定加锁顺序
  `mu -> auditMu`，避免死锁。

每个 resolve/read/write/redeclare 在其锁保护区间内被赋予唯一递增序号，该点即
线性化点。因为状态变更互斥、状态读取在一致快照下进行，每个操作观察到的规则
必然对应全序中某个确定时刻，不可能使用“介于两次重新声明之间、无法对应任何
时刻”的规则。重新声明即使允许集合内容相同也分配新的 `RuleID`，因此序号与
规则身份可区分，对照测试不会被内容巧合掩盖。

### 被放弃的方案

- **每属性原子指针 / 每类型 RWMutex 的细粒度锁**：单继承查找要沿链访问多个节点，
  多节点加锁同样需要全序规则，复杂度高且容易在删除中间节点时破坏遍历；本问题
  的争用集中在声明变更，粗粒度写锁 + 读锁已满足语义且明显更易论证。
- **不可变类型图 + copy-on-write 整体替换（RCU）**：读完全无锁、快照强，适合
  读极多写极少的场景，但每次重新声明需要复制链条并维护实例侧引用，工程量与
  GC 压力都更大；当前规模下读写锁方案更直接。
- **把继承属性物化（复制规则到每个子类型）**：查找可 O(1)，但父类型重新声明
  时必须主动向下传播并区分“子类型是否已自行声明”，传播失效逻辑正是需求中最
  容易出错的点；沿链查找从根本上消除了传播问题。
- **多继承 C3/MRO 线性化**：需求明确不涉及，且会破坏“第一个命中天然唯一”的
  论证，明确排除。

## 9. 审计与可核对性

每次 resolve/read/write（含被规则拒绝的写入）与成功的 redeclare 都产生一条
`TraceRecord`：操作类型、实例、具体类型、完整遍历链条、命中来源、定义祖先、
最终规则（含 RuleID）、写入值、是否接受、全序序号。`Audit()` 返回快照副本。

## 10. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin   # 若 go 不在默认 PATH
export GOCACHE=/tmp/gocache            # 默认缓存目录只读时需要

go test -race -v ./...
go test -cover ./...
go vet ./...
gofmt -l .
```

关键测试：

- `TestResolveAllRedeclareCombinations`：五层链条枚举 2^4 种重新声明层级组合，
  核对每个具体类型的命中来源、定义祖先与遍历链条，并核对 T0 重新声明后的
  穿透/遮蔽行为。
- `TestHistoryValuesSurviveRuleTightening`：收紧前写入、收紧后读历史与新写入
  的行为一致性。
- `TestConcurrentRedeclareAndIO`：20 个并发重新声明与 8 个读写 goroutine 交织，
  按审计序号排序后用一个**独立的朴素串行参考模型**逐条重放，核对每次写校验/读
  使用的规则身份与接受结果必须在全序中有对应时刻。
- `TestResolveCostBoundedByOwnDepth`：链条长度的实证复杂度验证。
