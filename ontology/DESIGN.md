# 合租费用分账与净额清算 — 设计说明

1. 模块切分：`types.go`（状态/记录）、`errors.go`（固定错误序）、`occupancy.go`（左闭右开在住段与重叠）、
   `attribution.go`（逐日归属）、`ledger.go`（净额、退出与补充清算）、`service.go`（六个操作与并发/校验）。
2. 在住期建模为若干左闭右开段 `[start,end)`，换房即“闭旧段+开新段”，端点交接（旧出=新入）允许重叠检查通过。
3. 账单金额逐日归属：先把金额按天切成整数（前若干天各多得 1），每天在当天在住者间分；
   人头每人权重 1，面积按房间面积权重；余数单位按“入住日早、房间号小”优先序列发放。
4. 某天无人在住：由该天之后最早入住者承担（同日取房间号最小），再无则房东承担（贡献槽位 ID=0）。
5. 归属不做一次性冻结：入住/换房/退出后用当前完整在住历史重算全部 active 账单，并对
   “双方均在住”的住户对做净额增量；这样晚入住者自然接管无人日、换房当天按新房间面积。
6. 净额只保存“双方均未退出”住户对的规范有符号值（`canonPair`，正=小 ID 应收），
   `NetBetween` 是单次 map 读取，开销 O(1)，与账单总数无关。
7. 退出清算按全局单调操作序号 `seq` 界定：仅 `billSeq < checkoutSeq` 的 active 账单入原清算；
   同 `now` 的多次操作靠互斥锁获得确定先后，避免同日歧义。
8. 已退出住户的累计头寸存 `folded[id]`，每张账单对每个住户至多并入一次（`included` 标记），
   杜绝并发或重复退出导致的双清算/遗漏。
9. 退出后新账单：只补“退出序号早于账单序号”的住户，按其有向贡献生成 `Suppl` 补充清算，不改原记录。
10. 争议立即从在住净额剔除并保存争议前快照；逾期/重复/已裁定按“状态不允许”拒绝，裁定额>原额按“金额越界”。
11. 裁定按新金额重算：在住部分回净额；涉及已退出住户的新旧有向贡献之差生成补充清算（原清算永不改写）。
12. 争议期间退出：原清算基于“账单被剔除”状态完成，裁定恢复后对受影响住户补一笔。
13. 错误固定次序：参数非法 < 时钟回退 < 不存在 < 在住期重叠 < 状态不允许 < 金额越界；
    所有变更在校验全部通过后才发生，被拒操作不留痕、时钟不前进。
14. 并发：单一 `sync.RWMutex` 串行化全部变更，读用 RLock；结果等价于某串行顺序。
15. 放弃方案：① 账单录入即永久冻结归属——无法支持晚入住接管无人日与换房面积重算，改为按历史重算+净额增量；
    ② 用退出日期比较界定清算——同 `now` 多操作会产生歧义，改用全局 `seq`；
    ③ 每对住户保存账单流水明细查询净额——查询随账单数增长，改为只留净额聚合值。
16. 守恒：每账单住户份额+房东份额恒等于金额；全体住户有向头寸之和恒为 0（随机测试逐步断言）。
17. 本地验证：`go test -race ./ontology`（场景用例 + 60 组随机序列与独立朴素模型对照 + 并发/重放/守恒）。
