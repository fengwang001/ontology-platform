# 理赔分摊结算引擎 — 设计说明

## 模块划分
1. `types.go`：条款 `PolicySpec`、理赔 `Claim/Line`、结果 `Settlement/LineOut`。
2. `errors.go`：六类可区分错误与固定拒绝次序。
3. `settlement.go`：无状态纯函数 `settle`，单笔结算唯一规则来源。
4. `yearbook.go`：保单年度定位（左闭右开 `(day-incept)/yearLen`）与年度累计结构。
5. `engine.go`：并发安全引擎，登记/提交/撤销/快照，维护每保单年度账与受理链。

## 关键取舍
- **四规则固定次序**：剔除不赔 → 扣每次事故免赔 → 按类别比例赔付（向上取整）→ 自付封顶截断。
  先算出每条“封顶前”名义免赔与比例自付，再单遍定位**最后一条被截断明细**：
  其前原样；该条只保留 `room` 自付，超出记入 `CapShift`；其后明细全额赔付（`FullAfter`）。
- **边界即截断**：累计自付在某条处**恰好**等于封顶时，该条保留、其后全额；不产生 `CapShift`。
- **年度免赔账记名义扣除额**（规格次序下免赔先于封顶确定）。
- **年度账只存两个标量** `deductUsed/oopUsed`，`settle` 为 O(明细数)，与历史笔数、年度数无关。
- **撤销**：每年度维护受理次序链表，仅末笔可撤销；记录结算前快照，撤销即恢复并释放理赔号。
- **并发**：引擎单互斥串行化同保单操作，故等价于某受理顺序；全程持锁更新，任何时刻累计自洽。

## 被放弃的方案
- 每笔重放历史求年度累计：实现简单但 O(历史)，违反常数性能，仅保留给朴素模型做差分对照。
- 逐分模拟免赔/比例：直观但随金额线性变慢，产品代码改为整数块 + `ceilDiv` 向上取整。
- 免赔与封顶交织消耗：会改变“先免赔后比例”的明细级归属，已弃用，差分测试曾据此抓到并修正。
- 每保单细粒度年度锁：复杂度高且跨年度撤销/查重仍需全局序，单锁已足够且可证明串行等价。

## 本地验证
- 定向用例：免赔恰等/小于、逐条跨明细、取整尾差、封顶恰好/越过归属、封顶后全赔、
  不赔项目不计、年度右端取等、撤销末笔再同号提交、非末笔不留痕、拒绝次序逐对。
- 差分：`naive_test.go` 独立流式朴素模型 + 重放式年度账，120 组随机提交/撤销序列逐字段对照，
  `-v` 打印每步输入、输出与判定依据。
- 并发：`-race` 下 8 worker 并发提交/撤销，校验错误类型、存活守恒与总账。
- 性能：`TestScaleComparison` 对照 1k 与 100k 历史（≈91 / 9091 个年度），
  单笔结算约 0.2–0.4µs 且比值 ≈1.0x；`go test -bench=. -run '^$'` 复现。
