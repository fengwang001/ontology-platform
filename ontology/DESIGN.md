# 属性索引重建的审计溯源证明器 — 设计说明

## 1. 问题与目标

对象的某些属性建有“按值查找”的倒排索引（`value -> set(object)`）。索引可能因故障
需要重建。重建不能只宣布“完成”，必须产出一份**可被第三方独立复核**的审计记录：
复核者仅凭审计记录与对象当前状态，就能判定索引每条目是否正确；且重建与持续写入
并发，基线范围与增量范围边界必须精确、等价于某个全局串行顺序。

## 2. 核心模型

### 2.1 单调序号代替墙钟时间

平台维护一个全局单调递增整数 `seq`。每次 `Put/Delete` 在**同一把互斥锁**的临界区内
同时完成三件事：`seq++`、写对象当前状态、维护所有已可用索引。因此：

- 写入对**对象**生效的顺序 = 写入对**索引**生效的顺序 = `seq` 升序；
- 不依赖时钟，不受 NTP 回拨/跨机时差影响，`seq` 可比较且单调。

对象属性单元 `AttrCell { Value, Deleted, Version }` 中保存“最后一次修改该属性的写入
序号” `Version`。这是实现单条目 O(1) 复核的版本指针。

### 2.2 基线 / 增量的精确边界

`StartRebuild` 在临界区内把当前 `seq` 记为基准点 `B`，并对基准点的对象属性做深拷贝
快照（基线范围）。边界按序号闭/开划分：

- **基线范围**：所有 `seq <= B` 已生效的对象状态（含恰好在发起前一刻落盘的那笔写入）；
- **增量范围**：所有 `seq > B` 且 `seq <= C` 的写入，`C` 是 `Complete` 原子切换时的
  当前序号（重建完成时点）。

重建期间到达的写入由 `maintainIndexLocked` 追加到 `pending.deltas`（**不**回写离线
构建的新索引），因此边界天然不重叠、不遗漏：每笔写入要么 `<=B`（体现在快照中），
要么 `>B`（体现在增量列表中）。`Complete` 先扫快照建基线，再按 `seq` 升序重放增量，
最后在临界区内用新索引+完整审计记录**原子替换**旧索引。切换后写入回到在线维护路径。

### 2.3 审计记录（自包含、防篡改）

`AuditRecord` 至少包含：

- `BaselineSeq`（基线范围标识）、`CompleteSeq`（重建完成时点），都是单调序号；
- `Entries`：重建产出的**每一条**索引条目到来源对象写入的对应关系
  `(object, value, source_seq, baseline)`，而非仅一个条目总数；
- `Digest`：对上述全部字段按固定字段序、长度前缀定界序列化后的 SHA-256 指纹。

删除（墓碑）不产生索引条目；同一对象多次写入只在最终索引中留下一个条目，其
`source_seq` 指向使最终值生效的那次写入，`baseline = (source_seq <= B)`。

## 3. 独立复核（不相信重建日志）

`Verify` 先在单把锁内取得一份**不可变一致快照**（对象当前状态 + 当前索引 + 审计记录
深拷贝），随后用**纯函数** `verifySnapshot` 计算结论。它绝不读取重建执行日志，也
不读取对象历史写入流水。判定三部分：

1. **审计自身可信**：指纹必须匹配；`B<=C`；每条目 `source_seq` 合法且在 `(0,C]`；
   `baseline` 标记与 `source_seq<=B` 一致（防止边界重叠）；同对象不得重复条目。
2. **逐条值一致**：对索引中每一条目 `(value,object)`，读取该对象该属性的
   **当前单元（恰好一次）**：
   - 单元不存在/已删除 → `extra_entry`；
   - 当前值 ≠ 索引值 → `wrong_value`（并给出对象实际值）；
   - 当前值相同但 `cell.Version ≠ entry.source_seq` → `stale_entry`（增量未按序应用）。
3. **覆盖完整**：扫描当前拥有该属性的每个对象，若未出现在索引中 → `missing_entry`。

每个不一致都精确报告“哪个索引值桶里的哪个对象、是什么类别”，不给笼统结论。

### 3.1 与规模无关的性能要求（可验证）

报告中带两个计数器：`CellReads`（读取的当前属性单元数）与 `HistoryReads`（读取的
历史写入记录数）。复核任何单条目**恒为 1 次当前态随机读 + 0 次历史读**，因为
`AttrCell.Version` 版本指针使“是否最新”一次比较即可判定，无需回放该对象的全部历史。
测试 `TestVerifyScaleIndependent` 把单对象历史写入从 10 次提高到 1000 次，断言
`HistoryReads==0` 且 `CellReads` 不增长，给出机器可检验的证明。作为对照，
`naive.go` 的朴素模型刻意线性回放全部历史（O(历史总次数)）。

### 3.2 并发复核一致性

复核只依赖不可变快照，且结论对 `(审计, 对象状态)` 是确定函数（所有集合遍历先排序）。
同一线性化点产生的快照逐字节一致 → 并发复核结论必然相同。
`TestConcurrentVerifyConsistency` 起 16 个复核 goroutine，断言 `SnapshotSeq` 相同且
报告逐条相等。

## 4. 失败隔离与查询状态

重建在 `pending` 上离线构建。`Fail` 丢弃整个 `pending`（已写出的部分条目随之隔离、
绝不发布），状态置 `Failed`。因此查询严格区分：

| 情形 | 错误类别 (`ErrorKind`) | 含义 |
| --- | --- | --- |
| 类型未声明该索引 | `KindIndexNotDeclared` | 索引**不存在** |
| 声明但重建中/上次失败、无完整审计 | `KindRebuildingUnavailable` | 索引**存在但不可用** |
| 可用但被复核标记过不一致 | 无错误，结果带 `DirtyNotice` | 可查，附未修复不一致声明 |
| 复核发现条目级不一致 | `VerificationReport.Mismatches`（`KindEntryMismatch` 语义） | 精确到条目 |

拒绝优先级严格为：未声明 > 重建中不可用 > 可用但带不一致声明。

`Verify` 严格只读、幂等；把不一致落到“需修复”标记是单独的显式管理动作
`MarkFlaggedFromReport`，避免只读复核产生副作用。下一次成功重建会清除该标记。
被拒绝的重建（未声明、重复发起）直接返回错误，不触碰对象状态与任何既有索引。

## 5. 关键取舍与被放弃的方案

- **取单调序号而非墙钟时间**：放弃时间戳，避免时钟偏差无法确定先后、无法可复核。
- **单把全局锁串行化**：放弃无锁/多版本并发，换取“对象顺序=索引顺序=全局串行顺序”
  的强可证明性；临界区只做内存 map 更新，粒度足够。需要扩展时可替换为带全局定序的
  OCC，但语义不变。
- **切换前暂停把新写入并入新索引，改用 delta 列表 + 切换时重放**：放弃“双写新旧索引”
  方案，因为双写期间新旧索引交错更新，边界难以自证；delta 列表让 `(B,C]` 精确可数。
- **审计只记最终条目**：被后续写入覆盖/删除的中间值不进最终索引，也不产生条目；
  放弃记录全部中间态，避免审计随写入次数无界膨胀，同时不损失对“最终正确性”的证明力。
- **复核读当前单元而非历史日志**：放弃回放历史（朴素模型做法），得到每条目 O(1)。
  代价是审计内的“B 时刻历史值”无法在很久以后仅靠当前状态重放验证；本设计的审计
  主张是“完成时点 C 的索引正确且来源可溯”，当前态复核覆盖了这一主张的可观测部分，
  审计指纹与来源序号保证记录本身不可伪造。
- **失败即整体不可用**：放弃部分可用/灰度发布，杜绝半成品索引对外提供查询。

## 6. 本地验证方法

```bash
# 本环境 Go 在 /usr/local/go/bin
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache

go test -race -v ./ontology          # 全部用例，含竞态检测
go test -cover ./...                  # 覆盖率
go vet ./... && gofmt -l ontology     # 静态检查/格式
```

判定日志（每次写入/查询/重建/复核的**输入、依据、输出**）由 `JSONLogger` 一行一条
JSON 打印；随机交错用例会真实产出日志，可直接查看 `"basis"` 字段。

### 测试覆盖与需求对应

- `TestBoundaryBeforeAfterWrite`：基准点恰好落在某写入之后的基线/增量归属。
- `TestIncrementAppliedInOrder`：重建期间同对象多次写入按生效顺序应用，不颠倒。
- `TestRebuildFailureUnavailable`：中途失败后部分条目不泄露、正确声明不可用，
  且“不存在”与“重建中不可用”可区分。
- `TestIndependentVerifyFindsInjectedMismatch` / `TestAuditDigestTampering`：
  不看重建日志，仅凭审计+当前状态发现人为注入的条目级错误与审计篡改。
- `TestConcurrentVerifyConsistency`：并发复核结论完全一致。
- `TestRandomInterleavingAgainstNaive`：4000 步随机写入/重建/失败交错，与独立朴素
  重建模型逐条对照。
- `TestVerifyScaleIndependent`：历史 10 → 1000 次，历史读恒 0、单元读不增长。
- `TestRejectedRequestNoStateChange` / `TestDirtyNoticeOnQuery`：拒绝无副作用、
  只读幂等、查询带不一致声明。
