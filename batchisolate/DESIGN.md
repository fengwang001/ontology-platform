# 批写入隔离器设计说明（batchisolate）

面向 **整批原子写入** 的 sink（一批编号要么全部成功，要么全部失败），
本隔离器在批失败时区分瞬时/永久错误，对永久失败的批做二分隔离，把毒丸
记录送入死信，其余记录保持原序 **恰好交付一次**，并对 sink 调用次数给出
可证明的上界。

## 1. 对外接口

```go
func New(retries, knownCap, budget int, sink SinkFunc) (*Isolator, error)
func (iso *Isolator) Submit(ids []string) (*Result, error)
func (iso *Isolator) Close() error            // 等待在途 Submit，幂等
func (iso *Isolator) Known() []string         // 已知毒丸表快照（追加先后）
func (iso *Isolator) Calls() int64            // 非导出计数器 calls 的只读视图

type Result struct {
    Delivered []string      // 按原序的交付清单
    Dead      []DeadLetter  // 按原序的死信清单（ID + Reason）
    Calls     int           // 本次 Submit 的 sink 调用次数
}
```

死信原因：`Known` / `Poison` / `Exhausted` / `Budget`。

参数校验（`New`：R∈[0,10]，Km∈[0,1000]，Cmax∈[1,10⁶]，sink 非 nil；
`Submit`：ids 长度 1..10⁵、元素非空且互不相同）失败时整体拒绝，
**不调用 sink、不改变已知毒丸表**。`Submit` 报错顺序固定为
「参数非法 → 已关闭」，只报第一个原因。

## 2. 错误处置：瞬时 vs 永久

sink 返回的错误用 `errors.Is(err, ErrTransient)` 分类：

- **瞬时错误**：在同一个待处理批上最多尝试 **R+1 次**。中途一次成功即整批
  交付；R+1 次全部瞬时则记 `perm=false`（瞬时耗尽），批失败但 **不做毒丸
  推断**，子批一律以 `certain=false` 继续递归。单条记录瞬时耗尽记
  `Exhausted`，**不进入** 已知毒丸表。
- **永久错误**：立即停止本批尝试并记 `perm=true`；单条记录记 `Poison`，
  按判定顺序进入已知毒丸表（受 Km 约束）。

语义前提：永久失败意味着「该批中至少存在一条永远无法与其它记录一起成功
写入的记录」；原子 sink 保证失败批没有任何记录被交付，因此对失败批重试与
拆分不会产生重复交付。每条交付的编号只出现在一次成功的 sink 调用中；
被判 `Poison` 的编号从未出现在任何成功调用中。

## 3. 二分隔离与右半推断

`solve(批, certain)` 规则：

1. 空批：成功。
2. `certain=true`：**不调用 sink**，直接记 `perm=true`（成立前提见下）。
3. 否则按第 2 节尝试 R+1 次，成功即返回；失败确定 `perm`。
4. 批长度为 1：`perm` 为真 → `Poison`（并入表）；为假 → `Exhausted`。
5. 批长度 n>1：拆为 **左半 = 前 ⌈n/2⌉ 个**、右半 = 其余：
   - `lok = solve(左半, false)`（左半永远重新尝试，因为父批的失败不能
         定位到左半——毒丸可能在右半）；
   - `solve(右半, perm && lok)`；
   - 多元素批恒返回「失败」（结果以子批裁决为准）。

**右半推断的成立前提**：当且仅当 ① 父批已确认 **永久** 失败（`perm=true`，
即至少含一条毒丸）且 ② 左半整批 **成功**（`lok=true`，左半无毒丸）时，
毒丸必在右半，故右半以 `certain=true` 进入：不再对右半整批调用 sink，直接
继续二分。任一前提不成立（瞬时耗尽，或左半本身也含毒丸而失败），右半都以
`certain=false` 正常尝试。注意 `certain` 只跳过「多元素批的整次尝试」；
拆分后左半仍以 `certain=false` 求解，因此推断只节省右半路径上的整批探测。

左半取 `⌈n/2⌉`（不是 floor）使递归深度为 ⌈log₂n⌉ 且奇数长度时毒丸归属
明确；测试对 n=3、n=5 的调用序列有专门断言。

## 4. 已知毒丸表

- Submit **开始时读取一次** 快照：命中的编号在任何 sink 调用之前被摘出，
  原因 `Known`，不产生调用；其余编号保持原序构成待处理批。
- Submit **结束时** 才把本次新判定的 `Poison`（不含 `Exhausted`/`Budget`/
  `Known`）按 **判定顺序** 并入全局表。因此并发 Submit 之间 **互不可见**
  对方新入表者，结果等价于某个串行顺序。
- 并入规则：已在表中者 **不改变位置、不重复插入**；表满时先淘汰最早追加者
  （FIFO）；`Km=0` 时不记录任何条目。任何时刻表条目数 ≤ Km 且无重复。
- 预算中止时，已经判定的 `Poison` 仍按判定顺序并入（见第 5 节）。
- 全局表由互斥锁保护；每个 Submit 内的 sink 调用严格串行，不同 Submit 的
  sink 调用允许并行。

## 5. 预算语义

每次 sink 调用 **之前** 检查：若本次 Submit 已调用 Cmax 次，则整个 Submit
立即中止——不再发起任何调用，**当前批与所有尚未裁决的记录**（例如尚未处理
的右半）一律记 `Budget`；已裁决的交付与死信保持不变；已确认的 `Poison`
仍进入已知毒丸表。因此每次 Submit 的实际 sink 调用次数 ≤ Cmax。

实现上 `solve` 以三态（成功 / 失败 / 中止）返回：中止沿递归向上传播时，
只在「中止点所在批」与「尚未触及的兄弟子树」处就地补 `Budget`，已经交付或
已判死信的记录不被覆盖。最终交付/死信清单统一按原始入参顺序重建，保证
两份清单各自保序、互不相交且并集恰为入参。

## 6. 调用次数上界（无瞬时、无已知、预算足够、k≥1）

结论：

```
calls ≤ 1 + 2·k·⌈log₂ n⌉
```

推导（计费论证）。把二分递归看成一棵二叉区间树：每个非叶子区间有左、右
两个孩子。给每个 **含毒丸的失败区间** 记一笔账：

1. 它自身的 1 次永久失败调用；
2. 它在该层的「成功探测」：
   - 若左半成功（lok=true），左半贡献 1 次成功调用，右半转为 `certain`
     不再调用；
   - 若左半失败（左半含毒丸），左半自身的失败调用由左半内毒丸的账单支付；
     右半不享受推断，其若含毒丸则调用由右半内毒丸支付，若不含毒丸则贡献
     至多 1 次成功调用——这笔成功调用记在导致右半被实际调用的那条毒丸
     （左半毒丸）的名下。

据此对任意递归子树归纳：设子树内含 p≥1 个毒丸、其根被实际调用（
certain=false）且永久失败，子树深度为 h（从该子树根到单元素叶的层数），
则该子树内调用次数

```
T(h, p) ≤ 2·p·h − (p − 1) ≤ 2·p·h
```

归纳：p=1 时，毒丸每下一层伴随至多一次成功兄弟探测，共 h 个失败节点与
至多 h 次成功探测，T≤2h。p>1 时，毒丸在根处不分离；按毒丸在左/右子树的
分布 pL+pR=p，左右子树深度均 ≤ h−1（左半 ⌈n/2⌉、右半 ⌊n/2⌋，长度每层
至少减半）。若左右都含毒丸：根失败 1 次，左、右各按归纳计费，
T≤1+2pL(h−1)+2pR(h−1) ≤ 2ph−2p+1 ≤ 2ph−(p−1)。若毒丸全在一侧：
另一侧是至多 1 次成功探测（或因 `certain` 被跳过，为 0），含毒丸侧
T≤1+1+2p(h−1) = 2ph−2p+2 ≤ 2ph−(p−1)（p≥1）。

整棵树深度 ⌈log₂n⌉（左半取 ⌈n/2⌉），根为唯一不含在任何毒丸账单里的
额外失败调用（k 个毒丸的失败链都从根的孩子开始计费），故

```
calls = 1 + (失败链上的调用 + 成功探测) ≤ 1 + 2·k·⌈log₂n⌉
```

`certain` 跳过的区间调用次数为 0，只会使实际计数更小；上述上界因此对
推断开启的情形同样成立。

n=1024（⌈log₂n⌉=10、k=1）的两个极值（上界取等/最省）：

- 毒丸全在最左位置：每层左半失败、右半是 1 次成功探测（右半永远不含
  毒丸、不享受 certain），calls = 1 + 10 个失败链调用 + 10 次成功探测
  = **21**，恰好取到上界；
- 毒丸只在最右位置：每层左半成功（1 次成功探测），右半 `certain` 直拆
  不调用，calls = 根 1 次 + 10 次左半成功探测 = **11**。

瞬时重试会按每批最多 R+1 次放大常数，预算 Cmax 是硬上界；已知毒丸摘出
只减少调用。三种因素都不会使计数超过「无瞬时无已知情形与 Cmax 的较小者」。

## 7. 可复现性

隔离器对 sink 唯一的依赖是「按同一有序批、同一调用次序」返回的错误序列：
记录不在本地缓存任何 sink 响应。相同的 sink 行为序列重放得到完全相同的
交付清单、死信清单、`Calls` 与已知毒丸表（测试中的 `scriptSink` 即按
有序批内容为 key 的确定性脚本）。
