# 混合逻辑时钟（Hybrid Logical Clock, HLC）

`package hlc` 为多节点系统提供在**物理时钟可能回拨**时仍然严格单调、
满足因果一致性的时间戳，并保留每个节点可按序查询的事件历史与
“恰好接收一次”的在途消息登记。

时间戳是字典序对 `Timestamp{Physical, Counter}`，字符串形式为 `l.c`：
先比物理部分 `l`，相同再比逻辑计数 `c`。

## 三类事件的推进规则

设节点当前时间为 `(l, c)`，本次物理读数为 `pt`；接收时消息携带 `(lm, cm)`。

**本地事件 / 发送事件**（`LocalTick`、`Send`）：

- `pt > l`：新时间 `(pt, 0)`
- `pt <= l`（含时钟回拨、同毫秒）：新时间 `(l, c+1)`

**接收事件**（`Receive`，标准 HLC 合并规则）：

- `pt > max(l, lm)`：`(pt, 0)`
- `l > max(lm, pt)`：`(l, c+1)`（本地领先）
- `lm > max(l, pt)`：`(lm, cm+1)`（远程领先）
- 三者相等：`(l, max(c, cm)+1)`

由此保证：同一节点相邻事件时间戳严格递增；接收事件时间戳严格大于其
发送事件时间戳（`SendAt`）。节点初次事件前的当前时间为零值 `0.0`。

发送会分配一个从 1 开始、严格递增的消息号；消息登记目标节点，
只有目标节点能接收，且只能接收一次。接收成功后消息标记 `Delivered`，
并从 `PendingMessages` 消失。

## 偏差与计数上限

- `Config.MaxDrift`（默认 `1000`）：候选时间戳的逻辑物理部分相对本次
  物理读数的领先量不得超过该值，即要求 `l' - pt <= MaxDrift`。
  超过返回 `drift_exceeded`（本地/发送受历史读数拖累、接收受消息携带
  时间拖累都可能触发）。偏差恰好等于上限是合法边界。
- `Config.MaxCounter`（默认 `4095`）：候选计数满足 `c' <= MaxCounter`，
  否则返回 `counter_overflow`。计数恰好等于上限是合法边界。
- `MaxDrift <= 0` 或 `MaxCounter == 0` 时使用默认值。

## 边界行为

- 物理读数允许为 `0`；负数一律拒绝。
- 同一物理毫秒内连续事件只增加计数，时间戳仍严格递增。
- 物理时钟回拨（`pt` 小于此前读数）不会使时间戳倒退。
- 给自身发消息（from == to）属于正常发送/接收。
- 并发的跨节点事件可能得到相同 HLC 时间戳（需要节点 ID 才能破平，
  本包不附加节点标识）；有因果关系的事件时间戳顺序始终正确。

## 错误类别（互不相同，可区分）

| Reason | 触发条件 |
| --- | --- |
| `invalid_argument` | 节点名为空/空白、重复注册等非法参数 |
| `node_not_found` | 操作引用了未注册的节点（发送方或接收方） |
| `negative_physical` | 物理读数为负数 |
| `message_not_found` | 消息号 <= 0，或系统中不存在该消息号 |
| `message_already_received` | 消息已经被接收，再次接收 |
| `target_mismatch` | 接收节点不是消息登记的目标节点 |
| `drift_exceeded` | 逻辑物理部分领先物理读数超过 `MaxDrift` |
| `counter_overflow` | 候选计数超过 `MaxCounter` |

错误以 `*RejectError` 返回，可用错误原因做分支判断。

**失败不留痕**：所有校验都在修改状态之前完成；任何一次拒绝都不会改动
节点时钟、消息登记（含 `Delivered` 标记、消息号序列）或事件历史。

## 并发与可复现性

整个系统由一把互斥锁保护，所有操作可被任意数量的 goroutine 并发调用。
在“每个节点上的事件先后顺序相同、消息的收发因果相同”的前提下，
产生的时间戳与线程调度无关；测试用串行与并发两种方式重放同一事件脚本，
断言每个事件的时间戳逐一对等。

## 本地验证

```bash
# 全量测试（带竞态检测）
go test -race -v ./hlc

# 重复 10 次检查并发稳定性
go test -race -count=10 ./hlc

# 覆盖率
go test -cover ./hlc
```

`go test -v` 的日志会逐步打印每个操作的输入（节点、物理读数、消息号）、
产生的时间戳、接受时的推进依据或拒绝原因。测试还维护一个朴素向量时钟
作为因果参照，断言“参照中因果在先的事件，HLC 时间戳也严格更小”。
