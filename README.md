# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 生成树协议网桥端口角色计算器（`stp` 包）

`stp` 包按简化的生成树协议（STP）保存各端口收到的配置消息，并计算根桥与每个端口的角色。

### 数据模型

- 网桥：有编号（越小越优）、最大寿命 `A` 与若干端口。
- 端口：有端口编号与正的路径开销；端口编号在本网桥内唯一。
- 配置消息（BPDU）向量：`(根桥编号, 到根开销, 发送桥编号, 发送端口编号)`，四项按顺序做词典序比较，数值小者更优。
- 每个端口只保存最近一条消息及其到达时刻；新消息直接替换旧消息。当 `现在 - 到达时刻 >= A` 时该消息失效，不参与任何计算。

### 根桥与根端口判定

1. 对每条**未失效**消息计算候选：经该端口到根的开销 = 消息到根开销 + 该端口路径开销，候选五元组为
   `(消息根桥编号, 本桥到根开销, 发送桥编号, 发送端口编号, 本地端口编号)`。
2. 仅在候选的根桥编号 **小于本桥编号** 时参与根端口竞选，取词典序最小的候选：
   - 其本地端口为**根端口**（转发）；
   - 本桥根桥 = 候选根桥；本桥到根开销 = 候选到根开销。
3. 不存在这样的候选时，本桥**自认根桥**：根桥为本桥、到根开销为 0，且没有根端口。

### 指定端口与阻塞端口判定

对根端口以外的每个端口，本桥在其上通告向量
`(根桥编号, 本桥到根开销, 本桥编号, 该端口编号)`：

- 端口无未失效消息，或**本桥通告向量严格优于**（词典序严格小于）保存的消息向量 → **指定端口**（转发）；
- 否则 → **阻塞端口**（不转发）。
- 根桥的所有端口均为指定端口；每个非根桥恰有一个根端口（端口无消息时该端口为指定端口）。

### 操作与拒绝规则

- `Receive(now, port, msg)`：保存消息。拒绝按以下顺序只报第一个：
  1. 时钟回拨（`now` 小于任一已接受操作的时刻，包括 `Roles` 查询）；
  2. 端口不存在；
  3. 根桥或发送桥编号非正、到根开销为负；
  4. 发送桥就是本桥。
- `LinkDown(now, port)`：先查时钟回拨，再查端口是否存在；通过后清除该端口保存的消息。
- `Roles(now)`：只读查询；`now` 回拨同样被拒绝，但不更新时钟。
- 任一被拒绝的操作都不会改变已保存的消息（或时钟）。
- 三个操作可并发调用：内部使用读写互斥锁保证一致；任意时刻每个端口恰有一种角色，根端口至多一个。

### 本地验证

```bash
# 全量测试（带竞态检测、重复运行）
go test -race -count=1 ./...

# 查看输入、输出与判定依据日志
go test -race -v ./stp

# 单独运行某个场景，例如三桥成环收敛
go test -race -v -run TestThreeBridgeRingConverges ./stp
```

测试覆盖：到根开销取“消息开销 + 本端口开销”、并列时依次按发送桥/发送端口/本地端口取小、指定与阻塞的严格优于判定（含完全相等不优）、根桥消息过期后重新自认根桥、三个网桥成环收敛后恰有一个阻塞端口、拒绝顺序与断链、并发安全与相同序列重放结果一致。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```
