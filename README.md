# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 事件时间 OVER 范围聚合器

`RangeAggregator(width, allowedLateness, capacity)` 用一把互斥锁串行化所有操作，保证并发调用结果等价于某个合法串行顺序；`Advance` 从释放缓冲、生成输出到更新水位线和清理状态是一个原子步骤。

### Insert 判定

设当前水位线为 `wm`，允许迟到为 `AL`：

- `ts <= wm-AL`：迟到丢弃，增加迟到计数，不改变缓冲、已释放行、水位线或 `seq`。
- `wm-AL < ts <= wm`：补发。立即扫描该键当前保留行中的 `[ts-R, ts]`，输出聚合；补发行保留在已释放集合中，但不会更正此前输出。
- `ts > wm`：进入缓冲；若缓冲行数已达 `Cap` 则拒绝。入缓冲行才分配递增 `seq`，迟到和补发不占序号。

判定顺序固定为先校验参数，再判定迟到，再判定补发，最后检查容量。因此缓冲已满时，迟到与补发仍会正常处理，不会错误地报缓冲满。

### Advance 与输出顺序

`Advance(w)` 在 `w < wm` 时拒绝；`w == wm` 是空操作。有效推进时弹出缓冲中所有 `ts <= w` 的行，并严格按 `(ts, seq)` 升序输出。

每个输出帧为同一键下、已释放且满足 `ts-R <= ts' <= ts` 的全部行。同一键、同一 `ts` 的并列行共享同一个帧；即使某行在输出次序中位于并列行之后，也会包含全部同 `ts` 并列行。跨键帧互不混入。

### 状态结构与增量维护

- 缓冲使用按 `(ts, seq)` 排序的最小堆。
- 每个键使用按时间戳排序的 treap 保存已释放行桶，支持范围扫描、删除与确定性回放。
- 普通释放维护每键活动帧：进入帧的行计入 sum/count，并通过最大堆维护最大值；离开下界的惰性最大堆项在堆顶弹出。
- 补发行使用独立的补发时间戳树。普通释放时只把当前帧范围内、尚未进入活动帧的补发桶按时间戳装载，避免补发乱序时间戳污染前向累加器。
- `frameWork` 仅统计真实的进入/离开累加器与最大堆入队/出队动作；同一已释放行生命周期内总计不超过 4 次，因此与 R 无关。
- 补发帧通过时间戳树范围搜索，`lateWork` 只增加固定边界定位成本和访问到的帧内不同时间戳桶数；帧外桶不参与计数，与保留行总数及帧外不同时间戳桶数无关。

### 清理边界

推进到新水位线 `w` 后，未来能被接受的最小事件时间为 `w-AL+1`。这样的行在时间戳 `t` 上需要的最小历史时间戳为 `t-R = w-AL+1-R`。因此：

`ts' <= w-R-AL`

的已释放行不可能再被任何未来帧访问，会在输出全部生成后清理；`ts' = w-R-AL+1` 保留。补发树使用相同边界裁剪。

### 本地验证

- `go test -v ./...`：包含两个题设示例、迟到/补发边界、并列行、跨键顺序、R=0、帧下界、最大值回落、清理边界、拒绝不改状态和 2000 组随机朴素模拟对照。
- `go test -race -run 'TestFrameWork|TestLateWork|TestConcurrent' ./...`：验证 `frameWork` 的 R=10 与 R=10^9 两档、`lateWork` 的 10 个与 10000 个帧外桶两档，以及并发原子性。
- 随机测试使用固定种子，逐组日志打印输入、输出、判定依据（缓冲/补发/迟到/拒绝/水位线回退），并与每个输出帧都重扫全部已释放行的朴素模型逐步比较。
