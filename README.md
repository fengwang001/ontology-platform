# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

当前提供的组件：**有向图可达性增量维护**（包 `reachability`）。

## 环境要求

- Go 1.26+（`go version` 确认；若 `go` 不在 PATH，使用 `/usr/local/go/bin`）

## 可达性增量维护组件（`reachability`）

### 可达定义

- 图是**有向多重图**，每条有向边 `u -> v` 带非负重数；边存在当且仅当重数为正；允许自环。
- 点对 `(u, v)` 可达，当且仅当存在一条**长度至少为 1 的有向游走**（walk）从 `u` 到 `v`。
  - 因此零条边不构成可达：空图中 `(u, u)` 不可达。
  - `(u, u)` 仅当 `u` 位于某个有向环（含自环）上时可达。

### 加边规则（`AddEdge(from, to)`）

1. 端点为空串：拒绝，返回 `ErrEmptyNode`，状态不变。
2. 边已存在（重数 `m > 0`）：重数变为 `m + 1`，可达集合不变。
3. 边不存在：创建重数为 1 的边，并把所有"经由新边"的可达点对并入闭包——
   令 `S = {from} ∪ 旧闭包中能到达 from 的点`，`T = {to} ∪ 旧闭包中 to 能到达的点`，
   新可达点对恰好是矩形 `S × T`。
4. 新边会使"已存在的不同边数"超过构造时设定的上限：拒绝，返回
   `ErrTooManyEdges`，重数、可达集合与索引均不变（重复加边不占用名额）。

### 删边规则（`RemoveEdge(from, to)`）

1. 端点为空串：拒绝，返回 `ErrEmptyNode`。
2. 边重数为 0：拒绝，返回 `ErrEdgeNotFound`。
3. 重数 `m > 1`：减为 `m - 1`，图结构与可达集合不变。
4. 重数为 1（删后边消失）：执行"先移除、再推导"，保证**不过删也不漏算**：
   - 在旧闭包上求 `S = {from} ∪ 能到达 from 的点`、`T = {to} ∪ to 能到达的点`，
     先移除整个矩形 `S × T`（任何可能经过被删边的见证游走都在其中）；
   - 再以剩余邻接关系对 `S` 中每个源点做正向遍历，把仍然可达的 `S × T`
     点对重新推导加回；矩形之外的点对不可能用到该边，原样保留。

### 可区分的拒绝原因

| 错误 | 触发条件 |
| --- | --- |
| `ErrInvalidArgument` | 构造参数非法（如负数边数上限） |
| `ErrEmptyNode` | 节点名为空字符串 |
| `ErrEdgeNotFound` | 删除重数为 0 的边 |
| `ErrTooManyEdges` | 新建边将使现存不同边数超过上限 |

### 读取接口与一致性

- `Reachable(from, to)`：单点对判定。
- `Pairs()`：全部可达点对（按源点、终点字典序）。
- `Path(from, to)`：返回最短见证游走（含两端点，至少一条边），作为判定依据。
- `Snapshot()`：在**同一把读锁内**返回全部点对及其最短见证路径，
  结果逐点对一致——并发写者不可能让其中一个点对处于旧状态、另一个处于新状态。
- `EdgeMultiplicity`、`Nodes`：查询重数与参与边的节点。

所有接口均并发安全（内部 `sync.RWMutex`，写操作串行、读操作可并发）。
输出顺序确定：同一输入序列反复计算得到完全相同的输出。

### 本地验证

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出（日志含输入、可达集合、每个点对的最短见证路径）
go test -race -v ./reachability/

# 重复运行验证确定性
go test -count=10 ./reachability/

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out

# 代码检查
gofmt -l .
go vet ./...
```

测试覆盖：删环上的边（含环恢复后再删另一条环边）、菱形备用路径（不过删）、
重复加边后只删一次、自环增删、各类非法输入与"被拒绝操作不改任何状态"、
长随机增删序列逐步与朴素 BFS 遍历对照、多协程并发增删与一致性快照。
