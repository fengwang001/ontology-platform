# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 事务批调度器（`scheduler` 包）

`scheduler.Scheduler` 按到达顺序接收声明了读集/写集的事务，在不违背冲突先后的前提下
尽量并行放行，使任意调度结果都**等价于按到达顺序（编号升序）的串行执行**。

### 冲突定义

事务编号从 1 起按到达连续分配。对事务 Ti、Tj（i < j），二者冲突当且仅当至少一个键
同时出现在一方的写集与另一方的读集或写集中，即：

- `W(Ti) ∩ R(Tj) ≠ ∅`（写—读）
- `W(Ti) ∩ W(Tj) ≠ ∅`（写—写）
- `R(Ti) ∩ W(Tj) ≠ ∅`（读—写，与第一项对称）

只读事务之间（`R × R`）永不冲突，因此多个读者可以并行。同一事务读写集可有交集，
键集合内部去重。

### 放行条件（每次到达 / 完成 / 取消后立即取批一次）

按编号升序扫描等待队列：

1. 当前运行数已达并发上限 K 时**立即停止扫描**（后续事务本轮不再评估，保持等待）；
2. 否则，仅当候选事务与**所有编号更小且未完成的事务**——包括运行中的，以及仍在
   等待的、甚至先前被跳过的——都不冲突时，才放行为运行；否则继续扫描后面的事务。

注意第 2 步的判断对象包含等待者：即使某候选与运行集毫无冲突，只要它与某个更早的
等待事务冲突，就必须继续等待。一次扫描内被放行的事务不会反过来重新评估本轮已跳过
者；新放行事务与被跳过者若冲突，阻塞关系留到下一次取批（下一次到达/完成/取消）
生效，不影响正确性。

### 为什么“不越过”能保证串行等价

规则保证了：**每个冲突事务对的放行先后都严格等于到达先后**（Ti 先于 Tj 被放行，
且 Ti 未完成时 Tj 绝不运行），而不冲突的事务之间无论如何交叠都无法相互观察到
中间状态。于是对任意键，所有访问它的事务按编号构成一个全序，该全序与到达序串行
执行完全一致；并行只发生在彼此不可见的事务之间，因此执行结果与按到达顺序串行
执行逐键相同。

“运行数达 K 立即停止”而非“跳过队首继续放行后面的”，同样是不越过规则的要求：
队首事务只是被容量而非冲突挡住，它编号更小、尚未完成，放行它后面的冲突者会造成
越过。

### 操作与拒绝规则

- `Arrive(readSet, writeSet) (id, released, error)`：登记事务并取批。
  按顺序只报第一个错误：读写集皆空 `ErrEmptyReadWriteSet` → 含空串键 `ErrEmptyKey`。
- `Complete(id) released`：成功或失败都算完成，转已完成并取批。按顺序报错：
  不存在 `ErrIDNotFound` → 已完成 `ErrAlreadyCompleted` → 并非运行中 `ErrNotRunning`。
- `Cancel(id) released`：只允许取消等待中的事务；取消后转已完成、移出等待队列、
  不再阻挡他人，并取批。按顺序报错：不存在 → 已完成 → 正在运行 `ErrRunning`。
- `Blockers(id) []int`：返回等待事务的阻塞者（与它冲突、编号更小且未完成）编号升序。
- 任一被拒绝的操作都不改变任何状态（包括不分配新编号）。
- 所有方法可被并发调用（内部互斥串行化状态变更），相同操作序列重放结果完全相同。
- 构造：`scheduler.New(k, scheduler.WithLogger(w))`；K 必须为正整数，日志默认写
  标准错误，传 `nil` writer 关闭日志。日志逐条打印输入、放行输出与判定依据
  （`release` / `hold blockers=...` / `stop scan ... limit reached` / `cancel`）。

### 测试覆盖

- 读者在等待的写者之后到达：即使与运行中的读者不冲突也须等待，冲突对放行顺序等于
  到达顺序；
- 被上限挡下的更早事务仍阻挡后来的冲突者，且不会在同批被越过；
- 取消等待者后阻挡解除，有名额时立即放行；
- 完成触发连锁放行（同批多个不冲突读者一起放行，冲突的后来写者继续等）；
- 到达/完成/取消的全部错误顺序与“拒绝不改状态”；`Blockers` 语义；
- 40 组随机种子下，随机事务、随机取消与并发完成时的**真实 KV 执行结果**与
  到达序串行执行**逐键一致**（失败事务不写入但仍完成）；
- 相同操作序列重放两次结果完全一致；高并发内部不变量（运行数 ≤ K、运行事务两两
  不冲突、运行者不与任何更早未完成者冲突、等待队列升序）。

## 环境要求

- Go 1.26+（`go version` 确认）

如构建缓存目录不可写，可指定临时缓存，例如 `GOCACHE=/tmp/gocache`。

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 调度器：竞态检测、随机差分用例与详细判定日志
go test -race -v ./scheduler
go test -race -run TestRandomEquivalentToSerial -v ./scheduler

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

gofmt -l .
