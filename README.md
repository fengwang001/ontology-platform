# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 常带宽服务器（CBS）带宽账本与零松弛回收器

`cbs` 包实现常带宽服务器（Constant Bandwidth Server）的带宽账本：
每台服务器有预算 `Q` 与周期 `P`（`1≤Q≤P≤10^6`，最多 32 台），预留带宽
`Q/P`，总带宽上限为 1。服务器保存剩余预算 `q`、截止期 `d`、待处理工作量
`w`，系统时钟 `now` 单调不减。

### 状态与零松弛判定式

服务器状态是 `now` 的纯函数（不落盘）：

- **就绪**：`w > 0`；
- **空闲占用**：`w = 0` 且曾被唤醒，且零松弛未到；
- **已释放**：从未被唤醒，或零松弛已到。

零松弛判定式（恰相等即算已释放）：

```
q·P ≥ (d − now)·Q
```

乘积可达 10^21 以上，全部用 `big.Int` 做 128 位安全比较，不使用浮点。

### 唤醒与补充规则

- `Wake(编号, now, 工作量)`：就绪者只累加 `w`；空闲占用者保持 `q`、`d`
  不变，`w` 置为工作量；已释放者须先通过接纳控制——其余占用带宽加
  `Q/P` 不超过 1——才置 `q=Q`、`d=now+P`、`w=工作量`，否则报“带宽不足”
  且不改任何状态（旧 `q`、`d` 保留，之后带宽空出时重试可通过）。
- `Run(编号, now, δ)`：服务器必须就绪、`δ≤w`，且是就绪者中截止期最早者
  （并列取编号字节序小者）。每消耗 1 单位 `q` 减 1，`q` 归 0 时立即补满为
  `Q` 且 `d` 加 `P`（`δ` 可跨越多次补充，`d` 一次加多个 `P`；`q` 恰在 `w`
  归零的同一单位耗尽时也照常补满）。结束后时钟为 `now+δ`，`w` 减 `δ`。
- `Remove(编号)`：仅已释放者可删，否则报“占用中”。
- 拒绝原因按固定顺序只报第一个：参数非法 → 编号重复/容量已满（仅 Add）
  → 编号不存在 → 时钟回退 → 带宽不足（仅 Wake）→ 不可运行（Run）
  → 非最早截止（Run）→ 占用中（Remove）。被拒绝的操作不改变任何
  `q`、`d`、`w` 与系统时钟。

### 带宽占用口径

就绪与空闲占用的服务器占用带宽 `Q/P`，已释放者不占用；任何时刻占用之和
不超过 1。`Total()` 返回占用带宽之和的既约分数（`big.Rat` 精确求和）；
`Next()` 返回就绪者中截止期最早者；`State(编号)` 按当前时钟判定状态。
所有操作与查询由单把互斥锁串行化，可并发调用，结果等价于某个串行顺序；
相同操作序列重放得到完全相同的 `q`、`d` 与拒绝点。

### 本地验证

```bash
# 全部单元测试（含规格示例走查、零松弛边界、64 位溢出场景）
go test ./cbs/

# 对拍：2000 组随机操作序列 vs 逐步朴素模拟器，
# -v 日志逐条打印输入、输出与判定依据
go test ./cbs/ -run TestDifferentialRandom -v

# 竞态检测
go test -race ./cbs/
```

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```
