# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 合约广告库存预订簿（`booking` 包）

`booking` 实现带超订比例、定向交叉可行性校验与候补顺位的合约库存预订簿。

### 容量与可行性

- 构造参数：单元个数 `C`（1–10）、各单元库存 `s_j`（0–10^12）、超订比例 `rho`（1–1000，百分数）。
- 定向用位掩码 `mask`（1–2^C−1）表示非空单元子集。
- 对非空子集 `T`：`S(T) = Σ_{j∈T} s_j`，容量 `Cap(T) = ⌊rho × S(T) / 100⌋`。
  取整作用于整体求和之后（如 `s=[105,55]`、`rho=90` 时 `Cap({0,1})=144`，
  而非逐单元取整之和 143）。
- 已预订集合可行 ⟺ 对每个非空子集 `T`：所有 `mask ⊆ T` 的已预订合约
  `qty` 之和 ≤ `Cap(T)`。这是各合约都能整量落在自己定向单元内的充要条件。

### 受影响子集的推导

每次判定只枚举负载真正变化的子集，且枚举全部、不提前退出：

- `Book`、递补扫描中的候补项、`Resize` 变大：新增负载只落在 `T ⊇ mask`
  的子集上，共 `2^(C−|mask|)` 个。
- `Retarget(m1 → m2)`：`T ⊇ m1 ∩ m2`（即同时包含两者）的子集负载不变，
  只需检查 `T ⊇ m2` 且 `T ⊉ m1` 的子集，共 `2^(C−|m2|) − 2^(C−|m1∪m2|)` 个。
- `Book` 的永不可订单点判定（`qty > Cap(mask)`）不计入子集考察计数。

考察次数由内部计数器累计，可通过 `SubsetChecks()` 读取，测试对
C=4 与 C=10 两档按上述闭式公式验证。

### 操作语义

- `Book(id, mask, qty)`：先判 `qty ≤ Cap(mask)`，否则拒绝为永不可订
  （不进候补）；再判加入后可行性，可行则预订，否则进入候补队列尾部。
- `Cancel(id)`：已预订的移除并触发递补；候补中的直接移除，不触发递补。
- `Resize(id, q2)`：仅限已预订合约；变小触发递补，变大须加入后可行否则
  拒绝（不进候补），相等为空操作。
- `Retarget(id, mask2)`：仅限已预订合约；新定向须可行否则拒绝，成功则
  触发递补；与旧定向相同为空操作（不触发递补）。
- 递补：按候补到达顺序只扫一遍，逐项判断加入当前已预订集合（含本轮
  已递补者）后是否可行，可行即转为已预订，不可行留在候补中且**不阻塞**
  后续项。
- 拒绝原因按固定优先级只报第一个：参数非法 → 合约已存在 → 合约不存在
  → 合约未预订 → 永不可订 → 不可行。被拒绝的操作不改变任何状态。

### 并发与确定性

所有操作与查询在同一互斥锁下串行化，递补是触发操作的一部分，任何
观察者都看不到递补的中间状态；任意时刻已预订集合可行。相同的操作
序列重放得到完全相同的预订、候补与递补顺序。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

gofmt -l .
