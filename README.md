# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## fslog：前向安全的密钥演进审计日志

`fslog` 包实现了一个前向安全的密钥演进审计日志及一趟检查点校验器。

### 密钥演进、换钥与标记

密钥与标记都是 `uint64`，由构造时注入的三个确定性函数产生：

- `Evolve(k)`：普通演进。每写入一条数据或封存记录，当前密钥恰调用一次 `Evolve`，旧密钥立即丢弃。
- `Rekey(k, i)`：换钥。写入换钥记录（`Typ=2`）时，当前密钥恰调用一次 `Rekey(k, i)`（不调用 `Evolve`）。
- `Mac(k, i, typ, ts, data)`：第 `i` 条记录的标记，使用第 `i` 个密钥计算。

写入者任意时刻只保存当前密钥 `ki`、下一条序号 `i`、`lastTs` 与封存标志。条目类型：`0` 数据、`1` 封存、`2` 换钥；封存与换钥记录的 `Data` 为序号 `i` 的十进制 ASCII 文本。时间戳取值 `0..10^15`，可相等但不得小于 `lastTs`。容量 `cap`（`2..10^6`）含封存记录：追加与换钥要求写入后总条数不超过 `cap-1`，为封存记录预留一个位置。`Export()` 导出当前 `(i, ki)` 供校验者托管，封存后不可导出。

### 一趟检查点校验

`Verify(entries, checkpoints, funcs)` 的输入为按位置 `0..m-1` 排列的条目列表与非空、序号互不相同的检查点集合 `(序号, 密钥)`。设最小序号为 `j0`：

- 位置小于 `j0` 的条目不可校验，只计入 `u=min(j0, m)`，内容完全不看。
- 从 `t=j0` 起令 `k` 为 `j0` 处检查点密钥，对 `t` 递增逐位置处理，每个位置按固定次序判定：
  1. 若有序号为 `t` 的另一检查点，比较其密钥与推导出的 `k`，不等报**检查点冲突**；
  2. `Index > t` 报**缺口**，`Index < t` 报**回放**；
  3. 前一条（`t>j0` 时）是封存记录报**封存后追加**；
  4. `t>j0` 且 `Ts` 小于前一条报**时间回退**（先于标记比较；`t=j0` 处不做此检查）；
  5. `Typ` 不属于 `0/1/2` 报**篡改**（不调用 `Mac`）；
  6. `Tag` 不等于 `Mac(k, t, Typ, Ts, Data)` 报**篡改**；
  7. `Typ` 为 `1` 或 `2` 而 `Data` 不等于 `t` 的十进制文本报**内容不符**；
  8. 全部通过则记为已校验，`Typ=2` 时令 `k=Rekey(k, t)`，否则 `k=Evolve(k)`。
- 处理完全部 `m` 条后：若 `m` 处有检查点则与当前 `k` 比较，不等报**检查点冲突**；其后若仍有序号大于 `m` 的检查点，报**尾部截断**，位置为 `m`。

第一个出错即停止。报告含类别、位置、已校验条数、不可校验数 `u`、`Evolve`/`Rekey` 调用次数，以及无错误时的「已封存」标志（最后一条为通过校验的封存记录）。校验一趟完成：`Evolve` 次数恰等于已校验的非换钥条数，`Rekey` 次数恰等于已校验的换钥条数，不对每个检查点从头重新演进，也不多演进一步。

### 前向安全的适用范围

由于旧密钥被丢弃且演进不可逆，持有第 `c` 条检查点密钥的攻击者只能重写第 `c` 条及之后的条目（重新计算标记即可通过校验），而无法伪造 `c` 之前的任何条目——改动 `c` 之前任一条必被标记校验发现。注意此性质依赖演进与标记函数的单向性：测试中的线性示例函数可被逆推，仅用于演示；实际部署应使用如 SHA-256 折成 `uint64` 的单向函数。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```
