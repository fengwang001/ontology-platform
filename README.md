# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## SSN 认证器（`./ssn`）

`ssn` 包在快照隔离（SI）之上实现串行安全网（Serial Safety Net）认证器，
在提交时以**排除窗口**判据拒绝可能造成非串行化的事务。

### 数据与水位

- 全局提交计数 `n`（初值 0）；`Begin()` 记快照号 `s = n`。
- 每键一条版本链，每个版本携带：创建号 `cs`、读者高水位 `ps`（初值 0）、
  后继水位 `ss`（初值 `+∞`，即 `ssn.Inf`）。初始版本为 `cs=0, 值=0`。
- 读集持有版本对象本身：版本即使后来被截断回收，其水位仍随对象存在
  并继续参与认证。

### η 与 π 的定义

事务 `t` 提交时取候选提交号 `c = n + 1`：

- **前驱高水位** `η = max( 读集各版本的 cs, 写集各键最新版本的 cs 与 ps )`。
  一个键既读又写时，读到的版本与最新版本是同一版本。
- **后继低水位** `π = min( c, 读集各版本在提交此刻的 ss )`。
  注意取的是提交此刻的 `ss`，而非读到该版本那一刻的值。

### 排除窗口判据

1. 写集中任一键最新版本 `cs > s`：以**写写冲突**中止（先于安全网上报）。
2. 若 `π <= η`：以**串行安全网**中止。直觉上，`η` 是所有"必须排在
   本事务之前"的前驱上界，`π` 是所有"必须排在本事务之后"的后继下界，
   窗口关闭（`π <= η`）则不存在可串行化位置。
3. 否则提交：`n = c`。

两种中止原因以不同的 `Reason` 上报；中止不消耗提交号，`n`、所有版本链
与水位逐字段不变。只读事务同样走上述流程并消耗提交号。

### 水位更新时机

仅在提交成功（第 3 步通过）时更新：

- 读集每个版本 `ps = max(ps, c)`；
- 写集每个键的**原最新版本** `ss = π`（是 `π` 而不是 `c`，后继水位由此
  沿版本链传递）；
- 写集每个键追加新版本 `(cs=c, ps=0, ss=+∞)`，链长超过 `H` 丢弃最旧者。

认证阶段（①②③）访问的版本数不超过读集与写集大小之和（由非导出计数器
`validateAccesses` 验证）；`Dump()` 等导出观察方法不计入。

### 本地验证

```bash
# 全部测试（含 2000 组随机序列与朴素模拟对照、依赖图暴力无环验证）
go test ./ssn

# 查看日志：输入、输出与判定依据（η/π 计算、水位变化）
go test -v ./ssn

# 竞态检测（所有调用可并发，等价于某个串行顺序）
go test -race ./ssn
```
