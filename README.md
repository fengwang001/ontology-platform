# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## ACL 求值器（`acl` 包）

带继承标志、仅继承位与保护开关的有序访问控制列表求值器，维护资源树并推导各节点的有效列表。

### 模型

- 构造：`NewStore(D, K)`，`D` 为深度上限（1..64），`K` 为单节点显式条目数上限（1..64），否则整体拒绝。根节点编号为 `/`，是深度 0 的容器。
- 变更：`AddNode(id, parent, container)`、`SetACL(node, aces, protected)`（原子整体替换）、`Move(node, newParent)`（连同子树改挂，深度按子树最大深度校验）。`Version()` 返回成功修改的累计次数。
- 条目：`ACE{Allow, Principal, Mask(1..65535), Flags}`，标志位 `OI=1`（对象继承）、`CI=2`（容器继承）、`NP=4`（不再传播）、`IO=8`（仅继承）；`IO` 或 `NP` 出现时 `OI` 与 `CI` 至少一个。

### 显式列表排序

`X(n)` 把节点 `n` 的显式条目重排为：全部拒绝条目（保持原相对顺序）后接全部允许条目（保持原相对顺序），条目带来源节点 `n`。

### 有效列表

`E(根) = X(根)`；非根时 `E(n) = X(n)` 后接 `T(E(父), n 是否为容器)`，`n` 的保护开关为真时后一段为空。继承部分沿用父有效列表自身的顺序，不做全局「拒绝优先」重排。

### 继承变换表 T（逐条、保持父列表顺序）

子为对象时：仅当父条目标志 `f` 含 `OI` 才产生副本，副本标志为 `0`；否则不产生副本。

子为容器时：

| 父条目标志 `f` 的条件 | 结果 |
| --- | --- |
| 含 `CI`，且含 `NP` | 副本标志 `0` |
| 含 `CI`，且不含 `NP` | 副本标志 `f & (OI\|CI)` |
| 不含 `CI`、含 `OI`，且含 `NP` | 不产生副本 |
| 不含 `CI`、含 `OI`，且不含 `NP` | 副本标志 `OI\|IO` |
| 其余（`OI`、`CI` 都不含） | 不产生副本 |

副本保留来源节点、允许类别、主体与掩码；`IO` 与 `NP` 不会原样带入下一代（`IO` 只按上表重新置位）。带 `IO` 的条目不参与其所在节点的判定，但留在有效列表中并继续向下变换。

### 判定规则（已授予位累计）

`Eval(token, node, R)`：令 `G=0`，按 `E(node)` 顺序逐条处理主体属于 `token` 且不带 `IO` 的条目：

- 拒绝条目：若 `Mask & R & ^G != 0`，立即返回拒绝（决定性条目即它）；只覆盖已授予位或与 `R` 无交的拒绝被忽略，已授予位不会被收回。
- 允许条目：`G |= Mask & R`，若 `G == R` 立即返回允许（决定性条目即它）。
- 走完仍未得 `R`：隐式拒绝，无决定性条目，返回当前 `G`。

结果含允许与否、结果类别（授予 / 命中拒绝 / 隐式拒绝）、决定性条目的下标与来源节点、是否继承（来源节点不是 `node`）以及 `G`。

### 保护开关

节点保护开关为真时，其有效列表不含任何继承部分（`E(n) = X(n)`），但不影响本节点显式条目，也不影响更深层节点继续从该节点继承（除非更深层节点自身受保护）。

### 错误类别

按「参数非法 → 节点不存在 → 冲突 → 超限」的顺序只报第一个；被拒绝的操作不改变任何节点、条目、保护开关与 `Version`。`Move` 先查 `node` 再查 `newParent`。

### 并发与计数

所有操作可并发调用，效果等价于某个串行顺序。`Eval` 内部记录两个非导出计数：访问的节点数（从目标节点沿祖先链到最近的保护节点（含）或根的链长）与处理的条目数（判定循环取出的条目数，含被跳过者，提前返回时只计到决定性条目）；`Effective` 不计入。
