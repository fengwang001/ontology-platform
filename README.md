# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## infer 包：带层级泛化与值限制的 Hindley-Milner 合一推断会话

`infer` 包（`ontology/infer`）实现一个可并发调用的合一推断会话。
会话以构造子表（名字到元数：名字 1–32 字节非空串，元数 0–4，1–16 个构造子）
与变量上限 V（1–10^6）构造；类型为 `Var(id)` 或 `Con(名字, 参数列表)`。

### 合一与层级调整

- 会话维护当前层级 L（初值 0，`Enter`/`Leave` 增减，范围 0–1000）、
  从 1 起严格递增无空洞的变量编号、每个变量的层级与绑定、以及模式环境。
- `Unify(a, b)` 先完整校验两侧类型（先左后右），再按固定过程递归合一：
  两侧各取 Prune（沿绑定链走到未绑定变量或构造子应用）；同一未绑定变量成功；
  一侧是未绑定变量时把它绑定到另一侧——另一侧是变量时其层级取两者较小值，
  是构造子应用时先做出现检查（沿已有绑定解析后变量出现在右侧即失败），
  通过后把右侧内每个层级更高的未绑定变量降到该变量的层级，再绑定；
  两侧都是构造子应用时名字不同即构造子不匹配，相同则按参数从左到右逐对合一。
- 一次 `Unify` 是原子步骤：失败时本次全部绑定与层级调整都撤销，
  任何观察者都看不到中间状态。未绑定变量的层级只会变小（出生时除外）。

### 泛化与值限制

- `Bind(名字, 类型, 昂贵)` 在当前 L 下泛化：先取类型的完全解析形式 R，
  再取 R 中层级严格大于 L 的未绑定变量，按从左到右先序首次出现排成
  量化列表（重复只记一次，层级恰等于 L 不量化）。
- 昂贵为假：量化这些变量，模式内按列表次序重编为 G0、G1……，
  与原变量解除关联，原变量保持原状。
- 昂贵为真（值限制）：不量化，把这些变量的层级都降为 L，模式保留原变量。
- 环境容量 1000 个名字；拒绝次序为参数非法 → 重名 → 容量超限。

### 实例化编号规则

- `Lookup(名字)` 返回模式实例：每个量化变量按量化次序依次换成新变量，
  层级为当前 L，编号连续递增；未量化部分与原变量共享。
  新变量会使总数超过 V 时拒绝且不消耗编号。
- `Resolve` 返回完全解析形式；`Level(id)` 返回 Prune 后未绑定变量的层级，
  已绑定到构造子应用则拒绝。
- 所有拒绝原因可用 `errors.Is` 区分（见 `infer/errors.go`）；
  被拒绝的操作不改变任何状态；相同操作序列重放得到完全相同的状态。
