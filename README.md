# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 带燃料计量的栈式解释器（`vm` 包）

`vm` 包实现一个嵌套调用的栈式指令解释器，按指令与内存扩展扣减燃料，
失败按帧回滚存储，并保证燃料账目逐帧可核对。

### 指令与固定费用

| 指令 | 费用 | 语义 |
| --- | --- | --- |
| `PUSH v` | 1 | `v` 入栈 |
| `ADD` | 2 | 弹出 `a, b`，压入 `b+a` |
| `LOAD` | 3 | 弹出键，压入存储值（缺省 0） |
| `STORE` | 4 | 依次弹出键、值（栈顶为键），写入本帧存储层 |
| `EXPAND n` | 2 + 水位差 | 内存高水位（字，只增不减）抬到至少 `n` |
| `CALL t, g` | 5（另计转发） | 调用程序 `t`，请求燃料 `g` |
| `RETURN` | 1 | 本帧成功返回 |
| `FAIL` | 1 | 本帧主动失败 |

内存以字为单位、只增不减。扩展到 `n` 字的累计成本为

```
cost(n) = 3n + n*n/512
```

`EXPAND n` 只在 `n` 超过当前高水位时收取新旧水位的成本差
`cost(n)-cost(旧水位)`，另收固定费用 2；不超过水位时只收固定费用。
费用在指令执行前预扣，扣不动即耗尽燃料（残余燃料全部记为消耗）。

### 调用转发规则

1. `CALL` 先扣自身固定费用 5。记扣后父帧剩余量为 `r`。
2. 实际转发量为 `min(g, r - r/64)`（整数除法），转发量立即从父帧划出。
   例如 `r = 64k+63` 时上限恰为 `63k+63`；`r=255`（`k=3`）时上限为 252。
3. 子帧结束后：
   - 成功：子帧写入并入父帧，未用完的燃料退回父帧，栈上压成功标记 `1`。
   - 子帧燃料耗尽：转发量**全部消耗、不退还**，子帧写入丢弃，
     父帧继续执行，栈上压失败标记 `0`。
   - 其他失败（栈下溢、主动失败等）：写入丢弃，**剩余燃料退还**，
     父帧继续执行并得到失败标记。
4. 调用深度：根帧深度为 1，允许到 `MaxCallDepth = 4`。在深度 4 发出的
   `CALL` 视为子帧**立即深度超限失败**：照常扣 5 的调用费，但不转发
   任何燃料，报告中生成一条 `FailDepthExceeded` 的合成子帧记录。

### 静态检查（执行前整体拒绝）

`NewExecutor` 会对全部程序做静态校验，任一不合法则拒绝整个程序集，
不产生任何执行与存储变更：

- 未知操作码；
- `CALL` 目标下标不存在；
- `EXPAND` 扩展量为负；
- `CALL` 请求燃料为负。

运行期失败按可区分原因归入所在帧：`FailOutOfFuel`（燃料耗尽）、
`FailStackUnderflow`（栈下溢）、`FailExplicit`（主动失败）、
`FailDepthExceeded`（调用深度超限）。

### 失败回滚范围

存储采用按帧分层的写视图：子帧读穿透父帧与已提交快照，写只落在本层。

- 子帧成功 → 本层写入并入父帧；
- 子帧失败 → 本层及全部已并入的子孙帧写入一并丢弃，父帧不受影响并继续；
- 顶层帧失败 → 根层（含所有成功子孙）整体丢弃，整个执行对共享存储不可见。

多个程序可并发提交到同一 `Store`：写锁使各次执行串行生效，读接口
（`Snapshot`/`Get`）只能看到某次执行**之前或之后**的完整存储，不会看到
半次执行；纯函数式执行（无随机、无时间、无 map 迭代依赖）保证相同输入
反复执行结果完全相同。

### 燃料守恒式

每个执行结果的 `FrameReport` 按帧给出 `Initial / Consumed /
SentToChildren / Returned`，单帧恒等式为

```
Initial = Consumed + SentToChildren + Returned
```

其中 `Consumed` 只统计本帧自身指令费与内存扩展差，`SentToChildren` 为
净转发（转发 − 退回）。在整棵帧树上净转发逐级抵消，顶层守恒式为

```
初始燃料 = 顶层剩余燃料 + Σ(每一帧自身 Consumed)
```

转发给“燃料耗尽”子帧的燃料计入子帧 `Consumed`，不会在父子间重复计数。

### 本地验证

```bash
# 全部用例（含竞态检测）
go test -race ./...

# 查看每个用例打印的输入、输出与判定依据
go test -v ./vm
```

测试覆盖：`r=64k+63` 的转发边界（上限/恰好/超出/原样转发/不足）、
内存扩展增量计价（64→128 字）、子帧耗尽而父帧写入保留、孙帧成功但
子帧失败时孙帧写入一并撤销、深度上限合成失败帧、顶层失败全撤（含
栈下溢）、静态拒绝、并发串行可见性与重复执行确定性。
