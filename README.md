# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## matcher：模式匹配穷尽性与冗余检查

`matcher` 包提供带类型登记与按序增臂的模式匹配检查器：
`DefineType` 登记代数数据类型，`NewSession` 开启会话，
`AddArm` 逐条追加匹配臂并返回冗余判定，`Check` 返回穷尽性与规范反例。
所有方法可并发调用，结果等价于某个串行顺序；相同操作序列重放得到完全相同的输出。

### 冗余的覆盖语义

- 一条臂的顶层分支列表为顶层 `Or` 的各分支（无顶层 `Or` 时只有模式本身，嵌套的 `Or` 不单独报告）。
- 一个分支**冗余**当且仅当它能匹配的全部有限值，都已被**此前所有不带守卫的臂**
  以及**本臂中更前的分支**所覆盖；整臂冗余当且仅当全部分支冗余。
- 带守卫的臂仍会逐分支给出冗余判定（本臂内更前的分支参与本臂后面分支的判定），
  但它不参与此后任何臂的冗余判定与穷尽性。
- 判定基于"覆盖"而非语法：模式先按从左到右先序展开成无 `Or` 的行
  （通配展开数为 1，构造子为各子模式展开数之积，`Or` 为各分支之和），
  再以矩阵特化/默认操作递归判定分支的每个取值是否被覆盖行集覆盖。

### 规范反例的构造

`Check` 不穷尽时返回由下述过程唯一确定的反例 `Missing(行集, 类型序列)`：
行集由各不带守卫的臂展开 `Or` 后的行按臂序、分支序组成。

- 类型序列为空：行集为空则反例为空序列，否则无反例。
- 首列构造子集合 Σ 含首类型的全部构造子：按声明顺序逐个特化
  （保留首列为该构造子或通配的行，首列换成各子模式，通配换成等长通配），
  递归取第一个有反例的构造子，把反例前 k 个模式包成 `c(...)` 再接其余模式。
- Σ 不完全：取默认行集（仅首列为通配的行，去掉首列）递归；
  反例首个模式在 Σ 为空时取 `_`，否则取声明顺序中第一个不在 Σ 的构造子
  并以字段数个 `_` 为参数。

反例文本：构造子名后接括号，子项以 `, ` 分隔，零字段构造子只写名字，通配写 `_`。

### Check 缓存与失效条件

`Check` 结果按会话缓存。自上次 `Check` 之后，若只加入了**带守卫的臂**或
**整条冗余的不带守卫的臂**（二者都不改变覆盖），再次 `Check` 直接返回缓存；
只有加入**含非冗余分支的不带守卫的臂**才使缓存失效。
包内以非导出计数器 `missingCalls` 记录 `Missing` 的实际计算次数，测试据此验证缓存行为。

### 本地验证

```bash
# 全部测试（含 2000 组随机类型与臂序列的朴素模拟对照）
go test ./matcher

# 查看对照日志（输入、输出与判定依据）
go test ./matcher -run TestFuzzAgainstNaive -v

# 竞态检测
go test -race ./matcher
```

朴素模拟对照（`matcher/fuzz_test.go`）枚举每个类型的全部
深度不超过"模式最大深度 + 2"的有限值，逐条臂比对分支冗余与整臂冗余、
逐次 `Check` 比对穷尽性，并验证反例匹配的所有枚举值都不被任何不带守卫臂覆盖。
