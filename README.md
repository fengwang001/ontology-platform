# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 密钥轮换调度器（`keyring` 包）

`keyring` 实现签名密钥集合的四步轮换调度，保证：任何在有效期内签发的令牌，
在任意验证方缓存状态下都能验证；已退役的密钥不再被任何合法令牌需要。

### 四步状态

1. **已发布（published）**：新密钥立即进入验证集合，仅供验证，不可签发。
2. **活跃（active）**：到启用时刻后成为唯一活跃密钥，可签发、可验证；
   旧活跃者同时转为停签。
3. **停签（deactivated）**：只验证不签发，仍留在验证集合。
4. **退役（retired）**：从验证集合移除，不再出现。

### 各最早时刻的推导

设验证方缓存最长保留时间为 `C`、令牌寿命为 `T`、验证方接受的时钟偏差为 `S`，
在时刻 `t` 请求轮换：

- **启用时刻 = `t + C`**：验证方缓存最迟 `C` 后刷新，此后任意验证方都能拿到
  新密钥，新密钥才可开始签发；启用时刻恒定，与何时被观察到无关。
- **停签时刻 = 启用时刻**：启用与旧密钥停签是同一事件的两个侧面，
  因此停签时刻记为启用时刻，而不是某个操作观察到它的时刻。
- **最早退役时刻 = 停签时刻 + `T` + `S`**：停签前最后一刻签发的令牌，
  在时钟最落后 `S` 的验证方眼中要到 停签时刻+`T`+`S` 才过期；
  恰到该时刻退役，已退役的密钥不再被任何合法令牌需要。

由此可证令牌不变量：令牌在时刻 `i` 由活跃密钥 `K` 签发，则任何待启用密钥的
启用时刻都大于 `i`，故 `K` 的停签时刻大于 `i`，其最早退役时刻大于
`i + T + S`，即 `K` 在 `[i, i+T+S)` 内始终在验证集合中。

### 标识不复用

已退役密钥的标识永久保留（含初始密钥）。验证方缓存中的旧密钥材料可能以标识
索引，若复用标识，滞后的缓存会把新密钥与已退役的旧密钥混淆，破坏验证语义与
审计确定性；因此轮换时新标识与任何曾用标识（含已退役）冲突即拒绝。

### 惰性推进与并发

状态随注入时钟惰性推进：每个操作先完成所有到点的启用再执行自身逻辑；
时钟读数早于已见最大读数即拒绝，被拒绝的操作不改变任何状态。
所有操作（轮换、退役、签发、查询）经互斥锁串行化，可并发调用；
相同的操作与时钟序列得到相同状态。
