# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 分区级过期判定与回填规划（`staleness` 包）

`staleness` 包实现分区级数据资产的过期判定、最小回填规划与重写影响面分析。

### 模型

- 资产按整数日序号分区，声明范围 `[first,last]`。
- 依赖边（上游 `U` -> 下游 `D`，偏移 `lo<=hi`）表示 `D` 的分区 `d` 读取 `U` 的
  分区 `[d+lo, d+hi]` 闭区间，落在 `U` 声明范围外的忽略。
- 无上游的资产为源；外部写入使其分区版本加一，首次写入即视为已物化。
- 层深：源为 0，其余为上游层深最大值加一；依赖成环（含自依赖）在 `Build` 时拒绝。

### 过期定义

已物化分区过期，当且仅当存在某个输入分区满足：物化时记录的消费版本与该输入的
当前版本不等，或该输入分区自身过期（递归传递）。未物化者为缺失，不算过期。

### 消费版本记录时机

消费版本在**物化运行开始时**记录（全部输入分区此刻的版本快照），成功完成时
分区版本加一并以该快照作为其消费版本。因此运行期间输入被改写时，结果一落地
即过期——与按定义逐分区重算一致。开始要求全部输入已物化且不过期；同一分区
已有运行中的不得再开始；失败完成不改变任何状态。

### 回填规划推导

`PlanBackfill(targets)` 从目标分区出发沿依赖边遍历全部传递输入，收集其中
**缺失或过期**的分区（新鲜的一律不进入），按（资产层深，资产名，分区号）升序
返回。任一目标非法（未知资产、分区越界）时整体拒绝，不改变任何状态。

### 影响面推导

`Impact(asset, part)` 在同一致快照上模拟“该分区被重写（版本加一）”，对重写前后
各做一次全量过期判定并取差集：传递地**将变为过期**的已物化下游分区即为影响面，
次序与规划相同。已过期的下游不算“将变为过期”，不进入结果。

### 并发与一致性

所有公开操作（开始、完成、外部写入、判定、规划、影响面）均可并发调用；内部由
同一把互斥锁串行化，每次判定基于一致快照，规划结果与某个串行顺序一致；同一
分区并发开始只成功一次。

### 错误

所有被拒绝的操作返回 `*staleness.Error`，`Kind` 字段区分原因（未知资产、重复边、
依赖成环、偏移非法、范围非法、分区越界、已有运行中、输入未就绪、运行号不存在、
非源外部写入等）；输入未就绪时 `Missing`/`Stale` 字段列出全部缺失或过期输入。
被拒绝的操作不改变任何状态。

### 本地验证

```bash
# 运行该包全部测试（日志含输入、输出与判定依据）
go test ./staleness/ -v

# 竞态检测
go test ./staleness/ -race
```
