# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 图脏判定（`graphdirt`）

`graphdirt.Detector` 以边为构建单元。每个边包含命令、至少一个输出，以及三类输入：

- 显式输入：修改时刻可使本边自身变脏，其产出边变脏也会传播到本边。
- 隐式输入：参与修改时刻与脏传播，语义上表示发现式依赖，但判定规则与显式输入相同。
- 仅排序输入：只保证其产出边先构建；它自身的修改时刻不使本边脏，其产出边脏也不传播到本边，但仍进入目标依赖闭包。

### 自身脏与脏

边“自身脏”只检查自身状态，满足任一条即为脏：

- 没有成功完成日志，或日志命令不同于当前命令。
- 任一输出文件不存在。
- 非 restat 边：多个输出取最小修改时刻，该值严格小于当前显式与隐式输入修改时刻最大值；相等不脏。
- restat 边：不比较输出修改时刻，而比较日志中的 `InMax < 当前输入最大值`。这允许命令重跑后输出文件保持旧时间戳。

边“脏”在自身脏之外，还会沿显式和隐式输入继承其产出边的脏状态。仅排序输入不传播脏，但脏的仅排序上游仍会作为闭包成员出现在结果中。输入没有可取修改时刻时，输入最大值为 `0`。

`Complete(edgeID, outputs)` 要求输出映射的键集恰好等于边的输出集合，所有时间戳至少为 `1`，且显式和隐式输入都存在。成功后写入输出时间戳，并把日志记录为 `(当前命令, 当前显式与隐式输入时间戳最大值)`，因此可立即再次调用 `DirtySet` 重新核对。

### 错误优先级

被拒绝的操作不会修改图、文件时间或日志。错误优先级如下：

- `AddEdge`：空边号、边号已存在、输出为空、路径为空、输出已有产出边、输出与输入重叠、加入后成环。
- `SetMtime`：空路径、时间戳小于 `1`；`Remove` 对空路径返回同类空路径错误。
- `Complete`：边不存在、输出集合不符、时间戳小于 `1`、显式或隐式输入缺失。
- `DirtySet`：先按目标列表顺序报告第一个既不是输入也不是输出的路径；然后闭包边按边号字节序、每边按显式/隐式/仅排序及列表下标顺序，报告第一个无产出边且文件缺失的路径。

所有方法由内部读写互斥保护，并发调用等价于某个合法串行顺序。`DirtySet` 使用迭代遍历和拓扑求值，深度 20000 的链不会栈溢出；同一次调用中闭包内每条边只求值一次。

### 本地验证

```bash

go test ./...

# 竞态检测
go test -race ./...

# 查看随机对拍日志（输入、当前文件时间和判定结果）
go test -v -run TestRandomGraphsMatchNaiveDefinition ./graphdirt
```

测试包含 2000 组随机图与时间戳，对拍“按定义逐边无记忆递归”的朴素实现；同时验证 1000、20000 条边的共享菱形与深度 20000 的线性链。
