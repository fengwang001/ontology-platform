# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## hdlc 包：位填充帧编解码

`hdlc` 提供 HDLC 风格的位填充帧编码器（`Encoder`）与流式解码器（`Decoder`），
两者均可并发调用，效果等价于某个串行顺序；解码结果与输入的字节切分方式无关。

### 位序与帧格式

- 位序：每字节低位（LSB）先传。
- 帧内容：载荷字节 + 2 字节 FCS（低字节在前）。
- FCS：CRC-16/X-25（多项式 0x1021 反射为 0x8408，初值 0xFFFF，结果取反；
  字符串 `123456789` 的校验值为 `0x906E`）。
- 载荷长度须在 1 到 `MaxPayload` 之间；空载荷或超长载荷被 `WriteFrame` 拒绝，
  不输出任何位，也不改变共享标志状态与位缓冲。

### 位填充与标志

- 内容位流中每出现连续 5 个 1 就在其后插入一个 0；内容恰好以 5 个 1 结尾时同样插入。
- 标志为 `01111110`。编码器在首帧前输出一个标志，每帧后输出一个标志，
  该标志兼作下一帧的起始标志（相邻帧之间只有一个标志）。
- `Flush` 把输出补齐到整字节，补的位全为 1；之后下一帧重新输出起始标志。

### 解码规则

- 凡最近收到的 8 位等于 `01111110` 即识别为标志，这 8 位不属于内容；
  相邻标志允许共享中间的一个 0（`0111110 1111110` 构成两个标志，其间内容为零位）。
- 两个标志之间的其余位为原始内容位；连续 1 满 5 个后的 0 是填充位，丢弃。
- 连续 1 达到 7 个即中止：丢弃当前帧、回到搜索态，`Aborts` 加一
  （Flush 补的 1 若恰为 7 位同样计一次中止，不做特殊处理）。
- 搜索态下只有最近 8 位全是中止之后（或流开头之后）收到的位且等于标志才生效；
  流开头的 1 不能充当标志前的 0。
- 两个标志之间内容为零位的是空闲，忽略且不计数；丢弃填充位之后的位数才用于
  「是否 8 的倍数」的判定。
- 帧在收到结束标志时判定，按顺序只报第一个丢帧原因并分别计数：
  `DroppedBadLength`（内容位数不是 8 的倍数）、`DroppedTooShort`（内容少于 3 字节）、
  `DroppedBadFCS`（FCS 不符）。丢帧后解码继续同步下一个标志，不会失败。
