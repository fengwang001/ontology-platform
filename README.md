# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 单寄存器线性一致性检查器（`register` 包）

`register` 包收集并发客户端的调用/返回记录，判定历史是否可线性化，
并在可行时给出唯一确定的见证序。寄存器初值为 0，支持写 `write(v)`、
读 `read()`（返回值 `r`）、比较交换 `cas(e, n)`（返回成功或失败）。

### 使用

```go
c := register.NewChecker()
id, err := c.Begin("client-a", register.NewWrite(1), 0) // 客户端、操作、调用时刻
err = c.End(id, 5, register.WriteResult())              // 编号、返回时刻、结果
ok, witness := c.Check()                                // 判定结论与见证序
```

`Begin`/`End`/`Check` 均可被并发调用；`Check` 基于调用瞬间的一致快照，
相同历史反复调用得到相同结论与相同见证序。

### 全序条件

判定把全部已结束操作及任意一部分未结束操作排成全序，需同时满足：

- **实时先后**：a 的返回时刻严格小于 b 的调用时刻，则 a 必在 b 前；
  时刻相等视为并发，不强制顺序。
- **寄存器语义**：从初值 0 出发，读返回值须等于此刻当前值；
  CAS 成功当且仅当当前值等于期望值（成功后当前值变为新值），
  失败当且仅当当前值不等于期望值（当前值不变）；写将当前值置为写入值。

### 未结束操作的处理

未结束操作视为返回时刻无穷大、结果未知：

- 未结束的**写**可放入序列并生效（可解释他人读到的值）；
- 未结束的 **CAS** 仅在当前值等于期望值时可放入并生效；
- 未结束的**读**不放入序列。

### 见证序的确定规则

见证序按深搜确定：每步候选是尚未放置、且不存在任何尚未放置的
已结束操作其返回时刻严格小于候选调用时刻的操作；按（调用时刻，编号）
升序逐个尝试，能放入就递归；已结束操作全部放完即成功，返回首个成功的
放置顺序（含被放入的未结束操作）。同一（已放置集合，当前值）失败过
则不再展开（记忆化只剪枝必然失败的状态，不改变见证）。

### 输入校验

- `Begin` 按顺序只报第一个错误并拒绝：客户端已有未结束操作、
  开始时刻小于该客户端上次结束时刻、操作总数超过 20。
- `End` 按顺序只报第一个错误并拒绝：编号不存在或已结束、
  结束时刻小于开始时刻、结果类型与操作不符（写带结果、读不带值、
  CAS 不带成功或失败）。
- 被拒绝的操作不得改变任何状态。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```
