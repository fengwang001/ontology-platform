# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

当前仓库包含一个**带撤回与预发布规则的包版本依赖求解器**（包 `depsolver`，根包导入路径 `ontology`）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 版本格式与排序

版本形如 `X.Y.Z` 或 `X.Y.Z-pre`：

- `X`、`Y`、`Z` 为 `0..9999` 的非负整数，**无前导零**（`0` 本身合法）。
- `pre` 为点分标识符序列；标识符为空非法。
  - 数字标识符：纯数字、无前导零，按**数值**比较。
  - 非数字标识符：只含字母、数字与连字符，按**字节序**比较。

排序规则（从小到大）：

1. 先比 `X`，再比 `Y`，再比 `Z`。
2. 同一三元组时，带 `pre` 的版本**小于**不带的（`1.0.0-alpha < 1.0.0`）。
3. 都带 `pre` 时逐标识符比较：
   - 两个数字标识符按数值；
   - 数字标识符小于非数字标识符（`1.0.0-1 < 1.0.0-a`）；
   - 两个非数字标识符按字节序；
   - 前面标识符全部相等时，标识符更少者小（`1.0.0-alpha < 1.0.0-alpha.1`）。

示例次序：`1.0.0-alpha.1 < 1.0.0-alpha.beta < 1.0.0-beta < 1.0.0-beta.2 < 1.0.0-beta.11 < 1.0.0-rc.1 < 1.0.0`。

## 范围语义

范围是用**空白分隔**的若干比较子的交集。语法严格：

- 空串、不含任何比较子、`op` 与版本之间有空白（如 `= 1.0.0`）均为语法非法。
- 比较子 = `op` 紧接版本；`op` 为 `=`、`>`、`>=`、`<`、`<=`、`^`、`~`。
- `^`（兼容上界，下界含、上界不含）：
  - `^X.Y.Z`，`X > 0`：`>= X.Y.Z, < (X+1).0.0`
  - `X = 0, Y > 0`：`>= 0.Y.Z, < 0.(Y+1).0`
  - `X = 0, Y = 0`：`>= 0.0.Z, < 0.0.(Z+1)`（因此 `^0.0.3` 只匹配 `0.0.3`）
- `~X.Y.Z`：`>= X.Y.Z, < X.(Y+1).0`。

## 预发布规则

- **带 pre 的候选版本**：仅当范围中至少有一个比较子本身带 pre，且其 `X.Y.Z` 与候选版本的三元组**相同**时，才可进入候选集合；其余比较子照常判定（被放行后仍要满足全部比较子）。
  - `>=1.0.0-alpha <2.0.0` 放行 `1.0.0-alpha.2`，但拒绝 `1.5.0-beta`。
  - `>=1.0.0-alpha.5 <2.0.0` 虽放行了 `1.0.0` 三元组的 pre，但 `1.0.0-alpha.2` 仍因小于下界被拒绝。
- **不带 pre 的候选版本**：只按比较子判定。

## 发布与撤回

- `Publish(PackageVersion{Name, Version, Dependencies})`：
  - 版本格式非法 → `ErrInvalidVersion`；
  - 同名同版本重复发布（含已撤回版本）→ `ErrDuplicateVersion`；
  - 任一依赖范围语法非法 → `ErrInvalidRange`；包名为空 → `ErrEmptyPackageName`。
- `Yank(name, version)`：被撤回的版本**仍然存在**但不参与求解选择；撤回不存在的版本 → `ErrVersionNotFound`。
- 任何被拒绝的操作都在持锁状态下完成校验后才写入，**不会改变仓库**。

## 求解与搜索次序

`Solve(ctx, root)` 以根依赖（包名 → 范围）为输入，返回包名到版本的映射。

- 一次求解开始时获取某一时刻的**完整不可变快照**；发布 / 撤回与求解可并发调用（`sync.RWMutex`），求解结果与发布顺序无关、可精确复现。
- 每个包最终至多选一个版本，必须满足**所有选中包**对它的约束；包之间允许循环依赖。
- 错误可区分：
  - 根范围语法非法 → `ErrInvalidRange`；
  - 依赖闭包中引用了仓库里不存在的包 → `ErrPackageNotFound`；
  - 约束无法同时满足 → `ErrNoSolution`。
- 固定搜索次序：
  1. 始终先决定「已有约束但尚未决定」的包中**名字字节序最小**者；
  2. 该包的候选版本（已排除撤回）**从高到低**依次尝试；
  3. 候选必须同时满足自身全部约束，且其依赖范围与**已经选定**的版本相容，依赖到的新包加入待决集合；
  4. 第一个能推出完整解的版本即被选中，失败则按相反次序回溯。

### 判定日志

通过 `depsolver.WithLogger(ctx, logger)` 注入 `Logf(format, args...)` 接收器，可打印输入、候选列表、每次拒绝原因、尝试、回溯与最终解。运行内置示例：

```bash
go run ./cmd/demo
```

## 本地验证

```bash
# 全量测试
go test ./...

# 竞态检测 + 详细日志
go test -race -v ./...

# 多次重复确认可复现
go test -count=5 ./...

# 朴素枚举对照：bruteForceSolve 独立枚举全部可行组合，
# 按同一次序模拟决策序列并取首个，与回溯实现逐项对照（见 solve_test.go）
go test -run 'TestBacktrackingRequired|TestByteOrder|TestDeterminism|TestBruteForceParity' -v

# 格式化与静态检查
gofmt -l .
go vet ./...

# 判定日志演示
go run ./cmd/demo
```

测试覆盖：`^0.0.3` / `^0.2.1` / `^1.2.3` 的上界、预发布放行与拒绝、`1.0.0-alpha.1` 与 `1.0.0-alpha.beta` 与 `1.0.0` 的次序、必须回溯才有解、撤回最高版后选次高、循环依赖、字节序最小者先决定导致与其它次序不同的解、全部可区分错误原因、并发安全与发布顺序无关性。
