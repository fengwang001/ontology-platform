# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## module 包：模块链接与求值器

`module` 包实现带循环依赖、暂时性死区（TDZ）与错误粘滞的模块链接与求值器。
核心入口：`Session.AddModule` 登记不可变模块，`Session.Evaluate` 原子地链接并求值，
`Session.Status` / `Session.Order` 查询状态与求值完成次序。

### 链接的原子性

`Evaluate` 分两步：先链接后求值。链接阶段从根沿依赖列表（导入语句来源按语句次序，
再接转出项来源按列表次序）做深度优先先序遍历，只进入"已登记"状态的模块；
随后按先序对每个模块先做全部导入的导出解析、再逐条做具名转出的解析。
任一环节失败（模块不存在 / 链接错误 / 链接歧义）整个调用被拒绝，
**不改变任何状态**（含各模块状态与函数导出的初始化位）；全部通过后才把访问到的
模块一并置为"已链接"并把它们的函数导出位置真。求值阶段的错误是结果而不是拒绝，
其对状态、初始化位与次序的修改全部保留。所有公开方法持有同一把互斥锁，
一次 `Evaluate` 对外是一个原子步骤，观察者看不到只链接了一部分或求值到一半的状态。

### 导出解析与解析集合

`ResolveExport(m, n)` 的每次顶层调用持有一个共享、只增不减的"解析集合"：
若 `(m, n)` 已在集合内（无论是祖先还是此前展开过的兄弟分支）直接返回"未找到"，
否则加入集合后展开——同一对在一次顶层调用内至多展开一次。
解析顺序：`n` 是 `m` 的本地导出则返回 `(m, n)`；否则若 `m` 有导出名为 `n` 的
具名转出 `(n, s, t)` 则返回 `ResolveExport(s, t)` 的结果（绑定、未找到或歧义原样上传）；
否则依次询问各星转出来源：任一来源报歧义则整体立即歧义；两个来源给出不同绑定
（定义模块与本地名不完全相同）则歧义；同一绑定不歧义。具名转出与本地导出优先于
星转出，星转出不提供本模块已定义的名字。

### 求值：深度优先后序与循环跳过

`Eval(m)`：已求值直接成功；出错返回其错误值；求值中直接成功返回（循环跳过）。
否则置求值中，按依赖列表次序依次 `Eval` 各来源，任一来源出错则 `m` 置出错
（继承同一错误值，体不执行）并立即返回；全部成功后按序执行体，体执行完置已求值
并追加到求值完成次序。因前面依赖出错而未被访问的后续依赖保持"已链接"，
之后从别的根求值时仍可继续。

### 暂时性死区与错误粘滞

`Read(n, x)` 先取链接时解析出的绑定 `(d, y)`（`n` 为本模块时是 `(本模块, x)`），
若 `y` 是 `d` 的 let 导出且初始化位为假，抛出错误值 `TDZ d.y`（报告定义模块名）。
函数导出在链接时即已初始化，循环中可读；let 导出在体内 `Init` 之前不可读。
`Throw(msg)` 抛出 `msg`；某步抛错则本模块置出错、体的后续步骤不执行，
但此前已执行的 `Init` 保留。出错模块永不重试，已求值与出错模块的体都不会再次执行，
let 导出的初始化位只会由假变真。

### 本地验证

```bash
# 全部测试（含 2000 组随机模块图与朴素模拟的对照、并发与不变量检查）
go test ./module/

# 查看随机对照的输入、输出与判定依据日志
go test -v -run TestDifferentialRandom ./module/

# 竞态检测
go test -race ./module/
```

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```
