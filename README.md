# ontology-platform

本包实现一个 Hekaton 风格的乐观多版本事务引擎。键编号为 `0..K-1`；每个键初始有一个由虚拟已提交事务创建的版本，值为 `0`，结束时间为 `0`。

## API

- `NewEngine(k int) (*Engine, error)`：构造 `1 <= k <= 64` 的引擎；键数越界返回 `ErrInvalidKeyCount`。
- `Begin() int`：递增全局时钟作为读时间 `RT`，返回从 `1` 起独立递增的事务号。
- `Read(tx, key int) (int, error)`：按规则扫描版本；推测读取预备创建者会记录提交依赖。
- `Write(tx, key int, value int) error`：乐观验证最新非垃圾版本；冲突时中止事务及其依赖者并返回 `ErrWriteConflict`。
- `Precommit(tx int) (int, error)`：递增时钟并转入预备态，返回事务结束时间 `ET`。
- `Finish(tx int) ([]int, error)`：标记预备事务已完成；依赖为空时提交并返回本次连续提交次序。
- `Abort(tx int) ([]int, error)`：中止活跃或预备事务，并返回升序级联集合。

拒绝原因的检查顺序固定为：事务号不存在、事务状态不符、键越界。构造参数非法时整体拒绝；被拒绝调用不改变任何状态。

## 版本可见性

扫描每个键时自新到旧跳过垃圾版本（创建者已中止的版本）。创建者为虚拟事务 `0` 或读者自己时，起点直接可见。

| 创建者状态 | 起点可见性 |
| --- | --- |
| 读者自己 | 可见 |
| 活跃 | 不可见 |
| 已中止 | 不可见，版本是垃圾 |
| 预备或已提交 | 仅当 `creator.ET < reader.RT` 时可见 |

起点可见后继续检查终点。结束者已中止的结束标记视为无效，等价于无结束者。

| 结束者状态 | 终点可见性 |
| --- | --- |
| 无有效结束者 | 可见 |
| 读者自己 | 不可见 |
| 活跃 | 可见 |
| 预备或已提交 | 仅当 `reader.RT < ender.ET` 时可见 |

因此，当新版本对读者尚未可见、但其结束事务的 `ET` 晚于读者 `RT` 时，读者仍会读到旧版本；这种情况不会对预备创建者产生依赖。只有读到的版本由“他人且处于预备态”的创建者创建时，读者才依赖该创建者。

## 写冲突与依赖

`Write` 总是选择最新的非垃圾版本 `V`：

- `V` 由当前事务创建：原地更新值，不新增版本。
- `V` 有有效结束者：写冲突，当前事务中止。
- `V` 的他人创建者仍活跃：写冲突，当前事务中止。
- `V` 的创建者预备或已提交且 `creator.ET >= writer.RT`：写冲突，当前事务中止。
- 否则追加新版本，把 `V.ender` 置为当前事务；创建者为预备态时，当前事务依赖该创建者。

成功提交的重叠事务因此不会写同一个键：更新版本要求看到更晚创建者，而更晚事务提交失败会经依赖图级联中止读者或写者。

## 提交解除与级联范围

依赖是有向边“依赖者 -> 被依赖的预备事务”。预备事务调用 `Finish` 后：

- 仍有依赖：保持预备态等待，返回空次序。
- 依赖为空：立即提交，然后按依赖者事务号升序移除边。
- 活跃依赖者只移除依赖，不自动提交；预备且已 `Finish` 且依赖变为空的依赖者进入就绪集合。
- 就绪集合反复取最小事务号提交，保证提交次序确定且可复现。

显式 `Abort` 或写冲突中止某个活跃、预备事务时，沿“被依赖者 -> 依赖者”方向收集全部直接与间接依赖者；依赖者即使仍活跃也会被中止。返回集合包含根事务并按事务号升序排列。事务终结（提交或中止）后，其依赖集合和被依赖集合都会清空。

## 并发与确定性

所有公共操作在同一个互斥锁内完成状态检查和状态修改，因此并发调用等价于某个合法串行顺序。所有次序均按事务号升序或按就绪集合最小号选择；固定随机种子重放相同调用序列会得到完全相同的返回值、版本链、依赖边、提交次序和级联集合。

## 本地验证

```bash
# 全量测试
go test ./...

# 2000 组随机调用序列：真实引擎逐步对照独立朴素模拟器
go test -run TestRandomOperationsMatchNaiveModel -v ./...

# 竞态检测
go test -race ./...

# 格式与静态检查
gofmt -w .
go vet ./...
```

若环境的默认 Go 缓存目录不可写，可为本机临时指定缓存，例如：

```bash
GOCACHE=/tmp/go-cache-ontology go test ./...
```

随机测试中的每一步都构造日志，内容包含输入、真实引擎输出、朴素模型输出和判定依据；只有结果、完整状态或不变量不一致时才打印整条 trace，便于精确定位。
