# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 单寄存器线性一致性检查器

`register` 包提供面向并发客户端的单寄存器线性一致性检查器，寄存器初值固定为 `0`。

### 操作与历史

- 写操作携带写入值；读操作完成时携带返回值；CAS 携带期望值 `e` 和新值 `n`，完成时携带成功或失败。
- `Begin` 记录整数调用时刻并分配编号；`End` 记录整数返回时刻和结果。
- 未结束操作的返回时刻视为无穷大；检查时会复制调用瞬间的一致快照，不阻塞其他 `Begin`、`End` 调用。

### 全序条件

检查器寻找一个包含全部已结束操作的全序：

- 如果操作 `a` 的返回时刻严格小于操作 `b` 的调用时刻，则 `a` 必须排在 `b` 前。
- 返回时刻与调用时刻相等视为并发，不产生先后约束。
- 写将当前值设置为 `v`；读必须观察到当前值且不改变当前值。
- CAS 当前值等于 `e` 时成功并设置为 `n`；不等于 `e` 时失败且当前值不变。

未结束操作可以选择性地进入见证：

- 未结束写可以进入，并正常生效。
- 未结束 CAS 只有在放置时当前值等于 `e` 时才能进入，并按成功 CAS 生效。
- 未结束读不进入全序。

### 见证序确定规则

见证序使用深度优先搜索确定。每一步从尚未放置的操作中选择候选：不存在任何尚未放置的已结束操作，其返回时刻严格小于候选调用时刻。候选按 `(调用时刻, 编号)` 升序尝试，能满足当前寄存器语义就递归；全部已结束操作放置完成即成功，返回首个成功顺序。

搜索会跳过已经失败过的 `(已放置集合, 当前值)` 状态。该状态只包含未来搜索所需信息，因此不会改变首个成功见证，只避免重复展开。相同快照重复检查会得到相同结论和相同见证。

### 请求拒绝规则

`Begin` 按以下顺序检查并只返回第一个错误，拒绝时不改变状态：

1. 该客户端已有未结束操作。
2. 调用时刻早于该客户端上一操作的返回时刻。
3. 历史中已有 20 个操作，即接受新操作后会超过 20。

`End` 按以下顺序检查并只返回第一个错误，拒绝时不改变状态：

1. 编号不存在，或编号对应操作已经结束。
2. 返回时刻早于调用时刻。
3. 结果类型与操作不符：写不能携带结果，读必须携带返回值，CAS 必须携带成功或失败。
