# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## resolver：带别名链的解析缓存

`resolver` 包实现沿别名链解析名字到地址的缓存解析器，上游由注入函数
`Upstream func(name string) (Answer, error)` 给出。

### 链解析规则

- 上游对每个名字返回三类应答之一：别名记录（目标名 + TTL）、地址记录
  （地址集 + TTL）、不存在应答（授权记录 TTL `S` 与最小值 `M`）。
- 解析时沿别名链逐环走查：先查缓存，未命中的环向上游查询；终点为地址
  记录时返回整条链与地址集，终点为否定条目时返回不存在。
- 返回的存活时间为链上所有环（含终点）剩余时间的最小值：缓存环取
  `到期时刻 - 现在`，上游新得的环取其 TTL。
- 别名记录超过 8 条即判定链过长。
- 拒绝按发现顺序只报第一个：名字为空 → 链成环（缓存与上游合起来成环）
  → 链过长 → 上游失败。被拒绝的解析不改动缓存（含淘汰与失效清除），
  已获得的部分记录随调用结束丢弃。

### 缓存与淘汰规则

- 缓存按名字存一条记录，同名替换；到期时刻为存入时刻加 TTL，
  `现在 >= 到期` 即失效。
- TTL 为 0 的记录不存入，但仍参与本次解析。
- 不存在应答存为否定条目，TTL 取 `min(S, M)`；失败的解析不写入缓存。
- 容量为 `C` 条：存入时先清除失效条目，仍满则淘汰到期最早者，并列时
  取名字字典序小者。

### 并发与确定性

- `Resolver` 可并发调用；并发解析同一未命中名字时只向上游查询一次
  （single-flight），等待者得到相同记录，上游失败则得到同一错误。
- 上游调用经互斥锁串行化，相同调用与上游应答序列重放结果完全相同；
  缓存条目数始终不超过 `C`。

### 本地验证

```bash
# 全部用例（日志含输入、输出与判定依据）
go test ./resolver/ -v

# 竞态检测
go test -race ./resolver/

# 单个场景，例如到期边界
go test ./resolver/ -run TestExpiryBoundary -v
```

## 带别名链的解析缓存（`aliascache` 包）

`aliascache` 实现了一个并发安全、容量受限的名字解析缓存，沿别名
（CNAME 风格）链把名字解析到地址集，缓存正反两类结果，并且只向上游
补查链上缺失（未命中或已到期）的环。

### 上游模型

上游由注入函数 `UpstreamFunc` 给出，对单个名字返回三种互斥应答：

- `Alias{Target, TTL}`：别名记录，指向另一个名字；
- `Addresses{Addresses, TTL}`：地址记录，携带地址集；
- `Negative{SOATTL: S, MinTTL: M}`：不存在应答，否定条目的存活时间
  取 `min(S, M)`。

### 链解析规则

- 从被查询名字起逐环推进：每一环先查缓存，未命中或已到期才向上游
  查询，新得的记录在整条链解析成功后一次性提交（“只补查缺失部分”）。
- 终点为地址记录时返回整条链与地址集；终点为否定条目时返回不存在。
- 两种终点的存活时间都取链上所有环（含终点）剩余时间的最小值：
  缓存环取 `到期时刻 - 现在`，上游新得环取其应答 TTL。
- 别名记录超过 8 条（`MaxAliasHops`）即链过长；链（缓存命中与上游
  新得合起来）重访任一名字即成环。
- 拒绝优先级固定：名字为空 → 成环 → 链过长 → 上游失败，不按发现
  顺序只报第一个。
- 任何拒绝都不写入已取得的部分记录：失败的解析不会污染缓存，缓存
  保持该次调用前的状态（包括不会提前触发淘汰与失效清除）。

### 缓存与淘汰规则

- 每个名字存一条记录，同名写入为替换；到期时刻为“存入时刻 + TTL”，
  `现在 >= 到期时刻` 即失效（恰在到期时刻也算失效）。
- TTL 为 0 的记录不写入缓存，但仍参与当次解析（可能把当次 TTL
  拉低为 0）。
- 存入新名字前先清除全部失效条目；若容量仍达上限 `C`，淘汰到期
  最早者，到期时刻并列时淘汰名字字典序较小者；缓存条目数不超过 `C`。

### 并发语义

- `Resolve` 可被并发调用。对同一未命中名字的并发解析由唯一发起者
  走链，其他调用等待并得到完全相同的结果；上游失败时得到同一错误。
- 链内按名字合并上游调用，因此同一次并发解析中链上每个缺失名字
  只向上游查询一次。
- 时钟可通过 `WithClock` 注入：相同调用序列、相同上游应答与相同时钟
  推进下，重放结果完全相同。
- 通过 `WithLogger` 注入 `io.Writer` 后，每次解析打印输入、逐环判定
  依据（缓存命中/上游应答/提交或跳过）以及最终输出与 TTL 取值理由。

### 本地验证

```bash
# 全部用例（含竞态检测）
go test -race -v ./aliascache

# 反复运行排查并发偶发问题
go test -race -count=10 ./aliascache

# 覆盖率
go test -coverprofile=/tmp/ac.out ./aliascache
go tool cover -func=/tmp/ac.out
```

覆盖点包括：链上最小剩余 TTL、别名命中而地址环到期只补查地址环、
否定 TTL 取 `min(S,M)`、TTL 为 0 不缓存、恰在到期时刻失效、淘汰
（先清失效 / 最早到期 / 并列字典序）、成环与失败后缓存不变、链过长、
空名字优先拒绝、并发单次上游查询与共享错误、确定性重放及日志内容。
