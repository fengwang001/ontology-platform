# ontology-platform

本仓库包含一个多实例、共享文件状态的 epoll 风格就绪事件队列，实现在 `eventqueue.go`。

## 构造与错误

```go
q, err := ontology.NewEventQueue(W, E, U)
```

- `W`：每个实例的监视项数上限，范围 `1..1_000_000`。
- `E`：实例数量，范围 `1..4`，实例编号为 `0..E-1`。
- `U`：所有实例的全局监视项总数上限，范围 `1..1_000_000`。
- 任一构造参数越界都会整体拒绝并返回 `ErrInvalid`。

可区分错误包括：

- `ErrInvalid`：参数非法。
- `ErrExists`：`Add` 时同实例同文件已有监视项。
- `ErrNoSpace`：该实例达到 `W`。
- `ErrTooMany`：全局监视项数达到 `U`。
- `ErrNoEnt`：`Mod` 或 `Del` 的监视项不存在。
- `ErrExclChange`：`Mod` 试图新增或移除 `Excl`。

被拒绝的操作不会改变任何监视项、文件状态或就绪链。

## 事件、兴趣与标志

事件位为：

- `In = 1`
- `Out = 2`
- `Err = 4`
- `Hup = 8`

标志位为：

- `ET = 1`：边沿触发。
- `OneShot = 2`：一次触发后禁用，直到 `Mod` 重新武装。
- `Excl = 4`：同一文件的多个独占监视项中，一次状态变化最多唤醒一个实例。

监视项的有效兴趣恒为：

```text
eff = interest | Err | Hup
```

因此即使 `interest == 0`，当前文件状态中的 `Err` 与 `Hup` 仍会报告。`Err`、`Hup` 不能通过兴趣参数关闭。

`flags` 只能包含上述三个标志位。`Excl` 不能与 `OneShot` 同用；带 `Excl` 时，`interest` 不能显式包含 `Err` 或 `Hup`。

## 文件状态共享

文件编号是非负整数。文件状态由所有实例共享，使用 `SetState(fd, m)` 原子地设置为 `0..15`，使用 `State(fd)` 查询；未写入过的文件状态为 `0`。

每个实例拥有独立的监视项表和 FIFO 就绪链。同一文件最多被每个实例各监视一次，键为 `(ep, fd)`。任一实例执行 `Wait`、`Del`、`OneShot` 禁用，都不影响其他实例的同名文件监视项。

`Add` 建立监视项后，如果当前 `state[fd] & eff != 0`，立即追加到本实例链尾；ET 和独占项也遵循这个初始就绪规则，不做独占候选选择。

`Mod` 整体替换兴趣和标志、清除 `disabled`，且必须保持原有的 `Excl` 位不变。如果替换后当前状态与新有效兴趣相交且监视项尚未在链中，则追加到链尾；已经在链中的项位置不变。

`Del` 删除本实例的监视项，并在 O(1) 时间内从该实例就绪链摘除，其他条目相对次序不变。

## 状态变化与触发

`SetState(fd, m)` 是一个原子步骤。它先记录旧状态 `old`，再设置为 `m`，然后只检查该文件上的监视项；每个文件至多有 `E` 个监视项，因此不扫描无关空闲监视项。检查顺序按实例编号升序。

未禁用且尚未在链中的监视项按下列规则成为触发候选：

- 水平触发：不含 `ET`，当 `m & eff != 0` 时触发。
- 边沿触发：含 `ET`，当 `(m &^ old) & eff != 0` 时触发，也就是只对本次新升起的位触发。
- 已禁用项不触发。
- 已在链中的项不会重复入链；它也不会作为独占候选，且不会阻止其他实例成为候选。

非独占触发项立即追加到自己的实例链尾。独占触发项先收集为候选，完整检查完该文件后，只选择实例编号最小的候选入链；因此一次 `SetState` 最多让一个独占监视项新入链。独占与非独占混合时，所有合格的非独占项仍都会入链。

状态清为 `0` 不会主动摘除已经在链中的条目；过期条目在后续 `Wait` 中重新求值并丢弃。

## Wait、丢弃与回填

`Wait(ep, max)` 是一个原子步骤，`max` 范围为 `1..1_000_000`。它只操作指定实例的就绪链和该实例的监视项：

1. 从链首弹出条目，直到返回事件数达到 `max` 或链空。
2. 每个弹出的条目用当前状态重新计算 `revents = state[fd] & eff`。
3. `revents == 0` 的条目被丢弃，不占用 `max`，也不回填。
4. `revents != 0` 时返回 `(fd, revents)`。
5. 带 `OneShot` 的返回项被标记为 `disabled`，不再回填；之后 `SetState` 不再让它入链，直到 `Mod` 重新武装。
6. 返回的非 ET 项按返回次序记入回填表；ET 项不回填。
7. 弹出阶段结束后，把回填表中的水平触发项按返回次序统一追加到链尾，即使当前状态已经为 `0` 也会先留在链中，等待下次 `Wait` 丢弃。

因此同一次 `Wait` 不会返回同一监视项两次；达到 `max` 时尚未弹出的原有链条目保持在回填项之前。

`Queue(ep)` 返回实例链中的文件编号；`Watches(ep)` 返回该实例全部监视项的快照，按文件编号排序。

## Close 语义

`Close(fd)` 是一个原子步骤：

- 删除所有实例中该文件的监视项。
- 从各实例自己的就绪链摘除对应条目。
- 将 `state[fd]` 置为 `0`。
- 返回被删除的监视项数量；没有监视项时返回 `0`。

## 并发与复杂度

所有方法共用同一把互斥锁。每个公开操作在锁内完成完整状态迁移，因此并发调用的结果等价于某个串行顺序；其他操作不会观察到独占候选选择中途、Wait 回填前或 Close 删除一半的链状态。

- `Add`、`Mod`、`Del`：O(1)。
- `SetState`：O(E)，只扫描该文件的监视项。
- `Close`：O(E)，只删除该文件上的监视项。
- `Wait`：只考察实际弹出的链条目，数量等于返回事件数加过期丢弃数，与总监视项数无关。
- `Queue`：O(链长)`；`Watches`：O(该实例监视项数)，它们是查询快照。

就绪链使用内嵌双向链表节点，保证队列摘除为 O(1)。文件监视项使用带索引的紧凑切片，删除为交换删除；`SetState` 先复制该文件的切片并按实例编号排序，保证独占候选选择的实例升序规则稳定可复现。

内部非导出计数器 `examined` 记录 `SetState` 实际考察的该文件监视项数，以及 `Wait` 实际弹出考察的链条目数。测试用 100,000 个不监视目标文件的空闲监视项验证：目标文件的 `SetState` 与单条目 `Wait` 只增加对应 1 次考察。

## 本地验证

如果当前 shell 找不到 `go`，可使用 `/usr/local/go/bin/go`；若默认 Go 缓存目录只读，可把缓存指到 `/tmp`：

```bash
export PATH=/usr/local/go/bin:$PATH
export GOCACHE=/tmp/go-cache-ontology

go test ./...
go test -race ./...
go test -run TestRandomAgainstNaiveSimulation -v ./...
go vet ./...
```

随机测试固定使用种子 `1..2000`。每组序列都同时作用于正式实现和按规则编写的朴素模拟（每实例链使用切片并线性查找），逐步比较：

- 操作输入、返回值和错误。
- 每个文件的共享状态。
- 每个实例的就绪链文件编号。
- 每个监视项的兴趣、标志、有效兴趣、`Queued` 与 `Disabled`。

使用 `-v` 运行随机测试时，日志会打印输入、输出和判定依据；发生不一致时，测试输出会包含导致分歧的完整逐步日志。
