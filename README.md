# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 有界账户（`account` 包）

`account` 包实现基于托管区间（escrow range）的有界账户：多个未决事务可以
不加锁地并发预留增减量，无论其中哪些事务提交、哪些中止、以何种顺序提交，
账户余额都不越出上下界。

### 可能区间的计算

每个账户维护余额 `b`、下界 `L`、上界 `H`、未决项上限 `M`，以及两个运行和：

- `negSum`：全部未决**负**增量之和（`<= 0`）
- `posSum`：全部未决**正**增量之和（`>= 0`）

账户的可能区间为：

```
[b + negSum, b + posSum]
```

区间下端对应「只有全部负增量提交」的极端情形，上端对应「只有全部正增量
提交」的极端情形。任何未决项子集、以任意顺序提交后的余额都落在此区间内。

### 正负两侧独立判定的理由

预留增量 `d` 时只检查它所推动的那一侧边界：

- `d < 0`：当且仅当 `b + negSum + d >= L` 才接受，否则报「下界不足」
- `d > 0`：当且仅当 `b + posSum + d <= H` 才接受，否则报「上界超出」

接受时不检查另一侧。理由：

1. **充分性**：负增量只会把区间下端往下推，正增量只会把上端往上推。
   只要每次下推前下端仍 `>= L`、每次上推前上端仍 `<= H`，区间就永远含于
   `[L, H]`，于是任意子集任意顺序提交后的余额（区间内的某个值）必然在
   `[L, H]` 内。
2. **必要性（不抵消）**：同一事务的多次预留各自独立计入两侧之和、互不
   抵消。因为事务可能部分跨账户提交语义下，正负两笔预留不一定同时生效；
   若允许互相抵消，则「只提交负的那笔」的情形会突破下界。因此两侧必须
   独立累计、独立判定。
3. **不检查另一侧**：负增量不会使上端变大、正增量不会使下端变小，检查
   另一侧既无必要也会错误地拒绝本可接受的预留。

提交把事务在所有账户上的未决项并入余额（必然成功），中止丢弃它们，二者
对该事务涉及的全部账户原子生效，之后事务编号终结。精确读在账户无未决项
时返回余额，否则报「余额不确定」并附当前可能区间。

### 本地验证

```bash
# 全部测试（含穷举对拍与并发守恒）
go test ./account/

# 带竞态检测与详细日志（日志打印输入、输出与判定依据）
go test -race -v ./account/

# 指定用例
go test -run TestIndependentSides -v ./account/
go test -run TestExhaustiveSubsetsAndOrders -v ./account/
```

测试覆盖：同一事务 `-50`/`+50`/`-1` 的下界不足用例、单侧边界检查、
未决项恰达上限、精确读的不确定性、1..10 个未决项对全部子集与顺序的
穷举对拍（子集大小 <= 6 时穷举全部顺序，更大子集取字典序前 720 种）、
并发下的余额守恒，以及相同操作序列重放的确定性。
