# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 公平份额作业调度器（`scheduler` 包）

按历史用量衰减的公平份额调度器：各账户的累计用量 U 按周期减半，每次
派发「U ÷ 份额」最小账户的队首作业，长期用量比例趋近份额比例。

### 衰减边界

- 创建时给定起点 `t0` 与衰减周期 `P`（整数毫秒，`P > 0`）。
- 边界为 `t0 + k×P`（k 为正整数）；时刻恰等于边界时该边界已生效。
- 每个边界上**全部**账户（含队列为空的）的 U 变为 `floor(U/2)`。
- 一次调用跨过 k 个边界时，先依次生效这 k 个边界（逐个减半，等价于
  `floor(U/2^k)`），再处理本次调用；边界只生效一次，不会重复应用。

### 派发与比较规则

- 候选为队列非空的账户，选 `U ÷ share` 最小者；比较用交叉相乘
  （`U1×share2` 与 `U2×share1` 的大整数比较），不使用浮点或整除，
  乘积再大也不会出错。
- 比值并列时取账户标识升序最小者。
- 取中账户的队首作业，其代价**即刻**计入该账户的 U，影响下一次派发。
- 派发结果携带判定依据：各候选的 U、份额以及被选原因（`Reason`）。

### 拒绝规则

份额不为正、账户重复、提交到未注册账户、代价不为正、作业标识重复、
周期不为正、全部队列为空时派发、时刻早于此前见过的任一时刻，均整体
拒绝并返回可区分的错误（`scheduler.Err*`）。多因同时成立时时钟回拨
优先，提交类错误按「账户未注册 → 代价 → 标识重复」只报第一个。被拒绝
的操作不改变任何 U、队列与已生效边界数。

### 并发与可复现

所有方法可并发调用（内部互斥串行化），结果等价于某个串行顺序；U 恒为
非负大整数；每个作业恰被派发一次；相同操作序列重放得到完全相同的派发
顺序与 U。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 只看调度器（日志含每次调用的输入、输出与判定依据）
go test -race -v ./scheduler

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```
