# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 路径摘要进度前沿

`ontology.Tracker` 在有向数据流图上追踪带时间戳的在途工作。

- 配置：位置数 `N` 为 1–64；边 `(u,v,s)` 的 `s` 为 0–10^6，边数最多 512；源位置集合必须非空且不重复。端点或时间越界、边数超限、存在零和有向环（含 `s=0` 自环）都会整体拒绝配置。
- 路径摘要：`d⁺(u,v)` 是至少含一条边的最小路径延迟和；不可达为无穷。`d(u,v)` 在 `u≠v` 时等于 `d⁺(u,v)`，而 `d(v,v)=0`，即位置自身持有的工作直接计入自己的前沿，不需要绕环。
- 账本：键为 `(位置, 时间戳)`，值为非负计数；计数为 0 的项立即删除。每次被接受的批使 `ver` 加一。
- 前沿：`F(v) = min{t+d(p,v) | (p,t) 的计数大于 0}`，不可达或没有可到达工作时为 `-1`。
- 批更新：批大小为 1–1000；时间戳为 0–10^12；非零增量绝对值不超过 10^6。同键增量先在批内求和，再依次校验参数非法、应用后计数为负、非源位置的生产违反因果。因果判据使用批生效之前的 `F(q) ≤ t`；源位置免除因果校验。
- 原子性：任何拒绝都不改变账本、前沿或 `ver`；接受时一次性提交全部净增量。返回的变化清单按位置升序列出前沿前后值，无穷对外为 `-1`。
- 查询：`Complete(v,t)` 仅在 `F(v)=-1` 或 `F(v)>t` 时为真，`t=F(v)` 为假。所有读写由内部锁保护，查询返回一致快照。
- 访问统计：非导出 `entryVisits` 只统计前沿重算中实际读取账本条目的次数；每位置最小活跃时间戳由惰性最小堆维护，单批更新的增量不超过该批不同键数的 2 倍，不随每位置活跃时间戳数量增长。

朴素测试模型在每批重新执行 Floyd-Warshall 并扫描全账本，随机 2000 组批序列与正式实现逐项对照。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```
