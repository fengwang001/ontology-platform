# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 脏净叉资源冲突协调器（`dining` 包）

`dining` 实现了 Chandy–Misra 风格的分布式资源冲突协调器：冲突图上的相邻进程
靠收发叉与请求令牌轮流独占资源，保证相邻进程从不同时进餐、优先关系始终无环、
无进程饿死。

### 叉与令牌的收发规则

- 每条冲突边恰有一把叉与一枚请求令牌；初始时叉在标识较小的一端且为脏，令牌在另一端。
- 进程状态按 思考 → 饥饿 → 进餐 循环转移（`Hungry` / `Eat` / `Finish`）。
- 饥饿进程对每把**缺少且持有令牌**的叉，把令牌发给对方作为请求。
- 进程收到请求时：
  - 手中该叉为**脏**且自己**未在进餐**：把叉洗净后发给对方；若自己仍饥饿，
    立即用这枚令牌再请求（令牌随即将由对方在让叉时带回）。
  - 叉为**净**或自己**正在进餐**：暂存（deferred）该请求。
- 收到的叉为净；只有持有全部邻接叉的饥饿进程才能进餐。
- 进餐结束后，所有持有的叉变脏，并立即洗净发出以满足全部暂存的请求。
- 消息经注入的 `Network` 接口投递：同一有向信道先进先出，不同信道任意交错；
  用 `Deliver(id)` 投递在途消息。

### 脏净的作用

脏净标记编码了"谁更该先吃"的优先级：叉在进餐结束后变脏（持有者已用过资源），
让出前被洗净（接收者尚未使用）。饥饿进程只缺叉时才请求，持有脏叉的邻居必须让出，
持有净叉的邻居可以先用完再让——这让刚刚进餐过的进程倾向于把资源让给邻居，
避免同一进程连续霸占资源。

### 无环的理由

由叉的位置与脏净导出优先关系：叉**脏**时边由持有者指向对方，叉**净**时边由对方
指向持有者；在途叉视为已到达接收方且为净。初始时所有边按标识升序定向，无环。
此后唯一改变定向的操作是 `Eat`：进餐者全部邻接边变为"由自己指出"（成为源点），
源点没有任何入边，不可能出现在环上；让叉（洗净+发送）与投递都不改变定向。
因此优先关系始终无环（`Snapshot.Acyclic` / `CheckInvariants` 逐步验证）。

### 无饿死与有界超车的理由

- 思考进程持有的叉必为脏（叉只在进餐后被持有，且即变脏），所以请求送达思考的
  持有者时会被立即满足；送达饥饿/进餐中的持有者时，至多等其再进餐一次即被满足。
- 请求被叉的持有者接受后，该邻居在请求者进餐前**至多再进餐一次**：邻居让出叉后
  自己缺叉，必须等请求者进餐结束让叉后才能再次集齐全部叉。
- 等待关系蕴含于优先关系之中（p 等 q 的叉 ⇒ 边 p→q），优先关系无环 ⇒ 等待关系
  无环 ⇒ 无死锁；结合每条请求至多被超车一次，任何饥饿进程最终都会进餐。

### 非法操作的拒绝

端点不存在、自环、重复边（含反向）、思考中或缺叉时进餐、饥饿退回思考、
结束不在进餐中的进程、投递不存在的消息，都会以可区分的哨兵错误整体拒绝
（`ErrUnknownProcess` / `ErrSelfLoop` / `ErrDuplicateEdge` / `ErrNotHungry` /
`ErrMissingForks` / `ErrHungryToThinking` / `ErrNotEating` / `ErrMessageNotFound`），
且被拒绝的操作不改变任何进程、叉或令牌的状态。所有方法可并发调用（内部单互斥锁），
相同的操作与投递序列重放结果相同。

```bash
# 千次随机交错无相邻同时进餐与无饿死/重放确定性/并发）
go test -v ./dining

# 竞态检测

```
