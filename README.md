# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

```bash

go test ./...
```

# 分代复制式垃圾回收器（`gencopy`）

`gencopy` 包在一段模拟内存（`[]byte`）上实现分代复制式 GC，附带可运行演示
`cmd/gcdemo` 与完整测试。

## 分代布局

整堆按字节偏移连续划分四个区域：

```
+--------+------------+------------+---------+
|  Eden  | Survivor A | Survivor B |   Old   |
| 分配区 |  幸存区 A  |  幸存区 B  | 老年代  |
+--------+------------+------------+---------+
```

- 两个幸存区等大，任一时刻一个是 `From`（存有上一轮存活对象），另一个是 `To`
  （空闲），每次次要回收后角色互换。
- 对象物理布局：`对象头 24B + numRefs 个 8B 引用槽 + 载荷`。对象头含
  年龄、引用字段数、载荷长度、转发代标记与转发地址。
- 对外只暴露不透明句柄 `Handle`；对象在 Eden/幸存区/老年代之间移动时句柄
  不变，由句柄表 `objs map[Handle]*loc` 维护当前位置，槽内存绝对偏移，
  `byAddr` 负责偏移→句柄反查。
- `nil` 引用编码为 `0xFFFF...`。

## 分配与触发

所有新对象分配在 Eden。Eden 剩余空间不足时**先**触发一次次要回收，再重试
分配；仍放不下则拒绝。

## 复制与转发规则（Cheney 半空间复制）

次要回收的 GC Roots = 调用方登记的显式根集 + 记忆集中的老年对象。

1. 遍历根与记忆集条目，可达的**年轻**对象进入疏散流程；老年对象不移动。
2. 疏散目标选择：
   - 年龄 +1 后达到 `PromoteAge` → 复制到老年代（晋升）；
   - 否则尝试复制到 `To` 幸存区；`To` 剩余空间不足 → 不论年龄提前晋升；
   - 老年代也放不下 → 返回 `ErrOldFull`，本轮回收整体撤回。
3. 对象复制后，在**原对象头**写入转发地址（代标记 + 目标绝对偏移），
   后续再次遇到该对象直接转发，保证同一对象只复制一次。
4. 新位置的对象进入 Cheney 扫描队列；扫描其引用槽，指向年轻对象的槽
   递归疏散并就地改写成转发后的新地址。
5. 提交阶段（此后不会再失败）：
   - 重建句柄表与偏移反查表；不可达年轻对象立墓碑（`ErrHandleReclaimed`）；
   - Eden/From 游标清零、`To` 游标置为实际存活字节、交换 From/To；
   - 精确重建记忆集；回收数 +1，晋升数 += 本轮晋升数。

每次回收后 Eden 必为空、`To` 必为空，各代已用字节严格等于其中存活对象
字节之和（`assertUsedEqualsLive` 在每个测试中校验）。

## 记忆集维护推导

次要回收只扫描年轻代，但老年对象可以持有年轻对象引用。若不记录这些引用，
仅被老年对象引用的年轻对象会被误回收。推导：

- **写屏障（入口）**：`SetRef` 写入 `老年代对象 -> 年轻对象` 引用时，必须把
  该老年对象加入记忆集，使它成为次要回收的根。加入/移除都在同一把堆锁内
  完成，屏障与回收不会交错。
- **晋升（入口）**：晋升本身就是一次“年轻对象变成老年对象”的代际转移。
  晋升对象的引用槽可能仍指向年轻对象，因此提交时对**全部**老年对象
  （含本轮晋升者）逐槽扫描，持有年轻引用者一律纳入记忆集——这也自然覆盖了
  写屏障在对象尚年轻时未拦截的写入。
- **出口（精确移除）**：两种情形会使老年对象不再引用年轻对象：
  1. `SetRef` 覆写/清空槽位后，立即重扫该对象全部槽位，不含年轻引用就从
     记忆集移出；
  2. 次要回收中年轻目标被晋升（引用从“跨代”变成“老→老”），提交阶段的
     全量精确重建会把它移出。

记忆集是**精确集合**（只含确实持有年轻引用的老年对象），按句柄升序维护，
配合根集升序遍历，保证同一操作序列得到完全相同的回收与晋升次数。

## 晋升失败与撤回

回收期间所有疏散写入直接发生在 `mem` 上，但映射表、游标、计数只在提交阶段
更新。回收开始前保存整堆字节快照；疏散中一旦老年代空间不足（`ErrOldFull`），
立即用快照还原 `mem` 并返回——由于其他状态尚未修改，堆与回收前**逐字节相同**。

## 并发模型

堆内一把 `sync.Mutex` 串行化分配、读写、根登记与回收。回收在锁内完成
全部复制与提交，因此其他调用要么看到回收前完整状态、要么看到回收后完整
状态，看不到中间态。新分配但尚未写入任何存活引用的对象（未发布对象）若
在此期间被回收，调用方随后使用该句柄会得到 `ErrHandleReclaimed`，这与
“根外不可达对象”的语义一致。

## 可区分的拒绝原因

| 错误 | 触发条件 |
| --- | --- |
| `ErrInvalidHandle` | 句柄从未由本堆颁发（含 0） |
| `ErrHandleReclaimed` | 句柄对应的对象已被回收 |
| `ErrSlotOutOfRange` | 引用字段下标越界（含负数） |
| `ErrPayloadTooLarge` | 载荷长度本身超过 Eden 大小 |
| `ErrObjectTooLarge` | 载荷不超限，但含对象头的整对象超过 Eden |
| `ErrOldFull` | 老年代放不下待晋升对象，回收整体撤回 |
| `ErrBadConfig` | 构造参数非法 |
