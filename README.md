# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 回溯正则执行器

包 `ontology` 提供带确定性优先序、步数预算和封禁升级的回溯正则执行器。

### 构造与注册

```go
executor, err := ontology.NewExecutor(L, E, G, K, D, P)
err = executor.Register("id", []byte(`a*b`), true)
result, err := executor.Match("id", []byte("aab"), now)
status, err := executor.Status("id", now)
```

构造参数范围：

- `L`：单次 `Match` 本地步数上限，范围 `1..1_000_000`。
- `E`：纪元长度，范围 `1..1_000_000_000`，纪元为 `floor(now / E)`。
- `G`：每纪元全局步数，范围 `1..1_000_000_000`。
- `K`：连续本地超限触发封禁的次数，范围 `1..100`。
- `D`：基础封禁时长，范围 `1..1_000_000_000`。
- `P`：指令数上限，范围 `1..100_000`。

注册参数：`id` 为 1 到 64 字节；模式为 1 到 200 字节。`Register` 拒绝顺序固定为参数非法、`id` 已存在、语法错误、可空重复、程序过大。

### 模式语法

模式按字节解释，不做 Unicode 解码：

- 字面字节；`\x` 表示字节 `x` 本身；`.` 匹配除换行 `\n` 外的任意字节。
- `[abc]`、`[a-c]`、`[^a]`；字符集内没有转义，范围要求低端字节不大于高端字节。
- `|` 为右结合嵌套选择；`( )` 只分组，不捕获。
- `^` 与 `$` 分别只断言输入位置 0 与输入末尾。
- 支持 `*`、`+`、`?`、`{m,n}`、`{m,}`，量词后的 `?` 表示懒惰。
- `0 <= m <= n <= 100` 且 `n >= 1`；`{m,}` 要求 `m <= 100`。
- 量词只作用于前一个字面、`.`、字符集或分组；断言后不得跟量词；连续量词（懒惰后缀除外）是语法错误。
- 任一字段为可匹配空串的分组或原子应用量词，均报可空重复。空选择支、纯断言、`*`、`?`、`{0,n}` 都可能使分组可空。

### 指令与执行

编译器从下标 0 发射指令：

- 字面、`.`、字符集各生成一条消耗字节的指令；成功时 `pc++`、`pos++`。
- `^`、`$` 各生成一条断言；末尾生成 `Match`。
- `x|y` 生成 `Split(x,y)`、`x`、`Jmp(exit)`、`y`。
- `e*` 生成 `Split/body/Jmp` 循环；`e+` 为一份 `e` 后接 `e*`；`e?` 为 `Split/body`。
- `e{m,n}` 先生成 `m` 份 `e`，再生成 `n-m` 个嵌套可选，所有跳过分支都直接跳到整个构造的出口。
- `e{m,}` 先生成 `m` 份 `e`，再接 `e*`。
- 贪婪 `Split(x,y)` 先调度 `x`，把 `y` 压栈；懒惰先调度 `y`，把 `x` 压栈。

`Match` 对起点 `s=0..n` 依次搜索，从 `(pc=0,pos=s)` 开始用显式栈回溯。`steps` 初值为 0，跨起点累计。每次实际调度指令前检查 `steps == λ`：相等立即超限，否则 `steps++` 后执行。记忆化开启时，跨起点共享已调度的 `(pc,pos)` 集合；命中集合的状态失败且不计步。因此记忆化的实际调度数等于返回的 `steps`，且不超过“指令数 × (n+1)”。

### 三层预算与封禁

每个纪元维护全局余量 `rem`，初值为 `G`。接受的 `Match` 若进入新纪元，先把纪元切到新纪元并把 `rem` 重置为 `G`：

- `rem' >= L` 时，`λ=L`，超限归类为本地超限。
- `0 < rem' < L` 时，`λ=rem'`，超限归类为全局超限。
- `rem'=0` 时直接拒绝，不执行、不计步、不推进状态。
- 执行后从 `rem` 扣除本次实际 `steps`；超限时实际步数即 `λ`。

每个模式维护连续本地超限计数 `c`、累计封禁次数 `b` 和封禁截止时刻 `u`：

- 匹配或无匹配使 `c=0`。
- 全局超限不改变 `c`，也不清零。
- 本地超限使 `c++`；当 `c >= K` 时 `b++`、`c=0`，并设置 `u=now+D*min(2^(b-1),8)`。
- 前四次封禁倍数分别为 `1,2,4,8`，之后封顶为 `8`。
- `now < u` 为封禁中；`now == u` 已解封。

`Match` 的拒绝顺序固定为：参数非法、模式未注册、时钟回退、模式封禁中、全局余量为 0。`Status` 按参数非法、模式未注册检查。任何被拒绝的调用都不改变最大 `now`、纪元、余量、计数或封禁状态；只有被接受的 `Match` 才推进时间与预算。

所有公开方法都由同一把互斥锁串行化，因此并发调用等价于某个串行重放顺序。

```bash
GOCACHE=/tmp/ontology-gocache go test ./...
GOCACHE=/tmp/ontology-gocache go test -race ./...
GOCACHE=/tmp/ontology-gocache go vet ./...

```
