# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 流依赖树份额分配器（`flowtree`）

`flowtree` 包维护流之间的父子依赖与权重（1–256），并按树形结构把字节
额度分给就绪流。虚拟根编号恒为 `0`（不存活、不拿份额）。任意时刻每个流
恰有一个父，树从不成环；`Open`/`Reroot`/`Close`/`Allocate` 均可并发调用
（内部互斥锁串行化）。

### 挂接（Open）

- 入参：编号（未用过的正整数）、父（`0` 或存活流）、权重、独占标志。
- 非独占：新流直接成为父的子。
- 独占：新流成为父的唯一子，父原有的全部子改挂到新流之下，权重不变。
- 拒绝顺序（只报第一个，且不改树）：编号非正或已用过 → 父不存在 → 权重越界。
- 编号一旦使用即永久占用，关闭后也不能复用。

### 重设依赖（Reroot）

- 入参：流、新父、新权重、独占标志。
- 新父是该流的后代时，先把新父连同其子树整体改挂到该流的原父之下，
  新父自身权重保持不变；随后再按 Open 的挂接规则（含独占语义）挂接。
- 拒绝顺序：流不存在 → 新父不存在 → 新父是自身 → 权重越界。

### 关闭（Close）

- 流的每个子改挂到它的父；子的新权重为
  `max(1, floor(被关流权重 × 该子权重 ÷ 各子权重之和))`，求和只针对直接子。
- 被关流从树中删除，编号不再可用。关闭不存在的流会被拒绝。

### 分配（Allocate）

- 入参：额度 `T`（非负）与就绪流集合。拒绝顺序：就绪流不存在 → 额度为负。
- 从虚拟根向下递归，只考虑子树中含就绪流的子（剪枝）：
  - 子树根自身就绪：额度全归它，其后代得 0；
  - 否则在含就绪流的兄弟之间切分。
- 同层份额：基数 `base = floor(T×w ÷ Σw)`，`Σw` 只含含就绪流的兄弟；
  剩余 `r = T − Σbase` 字节，按 `(T×w mod Σw)` 从大到小取前 `r` 个各加 1，
  余数并列时取编号小者。
- 份额之和恒等于额度；无就绪流时所有份额为 0，返回空映射。
