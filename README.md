# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 服务有序终止器

终止器位于 `shutdown` 包，所有调用都显式传入整数毫秒时刻。时间模型不读取系统时钟，因此同一组带时刻的调用可以完全重放并得到相同的终止与停止时刻表。

### API

- `New(logger)`：创建编排器；传入 `nil` 时使用丢弃日志。
- `Register(at, id, gracePeriodMS, dependencies...)`：注册服务和它依赖的已注册服务。
- `BeginShutdown(at)`：以该时刻为 T0，开始关停；不能重复调用。
- `ReportExit(id, at)`：服务自行退出并上报；在宽限期边界及之后不会被接受为自行退出。
- `Status(id, at)`：结算到指定时刻后返回单个服务状态。
- `Snapshot(at)`：结算到指定时刻后返回所有服务状态。

若 A 依赖 B，则 A 是 B 的依赖者，A 必须先于 B 停止。注册时依赖关系不得成环。

### 时刻推导

- 没有存活依赖者的服务在 T0 收到终止信号，终止时刻为 T0。
- 其他服务在全部依赖者都已停止的那一刻收到终止信号。
- 因此，任一服务的终止时刻等于其全部依赖者停止时刻的最大值；没有依赖者时取 T0。
- 服务在 `终止时刻 + g` 之前上报时，停止时刻为上报时刻，停止方式为 `Graceful`。
- 到 `终止时刻 + g` 仍未上报时，服务在该时刻被强杀，停止方式为 `Killed`。
- 恰好在 `终止时刻 + g` 的上报先结算强杀，因此返回“已停止”，不会改写成自行退出。

### 强杀级联结算

每次注册、开始关停、上报和查询都会先按本次调用时刻结算：

1. 从强杀事件堆中取最早到期事件。
2. 若服务已自行退出，则忽略其过期强杀事件。
3. 否则在强杀时刻把服务置为 `Killed`。
4. 该停止可能立即让其依赖的服务满足“全部依赖者已停止”，于是在同一时刻发出终止信号并安排新的强杀事件。
5. 继续处理所有不晚于本次调用时刻的事件；同一时刻按服务标识稳定排序。

因此，一次较晚的查询可以确定性地跨过多个到期点，并按时间先后连续完成强杀与下游终止级联。

### 拒绝规则

所有拒绝操作都不会改变服务图、信号状态、停止状态或待结算强杀。时刻回拨对所有调用最先检查。注册还会拒绝非正宽限期、重复服务、依赖未注册、依赖成环（含自依赖）以及开始关停后的注册。开始关停不能重复。退出上报按“时刻回拨、服务不存在、已停止、尚未收到终止信号”的顺序返回第一个原因。

所有公开操作由同一个互斥锁串行化；并发调用的结果等价于某个合法串行顺序。

### 日志

传入 `slog.Logger` 后，编排器会记录每次调用的输入与输出，并记录关键判定依据：

- 终止信号发出时刻与强杀截止时刻。
- 服务自行退出或强杀的停止时刻。
- 到期强杀、过期强杀事件被忽略的原因。
- 边界时刻上报因已强杀而被拒绝。

### 终止器测试

`shutdown/orchestrator_test.go` 覆盖菱形依赖取最晚停止时刻、宽限期边界上报、连续两级强杀、一次调用跨过多个到期点、上游自行退出后下游强杀、拒绝原因、并发查询与重放确定性。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```
