# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 字节码栈深校验器（`stackcheck` 包）

`stackcheck` 逐函数注册指令序列，按数据流推导每条可达指令的入口栈深，
保证通过校验的函数在任意控制流路径上栈深一致、不下溢且不超过构造时给定的上限 `L`（`L >= 1`）。
被拒绝的注册不改变已注册函数表；注册与查询均可并发调用，同名函数并发注册恰有一个成功，
已注册函数的最大栈深永不改变。

### 指令栈效应

| 指令     | 入口要求 | 栈效应 | 后继 |
|----------|----------|--------|------|
| `PUSH`   | 无       | +1     | 下一条（落空） |
| `POP`    | >= 1     | -1     | 下一条（落空） |
| `ADD`    | >= 2     | -1（弹二压一） | 下一条（落空） |
| `DUP`    | >= 1     | +1     | 下一条（落空） |
| `JMP t`  | 无       | 不变   | 仅 `t`，无落空 |
| `JZ t`   | >= 1     | 先弹一个（-1） | 先 `t` 后下一条，两路均以弹后栈深进入 |
| `RET`    | 恰为 1   | 函数帧退出（记 0） | 无 |

### 推导顺序

1. 静态检查（只报第一个错误）：名字已存在 → 指令序列为空 → 未知操作码
   （按下标从小到大找第一处）→ 跳转目标越界（同样按最小下标；只要存在未知操作码
   就先于任何跳转越界报告；合法目标为 `0..len-1`，等于 `len` 非法；
   跳转目标范围对全部指令含不可达指令都检查）。
2. 数据流推导：先进先出工作表，初始仅含下标 0（入口栈深 0）。取出一条指令按其
   入口栈深执行，依次给每个后继赋入口栈深并入队（`JZ` 先目标后落空）；后继已有
   入口栈深且不相等即为汇合不一致，相等则忽略。不可达指令不受任何栈约束检查。
3. 注册成功记录最大栈深：可达指令执行后栈深的最大值，且不小于 0。

### 数据流错误优先级

按推导过程中先遇到者报告；同一条指令内先下溢、后超限、再 RET 栈深检查：

- 下溢：入口栈深不满足指令入口要求。
- 超限：任一指令执行后栈深大于 `L`（恰等于 `L` 允许）。
- 汇合不一致：后继入口栈深与已有值不等。
- RET 栈深不为 1。
- 落空越界：落空到下标等于指令总数处。

查询不存在的函数报 `KindFunctionNotFound`。所有错误均为 `*stackcheck.Error`，
通过 `Kind` 字段（`ErrorKind` 枚举）区分原因。
