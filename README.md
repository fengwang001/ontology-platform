# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## snapshotlog：快照 + 增量日志衔接组件

`snapshotlog` 包在**不停源表**的前提下，对一个键范围“先做快照、再补上期间的增量日志”，
使下游视图始终与源表一致，输出**不重复、不回退**。

### 数据模型

- `Source` 是并发安全的源表。每次 `Put`/`Delete` 都在同一把锁内原子地
  追加一条日志并更新表状态，日志序号 `Seq` 从 **1** 开始、全局连续严格递增。
- 键范围 `KeyRange{Start, End}` 是**闭区间**，`Start`、`End` 两个边界键都属于该范围。
- 多个范围之间不得相交；边界键相同（如 `[1,10]` 与 `[10,20]`）即判相交，
  相邻但不接触（如 `[1,10]` 与 `[11,20]`）允许并存。

### 三步建立基线（低水位 → 快照 → 高水位 + 修正）

对范围 `r` 必须严格按顺序调用：

1. **`BeginSnapshot(r)` — 记低水位**
   `lowSeq` = 此刻源表已提交的最大日志序号（空表为 0）。
   `lowSeq` 及之后的写入都不保证出现在即将读到的快照里。
2. **`ReadSnapshot(r)` — 读快照**
   返回该时刻范围内存活键值的**冻结副本** `rows` 与快照序号 `snapSeq`
   （快照反映了所有 `Seq <= snapSeq` 的写入）。快照在第一次读取时冻结，
   之后重复调用返回同一份内容，保证下一步修正的就是这一份快照。
3. **`FinishSnapshot(r)` — 记高水位并修正快照**
   `highSeq` = 此刻源表已提交的最大日志序号；读取序号区间
   **`(lowSeq, highSeq]`** 内的日志，只保留键落在 `r` 内的条目，
   按 `Seq` 顺序在冻结快照上重放（`PUT` 覆盖、`DELETE` 删除），
   得到 `highSeq` 时刻范围内的正确状态，再**原子并入视图**。
   完成后该范围进入轮询阶段，处理位置 `AppliedSeq` 初始化为 `highSeq`。

   说明：快照已包含 `<= snapSeq` 的效果，因此重放区间里 `<= snapSeq` 的
   部分是幂等的，`(snapSeq, highSeq]` 部分补上快照期间及之后的写入——
   快照与写入并发进行也不会漏、不会重。

### 轮询过滤规则

`Poll()` 对每个**已完成**（走完三步）的范围：

- 只取 `Seq > 该范围 AppliedSeq` **且键落在该范围内**的日志；
- 进行中（尚未 `FinishSnapshot`）的范围不参与；不属于任何已完成范围的键一律跳过；
- 跨范围收集到的事件按**全局 `Seq` 排序**后依次应用，视图只增不改历史顺序；
- 应用成功后把各范围处理位置推进到本范围最后一条事件的序号
  （范围外键不会推进该范围的位置，这是预期行为）。

由此保证：水位以下的事件绝不再次输出（**不重复**）；事件严格按序号变基到视图
（**不回退**）；停写后反复 `Poll` 直到返回空，视图与源表范围内状态逐键一致。

### 拒绝原因（用 `errors.Is` 判定，互不混淆）

| 错误 | 触发条件 |
| --- | --- |
| `ErrInvalidRange` | 键范围非法，`Start > End` |
| `ErrRangeOverlap` | 与进行中或已完成的已有范围在闭区间上相交 |
| `ErrPhaseOrder` | 未 `BeginSnapshot` 就 `Read/Finish`、未 `ReadSnapshot` 就 `Finish`、已完成后再读/再完成 |
| `ErrViewLimitExceeded` | 并入后视图存活行数超过 `WithMaxViewRows` 设定的上限 |

**任何被拒绝的操作都不改变视图、处理位置或水位**：
完成阶段超限不会部分写入，范围仍停在快照阶段、可在数据回落后续重试；
轮询阶段按**整批应用后的最终行数**判定，超限则整批回滚、位置不前进，
下一批重放时此前被回滚的序号仍会被应用（不漏不重）。

### 并发与确定性

- 写入可与 `ReadSnapshot`、`FinishSnapshot`、`Poll`、`View` 并发；
  组件用互斥锁串行化状态变更，源表的日志追加与快照读取共用一把锁，
  读到的快照与序号有确定的先后关系，视图不会读到撕裂状态。
- 同一输入序列反复计算，得到完全相同的视图、事件序号序列与处理位置
  （见 `TestDeterminism`）。
- 通过 `WithLogger(*slog.Logger)` 注入日志器，日志中打印每次操作的
  **输入**（范围）、**输出**（水位/事件/行数）与**判定依据**（接受或拒绝理由）。
