# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```

## 周期资源调度预算管理器（`budget` 包）

`budget` 包实现分层调度（Hierarchical Scheduling）中周期资源模型的组件预算管理：
为每个组件内的 EDF 任务集求最小周期预算，并在全局带宽约束下增量接纳任务。

### 供给界 sbf 与需求界 dbf

组件由名称与周期 `Π∈[1,1000]` 确定，预算 `Θ∈[1,Π]`。最坏情形供给界：

```
a = Π − Θ
q = ⌊max(0, t − a) / Π⌋
sbf(t) = q·Θ + max(0, t − 2a − q·Π)     （Θ = Π 时 sbf(t) = t）
```

组件内任务含编号、`C`、`T`、`D`（`1≤C≤D≤T≤1000`），EDF 需求界：

```
dbf(t) = Σ max(0, ⌊(t − D)/T⌋ + 1)·C     （t < D 的任务贡献 0）
```

任务集在预算 `Θ` 下可调度，当且仅当：

1. 利用率条件 `Σ C/T ≤ Θ/Π`（有理数精确比较，不用浮点）；
2. 对所有 `0 < t ≤ Dmax + H` 有 `dbf(t) ≤ sbf(t)`，其中 `Dmax` 为最大 `D`，
   `H = lcm(Π, 全部 T)`。

### 检查范围的来由

- **只需检查跳变点**：`dbf` 是分片常值、右连续的阶梯函数，跳变点只出现在各任务的
  `D + mT` 处；`sbf` 单调不减。若某区间内有违反，则区间右端（跳变点）必违反，
  故只考察跳变点，考察点数不超过 `Σ ⌈(Dmax+H)/T_i⌉`，不逐个整数扫描。
- **上界 Dmax+H**：超过 `Dmax+H` 后，`dbf` 与 `sbf` 都进入以 `H` 为周期的线性增长段
  （斜率分别为 `ΣC/T` 与 `Θ/Π`），利用率条件保证之后不再出现新的违反。
- **规模保护**：`Dmax + H > 10^6` 直接报“规模过大”；`H` 的计算在超过 `10^6`
  时即停止，避免 lcm 溢出。

### 预算规则

- `MinBudget(Π, 任务集)`：`sbf` 对 `Θ` 单调，二分求最小可行整数 `Θ`，
  可行性检查次数不超过 `⌈log2 Π⌉+1`；`Θ=Π` 仍不可行时报不可行并携带
  `Θ=Π` 时最小违反点 `t`（仅因 `ΣC/T>1` 不可行时记 0）。
- **预算只增不减**：`AddTask` 后 `θ' = max(θ, MinBudget(原任务集+新任务))`；
  `RemoveTask` 只删任务不改 `θ`；`Compact(名称)` 才把 `θ` 重算为当前任务集的
  `MinBudget`（无任务则为 0）并释放带宽。全局带宽始终按已分配的 `θ` 计。
- **全局带宽**：要求 `Σ θ/Π ≤ 1`（恰等于 1 通过），用 `math/big` 有理数精确比较。
  `Total()` 返回既约分数（分母为正，零为 `0/1`）。
- **拒绝原因**按序只报第一个：参数非法 → 不存在 → 重复 → 容量已满（8 组件 /
  每组件 8 任务）→ 规模过大 → 不可行 → 过载。被拒绝的操作不改变任何状态。
- **并发与确定性**：所有方法可并发调用（内部互斥锁串行化，等价于某个串行顺序）；
  相同操作序列重放得到完全相同的 `θ` 与拒绝点。
