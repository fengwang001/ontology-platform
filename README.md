# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 流水线区域故障恢复规划器（`planner` 包）

### 区域划分

- 作业图由任务与有向边组成，边分**流水线边**与**阻塞边**两类。
- 仅由流水线边（不计方向）连通的任务构成一个**区域**，区域编号取区域内最小任务编号。
- 建图时整体校验，任一不满足即拒绝并返回可区分的原因（多因并存按此序只报第一个）：
  边引用不存在的任务 → 重复边（同一有序任务对）→ 阻塞边两端在同一区域 → 区域之间成环。

### 结果可用性

- 任务初始全部为运行中，完成上报使其变为已完成（仅对运行中任务有效）。
- 阻塞边的结果**当且仅当生产者已完成且未被上报丢失**时可用。
- 结果丢失上报要求：边存在、为阻塞边、生产者已完成；已丢失的再报视为成功且无变化。
  各类不符分别返回：任务不存在、任务未在运行、边不存在、非阻塞边、结果尚未产出。
  被拒绝的操作不改变任何状态。

### 重启集合三条规则

失败上报（仅对运行中任务有效）计算必须重启的**最小区域集合**，三条规则迭代至不再变化：

1. 集合含失败任务所在区域；
2. 集合内区域所产阻塞结果的全部消费区域也在集合内；
3. 集合内区域消费的某阻塞结果不可用且其生产者已完成时，生产者所在区域也在集合内
   （生产者仍在运行则不加入）。

上报生效后，集合内全部任务变为运行中，其所产阻塞结果的丢失标记清除，
返回升序的区域编号与任务编号；集合外区域不受任何影响。

### 并发与确定性

- 上报（完成/失败/丢失）与查询（`Snapshot`、`RegionOf`）均可并发调用，
  内部以互斥锁串行化，效果等价于某个串行顺序。
- 重启集合只依赖此前已生效的上报；相同上报序列得到完全相同的结果。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

gofmt -l .
go vet ./...
