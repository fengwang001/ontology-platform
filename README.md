# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 多线程信号投递子系统

实现位于 `signals` 包，入口为 `signals.New(L, leaderMask)`，所有公开方法由同一把互斥锁串行化，因此并发调用等价于某个合法的全序串行执行；`Deliver` 中“循环取信号、忽略丢弃、压栈并返回”整体是一个原子步骤。

### 待处理结构

- 进程有一份共享待处理集合，每个线程另有一份私有待处理集合。
- 标准信号 1–31 在每份集合中只用一个 `uint64` 位表示；同一份集合中已有实例时再次到达只合并，并增加 `Lost()`。
- 实时信号 32–64 在每份集合中按信号编号维护 FIFO 队列，队列项携带发送值；所有共享与私有实时队列总长度由 `RTQ()` 查询且不超过构造参数 `L`。
- 信号 `s` 使用第 `s-1` 位表示；屏蔽字在构造、`SetMask`、进入处理函数时都会清除信号 9 的位。
- `Pending(tid)` 与 `SharedPending()` 返回按信号编号升序的 `(信号, 条目数)`；标准信号条目数恒为 1，实时信号条目数等于对应 FIFO 长度。

### 入队、丢弃与合并

- `Send` 只写共享集合；先校验信号和进程状态，再在有效处置为忽略且组长未屏蔽时立即返回丢弃，不改变任何状态。
- `SendTo` 只写指定线程私有集合；校验顺序为参数非法、线程不存在、进程已终止，丢弃判定只看该线程自己的屏蔽字。
- 标准信号按份合并，所以同一信号可以同时在共享集合和一个私有集合中各有一个实例。
- 实时信号在全局 `RTQ == L` 时返回 `ErrAgain`；被拒绝的操作不会改变待处理、屏蔽字、栈、游标、RTQ 或合并计数。

### 目标线程与游标

进程级信号入共享集合后选择投递提示目标：

- 信号 9 或组长未屏蔽该信号时，目标恒为线程 1，且不更新游标。
- 否则从当前游标开始按线程编号循环扫描，选择第一个未屏蔽线程，并把游标更新为该线程。
- 全部线程均屏蔽时目标为 0，但信号仍保留在共享集合；已丢弃和已合并结果都不更新游标。

### 投递优先级

`Deliver(tid)` 首先检查共享集合或任一私有集合中是否存在信号 9；若存在，立即终止进程并返回 `(terminated, 9)`，与调用线程是否屏蔽无关。

否则在一个原子循环内取信号：

- 先完整查看调用线程的私有待处理集合，只有私有集合没有可取信号时才查看共享集合。
- 每份集合内先选同步信号 `{4,7,8,11}` 中编号最小且未屏蔽者。
- 没有可取同步信号时，在标准与实时待处理编号中选编号最小者；实时信号取该编号 FIFO 队首。
- 取出后若有效处置为忽略，则本集合条目消失、本次 `Discarded` 加一并继续；默认可终止信号会终止进程；处理函数则返回处理函数编号、信号、值以及来源集合。

选择过程只对待处理位图、屏蔽字位图、同步掩码和实时编号掩码做位运算，不扫描 64 个信号编号。

### 处理函数屏蔽字与冲刷

- 进入处理函数前压入旧屏蔽字；新屏蔽字为 `旧屏蔽字 | 附加屏蔽字 | 当前信号位`，`NoDefer=true` 时不叠加当前信号位。
- `Sigreturn(tid)` 按 LIFO 弹出并恢复屏蔽字；处理函数内调用 `SetMask` 只改变当前值，后续 `Sigreturn` 仍会恢复为压栈值。
- `SetAction(sig, Ignore)` 或把默认忽略集合 `{17,23,28}` 中的信号设回默认动作后，会冲刷共享集合及所有线程私有集合中的该信号标准位和实时 FIFO。
- 非导出计数器 `examined` 对一次冲刷最多增加“线程数 + 1 + 被冲刷条目数”；实现只访问该信号的位和该信号的实时队列，不考察其他信号上排队的条目。

### 本地验证

当前环境若 `go` 不在 `PATH`，可直接使用 `/usr/local/go/bin/go`，并把缓存指向可写目录：

```bash
# 普通全量测试
GOCACHE=/tmp/go-cache-ontology /usr/local/go/bin/go test ./...

# 竞态检测；-v 会输出 2000 组随机序列的输入、双模型输出和判定依据
GOCACHE=/tmp/go-cache-ontology /usr/local/go/bin/go test -race -v ./signals

# 静态检查
GOCACHE=/tmp/go-cache-ontology /usr/local/go/bin/go vet ./...
```

测试包含题目示例、目标游标、按份合并、实时 FIFO/配额边界（含刚满、差 1、`L=0`）、忽略保留后丢弃、共享/私有冲刷、同步优先、私有优先于共享、`nodefer` 与附加屏蔽字、LIFO 恢复、处理函数内 `SetMask` 被恢复覆盖、强杀、终止后报错、拒绝零变更、并发竞态，以及与逐信号逐线程线性扫描朴素模型的 2000 组随机操作对照。
