# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 令牌环终止检测

实现在 `termination` 包中。`New(n, options...)` 创建编号 `0..n-1` 的进程环，0 是发起者；默认全部空闲、白色、计数为 0。可用 `WithActiveProcesses(...)` 配置初始活跃进程，用 `WithLogger(...)` 替换默认标准输出日志。

### 状态与操作

- `Send(from, to)`：只有活跃进程可发送；发送后发送者计数加一，消息进入在途网络。
- `Deliver(message, to)`：只能投递网络中未投递的原始消息；接收者计数在发送者计数中减一，接收者变为活跃且变黑。
- `BecomeIdle(process)`：进程显式进入空闲；重复空闲调用不改变状态。
- `PassToken(holder)`：只有令牌当前持有者且持有者空闲时可调用；非发起者把本地计数加入令牌累计值、把自身黑色传播给令牌、再把自己变白，然后传给 `i-1`。
- 令牌方向为 `0 -> n-1 -> ... -> 1 -> 0`；单进程环为 `0 -> 0`。

### 颜色与计数规则

颜色用于捕获“令牌经过之后发生的活动”。消息接收会把接收者变黑；令牌经过该进程时把黑色带在令牌上，随后清除进程颜色。若令牌回到发起者后仍为白色，并且发起者也为白色，说明本轮扫描之后没有检测到新的接收活动。

计数器用于捕获令牌尚未扫描到的在途消息。每次发送在发送者计数上加一，每次投递递减一，因此恒有：

```text
所有进程计数之和 = 在途基本消息数
```

只看颜色可能漏掉与令牌反向赛跑、尚未被扫描到的发送；只看计数可能漏掉已经投递但没有在途消息的活跃进程。两者缺一不可。

### 宣告条件

第一圈是基线圈：令牌从发起者出发后完整经过每个非发起者再返回，用来建立整环快照。第一圈返回时即使条件为白且累计为 0，也只启动下一圈；这可避免令牌刚离开发起者、首条消息尚在反向传播时误报。单进程环没有未扫描进程，因此首圈可直接判定。

从第二圈开始，令牌回到空闲的发起者时，当且仅当以下条件全部满足才宣告：

- 发起者为白色；
- 令牌为白色；
- 令牌累计值加上发起者计数为 0；
- 计数器不变量保证此时在途消息数为 0；
- 令牌只能在持有者空闲时传递，因此回环时所有被扫描进程均为空闲。

宣告会返回轮数。此后继续发送、投递、转空闲或传递令牌会返回 `ErrTerminated`。

### 轮数上界

真正终止后没有进程能再变黑，也没有计数变化。若终止发生时某一圈已经在环上，该圈最多把已经存在的黑颜色或非零计数带回 0；下一圈从 0 重新置白、累计清零，并完整扫描所有进程。扫描期间不可能出现新活动，所以下一圈返回时一定满足全部条件。基线圈之后，真正终止点之后发起的轮次至多两轮宣告；若绝对时间从计算刚开始计算，首个基线轮之后再加至多两轮。

### 拒绝原因

所有非法操作先验证、后修改，并返回可用 `errors.Is` 区分的哨兵错误：

- `ErrInvalidProcess`：进程编号越界；
- `ErrIdleSender`：空闲进程发送；
- `ErrSelfMessage`：进程向自己发送；
- `ErrMessageNotFound`：网络中不存在该消息或消息内容不匹配；
- `ErrAlreadyDelivered`：重复投递已投递消息；
- `ErrWrongDestination`：把消息投递给非目标进程；
- `ErrNotTokenHolder`：非持有者传递令牌；
- `ErrActiveTokenHolder`：活跃持有者传递令牌；
- `ErrTerminated`：宣告后继续变更系统。

所有公开操作在同一个互斥锁内线性化，因此发送、投递、转空闲和令牌传递可并发调用。固定的操作序列按相同顺序重放会得到相同结果、宣告时刻和轮数。

## 环境要求

- Go 1.26+（`go version` 确认）

## 本地验证

```bash
# 若环境的默认 GOCACHE 位于只读目录，可显式指定缓存
export GOCACHE=/tmp/ontology-go-cache

# 全量测试
go test ./...

# 竞态检测与详细日志；确定性用例使用内存日志，默认 New(n) 会向标准输出打印输入、输出与判定依据
go test -race -v ./termination

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out

# 格式与静态检查
gofmt -w .
go vet ./...
```

## 覆盖场景

- 令牌经过后消息才到达，接收者变黑从而阻止误报；
- 消息与令牌沿环赛跑；
- 真正终止后至多两轮宣告；
- 单进程环；
- 1000 个固定种子随机交错、无提前宣告且最终宣告；
- 相同操作和投递序列重放得到相同宣告时刻与轮数；
- 多 goroutine 并发发送、投递、转空闲和传令牌，并通过竞态检测。
