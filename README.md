# ontology-platform

本体服务平台（对标 Palantir Foundry Ontology）。

## 分段日志保留策略（`segmentlog` 包）

`segmentlog` 是并发安全的追加型日志：记录按段组织，删除旧数据的最小单位是
整段；清理后剩余段首尾相接，起始位点只进不退，任意时刻读到的都是一段连续、
字节内容与追加时完全一致的区间。

### 数据模型

- `Record{Time int64, Data []byte}`：`Time` 为毫秒时间戳（正数），字节数按
  `len(Data)` 计；追加时数据会被拷贝，调用方事后修改切片不影响日志。
- 段（segment）维护：首/尾位点、字节数、段内最大时间戳（段的保留时间）、
  记录列表；最后一个段为活动段。
- 位点空间：每条记录的起始位点 = 其首字节在日志中的偏移；下一条记录的位点
  紧接上一条，删除整段只是把日志起始位点前移到该段尾位点，旧位点区间失效。

### 追加与段滚动

- 追加顺序：先校验输入，再加锁；活动段不存在或“当前段字节数 + 新记录字节数
  `> MaxSegmentBytes`”时先新建活动段（追加后超限才滚动，因此段可恰好写满）。
- 单条记录字节数超过 `MaxSegmentBytes` 会被整体拒绝（永远放不下的记录）。
- 记录时间戳必须单调不减（允许相等）；回退追加被整体拒绝。
- 任何被拒调用都在修改任何状态之前返回：段列表、总字节数、起始位点、
  下一位点均不变，失败不留痕。

### 两阶段保留（`Retain(now)`）

每次保留依次执行两个阶段，两阶段都从当时最旧的段起逐段判定，
且都遵守“遇到第一个不满足删除条件的段立即停止”：

1. **时间阶段**（`RetentionMillis > 0` 时启用）：删除条件为
   `段保留时间(段内最大时间戳) < now - RetentionMillis`。
   边界含等于：`maxTime == cutoff` 的段保留。
2. **大小阶段**：仅当当前总量 `> MaxTotalBytes`，且删除最旧段后
   `总量 - 该段字节数 <= MaxTotalBytes`（即删了就能达标）时才删除该段；
   若总量已达标则立即停止；若删除最旧段后仍超限，也立即停止，
   **不会跳过最旧段去删后面的段**。边界含等于：剩余总量恰好等于上限即停止。

两个阶段都**永不删除活动段**：当仅剩活动段时，即使它已过期或总量超限也保留。
删除整段会把起始位点前移到该段尾位点，并从总字节数中扣除整段字节数。

`Retain` 还会返回 `[]Step`，逐步记录每个被检查段的阶段、动作（remove/keep）、
段快照与文字判定依据，便于复现“为什么删/为什么停”。保留时钟 `now` 必须为正
且相对上一次保留单调不减。

### 读取（`Read(offset)`）

- 从某条尚存记录的起始位点读到日志末尾，返回记录内容的拷贝，拼接后覆盖
  `[offset, 当前末尾)` 的连续区间；末尾位点合法并返回空结果。
- 越界类别：位点早于当前起始位点（已被整段删除）、晚于末尾、或落在某条
  记录内部（不是记录边界），均返回 `ErrOffsetOutOfRange`。

### 错误类别（互不相同，可用 `errors.Is` 区分）

| 错误 | 触发场景 |
| --- | --- |
| `ErrInvalidConfig` | 段容量/总容量非正、`MaxTotalBytes < MaxSegmentBytes`、保留窗口为负 |
| `ErrInvalidRecord` | 时间戳非正、数据为空、记录字节数超过段容量 |
| `ErrClockBackwards` | 追加时间戳早于已接受的最大时间戳；或 `Retain` 的 `now` 回退 |
| `ErrOffsetOutOfRange` | 读取位点已删除、越过末尾或落在记录内部 |
| `ErrInvalidArgument` | 其它非法入参（如负位点、非正保留时钟） |

每条错误都带有说明具体原因的消息，但根因可通过 `errors.Is` 判定。

### 并发

`Append`、`Retain`、`Read`、以及状态查询均由同一把读写锁保护；
`Read` 持读锁可与其它读取并发。所有对外可见不变量（段首尾相接、
起始位点单调、总字节数一致、记录内容不可变）在并发调用下成立。

### 本地验证

```bash
# 全量测试（含竞态检测）
go test -race -v ./segmentlog/

# 覆盖率
go test -cover ./...

# 静态检查与格式
go vet ./...
gofmt -l .
```

测试用 `-v` 运行时会打印每步追加/保留的输入、完整段列表与每一步判定依据
（`dump` 输出），并覆盖：

- 追加滚动、段恰好写满、各记录位点读取连续；
- 时间边界（`maxTime` 恰好等于 cutoff 不删）与整段删除；
- 大小边界（删后恰好等于上限停止、删最旧段仍超限则零删除停止）；
- 活动段在时间与大小两阶段都不被删除；
- 非法配置/记录、时钟回退、读取越界，以及拒绝后段列表/总字节数/起始位点
  完全不变（失败不留痕）；
- 多 goroutine 并发追加/保留/读取的竞态安全与剩余区间连续性；
- 与独立的朴素参照实现（有状态段 + 相同两阶段规则）在确定性随机场景下
  逐步对账一致。

## 环境要求

- Go 1.26+（`go version` 确认）

## 运行

```bash
# 拉取依赖
go mod tidy

# 直接运行
go run ./cmd/server

# 编译后运行
go build -o bin/server ./cmd/server
./bin/server
```

## 测试

```bash
# 全量测试
go test ./...

# 带竞态检测与详细输出
go test -race -v ./...

# 单个包 / 单个用例
go test ./ontology
go test -run TestObjectType ./ontology

# 覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

## 代码检查

```bash
gofmt -l .
go vet ./...
```
