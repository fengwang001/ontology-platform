# 考场排考与调考引擎 — 设计说明

1. 模块划分：`calendar.go` 时段/日历；`domain.go` 考场容量、选考关系、监考名单（纯静态数据）；`engine.go` 排考判定、事务、查询与并发；`errors.go` 结构化错误码。
2. 时段编号 `slot = day*slotsPerDay + idx`，全日历唯一单调；考试占用为左闭右闭整时段集合，`[start,end]` 同日合法，跨日/越界拒绝。
3. 加时：延长量 `ceil(standard*num/den)`，实际时长取全体参考学生最长者；延长学生所在考场占用到延长终点，普通学生只到标准终点。
4. 座位确定性：延长学生（编号升序）优先，再普通学生，按调用给定考场顺序依次填满；凡承接延长学生的考场占用延长段。
5. 调用方显式列出的每个考场都视为被占用（含未分到学生者，按标准终点），以表达“预留考场”，故未用满的考场仍参与冲突与监考计算。
6. 学生冲突三分类按 `重叠 > 超门数 > 间隔不足`，同类取最小学号；间隔定义为相邻区间右端到左端之间的整时段数，恰好等于下限通过；只比较同日考试。
7. 复杂度：维护 `学生 -> 已参加考试` 倒排索引（有序切片），判定候选考试对学生 s 只遍历其 k_s 门考试，开销 O(k_s)，与考试总数/考场数/时段数无关；`BenchmarkStudentConflictScaling` 在 N=100…4000 下耗时恒定（约 100ns）可复现验证。
8. 监考：逐时段按监考人员编号升序，挑选该时段空闲且当日额度未满者，需要量=当时段被占用考场数×每考场人数；选择只依赖当前状态，故与调用历史无关。
9. 事务：所有变更先在 `world.clone()` 深拷贝上判定并写入，成功才整体替换；移动以“自身已移除”为基准，失败不触碰旧状态；互换先移除双方，再按考试编号升序试放，任一失败整体回滚并归因到失败方。
10. 拒绝优先级固定：参数非法 > 已安排 > 跨日越界 > 考场占用 > 容量不足 > 学生冲突 > 监考不足；容量检查特意排在考场占用之后（容量不足时全部考场按全长参与占用检查）。
11. 并发：单把 `sync.Mutex` 串行化全部读写，查询也加锁，天然可线性化；状态只在锁内通过整体替换更新。
12. 查询：按学生/考场/监考返回占用列表并按时段升序；学生查询给出其所在考场与其个人终点（含加时差异）。
13. 被放弃方案：(a) 用增量账目直接原地改再回滚——易因 map 别名留下脏占用（朴素模型早期即因此误报），改为 clone-and-commit；(b) 朴素扫描全部已安排考试判定学生冲突——随 N 增长，改用倒排索引；(c) 未分到学生的考场不占用——会让“预留考场”无法表达且产生漏报，已否定。
14. 本地验证：`go test ./...`、`go test -race ./...`、`go vet ./...`、`gofmt -l .`；`go test -run TestRandomDifferential -v` 打印每步输入/输出/依据，`SEED=<n> go test -run TestRandomDifferential` 复现；`go test -bench BenchmarkStudentConflictScaling` 验证复杂度。
