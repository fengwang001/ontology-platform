# 题库版本管理与组卷约束引擎 — 设计说明

## 模块划分（package `exam`，8 个 .go 文件）
- `question.go` 题目与不可变版本；`mutex.go` 互斥组与传递闭包；`paper.go` 试卷与纯约束检查；
  `engine.go` 串行化门面（生命周期、草稿、发布、替换）；`errors.go` 八类可区分错误（数值即优先级）；
  `doc.go` 包文档；`engine_test.go` / `model_test.go` 测试。

## 关键取舍
- **并发**：所有公开方法共用一把 `sync.Mutex`，调用结果等价于某串行序且线性一致；
  放弃细粒度锁——正确性论证简单，吞吐不是本需求重点。
- **互斥闭包**：把“题目-组”二部图的连通分量做增量维护（`comp[q]`）。
  加组=合并分量（按小并入大），减组=仅在受影响分量内 BFS 重算；
  候选题与试卷的冲突判定只读 `len(试卷题目)` 次 map（`checkOps` 计数器，
  `TestConflictCheckCostIndependentOfTotals` 在 3000 题/1500 组下断言 ≤ 试卷大小），
  与题库总量、组总量无关。放弃并查集（不支持删边）与每次 BFS（随分量规模增长）。
- **冻结口径**：发布/替换时把版本号与分值、难度、知识点快照进 `BoundQuestion`；
  之后修订只追加新版本，不回溯试卷。草稿只存题目引用，发布时才解析最新版本。
- **失效试卷**：不变式为“失效当且仅当含下架题”。下架使已发布试卷转失效并返回受影响清单；
  失效卷仅允许替换下架题，替换按全约束校验（其余下架题暂容），无下架题即恢复已发布。
- **全有或全无**：校验全部在锁内先算后写，任何一类失败直接返回，状态与版本号零副作用。
- **错误优先级**：每个操作按 参数>不存在>状态>可选用>互斥>总分>知识点>难度 的顺序检查，
  首个违例即返回；`Error.Questions` 带涉及题目。

## 被放弃的方案
- 事件溯源/持久化存储：需求只要求行为可复现，内存模型+摘要对照即可验证。
- 草稿加入时即校验总分/知识点：整卷约束只在 Validate/Publish 检查，草稿保持可中间态。

## 本地验证
```
go test ./exam                 # 场景+边界+对照测试
go test -race ./exam           # 并发线性一致（竞态检测）
go test -run TestDifferentialRandom -v ./exam  # 每步输入/输出/判定依据日志
go vet ./... && gofmt -l .
```
对照测试用独立朴素模型（BFS 求互斥、全量重算约束）重放随机操作序列，
逐步比较错误类别、受影响试卷清单与全量状态摘要（`Digest`）。
