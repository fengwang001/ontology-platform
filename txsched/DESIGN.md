# txsched：传输层发送端小段合并调度器 —— 设计说明

## 1. 模型与术语

调度器维护一条字节流上的三个序号：

- `sent`：已发送序号（含零窗口探测的那一个字节）；
- `acked`：累计确认序号（对端确认事件携带的累计确认字节数）；
- `rightEdge`：对端窗口右边缘，等于最近一次合法通告的 `ackNum + window`，只增不减。

由此派生：在途 = `sent - acked`；可发送余量 = `rightEdge - sent`（小于零时按零处理，
探测字节会使其暂时为 -1）。缓冲区是尚未发出的字节队列，按写入批次组织为
`(进入时刻, 长度)` 的块队列。

每个事件处理完毕后立即执行一次发送决策（`sendPass`），产出本次发出的各段
（长度、发出时刻、是否探测段）。时钟完全由调用方注入：每个事件携带发生时刻，
调度器自身不读真实时钟。

## 2. 发送决策

发送循环每轮取 `segLen = min(MSS, buffered, wndRemain)`：

- `segLen == MSS` 为满段，窗口允许范围内总是可发；
- `segLen < MSS` 为小段——可能是尾部不足一个满段，也可能是被窗口截短
  （截短的段不再视为满段，其余量留在缓冲中，之后凑满 MSS 仍可按满段发出）。

小段的保留约束按优先级依次为：

1. 已关闭：忽略一切保留约束，仅按窗口约束发送；
2. 软木塞打开：自最早被保留数据进入缓冲起满软木塞超时则解除，否则保留；
3. 不延迟打开：只受窗口约束；
4. 默认（Nagle）：在途为空可发，在途非空则保留。

循环在三种情况下停止：缓冲清空、窗口余量不大于零、小段被保留。

**关键不变式**：`reserved > 0` 当且仅当发送循环因"保留"而停止，且此时
`reserved == buffered`（全部缓冲都是被保留的小段字节）。证明：循环停止于
保留分支时，此前所有可发字节（满段与未被保留的小段）都已发出，窗口余量
仍为正（否则先命中窗口分支），因此缓冲中剩余字节全部处于被保留状态。
该不变式使"最早一批被保留数据进入缓冲的时刻"就等于队首块的进入时刻，
软木塞计时与 `reserved` 查询都是 O(1)。

## 3. 零窗口探测

`trackZero` 在每次发送决策后维护"窗口为零且缓冲非空"状态的开始时刻
`zeroSince`。探测条件：`zeroSince` 有效且在途为空；探测时刻为
`max(zeroSince, lastProbe) + probeInterval`。探测段长 1 字节、计入在途，
因此在途非空时自然不会再次探测；探测字节被确认后，其余数据是否可发只
取决于最新窗口（右边缘规则对探测字节一视同仁）。窗口重新打开或缓冲清空
时 `zeroSince` 失效，探测即取消。

## 4. 错误与拒绝语义

错误按固定优先级检查：参数非法 → 时钟回退 → 关闭后写入 → 缓冲已满 →
窗口收缩 → 确认越界。所有拒绝检查在修改任何状态之前完成，因此被拒绝的
事件不改变缓冲、在途、窗口与时钟（时钟只被已接受事件推进）。

- 写入长度为零、为负或超过 2^31-1：参数非法；2^31-1 本身合法。
- 窗口收缩用减法比较 `ackNum < rightEdge - window` 判定，避免加法溢出。
- 确认越界：累计确认倒退（增量为负）或增量超过在途。

## 5. 关键取舍

- **缓冲表示：写入批次块队列**。每块记录进入时刻与长度，发送时从队首消费。
  内存与"尚未发完的写入批次数"成正比，与缓冲字节总量无关；队首块时刻
  直接给出软木塞计时基准。
- **不变式取代区间追踪**：利用 `reserved > 0 ⟺ reserved == buffered`，
  无需为"被保留区间"单独维护起止位置。
- **探测计时基准取 `max(zeroSince, lastProbe)`**：严格对应"自窗口变为零
  或上次探测起满探测间隔"；`zeroSince` 的跟踪不要求在途为空，在途条件
  只在点火时检查，与题面语义一致。
- **软木塞计时基准取队首块进入时刻**：对应"自最早一批被保留数据进入
  缓冲时起"。数据若因窗口阻塞尚未被"保留"过，其进入时刻仍被计入——
  这与"进入缓冲时"的字面语义一致，且使计时无需额外状态。
- **关闭后探测仍然生效**：零窗口条款是无条件的窗口机制，关闭只解除
  保留约束，不解除窗口约束。

## 6. 被放弃的方案

- **每字节（或每段）时间戳链表**：时空开销随缓冲字节总量增长，违背
  复杂度约束，放弃。
- **为被保留区间单独维护起止偏移**：被第 2 节的不变式取代，放弃。
- **惰性段生成（迭代器/游标）**：输出段列表本身必须与输出等长，
  惰性化不降低渐近开销却显著复杂化 API，放弃。
- **软木塞抑制探测**：题面零窗口条款无条件成立，选择探测不受选项
  影响，放弃抑制方案。
- **注入时钟接口（`func Now()`）而非事件携带时刻**：事件携带时刻使
  "时钟回退"成为可校验的事件属性，且并发下语义更清晰，放弃接口方案。

## 7. 复杂度论证（可验证）

- 每个事件的校验、状态变更为 O(1)。
- 发送循环的每轮迭代恰发出一个段：开销与输出长度成正比，而输出段列表
  本身必须与输出等长，故不存在更优的渐近界。
- 块队列：每个块至多入队一次、出队一次；压缩在 `head >= 64` 且
  `head >= len/2` 时触发，搬移的块数不超过自上次压缩以来的出队数，
  故总搬移次数 ≤ 总出队次数 ≤ 总入队次数 ≤ 写入事件数。均摊 O(1)/事件。
- `Snapshot` 只读、O(1)。
- **验证方法**：`Stats()` 暴露 `ChunkPushes/ChunkPops/CompactMoves`
  计数器，`TestAmortizedCost` 以 20000 个写入事件断言
  `pops ≤ pushes ≤ writes`、`CompactMoves ≤ pops`、
  `pushes+pops+moves ≤ 3·writes`，直接验证上述界。

## 8. 并发

所有导出方法持有同一把互斥锁，每个操作在临界区内整体完成，因此任意
并发调用都可线性化，等价于某个串行顺序。`TestConcurrentLinearizable`
在 `-race` 下以 8 goroutine 混合调用验证无数据竞争且不变式保持。

## 9. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin GOCACHE=/tmp/gocache

go test ./txsched                 # 全部确定性单测 + 1500 组随机差分
go test ./txsched -race           # 竞态检测
go test ./txsched -run TestDifferentialRandom -v   # 打印每步输入/输出/判定依据
go test ./txsched -run TestDifferentialLogExample -v # 手工序列逐步日志样例
TXSCHED_SEED=42 go test ./txsched -run TestDifferentialRandom  # 更换随机种子复验
go vet ./txsched && gofmt -l txsched
```

差分测试以固定种子（1581）生成 1500 组随机事件序列（合法与非法事件混杂，
含时钟回退、越界确认、窗口收缩、负参数等），逐步比对真实实现与独立朴素
模型的错误、输出段与状态快照，并断言被拒绝事件不改变任何状态。
