# 变压器容量预约系统 — 设计说明

1. 模块划分（包 `pkg/reservation`）：
   - `model.go`：区间、预约状态机、`Logger` 接口（左闭右开 `[Start,End)`）。
   - `errors.go`：七类错误与拒绝次序；容量错误携带首个超限时刻与层级。
   - `capacity.go`：按生效时刻有序的容量表，`at(t)` 为二分查找；同一生效时刻后者覆盖。
   - `treap.go`：两个随机化 treap——事件差分 treap（子树和，`prefixBefore(t+1)` 取 t 时刻占用）
     与到期 treap（按 `(到期时刻,id)`，`drain` 只弹出本次到期者）。
   - `occupancy.go`：每馈线一棵 + 全局两棵（全部/仅已确认）事件树；两级校验与下调判定。
   - `system.go`：`System` 业务主体（单一互斥锁，所有操作等价于某种串行序）。
   - `naive.go`：独立逐时刻朴素模型，仅用于随机差分对照，不与生产代码共享数据结构。
2. 两级校验只枚举“校验窗口内”的事件时刻与容量生效时刻：占用在相邻这些点之间恒定，
   故不与任何不相交预约、更早容量记录发生关系，满足不随其数量增长的要求（`TestCheckCostIndependentOfIrrelevantData`
   直接断言窗口内候选时刻数为 1）。前缀和为 O(log n)。
3. 时钟推进 `settle` 先落定到期占位（到期时刻本身即到期，转已失效），再把 `End<=now` 的
   已确认预约转已完成并移出索引；到期 treap 的 `drain` 成本只与本次落定数量相关。
4. 确认不再校验（占位期容量被保障）；确认时若 `End<=now` 则成功后立即落定为已完成、不占用。
5. 改约先按排除自身的新值做两级校验，通过后在同一临界区原子替换；状态与占位到期时刻不变。
   已开始的已确认预约仅允许原地提前结束（新终点 ∈ [now, 原End]）。
6. 容量下调：先临时插入记录，仅用“已确认”树找首个超限时刻，超限则回滚容量表、整体拒绝；
   通过后反复找最早超限时刻并取消该时刻“创建时刻最晚（同刻 id 大为晚，保证可重放）”的占位，
   直至不再超限；已确认预约永不被取消。
7. 拒绝次序在每处入口固定：参数非法 > 时钟回退 > 预约不存在 > 状态不允许 > 占位已到期 >
   已取消（容量下调取消的占位再确认/改约/释放时报“已取消”）> 容量不足。
8. 被放弃的方案：
   - 按整数时刻开桶存占用：稀疏长区间下内存与下调扫描均爆炸；
   - 区间树 + 单点查询：无法廉价给出“首个超限时刻”，且容量分段叠加困难；
   - 每条预约扫描：违反“成本不随不相交预约数量增长”。
   差分事件 + 候选时刻枚举同时自然处理端点相接（同刻 +p/-p 净额为 0）与容量恰在预约起点生效。
9. 可复现：ID 单调、取消并列用 id 决胜、所有随机来源只在 treap 内部（结构不影响语义），
   同一操作序列重放得到相同状态序列。
10. 本地验证：
    `go test ./...`、`go test -race -count=1 ./...`、`go vet ./...`、`gofmt -l .`；
    `TestRandomDifferential` 对 120 个种子 × 600 条随机操作逐操作比对输出与全量预约状态，
    日志（注入 `Logger`，如 `strings.Builder`）逐条打印输入、输出与判定依据。
