# 占道施工许可审查服务 — 设计说明

## 模块（职责单一、彼此协作）
1. `types.go` 领域类型：路段/走廊/许可/时段(左闭右开)/状态机/操作与查询请求/不可变历史条目。
2. `errors.go` 十类互斥拒绝原因与严格优先次序；错误携带证据许可 ID 以便复现。
3. `network.go` 静态路网构建与校验，派生绕行正向表与"被谁纳入绕行线"反向表。
4. `index.go` 确定性 treap（按 (开始时刻,ID) 键，子树维护 maxEnd/size），支持墓碑与原地 upsert。
5. `rules.go` 纯判定：同路段车道、绕行双向、走廊扫描线、应急同路段、抢占目标选择。
6. `service.go` 加锁串行化、时钟/前置校验、受理/延期/撤销/查询、接受后落档与审计。
7. `preemption.go` 应急抢占、残余时段顺延、按原批准次序的级联重审、索引维护、快照。
8. `naive/naive.go` 独立编写的朴素全量重判预言机，与正式实现零判定代码共享。

## 关键取舍
- **时间索引全量保留 + 墓碑**：曾受理节点不做物理删除，撤销/重定位置 valid=false。
  查询支持任意时刻（含历史），相交枚举靠 maxEnd 剪枝与键序下界，O(log n + 命中数)，
  访问步数不随历史许可总数增长；历史节点被整棵剪枝，不会被遍历。
- 放弃"结束时刻最小堆惰性物理删除"方案：它会销毁历史节点，使过去时刻查询无法复现，
  且双堆（路段/走廊）交叉失效引入了陈旧条目误删新节点的严重 bug（差分测试捕获）。
- treap 优先级由 (start,id) 哈希确定，无随机源，保证相同序列重放逐字节一致。
- 时段原地变更（延期/缩短/顺延恢复）走 `upsert`：同键更新 end/lanes 后沿根路径重算 maxEnd。
- 判定带"在册下界"：只统计 end>bound 的许可；新申请 bound=min(操作时刻,候选开始)，
  使"冲突优先于起始早于当前"的报错次序在 start<opAt 时仍成立。
- 应急语义：应急受理只校验参数与应急间同路段车道数；常规许可同路段约束不含应急
  （相交常规由抢占移开），绕行方向 B 仍把已存在的上游全封闭（含应急）视为物理阻塞。
- 抢占顺延严格按 ApproveOrder 升序重审，先恢复者立即进入索引影响后者。

## 并发与复现
- 单把互斥锁使所有操作等价于某一串行顺序；确定性 treap/排序保证无随机分歧。
- 被拒绝操作零状态改动、不推进时钟；只有接受才记录操作并更新许可历史。

## 本地验证
- `go test ./...` 全量；`go test -race ./...` 竞态；`go vet ./... && gofmt -l .`。
- 规定场景见 `service_test.go`；查询复杂度见 `query_complexity_test.go`（2k vs 20k 历史对照）。
- 随机差分 `TestRandomDifferential`：120 种子×500 操作，逐条对照朴素全量模型；
  `TestRandomDifferentialLogged -v` 打印每条操作输入/输出/判定依据；
  `TestReplayDeterminism`、`TestConcurrentOperations` 验证重放一致与并发串行化。
