# 影像检查预约与对比剂准入系统 — 设计说明

## 1. 模块划分

所有代码在 `imaging` 包内，按职责拆分为相互协作的文件：

| 文件 | 职责 |
| --- | --- |
| `errors.go` | 11+3 种可区分错误（`Error` 字符串类型），按规定优先级使用 |
| `imaging.go` | 对外请求/响应结构体、`Config`、`Hospital` 与构造器 |
| `state.go` | 设备、检查类型、患者、预约的内部状态模型与状态枚举 |
| `validate.go` | 时间域 `[0,10^7]`、非空标识、正整数时长、配置合法性 |
| `ops.go` | 统一事务入口 `begin/commit/abort` 与登记类操作 |
| `rules.go` | 肾功能时效/阈值、每日质控求交、留观容量扫描 |
| `treap.go` | 两个确定性数据结构：键多重集合、增广区间树 |
| `appointments.go` | 预约受理、水化/预处理、签到复核、改约、取消的状态机 |
| `naive*.go` | **独立**朴素参考模型（切片全量扫描，不复用主实现判定） |
| `snapshot.go` | 主实现与朴素模型的统一确定性快照，供深比较 |

## 2. 关键数据结构

### 2.1 设备占用：增广区间树（确定性 treap）

- 每台设备一棵区间树，键为 `(start, 唯一id)`，子树维护 `maxEnd`。
- 插入/删除期望 `O(log n)`；“是否与 `[s,e)` 重叠”用 `maxEnd` 剪枝，
  只访问可能重叠的子树，复杂度 `O(log n + k)`，`k` 为受影响区间数。
- 半开语义：`a.start < b.end && b.start < a.end`，**恰相接不重叠**。
- treap 优先级由 `FNV-1a(id)` 确定性生成：相同操作序列重放得到完全相同的
  树形态与遍历结果，满足可复现要求。

### 2.2 留观位：开始/结束双多重集合

- 留观是半开区间 `[examEnd, examEnd+留观时长)`。用两个 treap 多重集合
  `starts`、`ends` 表示全部区间的起点与终点。
- 时刻 `t` 的人数 = `countLE(starts,t) − countLE(ends,t)`，各 `O(log n)`。
- 容量核对只枚举新区间窗口 `[s,e)` 内的事件（`rangeKeys`，`O(log n + k)`），
  在事件点做扫描线；同刻事件“先减后加”，保证恰相接（上例结束刻=本例开始刻）合法。
  **开销与窗口外的历史留观总数无关。**

## 3. 判定规则与边界

- **时间**：整数分钟、左闭右开；日长 1440。质控为日内 `[start,end)`，
  按占用落入的自然日逐日映射到 `[0,1440)` 求交；质控不跨日。
- **错误优先级**（只报第一个）：参数非法 → 时钟回退 → 对象不存在 →
  状态不符 → 设备类别不符 → 植入物不兼容 → 结果缺失或过期 →
  肾功能不足 → 设备时段冲突 → 质控时段冲突 → 留观位不足。
  其中“参数非法”在加锁前判定；“时钟回退”是加锁后第一步；
  登记类操作（设备/质控/检查类型/患者）本身不带 `now`，不参与时钟比较。
- **肾功能**：以预约 `start` 判定。只认采样时刻最晚、并列认登记次序在后者；
  采样晚于 `start` 的结果视同尚未出具。有效期 `start−sampledAt <= 配置`（**恰等仍有效**）；
  `value < 下限` 报不足；`下限 <= value < 上限` 须水化；`>= 上限` 免水化。
  高风险与普通患者使用不同有效期。
- **植入物**：仅 MR 检查，要求设备场强 `<=` 患者允许上限，**恰等兼容**；无植入物不限。
- **受理**只判：类别、植入物、肾时效与下限、设备区间（含质控）、留观位。
  水化/预处理**不在受理时要求**。
- **水化/预处理**：针对已受理预约登记开始时刻（不晚于操作 now）。
  要求 `开始时刻 <= 预约start − 提前量`（**恰取等满足**）；预处理仅对有
  对比剂过敏史患者要求。
- **签到窗口**：`[start−30, start+15]` 闭区间；窗口外报“签到窗口不符”，
  且**不改变状态与时钟**。
- **签到复核**：以签到时刻的最新结果按预约 start 重判时效与下限，再核
  水化、预处理。任一不过，预约转“需改期”，**立即释放设备与留观占用**，
  按序只报第一个原因：结果缺失/过期 → 肾功能不足 → 未水化 → 未预处理。
  签到本身是被接受操作（更新时钟）。
- **改约**：原子换到新 start / 新设备。旧占用（含自身）不阻挡新安排
  （区间查询 `skipID`、留观扫描扣除自身旧区间）；全部条件按新安排重判，
  失败则原约不变；成功后已登记的水化/预处理作废，需重新登记。
- **取消**：释放设备与留观占用；已签到、已取消不可取消（状态不符）。
  “需改期”只能改约或取消。

## 4. 并发与失败原子性

- `Hospital` 用单个 `sync.Mutex` 串行化所有写操作。所有操作在锁内完成
  “读判定 + 写状态”，因此任意交错都等价于某个串行顺序，且不可能观察到
  中间态。这是刻意取舍：域内单次判定都是对数/窗口级，全局锁简单且可证明正确。
- 统一事务范式：
  `begin(now)` 加锁并查时钟回退；校验全部通过后才修改状态，再 `commit`。
  任何错误返回走 `abort`（仅解锁，不更新 `lastNow`、不触碰业务状态）。
  从而**被拒绝操作不改变任何状态与时钟**。

## 5. 性能：可验证的历史无关性

基准位于 `bench_test.go`，两档对照（`go test -bench`）：

- `BenchmarkBookVsHistory`：全院历史 10,000 vs 400,000（40 倍），
  新预约落在所有设备都为空的新窗口（受影响占用数两档皆 0）。
  实测约 `2.17µs → 4.00µs`，属同一量级（差异来自缓存/构造，不随历史线性增长）。
- `BenchmarkObservationVsHistory`：历史留观 20,000 vs 400,000（20 倍），
  新留观窗口与历史完全不相交（窗口事件数皆 0）。
  实测约 `2.31µs → 2.80µs`，与历史留观总数无关。

复杂度小结：受理 = 设备区间树 `O(log n + k_dev)` + 留观窗口扫描
`O(log m + k_obs)`，其中 `k_dev/k_obs` 仅为受影响时段内的占用数；
`n/m` 为全院历史，仅以对数项出现，不随历史线性增长。

## 6. 被放弃的方案与理由

- **每设备/每资源细粒度锁**：能提高并行度，但“设备占用 + 全局留观位”
  跨资源一致性需要多锁顺序与死锁规避，证明成本高；题目更重判定精确可复现，
  故采用单锁，把并发正确性降为平凡结论。
- **用有序切片 + 二分保存占用**：实现简单，但插入/删除为 `O(n)`，
  受理会随该设备历史增长，直接违背性能约束，放弃。
- **留观位逐分钟布尔数组 / 计数数组**：查询直观，但时间域到 `10^7` 且
  区间稀疏，数组常驻与初始化都不经济，也无法干净表达“只看窗口”，改用事件多重集合。
- **区间树按 end 排序**：删除定位不便，且 start 键序与“新增按开始”天然一致，
  最终按 `(start,id)` 排序并用唯一 id 处理同刻。
- **朴素模型复用主实现的判定函数**：会使差分失去独立性，故朴素模型完全另写，
  设备占用与留观均用切片全量扫描。

## 7. 本地验证方法

```bash
# 环境（Go 1.26.5；如 go 不在 PATH）
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache GOPATH=/tmp/gopath

go test ./...                                   # 全量测试
go test -race ./imaging                        # 竞态检测
go vet ./... && gofmt -l .                     # 静态检查与格式

# 1800 步随机差分（15 个种子 × 120 步），逐步打印输入/输出/判定依据
DIFF_LOG=1 go test ./imaging -run TestDifferential1500 -v

# 两档规模性能对照
go test ./imaging -run '^$' \
  -bench 'BenchmarkBookVsHistory|BenchmarkObservationVsHistory' -benchmem
```

测试构成：

- `edge_test.go` / `edge2_test.go` / `edge3_test.go`：题目列举的全部边界
  （相接与差一分钟、质控跨日、有效期恰等、高风险/普通、下限/上限恰等、
  水化/预处理取等、场强恰等、留观恰满、改约与自身旧占用重叠、签到失败释放、
  错误优先级、窗口边界、状态约束）。
- `diff_*_test.go`：与独立朴素模型的随机差分，逐步比对返回值与完整状态快照。
- `concurrency_test.go`：16 goroutine 并发，校验无重叠占用与存活占用一致。
- `bench_test.go`：两档规模性能证据。
