# 渲染树布局失效与重排内核 — 设计说明

模块划分（包 `layout`）：
1. `node.go`：`node`/`Tree`/`Mode`/`Size`、尺寸纯函数 `computeSize`、可重入互斥锁（同 goroutine 可嵌套，支撑度量回调中查询）。
2. `dirty.go`：边界判定 `isBoundary`（隔离 && 宽固定 && 高固定，根恒为边界）、自身脏上溯 `markSelf`、移动/脱离子树的逃逸脏判定 `escapedDirty`、非根脏边界集合。
3. `tree.go`：属性修改（同值不脏）、Create/Insert/Remove/Move；结构变动标旧父/新父自身脏，被移动子树标记原样保留，按新位置经 `markSubOnly` 重传播；边界身份得失两方向的重成立。
4. `reflow.go`：显式/隐式提交共用的最小子树后序重排；子先父后、同父按序、多个脏边界按兄弟索引路径字典序（=树先序）；父仅在自身脏或子尺寸变化时重算，新尺寸不变即停止上溯；边界固定尺寸恒报"不向上扩散"。
5. `measure.go`：`Commit`、`SizeOf`（有脏先隐式提交，路径与显式完全一致）、`IsDirty`/`IsBoundary`。
6. `logger.go`：`Logger` 接口（IN/OUT/DEC 三类事件）、默认 stderr 实现、可静默。
7. `naive.go`：独立编写的朴素模型，任何操作后从根全量重算，作为差分测试 oracle。

关键取舍：
- 失效能"过度标记"、不能"漏标记"：`markSelf` 遇到已有 subDirty 的祖先即提前返回（该祖先上方链已被标记或它本身就是停止边界），传播成本 O(到最近边界深度)，与总节点数无关。
- 失去边界身份时无法廉价区分陈旧与新增 subDirty，选择向祖先补传播（可能过标），重排的"尺寸不变即停"天然消化过标；获得边界身份不撤回已上溯标记（失效只增不减）。
- 脏边界集合只存非根节点（根隐式）；提交只递归进入 self/subDirty 节点，重排节点数与干净节点数无关，`LastReflowCount()` 供可验证检查。
- 错误拒绝次序：参数非法 → 节点不存在 → 结构冲突 → 提交中重入；校验全部先于状态修改，拒绝即无副作用。
- 并发：全局串行化锁保证任意并发等价于某串行序；同 goroutine 重入靠 goroutine id + 条件变量，嵌套 `Commit` 仍以 `committing` 标志独立报重入错误。

被放弃的方案：
- 放弃"版本号/代际标记"精确区分陈旧 subDirty：需要额外遍历或引用计数，复杂且与 O(深度) 目标冲突；过标 + 早停已足够。
- 放弃提交时全树扫描收集脏边界：违反"成本不随干净节点数增长"；改为维护脏边界集合，排序键仅按到根路径构造。
- 放弃读写锁分离提交与修改：重排需稳定快照，且正确性优先于读多写少假设。

本地验证：
- `go test -race -v ./layout`（环境无 Go 于 PATH 时用 `/usr/local/go/bin/go`，并设 `GOCACHE=/tmp/gocache GOPATH=/tmp/gopath`）。
- 覆盖点：边界三条件逐一缺失、根边界、同值不脏、父尺寸不变即停、穿到边界即止、移动跨边界重传播、移除/再插保留脏、边界得失两方向、隐式=显式、重入拒绝、错误四类可区分及拒绝次序、并发后与全量重算一致、60×400 随机操作对朴素模型差分、2000 干净节点下重排计数上界。
