# 银行卡拒付案件与商户资金扣回系统 — 设计说明

包 `ontology/chargeback` 提供拒付案件从提起、应诉、发卡行审阅、预仲裁到
终局裁决的完整生命周期管理；`ontology/chargeback/naive` 是一套独立书写、
仅用于差分测试的朴素重放模型。

## 时间与状态的核心取舍

需求要求“逾期自动认定不依赖任何操作触发，任意时刻查询的结果只取决于已接受
操作与查询所用 now”。最容易写错的一点是：**不能在未来时刻查询时把自动判定
急切固化进可变状态**，否则一次 `now=100` 的查询会让之后 `now=10` 的及时
应诉被误判为逾期。我们尝试过并放弃了以下方案：

1. **截止日最小堆 + 查询时弹出并改写案件状态**：未来查询会永久固化判定，
   污染更早时间点的读，且被拒绝操作难以做到完全无痕。已放弃。
2. **校验前预提交 + 快照回滚（Fenwick 内部节点逆向 add、事件重入堆）**：
   Fenwick 存的是聚合节点，同一回滚段内多次同日过账无法用“逆向 add”精确
   撤销；事件弹出/重入与“已结算”标记之间也极易产生重复过账。实现复杂且
   脆弱，已放弃。

最终采用**双层、无回滚**结构：

- **案件状态是纯函数**。`caseRec` 只保存被接受的显式操作历史（提起日、
  应诉日、是否预仲裁、显式终局裁决）。`derive(cfg, now)` 依据这些字段与
  `now` 纯计算当前阶段（待应诉 / 待审阅 / 预仲裁 / 商户胜 / 发卡行胜），
  不写任何字段。因此“应诉期含第 R 天、第 R+1 天起逾期”等规则集中在一处：
  - 无应诉且 `now >= fileDay + R + 1` → 自动发卡行胜；
  - 已应诉且无预仲裁、`now >= defenseDay + P + 1` → 自动视为接受应诉。
- **钱分两部分**。被接受操作造成的即时资金动作（提起即扣回、显式接受/
  裁决的返还与归属、仲裁费）写入不可变的“按天点值时间线”；自动判定的钱
  不写入时间线，而是在查询时由 `autoMerchantDelta` /
  `autoIssuerAndPending` 对“尚无显式终局”的案件集合**虚拟求和**。自动
  判定的归属日按截止日（第一个不允许日）计入，语义与显式接受完全一致。

这样被拒绝的操作根本不会产生任何待回滚状态：参数/时钟/存在性/状态检查
全部在纯函数视图上完成，只有全部校验通过后才落到时间线与案件记录。

## 资金账与守恒

- 时间线对每个商户分别维护“充值序列”和“变动序列”，发卡行与待决扣回各
  一条全局序列。点值按天累积，前缀读数用压缩坐标 Fenwick 树，复杂度
  `O(log D)`（D 为出现过的不同天数）。
- 待决扣回 = 提起时 `+amount`，终局归属（显式或自动）时 `-amount`。
- 守恒（仲裁费除外）：任意时刻
  `Σ 商户余额 + 发卡行账 + 待决扣回 = Σ 商户充值`。
  仲裁费是体系外流出，完整恒等式为
  `Σ商户 + 发卡行 + 待决 + 累计仲裁费 = Σ充值`。
  差分测试每一步都断言该恒等式。

## 查询复杂度（可验证）

“商户余额”和“交易可拒付余额”不得随历史案件/交易总数增长：

- 可拒付余额只遍历该交易的案件索引 `txnCases`（进行中 + 发卡行胜占用）。
- 商户自动返还只遍历该商户的“进行中且无显式终局”索引 `merchOpen`。
- 发卡行账 / 待决扣回遍历全局“无显式终局”集合 `openCases`，其规模只随
  当前在途生命周期工作量变化，而不随已终局历史增长。
- `BenchmarkMerchantBalanceHistory` 在 100 / 1000 / 10000 条已终局历史下
  测量查询，ns/op 基本持平，作为可复现的证据。

## 提起规则与错误优先级

- 三类原因窗口可配置；`提起日 - 结算日 <= 窗口` 允许（恰等未逾期）。
- 金额为正且不超过可拒付余额；同交易允许多案件并存，合计不超额。
- 重复扣款需同卡、同商户、同金额且**严格更早**结算（结算日差 1..D）的
  依据交易；一笔依据同时只能支撑一个“未以商户胜告终”的重复扣款案件
  （发卡行胜或进行中都继续占用，商户胜释放）。
- 同交易同原因已有商户胜终局案件 → 报重复提起；其他原因不受影响。
- 提起错误优先级：参数非法 > 时钟回退 > 交易不存在 > 窗口已过 >
  重复提起 > 超出可拒付余额 > 无依据。
- 其余操作：参数非法 > 时钟回退 > 案件不存在 > 当前状态不允许。

## 并发与确定性

单一 `sync.Mutex` 线性化所有调用，因此并发等价于某个串行顺序。状态只由
被接受操作决定，时间是整数天且 `now < lastOp` 即报时钟回退；相同操作
序列重放得到逐点一致的状态与资金账（`TestReplayDeterminism` 与差分
测试覆盖）。

## 朴素参考模型

`naive` 不共享任何索引或算法：它保存被接受操作日志，每次决策/查询都从头
重放。重放第 i 个操作前，先把自动判定推进到第 i-1 个操作的时间（这正是
第 i 个操作被接受时看到的状态），重放结束后再推进到查询时间。随机差分
测试对两实现逐操作比对错误、逐查询比对四类余额、案件状态与资金守恒。
