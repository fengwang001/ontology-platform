# pagetable：三级基数页表映射器

`pagetable` 在 512 个虚拟页（vpn 0..511）的地址空间上管理 1、8、64 页三种
大小的叶子映射，支持按需建表、劈分、合并、空表即时回收与表页配额约束。
所有操作可并发调用，内部以一把互斥锁串行化，结果等价于某个串行顺序。

## 页表布局

固定三层基数树，每层 8 槽：

| 层级 | 每槽覆盖 | 槽为叶子时映射 |
| ---- | -------- | -------------- |
| 根表（不计配额） | 64 页 | 64 页叶子 |
| L1 | 8 页 | 8 页叶子 |
| L0 | 1 页 | 1 页叶子 |

每个槽有三种状态：空（未映射）、叶子、指向下一层表的指针。每个叶子携带
可写位 W 与访问位 A、脏位 D（A/D 初值为 0；一个叶子只有一组 A/D，大页
整体共用）。物理页号 pfn 取 0..2^20-1。

## 叶子语义

- `Map(vpn, size, pfn, w)`：size ∈ {1,8,64}，vpn 与 pfn 都必须是 size 的
  整数倍，且 `[vpn, vpn+size)` 内此前没有任何映射。路径上缺失的表按需
  创建（受配额约束）。
- `Translate(vpn)` 返回叶子 pfn 加上页在叶子内的偏移，以及叶子大小与
  W/A/D；未映射返回 `ok=false`。
- `Touch(vpn, write)`：置覆盖 vpn 的叶子 A=1；write 为真时要求 W 为真并
  置 D=1。写保护拒绝发生在置位之前，因此 A 保持不变。
- `ScanDirty()` 按起点升序返回所有 D=1 的叶子并清 D，不改变其他状态。

## 劈分与合并的 A/D 规则

- **劈分继承**：`Unmap` 遇到与区间只部分相交的叶子时，先把它劈成 8 个
  下一层叶子（64→8 个 8 页叶子，8→8 个 1 页叶子），第 i 个子叶子
  `pfn = 原 pfn + i*子大小`，W、A、D 原样继承；仍部分相交的子叶子递归
  劈分。劈分后立刻 `ScanDirty()` 返回的叶子数恰等于继承 D=1 的子叶子数。
- **合并取或**：`Promote(vpn, size)`（size ∈ {8,64}）要求 vpn 按 size 对
  齐、对应槽指向一张表、表的 8 个槽全是 size/8 的叶子、pfn 连续且起始
  pfn 按 size 对齐、8 个 W 全同。合并后新叶子的 A（同理 D）为 8 个子叶
  子对应位的逻辑或，W 不变。劈分再合并不会恢复大页原来的 A/D——合并只
  看子叶子当前的位。
- 劈分与合并都不改变任何页的 W。

## 峰值配额校验

构造参数 P（1..10^6，不含根表）是非根表页数的上限，越界按配置非法整体
拒绝。记当前已用表页数为 U：

- `Map` 按路径上缺失的表数预检 `U+need <= P`。
- `Unmap` 先以写时复制方式在单次遍历中算出劈分需要新建的表页数 s，再按
  峰值校验 `U+s <= P`：**同一次操作随后才会回收的旧表不得抵扣**。校验
  通过才提交新结构，失败则旧结构原样保留。
- 任何时刻 `U <= P`，且 U 恰等于由叶子集合唯一推出的表数（见下）。

## 空表回收与表数推导

除根表外，一张表的所有槽都为空时必须立即回收，并向上级联（父表因此变
空也回收）。因此结构由叶子集合唯一决定：

- 每个 8 页对齐组内若含有 1 页叶子，则需要一张 L0 表；
- 每个 64 页组内若含有任何小于 64 页的叶子，则需要一张 L1 表；
- `U = |L1 集合| + |L0 集合|`。

实现中每张表维护子树聚合（表数、已映射页数），被区间完整覆盖的表或叶
子整体释放而不逐槽遍历，`Tables()`/`Mapped()` 均为 O(1)。

## 错误顺序

各操作只报第一个错误，被拒绝的操作不改变任何叶子、A/D 位、表、U 与
Epoch：

- `Map`：参数非法 → 未对齐 → 区域重叠 → 表页配额不足
- `Unmap`：参数非法 → 表页配额不足
- `Touch`：参数非法 → 未映射 → 写保护
- `Promote`：参数非法 → 未对齐 → 槽不是表 → 子槽不全是叶子 → pfn 不连续
  或起始 pfn 未对齐 → W 不一致

`Epoch` 只对成功改变结构的操作计数：成功的 `Map`、取消了至少 1 页的
`Unmap`、成功的 `Promote` 各加一；`Touch` 与 `ScanDirty` 不计。

## 复杂度计数器

非导出字段 `Mapper.examined` 记录上一次受约束操作考察的槽数（同包测试
可读）：

- `Translate`：至多 3 个槽（每层一个）。
- `Unmap`：只考察与区间相交的槽，任意区间不超过 40；被完整覆盖的表整体
  释放不逐槽遍历；满载映像（8 张 L1 + 64 张 L0，P=72）上
  `Unmap(0,512)` 不超过 8。
- `Promote`：合并校验只扫描候选表的 8 个槽（定位路径为常数级指针跳转）。

对应测试：`TestComplexityTranslate`、`TestComplexityUnmapFull`、
`TestComplexityUnmapBounded`、`TestComplexityPromote`。

## 本地验证

```bash
# 全部单元测试（含规格示例、错误分类、计数器、并发）
go test ./pagetable/

# 竞态检测
go test -race ./pagetable/

# 朴素模型对照：2000 组随机操作序列，逐操作打印输入/输出/判定依据
go test -run TestDifferentialRandom -v ./pagetable/
```

`model_test.go` 中的朴素模型按规格规则在有序叶子列表上逐步实现（表数由
叶子集合推出），对照测试逐步比较返回值、错误码、叶子集合、U、Mapped、
Epoch，并在每个序列结束时全量比对 512 项 Translate。
