租赁转租链与责任传递服务 — 设计说明（40 行以内）
1. 模块：errors(错误码固定次序) types(领域结构/操作/Snapshot) consent(同意簿)
   chain(树结构、级联、提升) billing(月度账单、欠费、清偿、追偿)
   world(深拷贝工作副本+时间结算) service(互斥入口/参数校验/提交) naivemodel(独立朴素模型)。
2. 时间：每月固定 30 天；月 m 账单日为 30m+payDay；账单日落在[start,end)内才计费，
   now >= 账单日+G 生成欠费（含恰等边界）。每次被接受操作先做时间结算（到期级联→计费）。
3. 拒绝不留痕：所有变更在深拷贝 world 上执行；参数非法最先判（在取锁后立即判，优先于时钟回退），
   其后依次为时钟回退、租约不存在、同意、期限、租金、深度、状态；任一失败丢弃副本。
4. 并发：单把 sync.Mutex 串行全部操作 ⇒ 结果等价于某串行序；同一租约不会出现两份有效下级，
   同一笔欠费不会被清偿两次（并发场景测试验证）。
5. 级联：沿“至多一个有效下级”的线性链下行；触发租约终止；已被房东独立承认且在切断日仍在租
   (Start<=day<End) 的下级提升为 depth=1 的新根（房东直租，期限租金不变），其下整体上提一级；
   未承认、未起租或已到期的下级一并在 day 终止（End 截到 day）。
6. 欠费：生成时冻结责任链 Chain=[债务租约..根]。任一层清偿后同笔欠费对其下各级视为已清偿，
   恰好生成一条等额追偿（债务承租人→清偿人）；超额、已清再付按非法/状态错误拒绝。
7. O(depth) 可验证性：arrearsByID 直接按 id 取欠费；责任人/可追偿方只看该欠费冻结的 Chain 与
   Payments，与系统租约总数无关；liability_test 用基准证明租约总数 10→1000 时耗时持平(~31ns)。
8. 同意：一次性同意按次租约 id 命名、成立即消费；概括性同意取发起时刻最新未撤回者；
   撤回只影响其后发起的转租，已成立租约不变。
9. 确定性/重放：租约与同意 id 由调用方给定，欠费 id 单调；到期事件、计费、子节点选择均按 id
   定序，禁止依赖 map 遍历顺序；相同操作序列产生完全相同的链、欠费与追偿。
10. 被放弃的方案：a) 事件溯源/后台定时器——时钟由 now 驱动，惰性结算即可重放且无需异步；
    b) 细粒度锁/CAS——规则校验跨越多租约，单锁更简单且天然可串行化；
    c) 清偿时实时回溯父链——改为在欠费生成时冻结链，保证查询不随全局规模增长。
11. 本地验证：go test -race ./...；go test -run TestRandomDifferential（40 条随机序列×400 步，
    每步打印输入/输出/判定依据并与朴素模型全量比对 Snapshot）；
    go test -bench BenchmarkLiableParty（O(depth) 证据）。
