# extendhash：可扩展哈希桶页索引

`extendhash` 包实现一个并发安全的可扩展哈希（extendible hashing）目录—桶页索引。
哈希函数通过 `Config.Hash` 注入，目录用哈希值的**低 `G` 位**（`G` = 全局深度）定位，
目录大小恒为 `2^G`；每个桶有局部深度 `L`。

## 结构不变量

任何一次对外可见的操作之后都满足：

1. `len(directory) == 2^G`。
2. 每个在目录中出现的桶恰被 `2^(G-L)` 个目录项引用。
3. 任一桶内键按其哈希低 `G` 位必路由回本桶（无错位键）。
4. 桶内键数 `<= BucketCap`，键全局唯一。

测试中的 `checkInvariants` 在每一步操作后校验以上全部条款，并用朴素 `map`
逐项交叉核对查找结果。

## 伙伴桶定义

局部深度为 `L` 的桶，其目录项构成一个连续区间，代表前缀是该区间首个目录下标。
伙伴桶的下标区间在第 `L-1` 位上取反，即

```
buddyIndex = representativeIndex XOR (1 << (L-1))
```

若该下标仍指向本桶，说明伙伴尚未被分裂出来（当前深度没有真正的伙伴）。

## 分裂与目录加倍

插入时目标桶已满：

- 若 `L < G`：直接分裂该桶——`L += 1`，新建一个局部深度相同的空桶，按哈希
  第 `L-1` 位把旧键分到两侧，并把指向本桶、且该位为 1 的目录项改指向新桶。
- 若 `L == G`：目录先**加倍**（每个旧目录项镜像成两个，所有桶引用数翻倍，桶不变），
  `G += 1`，然后再分裂。
- 分裂后新键仍落入已满的一侧时，对该侧继续分裂；一次插入可能连续触发多次
  加倍 + 分裂（低位相同的键堆积场景）。

每次分裂桶总数 +1，因此分裂前检查 `MaxBuckets`。

## 溢出与整体撤回

当目标桶已满且 `L == HashBits`（哈希位数上限），低位已全部用尽、无法再分离，
返回 `ErrOverflow`。此时本次插入可能已经完成了若干次加倍与分裂：实现先把整体
状态深拷贝保存（`saveState`），失败时通过 `restoreState` 整体回滚，计数器一并
还原。`MaxBuckets` 拒绝同理处理。

## 合并与目录收缩

删除键后，从所在桶开始尝试合并，且可连锁：

1. 桶与其伙伴桶**局部深度相同**，且键数之和 `<= BucketCap`，则合并：键并入本桶，
   `L -= 1`，指向伙伴的目录项全部改指回本桶，伙伴桶删除，`Merges++`。
2. 对合并后的桶继续尝试与其新伙伴合并（连锁合并）。
3. 连锁结束后，只要**所有**桶的局部深度都严格小于 `G`（等价于目录前半与后半
   逐项相同），目录即可**减半**，`G -= 1`，`Shrinks++`；可连续减半到 `G == 0`。

## 拒绝原因（可区分）

| 错误 | 触发条件 | 是否改变状态 |
| --- | --- | --- |
| `ErrDuplicateKey` | 插入已存在的键 | 否 |
| `ErrNotFound` | 查找 / 删除不存在的键 | 否 |
| `ErrOverflow` | 局部深度达到 `HashBits` 仍放不下 | 否（撤回已做分裂/加倍）|
| `ErrTooManyBuckets` | 分裂会使桶总数超过 `MaxBuckets` | 否（撤回）|

## 并发语义

`sync.RWMutex` 保护：查找 / 快照持读锁，插入 / 删除持写锁。因此读者要么看到
分裂 / 合并前的完整状态，要么看到完成后的完整状态，看不到中间态。
`Counters()` 对外报告累计的 `Splits / Merges / Doubles / Shrinks` 次数。
桶内条目按插入顺序保存在切片中，目录与桶编号分配确定，保证同一操作序列
重放得到逐项相同的快照。

## 本地验证

```bash
# 详细日志（打印每步输入、输出与判定依据）
go test -race -v ./extendhash/

# 全量测试 + 竞态检测
go test -race ./...

# 静态检查与格式
go vet ./...
gofmt -l .
```

测试覆盖：低位相同键堆积触发连续多次分裂、溢出撤回后目录与计数器不变、
桶数上限拒绝回滚、删除触发连锁合并与连续目录收缩、4000 步随机操作与朴素
映射逐项一致、同一序列双跑确定性一致，以及读写并发下的竞态检测。
