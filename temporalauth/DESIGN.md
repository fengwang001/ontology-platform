# temporalauth 设计说明

面向“带时间类属性”的对象，提供属性级（per-property）查看权限校验。权限条件
之一是“当前是否处于对象所属地区默认时区下的某个时间窗口之内”。系统必须在三种
时区（录入发生地时区、对象所属地区默认时区、查询者所在时区）可能各不相同、且
可能跨越夏令时切换或地区默认时区定义版本迁移的情况下，给出确定、稳定、不泄密
的判定。

代码位于 `temporalauth/`，无第三方依赖，仅用 Go 标准库。

## 1. 关键概念与数据模型

- `Instant`：绝对时刻，Unix 纪元起的 UTC 秒数。系统内部所有比较都在
  `Instant` 上进行，从根本上消除“拿不同时区的墙钟直接比较”的错误。
- `Civil`：不带时区语义的民用墙钟时间（年月日时分秒）。
- `ZoneRules`：确定性时区规则 = 基础偏移 + 一张按 UTC 时刻升序的偏移跃迁表
  （`Transition{At, OffsetAfter}`）。不依赖运行环境的 IANA/tzdata，相同输入
  在任何机器、任何时刻结果一致。
- `ZoneCatalog`：不可变的时区规则目录。
- `Region` / `RegionVersion{ValidFrom, ZoneID}`：地区默认时区定义的版本链，
  `ValidFrom` 严格升序。
- `ObjectType` / `ObjectTypeVersion{ValidFrom, Properties}`：对象类型版本链；
  属性在某版本可被标记 `Deprecated`。
- `TemporalRecord`：时间类属性记录，含录入绝对时刻、录入标注时区、墙钟取值，
  以及录入时一次性冻结的 `normalizedAt`（归一化绝对时刻）与 `basisVersion`
  （归一化所用地区版本下标）。
- `WindowRule{RegionID, Start, End}` 与 `WindowVersion{ValidFrom, Rule}`：
  以地区默认时区表述、带完整日期的窗口规则及其版本链。

## 2. 归一化基准：统一规则

### 2.1 三种时区的角色

| 时区来源 | 是否作为归一化基准 | 用途 |
| --- | --- | --- |
| 对象所属地区默认时区 | 是（唯一基准） | 窗口边界归一化；录入时冻结取值基准 |
| 属性录入标注时区 | 否 | 仅随记录留存，用于溯源展示 |
| 查询者所在时区 | 否 | 仅用于解读查询者提供的本地输入 |

因此无论请求由谁发起、属性原来标注了哪个时区，基准选择规则都相同。

### 2.2 历史记录使用“迁移前还是迁移后”的明确规定

规定：**以录入那一刻对象所属地区当时生效的默认时区版本为基准，并在录入时把
归一化结果（绝对时刻）与所用版本一起冻结。**

- 判定“当前是否在窗口内”时，窗口边界使用判定时刻该地区生效的默认时区版本。
- 历史取值的归一化结果在录入时即固定，后续地区默认时区迁移不会回溯重算。
- 所有地区迁移只能“追加新版本、从未来某个 `ValidFrom` 起生效”，禁止修改或
  删除历史版本（`AppendRegionVersion` 强制 `ValidFrom` 严格递增、禁止未知
  ZoneID）。

这条规定保证：同一条历史记录在任意请求时刻被反复判定，其归一化结论恒定，不随
当前时间推移而摇摆；同时地区未来版本的窗口判定也能使用当时正确的时区定义。

被放弃的方案：

- “始终用地区最新时区重算所有历史记录”：会让同一条历史记录的结论在地区每次
  迁移后翻转，违反稳定性要求。
- “用查询者时区重算”：同一记录对不同查询者给出不同基准，直接违反统一性。
- “可变 + 原地更新的地区定义”：无法重建历史判定，也难以做无锁一致快照。

## 3. 夏令时 gap / overlap 与窗口边界

窗口在归一化后是绝对时刻上的**半开区间 `[start, end)`**：`Start` 边界归入窗内，
`End` 边界归入窗外（`WithinWindow`：`t >= start && t < end`）。窗口用带日期的
`Civil` 表述，因此跨午夜只是“End 的日历日晚于 Start”，没有特殊逻辑。

`CivilToInstant` 对夏令时切换当天采用统一约定，整个流程没有“如果是切换日”的
特例分支：

- **gap（弹簧向前跳过的本地时间）**：该墙钟在本时区不存在，归一化到触发该 gap
  的跃迁点 `At`，结果唯一。
- **overlap（秋季回退的重复本地时间）**：同一墙钟对应两个绝对时刻，取偏移更大
  的更早瞬间。
- 普通时刻：唯一合法映射。

实现方式是纯机械的：枚举该时区出现过的所有偏移，对墙钟构造候选瞬间，保留能反向
映射回该墙钟的候选并取最早者；若无合法候选（gap），定位把该墙钟跳过的向前跃迁并
取其 `At`。`timezone_test.go` 对春/秋切换当天逐秒穷举验证这一约定。

## 4. 错误分类、优先级与不泄密

四类错误相互区分（`errors.go`），在一次请求同时满足多类条件时，按固定优先级只
报告最高一类，使外部观察结果与内部求值顺序无关：

1. `REGION_TIMEZONE_UNRESOLVED`（基准都无法确定，一切后续判定失去前提）
2. `WINDOW_RULE_INVALID`（基准可定后，规则必须先可用、先通过校验）
3. `VIEWER_MISSING`（需要查询者身份/时区时缺失）
4. `PROPERTY_DEPRECATED`（对象类型版本迁移导致属性在当前版本废弃）

权限拒绝统一为 `DENIED`。

对外的 `Decision` 在错误/拒绝时**只含稳定错误码**，不含记录值、时区 ID、窗口
边界位置等任何细节；允许时才返回记录。未知对象也映射为
`REGION_TIMEZONE_UNRESOLVED`，避免通过错误差异泄露对象存在性。全部细节（输入、
归一化基准、窗口边界、结论、朴素模型对照）只写入服务端 `AuditLog`。

## 5. 并发串行化

`Store` 采用 **不可变状态 + copy-on-write + 原子指针**：

- 所有数据收敛在单一 `state` 对象中；`state` 一旦发布即不可变。
- 写路径持有互斥锁，基于当前 `state` 克隆出一个新 `state`，在其上应用一次变更，
  推进单调序列号 `seq`，再通过 `atomic.Pointer[state]` 发布。
- 读路径（一次查看）只用一次原子加载得到某个 `state` 的 `Snapshot`，随后全程
  无锁读取。由于快照不可变，读不会与并发写竞争（`go test -race` 验证）。
- 一次查看的所有读取来自同一个 `state`，观察到单个一致版本；每个已提交写操作
    都有唯一且递增的 `seq`。因此任意并发操作集合等价于按某一全局 `seq` 顺序串行
  执行的结果（线性一致）。

被放弃的方案：

- “RWMutex + 快照里共享内部 map/切片，读时放锁”：`append` 可能复用底层数组，
    与放锁后的读取构成真实数据竞争（开发中曾被 `-race` 捕获），已弃用。
- 多对象细粒度锁：能提升吞吐但显著复杂化一致性论证；本需求优先“可证明的串行等价”。

## 6. 单次判定复杂度（不随历史版本数线性增长）

- 快照获取：O(1)（一次原子加载）。
- 地区/对象类型/窗口的生效版本解析：对版本链做二分，O(log n)。
- 窗口判定：常数次时间换算与比较。

因此一次查看的归一化与权限判定开销为 **O(log n)**，不随地区累计版本调整次数 n
线性增长。独立验证方式有两种：

1. 探针计数：生产路径统一走 `Snapshot.resolveRegionIndex`，每次二分比较都累加到
   `Store.regionProbes`（原子计数）。`TestRegionResolutionLogarithmic` 断言比较次数
   不超过 `ceil(log2(n+1))+1`，可独立复核。
2. 基准：`BenchmarkViewVsRegionVersions` 对比 100 与 10000 个版本。实测
   约 `190ns -> 381ns`（版本数扩大 100 倍，耗时约 2 倍），呈对数而非线性。

> 注意：与朴素参考模型的逐条对照（cross-check）本身刻意是 O(n)，仅用于测试/
> 灰度校验，可通过 `SetCrossCheck(false)` 关闭；复杂度度量时已关闭它与审计追加。

## 7. 审计与独立对照模型

- `AuditLog` 记录每次查看：请求输入、快照 `seq`、归一化基准（地区、版本、时区）、
  归一化取值、窗口边界、最终结论，以及与朴素模型的对照结果（`CrossCheck` /
  `CrossMatch`）。审计只追加、线程安全，不进入对外响应。
- `NaiveDecider` 是独立的朴素实现：版本链一律线性扫描、不使用任何二分/缓存/原子
  快照技巧，但遵循与生产路径完全相同的基准选择、gap/overlap、半开窗口与错误优先级
  约定。`TestRandomizedCrossCheck` 在大量随机操作序列下逐条比对两者结论必须一致。

## 9. 关键取舍汇总

- 时间内部统一为 UTC `Instant`，时区只在边界（录入、窗口表述、展示）出现。
- 历史基准“录入时冻结 + 迁移只向后追加”，换取历史结论的永久稳定与可重建性。
- 半开 `[start,end)` 与机械的 gap/overlap 规则，保证跨午夜/跨 DST 无特例。
- 错误用固定优先级单报，拒绝与错误只返回稳定码，细节仅入审计，杜绝侧信道泄密。
- copy-on-write 不可变状态换取 O(1) 一致快照与可证明的线性一致；写放大（每次写
  复制 map）在本配置型元数据规模下可接受。
- 生产快路径 O(log n) + 朴素 O(n) 参考模型双轨并行，用随机对照持续校验正确性。
