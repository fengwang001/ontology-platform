# 设计说明

1. 全部时间、流量、排队量用 `math/big.Rat`，容量/漂移为分段常数，两次事件间队列是线性函数，故只在“恰会碰到 0 或满载”的时刻跳转，无数值积分误差；多次切片推进逐字段一致。
2. 有效通行能力：先对每条路取 `capacity*(1-maxReduction)`（同路多事件取最大比例，绝不相加），再对“已回溢”路段的直接上游做最小不动点松弛（SPFA/Bellman-Ford 均可）；只有队列已满的路段才继续向上游传限制，环路在有限值格上必然终止，回到起点是无下降的空操作，不重复限制。
3. 回溢状态 `spill` 与队列分离：满载且仍会继续增长才置位；空队列立即解除；外部变更（登记/修改/解除）恰落在边界时刻时，按新容量联合裁决——已满但恢复后不再溢出，则回溢“不生效”，直接开始排空。
4. 等级：以“活动事件路段=1”和“仍在排空的回溢路段保留上次等级”为种子，只沿 spilling 边沿做多源 BFS，天然取所有下游路径最小等级；空队列解除时清除粘性等级。
5. 事件开始时刻也作为推进的内部时间点，穿越即重算容量；修改/解除只作用于操作时刻，历史轨迹不变，之后按新漂移演化。
6. 并发：单一互斥锁串行化全部方法，任何并发历史等价于某个串行顺序；确定性重放靠固定序列本身（map 遍历在测试中显式排序）。
7. 错误按固定优先级检查：参数非法 → 时钟回退 → 路段不存在 → 事件不存在 → 事件已解除 → 比例越界 →（建网时）到达超容量；拒绝在任何状态变更前返回，时钟不动。
8. 查询是对预计算状态的两次 map 读取，不扫描路网，成本与未受影响路段数量无关（基准测试 1 万条无关路段）；重算只发生在事件驱动的 `Advance` 与写操作内。
9. 被放弃方案：浮点/统一微步积分（有舍入误差、无法精确判定“恰好”时刻、性能差）；每查询实时全图迭代（违背查询复杂度要求）；按登记顺序处理同时刻事件（违反“消散次序由数值决定”与切片无关性）。
10. 朴素对照模型独立编写：固定有理微步（测试取 1，全部事件时刻均为其整数倍），步内对新发生的回溢按精确时刻切分；随机 40 个种子×61 个时刻全字段比对。
11. 本地验证：`go build ./...`、`go vet ./...`、`gofmt -l .`、`go test -race -count=1 ./...`、`go test -run TestRandomDifferential -v ./traffic/`（失败时打印每条操作输入/输出/判定依据）。
