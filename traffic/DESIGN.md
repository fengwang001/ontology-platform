# 设计说明：交通事件影响传播与排队回溢推演
1. 时间模型：事件驱动，而非逐格积分。每路段保存分段线性锚点
   `(anchorTime, q, rate, full)`，`q(t)=q+rate*(t-anchorTime)`，在 0/容量处钳制。
2. 结构事件只有两类：排队恰好到 0 或容量、事件开始/修改/解除。引擎总是跳到下一个
   最早的精确时刻处理，故一次推进与任意多次拆分推进逐字段相等（`TestSingleVs...`）。
3. 有效能力：先按“同路段多事件取最大削减”定基值，再对回溢约束（上游能力 ≤ 本路段
   能力）做最小不动点松弛；环路天然收敛，回到起点不会再压低，不会死循环。
4. “直接上游”定义为流入本路段起点节点的边（`incoming[from]`）；回溢只往上游传。
5. 等级：事件路段为 1，多源 BFS 仅沿 `full` 路段的上游边递增，多路径取最小。
6. 满队列后在仍积压时保持容量；解除事件使能力恢复后，同一锚点立即以负速率消散，
   但 `full` 标记保留到排队真正降到 0（此刻才解除上游限制）。
7. CRUD 校验严格按固定次序返回最先一类错误：参数非法→时钟回退→路段不存在→事件
   不存在→事件已解除→削减越界（到达超能力在 `BuildNetwork` 单独校验）。
8. 被拒绝操作在校验阶段即返回，不触碰时钟与状态。
9. 并发：每条公开方法持同一把锁，结果等价于某串行顺序；所有时刻单调，重放确定。
10. 查询 O(1)：一次 map 索引 + 数组读取，不枚举路段（5000 路段测试佐证），
    故开销不随未受影响路段数量增长。
11. 日志：`Logger` 记录每次操作输入/接受或拒绝/判定依据；默认丢弃，测试用内存收集。

## 关键取舍

- 选分段线性解析推演，放弃逐时刻步进：前者精确、与切分无关；后者有 O(dt) 误差。
- 回溢约束用朴素松弛求最小不动点（最多 O(n) 轮、每轮 O(边数)），放弃写成复杂闭包
  表达式；图小且只在结构事件时重算，简单且对环路稳健。
- 队列用车辆数、容量 = 长度/单车占长；不引入车辆个体，保持解析性。
- 朴素参照模型独立实现（自带松弛/BFS、小步长、半格吸附），只共享路网，不复用引擎算法。

## 被放弃的方案

- 离散时间主模型：翻转时刻被网格量化，无法满足“精确时刻 + 任意切分一致”。
- 用仿真车辆逐辆推进：无法解析复现任意时刻状态，且有随机性。
- 等级在事件触发时增量维护：多事件/解除顺序复杂，改为每次结构变化后重算 BFS。

## 本地验证

- `go test ./...` 覆盖 7 个规定场景、随机对照、不变量、重放确定与查询复杂度；
  `go test -race ./...` 做并发与竞态检测。
- 随机对照用固定种子、可复现；`-v` 打印每个操作的输入/输出/判定依据。
- 朴素与引擎在每点逐字段比队列（严格小容差）；仅当某路段在一个积分步内跨越 0/容量
  边界（结构翻转可能相差一步）时豁免该点的能力/等级，这是离散参照的固有误差。
