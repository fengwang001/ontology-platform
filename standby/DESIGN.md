# 候补席位系统设计说明

1. 模块划分：`types.go`（六态、三级优先、错误类别、快照）、`trie.go`（128 位定深二叉 Trie）、
   `system.go`（航班/系统运行态）、`settle.go`（兑现与过期结算）、`ops.go`（校验次序与全部操作）、
   `txn.go`（撤销日志）。
2. 有序集合：键 `(登记时刻, 条目 id)` 或 `(期限, 条目 id)` 拼成 128 位；深度恒为 128，
   故插入/删除/首个不小于 K/后继对集合规模均为常数。删除一律从根按键重定位，
   不缓存父指针——这是支持事务安全回滚的关键取舍（略增常数、绝不悬空）。
3. 兑现：三个优先桶各一个集合，游标从键 0 起顺序考察；被跳过的大条目从不离开集合，位置天然保留。
   本次只访问“被兑现 + 被跳过”的叶子，已结束条目早被移出，扫描不随历史条目总数增长。
4. 过期：pending 集合按 `(期限,id)` 排序；取最小期限，同刻全部收集后合并释放、只兑现一次，
   再处理下一时刻。兑现以释放时刻为界 `registered <= at`，两次过期之间登记的条目无法参与第一次。
5. 试探性结算与回滚：拒绝次序要求“重复登记/队列满”在结算之后判定，但被拒操作不得改状态。
   做法：先在 `txn` 上结算，拒绝则逆序撤销。每个状态跃迁是一个原子撤销闭包（捕获全部旧值），
   禁止把字段级写入与集合操作交错记录——这是开发中被差分测试抓出的主要教训。
6. 查询同样结算到当前时刻再撤销；任何时刻看到的都是结算完毕的状态，且不推进时钟。
7. 释放来源统一走 `fulfill`：取消/撤回/过期/容量上调。容量下调只改容量，允许负空余、不兑现。
8. 并发：单把全局互斥（容量为 1 的信号量），结果等价于某一串行顺序；放弃了每航班细粒度锁，
   因为全局时钟本身就是串行点，细粒度锁只增加证明复杂度而无吞吐收益。
9. 容量不变量：待确认人数以 `pendingN` 显式维护（O(1) 空余计算），任何串行位置
   `已确认 + 待确认 <= 容量`（容量下调后的负空余除外）。
10. 放弃的方案：堆/平衡树（对数级，不满足“不随队列长度增长”的严格读法）、惰性堆（过期扫描会
    触及历史条目）、链表（同刻/改等级需重排）。
11. 本地验证：`GOCACHE=/tmp/gocache go test -race ./...`；`-run TestDifferentialRandom` 为
    2000 组随机序列与独立朴素模型的全状态差分（逐步打印输入/输出/判定依据）；
    `-run TestPerfIndependence` 为 200/2000 规模常数性比对；`TestTrieSanity` 验证集合不变量。
