# floorcontrol 设计说明

在线会议室发言权控制服务。模块划分：

| 文件 | 职责 |
| --- | --- |
| `errors.go` | 拒绝原因的分类错误（彼此可用 `errors.Is` 区分） |
| `queue.go` | 举手队列：随机 treap，按下标定位/删除/名次查询 |
| `room.go` | 成员、角色、发言权、惰性到期、全部操作与锁 |
| `doc.go` | 包文档 |

## 关键取舍

### 1. 惰性到期的时间模型

房间只保存当前发言者与他的 `expireAt = grantedAt + S`，不挂任何定时器。
每个通过参数与时钟检查的操作都先调用 `advance(now)`：

```
while speaker != "" and expireAt <= now:
    at = expireAt
    speaker 失权
    if 队列非空:
        队首在 at 时刻获得发言权   # 注意：授予时刻是 at，不是 now
        expireAt = at + S
        continue                  # 可能立即再次到期，连续顺延
    else:
        停止
```

因此一次操作可能连续触发多轮到期与顺延，循环次数恰好等于“实际发生的
到期轮数”，与成员总数无关。手动 `Grant` 的授予时刻取该操作的 `now`；
到期顺延的授予时刻取**到期时刻**，这是“授予时刻取到期时刻”的唯一实现点。

参数非法或时钟回退在进入 `advance` 之前返回，不做任何处理；其后被拒绝的
操作（已关闭/无权限/状态不允许等）也已经完成了到期处理并把时钟推进到
`now`，符合规范“通过参数与时钟检查的操作，无论是否被接受都先做处理”。

### 2. 队列数据结构

需求要求 `Raise`、`Lower`/移出队列成员、`QueuePos` 都不得随队列长度线性。
采用以“单调递增票号”为键的随机 treap（`queue.go`），另维护
`map[user]*node`：

- 队首 = 中序最小，期望 O(log n)；
- 任意成员删除 = 两次 split + merge，期望 O(log n)；
- 名次 = 沿 parent 链累加左子树大小，期望 O(log n)；
- 成员是否在队 = map O(1)。

票号每次成功 `Raise` 自增，天然按进入次序；成员离开或被移出后票号不复用。

被放弃的方案：
- 双向链表 + 名次 map：删除是 O(1)，但一次授予/移出后所有后续名次都要
  重写，名次维护退化 O(n)。
- 位图/定长环：容量 Q 上限 500 虽可接受，但删除后名次仍需扫描或额外
  Fenwick 树；treap 在更大规模下依旧成立，且实现集中。
- 时间轮/堆：这里需要的是“严格按举手次序的 FIFO + 任意成员删除”，堆的
  键与次序语义不一致，且到期根本不需要队列结构参与。

### 3. 并发

`Room` 用一把 `sync.Mutex` 保护全部状态，锁即线性化点。所有读写都在锁内，
`Snapshot` 在锁内拷贝出不可变快照后释放。单锁在 Q ≤ 500 的规模下足够，
避免了多锁带来的移交/顺延交叉复杂度。

### 4. 主持人移交与关闭

`Leave` 先处理“本人占有的发言权/队列位置”（这会触发顺延），再删除成员，
最后仅当离开者是主持人时移交：协管员中最早加入者 → 其余成员中最早加入者
→ 无人则关闭。成员切片按加入次序保存，故“最早”就是首次命中。移交本身
不触碰发言权与队列。关闭后清空状态，所有调用返回 `ErrClosed`。

### 5. 静音

只有主持人可静音，且不能静音主持人（`Mute`/`Unmute` 对主持人目标都返回
`ErrIsHost`，保证两侧拒绝次序一致）。静音：

- 若目标正在发言：立即失权，队首在本操作的 `now` 顺延；
	- 若目标在队列：直接移出；
- 静音是持久状态，不会因为发言到期而解除；被静音期间 `Raise` 返回专门的
  `ErrRaisedWhileMuted`。

### 6. 拒绝次序

统一在 `begin` 中按规范顺序短路：
参数非法 → 时钟回退 → 房间已关闭 → 操作者不在室内 → 权限不足 →
目标不存在 → 状态不允许。各类状态错误用独立哨兵，调用方可精确区分
（重复举手 / 正在发言 / 被静音举手 / 队列满 等）。

## 本地验证

```bash
export GOCACHE=/tmp/gocache        # 若默认缓存目录只读
go test ./floorcontrol/... -count=1 -v   # 全部用例
go test -race ./floorcontrol/...         # 竞态检测
go test -bench BenchmarkQueueOps ./floorcontrol
go vet ./...
gofmt -l .
```

测试组成：

- `scenarios_test.go`：到期恰好相等/差一秒、一次多轮顺延、授予时刻取到期
  时刻、静音发言者与队列成员、主持人移交三个优先级、关闭后拒绝、`QueuePos`。
- `rejectorder_test.go`：拒绝次序中每一对相邻类别。
- `diff_test.go`：1500 组随机操作序列，生产实现与独立朴素模型
  （`naive_test.go`，切片队列、独立逻辑）逐操作比对错误、名次、完整状态；
  每条序列打印输入、两侧输出与判定依据，完整日志写入测试临时目录
  `differential.log`（路径在测试输出中给出），前 3 条序列额外打到测试日志。
- `concurrent_test.go`：并发提交经随机串行点线性化后与朴素模型对照；另有
  `-race` 压力测试验证结构不变量（发言者至多一人且不在队列、队列无重复）。
- `queue_bench_test.go`：在 n=2^10/2^14/2^18 下测量插入+删除与名次查询，
  规模扩大 256 倍时单次耗时仅微增，验证期望 O(log n)。
