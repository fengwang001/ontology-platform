# rta — 固定优先级响应时间分析

`package rta` 实现带**释放抖动 J** 与**阻塞项 B** 的固定优先级响应时间
分析（RTA），支持增量接纳任务（尽量保持已有优先级次序）与 Audsley
最优优先级分配回退。容量固定为 32 个任务，所有操作可并发调用。

## 响应时间公式与终止条件

优先级从高到低排列。对序中任务 i，设 H 为排在 i 之前的全部任务：

```
w = C_i + B_i + Σ_{j∈H} ceil((w + J_j) / T_j) · C_j
```

- 迭代自 `w₀ = C_i + B_i` 开始，下式每轮从 `C_i + B_i` 重新求和
  （不是在旧 w 上累加），取收敛到的最小不动点。
- **截止判定先于每轮求和**：对每个被检查的 w（含初值 w₀），一旦
  `w + J_i > D_i` 立即判定不可调度并停止，该轮不再做干扰求和。
- 可调度时响应时间 `R_i = w + J_i`。本任务自己的抖动只进截止判定与
  R，不进周期上取整；更高优先级任务的抖动 J_j 出现在 ceil 内的 w 上。
- 中间和使用饱和运算（上限 2^62）防溢出：饱和只意味着序列不可能收敛到
  合法值，随后被截止判定拒绝。
- 迭代单调上升，`next == w` 即最小不动点（下一轮必然相同）。

## Add：插入尝试与 Audsley 回退

`Add(t)`（拒绝时不改变任何状态）：

1. 从**最低**优先级位置（序末）向高位逐个尝试把新任务插入现序，
   已有任务的相对次序始终不变。
2. 每个插入位置只重算该位置及其之后任务的 R（之前任务的 hp 集合不
   变）。第一个使全员可调度的位置即被采纳，`reordered=false`。
3. 所有位置都失败时，对"现有任务 + 新任务"整体重跑 **Audsley**：
   - 自最低位起填；对未分配任务中的每个候选，令其余全部未分配任务为
     H 做可调度判定（只依赖 H 的集合，与 H 内部次序无关）；
   - 在可调度候选中取**编号字节序最小**者占该位，再填次低位；
   - 某位无任何可调度候选则整体失败，错误携带当时尚未分配的任务个数
     （含正在填的那一位）；
   - 成功则以新序替换旧序，`reordered=true`。

`Remove(id)` 仅删除该任务，其余相对次序不变，只重算排在被删任务之后
的任务（删任务不会增大任何干扰和，故必然仍可调度）。`Order()` 返回
高到低的编号切片；`Response(id)` 直接返回任务上缓存的 R，**不执行任何
不动点迭代**（由 `SumTerms()` 非导出计数器在测试中断言增量为 0）。

不变量：任何时刻序中每任务 `R_i ≤ D_i`；`Order()` 的任意前缀作为独立
任务集仍全员可调度；相同操作序列重放得到完全相同的序、R 与重排标记。

## 拒绝原因优先级

按以下顺序只报第一个（`*rta.Error` 的 `Reason` 字段）：

1. `ReasonInvalidParam`：编号空或超过 64 字节、C/T/D/J/B 越界
   （`1≤C≤1e9`、`1≤T≤1e9`、`1≤D≤T`、`0≤J≤1e9`、`0≤B≤1e9`），
   或 `Remove/Response` 的编号为空。
2. `ReasonDuplicate`：编号已存在。
3. `ReasonCapacityFull`：已有 32 个任务。
4. `ReasonUnschedulable`：插入尝试全部失败且 Audsley 也失败；
   `Pending` 为失败位上未分配任务数（含该位）。
5. `ReasonNotFound`：`Remove/Response` 的编号不存在。

## 本地验证

```bash
# 全量测试（含 2000 组随机操作序列对拍、竞态检测）
go test -race ./...
go test -v ./rta

# 只跑 2000 组随机对拍（日志打印输入、输出与判定依据）
go test ./rta -run TestRandomDifferential -v

go vet ./...
gofmt -l .
```

对拍内容（`rta/naive_test.go`）：独立实现的朴素参考模型按规则逐 1
递增 w（自 C+B 起，每个 w 检查截止与 `demand(w) ≤ w`）模拟 Add 的
逐位置插入与 Audsley 回退；n ≤ 6 时穷举全部排列，核对实现 Add 失败
当且仅当不存在可行全序，并验证成功序全员可调度、每个前缀独立可调度。
`TestExactTermCountPerStep` 断言每个被重算任务的每个不动点单步，求和
项数恰等于其前导任务个数；`TestResponseNoIteration` 断言
`Response/Order` 不增加求和计数。
