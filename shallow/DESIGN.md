# 浅克隆边界管理与对象可达性 — 设计说明

1. 模块拆分：`model.go`（对象模型与五类错误）、`remote.go`（远端接口，提交为原子拉取单位）、`reachability.go`（不可变状态 + 纯函数可达性 BFS）、`repo.go`（并发控制、引用、序号、回收）、`deepen.go`（按深度/时刻深化与去浅）；测试为 `shallow_test.go`、`modeldiff_test.go`、`bench_test.go`。
2. 关键取舍：仓库状态做成不可变快照 `repoState`，写操作 clone 后整体替换；`sync.RWMutex` 让深化/去浅/回收串行化、查询并发读，天然得到线性一致的串行等价，无需细粒度锁。
3. 可达性只遍历「引用子图、遇边界停止」，结果惰性缓存（任何写操作置 nil）；单点查询是 O(1) 哈希命中，不随本地对象总数增长（`TestReachabilityQueryConstantSize` 可验证）。
4. 浅边界是显式集合，其提交存在但父被视为不存在——即使父恰好本地持有：BFS 在边界节点返回，故 `TestBoundaryParentHeldLocally` 中持有的边界父不可达、可回收。
5. 按深度深化按层 BFS，每层提交整层到位后才计入深度；已持有最浅深度 ≥ 目标深度时直接零副作用成功（序号与拉取次数均不变）。
6. 按时刻深化用 DFS 且维护独立 enqueued 集合：节点 `CreatedAt < t` 时该节点不入视图、不展开，从而每条路径独立停止；边界按「视图内节点存在不在视图的父」显式计算。
7. 边界只能向远端推进：合并新边界时对旧边界做保护性并集——旧边界提交仍有父不在新视图则保留，杜绝「已持有提交变成边界外却缺父」。
8. 去浅拉取全部祖先，边界为空；此后深度/时刻深化由「无界深度」与空边界直接判定为零副作用成功。
9. 回收严格按题意：不可达内容对象一律删除（被任一可达提交引用即保留）；提交删除时额外维护「可达节点到边界的祖先闭包」，保证回收后状态仍满足父闭合；回收幂等，再回收为零。
10. 原子性：深化先写入暂存区 `deepenPlan`，远端逐提交原子返回其全部内容对象；任何缺失（`ErrRemoteMissing`）或中断（`ErrRemoteFetch`）都丢弃暂存区，边界/对象/引用/序号不变。
11. 错误次序由代码顺序固定：非法参数 → 引用不存在 → 远端缺失 → 拉取失败 → 本地状态非法；被拒操作不触碰任何状态与序号。
12. 并发回收与深化在同一互斥点串行：深化先于 GC 则对象可达受保护，后于 GC 则所有缺失提交按提交单位重新拉取，不可能出现「引用已复活但对象未回」。
13. 被放弃方案：细粒度引用计数锁（复杂且易错，放弃换 RWMutex+不可变状态）；引用计数判断 blob 可达性（共享对象与不可达提交场景会误删，放弃换直接可达集合）；把时刻边界复用深度边界公式（会把本地持有的停止节点误判为新边界，已改为遍历期显式记录）。
14. 性能：深化只从引用出发遍历，绝不扫描引用不可达的远端区域，`TestDeepenSkipsUnreachableRemote` 断言 5000 个旁支零拉取。
15. 本地验证：`go build ./...`、`go vet ./...`、`gofmt -l .`、`go test -race -count=1 ./shallow/`；60 组随机图 ×80 随机操作与独立朴素模型逐步比对，20 组并发风暴做不变量与串行重放校验。
