# reassign：分区副本重分配控制器

线程安全的分区副本重分配控制器。核心保证：**新副本追平前不移除旧副本**，
且任意时刻 `ISR ⊆ 副本列表`、`领导者 ∈ ISR（或无）`、进行中数不超过全局并发上限。

## 数据模型

- 节点（Node）：存活或宕机；`NodeUp` 只改存活标记，不自动加入任何 ISR。
- 分区（Partition）：
  - `Replicas`：有序副本列表；
  - `ISR`：同步副本集，始终是副本列表的子集，对外按副本列表次序返回；
  - `Leader`：ISR 成员或空（无领导者）。
- 创建分区时，初始 ISR 为所有存活的初始副本，领导者取 ISR 的首个成员。

## 重分配规则

### 开始（StartReassign，目标列表 T）

1. 进行期间副本列表 = 原列表后接 T 中的新增节点（按 T 次序出现）。
2. 若 T 与当前副本列表**成员完全相同仅次序不同**：开始即完成——副本列表直接
   改为 T 的次序，ISR 不变，**领导者不变**，不占用并发名额。
3. 其他合法目标：登记进行中，占用一个全局并发名额。

### 追平上报（CatchUp）

1. 存活、在副本列表中、但不在 ISR 的节点加入 ISR。
2. 分区当前无领导者时，**首个加入者成为领导者**。
3. 每次成功上报后检查：若 T 的所有成员都在 ISR，则自动完成：
   - 副本列表改为 T 的次序；
   - ISR 取与 T 的交集（按 T 次序）；
   - 现领导者仍在 T 的 ISR 中则不变；否则取 T 中第一个在 ISR 的成员（按 T 次序）；
   - 释放一个并发名额。

### 取消（Cancel）

- 副本列表恢复为原列表；
- ISR 取与原列表的交集（宕机/未追平的新增节点被剔除）；
- 现领导者仍在该 ISR 中则不变，否则取原列表中第一个在 ISR 的成员，仍无则无领导者；
- 释放一个并发名额。

### 节点宕机 / 恢复

- `NodeDown(n)`：节点标记宕机；从所有分区的 ISR 移除 n；若 n 是某分区领导者，
  该分区改选**副本列表中第一个仍在 ISR** 的成员，无则无领导者。
  宕机不改变副本列表，也不自动完成或取消进行中的重分配（可稍后靠追平完成或取消）。
- `NodeUp(n)`：仅标记存活；必须再次 CatchUp 才会重新进入 ISR。

## 拒绝原因与错误次序

被拒绝的操作不改变任何状态，返回 `*ReassignError`，其 `Reason` 取值见下表，
各操作严格按所列次序判定，只报第一个：

| 操作 | 判定次序 |
| --- | --- |
| 开始 | `partition_not_found` → `already_running` → `empty_target` → `duplicate_replica` → `unknown_node` → `node_down` → `target_unchanged` → `concurrency_limit` |
| 追平 | `partition_not_found` → `node_not_replica` → `node_down` → `already_in_isr` |
| 取消 | `partition_not_found` → `not_running` |

## 并发语义

控制器内部用单一互斥锁串行化全部状态变更，因此并发调用的效果等价于这些操作
按某个串行顺序执行；相同的事件序列产生完全相同的最终状态。

每次操作都通过 `log.Logger` 打印**输入、输出（分区快照）与判定依据**（拒绝原因、
自动完成依据、领导者选取依据）。用 `NewWithLogger(max, w)` 可自定义输出，
传 `io.Discard` 关闭日志。

## 本地验证

```bash
# 单元测试（含竞态检测）
go test -race -v ./reassign

# 全量测试
go test ./...

# 格式与静态检查
gofmt -l .
go vet ./...
```

测试覆盖：追平前不移除旧副本、目标不含现领导者时的选举、仅调整次序时领导者不变、
新增节点宕机后取消回滚、领导者宕机与完成交错、并发上限拒绝、各操作错误次序、
无领导者时首个追平者当选，以及并发交错下的不变量检查。
