# 临床检验室内质控失控判定与报告拦截系统 — 设计说明

包 `qc` 实现检验项目（仪器，项目）粒度的室内质控：五条失控规则判定、
失控后报告暂停与追溯复核、恢复条件与质控有效期判定。全部数值为整数，
时间为 `0..1e9` 的整数秒。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `errors.go` | 七种可区分错误，检查顺序即优先级 |
| `types.go` | 规则编号、运行结论、项目/报告状态等公共类型 |
| `project.go` | 项目内部状态：水平参数、游程计数、可标记报告链表 |
| `rules.go` | 纯判定引擎：五条规则的 O(1) 求值与游程推进 |
| `system.go` | 系统门面：参数校验、时钟、状态机、报告拦截与追溯 |
| `model_test.go` | 独立朴素模型（保存全量历史、按定义重算），仅用于对照 |
| `system_test.go` | 确定性单元测试（边界、状态机、错误优先级） |
| `fuzz_test.go` | ≥1500 组随机序列与朴素模型逐步对照，逐步日志 |
| `bench_test.go` | 两档规模的复杂度对照（测试 + 基准） |

## 关键取舍

### 1. 游程计数代替历史序列（判定 O(1)）

规则二/四/五都是“末尾连续 k 点同侧且超过 k′ 倍标准差”的游程判定。
每个水平只保存三个计数（同侧超 2σ、同侧超 1σ、同侧）与上一偏离量，
每次运行先更新计数再比较阈值（≥2 / ≥4 / ≥10）。偏离量为零不属于任何
一侧，三个计数同时清零；异侧同理清零重计。这与“连续”的定义逐点等价：
连续段在遇到零点或异侧点时中断，计数恰好记录当前未中断段的长度。

被放弃的方案：保存全部偏离量、每次判定回扫。实现更直白，但单次判定
开销随历史运行数增长，不满足复杂度要求；且游程计数语义已被随机对照
测试（朴素模型按定义回扫）大规模验证等价。

### 2. 可标记报告链表（追溯开销只与待标记数相关）

追溯区间是（最近一次非失控运行时刻， 本次失控时刻]。关键观察：
**出具时刻不晚于当前最近一次非失控运行时刻的报告，未来永不可被标记**
（区间起点只增不减）。因此每个项目维护一条“仍可被标记”的报告链表：

- 出具时，若已有非失控运行且 `now <= lastNonRejTime`，直接不入链；
- 每次非失控运行清空链表（链上报告全部失去被标记资格）；
- 失控时顺序扫描链表并标记，随后清空。

由不变式，失控时链上节点**恰好**就是待标记报告集合（从无非失控运行时
链表从未被清空，即全部已出具报告），扫描开销与历史报告总数无关。

被放弃的方案：

- 失控时扫描项目全部报告并按时间过滤：开销随历史报告总数增长，违规；
- 按出具时间维护有序索引（平衡树/跳表）：能达到同样的渐近复杂度，
  但单调时钟下链表已足够，索引只增加常数与出错面；
- 出具时记录“区间起点指针”、失控时从起点扫描：起点指针在非失控运行
  后失效，失控时的跳过扫描仍会触及全部历史报告（本仓库第一版即此
  方案，`TestScalingCheck` 以 20 倍比值将其暴露，随后重写为现方案）。

### 3. 单互斥锁串行化

时钟与报告单号分配是全局状态，项目级细粒度锁仍需全局协调点。
采用一把 `sync.Mutex`：所有公开操作互斥执行，天然线性化，
并发调用等价于按加锁顺序的串行执行；判定逻辑无随机、无 map 迭代
副作用，相同操作序列重放结果逐位一致。被放弃的方案：每项目锁 +
原子时钟，收益有限而正确性论证成本高。

### 4. 时钟与错误优先级

每个带 `now` 的操作先验参数（含 `0 <= now <= 1e9`），再验时钟单调性，
通过后才按操作类型检查对象存在性与业务条件，顺序固定为：
参数非法 → 时钟回退 → 对象不存在 → 项目失控 → 从未质控 → 质控过期 →
状态不符。只有全部检查通过的操作才推进 `lastNow` 并改变状态；
任何被拒绝的操作不产生任何副作用（不推进时钟、不留报告记录、
不消耗报告单号）。

### 5. 其他语义决定（题面未明确处）

- 重复登记同一（仪器，项目）：视为重新登记，参数与全部运行/报告关联
  状态重置；已出具报告本身保留在系统中。
- “从无非失控运行则标记全部已出具报告”：经公开 API 不可达（出具要求
  已有运行且项目失控前必存在非失控运行），仍按规范实现，并以白盒
  测试直接构造该状态覆盖。
- 失控状态下的失控运行照常判定、记录并返回触发规则，仅不改变项目
  状态、不重复追溯。

## 本地验证方法

```bash
go test ./qc/ -race -v          # 全部单元测试 + 1500 组随机对照（逐步日志）
QC_FUZZ_SEQS=30000 go test ./qc/ -run TestModelComparison   # 放大对照规模
go test ./qc/ -run TestScalingCheck -v   # 两档规模复杂度对照（含断言）
go test ./qc/ -bench .          # 判定/追溯基准，10K 与 200K 两档
gofmt -l . && go vet ./...
```

对照测试打印每步输入、输出与判定依据（触发规则、结论、两水平偏离量），
并统计五条规则、警告、失控、追溯、复核、校准的覆盖次数，任一为零即失败。
`TestScalingCheck` 在 1 万与 20 万两档历史规模下测量单次判定与单次追溯
耗时，判定比值约 1.0、追溯比值约 1.5（阈值分别为 3 与 5），
若实现退化为随历史总量增长（比值应接近 20）则测试失败。
