# 只追加日志键值引擎 —— 设计说明

包路径：`ontology/kvlog`（Go 1.26，无第三方依赖）。

本引擎实现一个按段组织的只追加日志键值存储，重点在**启动恢复**、
**提示信息（hint）**、**读取自愈**与**段合并的崩溃原子性**。

## 1. 模块划分

| 文件 | 职责 |
| --- | --- |
| `record.go` | 记录二进制格式、CRC32C 校验、段字节扫描（区分完整/损坏/撕裂尾部） |
| `hint.go` | hint 文件的编码/解码与自带校验；hint 不含值 |
| `segment.go` | 磁盘文件命名规则、目录列举、原子写（临时文件 + rename） |
| `keydir.go` | 内存键目录：每键仅保留最大写序号的定位项 |
| `engine.go` | 引擎结构、配置、状态计数（撕裂字节数、自愈次数、读字节数） |
| `write.go` | Put/Delete、追加、活动段超限封口与滚动、封口时生成 hint |
| `recovery.go` | 打开恢复：合并残留清理、hint 采纳/回退、全段扫描、撕裂截断、seq 续号 |
| `read.go` | Get：按定位项直读、目录失真检测、整段重建后重试一次 |
| `merge.go` | 多段合并、墓碑保留/丢弃判定、崩溃提交协议、恢复时清理 |
| `errors.go` | 可区分错误类型与“只报次序最靠前一类”的约定 |

模块协作方向是单向的：`engine` 聚合 `keydir` 与若干 `segment`；
`recovery` 与 `merge` 是建立在 `record`/`hint`/`segment` 原语上的两个
平级服务；`read` 只依赖 `record` 校验与 `keydir`。

## 2. 磁盘格式

### 2.1 数据段 `NNNNNNNN.log`

每条记录（小端序）：

```
CRC32C(4) | seq(8) | klen(4) | vlen(4) | flags(1) | key | value
```

- CRC 覆盖从 `seq` 到记录末尾的全部字节（Castagnoli 表）。
- `flags=1` 表示删除标记（tombstone），此时 `vlen=0`。
- `seq` 全局唯一、存储内单调递增，从 1 开始；恢复后从最大 seq+1 续号。
- key 非空。

### 2.2 辅助文件

- `NNNNNNNN.sealed`：零字节封口标记。存在即封口；不存在即活动段。
- `NNNNNNNN.hint`：封口段可选提示，含段号、段有效字节数、每键最新记录的
  （seq、offset、length、tomb、key），以及整文件 CRC。**不含 value**。
- `NNNNNNNN.merge`：合并输出段的替代清单（空格分隔的段号）。

## 3. 内存键目录

`keydir[ key ] = { segment, offset, length, seq, tomb }`，每键只留 seq
最大者。因此读取结果三态明确可分：

- 目录无项：**从未出现（missing）**；
- 目录项 `tomb=true`：**已删除（deleted）**；
- 否则：**存在（present）**，按定位项读出值。

已删除与从未出现在墓碑被合并清除之前始终可区分（墓碑自身就是目录项）。

## 4. 恢复规则（确定性）

恢复结果是磁盘文件的**确定性函数**，不依赖任何易失状态：

1. 先处理合并残留（见第 7 节），再重新列目录。
2. 段号升序处理。**已封口段**：
   - hint 存在、其 CRC 正确、段号匹配、声明有效字节数 == 段文件实际大小、
     定位区间合法时，直接采纳 hint 建立目录，**不读取日志数据**；
   - 否则作废 hint，全段扫描，扫描结果为权威。
   - 封口段任何记录（含末条）头不完整/越界/CRC 失败即**段损坏**，
     报告段号与首个损坏偏移，恢复整体失败，**不产生部分状态**
     （失败前不改写任何封口段，也不安装任何目录供外部观察）。
3. **活动段**唯一；扫描时允许撕裂尾部：末条头不完整、声明长度越过段末、
   或恰为末条且 CRC 失败，都视为撕裂——丢弃该记录并把段截断到最后一条
   完整记录之后，丢弃字节数可经 `TornBytes()` 查询，不属于错误。
   活动段任何其他位置的失败仍是段损坏。
4. 段内记录 seq 必须严格递增，否则报段损坏（在该段首个违例偏移）。
   seq 的**跨段**全局序不由恢复推断，最终目录统一按“seq 最大者胜”归并，
   因此前段损坏不会被误报到后段（保证只报首个损坏位置）。

### 撕裂尾部 vs 中段损坏为何可分

扫描器逐条消费：只有“当前记录恰好位于段尾”且无法完整验证时才归类为
torn tail；一旦某条记录之后还有字节却验证失败，一定是 corrupt。
`allowTornTail` 仅对活动段开启。

## 5. 读取与目录失真自愈

`Get` 只打开定位项所在段、`ReadAt` 定位项长度的字节（O(1)，不随总键数、
总段数增长），校验 CRC 后比对**键**与 **seq**：

- CRC/结构失败：**段损坏**（hint 采纳段的惰性校验也走这里）；
- 键或 seq 与目录登记不一致：**目录失真**（`KindKeyDirDistorted`）。

遇到目录失真：升级写锁，**全段重扫**并整体替换该段在目录中的全部条目，
记一次自愈（`SelfHeals()`），随后重试一次：

- 重试成功：返回正确结果；
- 重扫发现字节损坏：报**段损坏**。

因此“目录失真（可自愈）”与“段损坏（不可自愈）”是两个不同错误类型。

## 6. 合并

`Merge(ids)` 合并调用方指定的若干**已封口**段（可不连续），活动段不可合并。

1. 读锁下规划：逐段扫描校验，求被合并集合内每键 seq 最大记录（`newest`）。
2. 扫描所有**集合外**存活段：对每个 `newest` 为墓碑的键，判断集合外是否
   存在 seq 更小的记录。墓碑仅当**不存在**这种旧记录时才可丢弃，否则必须
   保留——防止集合外旧值在墓碑消失后复活。
3. 输出按 seq 升序重写成一个新封口段，并生成其 hint 与 `.merge` 清单。
4. 写阶段**不持有全局锁**，并发读写照常进行；提交阶段在写锁下：
   先移除被替代段的目录项，再安装输出项，且只有当输出记录 seq 仍大于
   目录当前项时才覆盖（避免合并规划期间的并发新写被旧数据顶掉）。
5. 封口标记落盘后才删除被替代段文件。

合并纯做物理归并，合并前后任意键的逻辑读取结果相同。

## 7. 合并的崩溃原子性

提交顺序（每步 fsync，父目录也 sync）：

```
写临时输出 -> rename 为 N.log -> 写 N.merge -> 写 N.hint -> 写 N.sealed
```

`N.sealed` 是唯一的“已提交”标志。恢复时：

- 输出段**已封口**且扫描完好且与替代段并存：认定合并已提交，删除所有
  被替代段；
- 输出段**未封口**（崩溃发生在写数据/rename/清单/hint 期间任一点）或
  封口输出自身撕裂/损坏：整体丢弃输出段及其全部附属文件，保留旧段，
  如同合并从未发生。

因为被替代段只在封口标记之后才删除，“输出未封口 + 旧段存在”与
“输出已封口 + 旧段并存”两种状态都可被无歧义恢复。

## 8. 错误次序

错误类型常量按优先级升序：参数非法 < 段损坏 < 目录失真 < 段不存在 <
活动段不可合并。函数在参数校验阶段先拦截非法参数；恢复/读取按上述规则
返回最先出现的具体类型，错误结构携带段号与偏移，便于精确定位。

## 9. 复杂度与可验证证明

- **有效 hint 恢复一个封口段**：仅读 hint 文件，其大小只随段内**不同键数**
  增长，完全不打开 `.log`。`TestHintRecoveryCostIsDistinctKeys` 用 2000 条
  记录、8 个键、逾 10 万字节的段证明：采纳 hint 时引擎的“段数据读字节数”
  计数器为 0；删除 hint 后同一段恢复读取字节数 ≥ 段大小，形成对照。
- **一次 Get**：从哈希表取定位项（O(1)），随后仅 `ReadAt` 该记录长度。
  `TestGetCostIsConstant` 在 20 键与 400 键（多段）两种规模下断言一次 Get
  新增读取字节数完全相等，证明其不随总键数/总段数增长。

## 10. 并发

所有公开操作在引擎 `sync.RWMutex` 下串行化目录变更；Get 持读锁、Put/
Delete/合并提交持写锁，合并的重写阶段不持锁。结果等价于某一串行顺序。
测试用 `-race` 覆盖并发写/读/合并。段数据读字节计数器使用原子操作，
避免在读锁路径引入写竞争。

## 11. 确定性与重放

- 记录、hint、输出段均按确定的键/序号顺序编码（hint 条目按 key 排序，
  合并输出按 seq 排序）；段号与 seq 从恢复结果单调续发。
- `TestDeterministicReplay` 把同一操作计划在两个独立目录重放，断言全部
  文件逐字节相同。
- 崩溃点通过子进程 + `os.Exit(42)` 模拟，逐点验证恢复结果。

## 12. 关键取舍与被放弃的方案

- **放弃跨段严格递增校验**：曾要求段间 seq 严格递增，但这会把前段损坏
  “归因”到后段，违反“报首个损坏位置”。改为段内严格递增、目录按 seq
  最大值归并。
- **放弃在恢复时做任何跨文件引用检查**：合并清单只用于清理，不用于推导
  键归属，保证恢复只依赖单文件内容、可独立判定。
- **墓碑丢弃采用“集合外是否存在更旧记录”的保守判定**，而不是“键是否仅在
  被合并集合出现”。后者在非连续集合、链式合并下会误删墓碑导致旧值复活。
- **活动段以 O_APPEND 重开**：恢复截断后必须以追加模式打开，否则重开后
  的写入会覆盖段头（该缺陷由随机差分测试首次捕获并回归保护）。
- **读取校验为惰性**：采纳 hint 的封口段不在恢复时读数据，损坏在首次访问
  对应记录时报段损坏——这是满足“hint 恢复 O(不同键数)”的必要取舍。
- **合并重写不持锁**：为保证合并不阻塞读写；代价是提交时需要二次比对 seq
  以防并发新写被覆盖。

## 13. 本地验证方法

```bash
# 需 Go 1.26+
go test ./...
go test -race ./kvlog/
go test -v -run 'TestActiveTruncationEveryByte' ./kvlog/   # 逐字节截断
go test -v -run 'TestSealedBitFlipEveryPosition' ./kvlog/  # 封口段逐位翻转
go test -v -run 'TestHintFieldTampering' ./kvlog/          # hint 逐位篡改
go test -v -run 'TestMergeCrashPoints' ./kvlog/            # 合并各崩溃点
go test -v -run 'TestRandomOpsAgainstNaiveModel' ./kvlog/  # 朴素模型随机对照
go vet ./... && gofmt -l .
```

随机对照测试的每个随机种子都会通过 `Logger` 打印每条操作的输入、输出与
判定依据（`ENGINE: ...`）；`seed=1` 的完整轨迹落盘为该用例临时目录下的
`trace.log`。
