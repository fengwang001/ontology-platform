# costalloc — 逐级下推的服务部门成本分摊账本

`costalloc` 在每个结账期把服务部门的成本按**动态重算的次序**逐级分摊给尚未下推的部门，
并用跨期累计分摊额 `H` 决定余数分的归属，使下推次序、各部门所得与完全成本可精确复现。

## 构造与编号

- `New(K, P)`：`K` 个服务部门（编号 `0..K-1`）与 `P` 个生产部门（编号 `K..K+P-1`），
  `1 <= K, P <= 8`，`N = K+P`。
- `SetUsage(s, r, u)`：服务部门 `s` 向部门 `r` 提供服务量 `u`（`0 <= u <= 10^6`，
  `r != s`），覆盖旧值，初值全 0，**跨期保留**。
- 每个部门 `r` 维护累计收到的分摊额 `H_r`（初值 0，仅在 `Close` 成功时增加）。
- `Close(ds, dp)`：`ds` 为 `K` 个服务部门直接成本、`dp` 为 `P` 个生产部门直接成本
  （单位分，`0 <= 成本 <= 10^13`）。

## 下推次序：比例定义与逐步重算

`Close` 内分 `K` 步。令 `U` 为尚未下推的服务部门集合。对每个 `s ∈ U`：

- `b_s`：`u[s][r]` 对「除 `s` 自身与**已下推**服务部门之外的所有部门 `r`」求和；
- `a_s`：上述求和中 `r ∈ U` 的部分。

每步选出 `a_s / b_s` 最大者下推：

- `b_s = 0` 视为比例最小；
- 比较用整数交叉相乘（`a_s*b_t` 与 `a_t*b_s`），相等取编号小者；
- **每一步都按当时的 `U` 与已下推集合重算**，不沿用上一步的值——分母会排除已下推部门，
  因此次序可能随下推进展反转。

## 接收者与份额公式

被选中部门 `s` 的待摊总额 `T_s = ds[s] + 本期此前各步分给 s 的份额`。

- 接收者：`u[s][r] > 0` 且 `r` 既不是 `s` 也不是已下推服务部门的全部部门；
- `r` 分得 `floor(T_s * u[s][r] / b_s)`，乘积可达 `8×10^19`，实现用 128 位中间运算
  （`math/bits.Mul64` + `Div64`）；
- 余数 `m = T_s − 各份额之和`（`0 <= m < 接收者数`）：把接收者按
  **(H_r 升序, 编号升序)** 排序，前 `m` 个各加 1 分。`H_r` 取**本步开始时**的值，
  已含本期此前各步分给 `r` 的份额；每步结束立即把本步所得计入 `H`；
- `T_s = 0` 时该步无分摊，视为已下推；`T_s > 0` 且无接收者（`b_s = 0`）时整期 `Close` 被拒绝。

`K` 步结束后，生产部门 `r` 的完全成本为 `dp` 对应值加上本期收到的全部份额；
每期生产部门完全成本之和恰等于 `ds` 与 `dp` 之和。

## 拒绝语义

1. 参数非法（`SetUsage` 的 `s/r/u` 越界、`Close` 的数组长度或成本越界）——`ErrInvalidParam`；
2. 无接收者（某步 `T_s > 0` 而 `b_s = 0`）——`ErrNoReceiver`。

两类错误可区分，且按上述顺序只报第一个。`Close` 在工作副本上推演，全部成功后才提交 `H`，
因此被拒绝的操作不改变服务量与 `H`，也不计入结账期数。

## 并发与确定性

所有操作与查询（`SetUsage` / `Close` / `Snapshot` / `Periods`）由互斥锁串行化，
并发调用等价于某个串行顺序。任何时刻 `H_r >= 0` 且等于该部门历史上全部成功 `Close`
中所得份额之和。返回的清单与 `H` 快照均为新分配的切片，不与调用方持有的切片互为别名；
相同操作序列重放得到完全相同的结果。
