# 租赁押金争议处理服务 — 设计说明

## 模块划分（8 个 .go 文件）
- `errors.go`：固定错误码与哨兵错误，保证"只报第一个错误"的统一次序。
- `types.go`：`Category`/`Config`/`Deduction`/`RefundRecord`/`Snapshot`/`Service` 对外类型。
- `lease.go`：单租约内部状态、资金桶、一次性受偿固化（`finalize`）与违约金公式。
- `service.go`：对外操作（建租约/退房/申报/撤销/争议/裁定/退还/快照），单一互斥锁。
- `deposit_test.go`：边界与业务规则用例。
- `naive_test.go`：独立朴素模型，每次重算受偿（O(n log n) 排序）。
- `differential_test.go`：随机操作序列双模型对照（逐步打印输入/输出/判定）+ 并发测试。
- `bench_test.go`：争议+裁定单次开销基准。

## 关键取舍
1. 资金恒为五元桶守恒：`押金 = 已退 + 已归属房东 + 冻结 + 待退(awaiting) + 未处置(pending)`。
   `awaiting` 单列，避免"已确定该退但未退"被误算进 pending。
2. 受偿在申报期结束后的**第一个被接受的变更操作**一次性固化（`finalize`，每租约仅一次）；
   固化按 类别→申报次序 顺序分配，每条扣项的 `Satisfied` 此后永不变。
3. 争议/裁定是 O(1)/条：只在 landlord/frozen/awaiting 三个整数桶间搬移该条的 `Satisfied`，
   不扫描、不重算其他扣项。裁定高于冻结额的部分只进应收，绝不回押金。
4. 每次裁定释放金额生成独立"退款批次"，截止日 = 裁定日+C；基础批次截止日 = 申报期结束+C。
   退还必须一次性付清所有未付批次；部分退/零退一律拒绝。
5. 违约金按批次独立计息：`金额 × 日费率 × max(0, 退还日-1-截止日)`，恰在截止日退为 0 天；
   冻结期间不计息。费率用整数分子/分母，结果以 `big.Rat` 精确表示。
6. `Snapshot` 是纯查询：不推进时钟、**不触发固化**；申报期后未发生变更操作时，整笔押金仍记 pending。
7. 并发：服务级单锁串行化所有操作，天然等价某串行序，杜绝同一笔金额被退两次。

## 被放弃的方案
- 每条扣项动态重算受偿：裁定会波及后续扣项，违反"不得改变其他扣项"，放弃。
- 用树状数组/前缀和做 O(log n) 争议：实现复杂；一次性固化 + O(1) 桶搬运已满足"开销不随总数增长"。
- 申报期内 Snapshot 就固化：会让纯查询产生副作用、并把之后合法申报漏掉，放弃。
- 违约金浮点累计：有舍入误差，改用 `big.Rat`。

## 本地验证
```bash
go test -race ./...                      # 全部用例 + 竞态
go test -run TestDifferentialRandom -v   # 随机对照，逐步打印
go test -run NONE -bench BenchmarkDisputeAdjudicate -benchtime=10000x ./deposit/
go vet ./... && gofmt -l .
```
基准在 1 万与 10 万扣项下分别约 135ns/175ns 每条（争议+裁定），不随总数增长。
