# 租赁押金退还与扣减争议处理服务 — 设计说明

1. 单一互斥锁串行化全部公共操作，故并发等价于某串行顺序，时钟只在操作被接受后推进，拒绝不留痕。
2. 时间轴：退房日 d0；申报期截止 d0+A（当天可）；争议期截止 d0+A+B；首笔退款时限起算 d0+A。
3. 受偿在申报期结束时只计算一次：按 (类别, 申报序号) 稳定排序后顺序扣减，写入每条扣项 `Paid`。
4. 关键取舍：`Paid` 一经锁定不可变。撤销只允许在申报期内，故截止后无需再改；争议不影响他人；
   裁定只调整本扣项，超出冻结额只入应收、不追加押金。因此争议/裁定重算仅读自身 `Paid`，为 O(1)。
5. O(1) 的可验证性：`Dispute`/`Adjudicate` 函数体内无任何随扣项总数增长的循环或 map 遍历；
   唯一 O(n) 排序在 `allocate` 中且全程只执行一次（`allocated` 幂等门）。测试另做规模计时旁证。
6. 押金四桶守恒：已退 `Refunded` + 已归属 `Vested` + 冻结 `Frozen` + 尚未处置 `Pending` = 押金。
   `Pending` 含未归属受偿额与未退 tranche 本金；`Refundable` 是其中“当前可退”的子视图，不重复入账。
7. 未争议扣项的受偿额在争议期结束后惰性归属（`matureVested`），不引入额外事件。
8. 应退本金分 tranche：起始 tranche=押金减全部受偿额；每笔裁定释放另立 tranche，起算日为裁定日。
9. 裁定：vest=min(冻结, 裁定额) 归属房东，release=冻结-vest 退租户；应收=裁定额-vest。
10. 退款必须一次性结清全部未退 tranche，可退为零则拒绝；锁内完成，杜绝并发双退。
11. 违约金按 tranche 独立计算：免责区间 [start, start+C]，逾期天数 now-start-C-1（算到退还日前一日），
    每日 rateNum/rateDen，整数向下取整；冻结期间该笔不存在故不计，释放后以裁定日重新起算。
12. 错误固定次序（只报第一个）：参数非法 > 时钟回退 > 租约不存在/未退房 > 逾期 > 状态非法 > 金额越界。
13. 应收 `Receivable` 在押金之外，不参与守恒；违约金在押金之外由房东另行承担。
14. 被放弃方案：每次争议/裁定后全量重排受偿——违反“不得改变他人受偿”且非 O(1)；
    主动定时任务归属/退款——改为惰性结算，避免后台状态与回放不确定性；浮点违约金——改整数比例可回放。
15. 确定性：全部状态为整数、无 map 遍历参与决策（map 仅按 ID 查单条），相同序列重放结果一致。
16. 本地验证：`go test -race -count=1 ./...`；边界用例见 `service_test.go`；
    `TestRandomDifferential` 用 60 组随机种子驱动真实服务与独立朴素模型，逐步对账，
    logger 打印每步输入、输出与判定依据，失败时转储完整日志。
