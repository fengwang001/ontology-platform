# 单品种限价撮合引擎设计说明

支持普通（全部可见）、冰山（分批显示）、隐藏（不显示）三类委托的单品种限价簿。
实现位于包 `ontology/matcher`，独立朴素对照模型位于 `ontology/matcher/naive`。

## 1. 数据模型

- `bookOrder`（`order.go`）：委托的可变内部表示，恒守
  `total == filled + remaining`。冰山在簿时 `remaining = 当前显示批 + 价位聚合储备`。
- `slotNode`：一个显示批，是价位可见 FIFO 双向链表的一个节点。
  普通委托一生只有一个槽；冰山每补一批就新建一个槽追加到队尾，天然表达“补批丢失时间优先”。
- `hiddenNode`：价位隐藏 FIFO 链表的一个节点，按序号排列。
- `priceLevel`（`level.go`）：同一价位的
  可见链表 + 隐藏链表 + `visibleQty`（可见汇总）+ `icebergReserve`（冰山储备聚合）+
  `hiddenQty`。储备与隐藏量永不进入任何公开显示汇总。
- `levelIndex`（`heap.go`）：每侧一个 `map[price]*priceLevel` + 一个价格小顶堆，
  买侧用负价入堆从而用同一个小顶堆得到最高价。价位采用惰性删除：
  价位变空只从 active map 删除，堆顶取用时弹出陈旧键。

## 2. 撮合规则（`place.go`）

1. 校验参数，再查重；参数非法优先于编号重复。被拒操作不改状态、不占序号。
2. 接受时分配单调递增序号，随后 `match`：
   - 从对手方最优价位起逐价位推进，直到价格不再交叉（买 `>=` 卖，恰等成交）或主动量用完。
   - 成交价恒为被动方价位。
   - 每价位先 `matchVisible` 再 `matchHidden`。
3. `matchVisible`：一次成交严格只消耗一个显示批，绝不跨批；
   - 主动量先耗尽：批就地截短，位置不变；
   - 整批耗尽：槽出队；冰山若还有剩余，立即以
     `min(显示量, 剩余)` 补出新批追加到该价位显示队列队尾，且在本次主动委托中可被继续吃到；
   - 普通委托整批耗尽即完成。
4. `matchHidden`：仅当显示队列已空时才吃隐藏量（冰山储备的处理见第 3 节不变量），
   隐藏委托之间按序号由小到大。
5. 未成交余量按类型挂簿；冰山只有挂簿部分才产生显示批，其余进储备。

### 关键不变量：显示批 ⇔ 储备成对

冰山在簿的任一时刻，只要还有储备，就必然同时挂着一个非空显示批
（初次挂簿与每次补批都成对建立二者）。因此“显示队列为空”在构造上就等价于
“无显示批且全部冰山储备耗尽”，隐藏门控只判断 `visibleHead == nil`，
无需扫描委托、也无需依赖可能被改量影响的聚合储备做控制流判断。
`icebergReserve` 仅用于撤单/改量时的数量账务与价位空判。

## 3. 撤单与改量（`modify.go`）

- 撤单：摘除其显示批或隐藏节点，冰山同时从聚合储备中减去该单储备；已成交部分不变。
- 减量（`newRemaining <= 当前剩余`）：**保留原排队位置**。
  若新值小于当前显示批则显示批就地截短；冰山按“该单储备前后差值”调整价位聚合储备
  （务必只改自己的贡献，绝不能把聚合量整体覆盖）。
- 加量（`newRemaining > 当前剩余`）：整个委托失去优先级，分配新序号，
  摘旧槽后以满批（不超过新剩余）重新追加到队尾；冰山按新剩余重新建立批与储备。
- 已完成 / 已撤单不可改量、撤单。

错误优先级：参数非法 > 编号重复（新委托）/ 委托不存在 > 委托已完成。

## 4. 并发与确定性

所有公开方法在单一 `RWMutex` 下执行，变更操作用写锁、纯查询用读锁。
这给出可线性化的串行顺序；相同操作序列严格重放得到相同成交序列
（序号与成交编号均由同一互斥临界区单调分配）。

## 5. 复杂度与可验证方式

- 一次吃单的控制流只在“被触及的价位”和“被消耗的显示批”上循环，
  不遍历簿内委托或同价位全部委托。价位间用堆，取最优 `O(log P)`（惰性删除均摊）。
- 价位内出队 / 入队 / 截短 / 撤单摘槽均为链表 `O(1)`（每单持有自己槽与所在价位的反向指针）。
- 引擎暴露内部工作计数 `Stats()`：`BatchesConsumed`、`LevelsCrossed`、
  `HeapPushes`、`HeapStalePops`。`TestWorkScalesWithTouchedBatchesAndLevels`
  对比“小簿”与“垫了 2000 个无关委托的大簿”执行同一笔扫单：
  触及批数恒为 3、跨价位数恒为 2，与簿规模无关，从而以可运行断言证明开销只与
  被触及批数、价位数相关。

## 6. 被放弃 / 调整过的方案

- 用“补批也分配新序号”模拟失去优先：被放弃。题意中序号只授予“被接受的委托”，
  补批是同一委托内部重排，不应额外占序号；位置由链尾追加天然表达。
  朴素模型曾因此多占序号，随机对照中被抓出并修正。
- 在补批前短暂挂起新批、先判隐藏（pending 槽）：被放弃。该方案复杂且仍依赖
  聚合储备门控；改为“批/储备成对”不变量后，隐藏门控只需看显示队列是否为空。
- 用聚合 `icebergReserve == 0` 直接做隐藏门控：被放弃。改量若误用整体赋值会
  污染其他冰山的储备贡献，曾导致价位“非空但无可吃批”而空转。
  现门控不依赖该聚合量；减量改为按本单储备差值调整，恢复聚合守恒。

## 7. 本地验证

```bash
go test ./...                          # 全量
go test ./... -race                    # 竞态
go test ./matcher -v -difflog          # 随机对照打印每条 输入/输出/判定
go vet ./...
gofmt -l .
```

- 场景用例：恰等成交、冰山补批失位且同次可续吃、隐藏最后成交、
  减量保位 / 加量失位、显示批截短、单笔跨多价位、被拒操作不留痕、守恒。
- 差异测试：`TestDifferentialRandom` 对 60 个种子各 400 条随机操作流
  （含重复 id、非法参数、改量、撤单）双引擎逐条比对错误码、成交流、
  全局成交史、每个委托状态与各价位显示量。
