# 副本联邦分配器（fedalloc）设计说明

## 1. 职责划分

包 `fedalloc` 按四个相互协作、可单独理解的模块组织：

| 文件 | 职责 |
| --- | --- |
| `types.go` | 数据模型（`Cluster` / `Target` / `Change` / `AllocationResult`）与带优先级的错误类别 |
| `snapshot.go` | 登记期参数合法性校验，以及集群到“不可变分配视图” `clusterView`（含有效上限）的转换 |
| `allocate.go` | 纯函数核心算法：最小保障 → 按权分摊 → 上限饱和后再分配 |
| `plan.go` | 由目标副本数推导变更计划、总迁移量，并强制“目标之和恰好等于总数”不变式 |
| `registry.go` | 并发安全的动态登记处：增删改、一致快照、墓碑迁出、原子分配并提交 |

算法核心 `allocate` 是纯函数：只读取入参切片，不触碰任何可变状态。登记处负责
在锁内构造某一时刻的一致快照，再调用纯函数，因此“所见集合必须是某一时刻快照”
由结构本身保证，而不是靠调用方自觉。

## 2. 关键语义与取舍

### 2.1 有效上限与参与资格

- 有效上限 = `min(maxReplicas, capacity)`；未设置 `maxReplicas` 时只受容量限制。
- 不可用集群目标恒为 0，不参与最小保障与分摊；其当前承载量计入迁移量。
- 可用集群都参与最小保障；仅 **权重严格大于 0** 的可用集群参与后续按权分摊。
- 权重为 0 的可用集群恰好获得其最小副本数。

### 2.2 最小保障

按顺序产生两类高优先级错误（见 2.6）：

1. 任一可用集群 `minReplicas > 有效上限` → `KindConfigConflict`；
2. 所有可用集群最小数之和 > 请求总数 → `KindMinExceedsTotal`。

被拒绝时算法在写入任何目标前返回，登记处状态保持不变。

### 2.3 按权分摊（Hamilton / 最大余数法的多轮形式）

对当前仍未饱和（目标 < 有效上限）的正权重集群反复执行“轮”：

1. 令本轮剩余 `R`，未饱和权重之和 `W = Σ wᵢ`。
2. 每集群理想份额 `R·wᵢ/W`，整数部分 `floor`，小数部分为余数分子（分母恒为
   `W`，因此比较小数只需比较分子）。
3. `floor` 达到或超过剩余可用容量（headroom）的集群被**钉住**到有效上限并立即
   饱和；其 headroom 之外的份额成为溢出。
4. 取整余量按“小数部分从大到小，每集群至多 +1”发放；小数相同时：
   - 当前已承载副本数多者优先；
   - 仍相同按名称升序。
5. 当一个 +1 恰好把某集群补到上限，或第 3 步发生钉住，导致参与集合变化时，本轮
   立即结束，尚未发放的全部余量进入下一轮，在新的未饱和集合上按其权重重新分摊。
6. 直到余量为 0（成功），或没有任何未饱和正权重集群但仍有余量
   （`KindInsufficientCapacity`，错误信息携带缺口大小）。

**关键取舍：余数优先序只在“固定的一轮”内有效。** 一旦有集群因本轮分配达到上限，
权重基 `W` 就变了，本轮剩余绝不能继续沿用旧的小数顺序，而必须重算。这是朴素实现
最容易写错、差分测试重点捕捉的点（见测试 iter 35 / 78 / 95 / 712 类场景）。

### 2.4 整数与不溢出

总副本数与各集群数值同处 10^15 量级。份额比较需要乘积 `R·wᵢ`，64 位相乘会溢出。
所有跨集群求和与“分子/分母”比较一律使用 `math/big.Int` 的精确跨乘积
（`R·wᵢ vs R·wⱼ` 化为 `wᵢ·bn ? wⱼ·an`）。最终目标值本身保证落在 int64 有效上限
之内（不超过各集群容量），因此结果以 int64 返回，但总和校验仍用 big.Int 复核。

### 2.5 变更计划与稳定性

- 目标按名称升序输出，保证输入排列顺序不影响结果。
- `target == current` 的集群不出现在 `Plan` 中。
- `Delta = target - current`；总迁移量 = 所有减少量绝对值之和（big.Int 求和）。
- 当前承载数**只**用于打破小数部分完全相同的并列；其余任何路径（比例、floor、
  饱和判定）都不读取当前承载数。`TestCurrentLoadOnlyBreaksFractionTies` 显式验证：
  非并列时任意篡改当前承载数，目标不变。

### 2.6 错误类别与优先级

从高到低：

1. `KindInvalidArgument`（参数非法）：负总数、空名、负权重/最小/容量/当前值、
   `min > max`、删除不存在的集群等。
2. `KindConfigConflict`（配置冲突）：最小数超过有效上限。
3. `KindMinExceedsTotal`：最小数之和超过总数。
4. `KindInsufficientCapacity`：全部饱和仍有剩余（携带缺口）。

登记期即可判定的非法配置（如负权重、`min > max`）在 `Upsert` 时拒绝，因此不会
进入分配；而“最小数超过**容量**”取决于有效上限、且与其它分配期条件同时存在，
在分配期按优先级裁决（配置冲突高于最小和、最小和高于容量不足）。

### 2.7 动态登记、墓碑与并发

- `Upsert` 同名即原子替换，立即影响此后的分配；重复登记是更新而非新增。
- `Delete` 移除集群；若其仍承载副本，保留一条 `tombstone(name → load)`。下次
  分配时墓碑以“不可用、容量 0、当前承载 = load”的形态进入快照，其副本被强制迁出
  并计入迁移量；同名集群重新登记会清除墓碑。
- 被拒绝的分配不改变任何状态（`Allocate` 天然无副作用；`AllocateAndCommit` 在
  同一把互斥锁内完成“快照→计算→提交”，失败时不提交）。
- 所有读写经同一把 `sync.RWMutex`。分配在锁内取得深拷贝快照后释放读锁，纯函数
  在锁外计算；需要“分配结果即生效”时用 `AllocateAndCommit`，其整个临界区给出某个
  串行顺序下的结果，满足线性化等价。

## 3. 性能：为何只取决于集群数

**结构性论证（非耗时测量）：**

- 代码中不存在任何随副本总数增长的循环，份额由乘除一次性算出。
- 每一个“轮”要么耗尽余量，要么令至少一个正权重集群达到上限而永久退出活跃集合。
  设有 n 个参与集群，则轮数 ≤ n。
- 每轮做一次 O(n log n) 的并列排序，因此最坏时间复杂度为 O(n² log n) 次比较
  （实际多数请求一轮即结束），空间 O(n)。无论总数是 1 还是 10^15，工作量相同。

`TestComplexityIndependentOfTotal` 用固定的 7 集群集合，在 100 … 10^15 的总数上
分配，并要求 10^15 与 100 两档耗时之比保持在极小范围内（实测约 0.86）。逐副本
O(total) 的朴素实现需要约 10^13 倍的时间，不可能通过该断言，因此该测试可证伪地
区分了两种复杂度，而不是仅打印耗时。

## 4. 被放弃的方案

- **逐副本贪心（把每个副本给“最该得”的集群）**：直觉简单，但最大余数法并不是
  “下一份分数最大”的简单在线贪心，且直接逐副本会 O(total)，10^15 不可接受。最终
  仅在测试里以独立参考模型的形式使用，并严格对齐到轮次语义。
- **浮点比例 + 排序**：`R·w/W` 在 10^15 量级会丢失精度，错误地决定 +1 归属；放弃
  浮点，统一 big.Int 精确比较。
- **用当前承载数做再平衡/亲和性加权**：会破坏“仅小数并列才参考当前承载数”的
  稳定性要求，被明确排除；当前承载数只参与并列裁决与变更计划展示。
- **把分配结果直接写回集群状态**：会让一次失败请求污染状态、也无法做到“分配只是
  计划”。改为纯计划 + 显式 `Commit` / 原子 `AllocateAndCommit`。
- **无锁或分片锁**：当前规模下争用不是瓶颈，单一 RWMutex 的清晰一致性优于复杂的
  无锁结构；未来若成为瓶颈可在读侧用不可变快照 + 原子指针替换。

## 5. 本地验证方法

需要 Go 1.26+（仓库 `go.mod` 要求）。若 `go` 不在 PATH：

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache   # 仅当默认缓存目录只读时需要

go test ./fedalloc -v                 # 详细日志：每次操作输入/输出/判定依据
go test -race ./fedalloc -count=1     # 竞态检测
go test ./fedalloc -run TestDifferentialAgainstNaive -v   # 与朴素模型逐步差分
go vet ./...
gofmt -l .
```

测试日志由 `opLogger` 统一打印，编号列出每次 UPSERT / DELETE / ALLOCATE 的输入、
实际输出与每条断言的判定依据，可用 `go test -v` 完整复现。
