# 转租链与责任传递：设计说明

1. 模块划分（9 个实现文件）：`service.go`（类型、错误、事务入口、时钟）、`tx.go`（深拷贝事务）、
   `calendar.go`（日序号/月账期）、`billing.go`（账期、欠费、到期级联、链遍历）、
   `consent.go`（一次性/概括性同意）、`lease_ops.go`（签约、转租、承认、同意授予撤回）、
   `termination.go`（主动终止与退出）、`payment.go`（清偿、追偿、责任人链）、`naive.go`（朴素模型）。
2. 链结构：每租约存 `ParentID`（权威）与父侧 `ChildID`（缓存）。有效下级=未终止且 `ParentID==父`，
   读取先查缓存再按 `ParentID` 兜底，保证“任一时刻至多一份有效下级”不依赖缓存正确性。
3. 时钟：只在操作通过全部校验、即将生效时推进（`acceptClockLocked`）。被拒操作不推进 now，
   满足“now 不得小于上一次被接受操作的 now”，且拒绝不留痕。
4. 拒绝不留痕：每个变更操作在全量深拷贝事务（`txLocked`）中执行，失败丢弃副本，成功原子提交，
   连同时间驱动的账期/欠费/到期一起回滚，杜绝“校验前结算”泄漏。
5. 结算顺序固定：账期生成→欠费产生（按 due、leaseID 排序）→到期级联（按 End、ID），保证重放确定。
6. 月账期：整数日按 UTC 日历映射；起租月应付日不早于起租日，应付日≥终止日不计；逾期判据 `now>=due+G`。
7. 转租校验固定次序：参数→时钟→租约存在/有效→对自身→同意→期限→租金(`r*100<=上级*P`)→深度→已有下级。
8. 同意：一次性同意绑定全部条款，用后置 `Used`；概括性同意只存“有效/已撤回”，撤回仅影响其后新转租；
   重授清除撤回标记。二者均只由该链房东授予。
9. 终止级联：上级终止取终止日 now；递归向下，已承认下级改挂祖父（根则成为房东直接租约，期限租金不变），
   其整棵子树随之提升一级；未承认下级同批终止。主动终止/退出后统一再结算一次。
10. 责任与追偿：欠费由账期生成，`Paid` 累计；只有欠费租约自身或其逐级上级可清偿；
    每次清偿写一笔金额相等的追偿权，天然不可重复形成；超额、已清偿再清偿均拒绝。
    不变量由测试断言：每笔欠费 `Paid == 该欠费追偿总额 <= Amount`。
11. 责任人查询复杂度：`ResponsibleChain` 只沿 `ParentID` 上行，步数 `2d+1`（d=深度），不随租约总数 N 变化；
    测试在 N=10 与 N=2000 下断言步数相同，给出可验证证据。
12. 并发：单一互斥+事务使所有操作可线性化；`-race` 下并发转租恰一成一败、并发清偿恰一成一败。
13. 被放弃方案：①校验前先结算——会让被拒操作提前生成账期/终止租约而留痕，废弃；
    ②用时间戳集合管理概括同意——撤回/重授语义易错，改为单条有效/撤回态；
    ③级联时只清子指针不复核——缓存可能与父链不一致，改为 `ParentID` 权威兜底；
    ④细粒度锁提升并发——复杂度高且本题重正确性，单锁已满足“等价于某串行顺序”。
14. 本地验证：`go test ./...`（功能+40 组随机对照+不变量）、`go test -race ./...`（并发）、`go vet ./...`。
