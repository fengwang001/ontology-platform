# 路径锁服务设计说明

1. 模块：`path.go` 规范化；`errors.go` 错误码（码值即错误次序）；
   `treap.go` 持久化随机 treap；`service.go` 加锁/释放/校验/分页/审计；
   `admin.go` 管理员名册；三个 `*_test.go` 覆盖语义、朴素差分、并发与性能。
2. 规范化：字节扫描拒绝 <0x20 与 0x7f；按 `/` 分段，丢弃空段与 `.`，
   `..` 弹栈，弹空即逃出仓库根，结果为空即非法；规范化结果即锁的身份。
3. 存储：路径为键的持久化 treap（按字节序），另配 `Lock.ID -> Path` 映射。
   写操作只复制根到叶的 O(log n) 节点，旧根不可变，直接充当分页快照。
4. 加锁：精确命中先裁决（本人 self-held / 他人 other-held）；否则探测
   深度 O(d) 的祖先点查与 `p/` 前缀内的后代扫描，全部相关锁均属本人才放行；
   他人冲突选路径最短、同长取字节序最小者返回。
5. 释放：空用户 → 强制权限 → id 存在 → 持有者，按固定次序只报一个；
   普通释放成功不审计；强制释放追加审计并推进单调序号。锁 id 删除即失效，
   再释放一律 not-found，故同一 id 不可能释放两次。
6. 推送校验：批次先整体规范化（任一非法即参数非法），批内去重；每路径枚举
   精确/祖先/后代锁，非本人锁进入冲突表；冲突表非空则整批拒绝（按路径字节序
   列全部冲突），且零副作用；放行后若要求顺带释放，仅删批内本人精确持有的锁。
7. 查询：前缀按「等于前缀 或 `前缀/` 下」匹配；首页固定快照令牌，续页携带
   令牌与游标（严格大于上页末路径），因此翻页期间的增删要么整把出现要么不出现。
8. 并发：所有方法经单一互斥锁串行化，临界区内只有内存树操作，观察结果必然
   等价于某个串行顺序；两用户抢同一/祖先后代路径恰好一个成功。
9. 性能：单次加锁为 O(d log n)，单路径校验同阶，均不随总锁数线性增长；
   批校验只访问批内路径的祖先链与其前缀子树，与无关锁数量无关。
   `TestPerformanceNotLinear` 与 `BenchmarkAcquire`（10 万无关锁）可复证。
10. 放弃的方案：每目录读/写锁——快照与「顺带释放」难以做到无半记录；
    RWMutex 放宽并发——语义只要求可串行化，单锁更简单且已满足吞吐；
    非持久树 + 版本计数——无法低成本给出一致分页；线性扫描存储——不满足性能条。
11. 本地验证：`go test -race -v ./pathlock`（12 个用例）、
    `go test -bench=BenchmarkAcquire -run=^$ ./pathlock`、
    `go vet ./... && gofmt -l pathlock`。日志逐次打印输入、实际输出与判定依据。
