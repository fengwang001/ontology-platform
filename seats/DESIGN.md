# 设计说明：多航段联程座位库存与超售控制（包 `seats`）

## 模块划分（7 个 .go 文件）
- `errors.go`：拒绝类别 `RejKind`，枚举序即规定拒绝次序；`Error` 携带失败航段与条目状态。
- `entry.go`：条目状态机（预占/已出票/已取消）；“已过期”是导出判定而非状态。
- `segment.go`：航段、嵌套授权、可用数与可售判定、过期占用 FIFO 队列。
- `system.go`：时钟、预占/出票/取消/调授权/查询，惰性清扫与只读探测。
- `export.go`：快照导出/恢复，排序保证确定性，占用与队列由条目重建。
- `system_test.go` / `model_test.go`：定向测试；朴素对照模型 + 随机比对。

## 关键取舍
- 串行化：全部公开方法共用一把互斥锁，天然等价于某个串行顺序；条目标识
  来自单调计数器，到期时刻 = 接受时刻 + 预占时长，重放结果逐位相同。
- 占用计数增量维护（confirmed/held 两个数组），可用数 O(等级数)=O(3)。
- 过期处理：时钟单调 ⇒ 到期时刻单调 ⇒ 每航段一个 FIFO 队列；只在“不超
  过系统当前时刻”时提交清扫，每条记录恰好出队一次（摊还 O(1)，用
  `swept` 计数器在测试中精确证明，不依赖计时）。
- 被拒绝的预占若带有未来时刻，不得提前提交清扫（否则改变当前时刻可用
  数），改为只读探测队列前缀求值，被接受时才提交同一前缀——这是保证
  “被拒绝的操作不改变任何状态”与“可用数是纯函数”的核心机制。
- 可售判定取“该等级及所有更高等级可用数都 >= 旅客人数”：蕴含题目的
  >0 可售定义，且保证总占用不超过最高等级授权量这一不变式（仅按字面
  “指定等级可用数 >= 人数”会出现反例）。
- 出票只改变占用性质（held→confirmed），不重新检查库存：总量不变，且
  授权量下调后已有占用本就不受影响。
- 查询以系统当前时刻（最近一次被接受操作的时刻）求值，不参与时钟约束。

## 被放弃的方案
- 最小堆管理到期：O(log n) 随数量增长，且时钟单调下无必要。
- 每次查询全量扫描条目：O(n)，违反性能条款（对照模型仅用于测试）。
- 每航段独立锁：跨航段全有或全无需要全局排序加锁，复杂度高于收益。
- 拒绝操作也提交清扫：实现更简单但违反“被拒绝的操作不改变任何状态”。

## 本地验证
- `go test ./seats/ -v`：全部定向用例 + 3 种子 × 2000 步随机比对（逐步
  打印输入/输出/判定依据，用 `-run TestRandomAgainstNaiveModel -v` 查看）。
- `go test -race ./seats/`：并发等价串行与数据竞争检测。
- `gofmt -l seats/ && go vet ./seats/`：格式与静态检查。
