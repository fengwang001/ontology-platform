# 模块链接与求值器设计说明

`linker` 包实现一个支持循环依赖、暂时性死区（TDZ）与错误粘滞的模块
链接与求值器。所有操作（`AddModule` / `Evaluate` / `Status` / `Order`）
都持有会话级互斥量，可被并发调用，对外等价于某个串行顺序。

## 数据模型

- 模块状态：`registered`（已登记）→ `linked`（已链接）→
  `evaluating`（求值中）→ `evaluated`（已求值）；任一阶段失败落到
  `errored`（出错，粘滞错误值）。
- 每个 `let` 导出持有一个“已初始化”位，初为假，只会由假变真；
  `function` 导出在链接成功提交时立即置真。
- 会话持有“求值完成次序”列表，只有体成功执行完的模块才会恰好追加一次；
  出错模块不进入次序。

## 链接的原子性

`Evaluate(root)` 是一个原子步骤，链接与求值在同一次临界区内完成：

1. 根为 `evaluated` 或 `errored` 时直接返回，不做任何遍历。
2. 否则沿“依赖列表”做深度优先先序遍历，每个模块只访问一次，只进入
   `registered` 模块（`linked` 及之后状态不再进入）；遇到第一个未登记
   的来源即以“模块不存在”拒绝。
3. 遍历得到本次新链接集合（先序）。随后按先序对每个模块先做导入解析
   （语句次序、语句内名字次序），再做具名转出解析（列表次序）。
4. 任一解析失败即拒绝（“未找到”为链接错误，“歧义”为链接歧义，
   均带 `(本模块, 来源, 名字)`）。
5. 只有全部解析成功才提交：模块批量置 `linked`，函数导出批量置真。

拒绝发生在提交之前，因此不改变任何模块状态或初始化位。任何观察者都
不可能看到只链接了一部分的状态。

## 导出解析与解析集合

`ResolveExport(m, n)` 的每次顶层调用持有一个解析集合，初为空，在该次
调用内共享、只增不减：

1. `(m,n)` 已在集合中 → “未找到”（祖先环或此前展开过的兄弟分支相同）。
2. 否则加入集合并计数展开，然后依次：
   - `n` 是本地导出 → 绑定 `(m,n)`；
   - 存在名为 `n` 的具名转出 → 递归解析其 `(来源, 来源名)`，结果
     （绑定/未找到/歧义）原样返回，歧义由此向上传播；
   - 否则按列表次序展开星转出：歧义立即返回；绑定与已记录星绑定不同
     （定义模块与本地名都相同才算同一绑定）→ 歧义；相同或未找到则继续。

本地导出与具名转出优先于星转出；星转出不提供本模块已定义的名字。
非导出计数器 `resolutionExpansions` 记录最近一次顶层调用中每个
`(模块,名字)` 对的展开次数，其键数即解析集合的最终大小。

## 求值：深度优先后序与循环跳过

`Eval(m)`：

- `evaluated` → 成功；`errored` → 返回粘滞错误；`evaluating` → 成功
  返回（循环依赖跳过）。
- 否则置 `evaluating`，按依赖列表次序依次 `Eval` 各来源；任一来源返回
  错误则 `m` 粘滞该错误，体不执行并立即返回。未访问到的后续依赖保持
  `linked`，之后可从别的根继续求值。
- 全部来源成功后按序执行体：`Init(x)` 置位；`Read(n,x)` 先取绑定
  （本模块读本地；否则读链接时解析得到的定义模块绑定 `(d,y)`），若
  `d.y` 是未初始化的 `let` 则抛出 `TDZ d.y`；`Throw(msg)` 抛出 `msg`。
- 抛错时 `m` 置 `errored` 粘滞错误值，后续步骤不执行，此前的 `Init`
  保留；成功执行完才置 `evaluated` 并追加到完成次序。

求值阶段的错误是“结果”而非“拒绝”：状态、初始化位与次序的修改全部
保留。出错模块永不重试，已求值与出错模块的体至多执行一次（由非导出
计数器 `bodyRuns` 验证）。

依赖列表次序 = 导入语句来源按语句次序，再接转出项来源按列表次序，
它同时决定链接先序遍历与求值后序次序。

## 拒绝优先级

- `AddModule`：参数非法（格式/上限/空串）→ 名字已登记 → 模块数超限。
- `Evaluate`：根名非法 → 模块不存在（根或遍历来源）→ 链接错误 /
  链接歧义（按先序谁先谁报；遍历阶段的不存在先于解析阶段）。

## 本地验证

```bash
# 全量测试（含竞态检测）
go test -race -v ./linker

# 2000 组随机模块图 / 求值序列与朴素模拟器对照，并导出完整日志
go test -run TestRandomDifferential2000 -v -args -difflog=/tmp/difflog.txt

go vet ./...
```

随机测试（`random_test.go`）把同一组 AddModule/Evaluate 序列分别喂给
正式实现 `Session` 与独立的朴素参考实现 `naiveSim`（每次从头重算可达
集合、解析集合与状态转移，见 `simulator.go`），逐操作比对拒绝类别、
返回值，并在终态比对全部模块状态、let 初始化位与完成次序；日志中打印
每组的输入、双方输出与判定依据。
