# 骑手考核与申诉系统 — 设计说明

## 模块划分
- `types.go`：配置/事件/申诉/补偿类型、错误码、周期换算、阈值定级等纯函数。
- `cluster.go`：事件与根因簇。treap 保序 + 并查集维护"相邻差 ≤ ClusterSpan"的传递簇。
- `settle.go`：周期结算、等级→权益的下降上限/上升不受限、未冻结权益递推。
- `system.go`：门面与并发协调（单把互斥锁），编排时钟、登记、申诉、裁决、回溯。
- `naive.go`：独立的全量重算朴素模型，仅供差分测试。

## 关键取舍
- 成簇只可能经由有序集合中的直接前驱/直接后继，插入只看两个邻居并合并其簇，
  与该骑手全部历史事件数无关；并查集按大小合并 + 路径压缩。
- 簇内最早者不做缓存指针（曾导致跨合并读到过期根），改为并查集根持成员列表、
  取最早者时线性扫描；每节点仅在被并入那一次参与比较，摊销常数。
- 扣分总额按 (骑手,周期) 增量维护；撤销只影响簇内最早者所在周期。
- 结算是时刻的函数：查询只读地把周期冻结到 opTs，但不推进写入时钟；
  晚于右端点登记进已冻结周期的事件只影响实时值，不改写冻结快照。
- 回溯不改写历史冻结等级/权益；补偿后把"下一未开始周期"的下降基准覆盖为
  本应权益（baseOverride），未冻结权益递推从最大覆盖点/冻结点出发。
- 查询性能：冻结周期 O(1) 命中快照；未冻结仅按周期数递推，不扫描任何事件。

## 被放弃的方案
- 用区间树/排序切片维护簇：插入 O(n)，随历史事件数增长，不满足性能约束。
- 在并查集根缓存 earliest：多级合并后旧根缓存过期，差分测试暴露不一致，已弃用。
- 查询推进全局 maxTs：会让一次观察误伤后续合法写入（误报时钟回退），已改为只读。

## 并发
- 所有变更与查询在单锁内完成，天然等价于某串行顺序；
- 操作时刻在任何状态修改前校验，被拒操作不推进时钟、不改任何状态；
- 整簇撤销、补偿记账都在锁内，保证至多撤销/补偿一次。
