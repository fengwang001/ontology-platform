# 无等待原子快照

`snapshot.New(n)` 创建 `n` 个初值为 0 的单元（`1 <= n <= 16`）。

- `Update(writer, i, v)`：仅允许写者 `i` 向单元 `i` 写入整数 `v`。
- `Read()`：返回一份长度为 `n` 的值向量副本。
- `MaxCollections()`：返回所有外部快照读中，单次读使用的最大收集次数。

## 收集与借用规则

一次“收集”依次原子读取 `n` 个单元当前的不可变记录。记录包含本单元值、一次内部扫描得到的向量、扫描纪元和该向量的提交点。

每次扫描开始先取得一个新的单调纪元，然后循环收集：

1. **稳定返回**：相邻两次收集得到完全相同的记录指针时，两次收集之间没有任何单元发布。第一份收集结束到第二份收集开始之间没有写入，因此这份向量是某一时刻的整体真实状态。
2. **借用嵌入结果**：如果收集到记录的嵌入扫描纪元不小于本次扫描纪元，就借用该记录中的嵌入向量。纪元条件保证该嵌入扫描已经观察到本次扫描开始，不可能借到调用前延迟发布的陈旧结果。
3. 否则继续下一轮收集。

更新者在发布自己的新值前也执行同样的扫描，并把得到的向量、纪元和提交点嵌入自己的新记录。发布提交点在实现中串行分配，用于测试把每次结果精确还原到全局历史；读者不获取这把更新锁，只读原子记录，因此读不会等待写者。

## 为什么收集次数有界

一次扫描开始时，每个单元至多有一条“纪元前旧记录”可能阻止借用。扫描在收集到纪元后新记录时立即借用；即使写者持续更新，每条单元也只需越过至多一条旧记录。因此扫描最多使用 `n+1` 次收集：第 1 次初始收集加至多 `n` 次后续收集。

`n+1 <= 2n+1`（对 `n >= 1`），满足题目上界。实现的统计只记录外部 `Read()` 的实际收集次数，更新中的内部扫描不计入 `MaxCollections()`。

无效操作按以下顺序返回第一个错误，且在任何扫描或发布前完成检查：

1. `n` 不在 1 到 16：`ErrInvalidN`
2. 更新下标越界：`ErrInvalidIndex`
3. 调用者编号与单元不一致：`ErrInvalidCaller`

## 性质

- 原子性：返回向量等于某个全局提交点的真实值向量。
- 实时性：更新返回后，其新记录已发布；之后开始的读只能看到该值或更新值。
- 因果性：嵌入向量包含该更新者扫描时已观察到的完整状态；看到因后才发布果时，后续快照不会出现“果新而因旧”。
- 单调性：各单元只写递增值时，顺序调用的快照分量不会倒退。
- 有界无等待读：读路径只有原子载入、指针比较和向量复制，不等待任何执行体。

## 本地验证

```bash
go test -v ./snapshot
go test -race -v ./...
go test -count=20 ./snapshot
go vet ./...
gofmt -l .
```

如果系统的 Go 缓存目录只读，可指定：

```bash
GOCACHE=/tmp/ontology-go-cache go test -race ./...
```
