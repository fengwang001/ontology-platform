# 分代回收模型设计说明（gengc）

模块（5 个实现文件，职责单一）：
1. `object.go`：托管对象登记，固定引用槽、所在区、年轻回收次数、晋升次数。
2. `remembered.go`：写屏障与对象粒度记忆集（map），屏障 O(1)。
3. `collect.go`：年轻区回收（年轻根＋记忆集根、计数、晋升、重算记忆集）与年老区回收。
4. `heap.go`：分配/自动回收、字段读写、根集合、统计快照、全堆可达性。
5. `errors.go`：四类错误与固定拒绝次序。

关键取舍：
- 写屏障采用“卡表/快照屏障”的对象粒度简化版：仅在「年老对象写入年轻引用」时
  把承载对象加入记忆集；同对象多次写入只计一次。写入与登记在同一互斥临界区，
  对回收不可分，故并发严格等价于某串行顺序（一把 `sync.Mutex`，`-race` 验证）。
- 年轻回收起点 = 根 ∪ 记忆集成员字段；只在年轻对象间继续传播，不扫描其他年老对象。
- 回收末尾重算而非沿用记忆集：候选集 = 旧成员 ∪ 本次晋升者，仅保留仍引用存活
  年轻对象者；晋升者成为新成员，旧目标被改写后自然剔除，死目标不能保命。
- 晋升在存活判定之后；失败对象留年轻区，年龄钳制在阈值，下轮重试。
- 年老区回收只接受显式触发；全堆从根可达，清死亡年老对象及其记忆集项，不改年龄。
- “分配触发回收后仍空间不足”要求整次分配零副作用：先快照、推测执行回收，
  放不下则整体回滚（连本次 GC 计数也回滚）。
- 拒绝次序：未定义 > 参数 > 悬垂 > 空间不足；SetField 先校验 src 存在性，
  再校验字段越界，最后校验 dst（因此越界优先于 dst 悬垂）。

复杂度（可验证）：
- 写屏障：两次 map 访问 + 两次代数比较，O(1)，与任何规模无关。
- 年轻回收：访问根数 + 记忆集成员字段 + 存活年轻对象字段，
  O(|roots| + 字段数(记忆集成员) + 字段数(存活年轻对象))，
  不随年老区对象总数增长。朴素模型每次扫描全部年老对象，测试中两者结果逐位一致。

被放弃的方案：
- 字段粒度记忆集：能减少重扫字段，但违反“登记的是对象不是字段”的题设。
- 增量/并发标记：题目要求变更与回收串行等价，单锁方案最简且可证。
- 写时立即摘除记忆集成员：旧引用改写后若仍有其他字段指年轻对象会被误删，
  故只在回收末尾按真实字段重算。

本地验证：
- `go test ./gengc/ -race -v`（本机 Go 位于 /usr/local/go/bin，必要时 `GOCACHE=/tmp/gocache`）
- 定向用例见 `gengc_test.go`；随机差分（40 种子×300 步，逐条输入/输出/判定日志）
  见 `naive_test.go`、`modelstate_test.go`。
