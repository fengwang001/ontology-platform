# logstore：日志结构存储 + 代价收益段清理器

所有写入（值覆盖、删除墓碑）都以块追加到当前段；段是定长、只追加的，
写满即封存。清理器从已封存段中挑选一个“牺牲段”，把其中仍然存活的块
按原写入顺序搬到日志尾（保留原写入时刻），然后整段回收。

## 块与段

- 段大小 `SegmentSize` 固定；段总数受 `MaxSegments` 上限约束。
- 每个块的字节账目为 `17 + len(key) + len(value)`，其中 17 字节是定长头：
  时间戳 8 + 类型 1（值块/墓碑）+ 键长 4 + 值长 4；墓碑的值长计 0。
- 块按到达顺序追加；当前段剩余空间放不下时封存并开启新段。
- 内存中的段布局与字节账目完全由该公式决定，因此同一操作序列得到
  相同的清理顺序与段布局（回收段号按升序复用，map 遍历前全部排序）。

## 牺牲段挑选公式

对每个已封存段计算：

```
存活率 r   = live / SegmentSize
年龄   age = clock - seg.maxTS          // maxTS = 段内最新块的写入时刻
评分       = (1 - r) * age / (1 + r)
```

- 评分越大越优先：`(1-r)` 是回收可释放的比例，`/(1+r)` 惩罚高存活段
  （搬迁成本高），`age` 让冷数据优先。
- 使用 `math/big` 交叉相乘做**精确有理数比较**，没有浮点误差；
  评分并列时取段号最小。
- 存活率为 0 的段直接回收（同样并列取段号最小），不做搬迁。
- 当前活动段从不参与挑选。

## 存活判定

每个键的索引保留其所有物理存在的块（按写入时刻递增）：

- **值块**：只有该键索引中的最新块（且为值块）存活；被覆盖的旧值块
  在新值块追加成功的同一临界区内立即从存活字节中扣除。
- **墓碑块**：当且仅当“任一**其他段**中仍留有该键更旧的块”时存活。

每段的存活字节恒等式始终成立：

```
live[seg] = 索引指向 seg 的最新值块字节之和
          + seg 中仍需保留的存活墓碑字节之和
```

搬迁完成后以索引为权威来源重算所有段的 `live`，杜绝增量漏账。

## 墓碑保留推导

墓碑的语义是“该键在墓碑时刻之前的版本对外不可见”。

- 若墓碑所在段之外的某个段里还留着同键更旧的块，一旦先回收墓碑段、
  留下那个旧块，旧值就会“复活”。因此此时墓碑必须存活并参与搬迁。
- 若所有更旧块都已不存在（被覆盖或随其他段回收），墓碑不再遮蔽任何
  物理数据，回收它不影响任何读结果，其存活字节计 0。
- 判定以“其他段”为边界：墓碑与被它遮蔽的旧块本就在不同段（墓碑是
  之后追加的），同段整段共生死，不需要用墓碑保护同段旧块。

即使存活字节已计 0，墓碑可能仍是某键索引的最新块：此时 `Get` 仍返回
`ErrKeyNotFound`；直到该键再次被写入，或墓碑段本身被回收，索引条目
  才被移除。

## 搬迁语义

- 存活块按原段内写入顺序（即时间戳顺序）追加到日志尾。
- 搬迁**保留原写入时刻**（块的 `ts` 不变），且不推进逻辑时钟，
  因此搬迁后段年龄不重置、评分不被人为抬高。
- 先从段表删除牺牲段（释放槽位与段号），再追加存活块，因此段总数
  永远不会超过 `MaxSegments`，且一次清理至多新开一个段。

## 空间耗尽条件

写入时当前段放不下新块且没有空闲段，则尝试先清理：

- 只有当清理**能净增空闲段**时才执行。对“写入触发”的清理，要求
  牺牲段的全部存活字节都能搬入当前段剩余空间（`live <= activeFree`），
  这样回收出来的完整空闲段正好用于本次写入。
- 否则以 `ErrSpaceExhausted` 整体拒绝：不推进时钟、不封存段、
  不清理、不追加任何块。

可区分的拒绝原因：

- `ErrEmptyKey`：键为空。
- `ErrValueTooLarge`：单块字节超过段大小（在任何追加之前判定）。
- `ErrKeyNotFound`：删除不存在的键，或最新块已经是墓碑。
- `ErrSpaceExhausted`：清理无法净增空闲段。

## 并发

`Store` 用一把 `sync.RWMutex` 串行化写与清理、并发放行读者。清理的
“选段 / 释放 / 逐块搬迁 / 重算账目”都在同一个写临界区内，因此读者在
清理的任一步看到的都是清理前或清理后的一致快照，且每个键始终读到
最新值；`Get` 返回值的拷贝，调用方无法破坏段内数据。

## 日志

传入 `Options.Logger`（任意 `io.Writer`）后，每次读/写/清理都会打印
输入、输出与判定依据，例如：候选段的 `live/age/score` 精确分数、
并列选择结果、墓碑 `older-block-in-other-segment` /
`no-older-block-elsewhere` 的去留理由、搬迁 `ts preserved`、
空间耗尽的 `live vs activeFree` 等。

## 本地验证

```bash
# 常规测试
go test -v ./logstore

# 竞态检测 + 重复运行（清理顺序对操作序列确定）
go test -race -count=3 ./...

# 覆盖率与静态检查
go test -cover ./logstore
go vet ./...
gofmt -l .
```

测试覆盖：评分并列取最小段号、非零存活率精确有理评分、墓碑在旧块
回收前后的去留、搬迁保留时间戳与顺序、清理无法净增空闲段时拒绝写入、
清理与读/写并发（`-race`），以及同一操作序列布局确定性。
