# 可订日历与预订约束服务 — 设计说明

## 模块划分
- `types.go`：错误码（固定次序：参数<时钟<不存在<状态<不可订）、配置、快照类型。
- `treap.go`：起始日为键、哈希优先级的区间 treap；占用区间互不相交，形状确定。
- `calendar.go`：单房源日历；`judge` 只做 2 次树查找 + 常数次 minStay 查询。
- `service.go`：时钟、保留两阶段、退款阶梯、改期、封锁伸缩；全局互斥锁串行化。

## 关键取舍
- 区间一律半开 `[ci,co)`：退房日不占用，间隙 g 即两预订间空出的整天数。
- 并发：选全局 `sync.Mutex` 而非分房源锁——天然线性一致、无死锁风险；
  放弃的分片锁方案收益小、正确性成本高。
- 保留失效采用惰性摘除：每个操作先按 now 把过期保留从 treap 摘下再判定；
  操作被接受则提交失效，被拒绝则原样放回。这样"失效以 now 为准"与
  "被拒绝的操作不留痕（含时钟）"同时成立。放弃的"查询时跳过过期节点"
  方案会让 treap 邻居查找退化到 O(n)。
- 占用索引选 treap 而非按夜哈希表：哈希表查"最近占用"需无界扫描；
  treap 判定开销 O(log n)，以节点访问步数为指标在测试中可验证。
- 优先级由起始日哈希确定：同一操作序列重放得到相同树形与日历。
- 孤夜：空档夜数 = 两侧占用间隔 - 换客间隙，空档首日 = 邻居结束日 + 间隙；
  仅对预订邻居判定，封锁邻居豁免；空档为 0 不算孤夜。
- 不可订子原因按 封锁<冲突<间隙<最短入住<孤夜 报告第一个。
- 查询校验时钟但不推进时钟、不清除过期保留（只读）。
- 退款：d=入住日-取消日，d>=P 全额、d>=Q 一半、否则 0；边界取等归宽松档。
- 改期：摘下原区间后重新 judge，失败即放回，原预订不变；差价只记录。
- 封锁与任何占用（含其他封锁）相交即拒绝，保证占用集合互不相交。

## 本地验证
- `go test ./booking/`：单元测试（开闭区间、间隙 0/1、按日最短入住、
  孤夜边界、封锁空档豁免、保留边界付款、退款边界、改期、封锁伸缩、
  错误次序、拒绝不留痕、并发、复杂度上界、重放确定性）。
- `go test -race ./booking/`：并发安全。
- `TestRandomAgainstModel`：10 种子 x 1200 步随机序列对照朴素模型，
  逐步比对错误码、输出与快照，日志含每步输入/输出/判定依据。
- `TestJudgeComplexity`：历史 1k→100k，判定步数 <256 且增长 <4 倍。
