# 灰度放量流量切分器 — 设计说明

## 1. 目标与边界

在稳定版本与灰度版本之间切分流量，按严格递增的比例阶段逐步放量；每个阶段
由一个指标闸门把关，指标不达标按连续失败次数回滚。系统必须：

- 归属稳定：同一标识永远落在同一桶位（0..9999），与时间、阶段、状态无关；
- 会话粘性：标识在 `L` 毫秒内沿用上次路由版本；
- 精确可复现：错误率边界比较不用浮点数，同刻淘汰有确定平局规则；
- 时钟由调用方注入，时钟回退可检测；
- 并发调用等价于某个串行顺序；
- 路由/观测开销不随历史请求总数增长。

所有时间均为调用方传入的毫秒整数，组件本身不读任何时钟。

## 2. 状态机

```
                Start(now)              Evaluate 通过（最后一阶段）
 NotStarted ───────────────▶ Running ──────────────────────────▶ Completed
     ▲                         │  │                                 │
     │ Reset(任意状态)          │  │ Evaluate 失败累计达 F           │ Reset 后
     └─────────────────────────┘  ▼                                 ▼ 回到
                              RolledBack ◀──────────────────────────┘
                                  │ 仅 Reset 可离开
 NotStarted
 ```

- 未开始：比例 0。
- 进行中：记录阶段序号（从 0 起）与进入时刻 `enteredAt`；
  - 评估通过：晋级，`enteredAt = now`，窗口清空，失败累计清零；
    最后一阶段通过则进入已完成，比例保持末阶段值；
  - 评估失败但未达 `F`：留在当前阶段，`enteredAt = now`（驻留重新计），
    窗口清空；
  - 连续失败达到 `F`：进入已回滚，比例 0，清空全部粘性记录。
- 驻留未满（`now - enteredAt < D`）与样本不足（灰度请求数 `< G`）
  都**不**清窗口、**不**动失败累计、**不**重算驻留起点；判定是幂等观察，
  窗口可以跨多次评估累积。
- 人工降级只允许"进行中且阶段号 > 0"：降一阶段、清窗口与失败累计、
  驻留起点重算，粘性记录原样保留。
- 重置清空除配置外的一切（含粘性、窗口、失败累计、时钟锚点），回到未开始。

## 3. 归属位置

`Placement(id)` 是标识的纯函数：

1. `FNV-1a-64(id)`；
2. SplitMix64 雪崩混合（FNV 对 `id-0, id-1, ...` 这类结构化标识的**高位**
   扩散不足，直接用高位取桶会出现约 30% 空桶——这是实测发现并放弃的方案，
   见第 8 节）；
3. `hi = high64(hash * 10000)`（`math/bits.Mul64`），桶号 `i` 恰好覆盖
   哈希空间的 `[i/10000, (i+1)/10000)`，无取模偏差。

归属灰度当且仅当 `Placement(id) < 当前比例`。因阶段比例严格递增，
同一标识在"进行中"的整个生命周期内只会从稳定翻到灰度，不会反向翻回。

## 4. 路由与粘性

判定优先级（高到低）：

1. 已回滚 → 强制稳定，来源 `rollback`；**不读也不写**粘性表；
2. 存在未过期记录（`now - lastRouted < L`，左闭右开）→ 沿用其版本，
   来源 `sticky`，并把 `lastRouted` 刷新为 `now`；
3. 按桶位与比例判定，来源 `ratio`，写入/覆盖粘性记录。

粘性记录实现为 `container/list`（队首最近路由、队尾最久）+ `map[id]*Element`：
命中 O(1)；过期在路由时惰性删除；容量超过 `P` 时淘汰"最久未被路由"的记录。

**同刻平局**：注入时钟允许不同标识在同一毫秒路由，此时仅凭 `lastRouted`
无法区分新旧。淘汰按 `(lastRouted 更小, id 更小)` 比较，保证结果与
调用顺序无关、跨实现可复现（朴素模型用排序复现同一规则）。

`L = 0` 时所有记录立即过期，路由等价于纯比例判定。

## 5. 观测与评估窗口

- 观测仅在"进行中"计入当前窗口，其余状态静默忽略（不报错）；
- 窗口只有四个计数器：灰度总/失败、稳定总/失败；
- 阶段切换、回滚、重置、降级、失败（未达 F）时窗口清空；
- 稳定侧零请求时其错误率按 0 处理。

通过条件（灰度错误率不超过稳定错误率加容差）：

```
grayFail/grayTotal <= stableFail/stableTotal + T/10000
```

实现把两侧通分成交叉相乘的整数比较（`math/big.Int`），完全不引入浮点数：

```
rhsDen = stableTotal * 10000
rhsNum = stableFail  * 10000 + T * stableTotal   (stableTotal=0 时退化为 T/10000)
grayFail * rhsDen <= grayTotal * rhsNum
```

恰等时判定通过。朴素模型则用 `math/big.Rat` 独立再算一遍。

## 6. 错误优先级与时钟

每个入口固定按 **参数非法 → 时钟回退 → 状态不允许** 顺序检查：

- `Route`：空标识（参数）优先，随后时钟，回滚态不是错误（是正常路由结果）；
- `Observe`：非法版本号（参数）优先，随后时钟，非进行中属于"忽略"而非错误；
- `Start/Demote`：先时钟，再状态；
- `Reset`：任何状态可用，但仍检查时钟（重置同时重建时钟锚点）。

`lastNow` 是单调时钟锚点；任何被拒绝的调用都在修改前返回，
因此状态与锚点都不变。相等时刻合法（`now == lastNow`）。

## 7. 并发与复杂度

- 单一 `sync.Mutex` 保护全部状态；路由、观测、评估、人工操作都是
  临界区串行，因此任何并发交错都等价于某个串行顺序。`-race` 下
  16 goroutine × 200 次混合调用验证。
- `Route`：map/list 操作 O(1)，淘汰扫描 O(P)（P 为粘性上限，与历史无关）；
- `Observe`/`Evaluate`：O(1) 计数器/大整数比较（位数有界）；
- 粘性表常驻记录数 ≤ P，窗口是固定四个整数——没有任何随请求总数增长的
  结构。`TestRouteCostIndependentOfHistory` 用 1k 与 100 万历史下的
  每请求平均耗时对照给出可验证证明（实测后者不高于前者的 3 倍，
  且绝对值相近）。

## 8. 关键取舍与被放弃的方案

| 决策点 | 采用 | 放弃的方案与原因 |
| --- | --- | --- |
| 哈希取桶 | FNV-1a + SplitMix64 + `Mul64` 高位 | 裸 FNV 高位：结构化 id 高位雪崩不足，实测 20 万 id 约 30% 空桶；`hash%10000`：有微小取模偏差，桶概率不严格相等 |
| 错误率比较 | 交叉相乘的 `big.Int` 整数比较 | 浮点除法/`float64`：`11/100` 与 `10/100+100/10000` 的恰等边界可能误判；纯 int64 交叉相乘：计数大时有溢出风险 |
| 粘性存储 | list + map 的有界 LRU | 全量 map 不淘汰：内存随历史增长，违反开销约束；后台定时清理过期项：需要内部时钟，违背时钟注入 |
| 驻留/样本不足 | 视为幂等观察，不清窗不重计时 | 每次评估都重置窗口：会让样本永远无法累积到 G，且"样本不足不累计失败"难以表达 |
| 回滚态粘性 | 不读不写，进入回滚即全清 | 回滚后继续沿用灰度粘性记录：与"强制稳定"语义冲突 |
| 同刻淘汰 | `(时间, id)` 字典序确定性平局 | 依赖容器内部顺序：跨实现不可复现，朴素模型对照暴露过此问题 |
| 并发 | 单把互斥锁 | 分片锁/无锁：状态之间强耦合（路由改粘性、评估改状态），收益低且极易出错 |
| 时钟模型 | 每调用注入 `now`，单调锚点 | 内部读墙钟：测试无法精确构造 D-1/D、L-1/L 等边界 |

## 9. API 摘要

- `New(Config) (*Splitter, error)`：校验阶段序列严格递增且各项 ∈ [1,10000]，
  以及各非负/正数约束。
- `Start / Reset / Demote(now)`；
- `Route(id, now) (RouteResult{Version, Source}, error)`；
- `Observe(version, success, now)`；
- `Evaluate(now) (EvalResult{Outcome, RolledBack, Advanced, Stage,
  FailStreak, 窗口计数}, error)`；
- `Placement(id)` / `(*Splitter).PlacementOf(id)` 供测试独立对照；
- `Phase / Stage / Ratio / FailStreak / StickyCount` 只读观测。

错误哨兵：`ErrInvalidArgument`、`ErrClockWentBack`、`ErrIllegalState`，
用 `errors.Is` 判别。

## 10. 本地验证方法

```bash
# 全量测试（含 1200 组随机对照，-v 打印每步输入/输出/判定依据）
go test -v ./canary/

# 竞态检测
go test -race ./canary/

# 跳过耗时的复杂度证明
go test -short ./canary/

go vet ./canary/
gofmt -l canary/
```

随机对照（`TestDifferentialAgainstNaive`）同时驱动实现与独立朴素模型，
逐步比对：路由结果与错误、评估结果与错误、阶段、比例、失败累计、
窗口四计数、粘性表的键与值（版本 + 最近路由时刻）。
