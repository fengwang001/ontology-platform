# 服务网格工作负载授权策略评估器 — 设计说明

包路径：`ontology/authz`。本文档记录模块划分、关键取舍、被放弃的方案与本地验证方法。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `types.go` | 请求、结果、策略、规则等公共类型；`Action`/`Decision` 枚举。 |
| `errors.go` | 统一错误类型 `Error`，两类错误：`ErrKindInvalidArgument`（参数非法，优先级高）、`ErrKindInvalidPolicySet`（策略集非法）。 |
| `match.go` | 纯函数匹配语义：元素四种形式、选择器、来源/操作/条件三部分、规则与策略命中、适用范围判定。 |
| `validate.go` | 请求字段合法性校验；整份策略集校验（按提交次序报告第一个问题）。 |
| `store.go` | 版本化原子存储：`ReplaceAll` 整体校验后一次性交换不可变快照；`Evaluate` 在单版本快照上评估。 |
| `eval.go` | 决策过程：拒绝优先、无适用允许策略默认放行、允许命中/未命中、审计证据收集与排序。 |

## 语义要点与取舍

### 适用范围

策略适用当且仅当：策略命名空间等于请求目标命名空间或等于根命名空间，且选择器被目标标签满足（选择器列出的键值全部相等；空选择器恒真）。根命名空间策略网格内全局适用，但选择器仍须满足。

### 决策次序

1. 任一适用的拒绝策略命中 → 拒绝，依据列出全部命中的拒绝策略。
2. 不存在任何适用的允许策略 → 放行，决定依据为空。
3. 存在适用的允许策略：任一命中 → 放行并列出全部命中的允许策略；全部不命中 → 拒绝，决定依据为空。

审计策略只进入审计依据，不影响决定；所有适用且命中的审计策略按（名称， 命名空间）升序列出。决定依据中的策略引用同样按（名称， 命名空间）排序，保证输出确定性（规范只要求审计排序，决定部分排序是为可复现性做的加强）。

### 空规则与空规则列表

三部分全缺省的规则匹配一切请求；规则列表为空的策略不匹配任何请求，但其“适用性”仍然存在——一个空规则列表的允许策略会把目标工作负载从默认放行切换为默认拒绝。这是规范里最容易写错的一点，专门有测试锁定。

### 否定与请求头

每个集合先检查否定集（命中即否决该部分），再检查正集（非空则必须命中）。请求头名不区分大小写（评估时统一小写化），头值为精确匹配。头缺失时：带正值集合的条件不满足，仅含否定值集合的条件满足。多值头：任一值命中正集即满足，任一值命中否定集即否决——这是规范未明确处的显式取舍，与“集合内为或”的直觉一致。

### 元素形式

身份、命名空间、路径元素支持：精确串、前缀（`foo*`）、后缀（`*foo`）、单独 `*`。校验拒绝：空元素、中间含星、两端同时含星、多个星。方法精确比较且区分大小写。端口合法范围 [1, 65535]。

### 原子发布与并发

`ReplaceAll` 先在锁外完成整份校验与索引构建，再在写锁内一次指针交换替换不可变快照并令版本加一；任一问题则整体不生效、版本不变。`Evaluate` 在读锁内取快照指针后在锁外评估，因此评估永远看到某个完整版本，写替换几乎不阻塞读。任意并发交错等价于某个串行顺序（读写锁互斥 + 快照不可变）。

### 性能

快照内策略按命名空间分桶（`map[string][]*Policy`）。一次评估只访问两个桶：目标命名空间桶与根命名空间桶（目标即根时只访问一个）。被考察的候选策略数与无关命名空间中的策略总数无关——`TestEvaluationCostIndependentOfUnrelatedPolicies` 直接断言考察数恒定（0 / 1000 / 10000 条无关策略下均为 15），基准测试给出墙钟佐证（约 217ns vs 220ns）。

### 错误模型

单一错误类型 `Error` 携带 `Kind` 区分两类错误，优先级：参数非法 > 策略集非法。`Evaluate` 只可能产生参数非法错误；`ReplaceAll` 只可能产生策略集非法错误，并按提交次序报告第一个问题（`PolicyIndex` 给出下标）。评估本身绝不因策略内容失败：策略集入库前已全量校验，评估路径无错误分支。

## 被放弃的方案

- **逐条增量增删策略的 API**：被“整份原子替换”取代。增量 API 难以定义中间态的版本语义，也无法满足“整份策略集原子发布、任一问题整体不生效”的要求。
- **读路径加写锁或全量拷贝快照**：读锁 + 不可变快照即可保证版本完整性，拷贝每份策略集是浪费；替换时构建新快照、旧快照由 GC 回收。
- **按标签选择器建索引（如倒排索引）**：标签基数与组合不可控，索引维护复杂且收益不确定；命名空间分桶已满足“开销不随无关策略线性增长”的可证明要求，选择器只在候选集上线性检查。
- **正则表达式匹配**：规范只要求四种星号形式，引入正则既超需求又带来编译开销与注入面；用 `strings.HasPrefix/HasSuffix` 实现，O(元素数) 简单可证。
- **请求头值支持星号形式**：规范只给身份/命名空间/路径定义了星号形式，头值按精确匹配处理并在文档中显式声明，避免过度解读。
- **多值请求头要求“全部值都在正集”**：采用“任一值命中即满足”，与集合内为或的语义一致；否定集采用“任一值命中即否决”，与否定语义对称。

## 本地验证方法

```bash
# 全量测试（含竞态检测）
go test -race ./authz/

# 查看随机对照与并发测试的逐步日志（每次操作的输入、实际输出与判定）
go test -race -v -run 'TestRandomizedDifferential|TestConcurrent' ./authz/

# 性能证明：考察候选数恒定 + 基准
go test -v -run TestEvaluationCostIndependentOfUnrelatedPolicies ./authz/
go test -bench . -benchtime 1000x -run '^$' ./authz/

# 静态检查
gofmt -l authz/ && go vet ./authz/
```

测试覆盖：适用范围三判断（命名空间 / 根命名空间 / 选择器）、拒绝优先、无允许策略默认放行、空规则列表的允许策略导致全拒、空规则匹配一切、四种元素形式、方法大小写、否定否决、请求头缺失与多值、审计不改变决定、依据内容与排序、版本携带、非法策略集整体拒绝（版本不变、内容不泄漏）、重复名、按提交次序报告首个问题、版本单调、并发等价于串行（与朴素模型逐版本对照）、以及与独立朴素模型在 2000 步随机策略集/随机请求上的逐步对照。
