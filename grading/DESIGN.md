# 阅卷分配与双评仲裁引擎 — 设计说明

## 模块划分（各文件职责）
- `grader.go`/`paper.go`：评卷人、组别、配额、回避等状态；答卷、任务、终分类型。
- `allocator.go`：确定性选人，按组隔离，组内按 (在手任务数, 标识) 排序。
- `engine.go`：录入、任务发放、待分配队列、终分后关系释放。
- `state.go`：提交、分差判定、仲裁与终分、撤回、停用、只读查询。
- `errors.go`：错误分类与优先级；整数 tick 的网格靠拢 `gridRound`。

## 关键取舍
- 分数内部统一为步长整数 tick，回避浮点；半网格均值 `ceil((t1+t2)/2)`。
- 所有公开方法同一把互斥锁，并发可观察结果等价某串行序；被拒操作零副作用。
- 确定性：组名/待分配答卷/停用影响答卷均按字典序处理，任务 ID 全局递增。
- 同人单次关系在“未撤回且未终分”期内占用；撤回按剩余有效任务计数释放，终分后整卷释放。
- 配额=在手待提交任务数，提交/撤回即释放；待分配仅由录入评卷人、撤回、停用、
  仲裁触发等分配事件领走（`drainPending`），提交不触发全局重领。

## 选取代价为何不随历史增长（可验证）
- 选择谓词（活跃/配额/回避/同人单次/同卷回避）均为评卷人状态上的 O(1) 表查询；
  只扫描各组当前评卷人的有序快照，与完成任务总数、答卷总数无关。
- `TestSelectionCostIndependentOfHistory` 在 1 份与 100 份完成卷两种历史下
  计数单次选择的谓词求值次数，断言相等且不超评卷人数上界。

## 被放弃的方案
- 堆顶临时弹出再压回：易漏恢复破坏堆序（差分测试曾捕获），改只读有序快照。
- 浮点 + epsilon：不可复现，改整数 tick。
- 提交即全局重领：会改变其他答卷既有的确定性选择时序，改仅分配事件触发。

## 本地验证
```bash
go test -race -count=1 ./...
go test -run TestDifferentialRandom -v ./grading/   # 打印每步输入/输出/判定依据
```
随机差分测试用独立写成的朴素实现（全量扫描、无任何堆/索引）与引擎对照，
固定种子并循环重跑；曾由此发现并修复：撤回误释放同人占用、停用处理顺序不确定、
仲裁外提交误触发全局重领等问题。
