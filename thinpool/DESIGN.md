# 精简配置存储池空间管理服务 — 设计说明

## 1. 模块划分

代码位于 `thinpool/` 包，按职责拆分为四个协作模块：

| 文件 | 职责 |
| --- | --- |
| `errors.go` | 可区分的错误类别 `Kind`（九类）与错误值；定义全局错误报出次序 |
| `level.go` | 水位档位 `Level`、纯整数档位判定 `classify`、事件结构 `Event` |
| `runset.go` | 单卷虚拟块映射的有序合并区间集合（左闭右开），支撑 O(相交区间) 回收 |
| `pool.go` | 池级记账与全部操作：创建/写入/回收/删除/扩缩容/保留调整、快照与事件 |

测试侧另有两个模块：`naive_model_test.go` 是**独立编写的朴素逐块模型**
（每卷 `map[int]bool`，每次判定都遍历所有卷重算欠额）；
`differential_test.go` 用随机操作序列对照两种实现，
`concurrency_test.go` 覆盖并发不变量与确定性重放。

## 2. 关键数据结构与不变量

池在互斥锁内维护以下记账量：

- `allocated`：已分配物理块总数；
- `totalVirtual` / `totalReserve`：全部卷虚拟块数 / 保留块数之和；
- `totalDeficit`：全部卷欠额之和，**增量维护**，不遍历卷；
- `volumes` + `order`：卷表与稳定顺序（快照可复现）。

某卷欠额 `deficit = max(reservation - allocated, 0)`。

核心不变量（任意被接受的操作之后）：

1. `allocated <= physical`；
2. `totalReserve <= physical`；
3. `totalVirtual * 100 <= physical * overcommitPct`（超分上限，乘法整数比较）；
4. **`totalDeficit <= free`**，即全部卷欠额之和不超过空闲块数。

## 3. 关键取舍

### 3.1 分配可行性：一次 O(1) 的整数比较，不随卷数增长

对卷 `v` 的一次新分配，需求是“分配后空闲不小于**其余各卷**欠额之和”：

```
free - 1 >= totalDeficit - v.deficit()
```

`totalDeficit` 是增量维护的标量，因此无论卷有多少，一次写入的可行性判定
恒为常数时间。测试可验证这一点：`differential_test.go` 在每条 write 日志中
打印 `totalDeficit` 与“其他卷欠额”两个标量，朴素模型则逐卷遍历重算，
两侧结果在 3 万条随机操作上逐条一致。

欠额的增量规则：

- 新分配一块：仅当本卷仍处于“占用 < 保留”（分配后 `allocated <= reservation`）
  时，总欠额减一；
- 回收：总欠额增量 = `deficit_after - deficit_before`（只可能回升到保留线）；
- 删除/调整保留：按该卷欠额差值整体增减。

### 3.2 本卷保留空间可被本卷用尽

判定式只扣除**其他**卷欠额，因此当池空闲恰为全部剩余保留空间时，
占用尚小于自身保留的卷仍可分配，而别的卷会得到 `pool_exhausted`。
对应用例 `TestOwnReservationUsableOthersRejected`。

### 3.3 映射结构：有序合并区间，而非位图或物理块指针表

需求只要求精确复现“哪些虚拟块已映射”与块数，且各卷不共享物理块、
无需寻址物理块号，因此池只需一个全局已分配计数，单卷用
`[]interval{start,end}`（有序、不相交、写时合并）记录映射：

- 写入：二分定位 + 至多一次相邻合并；
- 回收：二分定位后只遍历与范围**相交的已映射区间**，支持整段释放、
  单侧残余与内部挖洞（区间分裂）。

这保证“回收开销不随范围内未映射虚拟块数增长，只随范围内已映射块
（合并后区间）数增长”。`runset_test.go` 覆盖了零长度、整段、左端、
  右端、中部裂洞与跨区间回收。

### 3.4 水位：整数乘法，取等升档，跨档一个事件

档位判定 `allocated*100 >= physical*pct`，全程无除法（超分上限同样）、
无浮点。每次成功且可能改变 `allocated` 的操作后调用一次
`noteLevelChangeLocked`：只比较旧档与新档，因此一次回收从严重直接
回到正常（跨两档）也**只追加一个**事件；档位不变不追加；
被拒绝的操作在任何状态修改之前返回，不产生事件。

### 3.5 并发等价串行：单把互斥锁

所有变更与快照在同一把 `sync.Mutex` 下完成，临界区内只做内存计算，
天然等价于某个串行顺序，且无 goroutine 本地缓存，相同操作序列重放
得到完全相同的映射与事件（`TestDeterministicReplay`）。

### 3.6 错误只报次序最靠前的一类

全局次序固定为：
参数非法 → 卷不存在 → 卷已存在 → 超分配 → 保留超池 → 保留超卷 →
卷内仍有数据 → 保留不足 → 池耗尽。

每个操作都按此次序短路返回；任何拒绝都在首次状态修改**之前**发生，
因此天然“不留痕”（`TestRejectionsLeaveNoTrace` 用快照深比较验证）。
`create` 上保留超池先于保留超卷（池级约束先于卷级约束）。

## 4. 被放弃的方案

- **每卷位图（`[]bool`/bitset）**：回收必须扫描范围内每个虚拟块，
  开销随未映射块数线性增长，直接违反需求；改为区间集合。
- **每次判定遍历各卷重算欠额**：实现简单但 write 判定随卷数 O(n)。
  保留在朴素模型中仅作为对照，生产实现改为标量增量。
- **为每个映射块记录物理块号并模拟分配器**：需求中各卷不共享块、
  只问可行性与计数，物理块身份不可观测，引入分配表纯属额外复杂度，
  故只保留全局计数（差分测试逐块核对映射集合已足够精确复现）。
- **细粒度锁 / 无锁结构**：临界区为纯内存且很短，细粒度锁会让
  欠额标量与事件序号的一致性变复杂；单锁即可提供严格可串行化。
- **先改状态再回滚**：被放弃。所有拒绝都前置校验并短路返回，
  避免回滚遗漏导致的“留痕”。
- **浮点比较水位/超分**：被明确禁止，全部改写为交叉乘法整数比较。

## 5. 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin

go test ./thinpool -v                       # 全部场景 + 区间集单测
go test -race ./thinpool                    # 竞态检测
go test -run TestDifferentialRandomSequences -v ./thinpool   # 朴素模型对照（含操作日志）
go vet ./...
gofmt -l .
```

随机差分测试执行 120 个随机配置的序列、每个 250 条操作（共 3 万条），
每条操作都打印输入、输出（OK/拒绝类别/释放数）与判定依据；
任何一次状态、逐块映射或事件序列分歧都会立即失败并打印尾部日志与随机种子。
