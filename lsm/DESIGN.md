# 分层日志结构存储的压实任务选择与安装服务 — 设计说明

包 `lsm` 实现了一个 LSM 风格分层存储的**压实计划选择（Pick）**与**结果安装（Install）**
服务。目标是让“本次该压哪些文件、为什么”可被精确复现：相同操作序列重放，
得到完全相同的计划；每个计划都附带可读的判定依据（`Plan.Reason`）与精确分数
（`Plan.Score`，`分子/分母` 形式）。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `lsm/config.go` | 静态参数（层数、L0 阈值、首层目标字节、层间倍数）与各层目标字节计算 |
| `lsm/file.go` | 文件元数据、闭区间重叠判定（端点相等算重叠） |
| `lsm/score.go` | 精确有理数分数（`big.Rat`），杜绝浮点舍入影响选择 |
| `lsm/index.go` | 非零层排序区间索引：重叠/等值查询 O(log n + k)，带比较计数 |
| `lsm/level.go` | 单层状态：文件集合、总字节、上次压实终点键；登记时的不变量校验 |
| `lsm/picker.go` | 选层、零层/非零层起点、边界闭合、下一层纳入、直接下移判定 |
| `lsm/service.go` | 对外门面：登记、选取、安装、取消；占用管理；错误优先级；并发串行化 |
| `lsm/errors.go` | 五类可区分错误及其报告优先级 |

依赖方向：`service → picker → level → index/score`，`config/file/errors` 为公共叶子。

## 关键语义与取舍

### 精确有理数打分

零层分数 = 文件数 / 触发阈值；非零层分数 = 总字节 / 目标字节（目标按固定倍数逐层
增长，用 `big.Int` 计算避免溢出）。所有比较用 `big.Rat.Cmp`，选取分数最大且不小于
一的层，并列取层号较小者。**取舍**：不用 `float64`——`1+2^-53` 会被舍入成 `1.0`
从而改变并列判定（`TestScoreExactRationalNoFloatRounding` 专门构造了该反例）。

### 起点与边界闭合

- 零层起点是**编号最小**的文件（最旧），随后按合并区间反复扩展，端点相等即算重叠；
  零层的扩展规则天然涵盖了边界闭合。
- 非零层起点是上次压实终点键之后（严格大于）区间最小值最小的文件；不存在则回绕到
  最小者。终点键只在**安装成功**时更新为本次源层输入的最大键；放弃、拒绝、取消均
  不更新。
- 边界闭合对任意层的输入集合生效：凡端点相接（一方最大值等于另一方最小值）的同层
  文件一律纳入，反复闭合到稳定——同一用户键的版本不得被劈开。闭合用索引上的
  `withMin/withMax` 二分等值查询实现，单键文件链 `[k,k],[k,k],…` 也能连锁闭合。
- 下一层先按合并区间纳入全部重叠文件，再对下一层做边界闭合；**下一层闭合带来的
  区间扩大不回流改变本层输入**（`TestNextLevelClosureDoesNotBackflow`）。

### 排序键的选择（一个被修正的取舍）

非零层索引最初按 `(Smallest, ID)` 排序。随机对照测试发现反例：同一键上共存的
单键文件 `[k,k]` 与长文件 `[k,x]` 在该序下可能让“相邻即不重叠”的检查失真。
改为按 `(Smallest, Largest, ID)` 排序后，合法集合中 `Largest` 严格单调不减，
相邻检查、重叠查询、`withMax` 二分的正确性都由此推出。该偏差正是由朴素模型
对照测试暴露的。

### 直接下移

本层输入只有一个文件且下一层**没有任何重叠文件（含端点相等）**时，计划类型为
`PlanMove`：不重写数据，安装时可用同一编号把文件改挂到目标层。下一层仅端点相等
也算重叠，必须按重写处理（`TestEndpointTouchingNextLevelIsNotMove`）。

### 在途占用与改选

计划创建（被接受）时其全部输入立即被占用。选取过程中，起点、扩展、闭合、下一层
纳入任一环节触碰被占用文件，该层本次即放弃，改选分数次高且不小于一的层；全部
冲突则计划为空（正常结果）。放弃是纯读操作，不留下任何占用或起点记录——占用
只在 `adoptPlan` 中发生。

### 安装的原子性与错误优先级

`Install` 先完成全部校验再生效，因此失败整体不生效且占用保持，调用方可修正后
重试或取消。校验按固定优先级只报最靠前的一类：
`参数非法 > 文件不存在 > 文件已被占用 > 计划不存在 > 层不变量被破坏`
（`TestErrorPrecedence` 用组合坏输入验证优先级）。成功则原子地删除输入、加入
输出、释放占用、推进终点键。

### 并发与确定性

所有公开方法用一把互斥锁串行化，天然满足“并发结果等价于某个串行顺序”。
决策路径不依赖 map 迭代序（成员表一律排序后输出）、不依赖浮点、不依赖时间，
因此重放完全一致（`TestModelRandomSequence` 用同一序列跑两遍逐条比对日志）。
**取舍**：单锁实现简单且易于论证线性一致；分片锁/读写锁被放弃，因为压实选择
本身是全局决策，读多写少的优化收益有限而正确性成本很高。

### 对数开销的可验证证明

目标层（必为非零层）的重叠查询走排序索引：二分定位最右一个 `Smallest <= hi`
的文件，再向左扫描结果集，利用 `Largest` 单调不减提前终止，开销 O(log n + k)。
索引统计每次查询的键比较次数，`TestOverlapQueryIsLogarithmic` 断言：文件数放大
100 倍（1e3 → 1e5）时比较次数仅从 13 增至 20，而线性扫描应放大 100 倍。

## 被放弃的方案

- **浮点分数**：舍入会改变并列与达标判定，见上。
- **区间树/线段树**：对“互不重叠、仅端点相接”的区间集合属于过度设计；排序切片
  + 二分即可达到 O(log n + k)，且更容易用比较计数证明。
- **选择时跳过被占用文件而非整层放弃**：会把“同一用户键不被劈开”的闭合语义变得
  不可判定（跳过中间文件可能劈开版本链），且与题面“该层本次放弃”的语义不符。
- **计划两阶段（先提议后接受）**：增加状态机复杂度而无收益；当前“选取即接受并
  占用”配合取消/重试已覆盖全部生命周期。
- **读写锁**：见“并发与确定性”。

## 本地验证方法

```bash
# 环境：Go 1.26+；若 go 不在 PATH：export PATH=$PATH:/usr/local/go/bin
# 沙箱中如缺构建缓存目录：export GOCACHE=/tmp/gocache GOPATH=/tmp/gopath

go build ./...            # 编译
go vet ./...              # 静态检查
gofmt -l .                # 格式（无输出即通过）
go test ./lsm/ -v         # 全量单测（打分/闭合/回绕/占用/下移/安装/取消/错误优先级）
go test ./lsm/ -race      # 竞态检测（含并发测试）
go test ./lsm/ -run TestModelRandom -v   # 朴素模型对照，逐条打印操作日志
go test ./lsm/ -run TestOverlapQueryIsLogarithmic -v  # 对数开销证明（打印比较次数）
```

随机对照测试的日志会打印每条操作的输入、输出与判定依据，例如：

```
op 15 Pick -> plan#2 L0->L1 move inputs=[5] next=[] score=4/3 | level 0 score 4/3 >= 1; L0 seed=file 5 (smallest ID), ...
op 17 Install plan#2 outputs=[14] -> invalid-argument
```
