# 设计说明（骑手考核与申诉系统）

1. 模块划分：`types.go` 类型；`errors.go` 可程序化错误码；`cluster.go` 事件与根因簇；
   `period.go` 周期账目、结算推进与定级；`appeal.go` 申诉、连带撤销与回溯补偿；
   `system.go` 并发入口、时钟与参数校验。
2. 时钟：单把 `sync.Mutex` 串行化所有操作；接受时刻小于已接受最大时刻报 `ErrClockSkew`，
   被拒绝操作不改时钟与任何状态。并发提交可用 `RegisterEventAtomicClock`（锁内取时刻）。
3. 成簇：同 rootKey 的存活事件进一棵 treap，键为 `(time, seq)`；新事件只与“左簇尾/右簇头”
   比较间隙，间隙 <= span 才经并查集合并。期望 O(log k)，不随骑手全部历史增长。
   无根因事件各自独立。撤销=整簇从 treap 摘除，撤销后同 span 的新事件另成新簇。
4. 计分不变量：每周期 `liveScore` 恒等于 `counting` 映射值之和；只有簇最早者在 `counting` 中。
5. 结算：任何操作/查询以 `now >= 周期右端点` 触发，顺序推进；结算时冻结分数、等级、
   计分明细快照（`frozenContrib`）与所用下降基准。权益=min(等级, 基准+MaxLevelDrop)，上升不受限。
6. 申诉：窗口 `[t, t+window)`；连带事件、已撤销、已申诉等按固定次序报第一个错误。
   成立则整簇撤销；未结算周期直接按新 `liveScore` 结算，已结算周期不改写历史。
7. 回溯：对受影响的已结算周期按冻结快照重算本应等级与本应权益，
   补偿=Σ max(0, 实际权益-本应权益) × 每级补偿额，每申诉至多一笔；
   本应权益沿已结算周期传播后写入“裁决后第一个未开始周期”的下降基准覆盖项。
8. 被放弃方案：(a) 每登记全量排序重算——O(历史)，违反性能约束；
   (b) treap 节点与簇成员节点复用同一左右指针——合并时会破坏桶结构（实测成环栈溢出），
   故桶 treap 与簇双向链表彻底解耦；(c) 撤销后让其余事件重新计分——与“连带一并撤销”语义冲突。
9. 迟到登记：发生时刻早于某已结算周期的事件仍被接受并参与当前/未来成簇与 live 账目，
   但不改写已冻结快照（结算纯为时刻的函数）。
10. 本地验证：`go test -race ./...`；`go test -run TestDifferential -v` 打印每步
    输入/输出/判定依据，并与独立全量重算朴素模型（`naive_test.go`）随机对比 40 种子×300 步。
