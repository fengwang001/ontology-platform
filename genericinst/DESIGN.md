# 泛型实例化登记与去重 — 设计说明

## 模块划分
1. `types.go` 类型实参规范化：`Nominal`/`Alias`/`Struct`/`InstanceRef` 各实现
   `CanonKey()`；别名透传到目标；结构按字段名+次序+类型编码（`strconv.Quote`
   保证定长无歧义）。
2. `normalize.go`：默认形参补齐、个数校验、`OneOf`/`SameAs` 约束、规范化键。
3. `registry.go`：登记/命中/嵌套会话/配额/并发。单一 `sync.Mutex` 串行化一切；
   嵌套复用同一临界区与会话；失败按「本次新建集合」整体撤销。
4. `graph.go`：双向依赖边、更新时沿 `depend` 反向 BFS 传播过期、清理条件。
5. `snapshot.go`/`errors.go`：同一临界区采样的汇总、稳定错误码、日志。

## 关键取舍
- 等价性用「规范化键 + 哈希表」：命中是一次 map 探测，O(1) 且与实例总数无关；
  `lookupSteps` 白盒计数器供测试证明。
- 过期传播只以「该定义仍有效的实例」为根反向 BFS，`staleVisits` 只统计受影响
  集合；过期实例立即移出命中索引但保留记录，可查询原因与传导深度。
- 单把互斥锁而非分段/无锁：操作含嵌套回调与撤销，单锁使线性一致显而易见，
  等价请求必返回同一实例，请求与更新不可能看到半成品。
- 撤销只删本次新建实例及其相关边，复用实例不动；撤销期间的命中计数一并还原，
  被拒绝请求不改变任何统计量。
- 配额（总数/单定义）在新建前判定且包含未清理的过期实例；命中不消耗配额。

## 被放弃的方案
- 逐字段 AST 比较：命中 O(实例数×字段数)，不满足 O(1)。
- 每定义独立 map：让总额度、全局撤销、跨定义依赖复杂化；单索引 `def\x00key`
  天然分区且更简单。
- 惰性过期：会让汇总与命中依赖遍历顺序，破坏「客观唯一答案」，改为更新即标记。
- 分段锁/乐观并发：与嵌套回调、整体撤销组合后正确性证明困难，收益有限。

## 本地验证
`go test -race -v ./genericinst/`；`go test -race -count=10` 重复随机与并发。
覆盖：别名/结构/默认形参等价命中；深度上限整体撤销且复用实例保全；多层过期
传导与清理依赖条件；配额取等边界；五类错误固定次序；64 路并发等价请求；
命中 O(1) 与过期只访问受影响集合的白盒断言；400 条随机序列与朴素模型
（不去重/不缓存，线性重算等价性）对有效实例多重集、命中/新建计数的对照。
