# 核保决策引擎设计说明

## 模块划分
- `types.go`：投保单、规则、条件、动作、结论等值类型，以及纯函数 `mergeDecision`（多规则命中的合并裁定）。
- `rulebook.go`：规则库。按职业类别分桶索引（不限职业的规则进入全部 6 个桶），增删改后置脏标记、查询前惰性重建。
- `engine.go`：引擎与状态机。登记即裁定并冻结快照；补充告知、再裁定、体检登记均按固定拒绝次序检查。
- `errors.go`：唯一错误类型 `Error{Kind, Msg}`，调用方以 `KindOf` 判别全部九类拒绝。

## 关键取舍
- **快照在首次裁定时冻结**：只保留申请时刻生效且年龄、职业命中的规则（深拷贝）；健康告知可增长，故告知过滤推迟到每次合并时。之后规则库的任何增删改与该投保单无关。
- **合并次序硬编码**：拒保 > 加费超限 > 延期（取最晚）> 需体检 > 承保；加费算术相加、除外取并集排序，恰等于上限/限额均不算越界。合并与规则顺序无关，另按编号排序保证可复现。
- **并发模型选全局互斥锁**：所有入口串行化，天然等价于某个串行顺序，杜绝半写入；放弃了按投保单细粒度加锁（收益小、死锁风险与复杂度高）。
- **性能靠职业分桶**：裁定只扫描投保单职业对应的桶，与年龄、职业都不相关的规则零开销；放弃了区间树等更复杂索引（桶内规则本就是“职业相关”的，扫描它们不违反要求）。
- **体检通过后限额持久视同无限制**：该投保单后续再裁定均不再触发需体检，避免“承保后补充告知又退回需体检、却无法再登记体检”的死锁。
- **延期用规则快照机械复算**：到期后再裁定被允许，但快照未变时结论仍是延期（至同一时刻），这是条文的直接推论，模型对照测试亦按此校验。

## 被放弃的方案
- 每次裁定实时读规则库 + 版本号：无法天然满足“裁定后变更不影响”，被快照方案取代。
- 错误用 `errors.Is` 哨兵值：类别多了之后组合表达力差，改用单一 `ErrKind` 枚举。

## 本地验证
```bash
go test ./underwriting/ -count=1            # 边界、拒绝次序、无痕迹、并发
go test ./underwriting/ -race -count=1      # 并发竞态
go test ./underwriting/ -run TestRandomSequenceAgainstNaiveModel -v   # 朴素模型对照（打印输入/输出/判定）
go test ./underwriting/ -run TestDecisionCostIndependentOfIrrelevantRules -v  # 性能对照（1k vs 100k）
go test ./underwriting/ -bench BenchmarkFirstDecision -benchtime 100x
```
