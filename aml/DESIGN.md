# 反洗钱现金存款结构化拆分检测系统 — 设计说明

包 `ontology/aml` 实现：识别客户把大额现金拆成多笔小额存入以规避大额申报的行为，
并在账户关联、冲正等变化下保持报告结果确定且不重复。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `config.go` | 配置与校验（`0 < L < H`、`K >= 2`、`D >= 1`，违反则创建失败并报 `ErrInvalidParam`） |
| `errors.go` | 可区分的哨兵错误，单操作内按固定优先级只报第一个 |
| `report.go` | 报告类型（大额 / 结构化）与不可变报告结构 |
| `group.go` | 客户组（并查集）、滑动窗口维护、合并、结构化评估 |
| `engine.go` | 引擎入口：操作校验与时钟、存款 / 关联 / 冲正、查询、报告发射 |
| `engine_test.go` | 边界与错误优先级单元测试、并发与复杂度证明测试 |
| `model_test.go` | 按规则字面实现的朴素模型 + 随机操作序列对照测试 |

## 核心不变式

1. **时钟单调**：被拒绝的操作不改变任何状态、报告与时钟；因此被接受操作的
   `now` 单调不减，存款日期（即 `now`）也单调不减。
2. **窗口有序**：每组的小额存款窗口切片按日期非递减排列；过期条目只会从头部
   出现，剔除均摊 O(1)（每条目至多被剔除一次）。
3. **增量统计一致**：每组的 `count / sum / uncovered` 始终等于"窗口内、未冲正"
   小额存款的笔数 / 合计 / 未覆盖笔数；存款、冲正、剔除、合并四处维护。
4. **评估不变式**：每次被接受的存款或关联之后，若判定集合成立则
   `uncovered == 0`（要么本不成立，要么刚发报告把集合全部覆盖）。因此大额与
   微小存款后的评估必为空操作，冲正（只缩小集合）无需评估。

## 关键取舍

- **并查集 + 按大小合并**：关联即合并两个客户组。组成员集合与窗口切片都从
  较小一组并入较大一组，每条窗口条目至多被迁移 O(log 组数) 次；单次关联的
  开销只取决于两组**窗口内**的条目数，与全部账户数、全部历史存款数、以及
  较大一组窗口之外的历史存款数均无关。
- **单调时钟 ⇒ 切片即窗口**：因为 `now` 单调，窗口用普通切片（队头剔除、
  队尾追加、两组合并时归并）即可，无需堆或平衡树。
- **`uncovered` 计数器**：评估时 O(1) 判断"集合中是否仍有未被任何结构化报告
  覆盖的存款"；只有确实要发报告时才扫描窗口物化交易号列表（输出本身的大小）。
- **冲正 = 标记 + 惰性剔除**：冲正只翻转标志并修正增量统计，条目留在切片中
  随过期或合并时剔除，避免切片中间删除的 O(n)。
- **报告物化且不可变**：报告在发出时记录排序后的全部账户、集合内全部交易号、
  合计、触发操作与日期；冲正不撤回报告、不恢复覆盖标记。排序保证相同操作
  序列重放得到完全相同的报告序列。
- **全局互斥锁**：所有操作在锁内完成，并发调用等价于某个串行顺序；只读查询
  走 `RLock`，并使用不做路径压缩的 `findRoot`，保证读路径无写操作。
- **查询契约**：`CurrentSet` 的 `now` 应不小于已接受操作的最大 `now`
  （"当前 now"）。引擎按增量维护窗口，不保留回答历史时刻所需的数据。

## 被放弃的方案

- **每次评估全量扫描所有存款**（朴素模型）：实现最简单，但评估开销随全部
  历史存款数增长，违反复杂度约束。仅保留在 `model_test.go` 中作为对照基准。
- **堆 / 平衡树维护窗口**：可支持任意时钟，但本题时钟单调，切片方案常数更
  小、代码更简单。
- **冲正时物理删除窗口条目**：切片中间删除 O(n)，且条目可能已随组合并迁移，
  定位成本高；改为标记 + 惰性剔除。
- **报告只记录新增未覆盖交易号**：规格要求记录集合内全部交易号与合计，放弃。
- **支持任意历史 `now` 的查询**：需要永久保留全部窗口外历史并在查询时扫描，
  与"开销不随窗口外历史增长"的要求冲突，改为明确的查询契约。

## 复杂度的可验证证明

引擎内置 `visits` 计数器（`Engine.Visits()`），统计窗口条目被访问的次数
（剔除、合并、发报告扫描）。`TestVisitsBound` 断言：

1. 5000 笔窗口外（微小）存款产生 **0** 次窗口访问 —— 开销不随全部历史存款数增长；
2. 200 笔窗口内存款的评估访问次数 ≤ 2×200 —— 单笔评估均摊 O(1)；
3. 时钟前进后一次性剔除 200 条过期条目，每条恰好 1 次 —— 均摊 O(1)；
4. 与拥有 5200 笔窗口外历史的大组关联，访问次数 ≤ 10 —— 关联开销与较大一组
   窗口之外的历史无关；
5. n ∈ {1000, 2000, 4000} 时总访问次数 ≤ 3n —— 整体线性，无隐式平方项。

## 本地验证方法

```bash
go test ./aml/            # 全部单元测试 + 20 个种子 × 1500 步随机对照
go test ./aml/ -race      # 并发线性一致性与数据竞争检测
go test ./aml/ -v -run TestRandomizedAgainstModel  # 打印每步输入、输出与判定依据
go test ./aml/ -v -run TestVisitsBound             # 打印复杂度计数证据
gofmt -l . && go vet ./...
```

随机对照测试对每个操作比较引擎与朴素模型的返回值（报告全字段、错误类别），
并周期性比较 `CurrentSet` / `GroupAccounts` 查询结果，终态比较完整报告序列。
