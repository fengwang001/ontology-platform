# 重复投保分摊赔付引擎 — 设计说明

金额单位为分（`int64`），区间 `[StartDay, EndDay)`。

模块：`policy.go` 值对象+校验+独立责任额；`allocate.go` 纯函数两阶段裁定
（只吃本次快照）；`engine.go` 账目/撤销/并发/日志；错误码同在 `policy.go`。
拒绝次序：参数非法 > 被保人不存在 > 保单重复 > 损失已存在 > 损失不存在 > 非末笔。

关键取舍：
- 权重：限额比例型取 `min(每次限额, 年度剩余)`；组内出现任一独立责任型，
  整组改按 IL；超额型仅第二阶段按 IL。
- 取整：比例份额全部向下取整；份额超 IL 者先钉顶、挤出部分按同比例重开轮次再分；
  尾差逐分给「IL 最大、编号字典序最小」者。每单最多达顶一次，O(k²) 且确定。
- IL 恒按整笔损失金额计算，第二阶段仅按 IL 比例切剩余目标，使 IL 定义唯一；
  合计双重封顶于损失金额与各 IL 之和；IL 全 0 时受理但账不变。
- 年度剩余恰为 0 的保单构造快照时即剔除（不入分母）；无参与者以「无可赔保单」
  受理，损失号在册、可撤销；撤销仅限末笔，恢复=加回逐单扣减额。

并发：全局锁护元数据，每被保人一把账户锁护账目；受理/撤销嵌套顺序统一为
「账户锁 → 全局锁」；不同被保人真并发，同一被保人等价于某串行顺序。

被放弃方案：浮点比例（不可复现，改为整数乘除+尾差裁定）；产品代码用 big.Rat
（与取整规则重复且慢，仅朴素对照模型保留）；分摊扫描历史（只维护当前剩余额，
历史仅用于 O(1) 末笔撤销）。

本地验证：
- `go test ./...`：区间右端、恰好耗尽、再分配、模式切换、超额接棒、尾差并列、
  双封顶、撤销、拒绝次序逐对。
- `go test -run TestDifferentialRandom -v`：400 组随机序列与 big.Rat 朴素模型对账。
- `go test -race ./...`：8 goroutine 同被保人受理+撤销、32 被保人并发。
- `go test -run '^$' -bench BenchmarkAcceptScaling`：历史 10/400 笔×
  他人保单 0/4000 三档，ns/op 不随两维度增长。
- `NewEngine(io.Writer)` 传非 nil 即打印输入、逐阶段权重/IL/应赔与余额。
