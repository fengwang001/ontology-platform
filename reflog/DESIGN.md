# 引用日志对象保留与回收子系统 — 设计说明

## 模块划分
- `types.go` 公共类型与错误（错误按声明次序排列）；`store.go` 对象库（首次写入时刻、祖先集合）。
- `refs.go` 单条引用的日志：按可达/不可达两档分片；`expire.go`/`gc.go` 过期与回收内核。
- `system.go` 门面：参数校验→时钟→引用→提交→记录的错误次序、单调时钟水位、读写锁。

## 关键取舍
- 每条引用的记录按档位分成两个按 (时刻,序号) 有序的切片。过期 = 二分查找切前缀，
  代价 O(log n + 过期条数)，与未过期条数无关；回收同样二分跳过已过期前缀，
  单个对象的存活判定是哈希表查询 O(1)，与日志总量无关（基准可复现）。
- 档位在引用移动/删除/重建时重算：对新头做一次 DAG 遍历物化祖先集合，再 O(记录数)
  重分片该引用的日志。用更新时的 O(记录数) 换过期时的 O(log n)。
- 过期记录只做逻辑失活，物理删除由过期操作执行；被 GC 删除的提交只会出现在已过期
  记录中（未过期记录必保活其新旧值），故档位不会因 GC 而失效，无需回扫。
- 引用当前值、未过期记录的新旧值都是存活根；从根沿父边与内容引用遍历即存活集。
  候选对象年龄 >= 新鲜宽限才删除（取等可删）；记录年龄 >= 档位期限即过期（取等）。
- 并发：全部写操作一把互斥锁串行化，查询走读锁，任意交错等价于某串行顺序；
  同时刻同引用的并发更新按取锁先后追加，序号递增保证日志次序确定。
- 时钟为系统级单调水位：被接受的调用推进水位；被拒绝的调用不追加、不删除、不推进。

## 被放弃的方案
- 单切片 + 原地过期标记：查询「现存第 k 条」与物理删除都退化为全扫，放弃。
- 过期时临时扫描全部记录判档位：违反「过期开销不随未过期记录数增长」，放弃。
- 每引用一把锁的细粒度并发：时钟水位与 GC 根快照是全局不变量，维护成本高，放弃。
- 已删引用墓碑独立存储：直接保留 logs 条目（当前值置空）即可共用日志，放弃。

## 本地验证
- `go test ./reflog/ -v`：功能用例（边界取等、合并历史归档、幂等、合并等价等）。
- `go test ./reflog/ -race`：并发更新/回收/查询的串行等价与不变量。
- `go test ./reflog/ -run TestRandomModelComparison`：3000 步随机序列对拍朴素模型。
- `go test ./reflog/ -run xxx -bench . -benchtime 100x`：过期与 GC 耗时随记录数平坦。
