# 对象生命周期状态机：到期迁移惰性结算子系统 — 设计说明

代码位于 `lifecycle/`，纯 Go 标准库实现，无外部依赖。

- `types.go`：类型 / 迁移 / 前置条件（Guard）/ 跨实例联动（Cascade）声明。
- `engine.go`：惰性结算引擎（生产实现）。
- `history.go`：只追加的实例历史与历史时刻重放。
- `scanner.go`：独立实现的朴素周期扫描模型，仅用于随机对拍。
- `errors.go`：四类错误与固定优先级。
- `clock.go`：可手动拨快 / 拨回的时钟。

## 1. 核心模型

### 1.1 每个实例只保存“当前状态 + 逻辑进入时刻”

到期判定只使用一个时钟来源：实例当前状态的逻辑进入时刻 `enteredAt`。

到期迁移在时刻 `due = enteredAt + Duration` 逻辑上发生。惰性结算时，新状态
的进入时刻被**确定性地回填为 `due`**，而不是被访问的墙钟时刻。回填值在结算
实际发生时才确定（它由上一个状态的进入时刻推出），结算发生前不依赖任何后台
扫描。真正访问的墙钟时刻单独记录在 `Entry.SettledAt`，仅用于审计，绝不参与
到期计算。

选择回填（logical fire time）而非“访问时刻”的理由：

1. 状态作为时间的函数与访问模式无关，这正是“历史时刻重推导出的状态必须与当时
   真的发生惰性结算一致”的前提；
2. 它让惰性模型和朴素扫描模型在同一时间线上天然可对拍；
3. 多步链路的每一环时限都从上一环的逻辑到期点起算，不会因晚访问而被压缩。

被放弃的替代方案：把新状态进入时刻设为访问时刻。该方案下，一条 1h→2h 的链
路在 4h 后才被访问时，第二环的到期点会被推迟到访问之后，导致“应处状态”依
赖访问历史，历史重放无法与扫描模型对齐，因此放弃。

### 1.2 结算只追加事实，从不扫描历史

每次状态推进都向只追加历史 `History` 追加一条不可变 `Entry`（含 `At` 逻辑进
入时刻、`SettledAt` 实际结算时刻、`DueAt`、迁移 id、代数 generation）。

结算路径**只读取实例当前内存态**（`state` / `enteredAt`）与类型声明，时间复
杂度为 O(本次新结算环节数)，与历史上已发生的到期迁移总数无关。代码中唯一会
遍历历史的操作是显式的 `StateAt` 历史查询，它计入 `Metrics.HistoryScans`；
`TestSettlementCostIndependentOfHistoryLength` 用一个自循环迁移构造 50 条历
史后，断言再结算一步时 `NewlySettledSteps == 1` 且 `HistoryScans == 0`，
不遍历历史即得证。

### 1.3 惰性结算点

`Read` 与 `Action` 在持锁后做的第一件事都是 `settle(root, trigger)`：

- `Read`：先结算，再返回快照（即便结算产出错误，也返回已结算到的状态）。
- `Action`：先完整结算；只有在**结算后状态**上才判定显式迁移的源状态与
  Guard。任何结算/动作错误都使动作不生效；动作被拒绝不改状态、属性或时间戳，
  但本次调用已经结算生效的到期迁移保留（它们是既成事实）。

`settleOne` 对单个实例沿迁移链循环推进，直到“没有到期迁移 / Guard 不满足 /
时钟异常”之一才停止，因此一次访问可正确穿过多步到期链路，且每一步都经过中
间状态（历史中可见完整的 `A→B→C`，不会跳成 `A→C`）。

### 1.4 到期环上的非时间前置条件

到期迁移可带 `Guard`（读取自身/他实例属性、Ref、有向链接）。到期但 Guard 不
成立时：

- 停在原状态，记 `KindGuardBlocked` 错误并在日志里输出一条 `Fired=false` 的
  判定记录；
- **不推进 `enteredAt`**：判定所用时钟来源保持指向当前状态，下一次访问以同一
  到期点重新评估外部条件，条件一旦成立即继续推进，不会“吃掉”这次时限。

### 1.5 跨实例链式联动

到期迁移可声明 `Cascade{Target, Transition}`：该环一结算，就强制目标实例发生
指定迁移。强制迁移：

- 是义务性的，不评估目标迁移自身的 Guard（声明即表达系统义务）；
- 其逻辑进入时刻加盖**触发环的逻辑到期时刻**，因此链上所有环保持声明的因果/
  时间次序；
- 可递归：被强制的迁移自身也可再声明 Cascade，整链在同一次结算中按声明顺序
    推进（历史种类记为 `EntryCascade`）。

顺序保证（入口无关）：`settleOrder(root)` 依据“当前待结算到期迁移的 Cascade
边”构造反向邻接，再从 `root` 做 DFS，严格先访问上游、后访问下游；无关实例按
id 确定序打破平局。于是即使调用入口是链路中段（如 `b`），也会先结算 `a`，再
强制 `b`、再联动 `c`。Cascade 目标无法解析 / 目标不存在 / 目标当前状态不启用
该强制迁移时，记 `KindCascadeFailed`；触发环本身已提交，不回滚。

被放弃的方案：

- *每实例独立锁 + 按需等待*：跨实例死锁风险高、顺序难论证；当前实现用单把引擎
  锁串行化所有结算，以可证明的“一次结算生效”换取简单正确，吞吐可后续按实例
  分区优化。
- *全局拓扑预计算*：Cascade 目标可依赖动态属性/链接，静态拓扑不存在；改为每次
  调用按当前物化态构造闭包（闭包大小与本系统实例规模有关，与任一实例的历史
  长度无关）。

### 1.6 时钟回退

`enteredAt` 与历史只增不减。已结算迁移是不可逆事实：时钟回退后：

- 已到达的状态、已追加的历史、已推进的进入时刻一律不撤销；
- 若当前时间早于物化的 `enteredAt`，新的到期判定无法给出可靠时间跨度，记
  `KindClockRegression` 并停止本次后续判定与动作准入；时钟恢复后自动正常。

### 1.7 并发去重

引擎用 `sync.Mutex` 串行化所有 `Read/Action`。并发命中同一实例时，只有第一个
调用执行结算并追加历史，其余调用在锁后看到已物化状态、新增 0 步。
`TestConcurrentSettlementDedup` 在 64 个并发 goroutine 下断言历史长度恰为
`init + 迁移数`、`NewlySettledSteps == 2`。

### 1.8 历史时刻查询

`StateAt(id, t)` 只对不可变历史按 `Entry.At`（逻辑时间，忽略 `SettledAt`）做
线性重放，返回 `t` 时刻应处状态；不加锁修改任何东西，也不看当前物化态。由于
惰性与扫描两种模型产生同一条逻辑时间线，重放结果与“当时若访问会惰性结算出的
状态”一致，见 `TestStateAtReplayMatchesLazyResult`。

## 2. 错误分类与固定优先级

| 优先级 | Kind | 触发情形 |
|---|---|---|
| 1（最高） | `time_guard_blocked` | 到期链路某环非时间 Guard 不满足，停止推进 |
| 2 | `cascade_failed` | 跨实例联动目标无法解析/不存在/迁移不启用 |
| 3 | `action_precondition_failed` | 结算后显式动作源状态或 Guard 仍不满足 |
| 4 | `clock_regression` | 当前时间早于已物化状态进入时刻 |

一次调用可能收集多条错误（链路 + 动作），`ErrorList.Primary()` 按上表固定优先
级返回，插入顺序不影响结果；同优先级保留结算因果上的第一条。被拒动作零副作
用，此前已结算的到期迁移保留。

## 3. 日志

`Logger` 接口在每次结算时打印：输入（当前时间、触发源、入口实例、实例结算次
序）、每个推进环节（实例、种类、迁移、From→To、DueAt、逻辑生效时刻、是否真正
触发、判定依据）、以及错误与优先级。`NewStdLogger(w)` 提供文本实现；测试通过
`t.Logf` 输出，`go test -v` 可见。

## 4. 朴素扫描模型与随机对拍

`Scanner` 独立重写全部规则（不调用 `Engine`）：虚拟时间按 tick 前进，每轮反复
扫描全部实例，推进任何到期迁移（含联动）直到一整轮无变化。

`TestRandomDifferential`（默认 40 个种子 × 300 步 × 4 实例）随机生成：

- 每实例独立的 1–5 分钟到期时长；
- 时间跳跃、Guard 开关、链接 / Ref 增删；
- 随机入口的读取与随机过去时刻的 `StateAt`。

两个模型接收完全相同的事件流，在每次访问与每次历史探测点比较状态，任何不一致
即带种子、步数、实例、时间戳失败。修改模型后可用 `go test -run TestRandomDifferential`
复现；把 runs 调大可加强对拍。

## 5. 关键取舍总览

- 逻辑到期时刻回填（1.1）换取访问无关的确定性时间线与可对拍性。
- 单引擎锁串行结算（1.7）换取并发正确性的可证明性；预留按实例分区的优化空间。
- 强制 Cascade 不看 Guard（1.5），区分“系统义务联动”与“带条件的到期迁移”。
- 每状态至多一条到期迁移（注册期校验），使惰性链无需任何历史扫描即可确定。

## 6. 本地验证

需要 Go 1.26+（仓库根 `go.mod` 要求 1.26.5）。

```bash
go test ./...
go test -race -v ./...
go test -run TestRandomDifferential -v ./lifecycle/   # 对拍 + 结算日志
gofmt -l . && go vet ./...
```
