# 门架计费服务设计说明

## 模块
- `types.go`:错误(按优先级定义)、配置、记录/调整/结果类型。
- `network.go`:有向路网;Dijkstra 求 (费用, 门架序列) 字典序最小的简单路径。
- `vehicle.go`:车辆、车型变更(按生效时刻排序)、行程、同门架去重。
- `settlement.go`:路径推定(途径点分段)、差额调整、月度台账。
- `service.go`:操作入口;互斥锁串行化;时钟校验;错误按优先级只报一类。
- `toll_test.go` 边界场景;`model_test.go` 独立朴素模型 + 随机对照。

## 关键取舍
- 串行化:单互斥锁,所有操作等价于某串行顺序;时钟只在接受操作时前进,被拒绝的操作不改任何状态。
- 途径点 = 入口 + 落在 [入口, 出口] 的有效记录(按记录时刻+到达序号排序) + 出口;逐段最短路拼接,
  字典序贪心正确:拼接序列的序由前段决定。只枚举简单路径(零费率环会使字典序下界不存在)。
- 车型取"路段起点门架经过时刻":有记录门架取记录时刻,无记录门架继承所在区间起点途径点时刻,
  使费用与路径选择无循环依赖,推定与重算用同一规则,可精确复现。
- 调整同步落账:差额>0 补扣(受月封顶约束,未收部分记 CappedUncollected),<0 退款
  (不使当月实收<0,溢出记 RefundOverflow),=0 不产生调整;因此任意串行位置
  "实收 = 全额重算经封顶修正后的值" 恒成立,无待补扣队列。
- 行程按 ID 直查(map),查询 O(1);BenchmarkQueryJourney 验证 100/10000 行程耗时持平。
- 重复判定按到达时已保留记录对称比较,间隔 < 窗口为重复,= 窗口独立;重放同一操作序列结果一致。

## 被放弃的方案
- 按里程插值推算无记录门架经过时刻:引入路径-费用循环依赖,且规格未定义,放弃。
- 迟到记录乱序到达时"保留最早一条"地替换已保留记录:会回溯修改已结算依据,与
  "重复记录不触发重算"冲突,改为到达序对称去重。
- 事件溯源 + 异步补扣队列:重放虽天然可复现,但查询需折叠事件流,复杂度远超收益。
