# directorycache

目录式缓存一致性协议模拟器。

## 模型

- `New(N, C)` 创建 `N` 个私有缓存，每个缓存最多容纳 `C` 个块；`N <= 0` 或 `C <= 0` 会被拒绝。
- 块号是非负整数，所有块初值为 `0`，内存保存每个块最近一次没有缓存修改者时的值。
- 缓存行状态为 `Shared` 或 `Modified`。
- 目录按块记录持有者集合 `holders` 以及可选修改者。共享行可被静默淘汰，因此 `holders` 允许包含已经不再实际持有该块的缓存；向这些成员发失效时计为空失效。

## 读操作

- 共享或修改行命中：返回本地值，`Hit=true`，刷新该行的 LRU 顺序，不发送消息。
- 读缺失且容量已满：先淘汰本缓存 LRU 队首，再处理缺失。
- 读缺失且目录有修改者：修改者把当前值写回内存并降级为共享；新读者从内存取值并进入共享状态；目录持有者集合变为原修改者和新读者。
- 读缺失且无修改者：新读者直接从内存取值并加入目录持有者集合。

## 写操作

- 修改行命中：本地写入，`Hit=true`，刷新 LRU 顺序，不发送消息。
- 非修改行写入都算缺失：共享升级、目录无记录或缓存未持有都走写缺失流程。
- 写缺失且本地没有该行、容量已满：先淘汰本缓存 LRU 队首。
- 目录先让修改者写回内存，并把修改者的失效放在其他成员之前；随后向持有者集合中除写入者以外的每个成员发送失效。
- 发给已静默淘汰该块的成员计为一条空失效；写入者自己不收失效。
- 最后写入者以 `Modified` 状态持有新值，目录持有者集合仅包含写入者。

## 淘汰规则

- 共享行淘汰是静默的：不写回内存，也不通知目录，因此目录中可能留下过期成员。
- 修改行淘汰时写回内存，并从该块目录持有者集合及修改者记录中移除。
- 读命中和写命中都会把命中的行移动到 LRU 队尾；缺失新装入的行位于队尾。
- 非法参数在任何状态变更前拒绝，拒绝顺序为：缓存编号越界、块号为负。

## API

```go
sim, err := directorycache.New(4, 2)

readResult, err := sim.Read(cacheID, block)
writeResult, err := sim.Write(cacheID, block, value)
```

`Result` 包含：

- `Value`：本次读返回值，或本次写入值。
- `Hit`：是否命中本地缓存行。
- `Invalidations`：本次发送的失效条数。
- `EmptyInvalidations`：其中发给已不持有者的空失效条数。
- `Writebacks`：本次修改者降级或修改行淘汰导致的写回条数。

`Read` 和 `Write` 可并发调用；模拟器内部串行化每个完整操作，因此等价于某个全序交错，重放相同操作序列会得到相同结果。

## 本地验证

```bash
# 普通测试；-v 会打印随机测试的输入、输出和判定依据
go test -v ./directorycache

# 竞态检测与全量测试
go test -race -v ./...

# 静态检查
go vet ./...
```

测试覆盖修改者被读降级写回、共享升级不给自己发失效、静默淘汰导致空失效、修改行淘汰写回、命中刷新 LRU、拒绝操作无副作用、并发调用、随机操作与单一内存参照对拍，以及相同操作序列重放。
