# 分层备份保留管理服务 — 设计说明

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `types.go` | 公共类型：`Policy`、`Reasons`（保留原因位集）、`ErrorKind`（可区分错误类别，声明顺序即报告优先级）、`Plan`。 |
| `calendar.go` | UTC 周期序号：日（整日）、周（周一起始）、月（公历月）。 |
| `retention.go` | 纯函数计划引擎：可恢复性判定、三层代表选取、保留原因传播、确定顺序输出。 |
| `service.go` | 服务门面：状态持有、单调时钟、错误优先级校验、清理执行、互斥锁串行化。 |
| `model_test.go` | 独立编写的朴素模型 + 随机操作序列对照测试（逐条打印输入/输出/判定依据）。 |
| `complexity_test.go` | 以步数统计验证线性复杂度的白盒测试与基准。 |

## 关键取舍

1. **登记顺序即拓扑序。** 父备份必须先登记，且时钟单调 ⇒ 登记顺序中父必先于子、创建时刻非递减。因此：
   - 原因为传播只需**逆序**遍历一次登记序列（子 → 父），每个备份访问一次；
   - 计划输出天然按创建时刻非递减，只需在**等时刻段内按标识排序**（插入排序），避免对全量备份做 O(n log n) 排序。
2. **可恢复性记忆化 + 迭代解析。** `recoverable(b) = !corrupted(b) && recoverable(parent)` 沿链向上行走并记忆化，每个备份只解析一次；用显式栈而非递归，2 万层深链不爆栈。
3. **原因传播用两个下行标记。** `legalDown`（自身或后代被法律保留）、`depDown`（自身或后代被直接保留）逆序向父传播；祖先分别得到 `ReasonLegalHold` / `ReasonDependency`，与直接保留原因位自然区分且可叠加。
4. **计划引擎是纯函数。** `computePlan(recs, order, policy, now)` 不触碰服务状态；`PlanCleanup` 只读（仅推进时钟），`ExecuteCleanup` 用同一函数算出计划后删除，二者结果必然一致，幂等性（第二次不删任何备份）由“保留集合在删除后不变”直接推出。
5. **时钟语义。** 所有带时刻的操作（含只读计划）共享一个单调时钟：被接受的操作把时钟推进到其时刻，被拒绝的操作不改变任何状态与时钟。错误检查严格按优先级：参数非法 → 时钟回退 → 标识重复 → 父备份不存在 → 时序矛盾 → 备份不存在 → 层数量越界，只报最靠前的一类。
6. **并发。** 单互斥锁串行化全部操作，等价于某个串行顺序；无共享可变状态泄漏（计划引擎操作的是服务持有的内部记录，锁内完成）。

## 被放弃的方案

- **逐备份沿链上溯判定可恢复性/传播原因**：实现最简单，但深链下是 O(n × 深度)。仅保留在 `model_test.go` 的朴素模型中作为对照基准。
- **计划输出整体排序**：简单但引入 O(n log n)；利用“登记顺序创建时刻非递减”只做等时刻段内排序，保持线性。
- **递归实现可恢复性解析**：代码更短，但深链会爆栈，改为显式栈迭代。
- **读操作不推进时钟**：曾考虑只读计划不触碰时钟，但规范明确“被拒绝的操作不得改变任何状态与时钟”隐含被接受操作（含只读计划）推进时钟；统一处理更简单、更可复现。

## 结构性说明

- **时序矛盾（子早于父）在本设计下不可达**：父备份登记时已把时钟推进到其创建时刻，此后任何操作的时刻都不小于该值，因此子备份创建时刻必然 ≥ 父备份。`ErrTimeOrder` 检查仍保留在登记路径上作为防御性守卫，错误类别完整可区分。
- **法律保留不受可恢复性限制**：`held` 标记独立于损坏标记参与原因传播，损坏备份及其祖先同样可因法律保留而保留。

## 本地验证方法

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache   # 默认构建缓存只读时

go test ./backup/...                 # 全部单元/场景/对照测试
go test -race ./backup/...           # 并发冒烟（互斥锁串行化）
go test -v -run TestDifferentialRandom ./backup/   # 查看 2 万条随机操作对照日志
go test -v -run TestPlanLinearComplexity ./backup/ # 线性复杂度步数断言
go test -run xxx -bench . ./backup/                # 登记 O(1) 与计划线性基准
gofmt -l . && go vet ./...
```

复杂度证明方式：`computePlan` 接受 `*planStats` 统计关键步数，
`TestPlanLinearComplexity` 断言在 1/10/1000/20000 层深链下，
可恢复性解析与原因传播步数都**恰好等于备份总数**（每个备份只访问一次），
从实现层面排除了平方行为；`BenchmarkRegisterBackup` 展示登记耗时
不随已登记总数增长。
