# 行宽适配排版引擎 — 设计说明

`pretty` 包实现一个 Wadler/Prettier 风格的代码格式化排版引擎：调用方构造
不可变的文档树，引擎按给定行宽把树渲染成文本——放得下的结构平铺，放不下
的结构在其可断点处换行并缩进。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `doc.go` | 文档树节点类型与构造器。节点不可变，可跨会话、跨渲染共享。 |
| `width.go` | 码点宽度规则（≥ U+2E80 为 2，否则为 1）。 |
| `errors.go` | 五类可区分错误（哨兵错误，用 `errors.Is` 判定）。 |
| `analyze.go` | 渲染前分析：参数校验 + 逐节点注解（平铺宽度、首个强制换行前宽度、是否含强制换行、是否含断点、展开后深度）。迭代后序遍历，不递归。 |
| `session.go` | 会话：命名片段的登记（校验 + 拒绝不改状态）与一致性快照。 |
| `render.go` | 渲染引擎：命令栈主循环、`fits` 放得下扫描、逐行修剪与超宽行统计。 |

## 核心算法

### 渲染主循环（render.go）

经典的三元组命令栈 `(缩进, 模式, 文档)`，但栈用**持久单链表**（`frame`）
而非切片。处理到组时做一次 `fits` 判定，决定该组平铺还是断开，然后把组内
容以决定的模式压栈。对齐节点在进入时把当前列记为新的缩进量；缩进节点在
外层缩进上累加。换行时输出 `\n` 加当前缩进量的空格。

### 放得下判定（fits）

`fits(剩余宽度, 组内容, 后续命令链)` 从当前列起累计宽度，遇到以下情况停止：

- 处于断开模式的可断点（含不在任何组内的可断点）→ 放得下与否看累计值；
- 强制换行 → 同上；
- 文档结束 → 同上；
- **累计宽度一旦超过剩余宽度立即返回放不下**（考察量与后续内容规模无关）。

后续内容里尚未轮到决策的组按平铺计入宽度。为了不逐节点展开这些组，
`analyze` 阶段为每个节点预算了三个注解：

- `flatW`：子树平铺宽度（上限 10001，超过行宽上限即等价于“放不下”）；
- `headW`：平铺到第一个强制换行为止的宽度；
- `hasHard`：子树是否含强制换行（含强制换行的组直接断开，不做判定，且该
  性质沿树向上传播，使所有外层组同样断开）。

扫描遇到未决策的组时：无强制换行 → 直接加 `flatW`（O(1)）；有 → 加
`headW` 并停止。因此**嵌套再深的组链，每层的判定都是 O(1)**，总开销不随
深度平方增长。纯文本子树（`hasStop=false`）同样被 O(1) 跳过。

### 行尾空格与超宽行

渲染按行增量构建：换行时把当前行的行尾空格剥掉再写入输出（只含缩进的行
因此输出为空行），同时统计修剪后宽度——超过行宽的行记入超宽清单（行号
升序自然满足），累计修剪后总宽度超过 10^7 立即以 `ErrOutputTooLarge`
中止。超宽不是错误，内容不丢弃。

## 错误与优先级

`Render` 的检查顺序即优先级：

1. `ErrInvalidArgument`：行宽 ∉ [1, 10000]；随后 `analyze` 一遍扫描发现
   的负缩进、含换行的文本、空片段名引用、空节点；
2. `ErrTooDeep`：引用展开后嵌套深度 > 1000（引用按“就地替换”计深度，
   即引用节点本身不额外增加一层；未登记引用按叶子计，使深度检查可以先
   于未登记检查完成）；
3. `ErrUnregisteredRef`：引用未登记的片段；
4. `ErrOutputTooLarge`：渲染结果修剪后总宽度 > 10^7（渲染中增量检查，
   超限立即中止）。

`Register` 的优先级：`ErrInvalidArgument`（空名、非法文档）→
`ErrDuplicateName` → `ErrUnregisteredRef`（片段引用了未登记片段）。
登记时强制“片段只能引用已登记片段”，因此引用图天然无环，渲染展开必然
终止。所有校验在写入前完成，**被拒绝的操作不改变会话状态**。

## 并发模型

- 文档树构造后不可变，渲染不写树；
- `Session` 用 `sync.RWMutex` 保护片段表；`Render` 在读锁下**复制一份
  快照**后释放锁，整个渲染只读快照；
- 登记在写锁内完成“查重 + 引用检查 + 写入”，因此所有已接受操作等价于
  某个串行顺序，渲染看到的是该顺序某个前缀的一致快照。

## 关键取舍

1. **注解按渲染现算，而不是缓存在节点上。** 引用展开依赖会话快照，同一
   节点在不同会话/不同时间的注解可能不同；每次渲染 O(n) 重算既保证正确
   又保持节点不可变、免锁共享。
2. **持久链表命令栈。** fits 需要考察“后续内容”；若每次判定都拷贝剩余
   命令栈，深嵌套（如 1000 层 Seq）会变成 O(深度²)。链表让 fits 直接从
   当前帧指针往后走，零拷贝。
3. **迭代代替递归。** 分析、渲染、fits 全部用显式栈/循环；深度 1001 的
   文档返回 `ErrTooDeep` 而不是栈溢出（深度检查本身也必须能在任意深的
   输入上运行）。
4. **逐行增量修剪，而不是渲染后二次处理。** 换行时即修剪并累计总宽度，
   使“输出过大”可以在渲染中途精确中止（例如 2²² 倍共享片段的指数展开
   在 10^7 处即停）。另设原始发射量安全上限 10^8：病态的“整行都是行尾
   空格”输出即使修剪后不超 10^7，也会在 10^8 处按输出过大拒绝，防止
   内存耗尽——这是唯一与字面语义的偏离，仅影响纯空格超巨量输出。
5. **fits 的组注解坍缩。** 未决策组用 `flatW`/`headW` 整体计入，是消除
   深度平方开销的关键；同时扫描在累计超宽时立即返回，考察量不随后续
   内容规模增长。

## 被放弃的方案

- **递归渲染/递归 fits**：实现最简单，但深度输入会栈溢出，且深度检查
  本身无法安全运行，放弃。
- **fits 拷贝后续命令切片**：每组 O(栈深) 拷贝，深嵌套 O(深度²)，放弃。
- **节点上缓存注解（sync.Once）**：注解依赖会话片段表，缓存会跨会话
  串味；加锁又破坏只读共享，放弃。
- **预计算“断点传播”改写树（prettier 的 propagateBreaks）**：需要复制
  或改写文档树，违背不可变性；改为分析阶段只算 `hasHard` 位，渲染时
  查表，等价且零改写。
- **渲染完整字符串后统一修剪**：无法中途精确中止超大输出，内存风险大，
  放弃（改为逐行增量）。
- **按宽度桶缓存 fits 结果**：fits 结果依赖后续命令链指针与剩余宽度两
  个维度，命中率低且内存不可控，放弃。

## 复杂度

设文档（展开后去重）节点数为 n，行宽 W ≤ 10000：

- 分析：O(n)（DAG 上迭代后序，每节点合并一次）；
- 渲染主循环：每节点处理 O(1) 次；
- fits：每次判定在累计宽度超过剩余宽度时立即停止；嵌套组经注解坍缩为
  O(1)；总开销 O(n · W) 上界，其中 W 有硬上限 10000，实测为近线性
  （见下）。病态情形（大量零宽兄弟组连续排列且全部放得下）理论上是
  O(n²)，这是所有贪心 pretty printer 的共性问题，实践中被行宽截断。

## 本地验证方法

```bash
# 全量测试（含竞态检测）
go test -race ./pretty/

# 随机对照测试的详细日志：每个随机文档的输入、输出与逐组判定依据
go test ./pretty/ -run TestRandomDocsMatchNaiveModel -v

# 线性开销的机器可验证证明（fits 扫描步数探针）
go test ./pretty/ -run 'TestFitsScan|TestDeepNesting' -v

# 模糊测试：引擎 vs 朴素模型
go test ./pretty/ -run FuzzRenderMatchesNaive -fuzz FuzzRenderMatchesNaive -fuzztime 60s

# 基准：宽文档与深嵌套
go test ./pretty/ -bench . -run XXX
```

测试体系：

- `render_test.go`：规格逐条的确定性用例（取等放得下/多一列断开、后续
  内容影响判定、外层断开截断、强制换行传播、对齐+缩进、条件文本、双宽
  字符、行尾修剪、超宽清单、片段等价、全部错误与优先级、输出过大）；
- `random_test.go`：独立朴素模型（逐组穷举平铺渲染并实际量宽，按规则
  选定模式）+ 300 个带种子随机文档对照 + fuzz 目标；日志打印每次输入、
  输出与判定依据；
- `scale_test.go`：并发渲染/登记（-race）、fits 步数探针的线性证明
  （深度 100..800 步数恒等于深度；5 万节点文档步数 = 2n）、深度边界
  （1000 通过 / 1001 拒绝）、基准。
