# 行宽适配排版引擎设计说明

`pretty` 包把调用方构造的文档树按给定行宽渲染成文本：能放进一行的
结构放在一行，放不下的结构在其可断点处换行并缩进。本文档记录模块
划分、关键取舍、被放弃的方案与本地验证方法。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `doc.go` | 文档树节点类型、构造函数（不可变、nil 归一化、序列拍平）、码点宽度函数 |
| `errors.go` | 错误类别（`ErrCode`）、错误类型（`Error`）与优先级约定 |
| `session.go` | 会话：片段登记表的并发安全存取、一致快照、公开 API 入口 |
| `validate.go` | 渲染前只读分析通道：参数校验、深度计算、未登记引用收集、扫描剖面预计算 |
| `render.go` | 迭代式渲染引擎：工作清单解释器、组的放得下判定、行尾空格裁剪、超宽行清单、输出上限 |

数据流：`Render` 先做行宽等直接参数校验，然后取登记表快照，
`analyze` 对文档树（含引用展开）做一次迭代式后序遍历产出逐节点
标注，最后 `render` 用标注驱动渲染。渲染只读文档树与快照，不改变
会话状态。

## 渲染模型

引擎是工作清单（显式栈）上的解释器。每个条目携带：

- **缩进量**：换行后新行开头的空格数。缩进节点累加增量，对齐节点
  把它重置为进入该节点时的当前列。
- **模式**：`Flat`（处于已平铺的组内）或 `Break`（顶层或已断开组的
  直接内容）。可断点与条件文本按条目模式行为；不在任何组内的可断点
  与条件文本因顶层模式为 `Break` 而自然按断开处理。
- **节点**：待处理的文档子树。引用节点弹出时就地替换为片段根节点，
  与直接写入该子树完全等价。

组在 `Break` 上下文中被弹出时做决策：含强制换行（查预计算的剖面
标志）则一律断开、不做放得下的判定；否则做放得下判定——组按平铺
渲染并连同其后续内容一起，直到第一个处于断开模式的可断点或强制
换行（或文档结束）为止，从当前列起累计宽度不超过行宽（取等放得下）
则平铺，否则断开。组平铺后其内容以 `Flat` 模式处理（嵌套组不再
判定）；断开后其直接内容以 `Break` 模式处理（嵌套组各自重新判定）。

## 关键取舍

### 扫描剖面预计算（放得下判定 O(1) 化）

放得下判定要考察"组平铺 + 后续内容直到第一个断点"。直接逐项扫描
会让每个组的判定成本随后续内容规模增长。`analyze` 为每个节点预算
两个**扫描剖面**：平铺剖面与断开剖面，各为 `(累计宽度, 是否中途停止)`，
分别对应"从当前列扫描该节点直到第一个断开的可断点或强制换行（或
子树结束）"的结果。剖面是组合式的（序列折叠、组在平铺/断开下都取
子节点的平铺剖面、缩进/对齐透明、引用取片段剖面），一次后序遍历
O(n) 算完。判定时组自身内容一次查表，后续内容按工作清单条目逐个
查表，一旦累计宽度超过剩余宽度立即得出放不下。

### 级联断开

组因判定失败而断开、且其内容剥开缩进/对齐/引用后直接是另一个组时，
内层组在同一列面对的考察序列与外层完全相同（上述节点类型在判定中
透明且不产生输出），可直接断开而不必重新判定。任何输出都会使级联
失效。这使深层组链的判定不随深度平方增长。

### 全程迭代、无递归

分析遍历与渲染主循环都使用显式栈，嵌套深度（上限 1000）不会导致
栈溢出。深度按"含引用展开"计算：引用节点不增加深度，片段根的深度
即引用点的展开深度；片段图无环（登记时要求只能引用已登记片段），
共享节点用备忘录只算一次。

### 延迟缩进与增量行尾裁剪

行首的缩进空格推迟到该行首次输出非空内容时才写入，因此只含缩进的
行自然输出为空行。当前行末尾连续空格的个数增量维护，换行时按计数
截断缓冲，实现"每行行尾的全部空格都要去掉"。

### 输出上限按裁剪后计

输出过大（总宽度超过 10^7）的判定不计入当前行末尾即将被裁掉的
空格：记账时减去行尾空格计数后再与上限比较，因此"巨额行尾空格被
裁掉"不会误报超限，而无法裁剪的内容一超限立即中止渲染。

### 并发：快照而非长锁

`Render` 在读锁下浅拷贝登记表（Doc 不可变，浅拷贝即稳定快照）后
释放锁再渲染；`Register` 在写锁下完成全部校验与插入。效果等价于
所有已接受操作按某个串行顺序执行，渲染看到一致快照，登记与渲染、
渲染与渲染可同时进行。被拒绝的登记在插入前返回，不改变状态。

### 错误优先级

分析通道在一次遍历中收集三类问题（参数非法、过深、未登记引用），
遍历结束后按 参数非法 > 文档过深 > 未登记引用 的优先级报告；输出
过大在渲染阶段发现，优先级最低。登记时按 参数非法 > 重复片段名
（> 未登记引用）报告。

## 被放弃的方案

- **递归渲染器**：表达最直接，但深度嵌套会栈溢出，且"后续内容"的
  考察需要显式延续，反而更复杂。放弃。
- **判定即试渲染**（把组平铺试渲染到临时缓冲量宽度）：实现简单但
  每个组的判定成本随子树与后续内容规模增长，深层/宽文档下退化为
  平方级。被扫描剖面取代。
- **构造期预算标注**：把剖面存在节点上。但引用的剖面依赖登记时未
  知的片段，且节点要被多个会话/渲染并发共享，故改为渲染前对快照
  做一次性标注（每次渲染 O(n)，可接受）。
- **渲染全程持读锁**：能保证快照一致，但登记会被长渲染阻塞。改为
  浅拷贝快照后释放锁。
- **哈希cons/节点共享**：可进一步降内存，但收益小、复杂度高。放弃。

## 复杂度

设文档与可达片段共 n 个节点。分析通道 O(n)。渲染主循环每个节点
处理 O(1) 次；每个组的判定 = O(1)（自身剖面）+ 考察的工作清单
条目数，而考察在遇到断开的可断点/强制换行即停、且累计宽度超过
剩余宽度立即停。深层组链由级联断开保证不随深度平方增长；所有
遍历均无递归。基准（`go test -bench=. ./pretty/`）显示规模翻倍
耗时近似翻倍。

## 本地验证方法

```bash
# 全量测试（含随机对照、并发、深度、规模）
go test ./pretty/

# 竞态检测
go test -race ./pretty/

# 查看随机对照的输入、输出与逐组判定依据
go test -v -run TestRandomDifferential ./pretty/

# 加大随机对照用例数
PRETTY_RANDOM_CASES=100000 go test -run TestRandomDifferential ./pretty/

# 性能特征（近线性扩展）
go test -bench=. -run '^$' ./pretty/
```

测试构成：

- `render_test.go`：规格逐条行为测试（取等边界、后续内容影响判定、
  外层断开截断考察、强制换行传播、对齐缩进叠加、条件文本、双宽
  字符、行尾空格、超宽清单、引用等价等）。
- `errors_test.go`：各类错误与优先级、被拒绝操作不改变会话状态。
- `naive_test.go` + `random_test.go`：独立朴素模型（递归实现，不用
  任何引擎优化，逐组记录判定依据）与随机文档对照；另含深层嵌套
  对照、大文档规模、深度级联用例。
- `concurrency_test.go`：并发渲染与登记（配 `-race`）。
- `bench_test.go`：宽度/深度两个维度的扩展性基准与用法示例。
