# 分代内存回收模型 — 设计说明

## 模块划分（gc 包，8 个 .go 文件）
- `object.go` 对象与引用登记：定长引用字段、代别、熬过的年轻区回收次数；回收后记录保留（alive=false），用于区分「未定义」与「悬垂」。
- `barrier.go` 写屏障与记忆集：仅当年老对象写入年轻对象时登记年老对象（按对象去重，O(1) map 插入）。
- `minor.go` 年轻区回收与晋升：起点 = 年轻根 + 记忆集成员的年轻字段；存活者年龄 +1，达到阈值且年老区有位则晋升，否则钉在阈值待下次重试。
- `major.go` 年老区回收：全堆从根标记，只清除死亡年老对象并移除其记忆集登记项；只由显式触发。
- `runtime.go` 对外 API 与统计：单互斥锁串行化全部操作；`Stats()` 持锁一次取齐，保证同一瞬间。
- `errors.go` 四类哨兵错误；校验次序硬编码为 未定义 > 参数 > 悬垂 > 空间不足。

## 关键取舍
- 记忆集重算而非沿用：任何「年老→年轻」边只能由写屏障或晋升产生，故新记忆集 = 旧登记项中仍引用活年轻对象者 + 新晋升者中引用年轻对象者，无需扫描年老区。
- 年轻区回收开销与年老区大小无关：`Stats.LastMinorWork` 记录每次回收扫描量（根数+记忆集扫描数+标记的年轻对象数），由 `TestMinorGCWorkIndependentOfOldSize` 验证。
- 并发：单互斥锁使写屏障登记与引用写入不可分，所有操作天然等价于某串行顺序；`-race` + 记忆集不变式校验佐证。
- 晋升按对象 id 升序处理，保证年老区部分剩余时结果确定、可与朴素模型对照。
- 自动回收真实发生故计入 MinorGCs；仅失败分配本身不产生对象、不改对象数/晋升数/记忆集/写屏障统计。
- `NilObj`(0) 可写入字段表示清除引用，不参与未定义校验。

## 被放弃的方案
- 按字段登记（卡表/精确卡）：粒度细但实现重，按对象登记已满足正确性且去重简单。
- 年轻区回收时扫描全部年老对象重建记忆集：简单但违背「开销不得随年老区增长」。
- 分代独立锁/无锁记忆集：收益不明，串行化语义反而难以证明。
