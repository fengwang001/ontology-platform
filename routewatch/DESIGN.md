# 配送车辆路线时间窗监控 — 设计说明

## 1. 模块划分

系统位于 `routewatch` 包，按职责拆成彼此协作的五个单元，外加一个独立参照模型：

- `model.go` — 静态数据模型：`Config` / `Stop` / `Window` / `TravelTable` /
  `StopResult` / `Snapshot`，以及唯一的参数合法性来源 `Config.validate`。
- `clock.go` — 单调逻辑时钟。`accept(t)` 在 `t < last` 时返回
  `ErrClockRollback` 且不写入；被拒绝的操作因此不可能移动时钟。
- `simulate.go` — 增量推演引擎。输入“重推演起点 + 已确认实际到达（锚点）”，
  只重写后缀结果，前缀内存不读取、不写入。
- `eta.go` — 对外发布 ETA 的状态机：首次发布、防抖（差值严格大于阈值才更新，
  恰等不更新）、锁定窗口（`ETA - clock <= lock` 视为已入窗，恰等也算入窗，
  入窗后冻结），以及到达/跳过/取消后撤下发布值。
- `monitor.go` — 并发安全门面。单把 `sync.Mutex` 串行化所有操作，按规定的
  拒绝优先级做校验，接受后只触发“受影响后缀”的重推演与再发布，并返回防御性
  拷贝快照。
- `naive/naive.go` — 独立编写的朴素参照模型：每次接受操作后**从车场全量重
  推整条路线**，再对所有站点重算发布。它与主实现不共享任何推演代码，专用于
  随机差分测试。

## 2. 关键推演语义

### 2.1 时间窗

- 到达 `< earliest`：等待到 `earliest` 开始服务，状态 `waited_then_on_time`。
- 到达 `== latest`：准时（两端含）。
- 到达 `> latest`：迟到。软窗照常服务（`late`）；硬窗**跳过**（`skipped`，
  不服务、不停留）。
- 被跳过站点的行驶时长取“上一个实际到达（被服务）站点 → 下一站”的表值，
  永远不经过被跳过点。

### 2.2 连续驾驶

推演过程中携带的状态只有三元组：

1. `fromIdx` — 上一个被服务的位置（0 表示车场）；
2. `readyAt` — 在该位置可出发的时刻；
3. `driving` — 离开该位置时已累计的连续驾驶时长。

对每个候选点，独立地评估“该服务位置 → 候选点”的直达路段：

- `driving + leg > MaxDriving` 时，先在该服务位置休息 `RestDuration` 再出发，
  休息后连续驾驶清零；`== MaxDriving` 合法（严格大于才休息）。
- 硬窗跳过的候选点**不计入**连续驾驶累计：因为车并未分段行驶，而是直接从
  当前服务位置驶向下一候选点；该直达段的疲劳在“下一个真正服务的候选点”被
  评估时计入。这样保证休息不会因为中间隔着若干跳过点而被重复施加。
- 服务点的停留 = 等待 + 服务，`departure - arrival >= RestDuration`（恰等也
  算）使连续驾驶清零。

### 2.3 实际上报（锚点）

- 必须严格晚于“前一个实际上报且被服务站点”的离开时刻；此前没有上报时，以
  车场出发时刻为基线（到达 `<= departure` 拒绝）。
- 上报把该站的到达时刻钉死为实际值，随后从该站起重推演。
- 已上报、已取消 → `ErrInvalidState`；推演中被硬窗跳过 → `ErrStopSkipped`；
  站点不存在 → `ErrStopNotFound`。
- 锚点只替换到达瞬间：服务开始/离开仍按时间窗与服务时长推导；疲劳与休息依
  计划路段计算（一条实际上报不会抹消已经累积的疲劳）。

### 2.4 取消

- 仅允许取消“未上报、当前推演有效（未被硬窗跳过）、未取消”的站点。
- 取消后从该站起重推演，该站永久从路线中剔除（不再有发布值），其后站点的
  行驶时长沿“最近被服务站点”的表行直达。

## 3. 拒绝优先级

严格按以下顺序短路返回（任一步拒绝都不发生任何写入）：

1. 参数非法（空 ID、负时刻、配置非法）
2. 时钟回退
3. 站点不存在
4. 状态不符（已上报 / 已取消；取消已到达或已跳过站点）
5. 上报被跳过的站点 → 专门的 `ErrStopSkipped`（状态检查优先于跳过检查）
6. 顺序错误（实际上报不严格晚于前站离开）

## 4. 后缀增量与复杂度论证

- 上报站点 `i` / 取消站点 `i` 后，调用
  `engine.resimulate(results, i, anchors)`，循环范围是 `[i, n)`；`eta` 的
  再发布同样只遍历 `[i, n)`。
- 重推演入口需要一个边界三元组。正常情况下它就是 `results[i-1]`；当
  `results[i-1]` 因后缀重写而暂时是“跳过/取消”时，向左线性回溯到最近的
  被服务位置（其 `Departure` / `Driving` 永不变，因为它在重推演前缀内）。
  该回溯的步长等于“紧贴起点左侧连续的跳过/取消点数”，属于后缀语义的一部分
  （这些点本就要在本次或后续推演中被重新评估），**永远不触碰更早的已服务
  站点的计算**。
- 机器可验证的证据：`routewatch/sim_bench_test.go` 中
  `BenchmarkResimulateLastSuffix` 在 `n=256…16384` 下只重推最后一站
  （后缀大小恒为 1），实测约 40–70 ns/op、0 分配，不随前缀长度增长；
  `BenchmarkResimulateHalfSuffix` 随后缀长度线性增长，作为对照。
- 注意：`ReportArrival` / `CancelStop` 返回的是整份 `Snapshot` 防御性拷贝，
  该拷贝天然 O(n)，属于对外读接口成本而非推演成本；基准因此直接隔离测量
  `engine.resimulate`。

## 5. 并发与确定性

- 所有读写经同一把互斥锁串行化，因此“结果等价于某个串行顺序”是执行模型的
  直接推论，而非事后补偿；`go test -race` 下保持干净。
- 任一时刻状态 = 以当前时钟、锚点集合与取消集合，从车场按规则推演的结果，
  朴素模型随时全量重推，差分测试对每个接受步骤都校验这一等价性。
- 状态中没有随机源；同一操作序列（含时间戳）重放得到完全一致的推演与发布
  值（`TestDifferentialDeterminism` 两次重放比对指纹）。

## 6. 关键取舍与被放弃的方案

- **放弃“跳过分段累计疲劳”**：曾让连续驾驶在每个跳过点累加 `lastServed→skip`
  路段，再用 `skip→next` 表值。这既与“直接从上一服务站驶向下一站、取该表
  值”矛盾（会双算），也会让一次休息在一串跳过点上被重复生效。最终只在真正
  服务的候选点上累计其直达路段。
- **放弃稠密行驶矩阵**：早期 `newEngine` 构造 `(n+1)×(n+1)` 表，初始化即
  O(n²)，在大路线基准中主导成本。现直接查 `TravelTable` 的稀疏 map，缺省
  点对按 0 秒处理；构造 O(1)，推演每点期望 O(1) 查表。
- **放弃把“全部已知信息从头推演”做成每次操作的真实行为**：对外语义仍保证
  与全量推演一致（由朴素模型差分把关），但实现只写后缀；全量推演仅存在于
  参照模型与文档论证中。
- **发布值与推演值分离存储**：发布 ETA 独立于推演结果存放，使“防抖/锁定
  保留旧值”和“前缀发布值永不被改写”都成为显式不变量，而不是从推演结果反
  推。
- **时钟起点**：逻辑时钟初始化为车场出发时刻；第一次构造即完成首次推演与
  首次发布（首次发布不防抖、不锁定）。

## 7. 本地验证方法

环境要求 Go 1.26+（本机 Go 位于 `/usr/local/go/bin`）。若默认构建缓存目录
只读，可将缓存指向 `/tmp`：

```bash
export PATH=$PATH:/usr/local/go/bin
export GOCACHE=/tmp/gocache GOMODCACHE=/tmp/gomodcache

go test -race -count=1 ./...          # 全量（含 400 组随机差分、竞态）
go test -v -run TestWindowEndpoints ./routewatch
go test -run=XXX -bench=Resimulate -benchtime=20000x ./routewatch
gofmt -l . && go vet ./...
```

随机差分的输入/输出/判定日志可通过对单个用例调用
`runDifferential(t, c, true)` 查看（`diff_test.go` 中 `verbose=true` 时逐
步打印操作、双方拒绝类别、接受后的完整结果与发布值）。
