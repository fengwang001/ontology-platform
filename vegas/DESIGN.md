# Vegas 式并发限制器（`vegas` 包）

带**令牌超时回收**、**丢弃降级冷却**与**滑动最小时延窗口**的 Vegas 式并发限制器。
所有状态更新都带显式时刻 `now`（`int64`），相同的操作序列在独立实例上重放
会得到完全相同的上限序列与放行判定。

## 维护的状态

| 状态 | 含义 |
| --- | --- |
| `L` | 当前并发上限，初值 `L0`，恒有 `Lmin ≤ L ≤ Lmax` |
| `n` | 在途（已放行未归还、未超时）请求数 |
| 窗口 | 成功样本 `(t, rtt)`，只保留满足 `t + Wm > now` 的项 |
| `lc` | 上次降级时刻（可空），配合冷却 `Cd` |
| 令牌表 | 序号 → `{w, expiresAt, done}`，`w` 为放行后的 `n`，`expiresAt = now + Tmo` |
| 序号计数 | 首个令牌序号为 `1`，每次成功放行 `+1`；被拒绝的 `Acquire` 不消耗序号 |
| `maxNow` | 已通过前置检查的最大时刻，初值 `0`，用于时钟回退判定 |

## 排队估计公式

成功归还时先把 `(now, rtt)` 放入窗口，令

```
m = min { rtt_i | t_i + Wm > now }   // 含本次样本
```

Vegas 排队估计量为

```
        ⎡ L · (rtt - m) ⎤
q = ceil ⎜ ───────────── ⎟
        ⎣      rtt       ⎦
```

（整数上取整：`q = (L*(rtt-m) + rtt - 1) / rtt`。）

- `q < α`：`L = min(Lmax, L+1)`
- `q > β`：`L = max(Lmin, L-1)`
- `α ≤ q ≤ β`：`L` 不变

边界：`q == α` 与 `q == β` 都不调整；首个样本使 `m = rtt`，故 `q = 0 < α`
（前提是不受应用受限约束），触发一次增长。

## 应用受限判定

仅当令牌放行时的在途位次 `w` 满足 **`w·2 ≥ L`** 时，本次成功样本才参与升降级。

- `w·2 < L`：应用受限，本次**不改 `L`**；
- `w·2 == L`：**不算**受限，正常按 `q` 调整；
- 无论是否受限，样本都已入窗、`m` 都已更新。

注意判定使用的是令牌记录的 `w`（放行时刻的位次），不是归还时的 `n` 或当前 `L`。

## 丢弃降级与冷却

`cut(now)`：

```
若 lc 为空 或 now ≥ lc + Cd：
    L = max(Lmin, floor(L · 9 / 10))
    lc = now                    // 即使取整后 L 未变也更新
否则：什么都不做
```

- `Cd = 0` 时每次 `cut` 都生效；
- 冷却边界为闭区间：`now == lc + Cd` 即生效，`now == lc + Cd - 1` 仍在冷却；
- 到达 `Lmin` 后取整结果被夹回 `Lmin`（数值不变），但 `lc` 仍刷新。

## 超时回收及其次序

`reap(now)`：按序号升序处理所有满足 `expiresAt ≤ now` 的**未归还**令牌
（恰相等即超时）。对每个这样的令牌依次：

1. `n = n - 1`，从在途令牌中移除并记入“已超时集合”；
2. 执行一次 `cut(now)`。

因此一次 `reap` 内多个超时令牌会各触发一次 `cut`；冷却使它们通常只在第一次
真正收缩。`Acquire` 与 `Release` 都**先 `reap(now)` 再做判定/处理**：

- `Acquire`：`reap` 后若 `n < L` 放行，否则返回“已达上限”；
- `Release`：`reap` 后再依次校验令牌与 `rtt`。因此若令牌已在本次 `reap` 中
  超时，即使它的名额刚被释放，归还仍返回“令牌已超时”。

当 `L` 因收缩/回收降到低于当前 `n` 时，已放行的请求不受影响；后续 `Acquire`
一律拒绝，直到归还/回收使 `n < L`。

## 滑动最小时延窗口的数据结构

窗口同时需要按时间淘汰队首与取最小值，使用**单调双端队列**：

- 队首是当前窗口内 `rtt` 最小的样本；新样本入队前，把队尾所有 `rtt ≥ 新 rtt`
  的样本弹出；
- 每次操作先从队首弹出 `expire = t + Wm ≤ now` 的过期样本。

每个样本入队一次、至多从队首或队尾被移除一次，因此窗口维护累计为
`O(成功样本总数)`。令牌表按序号连续存储，且令牌的 `expiresAt` 随序号单调不减，
`reap` 只需检查并前移队头游标，每个令牌在其生命周期内至多被处理一次，
累计为 `O(放行总数)`。非导出计数器 `tokenExamined`、`windowExamined`
记录累计考察数，见 `amortized_test.go` 在 1k / 100k 规模下的断言。

## 参数校验与拒绝优先级

构造参数（任一非法即整体拒绝 `ErrInvalidConfig`）：

- `Lmin < 1`
- `Lmax < Lmin` 或 `Lmax > 10^6`
- `L0 ∉ [Lmin, Lmax]`
- `α < 0`
- `β ≤ α`
- `Tmo`、`Wm ∉ [1, 10^9]`
- `Cd ∉ [0, 10^9]`

操作拒绝原因（按此顺序只报第一个）：

1. （仅 `Release`）结果不是成功/丢弃/忽略三者之一 → `ErrInvalidResult`；
2. 时间非法：`now < 0` 或 `now > 10^15` → `ErrInvalidTime`；
3. 时钟回退：`now < maxNow` → `ErrClockRewind`。

以上三类**不改变任何状态**（`maxNow` 也不推进、不回收）。

通过三项检查后 `maxNow` 推进到 `now` 并执行 `reap`；此后的**状态类拒绝保留
`reap` 与 `maxNow` 的推进**，其余状态不变：

- `Acquire` 已达上限 → `ErrAtCapacity`；
- 令牌序号在已超时集合 → `ErrTokenTimedOut`（与无效令牌区分）；
- 令牌从未发放或已归还 → `ErrInvalidToken`；
- 成功而 `rtt < 1` 或 `rtt > 10^12` → `ErrInvalidRTT`，令牌仍视为未归还，
  之后仍可正常归还；忽略/丢弃结果不校验 `rtt`。

## 并发与确定性

所有公共方法持有同一把互斥锁串行化，因此并发的 `Acquire`/`Release`/查询
等价于某个合法的串行顺序，在途数始终等于未归还且未超时的令牌数。
由于时刻由调用方提供，可复现性来自“相同输入序列”：显式时刻全部非降时，
重放同一序列即可逐字节复现 `L`、`n`、`m` 与放行判定（见 `replay_test.go`）。

## 本地验证

```bash
# 全量
go test ./...

# 竞态 + 详细日志（规则用例打印每次输入、输出与判定依据）
go test -race -v ./vegas

# 仅随机对照（2000 组，朴素逐项扫描模拟器）
go test ./vegas -run TestAgainstNaiveRandom -v

# 摊销考察次数（1k / 100k）与确定性重放
go test ./vegas -run 'TestAmortized|TestSingleOperation|TestDeterministicReplay' -v

go vet ./...
gofmt -l .
```

测试组成：

- `rules_test.go` / `rules2_test.go`：规则边界（`w·2` 等于/小于、`q` 恰为
  `α/β`、冷却、取整不刷新数值但刷新 `lc`、超时边界、多令牌回收、窗口出窗、
  上下限夹取、错误区分、三类前置拒绝不改状态、状态类拒绝保留 `reap`）；
- `naive_test.go`：严格逐行、逐项全表扫描窗口与令牌表的朴素模拟器；
- `random_test.go`：2000 组随机配置 + 随机/非法操作序列与朴素模拟器逐操作对照，
  并统计全部七类拒绝原因都被覆盖；
- `concurrency_test.go`：阶段屏障下的真实并发放行/归还，断言在途峰值不超过 `L`、
  令牌唯一、无回退、结束 `n=0`（`-race` 下运行）；
- `amortized_test.go`：累计考察数为放行/成功样本总数的常数倍，单次操作考察数
  不随在途数与窗口长度增长；
- `replay_test.go`：相同序列两次重放，结果记录完全相等。
