# 可增长协程栈 — 设计说明

## 关键取舍
- 指针用「协程 id + 单调帧 id + 槽号」逻辑表示，不暴露裸地址：搬迁只移动字节并改写仍存活的指针单元，
  句柄对搬迁天然免疫；只有目标帧弹出才悬垂。
- 每个协程维护两张表：活指针集合（仅含指针型槽位）与按目标槽位的入站索引。普通压/弹/读写为 O(1)；
  搬迁修正只遍历活指针数 P，复制仅复制已用前缀 U，与其他协程数量、总槽位数无关（测试用计数器证明）。
- 增长尺寸 = 满足 need 的最小 `当前*GrowthMul^k`；上限不可达即栈溢出；先判溢出再判配额，申请失败原栈不动。
- 弹帧后若 `used < ShrinkRatio*size`，收缩到仍满足该不等式的最大 `Base*G^k`；收缩失败不撤销弹帧（逻辑帧已弹出）。
- 反抖动在创建实例时核验：`ShrinkRatio < 1/GrowthMul`。增长后使用率严格大于 1/G，故增长后不可能立刻落入收缩区。
- 并发：单把全局互斥串行化所有变更，配额在同锁内扣还，总体等价于某个串行顺序；统计在锁内一次性快照。
- 跨栈与逃逸在「写入时刻」拒绝：`CopyPtr` 比较目标协程，`PublishPtr`/发布指针型槽位一律拒绝。
- 悬垂指针保留为槽内值但不参与搬迁修正、不阻止收缩；经句柄解引用或复制时报悬垂。

## 被放弃的方案
- 句柄保存物理地址 + 搬迁时遍历所有句柄：句柄会逃逸到栈外、且无法在写入时检测跨栈/逃逸。
- 搬迁时全栈扫描找指针：修正成本变成 O(总槽位)，不满足要求；改用显式指针索引。
- 收缩失败回滚弹帧：会让逻辑已死的帧复活，语义矛盾；改为收缩失败仅保留较大物理栈。

## 模块
- `config.go/errors.go`：配置核验与错误类别、固定拒绝次序（未定义>参数>悬垂>跨栈/逃逸>溢出>配额）。
- `runtime.go`：所有权、锁、配额、分配器抽象、统计快照。
- `registry.go`：协程/帧登记与全部公开操作及日志。
- `pointer.go`：活指针集、入站索引、弹帧悬垂标记。
- `grow.go`：最小倍数增长、阈值收缩、搬迁与指针修正。

## 本地验证
```bash
GOCACHE=/tmp/gocache go test -race -count=2 ./growstack/
GOCACHE=/tmp/gocache go test -run TestNaiveEquivalence -v ./growstack/   # 朴素模型对照
GOCACHE=/tmp/gocache go test -cover ./growstack/
gofmt -l growstack && go vet ./growstack/
```
测试覆盖：最小整数倍增长、上限/配额取等、搬迁前后读写语义、悬垂拒绝、跨栈与逃逸写入时拒绝、
配置核验、搬迁失败原栈完好、并发配额精确（任意时刻尺寸之和≤总配额）、统计一致性、复杂度计数器、
以及 60 个种子的随机序列与「不搬迁、起始即最大栈」朴素模型逐槽位/逐指针对照。
日志由 `WithLogger`/`SetLogger` 注入，逐条记录输入、ACCEPT/REJECT、错误类别与判定原因。
